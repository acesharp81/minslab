DB 식별자·구조·테이블 집합, 보호 컨테이너의 ID·시작 시각·재시작 횟수·실행 상태·마운트는 동일했다. Docker 마운트 배열의 표시 순서는 정규화하여 비교했다. 두 보호 데이터 폴더와 모든 보호 컨테이너의 마운트가 삭제 경로와 겹치지 않는 것도 검사했다. 보호 DB에 데이터 변경 SQL을 실행하거나 보호 컨테이너·수집 프로세스를 중지/재시작하지 않았다.

## 이력과 증빙

10월 20일 23:05 예약은 HOME README의 무관한 추가 수정까지 차단하는 전체 파일 해시 검사 때문에 삭제 전 중단됐다. 이후 README는 삭제 대상 문구만 검사하도록 수정했다. 10월 21일 즉시 실행 시에는 보호 범위를 더 좁혀 PoC 7·10 파일을 변경 대상에서 완전히 제외했다. 어제 실패 기록은 `data/maintenance/poc11-12-20261020/result.json`에 보존한다.

완료 상태와 읽기 전용 검증 자료:

```bash
cat data/maintenance/poc11-12-20261021/result.json
cat data/maintenance/poc11-12-20261021/verification.json
cat data/maintenance/poc11-12-20261021/protected-comparison.json
cat data/maintenance/poc11-12-20261021/protected-files-comparison.json
```

`review.json`과 `removal.patch`는 실행 전 검토 자료이며, 실행 후 재적용하지 않는다. `run.py`는 완료 기록을 발견하면 재실행을 중단한다. 공용 파일의 실행 전 복구본은 같은 비공개 증빙 디렉터리의 `shared-before`에 보존했다.
