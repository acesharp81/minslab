## 직접 실행

Python 3.12 기준으로 검증합니다. 프로젝트 디렉터리에서 실행하세요.

```bash
cd PoC/13-handover
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
bash scripts/run.sh
```

브라우저: **http://127.0.0.1:18130/**. 이 주소는 앱이 실행 중인 컴퓨터의 주소입니다. 원격 서버에서 실행했다면 VS Code의 포트 전달 기능으로 **18130**을 전달하거나 다음 SSH 터널을 사용하세요.

```bash
ssh -L 18130:127.0.0.1:18130 사용자@서버주소
```

SSH 서버가 별도 포트를 사용하면 `-p 포트번호`를 추가하세요. 터널 연결 후 자신의 브라우저에서 위 주소를 엽니다. 공유 웹 주소 연결은 [라우팅 설정안](docs/nginx-handover.conf.example)을 참고하세요. 설정안 생성 자체가 배포 완료를 뜻하지 않습니다.

## 4개 업무 흐름 체험

1. **시연 및 샘플 데이터 다운 → 샘플2**을 실행하거나 자료실의 `practice-samples.zip`을 새 인수인계함에 등록합니다. DOCX 4개·XLSX 6개·PDF 3개·TXT 2개입니다.
2. Solar Pro 4로 분석하면 5개 후보가 나옵니다. 앞의 3개 업무는 계획·착수·중간/완료 보고를 자동 연결합니다.
3. **예약포털 접근성 보완 → 같은 업무로 매칭**에서 **문화시설 통합예약 개선**을 선택합니다. 09_업무동일성_담당확인.txt에서 동일 범위·진행률 기준·담당자를 확인하고 담당 **디지털지원팀**·확인 사유를 입력합니다.
4. 4개 업무로 정리되면 검토·확정합니다. 최상단 간트에서 **65%·40%·100%·75%**, 기한 임박·경과·완료를 비교합니다. 일정 판정은 확정일에 고정됩니다.
5. 후임자로 역할을 바꿔 같은 최종 보고서를 확인하고 인수 확인합니다. HTML·DOCX·MD와 인쇄/PDF 저장을 지원합니다.

보고일·계획 시작일·전체 진행률 라벨이 명확한 단일 업무 문서에서 일정을 읽습니다. 보고일이 없거나 중복되면 최신 상태를 임의 선택하지 않습니다. 기간 경과를 달성률로 계산하지 않습니다. 원문이 없는 값은 미기재로 남습니다. 샘플은 전부 합성 자료입니다.

## AI 연결과 로컬 모드

현재 배포는 **Solar Pro 4 실제 연결 완료** 상태입니다. 샘플 시작과 초안 생성 화면에서 AI 분석이 기본 선택되며, 사용자 자료는 외부 전송 동의 후 분석합니다. 초안의 **모델 사용 기록**에서 호출 수와 토큰 사용량을 확인할 수 있습니다. 비정형 문서·일반 엑셀 표를 포함한 합성 자료 12개 검증에서 예상 업무 11개와 인용 67개를 확인했습니다. [Solar 4 실측 보고서](docs/SOLAR4_VALIDATION.md)를 참고하세요.

키 없이 실행하면 **로컬 규칙 추출**입니다. `업무:`, `담당:`, `기한:`, `상태:`, `다음 행동:` 같은 명시적 라벨을 추출합니다. 모든 블록을 조사하지만 라벨 없는 문장을 이해했다고 표시하지 않으며 추가 검토 범위를 표시합니다. 임베딩·의미검색·LLM 호출을 했다고 주장하지 않습니다.

비정형 문서에는 왼쪽 **AI 모델 연결**에서 프로젝트 전용 Upstage 키를 입력할 수 있습니다. 짧은 합성 문장으로 연결·응답 계약을 시험하고, 키는 현재 프로세스 메모리에만 보관합니다. 이 작업에는 API 사용료가 발생할 수 있습니다. 연결 성공 후 **초안 생성 → AI 문서 해석**과 외부 전송 동의를 선택합니다. 기존 서비스의 키를 자동으로 읽지 않습니다.

재시작 후에도 유지할 설정은 `.env.example`을 `.env`로 복사해 넣습니다. `.env`는 Git에서 제외됩니다.

```dotenv
HANDOVER_LLM_URL=https://api.upstage.ai/v1
HANDOVER_LLM_MODEL=solar-pro4
HANDOVER_LLM_KEY=프로젝트_전용_키
HANDOVER_ACCESS_TOKEN=길고_무작위인_공유_접속_코드
```

[Upstage 공식 Chat API](https://console.upstage.ai/api/chat)의 `solar-pro4`를 사용하며 실호출 응답 모델은 `solar-pro4-260806`이었습니다. UI는 `solar-mini4`도 선택할 수 있지만 이번 실측 대상은 Pro 4입니다. 자동화 계약 시험은 모의 HTTP 모델로, 별도 확대 평가는 실제 Solar API로 수행했습니다. 기록한 토큰 수는 청구 금액이 아니며 실제 과금은 계정의 계약·사용량에 따릅니다.

## 구현 범위

- ZIP 및 개별 파일 등록, 경로·압축률·크기 검사, 파일별 처리 결과, 불변 원문·파서 스냅샷.
- HWP 5.x/HWPX 본문·표, 텍스트 PDF, DOCX 본문·표, XLSX 셀·날짜·수식 캐시, UTF-8/CP949 TXT.
- 문서별 후보·블록 검토 범위, 동일 업무명·명시 담당의 보수적 그룹화, 기한 충돌·상태 변화 확인 표시.
- 필드별 원문 인용 검증, 전임자 입력 출처, 과거 근거·사유가 보존되는 불변 판본.
- 동시수정 방지, 원자적 확정, 확정본 우선 열람, 후임자 확인, MD/HTML 출력.
- SQLite 기반 본문 키워드 검색, 사건 경계 검사, 재시작 중단 표시·완료 문서 단계 캐시·재시도.
- 합성 샘플, 데스크톱/모바일 화면, 접속 코드 옵션, 자동화 시험.

검색은 **로컬 키워드 방식**을 채택했습니다. minirag MCP·벡터 검색은 이 버전에 포함되지 않습니다. 현 계획에서 허용한 대체 경로이며 독립 전환 MCP 3종이나 AIWorks Hub를 구현한 버전이 아닙니다.

## 제약

- 스캔 OCR, HWP 3.x, 암호화 파일, 매크로, 이미지·도형 의미 해석, 복잡한 서식의 완전 재현은 지원하지 않습니다.
- 후임자 역할 선택은 데모 UI이며 본인 인증이나 전자서명이 아닙니다. 사건 ID를 이용한 교차 참조는 서버에서 차단하지만 사용자별 문서 ACL은 없습니다. 접속 코드를 공유한 사용자는 같은 워크스페이스를 봅니다.
- 문서 확정은 모든 추출 사실을 `CONFIRMED`로 바꾸지 않습니다. 미확인·충돌·부분 추출 주의사항이 남습니다.
- 초안 재생성은 원문에서 새로 시작합니다. 전임자 수정값을 새 초안에 자동 병합하지 않으며 이전 확정본은 그대로 유지합니다.
- 외부 전송은 공개·합성 자료만을 전제로 합니다. 모델 응답의 원문 일치 검증이 의미 정확성까지 보증하지 않습니다.
- 단일 프로세스(`--workers 1`)로 실행하세요. 다중 워커/기관 운영 보안·백업·감사 정책은 별도 확장 범위입니다.
- 자연어 Q&A는 확정 필드 선택 방식이며 자유로운 추론·답변 문장 생성 기능은 아닙니다. 원문 보충은 미확정 배경으로 구분합니다. 자유 양식 HWPX 출력과 ERP/SSO 연동은 구현하지 않았습니다.

## 본문 기준 최신 판본 비교 (1.4.0)

홈의 **파일명·버전 혼선 체험**은 합성 중앙부처 개조식 문서 13개(HWPX 4, XLSX 4, PDF 5)를 Solar로 분석합니다. 파일명은 모델에 보내지 않습니다. 본문 사업명·사업관리번호로 연결하고 기준일, 같은 보고서의 수정차수·수정일시로 최신본을 채택합니다. 초안은 현재 사실에서 제외하고 상충·미상은 보류합니다.

`release/public/version-guide.md`에 시연 절차와 범위를 기록했습니다. `scripts/build_version_samples.py`는 `requirements-authoring.txt`의 저작 도구와 Playwright Chromium을 추가 설치한 개발 환경에서 원본을 재생성합니다. `scripts/version_e2e.py`는 실제 Solar 호출을 포함하므로 명시적인 검증 실행 시에만 사용합니다. 체크포인트를 보존하여 완료 결과를 재사용하며 다른 모델을 호출하지 않습니다. `tests/test_versions.py`는 모델 호출 없이 판정·본문 추출·파일명 독립성을 검사합니다.
