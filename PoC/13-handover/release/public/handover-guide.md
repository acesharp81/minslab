직접 등록은 ‘새 인수인계’ → 제목·인수 직원 지정 → ‘여러 파일 선택’ → practice-samples.zip → ‘초안 생성’ 순서입니다. 로컬 규칙 모드는 명시적 라벨을 분석하며 일반 문장의 AI 해석과 구분됩니다. 그림 분석은 기본 꺼짐입니다. 직접 선택하면 최신 채택본의 그림만 GPT-5.4로 후처리하며, 공용 일일 한도가 소진되면 GPT-6.1 Terra 공용 월 무료 예산으로 전환합니다. 상단에서 Solar 잔액, GPT 일일 잔여 토큰, PoC7·10·11·13 공용 월 무료 잔액을 확인할 수 있습니다.

## 3. 같은 업무로 매칭하기

초안은 5개 후보입니다. 보고서 상단 왼쪽 ‘업무 전체 보고 묶기’를 누릅니다. 팝업의 왼쪽은 묶인 업무, 오른쪽은 확인할 업무입니다. ‘예약포털 접근성 보완’을 ‘문화시설 통합예약 개선’ 위로 끌어 놓으세요. 원문 펼침에서 기준일·범위를 확인하고, 09_업무동일성_담당확인.txt와 대조합니다. 두 보고가 같은 사업 전체 범위이며 20%·75%가 동일 기준의 다른 시점인지 확인해야 합니다.

담당은 ‘디지털지원팀’으로 확인하고 ‘4개 업무로 저장’을 누릅니다. 저장 후 초안의 채택값과 흐름을 검토하세요. 여러 후보도 같은 묶음으로 옮길 수 있습니다. 목록 끝으로 카드를 가져가면 자동 스크롤되며, 두 열은 각각 스크롤됩니다. ‘이동’으로 대상 묶음을 고르거나 저장 전 되돌리기·분리도 가능합니다. 관리번호가 같다는 이유만으로 업무 범위를 확정하지 마세요.

## 4. 항목별 검토·수정과 확정

각 항목 옆 연필을 누르면 현재 값·수정값·변경 사유와 관련 근거를 함께 볼 수 있습니다. ‘업무 개요·계획·실무 절차·예산·연락망 확인’ 영역을 펼치면 상세실무편의 추가 항목도 각각 수정할 수 있습니다. 선택한 항목만 새 판본에 저장하며 변경 이력을 남깁니다.

필수 미기재가 없는지, 원문 기록과 전임자 입력이 구분되는지 확인하고 ‘검토 완료 · 확정하기’ → 확인 체크 → ‘이 판본 확정’을 누릅니다. 원문 추출 PARTIAL은 입력란 미정과 다른 개념입니다. DOCX의 본문·표 밖 범위 안내 등이 남을 수 있으며 원본에서 확인합니다. 보고서의 자료 검토 참고에 별도로 표시됩니다.

## 5. 완성 보고서를 읽는 순서

첫 화면의 간트에서 계획 기간·원문 달성률·지연 일수·실제 완료일을 확인합니다. 색 막대는 경과 시간으로 계산한 값이 아닙니다. 확정일이 달라지면 D-n과 지연 일수도 달라집니다. 배포 예시는 2026-11-09 기준입니다.

우선순위 페이지에서 기한 경과·임박 업무와 당장 할 일을 확인합니다. 각 업무의 A면은 개요·목표·인계 범위·보고 흐름·현재 진척·개별 실적·현안 경과, B면은 추진 계획·담당과 일정별 추후 계획·실무 순서·완료 기준·인계 산출물·결재·자료 위치를 담습니다.

공통 예산은 같은 예산코드를 한 번만 합산합니다. 5개 예산의 편성 합계 358,000,000원, 집행 212,000,000원, 지급 예정 33,000,000원, 가용 잔액 113,000,000원입니다. 공통 B-COM이 4개 업무에 등장해도 4번 합산하지 않습니다. 금액·기준일이 충돌하면 합계를 확정하지 않습니다. 연락망은 관계자ID 기준 11명이며 공통 회계·자료 지원 담당의 중복을 제거합니다.

과거 현안은 해소 기록이 있는 경우에만 해소로 설명합니다. 앞으로 만들 승인문·검수 결과는 제공된 증빙으로 표시하지 않습니다. 모든 인명·연락·금액·기록은 가상이며 실제 공문·영수증·현장 사진은 포함하지 않습니다.

## 보고서 화면의 목차와 챗봇

보고서 탭은 화면 높이에 맞춰 열리며 본문 안에서 스크롤합니다. 왼쪽 목차는 상위 주제만 먼저 보입니다. 화살표 또는 상위 제목을 누르면 세부 항목이 펼쳐지며 다시 누르면 접힙니다. 제목 클릭 시 본문도 해당 위치로 이동합니다. 작은 화면에서는 상위 제목을 펼쳐도 목차를 유지하고 하위 항목 선택 시 본문을 보여줍니다. 작은 화면에서는 위쪽 ‘목차’, ‘챗봇’ 버튼으로 패널을 열고 닫습니다.

상단의 역할 선택과 Solar 추정 잔액은 고정됩니다. 잔액을 누르면 $100 기준 사용량, 집계 시작 시점과 실제 Upstage 결제 콘솔 링크를 확인할 수 있습니다. 앱 집계 이전·외부 사용, 할인·세금 및 사용량 미확인 호출은 반영하지 않는 추정치입니다.

오른쪽 보고서 챗봇에서 ‘보조금 정산 남은 업무는?’처럼 질문합니다. Solar Pro 4 AI 질의는 질문·이전 질문·확정 보고서·관련 자료의 전송 동의 후 사용할 수 있습니다. ‘키워드 검색’은 외부 전송 없이 조회합니다. AI 답변은 실제 생성되는 대로 커서와 함께 글자 단위로 표시됩니다. 생성 중 문장은 미완성 상태이며, 완료 후 근거 검증을 통과하면 출처 버튼이 연결됩니다. 연결 오류나 근거 검증 실패 시 미완성 문장은 제거하고 오류를 표시합니다. AI는 결론·이유·바로 할 일을 문장으로 설명하며 문단별 ‘근거 확인’을 펼쳐 원문과 확정값을 볼 수 있습니다. 우선순위는 보고서에 근거한 AI 판단이며 이후 진행 상황은 별도 확인합니다. ‘그럼 담당은?’ 같은 후속 질문은 앞선 질문의 업무를 참고합니다.

답변은 확정 보고서에 기록된 값을 표시하고 원문 근거 버튼을 제공합니다. 참고자료는 별도 펼침 영역에 표시하며 과거 원문이 수정·확정한 값을 덮어쓰지 않습니다. 자료가 없으면 답을 추정하지 않습니다. 질문·근거 열람 중에도 읽던 보고서 위치를 유지합니다. 새 확정 판본이나 다른 인수인계함에서는 대화 범위를 새로 시작합니다.

## 6. 다운로드·후임자 확인

practice-report.html/pdf/docx/md는 같은 Solar 분석·담당자 매칭·확정 판본에서 생성한 예시입니다. HTML·PDF는 간트·추이·실적·예산 차트를, DOCX는 간트 이미지와 편집 가능한 표를, MD는 원문 인용까지 포함한 텍스트를 제공합니다.

앱의 ‘인쇄 / PDF 저장’ 또는 ‘보고서 새 창’에서 출력합니다. 검토 후 보고서 상단 오른쪽 ‘검토 완료 · 확정하기’를 누르고, ‘변경 이력’ 오른쪽 ‘인계하기’로 이동하세요. 받을 직원과 확정 판본을 확인하고 전달 의견을 적은 뒤 확인 체크 → ‘최종본 인계하기’를 누릅니다. 받는 직원은 인수인계함 생성 시 선택한 직원입니다.

오른쪽 위 직원 선택에서 해당 인수 직원으로 전환하면 같은 최종 보고서와 전달 의견을 확인할 수 있습니다. 보고서를 읽고 ‘인수 확인’을 누르면 완료됩니다. 전달 기록은 판본·인계자·인수자·의견·시각을 함께 보관합니다. 새 초안이나 새 자료가 있으면 최신본을 먼저 생성·검토·확정해야 인계할 수 있습니다. 기존 확정본과 인계 의견은 변경하지 않습니다. DOCX 외부 편집은 앱에 반영되지 않습니다.

## 7. 직접 실행·검증 범위

Python 3.12: 소스 ZIP 해제 → python3 -m venv .venv → .venv/bin/pip install -r requirements.lock → .env.example을 .env로 복사 → Upstage 키·접속 코드 설정 → bash scripts/run.sh. 기본 주소는 http://127.0.0.1:18130/ 입니다.

Docker: docker build -t poc13-handover:1.6.7 . → docker compose up -d. 전용 볼륨에 자료를 보존합니다. 소스 ZIP에는 운영 키·DB가 없습니다. 검사: bash scripts/verify.sh.

practice-expected.json은 원본 정답, practice-validation.json은 이번 실무 샘플의 실제 Solar 대조·출력·기능 검증 기록입니다. ‘100점’ 점검표는 이번 합성 시나리오의 정해진 항목 충족 여부이며 일반 문서 정확도나 외부 인증을 뜻하지 않습니다. 기존 GPT-5.4-mini 1회 평가 결과는 이전 7개 업무 샘플에 한정하여 유지하며 새 GPT 호출은 하지 않았습니다.

텍스트 PDF·DOCX·XLSX·TXT·HWP/HWPX 본문을 지원합니다. 스캔 OCR·복잡한 한글 서식 재현·기관 SSO·개인별 권한·전자서명은 범위 밖입니다. 역할 선택은 시연 기능입니다. 사용 라이선스는 docs/THIRD_PARTY_NOTICES.md를 참고하세요. 시연 영상과 참가 접수는 별도 진행합니다.
