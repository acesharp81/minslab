# Solar Pro 4 실제 연결 검증

검증일: 2026-11-08. 버전: 0.2.0. 사용자가 요청한 Solar 4는 `solar-pro4`로 연결했으며 실제 응답 모델은 **`solar-pro4-260806`**입니다.

## 판정과 범위

**실제 API 연결·합성 자료 확대 E2E: PASS.** 문서 등록부터 Solar 분석, 인용 검증, 전임자 수정, 확정, 후임자 조회, MD/HTML 출력까지 실행했습니다. 이 수치는 직접 작성한 소규모 합성 자료의 단일 실행 결과이며 일반 행정 문서의 정확도나 처리시간을 보장하지 않습니다.

시간에는 이 평가 스크립트의 등록·생성·수정·확정·출력 확인이 포함됩니다. 모델 자체의 순수 추론 시간이나 평균 응답시간은 아닙니다. 토큰 수는 **이 확대 평가 실행만**의 합계로, 앞선 연결 시험·문제 진단 및 배포 후 브라우저 시험 호출은 포함하지 않습니다. API 비용의 원화 금액은 측정하지 않았습니다.

## 자료와 반례

기존 HWPX·DOCX·XLSX·PDF·TXT 5개에 라벨 없는 문장, 일반 엑셀 표, 지역예술인 간담회, 접수만 종료된 사업, 문서 내 가짜 지시문, 무텍스트 PDF 등 7개를 추가했습니다. 모든 자료는 가상 한빛시를 배경으로 직접 생성했습니다.

- 서로 다른 기한은 충돌로 남겼습니다.
- 협의 부서를 담당 부서로 임의 지정하지 않았습니다.
- 미정 담당·기한은 확인 필요로 남겼습니다.
- 접수 종료를 전체 사업 완료로 바꾸지 않았습니다.
- 문서에 포함된 가짜 지시문으로 예상 밖 업무를 만들지 않았습니다. 단일 반례 통과가 모든 프롬프트 주입 방어를 보장하지는 않습니다.
- 전임자 수정 후 확정본을 후임자가 같은 판본으로 조회하고 MD/HTML로 출력했습니다.

## 실제 연결에서 보완한 점

초기 모델 응답은 원문을 자연스럽게 요약해 엄격한 인용 검증에 실패했습니다. 이를 성공으로 처리하지 않고, 원문 구절과 블록 ID만 선택하는 strict JSON Schema로 변경했습니다. 서버는 원문 일치를 검사한 뒤 해당 구절을 필드 값으로 사용합니다.

문서별 시도는 최대 2회입니다. 검증 실패와 일시 오류는 재시도하며, 인증 실패는 바로 중단합니다. 실패를 로컬 성공으로 대체하지 않고 진단과 반환된 사용량을 기록합니다. 이 계약에 대한 4개 시험을 추가해 전체 **20개 자동화 시험**이 개발 환경과 네트워크 차단·읽기 전용 Docker 환경에서 통과했습니다.

## 설정과 한계

사용자의 모델 연결 요청에 따라 기존에 설정된 Upstage 자격 증명 중 유효한 값을 읽어 **업무바통 전용 Git 제외 `.env`에 별도 저장**했습니다. 기존 설정 파일은 변경하지 않았으며, 앱은 다른 서비스의 설정을 실행 중 참조하지 않습니다. 별도의 새 Upstage 계정이나 키를 발급한 것은 아니므로 계정 사용 한도·과금은 공유될 수 있습니다. 키 값은 문서·판본·응답에 포함하지 않습니다.

외부 전송 동의, 원문 확인, 전임자 검토를 전제로 하는 체험 버전입니다. OCR·기관 SSO·사용자별 ACL·전자서명은 구현 범위에 포함되지 않습니다.
