## 서비스 개요와 목적

인수인계의 목적은 파일을 전달하는 데서 끝나지 않는다. 후임자가 **왜 시작한 업무인지, 어디까지 진행됐는지, 무엇이 남았는지, 누구와 협의해야 하는지**를 이해하고 다음 행동을 이어갈 수 있어야 한다.

업무바통은 흩어진 문서를 바탕으로 인수인계 보고서 초안을 만들고, 인계자의 근거 확인·수정·확정, 의견 전달, 인수자의 보고서 열람·질의응답·인수 확인을 하나의 흐름으로 연결한다. 문서에 기록된 업무 맥락을 승계하며, 기록되지 않은 경험이나 판단까지 자동으로 복원한다고 가정하지 않는다.

### 문제 정의

- 인사이동·업무분장 변경 때 자료가 여러 문서와 저장 공간에 흩어져 핵심 내용을 파악하는 데 시간이 든다.
- 수작업 인수인계서 작성 부담이 크고, 업무 추진 배경과 판단 근거가 빠지기 쉽다.
- 후임자는 자료를 반복 탐색하거나 전임자에게 다시 문의해야 한다.
- 개인 경험에 의존한 이관은 점검 사항 누락과 업무 공백으로 이어질 수 있다.

### 추진 방향

| 단계 | 구현 방향 | 사용자가 확인하는 결과 |
|---|---|---|
| 01 문서 통합 | 여러 형식의 자료 등록, 본문 판본 비교, 동일 업무 묶기 | 어떤 자료가 어떤 업무의 근거인지 확인 |
| 02 보고서 생성 | 업무별 개요·목표·계획·진척·현안·후속 조치와 공통 정보 정리 | 원문을 대조하고 수정·확정할 수 있는 보고서 |
| 03 AI 질의응답 | 확정 보고서 우선, 연결된 참고자료와 근거를 활용한 대화 | 우선순위·담당자·실행 순서·변경 이유 탐색 |
| 04 절차 지원 | 시작 가이드, 자료 등록부터 검토·확정·전달·인수까지 단계 표시 | 같은 최종본과 전달 의견을 바탕으로 인수 확인 |

### 약 200자 소개

> **바통 | 사람은 바뀌어도 업무의 맥락은 이어지도록**  
> 바통은 흩어진 업무 문서를 모아 AI가 인수인계 보고서 초안을 만들고, 담당자가 근거를 확인해 다음 사람에게 전달하는 지원 도구입니다. 후임자는 진행 현황과 남은 일, 담당자와 연락처를 한눈에 확인하고 챗봇에 필요한 내용을 질문할 수 있습니다. 자료 등록부터 검토·확정·인수 확인까지 연결해 업무 공백을 줄이고, 문서에 담긴 업무지식이 이어지도록 돕습니다.

## 구현 성과와 기대 효과

### 현재 구현한 성과

- **보고서 작성 지원:** 문서별 업무 후보를 추출하고, 여러 보고의 흐름·최신 판본·실무 정보·공통 예산과 연락망을 정리한다.
- **근거에 연결된 검토:** 항목별 연필 편집, 원문 팝업, 변경 사유와 과거 판본 보존을 제공한다.
- **완결된 보고서 전달:** 인계자와 인수자가 같은 확정본, 전달 의견, 확인 기록을 열람한다.
- **대화형 업무 탐색:** 자연어 답변을 생성되는 대로 표시하고, 답변 근거와 참고자료를 확인할 수 있다.
- **업무 연속성 지원:** 이전 인수 완료 보고서를 기준으로 기존 업무를 현행화하고 새 업무를 추가한다.
- **복합 사례 검증 자료:** 5개 사업·21개 원본·사업 보고서 표 95개의 합성 샘플과 완성 보고서 예시를 제공한다.

v1.6.7 개발 당시 자동 검사 **105개**가 통과했다. 샘플1에서 실제 Solar 응답의 PDF 줄바꿈 인용 오류를 재현·수정했으며, 실패한 작업을 재개해 초안 생성 완료를 확인했다. 당시 복구 작업은 이전 보고서 계승 옵션이 꺼진 사례였다. 이 기록은 합성 사례의 기능 검증이며, 실기관 도입 성과나 일반 문서 전체의 정확도 수치가 아니다. [관련 수정 기록](../v167-pdf-citation-recovery.md)

### 향후 확인할 기대 효과

보고서 작성 부담 완화, 후임자의 업무 파악 시간 단축, 반복 문의 감소, 누락 방지와 업무 연속성 향상을 기대한다. **실기관 활용에 따른 절감률·만족도·도입 규모는 아직 제시하지 않는다.**

| 측정 지표 | 권장 측정 방법 |
|---|---|
| 보고서 작성 시간 | 자료 준비·AI 처리·담당자 검토·수정 시간을 나누어 기존 방식과 비교 |
| 인수인계 준비 기간 | 동일 업무 범위에서 준비 시작부터 전달 완료까지 측정 |
| 후임자의 업무 파악 시간 | 담당자·기한·첫 조치 등 동일 질문에 답을 찾는 시간 비교 |
| 반복 문의·누락 | 인수 후 일정 기간의 추가 문의와 누락·재수정 사례 집계 |
| 후임자 만족도 | 실제 사용 후 이해도·근거 확인 편의·활용성을 설문 |

| 영역 | 구현 범위 |

문서의 **확정**과 업무의 **완료**는 다르다. 진행 중이거나 지연된 업무도 현황과 후속 조치를 기록해 인계한다. 진행률은 원문에 명시된 값이며 경과 시간으로 추정하지 않는다. 예산은 동일 코드 중복을 제거하고 기준일·금액에 문제가 있으면 전체 합계를 보류한다.

## 지원 범위와 적용 시 유의점

- 본문과 단순 표를 우선 지원한다. 스캔 OCR, HWP 3.x, 암호화·매크로 문서, 복잡한 서식 완전 재현, 벡터 도형·수식 해석은 지원 범위 밖이다. 부분 추출·미검토 표시는 사람이 확인한다.
- 삽입 그림 판독은 선택 기능이다. 전체 페이지를 OCR하거나 그림만으로 최신본을 판정하지 않는다. 판독 결과는 참고이며 확정 진행률·기한을 자동 변경하지 않는다.
- AI가 원문의 인용을 선택하고 서버가 실제 구간과 대조한다. 원문 일치 검증은 의미 정확성이나 누락 없음까지 보증하지 않는다. 미기재·미확인 사항은 확정 후에도 남을 수 있다.
- 직원 선택과 공유 접속 코드는 **시연용**이다. 직원별 화면·사건 범위 검사는 있으나 기관 인증, 검증된 개인별 권한, 전자서명·전자결재를 대신하지 않는다.
- 외부 AI 전송은 공개·합성 자료를 전제로 한다. 실기관 자료 적용에는 해당 기관의 보안·개인정보·모델 사용 기준과 운영 통제가 필요하다.
- 자연어 챗봇은 구현돼 있으나 문서 검색 기반은 로컬 키워드 방식이다. 임베딩·벡터 검색이나 minirag MCP를 구현한 것으로 설명하지 않는다.
- 현재 PoC는 업무바통 독립 앱이다. 초기 검토 주제였던 독립 문서 전환 MCP 3종이나 AIWorks Hub 확장판을 구현한 프로젝트가 아니다.
- 파일 생성 결과는 HTML·MD·DOCX 및 인쇄/PDF다. 자유 양식 HWPX 보고서 생성, ERP·SSO·기관 전자결재 연동은 별도 확장 대상이다.

## 실행 환경과 설정

### Python으로 실행

Python **3.12** 기준이다. 다음 명령은 저장소 루트에서 시작한다. 새 설치에만 `.env` 복사를 수행하고 기존 운영 설정을 덮어쓰지 않는다.

```bash
cd PoC/13-handover
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
cp -n .env.example .env
# .env에 이 프로젝트의 접속 코드와 필요한 모델 설정 입력
bash scripts/run.sh
```

기본 접속 주소는 `http://127.0.0.1:18130/`이다. 원격 서버라면 `ssh -L 18130:127.0.0.1:18130 사용자@서버주소`로 연결한 뒤 자신의 브라우저에서 연다. AI 키 없이도 로컬 규칙 모드로 명시적 라벨 자료를 처리할 수 있다.

### Docker로 새로 설치

```bash
# PoC/13-handover 디렉터리에서 실행
docker compose up -d --build
docker compose logs --tail=100 app
```

Compose는 호스트 `127.0.0.1:18130`을 앱의 `8000`에 연결하고 `poc13-handover-data` 볼륨을 사용한다. 기존 운영 컨테이너와 동시에 같은 포트·볼륨을 사용하는 새 인스턴스를 만들지 않는다. `scripts/docker-run.sh`는 현재 운영과 같은 단일 컨테이너 실행 방식이며 Compose와 둘 중 하나만 선택한다.

### 주요 환경 변수

설정 예시는 [.env.example](../../.env.example)을 기준으로 한다. 실제 `.env`, 키, DB는 배포 문서나 공개 패키지에 포함하지 않는다. 키 설정은 운영 환경에서 수행하며 사용자 화면의 ‘AI 모델 연결’ 메뉴는 없다.

| 변수 | 용도 |
|---|---|
| `HANDOVER_DATA_DIR` | 데이터 디렉터리. Docker에서는 `/app/data` |
| `HANDOVER_ACCESS_TOKEN` | 공유 시연 접속 코드 |
| `HANDOVER_LLM_URL`, `HANDOVER_LLM_MODEL`, `HANDOVER_LLM_KEY` | 문서 분석·답변 생성 연결. 현재 구현 기준 모델 ID는 `solar-pro4` |
| `HANDOVER_LLM_BUDGET_USD` | 앱 사용량 표시·관리 기준 금액. 제공사 확정 잔액을 뜻하지 않음 |
| `HANDOVER_VISION_KEY`, `HANDOVER_VISION_URL` | 그림 판독 연결 |
| `HANDOVER_USAGE_GATEWAY_URL`, `HANDOVER_USAGE_METER_TOKEN` | 공용 사용량·한도 게이트웨이 연결. 그림 기능에 필요 |
| `HANDOVER_SOLAR_SHARED_POOL` | 선택 설정. `key2`이면 설정된 게이트웨이에 Solar 사용량도 연계 |
| `HANDOVER_PORT` | `scripts/run.sh`의 로컬 서버 포트, 기본 18130 |

문서·답변 생성은 Solar Pro 4를 사용한다. 그림은 GPT-5.4 일일 공용 한도를 먼저 사용하며, **요청 전 일일 한도 소진이 명시적으로 확인될 때** GPT-6.1 Terra 월 공용 예산으로 전환한다. 단순 통신 실패를 이유로 다른 모델에 중복 요청하지 않는다. 모델명은 현재 앱의 연결 계약이며 모든 환경에서 해당 모델 사용이 가능한 것은 아니다.

앱 코드와 DB는 다른 PoC와 분리돼 있다. 다만 운영상의 사용량 게이트웨이는 선택적 외부 의존성이다. 특히 그림 분석과 공용 잔액 표시를 함께 재구축하려면 게이트웨이 계약도 준비해야 한다. 게이트웨이 없이 모든 부가 기능이 독립 실행된다고 설명하지 않는다.

## 유지보수와 장애 대응

### 데이터·배포 보존 원칙

- `data/` 또는 전용 볼륨에 SQLite DB, 원본, 파싱 결과와 그림 관련 캐시가 저장된다. DB만 복사하지 말고 **전체 데이터 디렉터리**를 함께 백업한다.
- 작업이 `RUNNING` 또는 `QUEUED`인지 확인하고 배포한다. 정상 종료 후 일관된 백업을 만들고, 이전 이미지·실행 설정을 보존한다.
- 교체 후 `/api/health`, 인수인계함 개수, 현재·확정·인수 판본 연결, 원문 열람, 공개 다운로드를 확인한다.
- 원문·이전 확정본·완료 문서 캐시를 장애 해결 목적으로 임의 삭제하지 않는다. `docker compose down -v`는 자료 볼륨을 지우므로 일반 중지 명령으로 사용하지 않는다.
- 다른 PoC의 코드·컨테이너·데이터를 수정 대상으로 삼지 않는다. 공용 프록시와 사용량 서비스는 변경 범위를 구분해 관리한다.

### 증상별 확인

| 증상 | 먼저 확인할 사항 | 대응 |
|---|---|---|
| 초안 생성 중단 | 작업 오류, 실패 파일명, 파싱 상태, 모델 실패 감사 기록 | 원인 수정 후 ‘다시 시도’. 완료 문서 단계는 재사용 |
| 재시작 후 중단 표시 | 작업 상태 `INTERRUPTED` | 같은 원본·모델·프롬프트 조건인지 확인 후 재시도 |
| PDF 인용 불일치 | 실제 내용 변경인지 시각적 줄바꿈인지 | v1.6.7은 제한된 줄바꿈 차이만 원문 구간으로 복구. 숫자·단어 변경은 계속 거부 |
| 예산 합계 미확정 | 예산코드 중복, 금액·기준일 불일치 | 원문 대장과 대조하고 수정 사유 기록 후 재확정 |
| 최신본 선택 보류 | 기준일 누락, 차수·시각 충돌, 문서상태 | 업로드 순서로 강제 선택하지 말고 본문 근거 확인 |
| 그림 분석 미실행 | 수동 체크, 최신본 채택 여부, 게이트웨이·한도 설정 | 사용자가 선택한 범위와 최신 파일만 처리되는지 확인 |
| 보고서와 최근 수정값 불일치 | 새 초안의 확정 여부 | 인수자는 전달된 확정본을 본다. 검토 후 새 판본을 확정·전달 |

### 검증과 패키징

```bash
bash scripts/verify.sh
python3 scripts/build_readme_views.py
.venv/bin/python scripts/prepare_manifest.py
.venv/bin/python scripts/package_release.py
.venv/bin/python scripts/prepare_manifest.py
```

`verify.sh`는 자동 테스트·Python 컴파일·프런트 JavaScript 구문을 검사한다. 일반 자동 테스트는 외부 모델 호출을 대체한다. 실제 모델 평가 스크립트는 별도이며 비용과 자료 전송을 확인한 뒤 실행한다. 상세 운영 절차는 [RUNBOOK](../RUNBOOK.md)을 참고하되 이전 버전의 화면·메뉴 설명과 이 마스터 문서를 구분한다.
