## 서비스 개요와 목적

인수인계의 목적은 파일을 전달하는 데서 끝나지 않는다. 후임자가 **왜 시작한 업무인지, 어디까지 진행됐는지, 무엇이 남았는지, 누구와 협의해야 하는지**를 이해하고 다음 행동을 이어갈 수 있어야 한다.

업무바통은 흩어진 문서를 바탕으로 인수인계 보고서 초안을 만들고, 인계자의 근거 확인·수정·확정, 의견 전달, 인수자의 보고서 열람·질의응답·인수 확인을 하나의 흐름으로 연결한다. 문서에 기록된 업무 맥락을 승계하며, 기록되지 않은 경험이나 판단까지 자동으로 복원한다고 가정하지 않는다.

### 문제 정의

- 인사이동·업무분장 변경 때 자료가 여러 문서와 저장 공간에 흩어져 핵심 내용을 파악하는 데 시간이 든다.
- 수작업 인수인계서 작성 부담이 크고, 업무 추진 배경과 판단 근거가 빠지기 쉽다.
- 후임자는 자료를 반복 탐색하거나 전임자에게 다시 문의해야 한다.
- 개인 경험에 의존한 이관은 점검 사항 누락과 업무 공백으로 이어질 수 있다.

### 추진 방향

| 단계 | 구현 방향 | 사용자가 확인하는 결과 |
|---|---|---|
| 01 문서 통합 | 여러 형식의 자료 등록, 본문 판본 비교, 동일 업무 묶기 | 어떤 자료가 어떤 업무의 근거인지 확인 |
| 02 보고서 생성 | 업무별 개요·목표·계획·진척·현안·후속 조치와 공통 정보 정리 | 원문을 대조하고 수정·확정할 수 있는 보고서 |
| 03 AI 질의응답 | 확정 보고서 우선, 연결된 참고자료와 근거를 활용한 대화 | 우선순위·담당자·실행 순서·변경 이유 탐색 |
| 04 절차 지원 | 시작 가이드, 자료 등록부터 검토·확정·전달·인수까지 단계 표시 | 같은 최종본과 전달 의견을 바탕으로 인수 확인 |

### 약 200자 소개

> **바통 | 사람은 바뀌어도 업무의 맥락은 이어지도록**  
> 바통은 흩어진 업무 문서를 모아 AI가 인수인계 보고서 초안을 만들고, 담당자가 근거를 확인해 다음 사람에게 전달하는 지원 도구입니다. 후임자는 진행 현황과 남은 일, 담당자와 연락처를 한눈에 확인하고 챗봇에 필요한 내용을 질문할 수 있습니다. 자료 등록부터 검토·확정·인수 확인까지 연결해 업무 공백을 줄이고, 문서에 담긴 업무지식이 이어지도록 돕습니다.

## 구현 성과와 기대 효과

### 현재 구현한 성과

- **보고서 작성 지원:** 문서별 업무 후보를 추출하고, 여러 보고의 흐름·최신 판본·실무 정보·공통 예산과 연락망을 정리한다.
- **근거에 연결된 검토:** 항목별 연필 편집, 원문 팝업, 변경 사유와 과거 판본 보존을 제공한다.
- **완결된 보고서 전달:** 인계자와 인수자가 같은 확정본, 전달 의견, 확인 기록을 열람한다.
- **대화형 업무 탐색:** 자연어 답변을 생성되는 대로 표시하고, 답변 근거와 참고자료를 확인할 수 있다.
- **업무 연속성 지원:** 이전 인수 완료 보고서를 기준으로 기존 업무를 현행화하고 새 업무를 추가한다.
- **복합 사례 검증 자료:** 5개 사업·21개 원본·사업 보고서 표 95개의 합성 샘플과 완성 보고서 예시를 제공한다.

v1.6.7 개발 당시 자동 검사 **105개**가 통과했다. 샘플1에서 실제 Solar 응답의 PDF 줄바꿈 인용 오류를 재현·수정했으며, 실패한 작업을 재개해 초안 생성 완료를 확인했다. 당시 복구 작업은 이전 보고서 계승 옵션이 꺼진 사례였다. 이 기록은 합성 사례의 기능 검증이며, 실기관 도입 성과나 일반 문서 전체의 정확도 수치가 아니다. [관련 수정 기록](../v167-pdf-citation-recovery.md)

### 향후 확인할 기대 효과

보고서 작성 부담 완화, 후임자의 업무 파악 시간 단축, 반복 문의 감소, 누락 방지와 업무 연속성 향상을 기대한다. **실기관 활용에 따른 절감률·만족도·도입 규모는 아직 제시하지 않는다.**

| 측정 지표 | 권장 측정 방법 |
|---|---|
| 보고서 작성 시간 | 자료 준비·AI 처리·담당자 검토·수정 시간을 나누어 기존 방식과 비교 |
| 인수인계 준비 기간 | 동일 업무 범위에서 준비 시작부터 전달 완료까지 측정 |
| 후임자의 업무 파악 시간 | 담당자·기한·첫 조치 등 동일 질문에 답을 찾는 시간 비교 |
| 반복 문의·누락 | 인수 후 일정 기간의 추가 문의와 누락·재수정 사례 집계 |
| 후임자 만족도 | 실제 사용 후 이해도·근거 확인 편의·활용성을 설문 |

## 현재 제공하는 기능

| 영역 | 구현 범위 |
|---|---|
| 자료 등록 | 파일·여러 파일·폴더·ZIP 등록, 같은 파일명의 서로 다른 판본 보존 |
| 문서 해석 | HWP 5.x/HWPX, 텍스트 PDF, DOCX, XLSX, TXT/MD의 지원 범위 내 본문·표 추출 |
| 판본 비교 | 본문 기준일·수정차수·수정시각·문서상태 비교, 불명확한 경우 선택 보류 |
| 업무 통합 | 자동으로 연결된 업무와 확인할 후보 표시, 여러 후보를 드래그해 묶기 |
| 검토와 수정 | 항목별 원문·주변 본문 확인, 수정 사유와 이전 값 보존 |
| 보고서 | 상단 간트·달성률·지연, 업무별 추진 흐름·현안·추후 계획, 예산·연락망 |
| 보고서 읽기 | 왼쪽 트리 목차, 보고서 내부 스크롤, 원문 기록 팝업, HTML·MD·DOCX 출력과 인쇄/PDF 저장 |
| 챗봇 | 확정값 우선 자연어 답변, 후속 질문 문맥, 스트리밍 출력, 인용 근거 확인 |
| 그림 후처리 | 사용자 선택 시 최신본으로 채택된 문서의 삽입 래스터 그림만 추가 판독 |
| 인계·인수 | 직원 1~4 시연 역할, 인수·인계함 분리, 의견과 확정본 전달, 인수 확인·완료 목록 |

문서의 **확정**과 업무의 **완료**는 다르다. 진행 중이거나 지연된 업무도 현황과 후속 조치를 기록해 인계한다. 진행률은 원문에 명시된 값이며 경과 시간으로 추정하지 않는다. 예산은 동일 코드 중복을 제거하고 기준일·금액에 문제가 있으면 전체 합계를 보류한다.

## 사용자 시작 순서

1. [업무바통](https://www.minslab.kr/handover/)에 접속하고 운영자가 제공한 접속 코드를 입력한다. 오른쪽 위에서 시연할 직원을 선택한다.
2. ‘새 인수인계’에서 받을 직원을 정하고 자료를 등록하거나, ‘시연 및 샘플 데이터 다운’에서 샘플을 실행한다.
3. ‘초안 생성’에서 추출 방식을 선택한다. AI 모드는 자료 전송 동의가 필요하다. 그림 분석은 별도의 수동 선택이며 시연 메뉴를 누르는 것만으로 실행되지 않는다.
4. 이전 업무를 이어갈 때 ‘이전에 인수한 보고서 이어서 작성’을 체크하고 인수 완료된 기준 보고서를 선택한다.
5. ‘업무 전체 보고 묶기’에서 후보를 정리하고, 항목 옆 연필에서 근거·값·변경 사유를 확인한다.
6. ‘검토 완료 · 확정하기’에서 남은 주의사항까지 확인하고 최종본을 확정한다.
7. ‘인계하기’에서 의견과 받을 직원을 확인하고 최종본을 전달한다.
8. 인수 직원으로 전환해 인수함을 연다. 보고서 목차·차트·원문과 오른쪽 챗봇으로 내용을 확인한 뒤 ‘인수 확인’을 누른다.

### 보고서 챗봇 질문 예시

- “기한이 지났거나 임박한 업무와 먼저 처리할 이유를 알려줘.”
- “보조금 정산은 누구에게 연락하고 무엇을 확인해야 해?”
- “인수 직후 해야 할 일 세 가지와 필요한 증빙을 알려줘.”
- “지역생활서비스 통합지원이 80%에서 65%로 정정된 이유는?”
- “공통 예산의 기준일과 중복 합산 시 주의할 점은?”

AI 질의에는 전송 동의가 필요하다. ‘키워드 검색 · 외부 전송 없음’도 선택할 수 있다. 답변의 근거와 보고서 기준일을 함께 확인하며, 기록 이후의 실제 진행 상황까지 자동 조회하는 서비스는 아니다.

## 샘플1로 전체 흐름 체험하기

[샘플1 ZIP](../../release/public/comprehensive-kit.zip) · [점검 안내](../../release/public/comprehensive-guide.md) · [완성 보고서](../../release/public/comprehensive-report.html) · [기능 검증 결과](../../release/public/comprehensive-validation.json)

샘플1은 이전 원본 **2개**와 현행 자료 **19개**, 총 **21개**다. HWPX 9개·XLSX 6개·텍스트 PDF 6개이며, 사업 보고서 19개에 각 5개씩 총 **95개 표**를 넣었다. 기관·인물·연락처·실적은 합성 자료다.

| 사업 | 정리 후 진척 | 주요 확인 사항 |
|---|---:|---|
| 지역생활서비스 통합지원 | 65% | 구판 80%·미승인 초안 100% 제외, 이전 20% 현행화 |
| 문화시설 통합예약 개선 | 75% | 세 별칭의 동일 범위·담당 확인 후 묶기 |
| 보조금 정산 승인 | 40% | 같은 날짜의 수정차수 비교, 누락 영수증과 승인 지연 |
| 공공시설 안전점검 | 100% | 이전 완료 기록 유지, 예산 기준일 대조 |
| 공공데이터 개방 품질개선 | 60% | 같은 날짜·차수의 수정시각 비교, 검토중·폐기본 제외 |

- 직원2 → 직원3으로 실행하고 **‘이전에 인수한 보고서 이어서 작성’**을 선택한다. 후보 7개를 묶어 5개 사업으로 정리한다. 계승을 선택하지 않으면 안전점검이 빠져 후보 6개 → 사업 4개가 된다.
- `memo.pdf`는 **자료 등록 → 본문 보기**에서 먼저 확인한 뒤 묶기 팝업을 연다.
- `q77.xlsx`도 **자료 등록 → 본문 보기**에서 예산을 먼저 대조한다. 안전점검 예산의 기준일만 `2026-01-08`에서 `2026-11-08`로 수정하고 사유를 남긴다. 실제 완료일은 수정하지 않는다.
- 대조 후 예산코드 6개의 합계는 편성 **4억 원**, 집행 **2억 5,900만 원**, 지급예정 **4,500만 원**, 가용 **9,600만 원**이다. 공통 예산은 한 번만 포함한다.
- 완성 예시는 기대 결과를 확인하는 자료다. Solar가 생성한 새 초안도 담당자 검토를 거쳐야 하며, 답변·항목이 매번 동일하다고 보장하지 않는다.

샘플2는 4개 업무의 단계별 보고, 샘플3은 파일명·판본 혼선, 샘플4는 이전 보고서 계승을 체험한다. 전체 KIT에는 설명·정답·내부 ZIP이 포함되므로 전체 KIT 자체를 업무자료로 등록하지 않는다. 내부 단계 ZIP의 등록 순서는 점검 안내를 따른다.

## 지원 범위와 적용 시 유의점

- 본문과 단순 표를 우선 지원한다. 스캔 OCR, HWP 3.x, 암호화·매크로 문서, 복잡한 서식 완전 재현, 벡터 도형·수식 해석은 지원 범위 밖이다. 부분 추출·미검토 표시는 사람이 확인한다.
- 삽입 그림 판독은 선택 기능이다. 전체 페이지를 OCR하거나 그림만으로 최신본을 판정하지 않는다. 판독 결과는 참고이며 확정 진행률·기한을 자동 변경하지 않는다.
- AI가 원문의 인용을 선택하고 서버가 실제 구간과 대조한다. 원문 일치 검증은 의미 정확성이나 누락 없음까지 보증하지 않는다. 미기재·미확인 사항은 확정 후에도 남을 수 있다.
- 직원 선택과 공유 접속 코드는 **시연용**이다. 직원별 화면·사건 범위 검사는 있으나 기관 인증, 검증된 개인별 권한, 전자서명·전자결재를 대신하지 않는다.
- 외부 AI 전송은 공개·합성 자료를 전제로 한다. 실기관 자료 적용에는 해당 기관의 보안·개인정보·모델 사용 기준과 운영 통제가 필요하다.
- 자연어 챗봇은 구현돼 있으나 문서 검색 기반은 로컬 키워드 방식이다. 임베딩·벡터 검색이나 minirag MCP를 구현한 것으로 설명하지 않는다.
- 현재 PoC는 업무바통 독립 앱이다. 초기 검토 주제였던 독립 문서 전환 MCP 3종이나 AIWorks Hub 확장판을 구현한 프로젝트가 아니다.
- 파일 생성 결과는 HTML·MD·DOCX 및 인쇄/PDF다. 자유 양식 HWPX 보고서 생성, ERP·SSO·기관 전자결재 연동은 별도 확장 대상이다.
