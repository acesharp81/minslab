# 췤미! — 체크 이미지 · PoC 11

대외 홍보물의 이미지·표현을 원문 **25개 항목 / 156개 세부 행동**으로 점검하는 검수 지원 서비스입니다. 자동 결과는 최종 공개 승인과 별개입니다.

서비스: **https://minslab.kr/imgscan** (대표 도메인 `www.minslab.kr`로 연결)
홈페이지: PoC 목록 → **11 · 췤미! · AI 이미지 품질검수**

## 독립 실행

Python 3.12 이상에서 **이 폴더만 복사하여** 실행합니다. 부모 저장소·PoC7 코드·공용 가상환경을 참조하지 않습니다.

```bash
cd 11-image-inspection
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/bootstrap.py
# .env에 키와 로그인 설정 입력
bash scripts/run.sh
```

기본 주소는 `http://127.0.0.1:18110`입니다. Windows는 `.venv\Scripts\python.exe scripts\serve.py`로 실행합니다. Docker는 `bootstrap.py`로 `.env`를 만든 뒤 `docker compose up -d --build`를 사용합니다. Docker에서 중앙 서비스 주소는 해당 컨테이너에서 접근 가능한 주소로 바꾸세요. 호스트 loopback은 컨테이너의 loopback과 다릅니다.

- `.env`: 실제 API 키·검토자/관리자 비밀번호·공용 사용량 인증. Git과 Docker 빌드·소스 ZIP에서 제외. 초기 생성 시 권한 0600.
- `.env.example`: 키 없는 공유용 설정 예시.
- `scripts/bootstrap.py`: 키나 기존 설정을 덮어쓰지 않고 빈 로그인 비밀번호와 세션 비밀만 생성.
- 운영 서비스: `poc11.service`, 포트 `127.0.0.1:18110`. 공용 서버는 `/poc/image-inspection/`로 프록시하고 `/imgscan`을 연결.
- 운영 MinsLab 관리자 세션은 서버 서명으로 연동됩니다. 독립 실행은 `.env`의 `ADMIN_PASSWORD` / `REVIEWER_PASSWORD`로 로그인합니다.

## API 키와 두 단계 모델 선택

```dotenv
OPENAI_API_KEY=입력
UPSTAGE_API_KEY=입력
OPENROUTER_API_KEY=선택_무료_이미지_모델용
```

| 단계 | 선택 모델 | 역할 |
|---|---|---|
| 그림 읽기 | GPT-5.4 / GPT-5.4 mini / GPT-6.1 Sol / GPT-6 Astra / OpenRouter Nemotron 3.5 Super VL 무료 | 원본+위치 격자로 객체·문자 품질을 읽고 한도 내 확대 재검사 |
| 분석 | Solar Pro 4 / GPT-5.4 / GPT-5.4 mini / GPT-6.1 Sol / GPT-6 Astra | 저장된 관찰로 규칙별 검토 |

기본값은 **GPT-5.4 이미지 읽기 + GPT-5.4 mini 분석**입니다. Solar Pro 4는 이미지 입력을 받지 않습니다. 두 번째 단계는 원본 이미지를 재전송하지 않고 관찰 근거를 재사용합니다. 분석 모델은 저장된 객체 ID만 인용하며 새 관찰·좌표를 만들 수 없습니다. 검수 이력에서 분석 모델을 바꾸고 `이미지 재사용 · 원문 전체 재분석`을 누르면 새 버전이 생성됩니다. 이전 결과·사람 검토는 보존됩니다. 구버전 관찰도 재사용할 수 있지만 원래의 누락·오독은 그대로 남습니다.

실행모드 선택은 없습니다. `그림 + 분석 실행`은 실제 AI 검사이며, 새 이미지·모델 조합의 최초 실행 시 전송 확인창에서 동의한 경우에만 외부 API를 호출합니다. 동의는 현재 화면 세션에서만 유지됩니다. `EXTERNAL_API_ENABLED=false`는 서버 전체 외부 전송 차단입니다. 키가 없어도 합성 샘플·mock·검토·보고서를 사용할 수 있습니다. 임의 업로드에 mock을 적용하면 실제 판정 대신 REVIEW만 반환합니다.

실행 중 `.env`를 변경했다면 서비스 재시작이 필요합니다.

## 검수 흐름

1. 로그인 → 왼쪽 첨부 영역에서 이미지 선택. 해당 영역이 즉시 미리보기로 바뀝니다. 제목·표현 의도를 입력하고 필요한 경우 상세 정보에서 부서·배포일·유형을 입력합니다.
2. 그림 읽기/분석 모델 선택 → `그림 + 분석 실행`. 이미지 등록과 전체 검사를 한 번에 진행합니다.
3. 스캔 진행 표시와 세부 행동 완료 수 확인. **원문별로 묶은 텍스트 분석 요청이 완료될 때마다** 결과가 나타납니다.
4. 왼쪽 발견 사항 또는 원형 번호 선택 → 관찰·이유·인용 자료·셀·모델 확인.
5. 한 객체 또는 근접한 위치에 번호 하나를 표시하고 규칙별 검토 의견을 묶습니다. 선택한 위치의 탐색 범위만 테두리로 표시합니다. 증빙·최종 판단 확인은 위치 번호에서 분리합니다. 격자는 기본 숨김입니다.
6. 오른쪽 부모 항목 선택 또는 세부 행동 선택 → 부분 재검사. 번호 영역은 주변 1셀까지 포함해 확대 재검사 가능.
7. 사람 판정·사유 저장 → JSON 전체 이력 보고서 또는 화면 인쇄/PDF.

`PASS / FAIL / REVIEW / NOT_APPLICABLE / ERROR / NOT_RUN`을 구별합니다. ERROR나 미실행 항목이 있으면 완료된 항목으로 표시하지 않습니다. 자동 FAIL도 사람 확인 전에는 오류 의심입니다. 공개 승인 기능은 없습니다.

## 비용과 격자 경계 대책

- 이미지 관찰 1회 + 자동 확대 재검사 최대 3회(객체 최대 9개) + 텍스트 규칙 분석입니다. 분석은 최대 두 묶음을 동시에 처리합니다. 원문 항목을 쪼개지 않고 묶음당 최대 40개 세부 행동·6개 원문 항목, 객체 7개 이상이면 24개 행동으로 제한하며, 다른 원문 항목끼리 판정 의견을 공유하지 못하도록 응답을 검증합니다. 재분석은 이미지 호출 0회입니다.
- `low` 추론, 최대 1536px 기본 판독, 분석 단계에 저장된 관찰만 전달. 같은 부모 안에서 판정·관찰·이유가 같은 행동은 한 응답에 묶고 서버에서 세부 행동별 이력으로 풀어 저장합니다.
- 이미지 해시·메타데이터·규칙·기준자료·모델 설정이 같은 결과는 캐시 재사용(API 0회). 사람이 수정한 판정은 재사용하지 않습니다.
- 선택 규칙만 재검사. Astra 자동 승격·타임아웃 자동 재호출은 하지 않습니다. 같은 객체의 여러 결과는 한 번호의 상세 의견으로 보존합니다.
- 깨끗한 전체 원본만 보냅니다. 가상 12×12 등분 셀 ID로 대략적인 위치를 받고, 격자선이 문자·도안을 가리지 않게 합니다. 처음부터 격자별로 잘라 보내지 않습니다.
- 확대 시 사방 1셀의 문맥을 추가하고 원본 전체도 함께 보냅니다. 확대에는 8×8 격자를 쓰며 서버가 원본 좌표로 변환합니다. 확대 결과는 전체 결과를 대체하지 않는 보충 증거입니다.
- 모델의 공간 인식·객체 누락은 여전히 오류 가능성이 있습니다. 원형 번호는 검증된 격자 근거를 표시하며 정밀 객체 좌표를 의미하지 않습니다.

## PoC7 공용 사용량과 예산

두 연결은 별개입니다.

1. **중앙 집계**: 기존 PoC7 게이트웨이 `USAGE_GATEWAY_URL/internal/usage-events`에 `USAGE_METER_TOKEN` 인증으로 OpenAI/Solar/OpenRouter 호출을 전송합니다. 고유 event_id와 로컬 outbox로 중복·장애를 처리합니다. 중앙 일별 집계는 수신일 UTC 기준, 실제 발생 시각은 PoC11에도 저장합니다.
2. **OpenAI 공용 예산**: `SHARED_BUDGET_DATABASE_URL`의 기존 `openai_credit_grant_usage`와 **동일 grant**에서 원자적 예약·정산합니다. PoC7의 무료 mini/main 배정에서 차감하지 않습니다. `poc11_credit_reservations`는 중복 정산 방지용입니다. 월말 갱신 정책도 PoC7의 명시된 설정을 복사해 같은 규칙을 사용합니다.

현재 서버의 일회성 연결 설정:

```bash
.venv/bin/python scripts/connect_poc7.py /절대경로/07-NationalAssembly/.env --initialize
```

이 명령은 키를 출력하지 않고 연결 설정만 로컬 `.env`에 복사합니다. 기본 모델 API 키는 복사하지 않습니다. PoC7 소스나 수집기를 수정·재시작하지 않습니다. DB 주소가 변경되거나 PoC7 예산 정책이 바뀌면 다시 실행하세요. 다른 서버는 접근 가능한 DB/게이트웨이 URL과 인증을 직접 설정할 수 있습니다.

실제 API 실행은 기본적으로 중앙 집계와 공용 예산 연결을 요구합니다. 외부 공유자가 완전한 독립 환경에서 자체 비용으로 사용하려면 의미를 이해한 후 `USAGE_REQUIRE_SHARED=false`, `SHARED_BUDGET_REQUIRED=false`로 설정할 수 있습니다. 현재 운영 설정은 둘 다 true입니다. 중앙 사용량 연동이 없는 mock은 그대로 실행됩니다.

공용 사용량 화면은 PoC11 단계별 호출·토큰·보수적 비용 추정치, 전송 대기, PoC7과 공유하는 크레딧 잔여를 보여줍니다. Solar는 중앙 보고 대상이며 OpenAI 크레딧과 합산 차감하지 않습니다. 공급자 청구서·조직 전체 잔액 API로 오인하지 마세요.

## 기준자료와 데이터

관리자가 출처 URL·발행기관·발췌·버전·적용 규칙·유효기간을 등록합니다. 공식 상징/지도/문양의 경우 실제 기준 이미지 첨부 후 승인해야 합니다. 승인된 자료만 검사에 전달되고 실행 시점의 스냅샷을 보존합니다. 공식 자료는 임의로 승인하지 않습니다.

`data/`에 EXIF를 제거한 정규화 이미지, 이미지 해시, SQLite 결과/검토/사용량을 저장합니다. 원본 업로드 바이트는 영구 저장하지 않습니다. 문서·영상은 현재 입력 범위 밖입니다. 로그인은 공동 검토실의 관리자/검토자 역할이며 개인별 자료 격리를 제공하지 않습니다.

관리자만 검사 자료를 삭제할 수 있습니다. 보관 정책 확인 후 `scripts/cleanup.py`의 dry-run을 검토하고 `--apply`합니다. 진행 중 작업과 비용 원장은 삭제하지 않습니다. 실제 키·업로드·DB는 공유하지 마세요.

### 상단 모델별 잔여량

화면 상단에 PoC7 공용 잔여 예산과 무료 잔여 요청 횟수를 간결하게 표시합니다. 로그인 후 30초 간격 및 검사 완료 시 갱신합니다. GPT-5.4는 PoC7 main 공용 일 100만, mini는 mini 공용 일 1,000만 입력+출력 토큰의 잔여량을 각각 표시합니다. 예약·미확정 사용량도 차감하며 UTC 자정(한국시간 09시)에 갱신합니다. GPT 6.0·6.1은 공용 비용 예산 카드로 표시합니다. OpenRouter는 `/api/v1/key`의 `free_model_daily_requests` 값을 사용하고, 값이 없으면 추정하지 않습니다. Solar는 사용량만 집계하며 공급자 잔액 미연동 상태를 `잔여량 미확인`으로 표시합니다. 조회 실패는 `확인 불가`, 확인된 0은 `소진`으로 구별합니다. 카드 선택 시 공용 사용량 화면으로 이동합니다.

## GPT-5.4 무료 토큰과 OpenRouter

이 배포의 GPT-5.4 한도는 사용자가 지정한 일 1,000,000 토큰이며 PoC7의 `openai_group_daily_usage` 중 `main` 원장을 직접 공유합니다. 입력+출력, 진행 중 예약, 사용량 미확정을 합산합니다. 한국시간 09시 초기화되며 한도 초과는 호출 전 차단합니다. GPT 6.0·6.1의 크레딧 예산과는 별도입니다. 이는 로컬 사용량 통제이며 공급자의 청구서나 데이터 공유 설정을 변경하지 않습니다.

OpenRouter 무료 모델은 전용 키가 필요하며, 현재는 이미지/구조화 응답을 확인한 `nvidia/nemotron-3.5-super-vl:free`를 제공합니다. 유료 대체 모델로 자동 전환하지 않습니다. 통상 무료 요청은 분당 20회, 하루 50회(누적 구매 조건 충족 시 1,000회)이며 계정 공용입니다. NVIDIA 무료 엔드포인트는 입력을 제품 개선에 사용할 수 있으므로 기밀·개인정보에 사용하지 않습니다.

- [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4)

## 4괘 구조 비교와 검증 범위
`app/taegeukgi.py`는 원본의 적·청 원형 중심 후보 주변에서 세 줄의 실제 연결 성분, 평행성, 길이, 간격, 중간 끊김을 측정합니다. 세 임계값 중 두 개 이상에서 읽힌 괘가 일치해야 합니다. 내장 기준 출처는 [구리시 국기의 제작](https://www.guri.go.kr/www/contents.do?key=461)의 괘의 작도(확인 2026-10-29)입니다. 관리자 기준자료를 임의로 승인한 것으로 기록하지 않으며, `technical_reference`로 구분합니다.

이 측정은 H-04의 보조 근거입니다. H-04-h/i도 선택한 분석 모델이 원문 질문·전체 이미지 문맥과 함께 평가하며, 로컬 측정으로 AI 분석을 대체하거나 다른 국가상징의 적합성을 확정하지 않습니다. 서버가 계산한 객체 영역을 사용하므로 격자 경계에 따라 괘가 잘리지 않습니다. 보조 측정 자체는 API·토큰을 사용하지 않습니다. 원문 분석에는 선택한 모델의 호출·토큰이 사용됩니다. 관찰을 재사용하는 검사에서도 원본을 로컬 비교합니다. 네 보기 실물에서 02는 건/감/리/곤 배치 일치, 01·03·04는 배치 불일치가 확인되었습니다. 퀴즈 오답일 가능성은 별도 문맥 검토입니다. 평면·정면 인쇄 도안에 한정하며 휘날림·원근·가림·거울상·작은 도안 등 일반 이미지의 정확도를 보장하지 않습니다. 미검출은 정상이 아닙니다. 색도·태극 곡선·치수의 전체 적합성은 미검사입니다.

일반 REVIEW는 추가 확인 목록에 표시하고, 구체적 시각 결함만 번호를 표시합니다. 모서리별 원본 확대/읽은 괘/공식 기준은 원문 H-04 결과 안의 접힌 보조 근거에서 확인합니다.

## OpenRouter 공용 요청 한도
배포 환경은 `OPENROUTER_GATEWAY_URL=http://127.0.0.1:18071`, `OPENROUTER_REQUIRE_SHARED=true`로 PoC7 중앙 예약·동시 호출 제한을 공유합니다. PoC11 이미지는 사용자 동의와 meter 인증을 요구하며 승인된 무료 VL 모델 하나로 고정합니다. 유료·텍스트 모델로 대체하지 않습니다. 공식 한도는 1,000회/일, 기존 PoC7 운영 한도는 950회/일(50회 안전 여유), UTC 자정(한국시간 09시) 초기화입니다. 잔여량은 공급자 공식 잔여와 중앙 운영 잔여 중 작은 값입니다. 공용 게이트웨이가 없으면 호출을 막습니다. 독립 설치에서 직접 호출을 원할 때만 `OPENROUTER_REQUIRE_SHARED=false` 및 빈 gateway URL을 명시하세요.

실제 공용 무료 모델 연결 확인: 합성 샘플 1회, 입력 1,370 / 출력 1,041 토큰, 비용 $0, PoC7 공용 운영 잔여 884→883회. 일반 검수의 target_presence(대상 있음/없음/미확정)를 상태보다 먼저 판정하여 대상 부재가 REVIEW로 증가하지 않게 합니다.

모델은 각 세부 규칙에 근거·판정·조치를 개별 작성하며, 서버에서 규칙별 근거·정책을 검증합니다. 화면에서는 같은 객체의 의견을 번호 하나로 모읍니다. 이전 형식의 같은 규칙/객체 중복은 병합하고 상충 의견은 REVIEW로 보존합니다.

응답 누락 방지: 분석 API는 `assessments` 객체에 모든 요청 rule_id를 필수 키로 반환하며, 값에는 각 규칙의 판정·적용성·근거·이유·조치가 들어갑니다. 동일 의견 하나를 여러 규칙에 배정하는 응답 최적화는 실제 판단이 섞이는 문제로 제거했습니다. 묶음 요청·이미지 관찰 재사용·같은 스키마 재사용으로 비용을 줄입니다.

## 원문 체크리스트 전체 분석 결과
이미지 읽기와 분석 단계에 원문 25개 질문을 전달합니다. 결과 첫 화면에는 25개 원문별 관찰 근거·분석 의견·확인 사항·사용 모델·인용 자료·세부 규칙을 표시합니다. 로컬 보조 측정과 AI 원문 판정을 구분하며, 실행 오류·미실행은 분석 완료로 세지 않습니다. JSON 보고서에도 동일한 `checklist_report`가 포함됩니다.

**이미지 재사용 · 원문 전체 재분석**은 이전 실행이 부분 검사였어도 156개 전체를 새로 평가합니다. 선택 항목 재검사와 확대 재검사는 지정한 범위에만 적용합니다. 부분 검사의 결과에는 이번 실행 범위를 표시하고 나머지 기존 결과가 포함됨을 알립니다. 이전에 로컬 측정만으로 처리한 규칙은 새 전체 분석 전까지 원문 판정 미완료로 표시합니다.

## 통합 작업 화면
왼쪽은 첨부와 미리보기를 겸하는 하나의 이미지 영역이며, 오른쪽 상단에 정보·모델·실행 버튼, 하단에 결과가 있습니다. `원문별 결과`·`위치별 확인`·`선택 재검사`를 전환하며 이미지 위치와 분석 의견을 함께 봅니다. 원문 전체를 큰 카드 벽으로 펼치지 않고 간결한 행에서 상세 내용을 열 수 있습니다.

직접 측정된 4괘 배치 차이는 원문 AI 판정이 REVIEW여도 위치 번호로 확인합니다. 번호 하나에 해당 객체의 측정과 관련 원문 의견을 모으며, 측정 차이가 곧 제작 오류나 공개 불가를 뜻하지 않습니다. 퀴즈 의도 판단과 측정 결과를 구분합니다.

### 위치 색상과 불명확한 좌표
원본에서 측정한 괘 불일치는 빨강, 측정 미확정은 노랑, 일치는 정상 영역 옵션을 켰을 때 파랑으로 표시합니다. 원문 AI의 제작 의도/권리 검토 상태와 측정 상태는 별개입니다. 비교표에서도 같은 색 기준을 사용합니다.

하나의 관찰에 서로 떨어진 셀이 연결돼 있으면 그 사이의 중간점을 오류 위치로 찍지 않습니다. 해당 의견을 `위치 확인 필요`로 남기고 원본 확대 확인을 안내합니다. 연결된 위치의 번호는 실제 근거 셀 안에 놓으며, 이미지 읽기 지침은 서로 다른 카드·문장 블록을 별도 관찰로 수집하도록 지정합니다. 기존 결과를 표시하기 위해 추가 API를 호출하지 않습니다.

좌표 미확정은 발견 내용의 삭제나 판정 변경 사유가 아닙니다. 해당 발견에도 번호를 부여하고 결과 상단에 원래 의견을 표시합니다. 떨어진 위치 후보가 있는 경우 이미지 오른쪽 가장자리의 번호로 연결합니다. 가상 셀은 실제 글자 경계가 아니므로 사각형으로 표시하지 않습니다. 직접 픽셀로 측정한 구조 영역에만 사각형을 표시합니다. 번호는 정확한 오자 좌표가 아닌 의견을 여는 버튼입니다. 한 객체의 여러 의견은 하나의 번호로 묶습니다. 원문별 요약은 오류 의심 의견부터 보여 줍니다.

### 잘못된 관찰 좌표의 처리
이미지 읽기 응답 스키마는 전체 12×12, 확대 8×8의 유효한 셀만 허용합니다. 공급자가 범위 밖 셀을 반환해도 해당 셀만 제외하고 OCR·객체 관찰과 나머지 25개 원문 분석을 유지합니다. 제외 기록은 `observation.location_warnings`에 보존합니다.

공용 원장 연결 시 `scripts/connect_poc7.py --initialize`가 PoC11 토큰 예약 이력 테이블을 추가합니다. 다른 PoC 소스는 실행 시 참조하지 않습니다.

번호는 고정 크기에 상태별 진한 배경, 대비되는 숫자, 흰색·짙은색 이중 테두리를 사용합니다. 선택 시 크기를 확대하지 않습니다.

## 이미지 영역 선택·문자 품질·규칙 작성 안내

번호가 없는 이미지 영역도 저장된 근거 위치와 연결되어 있으면 선택할 수 있습니다. 해당 분석이 하나면 상세를 열고, 여러 개면 선택 팝업을 엽니다. 떨어진 두 위치 사이의 빈 공간은 클릭 대상으로 합치지 않습니다. 위치가 없는 문서/권리 검토 항목은 원문별 결과에서 확인합니다.

문자 품질 민감도는 `표준`/`엄격`이며 기본은 엄격입니다. 새 그림 읽기에서 전사 문자열과 `text_legibility`, `legibility_evidence`, `transcription_inferred`를 구분해 기록합니다. 읽을 수 있어도 실제 획 번짐·손상은 별도 검토합니다. 이는 모델에 전달하는 검사 지침이며 정확도를 보장하는 결정적 픽셀 임계값이 아닙니다. 분석만 재실행하면 기존 이미지 인식과 당시 민감도를 재사용합니다. 새로운 문자 품질 기록은 `그림+분석` 실행으로 얻습니다.

검수 규칙 관리의 `다른 AI에 전달할 내용 복사`는 작성 형식 안내, 현재 25개 부모/156개 세부 규칙 전체, 편집 중 초안을 함께 복사합니다. 임의 구조의 v2.0 문서는 이 형식으로 변환한 후 형식 검사·저장합니다. 변환 안내는 [rule-authoring-guide.md](docs/rule-authoring-guide.md)에 있습니다. 잘못된 입력은 편집기에 보존하고 저장 규칙은 변경하지 않습니다.

공식 공통 기준 11건(다행이·부리부리 별도)의 출처·2회 이상 검증·재등록 방법은 [기준자료 기록](docs/reference-library-2026-10-29.md)을 확인하세요.

### 잔량 버튼의 게이지

잔량 버튼은 남은 비율만큼 왼쪽부터 배경이 채워지며 수치와 백분율을 함께 표시합니다. GPT 6.0·6.1은 PoC7과 동일한 `openai_credit_grant_usage`를 예약·정산합니다. 월 기준은 $100, 갱신은 매월 말일 한국시간 00시입니다. 현재 최초 주기에 이미 확인된 시작 잔액 $8은 그대로 차감하고 $100은 게이지의 월 기준으로만 사용합니다. 다음 주기부터 $100이 배정됩니다. 기존 사용 기록을 초기화하지 않습니다. GPT-5.4는 별도 일 100만 토큰 원장을 공유합니다.

무료 이미지 모델 카드는 `Nemotron 3.5 Super VL`로 표시하며, OpenRouter 공용 요청 한도의 운영 여유 50회는 기존대로 유지합니다. 잔량 미확인은 0%로 표시하지 않습니다.

엄격 문자 검사에서는 작은 표지를 첫 판독의 CLEAR 여부와 무관하게 재검사 후보로 넣습니다. 문자·지도·기관 문양·손·상징에 검사 순서를 분산하고, 정상 설명만으로 우선순위를 높이지 않습니다. 자동 확대는 최대 9개/3회이며 미확인은 미확인으로 남습니다. 첫 전사 문자열을 객체 이름에서도 제거하며 이미지마다 대상/격자/기준자료 역할을 표시합니다. 문자 대상에서 빈 전사를 반환한 재검사는 완전 판독으로 인정하지 않습니다. 위치가 불확실한 오류는 다른 물체 위에 번호를 이동시키지 않고 이미지 밖 목록에서 보여 줍니다.


## 독립 한국어 OCR (2026-10-30)

기존 기본 모델 선택은 그림 읽기 GPT-5.4 + 분석 GPT-5.4 mini입니다. 별도 OCR 환경을 `bash scripts/setup_ocr.sh`로 설치하고 `.env`의 `OCR_ENABLED=true`를 설정하면 원본 문자 crop과 독립 PaddleOCR 판독을 대조합니다. 기존 분석만 재실행하면 저장된 OCR도 재사용합니다. 새로운 OCR 검사는 그림+분석으로 실행하세요.

NAVER 보조 OCR은 `.env`에 `NAVER_OCR_API_KEY`와 콘솔의 **APIGW Invoke URL**을 `NAVER_OCR_API_URL`로 설정합니다. 월 한도는 **API 호출 100회**, 한국시간 **매월 1일 00:00 초기화**이며 사용량 화면에서 잔량·이력을 봅니다. 키·API 전용 주소·이미지·OCR 실행 결과는 Git/공유 ZIP에 넣지 않습니다.

[OCR 구조·엔진 비교·전송 해상도·비용·한계](docs/ocr-architecture-2026-10-30.md)를 참고하세요. OCR이 정상 문구를 읽었어도 원본 글자 모양이 정상이라는 뜻은 아닙니다.
