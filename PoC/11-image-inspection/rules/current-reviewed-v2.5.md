# 췤미! 검수 규칙

# 공통 검수 지침

> **버전:** v2.5 · LLM 실행형 · 기존 파서 호환. 본 절은 모든 이미지에 적용하며, 아래 25개 상위 규칙과 156개 하위 규칙의 명칭·ID·순서는 변경하지 않는다. 규칙의 목적은 홍보물의 실제 결함을 찾아 담당자의 수정·판단을 돕는 것이다. 확인하지 못한 것을 확인했다고 표현하지 않으며, 근거 없는 우려만으로 사용자 검토를 남발하지 않는다.

**A. 반드시 지킬 판단 순서**

1. 먼저 전체 이미지에서 검사 대상을 찾아 목록화한다. 텍스트, 인물과 각 손, 태극기, 지도, 로고, 제복·표식, 동물, 도표·숫자, 특정 표현, 얼굴·차량번호 등 식별정보를 탐색한다. 작은 각주·간판·배경의 객체도 2차로 살핀다.
2. 발견된 객체마다 `TEXT-001`, `HAND-001`, `FLAG-001` 등 고유 ID를 부여한다. 같은 종류가 여러 개이면 **각각** 검사한다. 규칙 적용 여부는 대상 확인 후 결정한다.
3. 적용 대상이 없고 객체 의존 규칙이라면 `NOT_APPLICABLE`이다. 예: 그림에 태극기가 없으면 괘·태극 문양 검사는 비적용. 다만 금지 표현의 존재 여부처럼 이미지 전체를 검색하는 규칙은 스캔 후 문제 없으면 `PASS` 가능하다.
4. 실제로 관찰되고 기준과 비교 가능한 사항부터 판정한다. 정상 근거가 있으면 `PASS`, 분명한 시각 오류 또는 승인 정본과의 불일치가 있으면 `FAIL`이다. 확실하지 않은 결함을 만들어내지 않는다.
5. 모호한 대상은 곧바로 `REVIEW`로 넘기지 않는다. 원본 확대·crop, OCR 재인식, 승인된 참고 도안 대조 등 유효한 재검사를 수행한 뒤에도 해결되지 않는 **특정 객체·세부 항목**만 `REVIEW`로 둔다. 재검사할 수 없는 이유와 필요한 후속 조치를 적는다.
6. 이미지 밖의 사실관계(법령, 최신 정책, 역사적 사실, 이용허락, 초상권 동의)는 관련 주장·소재가 실제 있는 경우만 근거자료와 확인한다. 외부 증빙이 없음을 시각 오류로 처리하지 않는다. 검증한 사실과 미검증 주장을 분리한다.
7. 모든 결과에 `무엇을 보았는가 → 어떤 기준과 비교했는가 → 무엇이 다른가/정상인가 → 어디인가 → 후속 조치`를 간결하게 기록한다. 이미지에 없는 사실이나 출처를 만들어내지 않는다.

**B. 결과 코드와 화면 표시**

- `PASS`: 해당 대상과 검사 기준이 있고 관찰 가능한 범위를 검사한 결과 위반이 발견되지 않음. 확인한 객체는 정상 영역 옵션을 켜면 파란 위치 표시.
- `FAIL`: 실제 오류의 시각적 증거나 승인된 정본과의 구체적 불일치를 확인함. 문제 객체·부분에 빨간 위치 표시.
- `REVIEW`: 실제 검사 대상에서 구체적인 미해결 문제가 남았고 재검사 후에도 판단할 수 없음. 그 영역에 노란 위치 표시. 판단 불가 사유와 요청할 행동을 반드시 표시.
- `NOT_APPLICABLE`: 적용할 객체·조건이 없음. 박스 없음. `NOT_RUN`: 입력·도구 오류로 검사를 수행하지 못함. 박스 없음, 재시도 요청.
- 증빙 상태는 `evidence_status = NOT_REQUIRED | VERIFIED | REQUIRED | UNAVAILABLE`로 따로 저장한다. 라이선스 등 이미지에서 위치를 지목할 수 없는 증빙 요청은 설명 패널에 둔다.
- 객체별 결과를 보존한다. 같은 규칙에서 FAIL이 1개라도 있으면 상위 결과는 FAIL; 없고 REVIEW가 남으면 REVIEW; 적용 객체를 전부 검사했으면 PASS; 모두 비적용이면 NOT_APPLICABLE. 하위의 노란 쟁점을 상위 빨강으로 숨기지 않는다.

**C. 반드시 실행할 텍스트·오탈자·OCR 검사**

1. **문자 영역 발견:** 홍보물의 제목·본문·작은 각주·간판·말풍선·지도 지명·표/그래프 축·출처·버튼·로고 글자를 빠짐없이 찾는다. `TEXT-001` 등 식별자와 격자를 부여한다. OCR에서 아무 결과도 나오지 않았더라도 **문자처럼 보이는 영역은 검사 목록에서 제외하지 않는다.**
2. **원본 전사:** 1차 시각 모델 전사와 확대 원본을 독립 재판독한 문자열을 별도로 저장한다. 현재는 동일 시각 모델의 두 판독이며 독립 OCR 엔진을 실행했다고 표현하지 않는다. 글자를 임의 교정해 전사하지 않는다. 알 수 없는 획은 `[판독불가]`로 표시한다. 격자선이 글자를 가리지 않는 깨끗한 원본을 읽는다.
3. **누락·충돌 검사:** 탐지한 문자 구역 수와 전사한 구역 수를 대조한다. OCR 누락·인식 결과 불일치·뭉개진 구역은 주변을 포함한 crop과 깨끗한 확대 원본으로 재판독한다. 자동 한도 때문에 재검사하지 못한 구역은 미확인으로 남기고 선택 재검사를 안내한다.
4. **실제 오탈자:** 원본에서 오자·누락·중복·비정상 글리프·조사·띄어쓰기·특수문자·숫자·단위가 보이는지 확인한다. 제작자가 제공한 확정 원고, 공식 기관명·사업명, 동일 문서의 일관된 표기와 대조한다. 정본 없이 단정하기 어려운 고유명사와 브랜드명은 자동 수정하지 않는다.
5. **오류 종류 분리:** `TYPO_CONFIRMED`(원본에 분명히 잘못 표시됨→FAIL), `OCR_MISMATCH`(원본은 정상인데 인식기만 틀림→이미지 FAIL 아님), `OCR_UNREADABLE`(판독 미완료→재검사/남은 구역 REVIEW), `VISUAL_TEXT_DEFECT`(글자 자체가 깨지고 뭉개져 사람이 읽기 어려움→가독성 FAIL), `SOURCE_MISMATCH`(원고·정본과 실제 이미지 문구가 다름→확인 시 FAIL), `FACT_OR_STYLE_ISSUE`(사실/표현 해석의 별도 확인 필요)로 구분한다.
6. **인식 실패와 제작 오류를 혼동하지 않는다.** 읽을 수 없는 문구를 문맥으로 추측해 PASS 하지 않는다. OCR이 틀렸다는 이유만으로 원본을 FAIL 처리하지 않는다. 사람이 읽을 수 없을 만큼 흐릿한 실제 글자는 철자를 특정하지 못해도 `VISUAL_TEXT_DEFECT`로 FAIL 처리할 수 있다.
7. 모든 문자 구역에 상태를 부여한다. `detected_text_regions`, `transcribed_regions`, `unreadable_regions`, `ocr_disagreement_regions` 등을 기록해 OCR 누락 여부를 진단한다. **OCR이 읽지 못한 구역을 '문자 없음'으로 무마하지 않는다.**

**D. 판정 사례: 비슷한 상황에서는 같은 논리를 적용**

- **태극기:** 선명한 태극기의 태극 문양과 네 괘를 제공된 공식 도안과 비교하여 정상이면 부분별 PASS. 우상단 괘의 선분이 기준과 다르면 해당 괘 FAIL. 국기가 없으면 국기 세부 검사 비적용. 작은 괘가 가려졌으면 확대 재검사 후에도 보이지 않는 그 괘만 REVIEW. 휘날리거나 뒷면이 보인다는 이유만으로 오류 확정 금지.
- **손가락:** 손가락 6개가 각기 손바닥에 붙어 있는 것이 선명하면 FAIL. 주먹이나 가림 때문에 3개만 보이지만 비정상 구조가 없다면 5개 미만이 보인다는 이유로 FAIL 하지 않는다. 겹친 손이 확대 후에도 판별되지 않으면 해당 손만 REVIEW. 의도적인 4지 캐릭터는 디자인 기준을 고려한다.
- **오탈자:** 이미지에 `행정안정부`, 제공 정본에 `행정안전부`가 선명하게 확인되면 `TYPO_CONFIRMED`와 FAIL. 반대로 원본은 `신청 기간`인데 OCR만 `신청 기긴`이라면 `OCR_MISMATCH`, 홍보물 오류로 표시하지 않는다.
- **글자 뭉개짐:** 원본을 확대해도 `지원대상`인지 다른 글자인지 사람이 구별할 수 없다면 `VISUAL_TEXT_DEFECT`로 가독성 FAIL, 실제 철자는 `[판독불가]`로 둔다. 복원된 단어를 사실로 주장하지 않는다.
- **숫자:** 확정 원고의 마감일은 11월 30일인데 이미지에 11월 20일로 명확히 적혀 있으면 원고 불일치 FAIL. 정책상 정답이 무엇인지는 별도 출처로 검증한다.
- **모호한 사회·정치 표현:** 실제 비하 문구·상징과 문맥을 확인하지 못했으면 위험을 상상해 REVIEW 하지 않는다. 색상이나 일반 손동작만으로 정치적 성향을 추정하지 않는다.

**E. 격자 기반 하이라이트 계약**

- 원본과 **실제로 셀 번호가 그려진 격자 참고 이미지**를 함께 이용한다. 원본은 판단·OCR용, 격자는 위치 확인용이다. 모델은 픽셀 좌표를 계산하지 않고, 실제 표기된 셀 번호(`R01C01`: 위에서 아래로 행, 왼쪽에서 오른쪽으로 열)를 반환한다.
- 손·태극기·작은 글씨는 필요 시 crop 후 별도 격자로 재검사한다. crop과 원본의 좌표 변환은 프로그램이 담당한다. 발견한 영역만 표시하며 위치를 확정할 수 없으면 `location_unresolved=true`로 남긴다.
- 파랑 PASS, 빨강 FAIL, 노랑 REVIEW. 동일 셀에서는 시각적으로 FAIL > REVIEW > PASS를 우선한다. 클릭 패널에는 같은 셀의 모든 규칙별 판정을 보존한다. 확인하지 않은 빈 셀을 파랑으로 칠하지 않는다.
- **검사 완료의 의미:** 적용 대상과 하위규칙별 결과가 기록되어야 한다. 확인하지 못한 필수 검사는 NOT_RUN/해당 쟁점 REVIEW로 남긴다. 전체 PASS는 정책·법률·권리관계에 대한 포괄적 보증이 아니다.

**F. 재검사 우선순위**

누락 의심 영역·작은 태극기·작은 문자·손을 우선한다. 여러 객체를 하나로 합치지 않는다. 태극과 각 괘의 존재/획/위치를 구분하고 한 요소의 가림 때문에 나머지 확인 결과를 보류하지 않는다. 문자 줄 앞뒤·줄바꿈과 제공 정본의 숫자/단위를 대조한다. 고유명사·서비스명·의도된 카피를 사전에 없다는 이유만으로 오타 처리하지 않는다. FAIL에는 관찰·기준·수정 사항, REVIEW에는 미해결 사유·실제 재검사 기록·확인 질문, PASS에는 검사한 범위를 적는다. 자체 확신도를 검증된 정확도로 설명하지 않는다.


**G. 실행 계약과 비용 한도**

- 세부 ID 의미는 각 `### ID` 아래 행동 한 곳에서만 정의한다. 상위 설명은 상황·예시이며 세부 ID에 다른 행동을 재배정하지 않는다.
- 새 그림 읽기는 깨끗한 원본과 위치 참고 격자를 함께 전달한다. 화면에 격자를 강제로 그리지 않으며 가상 셀을 정밀한 글자 경계라고 표시하지 않는다. 원형 번호 및 영역 클릭으로 관련 의견을 연다.
- 자동 확대/공식 도안 비교는 후보 객체 최대 9개, 묶음 호출 최대 3회이다. 문자·지도·문양·인체 대상을 나눠 우선 배정한다. 엄격 모드의 작은 표지는 첫 판독이 선명해도 확대한다. 정상 설명은 재검사 신호가 아니다. 첫 판독 문자열과 정답을 암시하는 객체 이름은 재판독에 전달하지 않는다. 위치가 불확실한 번호는 이미지 밖 목록에 표시한다. 객체 ID·원본 crop 범위·판독 결과·공식 자료 ID·비교한 rule_id·자료 이미지 해시를 기록한다. 미확인/한도 초과/실패는 확인 완료로 쓰지 않는다.
- `assessments[rule_id]`는 객체별 판정 배열이다. 한 항목에 evidence_ids는 객체 하나만 연결하며 서로 다른 객체의 PASS/FAIL을 합치지 않는다. 대상이 없으면 ABSENT/NOT_APPLICABLE 항목 하나를 반환한다. 부모 집계와 무관하게 객체별 의견을 보존한다.
- `error_type`은 문자 오류 종류를 기록한다. `evidence_status`·`location_unresolved`·문자 영역 집계는 서버가 실제 저장된 근거에서 계산한다. 필드 이름을 자유롭게 추가하지 않는다.
- 등록된 기준 이미지가 있어도 자동으로 모든 대상과 대조했다고 보지 않는다. 실제 해당 객체·세부 행동·동일 자료 이미지의 직접 비교 기록이 있어야 공식 도안 확인 근거로 쓴다. 불명확한 비교는 UNAVAILABLE/REVIEW이며 적합한 기준자료 자체가 없으면 REQUIRED다.
- 개별 자산 이용권·동의·법적 해석은 담당자 검토를 유지한다. 공공누리 일반 안내를 개별 이미지 사용 허락으로 취급하지 않는다.
- 분석만 재실행은 저장된 첫 인식과 재검사 기록을 재사용하며 추가 이미지를 호출하지 않는다. 이전 기록에 문자 품질·비교 기록이 없으면 이를 확인했다고 주장하지 말고 새 그림+분석이 필요함을 알린다.


## H-01 | 역사적 사실·표현·인용의 정확성

**원문:** 역사적 사실, 표현, 인용 등이 정확한 사실관계 및 국민 인식에 부합하는가?

**적용:** 역사적 사건·인물·날짜·시설·인용·시대 재현이 **실제로** 등장할 때. 단순 현대 풍경에는 `NOT_APPLICABLE`.

**LLM 점검 행동**
1. 해당 세부 항목 텍스트와 그림에서 역사 관련 요소(인물명, 사건명, 날짜, 인용문, 시대 표시)를 추출한다.
2. 해당 세부 항목 어느 부분이 **검증 가능한 주장**인지 표시한다. 이미지 안의 주장과 승인된 사실자료를 분리한다.
3. 해당 세부 항목 제공된 기준 사료·기관 자료와 인용/연도/순서를 하나씩 비교한다. 참조가 없으면 역사 사실 검증의 `evidence_status=REQUIRED`.
4. 해당 세부 항목 시기와 맞지 않는 의복·시설 등은 **무엇이 다른지 설명 가능한 경우만** 지적한다. 사회적 해석은 별도 기록한다.

**판정/예시**
- `PASS`: 사진 속 역사 사건 표기와 제공된 기준 연표가 일치함.
- `FAIL`: 기준자료는 `19XX년`인데 선명하게 인쇄된 홍보물은 `19XY년`이라고 표시한 **불일치가 확인됨**.
- `REVIEW`: 해당 사건에 관한 사실 주장은 있으나 출처/기준 원고가 제공되지 않아 맞는지 확인할 수 없음. **역사적 사실 하위 점검만** 검토 요청.
- `NOT_APPLICABLE`: 역사 요소가 전혀 없음. `국민 인식`이라는 추상어만 이유로 전부 노랑 처리 금지.

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-01-a

역사 사건·인물·시대·날짜·장소·발언/인용을 텍스트와 그림에서 각각 추출한다.

### H-01-b

추출 요소 중 검증 가능한 주장(연도, 사건 순서, 인용문, 명칭)을 식별한다.

### H-01-c

승인된 역사·공공기관 출처 또는 사용자가 제공한 출처와 항목별 대조한다(출처·접근일·문장/페이지 보존).

### H-01-d

역사적 의복·시설·장면이 특정 시기와 맞지 않는 것으로 보이는 요소를 **의심점**으로 제시한다.

### H-01-e

사실오류와 '국민 인식에 부합'과 같은 가치·사회적 해석을 분리한다. 후자는 사람 검토로 연결한다.

### H-01-f

출처 불명·모델 기억만 존재하는 경우 사실확인 완료로 표시하지 않는다.

## H-02 | 5·18, 4·3, 독립·민주화운동 등 민감한 역사 사건 표현

**원문:** 5·18, 4·3 등 국가 공식 인정 사건, 독립운동, 민주화운동 등에 대한 왜곡, 폄훼, 혐오 묘사, 희화화, 부적절한 패러디는 없는가?

**적용:** 관련 사건명, 기념일, 명시적 묘사, 명확한 상징·문구가 있을 때.

**LLM 점검 행동**
1. 해당 세부 항목 특정 사건을 나타내는 **명시적 단서**를 먼저 찾는다. 일반 군중·옛 거리만으로 역사 사건을 특정하지 않는다.
2. 해당 세부 항목 실제 표현을 인용하거나 장면 요소를 구체적으로 묘사한다.
3. 해당 세부 항목 날짜·명칭·사실 주장은 승인된 출처와 비교한다.
4. 해당 세부 항목 조롱·왜곡 의심 문구가 있다면 **대상이 누구인지, 어떤 표현인지** 제시하고 교육·기록·비판적 인용인지 구별한다.

**판정/예시:** 기념행사 명칭이 정본과 일치하고 폄훼 표현이 없다면 검사 가능한 사항 `PASS`; 역사적 피해자를 직접 조롱하는 **명확한 카피**가 관찰되면 해당 위험 표현 `FAIL` 후보와 근거 제시; 풍자·비판의 의도가 양면적이면 **그 문구에 한해** `REVIEW`; 관련 소재가 없으면 `NOT_APPLICABLE`. 포괄적인 사회적 수용성 판단은 검토자에게 남긴다.

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-02-a

관련 사건·운동의 명칭, 날짜, 장소, 상징을 탐색한다.

### H-02-b

장면 또는 문구가 특정 사건과 연관되는 객관적 단서를 기록한다(연관이 약하면 임의 확정 금지).

### H-02-c

사건 사실관계·공식 명칭·기념일 등은 승인된 출처에 대조한다.

### H-02-d

희화화·조롱·비하로 **해석될 소지**가 있는 대사·표정·구도를 발견하면 인용/묘사와 함께 플래그한다.

### H-02-e

교육·비판·기록 목적의 인용이나 풍자와 실제 폄훼를 혼동하지 않도록 전체 문맥을 확인한다.

### H-02-f

사회적 수용성 및 위반 판정은 검토자에게 넘긴다.

## H-03 | 지도(동해·독도·외곽 도서) 표기의 정확성

**원문:** 지도(동해, 독도 등) 표기가 정확하며, 외곽 도서 지역(울릉도, 마라도, 백령도 등)이 누락되지 않았는가?

**적용:** 지도·지구본·행정구역 도식·지명·해역 명칭이 등장할 때.

**LLM 점검 행동**
1. 해당 세부 항목 지도 유형·축척·표시 범위를 파악한다(전국/지역/단순 개념도).
2. 해당 세부 항목 지도 안의 지명·해역명·섬 이름을 OCR과 시각 판독으로 전부 추출한다.
3. 해당 세부 항목 제공된 기준 지도/지명 목록과 **그림의 표시 범위에 속하는 곳만** 비교한다.
4. 해당 세부 항목 섬이 정말 표시되어야 하는 지도인지 판단한 뒤 누락·위치·명칭 오류를 검사한다.

**판정/예시:** `PASS`=승인 전국 지도와 요구 지명이 일치; `FAIL`=승인된 비교 기준상 표시되어야 할 섬을 누락하거나 이름을 다른 곳에 명백히 붙임; `REVIEW`=축척·참조 지도 부재로 누락 여부 불확정; `NOT_APPLICABLE`=지도 없음. **서울 구 단위 지도에서 독도가 안 보인다는 이유로 FAIL 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-03-a

지도·지구본·지명·해역명 표현이 있는지 찾고, 지도 유형과 표시 범위를 파악한다.

### H-03-b

동해·독도 관련 명칭 또는 위치가 등장하면 OCR 및 시각 판독을 수행한다.

### H-03-c

해당 표현에 적용되는 **사전 승인된 공식 지도/지명 기준자료**와 대조한다.

### H-03-d

울릉도·마라도·백령도 등의 존재·표시 여부를 지도의 축척과 실제 묘사 범위를 고려하여 확인한다.

### H-03-e

지도에 해당 지역이 없더라도 지도 목적·범위상 원래 표시되지 않을 수 있는 경우는 오답으로 단정하지 않는다.

### H-03-f

투영법·생략 기호·도식화·분할 지도·지도 이미지 해상도의 예외를 검사한다.

### H-03-g

기준 지도 또는 범위가 없어 결론 불가 시 사람 검토로 보낸다.

## H-04 | 국가명·국기·국가·국화 등 국가상징의 정확성

**원문:** 국가명, 국기(건곤감리 방향 등), 국가, 국화(무궁화) 등 국가 상징물이 적절하게 묘사되었는가?

**적용:** 태극기·무궁화·국가명·애국가 관련 문구 등 실제 등장한 객체 **각각**. 없는 객체는 해당 하위 규칙만 `NOT_APPLICABLE`.

**LLM 점검 행동 — 태극기 하나마다 `FLAG-001` 등으로 분리**
1. 해당 세부 항목 국기 객체를 모두 탐지하고 **정면/휘날림/접힘/뒷면/기울어짐/거울상/가림** 상태를 설명한다.
2. 해당 세부 항목 공식 표준 도안(서버가 제공한 승인 참고 이미지)과 비교 가능한 상태인지 정한다. 단순 회전·원근을 도안 오류와 구분한다.
3. 해당 세부 항목 중앙 태극 문양의 **빨강·파랑 영역 존재, 상대적 방향, 경계**를 확인한다.
4. 해당 세부 항목 흰 바탕, 붉은색·푸른색·검은색 구성에서 **명확한 잘못된 색**을 찾는다. 조명·압축으로 생긴 경미한 색차는 오류로 단정하지 않는다.
5. 해당 세부 항목 네 괘가 각각 있는지 센다: **건(☰)·곤(☷)·감(☵)·리(☲)**. 이름을 맞히는 것에서 끝내지 않는다.
6. 해당 세부 항목 **각 괘를 세 줄씩 따로** 읽고 이어진 획과 끊어진 획의 배열이 맞는지 공식 도안과 비교한다.
7. 해당 세부 항목 **정면 기준** 네 괘의 위치와 방향이 공식 참고 도안과 일치하는지 비교한다(기준 정면도: 좌상 건, 우상 감, 좌하 리, 우하 곤). 국기가 실제로 회전·펄럭이거나 뒤집힌 면이 보이면 촬영 각도를 정규화해 판단한다. **보이는 뒷면 자체를 불량으로 단정하지 않는다.**
8. 해당 세부 항목 정면에 펼쳐진 국기에 한해 구도·비율·괘 위치의 뚜렷한 이상을 확인한다. 접힘·휘날림의 픽셀비를 그대로 쓰지 않는다.
9. 해당 세부 항목 오류면 **전체 태극기 위치 + 잘못된 특정 요소의 셀**을 함께 반환한다. 참조 도안의 해당 부분을 사용자 화면에 나란히 보여줄 수 있도록 `reference_ids`를 보존한다.
10. 해당 세부 항목 국가명은 OCR/정본과 비교, 애국가 문구는 제공된 정본과 비교, 무궁화는 분명한 꽃 형태에 한해 확인한다. 무궁화의 모든 품종·창작 표현을 단일 색상으로 강제하지 않는다.

**판정/예시**
- `PASS`: 선명한 정면 태극기의 4괘 및 태극 문양이 제공된 승인 도안과 각각 일치함. **각 하위 항목에 PASS를 분리 기록**.
- `FAIL`: 오른쪽 위 괘가 공식 참고 도안의 **감(☵)** 형태와 달리 세 줄 모두 이어져 있는 것으로 선명하게 보임 → 해당 세부 항목, **그 괘 영역 빨간 위치 표시**.
- `FAIL`: 정면으로 똑바로 그려진 국기에 태극의 빨강/파랑이 뒤바뀐 사실이 분명함 → 해당 세부 항목.
- `REVIEW`: 아주 작은 국기를 확대해도 특정 괘의 선분이 가려져 참조 대조가 불가능 → 해당 **괘만 노란 위치 표시**.
- `NOT_APPLICABLE`: 태극기 자체가 없음 → **태극기 하위 규칙들** 비적용. 무궁화 등 다른 상징은 독립적으로 검사.
- **오탐 방지:** 국기가 180도 돌아가 보이거나 펄럭인다는 사실만으로 FAIL 금지. 기준 참조물이 없는데 기억만으로 과도한 확신도 금지.

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-04-a

국기(태극기), 국가명, 국가(애국가) 관련 텍스트/가사, 국화(무궁화) 등이 보이는지 객체·텍스트별로 찾는다. **여러 개면 모두 개별 검사**한다.

### H-04-b

대상별 `검사 가능/작아서 판독 불가/가림/의도적으로 추상화/없음`을 판정한다.

### H-04-c

태극기 영역 전체를 선택하고 **정면·회전·기울어짐·휘날림·거울상·부분 가림 여부**를 파악한다.

### H-04-d

단순 상하 뒤집힘(180도 회전), 좌우 반전(거울상), 안팎으로 비친 뒷면 등을 구분한다. 관찰 각도 자체를 곧바로 오류로 판단하지 않는다.

### H-04-e

정면 표준 도안과 비교하여 중앙 태극 문양의 **빨강/파랑 구성 및 방향**이 맞는지 확인한다.

### H-04-f

흰 바탕과 색상 구성이 공식 자료와 맞는지 확인한다. 조명·인쇄·영상 압축 때문에 발생한 색차는 별도로 판단한다.

### H-04-g

건·곤·감·리 **네 괘의 존재**를 각각 확인한다.

### H-04-h

각 괘의 **세 줄 구성, 연속/분절 패턴**을 괘별로 개별 점검한다(획 수/끊김 방식 누락·중복·교체 여부).

### H-04-i

**네 괘의 상대적 배치와 방향**을 공식 도안에 대조한다. 기준 **정면 도안**의 위치는 왼쪽 위 `건(☰)`, 오른쪽 위 `감(☵)`, 왼쪽 아래 `이(☲)`, 오른쪽 아래 `곤(☷)`이다. 각 괘의 획 패턴도 동일한 공식 도안을 대조한다. 이 위치 정의는 **정면을 올바르게 보는 상태**에 한정하고, 기울임·거울상·뒷면·접힘은 구분한다. 모델의 기억만으로 위치를 확정하지 않는다.

### H-04-j

중앙 태극 문양과 괘 사이의 상대적 위치·간격·회전이 비정상적이지 않은지 확인한다.

### H-04-k

직사각형의 정면 전면도에서만 태극기 규격 비율을 비교한다. 휘날림·원근·구겨짐 상태에서는 단순 픽셀 가로세로 비로 FAIL 처리하지 않는다.

### H-04-l

태극기 이미지가 매우 작거나 가려졌다면 고해상도 확대 재검사; 그래도 확인 불가하면 `REVIEW`.

### H-04-m

잘못된 부분을 확인했다면 전체 국기 박스와 **문제가 있는 괘/태극 부분 셀**을 별도 기록하고, 공식 참고 도안과 비교 화면을 제공한다.

### H-04-n

국가명·국호 표기의 철자와 맥락을 확인한다.

### H-04-o

애국가 관련 문구가 있다면 인용·표기·저작권 등 별도 검증 필요 항목을 구분한다(음원 자체는 MVP 비대상).

### H-04-p

무궁화 표현에서 해당 꽃을 나타내는 시각적 특징을 확인하되 품종·추상화·색상 변이에 대해 근거 없이 오류 확정하지 않는다.

### H-04-q

공식 기준자료가 없는 국가상징·정부상징은 사람이 검토하도록 한다.

## H-05 | 홍보물 배경 장소의 국가 오인 가능성

**원문:** 홍보물 배경에 나오는 장소가 타국으로 오인될 소지는 없는가?

**적용:** 이미지/캡션이 특정 국가·도시·기관의 실제 장소라고 주장하거나 국내 장소로 **명백히 해석되도록 설계된 경우**.

**행동:** 해당 세부 항목 배경의 명시적 지명·간판·국기·건축물 단서 추출 → 해당 세부 항목 홍보물이 주장한 실제 위치 확인 → 해당 세부 항목 제공된 위치 자료와 충돌하는 단서 찾기 → 해당 세부 항목 배경의 단순 외국풍·창작 스타일은 별도 처리.

**판정/예시:** `FAIL`=서울 행사 사진이라고 표기하면서 이미지에 다른 도시명이 선명하게 표시됨(충돌 근거 확인); `PASS`=제공된 위치와 시각적 지명이 일치; `REVIEW`=특정 랜드마크처럼 보이지만 촬영지 확인 자료 없음; `NOT_APPLICABLE`=추상 배경이고 실제 장소 주장 없음. **이국적 분위기만으로 REVIEW 남발 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-05-a

배경에 도시·건축물·산세·교통표지·국기·언어·랜드마크를 식별한다.

### H-05-b

장소가 특정 국가/지역이라는 **명시적인 설명 또는 홍보 목적**이 있는지 확인한다.

### H-05-c

배경 시각 단서와 주장된 국가/장소가 충돌하는지 점검한다.

### H-05-d

실제 촬영지, AI 생성 배경, 합성 여부를 이미지 자체로 확정하지 않는다. 제공 메타데이터를 우선한다.

### H-05-e

장소의 유사성·이국적 스타일만으로 타국이라고 단정하지 않고, 오인 소지를 근거와 함께 검토 요청한다.

## H-06 | 의상·음식·문자 등 문화 요소 정확성

**원문:** 의상(복식), 음식, 글자 등 문화 요소가 정확하게 반영되었는가?

**적용:** 전통복식·음식·문화재·언어·간판·문자 등이 등장하면 해당 부분에 적용. **일반 문자에는 공통 문자을 별도로 항상 실행**.

**행동:** 해당 세부 항목 실제 문화 요소 인스턴스 식별 → 해당 세부 항목 관련 라벨·간판 OCR/오탈자 검사 → 해당 세부 항목 특정 문화/시대/음식 명칭이 명시된 경우 제공 기준 이미지·설명과 비교 → 해당 세부 항목 전통 고증과 현대적 창작·재해석 구분.

**판정/예시:** `FAIL`=자료에서 `김치`로 명시한 음식 그림과 바로 옆의 명칭이 명백히 어긋나고 기준 자료에 의해 확인됨; `PASS`=명칭·문자가 선명하고 관련 기준과 일치; `REVIEW`=전통 복식의 시대별 정확성이 핵심이지만 참조 없음; `NOT_APPLICABLE`=검사할 문화 요소 없음. **문화 혼합·창작이라는 이유만으로 오류 확정 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-06-a

전통복식, 음식, 한글·한자 등 문화 표현이 있는지 탐색한다.

### H-06-b

OCR로 문자·표지·간판을 읽고 오자·깨진 글자·비정상 조합을 추출한다.

### H-06-c

특정 명칭·역사 시대가 명시된 경우 그 설명에 대한 기준자료를 확인한다.

### H-06-d

실제 의복 구조나 음식 형태가 기준 이미지와 확연히 다른 곳을 추출한다.

### H-06-e

창작·혼합·현대적 재해석을 오류로 즉시 판정하지 않도록 의도·문맥을 확인한다.

### H-06-f

문화적 적절성 또는 특정 문화의 오용에 관한 판단은 사람 검토로 넘긴다.

## H-07 | 국가·정부 문양·제복·계급장·동작

**원문:** 국가/정부 관련 문양(경찰·소방 표식, 계급장 등)이 정확하며, 경례 자세 등 동작은 올바른가?

**적용:** 공공기관 로고·제복·계급장·경례 등 실제 발견된 대상.

**행동:** 해당 세부 항목 기관 표식·제복·동작을 개별 인스턴스로 탐지 → 해당 세부 항목 표식의 문구·색·구성과 승인 도안 비교 → 해당 세부 항목 계급장의 모양·수량·위치 확인 → 해당 세부 항목 공식 동작 기준이 제공되면 자세를 비교 → 해당 세부 항목 일부 가림·장식용/가상 상징은 예외로 분리.

**판정/예시:** `FAIL`=승인된 특정 계급장 도안과 다른 획/별 수가 선명함; `PASS`=식별 가능한 공식 로고가 승인 도안과 일치; `REVIEW`=계급장이 너무 작거나 해당 시기의 참고 도안이 없음; `NOT_APPLICABLE`=해당 대상 없음. **일반 제복과 공인 기관 제복을 혼동하지 않는다.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-07-a

공공기관 로고, 정부상징, 경찰·소방 표식, 제복, 계급장, 공적 의례/경례 장면을 찾는다.

### H-07-b

문양이 공식 표준 이미지와 일치하는지 형태·색·문자·구성요소별로 점검한다.

### H-07-c

계급장 모양·배치·수량이 관련 기준자료와 맞는지 점검한다.

### H-07-d

특정 기관/직급으로 단정하기 전에 사용 맥락·해당 시기·대상 기준을 확인한다.

### H-07-e

경례나 의식 자세를 손·팔 방향, 자세, 상황별 공식 지침과 비교한다.

### H-07-f

장식용 패턴, 희화화된 캐릭터, 비정형 재현일 경우 명백한 오용과 단순 스타일 차이를 구분한다.

### H-07-g

공식 도안·지침 미확보 또는 세부 문양 판독 불가 시 `REVIEW`.

## H-08 | 남북관계·안보 관련 표현

**원문:** 남북 관계 및 안보 관련 사항이 정부의 통일‧안보 기조와 부합하는가?

**적용:** 남북관계·통일·안보 관련 주장, 지도·상징·문구가 실질적으로 등장할 때.

**행동:** 해당 세부 항목 관련 주장·표현을 정확히 전사 → 해당 세부 항목 사실 주장과 정책 방향 평가를 분리 → 해당 세부 항목 기준일이 명시된 **승인 정책 자료**와 사실·문구 대조 → 해당 세부 항목 외부 증빙 부족 시 해당 주장만 요청.

**판정/예시:** `FAIL`=제공된 공식 정책 문서와 홍보물의 제도명/시행일이 명백히 다름; `PASS`=구체적 주장이 승인된 자료와 일치; `REVIEW`=현재 정책 부합성 판단이 필요한데 기준 문서가 없음; `NOT_APPLICABLE`=관련 내용 없음. **국가 상징 한 개만으로 민감한 정책 규칙을 일괄 REVIEW 하지 않는다.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-08-a

남북관계·안보·통일 관련 텍스트, 국기·지도·상징, 시기·사건 표현을 식별한다.

### H-08-b

정부의 공식 통일·안보 정책과 대조해야 하는 구체적 주장/문구를 추출한다.

### H-08-c

**기준일과 승인된 최신 정책자료**를 확인한다. 최신 정책자료가 없으면 판정 불가로 둔다.

### H-08-d

사실관계가 틀린 것으로 보이는 표현과 정책 취지 해석/평가를 분리한다.

### H-08-e

최종 정책 부합 여부는 소관부서 또는 권한 있는 검토자에게 넘긴다.

## H-09 | 한일관계 관련 표현 및 외교적 오인 가능성

**원문:** 한일 관계 사안에 대해 국민감정을 자극하거나 외교적으로 우려되는 문구는 없는가?

**적용:** 일본·한일관계에 관한 사실·외교·역사 문구가 있는 경우.

**행동:** 해당 세부 항목 명칭·문구 OCR → 해당 세부 항목 사실/명칭은 승인 자료와 대조 → 해당 세부 항목 모욕·조롱·직접적인 선동 등 **관찰되는 표현**을 특정 → 해당 세부 항목 외교적 해석과 사실 오류는 분리.

**판정/예시:** `FAIL`=승인된 명칭과 정면 충돌하는 명백한 표기 오류; `PASS`=중립적 행사 안내이고 관찰 가능한 모욕·오류 없음; `REVIEW`=실제 외교 사안의 해석이 첨예하고 **해당 문구가 특정됨**; `NOT_APPLICABLE`=한일 관계 무관. **일본어가 있다는 사실만으로 REVIEW 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### H-09-a

일본 또는 한일관계와 관련된 명칭, 역사·영토 문구, 국가상징을 검출한다.

### H-09-b

문구를 정확히 OCR/전사하고 주변 문장을 함께 보존한다.

### H-09-c

검증 가능한 사실관계·명칭 오류는 관련 공신력 있는 출처와 대조한다.

### H-09-d

감정 자극·외교적 우려는 상황 의존적이므로 **이유가 있는 검토 의견**으로 생성한다.

### H-09-e

관련 문맥이 없으면 비적용 처리하고, 정부의 외교적 판단은 AI가 최종 결정하지 않는다.

## E-01 | 성별 고정관념·성역할·성적 대상화

**원문:** 성별 고정관념, 고정된 성역할 강화, 성적 대상화, 비하, 젠더 갈등 유발 요소는 없는가?

**행동:** 해당 세부 항목 성별에 대한 명시적 서술·카피 검사 → 해당 세부 항목 직업·돌봄·권한을 특정 성별의 *당위*로 표현했는지 확인 → 해당 세부 항목 불필요한 신체 대상화·비하 문구/구도를 특정 → 해당 세부 항목 통상적인 인물 배치와 고정관념 강요를 구분.

**판정/예시:** `FAIL` 후보=“여성은 반드시 ○○만 해야 한다” 등 특정 성별 역할을 직접 강요하는 명시적 카피; `PASS`=다양한 인물이 일하는 장면이며 비하·강요 표현 없음; `REVIEW`=구체적 장면·카피 때문에 대상화로 읽힐 수 있으나 맥락 논쟁 존재; 전역 스캔에서 단서 없으면 `PASS`. **인물 수의 성별 추정/구성만으로 결함 단정 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### E-01-a

문구·대사·장면에서 특정 성별을 단정적으로 규정하는 표현이 있는지 식별한다.

### E-01-b

인물의 직무·가사·돌봄·지휘·기술 역할이 특정 성별의 당위처럼 제시되는지 문구 중심으로 확인한다.

### E-01-c

신체 일부만 강조하는 구도·수식어 등 대상화 소지를 탐색한다.

### E-01-d

성별을 조롱·비하하거나 성별 간 갈등을 의도적으로 유발하는 표현을 맥락과 함께 기록한다.

### E-01-e

단순 인물 구성의 불균형만으로 위반을 확정하지 않는다. 홍보 목적·문구와 결합해 `REVIEW`.

## E-02 | 특정 세대 비하·멸칭

**원문:** 특정 세대 비하 용어 및 멸칭을 사용하지 않았는가?

**행동:** 해당 세부 항목 모든 문구 OCR → 해당 세부 항목 **승인된 표현 사전의 실제 항목**과 일치 여부 확인 → 해당 세부 항목 직접 비하인지 인용·교육 목적 설명인지 문맥 확인 → 해당 세부 항목 표현 위치 반환.

**판정/예시:** `FAIL`=승인된 멸칭을 특정 세대를 조롱하는 카피로 직접 사용; `PASS`=세대별 정책 안내에 비하어 없음; `REVIEW`=표현 자체는 관찰되나 인용·풍자 맥락 판단 어려움. **인증되지 않은 최신 유행어 의미를 모델이 만들어내지 않는다.**

**원문:** 특정 종교를 옹호‧비하하거나 편향된 상징물 및 용어는 없는가?

**행동:** 해당 세부 항목 종교명·종교 상징·직접적인 신앙 권유/배제 문구를 식별 → 해당 세부 항목 종교 문화 소개와 신앙 참여 요구를 구분 → 해당 세부 항목 명백한 조롱·비하·배제 표현 확인.

**판정/예시:** `FAIL` 후보=정부 홍보문에서 특정 신앙을 믿도록 직접 권고하는 표현; `PASS`=문화재·역사 관련 종교 건축물의 중립적 설명; `REVIEW`=특정 종교 홍보처럼 읽히는 구체적인 문구가 있으나 행사 목적 불명확; `NOT_APPLICABLE`=종교적 표현·주제 전무. **사람의 외모/복식으로 종교 추정 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### P-03-a

종교명·교리·상징·종교 행사 문구가 **명시적으로** 나타나는지 확인한다.

### P-03-b

공적 정책 안내와 특정 종교 참여/지지 권유를 구분한다.

### P-03-c

특정 종교·신앙인을 조롱하거나 배제하는 표현이 있는지 확인한다.

### P-03-d

복식·외모만으로 개인 종교를 추정하지 않고, 단순 상징의 등장 자체를 위반으로 보지 않는다.

### P-03-e

정치·종교적 편향성 해석은 사람 검토로 보낸다.

## P-04 | 재난 피해자·유가족에 대한 부적절한 이미지·문구

**원문:** 재난 피해자·유가족 등의 입장 및 사회적 정서에 반하는 영상, 이미지, 내용은 없는가?

**행동:** 해당 세부 항목 특정 재난/피해/추모 관련 텍스트·장면 확인 → 해당 세부 항목 고통을 명시적으로 희화화·조롱·선정적 소비하는 구체적 요소 확인 → 해당 세부 항목 예방/구호/추모 맥락과 구분 → 해당 세부 항목 사실관계는 따로 대조.

**판정/예시:** `FAIL` 후보=재난 피해자를 조롱하는 선명한 홍보 카피; `PASS`=안전수칙·추모 정보의 존중하는 전달; `REVIEW`=피해 장면의 매우 자극적인 연출에 대한 구체적 우려; `NOT_APPLICABLE`=재난·피해 맥락 없음.

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### P-04-a

재난·사고·사망·부상·유가족 관련 묘사나 문구를 탐색한다.

### P-04-b

고통·슬픔을 희화화하거나 자극적으로 소비하는 장면·카피의 후보를 식별한다.

### P-04-c

피해 사실 전달·예방 교육·추모 목적과 선정적 소비를 구분할 수 있는 문맥을 수집한다.

### P-04-d

특정 재난을 잘못 지칭하거나 검증되지 않은 피해 사실을 묘사할 경우 사실확인 대상으로 분리한다.

### P-04-e

사회적 정서와 윤리적 적절성은 사람 검토로 올린다.

## P-05 | 재난 피해자 얼굴·개인정보 노출

**원문:** 재난 피해 장면 사용 시 피해자 얼굴 등 개인정보 노출은 없는가?

**적용:** **재난·사고 피해 장면**이 있고 식별정보 노출 여부를 검사할 때.

**행동:** 해당 세부 항목 재난 장면 여부 확인 → 해당 세부 항목 얼굴·이름표·주소·전화번호·차량번호·의료 기록 등의 **보이는 노출 여부** 확인 → 해당 세부 항목 모자이크 등 비식별 상태 확인 → 해당 세부 항목 동의·적법성은 제공 증빙과 분리. 개인정보 원문은 보고서에 마스킹.

**판정/예시:** `PASS`=재난 이미지에 등장하는 얼굴·표식이 충분히 비식별 처리됨(시각적 노출 검사 한정); `FAIL`=명확히 읽히는 개인 연락처가 공개된 재난 현장 이미지이며 비식별 처리가 없음 **→ 노출 위험 `FAIL`, 법률적 위반 여부는 별도**; `REVIEW`=가려진 얼굴이 실제로 식별 가능한지 애매함/동의 자료 필요; `NOT_APPLICABLE`=재난 관련 이미지 없음.

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### P-05-a

재난 장면이 있는지 먼저 판별한다(없으면 비적용 가능).

### P-05-b

얼굴·이름표·연락처·주소·차량번호·의료/개인 기록 등 식별 단서를 탐색한다.

### P-05-c

노출된 정보가 식별 가능할 정도로 선명한지 점검한다. **사람의 실제 신원은 추정하거나 특정하지 않는다**.

### P-05-d

비식별 처리 여부(모자이크·가림·크롭)를 확인한다.

### P-05-e

공개 동의·보도 목적상 적법성은 이미지로 알 수 없으므로 증빙 및 사람 검토가 필요하다.

### P-05-f

발견된 개인정보는 보고서/로그에서 원문을 불필요하게 재출력하지 않고 마스킹한다.

## D-01 | 법령 준수 및 정부 주요 정책 부합

**원문:** 홍보 문구, 이미지, 영상 등이 관련 법령을 준수하며 정부 주요 정책과 배치되지 않는가?

**행동:** 해당 세부 항목 법령·사업·지원 대상·금액·일정·연락처 등의 **구체적인 홍보 주장**을 먼저 모두 추출 → 해당 세부 항목 정본/관련 법령/시행일 기준자료가 있으면 항목별 대조 → 해당 세부 항목 명백한 숫자·기준일·자격조건 불일치를 기록 → 해당 세부 항목 법률적 평가와 이미지 자체 오탈자는 분리.

**판정/예시:** `FAIL`=제공된 승인 사업 안내에는 지원 금액이 `100만 원`인데 이미지는 `1,000만 원`으로 선명히 표기; `PASS`=검증 가능한 숫자·문구가 제공된 정본과 모두 일치했다는 **제한적 사실 점검**; `REVIEW/evidence REQUIRED`=시행일 등 관련 주장이 있는데 승인 자료가 없어 검증 불가; 해당 주장 자체가 없을 때는 사실 대조 하위 항목 `NOT_APPLICABLE`. **이미지 하나만으로 전반적 법령 준수 PASS 선언 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### D-01-a

법령·정책·사업·지원 대상·기간·금액·연락처 등에 관한 주장과 문구를 추출한다.

### D-01-b

해당 주장에 관한 기준일과 적용 가능한 법령/시행일/정부 발표 출처를 확인한다.

### D-01-c

출처가 확인된 구체적 불일치(숫자, 날짜, 자격요건, 시행시점)를 표시한다.

### D-01-d

이미지 의미만으로 법 준수·정책 부합 여부를 확정하지 않는다.

### D-01-e

최신 규정 접근권한·승인된 근거자료가 없으면 `REVIEW`와 `증빙 필요`를 생성한다.

### D-01-f

법령해석·정책 적합성에 관한 최종 책임은 소관부서에 둔다.

## D-02 | 생성형 AI 그래픽 오류·환각(핵심 시각 품질 규칙)

**원문:** 생성형 AI 활용 시 그래픽 오류(예: 손가락 개수)나 AI 환각(팩트체크 오류)은 없는가?

**적용:** AI 이미지 여부가 제공되면 우선하고, 생성 여부가 불명확해도 일반적인 시각 오류·문자 오류 검사는 시행한다. `그래픽 오류`와 `사실관계 환각`을 별도 결과로 저장한다.

**LLM 점검 행동**
1. 해당 세부 항목 화면의 사람·손·발·얼굴·물체·구조물·문자·숫자·표를 목록화한다.
2. 해당 세부 항목 **보이는 모든 손을 각각** 기록한다(인물/왼손·오른손/가림/손자세/crop). 사람 2명에 손 3개가 보이면 손 3개를 개별 점검한다.
3. 해당 세부 항목 손바닥·손등·엄지·손가락의 연결을 순서대로 따라간다. **정상적인 5개 손가락이 항상 전부 보일 필요는 없다.**
4. 해당 세부 항목 분명하게 **여섯 번째 손가락이 붙음**, 손가락이 Y자로 갈라짐, 서로 다른 손이 비현실적으로 융합됨, 손목과 팔이 불가능하게 연결됨 등의 **관찰 가능한 비정상 구조**를 찾는다.
5. 해당 세부 항목 손이 겹치거나 물건을 쥐거나 주먹을 쥔 경우 보이지 않는 손가락을 결손으로 단정하지 않는다.
6. 해당 세부 항목 발·다리·팔·관절·얼굴의 복제/비정상 접합, 물체 중복·관통·사라짐, 구조물·반사 이상 등도 **개별 객체**로 점검한다.
7. 해당 세부 항목 원본에서 손이 작으면 crop+격자 세부검사. 명확해지면 **PASS 또는 FAIL을 내고** 개선되지 않는 특정 손만 REVIEW.
8. 해당 세부 항목 사람 손가락 외에 **문자 모양의 뭉개짐/유사 문자**를 반드시 공통 문자 검사로 넘긴다. `텍스트 존재`와 `정상적으로 판독됨`은 다르다.
9. 해당 세부 항목 현실과 다른 창작 표현이 의도된 만화·판타지·디자인(예: 의도적으로 손가락 4개인 캐릭터)이면 **사전 디자인 설명과의 관계**를 확인하여 성급히 FAIL하지 않는다.
10. 해당 세부 항목 도표·수치의 사실관계는 **제공된 원본 데이터**와 비교할 때만 사실검증 PASS/FAIL. 자료 없으면 그래픽 점검과 별도로 증빙 요청.

**판정/예시**
- **G1 PASS:** 손바닥이 또렷한 손이 있고 엄지 1개+나머지 4개의 정상적 구조. 해당 손 `PASS`, **파란 테두리**.
- **G2 FAIL:** 확대된 손에서 손바닥으로부터 손가락 6개가 각기 별도 뿌리로 뻗음. `FAIL`, 손 셀 **빨간 테두리**. “무엇이 6개인지”를 서술.
- **G3 PASS:** 주먹을 쥐어 손가락 끝 2개만 보이지만, 다섯 손가락보다 적게 보인다는 사실 외에 이상 없음. **보이지 않는 숫자만으로 FAIL 아님**.
- **G4 REVIEW:** 물건 뒤에 가린 손에서 추가 손가락이 있는 듯 보이지만 확대해도 두 손이 겹친 것인지 분별 불가. **그 손만** `REVIEW`.
- **G5 FAIL:** 인물의 팔이 관절 없이 다른 인물의 손에 부자연스럽게 이어져 있음이 분명함. 해당 접합 부위 빨간 셀.
- **G6 PASS:** 4지 손으로 디자인된 마스코트임이 제작 명세에 명시돼 있고 스타일 전반이 일관됨. 인체 오류로 강제 FAIL하지 않음.
- **G7 FAIL:** 표지판이 한국어 글자처럼 보이나 글리프가 겹쳐 **사람이 읽을 수 없는 제작 품질 오류**. `VISUAL_TEXT_DEFECT`로 `FAIL`. 문구의 의미를 만들어내지 않는다.
- **G8 별도 검증:** 그래프 수치가 의미상 맞는지는 원본 통계자료가 있을 때에만 판단한다. 자료 없으면 도표 자체의 읽힘 여부는 판정하되 수치 사실관계만 증빙 필요.

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### D-02-a

AI 활용 여부가 메타데이터로 제공되었는지 확인한다. AI로 생성되었다고 알려진 그림을 대상으로 우선 검사하되, 원본이 없으면 이미지 자체만으로 제작 방식을 단정하지 않는다.

### D-02-b

사람·손·발·얼굴·물체·표지판·글자·건축 구조·지도·숫자·도표 등을 탐색한다.

### D-02-c

모든 사람/캐릭터 인스턴스를 탐지한 뒤 보이는 왼손·오른손을 개별로 식별한다. 화면에 손이 여러 개면 각각 분리해 검토한다.

### D-02-d

각 손의 손바닥·손등·손목·손가락 구조를 파악한다. 손이 쥐어져 있거나 일부 가려져 있는지 기록한다.

### D-02-e

보이는 손가락 수가 비정상적으로 많은지(예: 6개로 보임), 또는 여러 손가락이 비자연스럽게 결합/분기/중복되는지 확인한다.

### D-02-f

**'사진에서 보이는 손가락 수가 5개 미만'은 단독 FAIL 사유가 아니다.** 주먹, 원근, 물체를 쥠, 겹침, 화면 밖 잘림 등 예외를 확인한다.

### D-02-g

손·손목·팔이 엉뚱하게 연결되거나 관절이 부자연스럽게 중복되는지 확인한다.

### D-02-h

발·발가락·다리·관절 수/구조·인체 중복·머리와 몸통 연결 등 유사한 인체 오류를 확인한다.

### D-02-i

손 또는 얼굴이 작고 불명확하면 해당 영역을 **확대 crop + 세부 격자**로 재검사한다. 그래도 모호하면 `REVIEW`.

### D-02-j

중복 물체, 일부가 사라진 물체, 부자연스러운 접합·관통, 엉뚱한 그림자·반사 등을 확인한다.

### D-02-k

물체 사용 장면과 기능적 관계가 현저히 모순되는지 확인한다(예: 손잡이를 잡는 방식, 다리 연결).

### D-02-l

이미지 속 문구를 OCR로 추출하여 오자, 비정상 문자, 부호·숫자 깨짐을 점검한다.

### D-02-m

도표·그래프·수치·비율·각종 표식이 **제공된 원본 데이터**와 맞는지 대조한다. 자료가 없으면 '미검증'으로 둔다.

### D-02-n

실제처럼 보이는 인물·장소·사건의 사실관계는 이미지 사실성만으로 확정하지 않는다.

### D-02-o

그래픽 오류(시각적 구조)와 AI 환각(사실의 부정확성)을 **서로 다른 하위 판정**으로 저장한다.

### D-02-p

만화·캐릭터의 의도적인 4지 손, 추상화, 의도적 원근·판타지 장면 등을 오탐하지 않도록 **콘텐츠 스타일 및 의도**를 확인한다.

## D-03 | 폰트·이미지·음원·템플릿의 상업적 이용권

**원문:** 폰트, 이미지, 음원(BGM), 템플릿 등의 상업적 이용 라이선스를 확보하였는가?

**적용:** 실제 사용된 외부 소재·폰트·템플릿·음원 등이 있고, 사용 내역과 허가 조건 확인을 요할 때. 이미지 한 장만으로 음원 존재를 추정하지 않는다.

**행동:** 해당 세부 항목 제공된 사용 자산 목록과 출처를 수집 → 해당 세부 항목 사용범위(상업적 이용, 수정, 배포, 매체, 기간)를 구조화 → 해당 세부 항목 계약서/라이선스 문서와 이용 방식 대조 → 해당 세부 항목 증빙 없는 항목만 `evidence REQUIRED`.

**판정/예시:** `PASS`=제공된 라이선스 문서의 이용 범위가 해당 사용 형태와 부합하는 것이 확인된 **서류검증 항목**; `FAIL`=명시된 계약 금지 조건과 실제 예정 사용방식이 충돌함이 증빙으로 확인; `REVIEW`=사용 자산은 확인됐지만 허가증이 없음; `NOT_APPLICABLE`=해당 종류의 자산을 사용하지 않았음이 **제작 정보로 확인**됨. **이미지가 예뻐 보인다는 이유로 저작권 PASS/FAIL 금지.**

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### D-03-a

사용한 폰트·사진·일러스트·음원·템플릿 목록 및 출처 정보를 입력받는다.

### D-03-b

상업적 이용, 수정·재배포, 표시의무, 사용기간, 매체 범위 등을 항목화한다.

### D-03-c

허가증·계약서·구매내역·라이선스 URL/버전 등 증빙의 존재와 유효 범위를 점검한다.

### D-03-d

이미지가 특정 저작물과 유사하게 보인다는 이유만으로 침해 여부를 확정하지 않는다.

### D-03-e

증빙이 없거나 조건이 불명확하면 **항상 `REVIEW`/`DOCUMENT_REQUIRED`**. 시각 검사만으로 PASS 불가.

### D-03-f

권리관계에 관한 최종 법적 판단은 사람/전문가에게 위임한다.

## D-04 | 일반인 얼굴·차량번호 등 개인정보 노출

**원문:** 일반인 얼굴, 차량 번호 등 원치 않는 개인정보 노출은 없는가?

**행동:** 해당 세부 항목 얼굴·번호판·전화번호·실명·이메일·주소·명찰·문서의 식별정보를 찾는다 → 해당 세부 항목 읽거나 식별 가능한지, 모자이크/가림 여부를 본다 → 해당 세부 항목 실제 신원 식별·값의 불필요한 저장을 피한다 → 해당 세부 항목 동의·공개 근거는 별도 증빙 확인.

**판정/예시:** `PASS`=노출 위험 요소가 전역 스캔에서 없거나 식별정보가 충분히 비식별 처리됨(시각적 노출 점검 한정); `FAIL`=공개 자료의 번호판/연락처 등 민감할 수 있는 식별정보가 명확히 노출되어 **조치 필요 위험**이 식별됨(법 위반 확정은 아님); `REVIEW`=사람 얼굴·번호가 있는데 실제 공개 동의/사용 목적이 확인되지 않음(서류 검토, 좌표 있으면 해당 객체만); 얼굴 등 단서가 전혀 없으면 전역 스캔 `PASS`. **모든 사람 얼굴이 곧 개인정보 위법이라는 결론 금지.**

---

**세부 점검 행동(기존 ID 유지; 위 판정 예시와 함께 적용)**

### D-04-a

얼굴, 차량번호판, 실명, 전화번호, 이메일, 주민번호로 보이는 문자열, 주소·명찰·서류 등을 찾아 **노출 위치**를 표시한다.

### D-04-b

이미지가 실제 개인을 식별할 수준인지, 이미 모자이크/가림 처리됐는지 확인한다.

### D-04-c

실제 정보의 값이나 인물 신원을 판정 근거로 불필요하게 저장하지 않는다.

### D-04-d

개인정보·초상권 사용 동의가 있는지 여부는 별도 증빙으로 확인한다.

### D-04-e

안내용 가상번호·가상인물·비식별 예시 등 예외에 관한 근거가 없으면 사람 검토로 보낸다.

### D-04-f

비공개 자료에 대한 외부 API 전송 여부를 보안 정책에 따라 통제한다.
