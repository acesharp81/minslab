# 기본 그림·분석 흐름의 손·글자 정밀 확인

## 원인과 변경

기존 ImageGen_Exploratory_01 확대 재검사에서는 GPT-5.4가 작은 표지판을 `김치찌개`, `한복 체험`으로 읽고 손을 자연스러운 브이 자세로 설명했다. 추가 호출은 실제로 실행됐으나 구체적 손 결함을 발견하지 못했다. 단순히 화면에서 숨겨진 오류가 아니었다.

별개의 구현 오류도 확인했다. OCR 한 줄이 인접 격자 두 칸에 걸치면 각 칸의 중첩률이 각각 0.5 미만이어서 해당 객체와 연결되지 않았다. 현재는 잘라낸 사각형들의 정확한 합집합 면적을 계산한다. 떨어진 영역 사이를 채우거나 중복 좌표를 여러 번 세지 않는다. 객체 위치가 측정 사각형이 아닌 거친 격자 주소뿐이면, OCR 중심이 해당 칸 내부이고 실제 겹침이 20%를 넘는 경우도 연결 후보로 삼는다. 후보가 여럿이면 확정하지 않는다. 같은 위치의 판독 문자열이 달라도 비슷한 길이의 한 줄이면 정확한 OCR 좌표로 확대한다. 문구 일부만 읽었거나 여러 객체가 중첩되면 전체 대응으로 간주하지 않는다.

## 기본 실행

`그림 + 분석 실행`으로 새 관찰을 만들면 기존 25개 원문·156개 행동과 공식 도안 비교를 유지하면서 다음 단계를 수행한다.

1. 기존 로컬 문자 탐지와 확대 묶음 검사. 객체 선택에서 손을 두 번째 문자 후보 뒤로 밀어내지 않는다.
2. 민감 모드에서는 판독 차이·작은 안내문을 우선하여 최대 4개 영역의 획을 한 묶음으로 독립 판독한다. 이미 저장된 로컬 탐지 좌표를 재사용하고 NAVER를 새로 호출하지 않는다.
3. 분리가 가능한 짧은 한글은 최대 16개 음절을 두 독립 요청(GPT-5.4, mini)으로 판독한다. 단어 순서·이전 문자열·정답은 전달하지 않는다. 원근 보정은 음절 경계 측정에만 쓰고, 모델에는 역변환한 원본 픽셀 crop과 픽셀 반복 확대를 보낸다. 보이지 않는 획을 생성하지 않는다.
4. 최대 3개 손 객체는 mini 한 요청으로 손 위치를 먼저 좁힌 뒤 GPT-5.4 한 요청으로 손목·손바닥·뿌리·관절·끝의 연결을 기록한다. 처음부터 검지·중지 또는 브이 자세를 가정하지 않고 펼친 경로/접힌 경로를 나눠 기록한다. 같은 뿌리에서 양립 불가능한 두 상태가 이어지는지와 정상적인 다른 손가락의 겹침을 비교한다. 가림이나 보이는 손가락 개수만으로 경고하지 않는다. 별도 구조 소견과 위치가 있을 때만 REVIEW로 연결한다. **이 절차를 추가해도 이번 성인 남성 손의 중지 중복 오류는 검출하지 못했다.**
5. 저장된 관찰과 위 근거를 분석 모델에 전달한다. 원본 문자 판독의 구체적 불일치는 PASS로 사라지지 않지만, 불일치만으로 오탈자 FAIL을 만들지 않는다.

추가로 문자 정체의 확신과 획 품질을 분리했다. 글자를 읽지 못하더라도 원본에 보이는 번짐 위치를 특정할 수 있으면 전사는 `□`, 품질은 `DEFECT`가 될 수 있다. 미판독 `□` 자체를 OCR 문자열 불일치로 분류하지 않는다. 단순히 작거나 가려서 읽지 못하는 경우는 결함 경고로 올리지 않는다.

추가 정밀 경로는 최대 5회(획 1 + 음절 2 + 손 위치 1 + 손 구조 1)다. 대상이 없거나 분리가 불가능하면 해당 호출을 생략하며, 기존 확대 호출·철자 검사·규칙 분석은 별도다. 모든 호출은 PoC7 공통 원장의 예약·정산을 거친다. 손/글자 정밀 검사는 GPT-5.4·mini만 사용하며 Sol/Astra로 자동 전환하지 않는다.

그림 읽기를 재사용하는 일반 `분석 재실행`은 이 추가 이미지 호출을 수행하지 않는다. 저장된 손·글자 근거를 그대로 분석한다. 구버전 이력에는 없던 관찰을 얻으려면 한 번은 그림부터 실행해야 한다. 수동 `손·글자 확대 재검사`는 기존의 선택 영역 최대 6곳/확대 2회 계약을 유지한다.

## 표시와 설정

- 결과 상단 단계별 토큰: 손 구조·독립 음절 호출도 2단계에 실제 입력/출력으로 합산한다.
- 관찰 기록 · 토큰 사용량 → **자동 손·글자 정밀 확인**: 새 판독, 음절별 미확정, 손 연결 관찰, 범위 밖 대상을 표시한다.
- 번호 상세: 같은 위치의 OCR/그림 판독 비교와 손 연결 근거를 표시한다. 단순 미완료·OCR 실패는 이미지 오류로 만들지 않는다.
- 추가 확대 응답 실패는 규칙 분석이 종료됐더라도 결과 상단에 표시한다. 영역 한도로 보류된 것과 공급자 응답 실패를 구분한다.
- `GLYPH_AUDIT_ENABLED=true`, `GLYPH_AUDIT_MAX_REGIONS=4`, `ISOLATED_GLYPH_ENABLED=true`, `ISOLATED_GLYPH_SCALE=3`.
- `HAND_AUDIT_ENABLED=true`, `HAND_AUDIT_MAX_OBJECTS=3`.
- `AUTO_VERIFY_MAX_CALLS=0`은 자동 확대와 새 정밀 경로도 끈다. `PIXEL_TEXT_ENABLED=false`이면 별도로 명시하지 않은 글자 정밀 경로도 끈다.

`detail: original`과 작은 글자 확대는 공식 이미지 입력 문서에 근거한다. 한국어·작은 글자·정밀 위치 추론의 한계도 명시되어 있으므로 원본 detail 또는 두 모델의 판독 일치만으로 정상이라고 인증하지 않는다. [OpenAI 이미지 입력 문서](https://developers.openai.com/api/docs/guides/images-vision)

## 실제 평가 기록

평가별 상한은 GPT-5.4 **400,000토큰**, mini **2,000,000토큰**이며 공용 일일 잔량도 각 호출 전에 검사했다. 최초 240,000/1,000,000 상한에서는 병행 호출의 보수적 예약으로 추가 검사가 생략되어 위 범위로 조정했다. 공용 일일 한도를 늘리거나 우회하지 않았다. Sol/Astra/Solar/OpenRouter/NAVER 호출은 **0회**다. 정답 JSON과 정답 ROI는 자동 판독 프롬프트에 넣지 않았다. 마지막 손 진단은 사용자가 지목한 성인 남성 객체만 선택했으며 기대 판정이나 정답 좌표는 보내지 않았다. 상세 원본 응답은 비공개 `data/refinement-20261106/`에 보존한다.

탐색 시험에서 손 경로의 내부 응답 스키마 선택 오류와 출력 길이 초과가 발생했다. 해당 호출도 사용량에서 차감했고 응답을 성공으로 표시하지 않았다. 스키마 회귀 테스트를 추가했다. 긴 글자 획 출력은 최대 12음절만 기술하도록 제한하고 상한을 공통 최대 10,000토큰으로 조정했다. 손 구조는 고강도 추론에서 시간 초과도 발생하여 최종 medium/출력 최대 6,000토큰으로 조정했다. 새 정밀 경로에 자동 재시도는 추가하지 않았다.

### 전체 실행과 검수 이력

ImageGen_Exploratory_01의 그림부터 새로 읽는 전체 실행을 3회 수행했다. 각 실행은 원문 25개/156개 행동의 분석을 마쳤다. 다만 두 실행에는 추가 확대 응답 시간 초과가 있어 **모든 시각 검사가 성공한 것은 아니다**. 소요 시간은 약 9분 16초, 6분 57초, 9분 17초였다. 정밀 경로를 포함한 처리 속도는 아직 개선 대상이다.

| 기록 | 범위 | 결과 |
|---|---|---|
| `631eb6155bcf4d2689a2e6bf51a8e2ce` | 새 그림 + 전체 분석 | 손 구조 호출 완료, 중복 오류 미검출 |
| `40e6e4a3afe449fe9477fc3f6ac4cd02` | 새 그림 + 전체 분석 | 확대 응답 실패 및 평가 예약 한도로 정밀 단계 일부 미완료 |
| `1ba98f36e36548ffb28d34487e2c3968` | 새 그림 + 전체 분석 | 손 3곳 판독 완료, 중복 오류 미검출. 확대 1회 응답 실패 |
| `506a54c014ab4a40903adae47ac2fc7e` | 성인 남성 손 추가 독립 판독 2회 반영 | 경로를 나눠 읽었지만 접힌 부분을 가림으로 해석, 여전히 미검출 |
| `6b7744f057084509bc7cebc3273b06f2` | 저장 관찰로 관련 행동 4개 mini 재분석 | 글자 판독 충돌/정확한 OCR 위치 연결 확인. 나머지 행동은 기존 결과 유지 |

최신 이력에서 음식 표지판의 OCR `김처찌개`와 그림 판독 `김치찌개`가 **REVIEW**로 연결된다. 사각형은 원본 1536×1024에서 대략 x963–1072, y832–878이다. 오탈자 확정 FAIL이 아니라 서로 다른 판독의 원본 확인 요청이다. `한북/한복 체험`은 음절 검사 간 결과가 흔들리고 최신 검사에서는 두 모델 모두 한복으로 읽어, 안정적인 검출에 도달하지 못했다.

추가 손 판독이 미검출이었다는 사실을 사용자 지적으로 만든 자동 FAIL로 바꾸지 않았다. 사용자에게서 들은 오류 설명을 정답처럼 복사하여 자동 검출 성공률에 포함하지 않는다.

### 대조 사례와 한계

아래는 **저장 관찰에 새 정밀 경로만 적용한 평가**다. 전체 그림·원문 규칙을 새로 실행한 비교가 아니며, 이 결과로 전체 검출률/오탐률 향상을 주장할 수 없다.

| 사례 | 실행 결과 | 해석 |
|---|---|---|
| QA_03 | 글자 획 출력 길이 초과 | 검사 미완료. 정상/미검출 표본으로 계산하지 않음. 최종 10,000 상한에서 재검증하지 못함 |
| QA_07 | 글자·독립 음절 3회 + 번짐/선명 획 대조 2회 완료 | 비빔밤 관련 음절 차이는 REVIEW. 판독 확신/품질을 분리한 후 번짐 영역을 위치 있는 FAIL로 검출. 선명한 글자 대조에서는 품질 CLEAR |
| QA_02 | 손 위치 완료, 구조 요청 시간 초과 | 구조 검사 미완료 |
| QA_08 | 손 위치 완료, 구조 요청 평가 한도에서 차단 | 정상 손의 오탐률을 검증한 것으로 계산하지 않음 |

QA_07의 마지막 대조 2회는 이전 획 검사에서 가장 낮은 문자 영역과 선명하게 판독됐던 짧은 문자 영역을 선택한 집중 검증이다. 기대 문자열·결함 종류는 요청에 넣지 않았다. 번짐 FAIL은 원본 crop 좌표로 검증했으며, 선명 획의 CLEAR는 철자 정상이라는 뜻이 아니다. 두 사례만으로 전체 오탐률을 산출하지 않는다. 검수 이력 `QA_07`의 `87630f7596a84de39d58dd448d8f9c39` 버전에 실제 판독 5회와 새 근거를 저장했다. 이 버전도 기존 전체 분석에 추가 근거를 반영한 것이며 새 전체 실행은 아니다.

QA_07의 기존 전체 검사에는 이 번짐에 대한 결함 기록이 이미 있었다. 이번 결과는 새 독립 획 검사 경로가 같은 결함을 다시 설명하고 표시하게 된 검증이며, 기존 시스템에서 놓친 새 결함 1건을 발견한 것으로 집계하지 않는다.

따라서 이번 변경은 **정밀 경로 통합, 위치·근거 누락 보완, 번짐 표본의 품질 판정**까지 검증했으며, 사용자가 원하는 손 중복과 뭉개진 한글을 모두 자동 검출하는 수준은 아직 아니다. 독립 판독 횟수를 늘리는 것만으로 해결되지 않았다. 향후에는 실제 결함/정상 가림이 짝지어진 ROI 평가를 확보한 후 구조 판독 방법을 비교해야 한다. 현재 코드의 회귀 테스트 통과와 모델의 실제 결함 검출 성능은 별개다.
