# 검수 이력의 검사 열기 성능 개선 — 2026-11-06

## 적용 내용

- 화면은 `GET /api/jobs/{id}?view=screen`으로 최신 검사 한 개를 받는다. 모든 발견 항목·관찰·좌표·검토 기록·단계별 토큰은 유지하고, 큰 규칙집과 기준자료 스냅샷은 화면에서 사용하는 요약만 전달한다.
- 개별 의견을 처음 선택하면 인증된 `GET /api/jobs/{id}/runs/{run_id}/details`에서 **그 검사 버전**의 규칙집과 기준자료를 받아온다. 동시 선택은 한 요청을 공유하며 실패 시 재시도 버튼을 제공한다. 다른 검사로 이동한 뒤 도착한 응답은 현재 화면을 덮어쓰지 않는다.
- 이력 JSON에는 gzip 압축을 적용한다. 원본 PNG·PDF에는 재압축을 적용하지 않는다. 인증과 `Cache-Control: no-store`를 유지한다.
- 검사 열기를 누르면 이미지와 결과를 동시에 요청한다. 버튼에 로딩 상태를 표시하고, 빠르게 다른 검사를 선택하면 이전 결과 응답을 무시한다. 실패 시 이전 검사 화면을 유지한다.
- 원문별 결과의 접힌 상세 내용은 펼칠 때 생성한다. 인쇄 전에는 해당 원문별 상세 내용을 채워 넣는다.
- 문제 묶음 계산은 검사 데이터·검토 데이터·선택·정상 영역 표시·이미지 크기가 같을 때 재사용한다. 데이터나 표시 조건이 바뀌면 다시 계산한다.
- 기존 `view=latest`, 기본 전체 상세 조회 및 JSON 보고서의 응답 내용은 보존한다. 저장 데이터나 분석 알고리즘은 변경하지 않는다. 분석 진행 중 조회는 기존 `view=latest`를 유지한다.

## 측정

대상: 저장된 `ImageGen_Exploratory_01`, 최신 1개 버전·236개 결과. Chromium, 화면 1500×1000, 로컬 서비스에 다운로드 **10Mbps·지연 80ms**, 첫 이미지 로딩을 모의했다. 같은 측정 스크립트의 변경 전후 단일 표본이며 사용자 인터넷 환경의 보장값은 아니다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 결과 표시까지 | 1.116초 | 0.371초 |
| 원본 이미지와 결과 표시까지 | 3.411초 | 2.436초 |
| 결과 JSON 실제 전송 본문 | 1,139,915바이트 | 117,038바이트 |

후속 이미지 요청 대기를 없앴고, 첫 결과 전송량은 약 90% 감소했다. 원본 이미지는 보존하므로 느린 연결에서는 이미지 전송 시간이 여전히 남는다. 이미지 축소나 문자 품질 손실을 감수해 시간을 줄이지 않았다.

DB 상세 조회는 기존 기본키 인덱스를 사용한다. 이번에는 추가 인덱스나 DB 마이그레이션을 도입하지 않았다.
