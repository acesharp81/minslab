# 손·글자 선택 확대 재검사 보완 — 2026-11-06

## 첨부 결과에서 확인한 원인

사용자가 제공한 Exploratory 01의 분석 재실행 결과는 전체 관찰과 이전 확대 판독을 재사용했다. 새 로컬 검사는 SHADOW 상태로 후보만 기록했고, 손 이상으로 이미 기록된 객체만 후보로 골랐다. 따라서 손 구조가 미기록되었거나 부분 확인인 경우를 새로 판독하지 않았다.

기록에는 남성 손짓이 PARTIAL, 두 아이의 손짓이 확대 객체 한도로 미실행인 상태가 있었다. 체험 표지판도 PARTIAL이었다. 그림 관찰 자체가 없는 것과, 저장된 위치는 있지만 충분히 확대 확인하지 못한 것을 구분해야 한다.

한 OCR 줄을 전체 문구/지도 지명 묶음과 직접 비교하는 문제도 있었다. 같은 첨부 기록과 원본을 로컬로 재현했을 때, 문구 일부 일치를 구분한 후 READING_DISAGREEMENT 후보는 12→4곳이었다. 이는 판독 비교 범위 보정이며 실제 손/문자 결함 검출률 개선을 입증하는 수치가 아니다.

## 적용한 동작

- **분석 재실행**: 저장된 그림 관찰을 사용해 규칙을 다시 분석한다. 새 손/글자 판독을 수행한다는 의미가 아니다.
- **손·글자 확대 재검사**: 기존 이력에서도 사용할 수 있다. 손/글자 객체와 확대 범위를 표시하고 관리자가 선택한다. 부분 확인·확대 미실행·세부 구조 미기록을 우선 제안하며, 기존 CLEAR도 재선택할 수 있다. 제안 목록 자체는 오류 목록이 아니다.
- 최대 6개 영역, 3개씩 묶어 확대 이미지 호출 최대 2회. 기존 AUTO_VERIFY_MAX_CALLS/OBJECTS가 더 작으면 그 설정을 따른다. 이후 선택 영역에 따라 손 관련 D-02-c~i와 문자 관련 H-06-b/D-02-l만 재분석한다. 관계없는 항목은 선택한 원본 검사 버전의 결과를 유지하여 156개 행동 전체 재분석 비용을 피한다. 관련 분석 토큰은 별도로 사용된다. 전체 그림 읽기 및 NAVER OCR을 다시 호출하지 않는다. 이 경로에서는 별도 pixel-confirm 호출을 추가하지 않는다.
- 화면에서 선택한 그림 읽기/분석 모델을 사용한다. 고가 모델로 자동 승급하지 않는다. 기존 공급자 공용 한도 예약과 호출별 사용량 기록을 그대로 통과한다.
- 텍스트는 **하나의 객체에 유일하게 연결되고 전체 문자열이 일치하는 OCR 경계**가 있으면 그 경계에 여백을 붙인다. 문구 일부만 일치하거나 위치 연결이 모호하면 이를 객체 전체 경계로 사용하지 않는다. 손은 지정 격자 주변 1셀의 손목/팔 문맥을 남긴 원본 crop을 사용한다. 기존 일반 확대의 2셀 여백보다 좁혀 주변 인물의 혼입을 줄이며, 경계에 손이 잘렸으면 PARTIAL로 남긴다. 생성형 선명화/획 복원은 하지 않는다.
- 판독 요청에는 이전 전사나 이전 정상/오류 결론을 제공하지 않는다. 글자별 획 품질과 보이는 손 구조를 별도로 요구한다. 전사 성공을 획 정상의 증거로 사용하지 않는다. 접힘/가림 자체를 손 이상으로 판정하지 않는다.
- 집중 재판독에서 hands 또는 glyph_checks를 누락하면 COMPLETE를 인정하지 않는다. 실패/부분 확인 때문에 이전 유효 관찰을 지우지 않으며 새 시도는 별도로 보관한다. 부분 판독에서 구체적으로 관찰한 원본 글자 결함이나 손 이상은 범위를 한정해 기존 근거 보호 경로로 전달한다.
- 글자/손 재판독은 기존 공식 도안 비교를 새로 한 것으로 취급하지 않는다. 기존 비교는 원래 crop·호출·기준자료 해시와 함께 reference_results에 보존하며 규칙/기준자료 변경 검증을 유지한다.
- 결과 하단 ‘관찰 기록 · 토큰 사용량’에 **선택 영역 새 판독 결과**를 표시한다. 이번 호출 이벤트가 없는 옛 결과는 새 판독 완료로 표시하지 않는다.

## 자동 실행 범위

로컬 후보의 자동 추가 재판독(ARTIFACT_RECHECK_ENABLED)은 여전히 기본 꺼짐이다. 이번 기능은 관리자가 원본 확대와 영역을 확인하고 직접 실행하는 별도 경로이다. 검토자는 실행할 수 없다. 기존 이력의 판정이나 표시 번호를 소급 변경하지 않았다.

GET `/api/jobs/{jid}/runs/{run_id}/quality-plan`은 읽기 전용이며 해당 버전의 관찰로 계획만 만든다. POST runs의 `quality_recheck=true`는 관찰 재사용 버전과 유효한 대상 ID가 필수이다. ID·선택 수·중복·위치·한도는 서버에서도 검증한다.

## 검증과 한계

- Python 전체 회귀 289 통과, 2 생략. 실제 HTTP 공급자 전송을 차단했으며 외부 요청 시도 0회.
- JavaScript 회귀 71 통과. 선택/취소, 기존 판독 재사용, 새 호출과 재사용 근거 표시 구분, 확대 미리보기 등을 검사했다.
- 실제 서비스 브라우저에서 15개 선택 대상, 6개 선택 한도, 실행 취소, 모바일 가로 넘침 없음, 검토자 버튼 숨김, 기존 결과·관찰·좌표 보존을 확인했다. 분석 POST 0회, JavaScript 오류 0건.
- 화면 그룹 병합이 원본 관찰의 좌표 배열에 좌표를 덧붙이던 문제도 수정했다. 화면 크기를 바꿔 재렌더링해도 저장 좌표를 변형하지 않는다.
- 실제 LLM/OCR 호출 테스트는 사용자 요청대로 보류했다. 따라서 실제 검출률/오탐률 개선은 아직 측정하지 않았다. 모의 응답 검증은 입력·한도·근거 전달 경로를 확인하는 시험이다.
- 별도 손 탐지 모델을 도입한 것은 아니다. 기존 관찰에 위치조차 없는 손은 선택 목록에 없을 수 있다. 격자가 손 전체를 충분히 포함하지 못하거나 원본 자체가 너무 작으면 확대 재판독도 미완료가 될 수 있다.
- 일부 문구가 다른 큰 문구 안에 들어간다는 것만으로 해당 글자가 정상이라는 결론은 내리지 않는다. FRAGMENT_MATCH 상태로 전체 전사 일치와 구분한다.

실제 평가를 재개할 때는 QA_02·QA_03·QA_07·QA_08·QA_10 및 정상적인 브이/주먹/가림 사례를 함께 확인한다. Exploratory 01은 보고된 실패의 회귀 사례로 사용하고 정답 내용은 판독 프롬프트에 넣지 않는다. 일일 GPT-5.4/mini 한도 안에서 진행하며 유료 Sol/Astra 승급은 자동 실행하지 않는다.
