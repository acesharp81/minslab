# 원문 체크리스트 중심 분석 복구

## 문제

특정 샘플의 4괘 비교가 화면 상단과 실제 판정 경로를 차지했다. H-04-h/i는 로컬 측정으로 모델 평가를 대체했고, 관찰을 재사용하는 전체 재분석이 마지막 부분 검사 범위를 상속했다. 원문 25개 질문의 개별 판단은 결과 화면에서 파악하기 어려웠다.

실제 전체 검증에서 추가로 발견한 문제는 응답 압축이었다. `groups`/`assignments`는 156개 ID를 모두 채워도 하나의 가독성 의견을 지도·역사·차별 항목에 돌려 쓸 수 있었다. 부모별 그룹 ID만 강제해도 같은 부모의 서로 다른 세부 행동에 판정이 퍼졌다. 형식상 완료를 내용상 완료로 잘못 간주했다.

## 최종 변경

- 원문 25개 질문을 이미지 관찰 단계와 해당 텍스트 분석 요청에 전달한다.
- 전체 재분석은 항상 156개를 요청한다. 부분 검사·확대 재검사는 지정 범위를 유지한다.
- 4괘 측정은 H-04의 보조 근거이며 해당 항목이 없는 요청에는 보내지 않는다. H-04-h/i 역시 모델이 원문·퀴즈 문맥에 따라 평가한다.
- 원문을 쪼개지 않는 최대 40개 세부 행동·6개 원문 단위로 요청한다. 현재 전체는 5묶음, 동시 요청은 2개다.
- 모델은 `assessments`에 각 rule_id의 판정·적용성·근거·이유·조치를 개별 반환한다. 공통 의견을 여러 규칙에 할당하는 형식은 제거했다. 이미지 관찰 재사용, 묶음 전송 및 공통 스키마로 비용을 줄인다.
- 이용권 증빙과 검사 대상의 부재를 구분한다. 원문 D-03-e의 필수 증빙을 `NOT_APPLICABLE`로 우회하지 못하게 검증한다.
- 첫 결과 화면과 JSON 보고서에 동일한 원문 25개별 질문·관찰 근거·분석 의견·확인 사항·모델·자료·완료 범위를 제공한다. H-04 보조 측정은 해당 카드의 접힌 상세에만 표시한다.
- 이전 검수·관찰·규칙 스냅샷은 보존한다. 기존 로컬 전용 결과는 원문 AI 분석 완료로 집계하지 않는다.

## 검증 범위와 한계

원문 25개/156개 매핑, 원문을 분할하지 않는 전체 배치, 개별 규칙 응답 및 누락 거부, 부분 검사 후 전체 재분석, 이미지 재사용, 이용권 증빙, 관리자 MD 편집, JSON 내보내기를 검증한다. 실제 제공 이미지의 모든 원문 항목을 Solar로 재분석하고 개별 판단을 읽어 확인한다. 한 사례 검증은 모든 홍보물에서의 정확도를 보장하지 않는다. 승인되지 않은 역사·정책·권리 자료와 이미지에서 읽지 못한 내용은 검토 대상으로 남긴다.

실측(2026-10-29): GPT-5.4로 새로 수집한 관찰을 재사용한 Solar 전체 분석은 5호출, 입력 36,538 / 출력 13,199 토큰, 추정 $0.0268002, 186.91초였다. 25/25 원문과 156/156 행동이 응답했으며 실행 ERROR는 0이었다. 판정 하나를 재사용하는 최적화보다 느리므로 속도 개선 여지는 남는다. 이 숫자는 1회 실측이며 지연 보장값이 아니다. 실제 의미 검토에서 라이선스의 증빙 부재를 대상 부재로 처리한 응답을 확인하여 D-03-e 필수 검증을 추가했다.
