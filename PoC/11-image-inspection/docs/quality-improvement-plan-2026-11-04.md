# 췤미! 경고 정밀도·한글 검출 보완 계획

기준일: 2026-11-04. 사용자 제공 「췤미! 현행 기능과 타 홍보물 AI 검수 웹앱 계획서 비교·보완 분석」을 현행 코드·운영 설정·저장 검사와 대조했다. **이 문서는 검토 결과와 개발 계획이며, 아래 변경의 구현·배포 완료 보고가 아니다.** 이번 검토에서 모델 호출·외부 OCR 호출·토큰 사용은 없었다.

## 1. 검토 결론과 첨부안의 적용 순서

첨부안의 ‘기존 기능 재사용, 조건부 검사, 관찰과 판단 구분, 정답 품질관리’ 방향을 채택한다. 우선순위는 현재 사용자 문제에 맞춰 바꾼다.

1. **손의 자연스러운 접힘·가림이 노란 경고가 되는 문제를 먼저 줄인다.** 관찰하지 못한 부분과 실제로 이상한 부분을 구별한다.
2. **문자 누락·판독 불일치가 검사에서 빠지는 경로를 보완한다.** 정확해 보이는 전사만 철자 검사하는 현재의 안전장치가 어려운 문구를 놓치는 원인이 되기도 한다.
3. **기관명·지명·승인 원고 대조를 강화한다.** 기존 사전과 원고 대조를 확장하고, 이미지의 글자를 독립 확인한 뒤 정본과 비교한다.
4. **QR·URL·연락처 전용 검사는 다음 순서에 둔다.** 유용한 추가 기능이지만 현재 손 경고·한글 미검출을 직접 해결하는 기능은 아니다.
5. 제복 부위별 대조와 PDF 입력은 뒤이어 검증한다. 전문 탐지 모델·GPU 상시 운영은 현재 병목을 해결할 근거가 확보된 후 판단한다.

## 2. 실제로 확인한 병목

### 손: 관찰 불완전을 경고로 확대하는 두 경로

- `app/observations.py`의 분석 지침은 주먹으로 가려져 확인 불가하면 PRESENT/REVIEW를 유지하도록 한다. `ObjectObservation`에는 손별 자세·보이는 범위·실제 결함을 구별하는 전용 필드가 없다.
- `web/app.js`의 `reviewMarkerKind()`는 직전 수정에서 손 관련 행동의 `READING_LIMIT`를 기본 이미지 번호에 허용했다. 이 조건은 구체적인 이상 소견 없이도 손가락 전체를 셀 수 없다는 이유로 노랑을 만든다.
- 규칙집 `rules/current-reviewed-v2.5.md`와 D-02-f에는 주먹·원근·겹침 예외가 이미 있다. 규칙 부족보다는 분석 지침·정규화·표시 조건의 연결 문제다.
- `app/rules.py::validate_batch()`는 불확실한 관찰과 사람 검토 정책에 따라 PASS/FAIL을 REVIEW로 바꾼다. 따라서 REVIEW 전체를 이미지 경고로 보면 승인 확인·판독 한계·실제 결함 후보가 섞인다.

저장된 Exploratory 02의 남성·아동 손 관찰에는 ‘엄지를 제외한 손가락은 접힘/가림’, ‘노골적인 여분 손가락은 보이지 않음’, ‘손바닥 연결은 자연스러움’이 있다. Exploratory 01에도 ‘브이 자세·나머지 손가락 접힘·명백한 추가 손가락 없음’이 있다. 이 기록들은 펼친 다섯 손가락을 확인하지 못했다는 사정만으로 기본 경고를 만들면 안 되는 사례다. 실제 손 모양의 정답을 이번 문서 검토만으로 새로 확정하지는 않는다.

### 문자: 판독 일치 중심의 후보 선정과 제한된 획 비교

- 운영 `.env`는 `OCR_ENABLED=false`다. 이는 **전용 GPT 독립 OCR 판독·NAVER 분기를 매번 실행하지 않는다는 의미**다. `app/pixel_text.py`에서 사용하는 로컬 Paddle 탐지·인식은 별도로 작동하고 있다.
- `scripts/ocr_worker.py`는 이미 탐지와 인식을 별도 모델로 처리한다. 원본 타일 겹침, 저신뢰/빈 전사 영역 보존, 최초 관찰의 문자 후보 보충도 있다. 이를 새로 만들기보다 후속 검사에서 활용해야 한다.
- `app/spelling_audit.py::candidates()`는 주로 Paddle 인식 신뢰도 ≥0.9, 탐지 신뢰도 ≥0.55, 최초 관찰과 전사 일치, 유일한 객체 연결을 요구한다. 독립 확인된 획 전사도 받을 수 있다. 반면 판독 불일치·낮은 인식 신뢰도·반복 문구·최초 관찰 누락은 후보에서 빠지기 쉽다.
- `app/pixel_text.py::inspect_regions()`의 글꼴 획 대조는 수평·단순 배경·짧은 한글 2~6자에 제한된다. 긴 줄·장식체·기울어진 간판 전체를 검사하는 일반 해법이 아니다. 현재 일부 제외 경로는 `continue`로 끝나므로 영역별 제외 사유를 더 남겨야 한다.
- `app/text_location.py`도 높은 OCR 신뢰도와 전사 일치에 기대는 경로가 있다. 문제가 있는 문구는 결과가 생성돼도 정밀 위치 연결이 어려울 수 있다.
- `app/evidence_guards.py`와 `rules/official-terms.json`의 전용 명칭 기준은 현재 행정안전부·KOREAN AIR 2종이다. 라벨·정체성 문맥 조건이 있으므로 모든 책등·표지석·간판을 동일하게 대조하지 않는다.
- `app/source_copy.py`에 승인 정본과 문자 단위 대조가 이미 있다. 이미지 해시와 정확한 라벨 연결이 필요하며 라벨이 없거나 중복되면 보류한다. 신규 구현보다 등록·대상 연결을 쉽게 만드는 보완이 필요하다.

운영 DB의 최신 저장 버전에서 확인한 문자 처리 규모:

| 자료 | 로컬 탐지/후보 영역 | 픽셀 측정 처리 영역 | 독립 철자 검사 입력 문구 |
|---|---:|---:|---:|
| Exploratory 01 | 25 | 17 | 3 |
| Exploratory 02 | 26 | 14 | 5 |
| Exploratory 03 | 39 | 17 | 5 |
| QA_03 | 13 | 13 | 7 |
| QA_07 | 13 | 13 | 5 |

영역과 문구의 단위가 달라 위 비율을 오탈자 검사 완료율로 해석할 수 없다. 픽셀 측정 완료도 모든 글자의 철자·획 정상 검증 완료를 뜻하지 않는다. 다만 탐지한 후보 중 별도 철자 검사로 넘어간 대상이 제한적이라는 병목은 확인된다.

### 해상도·모델 설정: 이미 구현된 부분과 남은 문제

- 업로드는 원래 픽셀 크기를 보존한 정규화 PNG로 저장한다. 전체 관찰은 `app/engine.py::resized()`에서 최대 1536px로 축소한다.
- `app/providers.py`는 OpenAI 확대 판독 및 지원 모델의 문자 검사에 이미 `detail=original`을 사용한다. 전체 이미지 호출은 운영 설정 `high`다.
- 문자 고강도 재검사, 확대 판독의 별도 추론 강도, 최대 6글자의 독립 획 비교도 있다. 모든 호출을 높은 추론 강도로 바꾸는 것은 우선 해법이 아니다.
- 따라서 **원본 crop을 보낼 후보 선정과 미처리 영역 연결**을 먼저 개선해야 한다. 그림 읽기에서 빠진 정보를 mini 재분석만 반복해 복구할 수는 없다.

## 3. P0 — 손 판단과 기본 표시 기준 조정

### 구현 항목

1. 손 관찰을 인물·좌우 손 단위로 연결한다. 신규 관찰에 자세(주먹/브이/엄지/쥐기/펼침/불명), 가림 원인, 확인한 손바닥·손목·관절 범위, 실제 이상 부위, 재검사 결과를 구조화한다. 화면의 좌우와 인물의 좌우를 구분하고 확정 불가 시 추측하지 않는다.
2. 보이는 부분이 자연스럽고 나머지가 접힘·물건·원근으로 가려진 경우, ‘다섯 손가락 전체 미확인’만으로 결함 후보를 만들지 않는다. 확인 범위는 기록한다. 보이지 않는 부분까지 정상으로 인증하지 않는다.
3. 여분 손가락·융합·비정상 분기·관절 연결처럼 **구체적인 이상 소견**이 있으면 관련 손에 노랑 또는 근거가 명확할 때 빨강을 유지한다. 이상이 의심되는 부위를 실제로 구별할 수 없는 경우는 원본 확인이 필요한 REVIEW로 남긴다.
4. 기본 번호는 실제 관찰 차이 또는 조치가 필요한 특정 미확정 사항에 한정한다. 자연스러운 접힘·가림뿐인 `READING_LIMIT`는 기존 ‘번호 없는 검토 의견’으로 보낸다. 단계·세부 행동마다 같은 손 경고를 반복하지 않는다.
5. 기록된 이상 관찰과 승인·기준 부족을 분리한다. `document_review`나 증빙 미확보라는 이유만으로 구체적인 기관명·지명 차이를 숨기던 예전 동작으로 되돌리지 않는다.
6. 기존 이력에는 추가 시각 확인을 했다고 표시하지 않는다. 저장 판정을 덮어쓰지 않고 호환 표시 정책을 적용한다. 근거가 부족한 옛 기록을 임의로 PASS로 승격하지 않는다.

### 수용 조건

- 정상 주먹·브이·엄지·물건 쥐기·원근·부분 가림·캐릭터 손을 포함한 고정 표본에서, **가림만을 이유로 생긴 기본 노란 경고 0건**을 목표로 한다.
- 여섯 손가락·융합·분기·관절 중복·비정상 접합 정답 사례의 경고 회수율은 기준선보다 낮아지지 않아야 한다.
- ‘검토 의견 자체를 지워 경고 수를 줄이는 것’과 ‘자연스러운 가림을 정상 범위로 해석하는 것’을 구별해 채점한다.

## 4. P1 — 문자 경로 보완

### 후보를 버리지 않고 검사 경로를 나눈다

기존 탐지 결과와 객체 관찰을 공간 겹침·줄 순서·문구 특성으로 연결한다. 문자열 완전 일치는 연결 보조 근거로 쓰고, 완전 일치하지 않는 후보도 보존한다. 떨어진 문구를 하나로 합치거나 반복 문구를 임의의 첫 객체에 붙이지 않는다.

| 후보 | 처리 |
|---|---|
| 독립 판독이 일치하고 획 문제가 없는 문구 | 기존 mini 철자 검사에 묶음 전달 |
| 판독이 다르거나 일부 문자가 불확실함 | 원문별 전사·불확실 음절·crop을 보존하고 제한된 독립 원본 재판독 후보로 전환 |
| 탐지했지만 읽지 못했거나 관찰 목록에서 누락됨 | 탐지 좌표로 문자 존재와 실제 글자 품질을 재확인. OCR 실패만으로 홍보물 오류 확정 금지 |
| 문맥상 자연스러워도 획 형태와 충돌함 | 단어 문맥을 제공하지 않는 기존 음절 획 비교 활용 |
| 획 비교 미지원/예산 보류/실행 실패 | 제외·보류 사유를 남기고 완료·정상 수에 포함하지 않음 |

### 검사 내용과 위치를 함께 보강한다

- 탐지·전사·철자·가독성·정본 대조의 단계별 상태를 기록한다. 기존 최종 상태 6종은 유지하고 부가 검사 근거로 연결한다.
- `김처찌개` 같은 선명한 실제 오자는 원문을 확인한 뒤 철자 비교한다. `한북/한복`, 끊긴 `리`, 이상한 `ㄹ` 같은 획 문제는 문맥상 정답을 먼저 제시하지 않고 형태를 독립 확인한다.
- OCR과 GPT가 서로 다른 단어를 읽은 것 자체는 도구 간 불일치다. 원본 글자의 실제 오류·가독성 손상이 확인되기 전에는 동일한 빨간 오류로 처리하지 않는다.
- 원본을 확인한 뒤에도 판독이 불명확하면 불확실 음절과 원인을 표시한다. 양쪽 엔진이 같은 자연스러운 문구를 냈다는 이유만으로 획 정상을 인증하지 않는다.
- 작은 글씨는 원본 crop과 문맥 여백을 사용한다. 생성형 복원·샤프닝으로 새로운 획을 만들지 않는다. 기울어진 영역은 기존 OCR 다각형을 활용한 비생성형 정렬을 시험하되, 원본 좌표로 역변환하고 미지원 변형은 보류한다.
- 위치는 독립 탐지 박스와 대상 연결 근거로 검증한다. 실제 글자 경계를 확인하지 못하면 격자 사각형을 정밀 경계로 표시하지 않는다.
- 각 영역에 `전사 없음 / 불일치 / 획 비교 미지원 / 예산 보류 / 실제 획 결함 / 정본 차이` 등의 사유를 남긴다. 대상별 누락을 관리자와 평가기가 볼 수 있게 한다.

### 비용 조건

- 로컬 탐지 결과·원본 crop·검증된 전사·변경되지 않은 기준은 재사용한다. 문구별 호출 대신 기존 묶음 요청을 사용한다.
- 후보가 많으면 기관명·주요 제목·작은 안내·숫자/날짜를 균형 있게 선택한다. 본문이나 시험용 큰 제목 하나가 검사 예산을 독점하지 않게 한다.
- 전용 OCR 전체 경로를 일괄 활성화하지 않고 중요도 높은 누락·불일치 후보에 한정해 기존 GPT-5.4 추가 판독 예산을 배분한다. 기존 확대 상한과 별개로 무제한 호출이 늘지 않도록 **검사 전체의 공통 상한**을 둔다.
- mini는 문자 판독 확정 후 철자·문맥 판단에 사용한다. 이미지 정보가 없는 mini에 반복 질문하지 않는다.
- NAVER는 실제 불일치·중요 후보에서만 선택적으로 사용하고, 앱 원장의 월 100회 API 호출 상한과 매월 1일 갱신을 유지한다.
- GPT-5.4/mini는 PoC7 일일 공용 한도의 원자적 예약을 통과한 호출만 수행한다. GPT-6 Astra/Sol은 반복 미검출 사례의 제한된 비교 검증 대상으로 둔다.

## 5. P1 후반 — 정본·명칭·기준자료 연결

- `rules/official-terms.json`을 버전·적용일·대상 유형·공식 출처·허용 별칭·검토자·연결 규칙을 가진 기준표로 확장한다. 브랜드·옛 명칭·의도된 카피를 근접 문자열이라는 이유만으로 수정하지 않는다.
- 기관명은 라벨에 ‘기관명’이 있는지뿐 아니라 책등·간판·표지석 등 실제 용도를 확인한다. `KOREA AIR`는 대한항공을 지칭한다는 근거와 승인 표기가 있을 때 비교한다.
- 다국어 동해/독도 명칭, 기관명, 정책 용어, 연락처 기준을 유형별로 관리한다. 교육·역사적 인용과 실제 사용 문구를 구별한다.
- `app/source_copy.py`의 정본 대조를 재사용한다. 이미지 해시·객체 ID·탐지 영역·라벨로 원고 대상을 연결하고, 중복·충돌은 관리자에게 확인받는다. 원고는 판독 이후 대조에만 사용해 기대 정답이 이미지 판독에 섞이지 않게 한다.
- 문양은 `person_id → 모자/가슴/어깨/견장`으로 분리한다. 관련 기준의 소속·시기·부위가 맞는 경우만 대조한다. 한 부위가 불명확하다고 다른 부위 결과까지 보류하지 않는다.
- 출처 없는 일반 용어 목록을 즉시 승인 기준으로 자동 등록하지 않는다. 출처 원문 대조와 적용 대상·시점 대조를 각각 완료한 자료만 사용한다. 내부 PDF 사례 사진과 공식 정상 도안은 계속 구분한다.

## 8. 평가·배포 조건

현재 `scripts/evaluate.py`/`score_suite.py`는 FAIL 검출·오탐·REVIEW 비율·위치 대응을 계측한다. 하지만 **정상 대상에 표시된 노란 번호의 부담**은 FAIL 오탐률과 별도다. 기존 평가를 재사용하면서 아래를 추가한다.

| 지표 | 측정 단위와 기준 |
|---|---|
| 실제 결함 검출률 | 정답 결함별 판정·대상·근거 위치 일치. REVIEW 발견과 FAIL 확정을 별도 집계 |
| 정상 손 경고율 | 정상 자세로 라벨된 손 중 기본 노란/빨간 번호가 붙은 손 비율 |
| 실제 경고의 정밀도 | 화면 경고 중 사람 라벨로 결함 후보/필수 검토로 인정된 비율 |
| 문자 탐지 누락률 | 정답 문자 영역 중 탐지/객체 후보 모두 연결되지 않은 비율 |
| 판독·철자·가독성 구분 | 문자 오인식, 실제 오자, 실제 획 손상, 미검사를 별도 채점 |
| 위치 정확도 | 정답 ROI와 실제 글자·손 근거 위치 대응. 넓은 영역 겹침만으로 성공 처리하지 않음 |
| 비용·지연 | 단계/모델별 호출·입력·출력·미확정 사용, OCR 호출, 전체 검사 p50/p95 |
| 미처리 비율 | 예산 보류·미지원·도구 실패·연결 실패를 분리. 정상으로 계산하지 않음 |

순서는 **저장 결과 재생 → 로컬 회귀 → 필요한 경우 소규모 실제 호출 → 기본값 반영**으로 한다.

- QA_03·QA_07, 기관명·정본·숫자·도안 사례를 회귀에 포함한다. Exploratory 3종은 사용자가 이미 오류를 알려준 개발 사례로 관리하고 독립 평가 성능으로 내세우지 않는다.
- 정상 가림 손, 실제 변형 손, 정상/오타/뭉개짐/기울임/장식체/저해상도 문자를 구분한 평가 표본을 추가한다. 경고 회피를 위해 오류 정답을 정상으로 바꾸지 않는다.
- 과거 정답의 rule_id가 현재 의미와 달라진 경우 버전형 대응표와 근거를 남긴다. 정답 ROI·판정은 채점에만 사용하고 추론 입력이나 후보 탐지에는 넣지 않는다.
- 저장 결과 재생은 UI 변경 검증에만 사용한다. OCR 경로 개선의 성능은 같은 이미지·같은 기준의 재검사로 별도 비교한다.
- 과거 보고서의 선택된 7장 A/B에서 FAIL 9/15, 정상 오탐 1/14 등이 있었으나 이는 그 당시 설정·표본의 결과다. 현재 제품 전체 정확도로 인용하지 않는다.
- 정상 손 경고가 감소해도 실제 손 결함·기관명·오탈자 검출이 후퇴하면 기본값에 반영하지 않는다. 지표가 충돌하면 대상별 동작을 보정하고 반복 검증한다.

## 9. 다음 개발 단위

첫 배포 단위는 **P0 손 판정·표시 정리 + 영역별 미처리 사유 계측**으로 제한한다. 그다음 **P1 문자 누락/불일치 연결·원본 재판독·철자/정본 대조**를 별도 비교한다. QR/PDF까지 한 번에 묶어 어떤 변경이 결과를 개선했는지 알 수 없게 만들지 않는다.

이 계획은 표시 개수의 일괄 상한이나 모델 확신 점수 하나로 문제를 해결하지 않는다. 사용자가 확인할 가치가 있는 근거를 우선 표출하고, 미검사·인식 실패·문서 확인을 그대로 보존하면서 실제 오류 검출을 개선하는 것을 목표로 한다.
