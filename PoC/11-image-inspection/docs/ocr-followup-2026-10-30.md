# OCR 추가 검증과 이미지 확대 (2026-10-30)

## 화면에 반영한 기능

첨부 이미지 오른쪽 위의 − / 배율 / + 버튼으로 50~800% 확대·축소한다. 이미지 위 마우스 휠은 커서 위치를 기준으로 확대하며, 확대 상태에서는 드래그로 이동한다. 배율 버튼은 화면 맞춤(100%)으로 복귀한다. Ctrl/Command+휠은 브라우저 확대 동작을 유지한다.

이미지·사각형·번호 위치에 같은 좌표 변환을 적용한다. 번호는 역배율을 적용해 화면상 크기를 유지한다. 번호 그룹 계산은 확대 이전 크기를 사용하므로 확대할 때 번호가 바뀌지 않는다. 새 이미지 로드는 배율을 초기화한다. 진행 중 검수를 중단하지 않기 위해 기존 정적 JS/CSS 파일로 배포했다.

브라우저에서 버튼, 휠, 드래그, 맞춤, 번호 좌표·크기 유지, 모바일 가로 넘침 없음을 확인했다. 서버 회귀 테스트 115개 통과/선택 PostgreSQL 테스트 2개 생략, JS 테스트 11개 통과.

## OCR 코드 보완

- 원본 획 손상과 문자 전사 실패를 분리하도록 판독 지침을 구체화했다. 주변 여백의 다른 줄을 읽지 않도록 crop 내 대상 좌표를 전달한다.
- 독립 OCR의 영역 ID를 문자 규칙 분석의 허용 근거 ID에 포함했다. 이전에는 보조 텍스트로만 전달돼 직접 위치 근거로 선택할 수 없었다.
- 전사가 명확하고 일치하지만 공식 명칭 대조가 필요한 경우, 의미 불확실성을 전사 실패로 취급해 후속 오류 판정을 취소하지 않는다.
- NAVER 단어를 고정된 y 좌표 구간으로 정렬하면 같은 줄의 단어 순서가 바뀌었다. 수직 겹침으로 줄을 묶고 가로순으로 정렬하도록 수정했다. 단어별 위치·신뢰도를 남기고 줄 신뢰도는 문자 수 가중 평균으로 계산한다.
- OCR 추론 강도를 별도로 설정하고 캐시 키에 반영한다. **OCR_ENABLED=false는 유지했다.**

## 실제 결과

정답지는 채점 단계에서만 사용했다. QA_03·QA_07은 기존 첫 관찰과 Paddle 탐지 결과를 재사용했으며, 새로운 GPT 독립 판독과 NAVER를 적용했다. 분석 모델 전체 재실행이나 25개 규칙 전체 평가는 아니다.

| 구분 | 이전 | 이번 자동 OCR 비교 |
|---|---:|---:|
| 오류 확정 검출 | 0/4 | 1/4 |
| 정상 라벨 오탐 | 0/1 | 0/1 |
| REVIEW | 3/5 | 3/5 |
| 문자 전사 누락 | 2/5 | 2/5 |

이전 열은 첫 OCR 개선 경로의 결과다. 최초 기존 서비스 기준선은 REVIEW 2/5, 전사 누락 1/5였다. 이번 검출은 QA_03의 심하게 흐린 문구다. 개발에 사용한 작은 표본이므로 일반 성능 수치로 해석하면 안 된다. 별도 정상 대조 QA_08의 문자 13영역은 PASS 8, REVIEW 5, FAIL 0이었다. 이 13개는 라벨 단위 성능과 합산하지 않는다.

### 기본 경로와 구분한 탐색 실험

1. 불일치 단어를 원본 음절로 나누고 순서를 섞어 읽었다. `행정안정부가`는 정확히 재구성했고 두 전문 OCR과도 일치했다. 이 근거를 승인된 기관명과 대조하자 TYPO_CONFIRMED/FAIL이 나왔다. 반면 `비빔밤`은 잘못된 음절 연결이 발생해 재구성 결과를 채택하지 않았다.
2. 주변 문맥 crop과 상대 좌표를 제공한 고강도 검사에서는 작은 흐린 각주 대신 위쪽 큰 글자를 읽었다. 정상 결론으로 사용하지 않았다.
3. 원본과 최근접 4배 확대본을 함께 제공한 고강도 검사는 출력 한도 내에 완료되지 않았다. 복원·샤프닝을 하지 않은 같은 확대 자료를 단일 영역 저강도로 검사하자 작은 각주의 획 번짐을 DEFECT로 기록했다. 이 전처리는 별도 실험이며 현재 기본 경로에 포함하지 않았다.

별도 실험을 자동 경로의 검출률에 더하지 않는다. 실패한 경우를 숨기거나 답안에 맞춰 정상/오류 상태를 바꾸지 않았다. 다음 활성화 판단에는 단어별 재검사 안정성, 잘린 글자 처리, 작은 글꼴·의도된 효과의 오탐 평가가 필요하다.

## 사용량과 중단 기준

추가 GPT-5.4 요청 13회의 확인된 사용량은 37,656토큰이다. 대화 중단 당시 응답을 받지 못한 요청의 17,423토큰 예약은 보수적으로 유지했다. 공용 일 한도 잔여는 최종 6,790토큰, 다음 단일 영역 검사의 예약 요구량은 7,294토큰이어서 추가 전송을 중단했다. 예약량을 임의 해제하거나 한도를 높이지 않았다. NAVER는 재검사·단어 좌표 확인에 4회 추가 사용해 잔여 92회다.
