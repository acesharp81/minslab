# 2026-10-29 실제 태극기 검사 실패 수정

## 확인된 원인

- 운영 저장 기록: 372.04초, API 9회, REVIEW 145개, 누락 오류 11개. 세부 행동마다 같은 객체의 관찰을 반복 생성하고 이미지 전체를 여러 번 전송했다.
- 분석 모델이 셀과 기준자료를 다시 생성하면서 원래 관찰 범위를 벗어났다. 응답 누락이 발생하면 묶음 전체를 활용하지 못했다.
- 화면이 모든 세부 결과의 셀 테두리와 번호를 그려 가독성을 해쳤다. 선택한 객체 ID와 규칙 ID도 분리할 필요가 있었다.
- 테스트 수집의 `app.main` import가 전역 앱을 생성하고 운영 DB의 실행 상태를 중단으로 바꿀 수 있었다. 이로 인해 배포 전 DB상 진행 작업 확인만으로는 충분하지 않았다. 실제 서비스 재시작이 검사와 겹쳤고 종료 대기 시간 초과도 기록됐다.
- JSON 저장이 `location.href`로 이동하여 서비스 연결 오류가 작업 화면을 대체할 수 있었다. 보고서 직렬화 자체가 프로세스를 종료시켰다는 증거는 확인되지 않았다.

## 수정

원본 이미지 1회 관찰 → 객체/OCR/불확실성 저장 → 최대 78개 규칙씩 두 텍스트 요청. 동일 부모 내 같은 근거·판정의 행동을 한 응답으로 묶되 모든 행동의 누락·중복을 검증하고 개별 기록으로 전개한다. 일부 누락은 해당 행동만 오류로 남긴다. 새 분석 모델은 객체 ID만 재사용하고 위치를 만들 수 없다. 구버전 관찰은 불완전한 기록이라는 표시와 함께 복원한다.

번호는 객체별로 묶고 근접 번호는 모바일 크기에 맞춰 합친다. 선택된 위치만 탐색 테두리를 표시하며 증빙 확인은 번호에서 분리한다. 원본 전송에 격자선을 넣지 않는다. 이미지 재인식 없이 분석 모델만 바꾸는 이력 기능, 모델별 입력·출력 토큰, 공용 예산 한 카드, OpenRouter 공식 잔여 요청 조회를 추가했다.

모듈 import 부작용 제거, uvicorn 앱 팩토리 사용, async 종료 대기, fetch/Blob 다운로드를 적용했다. 테스트와 실제 검증은 임시 저장소에서 실행한다.

## 검증 결과와 한계

- 자동 테스트 49개. 그룹 응답 전개/누락·중복, 모델별 토큰, 이미지 1회, 재분석 이미지 0회, 원래 이력 보존, API 오류, 무료 공급자 요청, 인증, 참조/위치 검증 포함.
- 실제 동일 태극기 관찰을 재사용한 최종 방식: GPT-5.4 분석 51.16초/2호출, Solar 분석 34.14초/2호출. 네트워크·모델 부하에 따라 달라지며 속도 보장치가 아니다. 전사된 객체와 문구의 내용은 재분석 사이에 동일했다.
- 그 전 단계 전체 검사(구 묶음 방식): GPT-5.4 이미지 읽기 1회 + Solar 텍스트 분석 3회, 110.59초. 최종 두 묶음 방식의 전체 시간으로 인용하지 않는다.
- GPT-5.4 전체 선택 규칙 156개 분석 완료, 누락/중복/스키마 실행 오류 없음. Solar도 완료했으나 보류 판정이 더 많았다. 완전한 정답률/오탐률을 입증한 것은 아니다.
- 데스크톱/390px 모바일, 위치 번호 겹침 방지, 선택한 객체의 묶음 의견, 보고서 성공과 503 실패 후 화면 유지, 이력 재분석 요청을 브라우저에서 확인한다.
- OpenRouter의 실제 목록에서 이미지 및 구조화 응답 지원 확인. 키가 없어 실제 추론/계정 한도 조회는 하지 못했고 HTTP 모의 응답으로 검증했다. 키 설정 전은 '키 미설정', 카운터 미제공은 '잔여량 미확인'.
- OpenAI 데이터 공유 무료 토큰은 계정 참여 여부를 확인하지 못했다. 계정 설정을 변경하지 않으며 Standard 요금 기준의 공용 비용 원장을 그대로 사용한다.
- 공식 도안 미등록/직접 비교 미실시, 작은 괘/OCR 판독 불확실성은 검토 필요로 남긴다. 결과 수를 줄이려고 이를 정상으로 바꾸지 않는다.
