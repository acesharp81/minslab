# 독립 OCR·원본 획 검사 (2026-10-30)

## 범위와 전송 점검

원문 25개/156개 행동, 이미지 위치 격자, 객체별 번호·여러 의견 묶기, 검토 이력과 관찰 재사용은 유지한다. 새 OCR 근거는 D-02-l에 객체별 결과로 연결하고 H-06-b의 상충 판독을 정상으로 덮지 못하도록 한다. 규칙 문구는 수정하지 않았다.

업로드는 EXIF 회전·투명 배경 정규화 후 원래 픽셀 수의 PNG로 저장한다. 기존 전체 이미지 판독은 최대 1536×1536 축소본 + 최대 1800px 격자판, `detail=high`를 전송한다. 일반 재검사도 1536px thumbnail을 사용했다. 새 문자 경로는 이 thumbnail을 쓰지 않고 저장된 원본 PNG에서 격자 없는 crop을 만든다. 가로 8%, 세로 25%, 최소 4px 문맥 여백을 넣고 리사이즈·샤프닝·생성형 복원은 하지 않는다. crop 위치와 전송 픽셀 크기를 기록한다.

OpenAI의 지원 모델에는 `detail=original`을 사용한다. 이 옵션도 공급자 측 해상도 제한을 없애지는 않는다. Nemotron/OpenRouter에는 지원을 추정하지 않고 기존 high 경로를 사용한다. 기본 문자 판독은 low 추론, 상충하는 한 영역만 high 재검사한다. high를 모든 문자에 적용하면 출력 예산 소진과 지연이 커지는 것을 실제 시험에서 확인했다.

공식 근거: [OpenAI 이미지 detail·해상도 제한](https://developers.openai.com/api/docs/guides/images-vision), [GPT-5.4 문서/시각 인식 가이드](https://developers.openai.com/cookbook/examples/multimodal/document_and_multimodal_understanding_tips).

## 실행과 비용

1. Paddle 탐지: native 1280px tile, 192px 겹침, 중복 제거. 최대 24 tile/64 후보를 기본으로 제한하고 빠진 수를 기록한다.
2. 인식: `korean_PP-OCRv5_mobile_rec`. 빈 문자열/낮은 신뢰도도 삭제하지 않는다. 일반 시각 판독의 문자 유사 영역을 추가 후보로 사용한다. 서로 연결된 셀은 합치며 떨어진 블록을 한 crop으로 연결하지 않는다.
3. GPT 독립 전사·획 검사: OCR 문자열, 기존 GPT 답, 정답지 없이 crop만 6개씩 전달한다. 기본 24영역/4회, 실제 불일치 한 영역에 고강도 최대 1회. 원문 `literal_text`와 교정 후보 `suggested_text`는 별도다.
4. NAVER 설정이 있으면 불일치/누락이 있을 때 원본 한 장을 최대 1 API 요청으로 보낸다. NAVER가 찾은 추가 영역도 기록하며, GPT 획 검사가 없으면 REVIEW이다.
5. 텍스트가 아닌 지도·기관 문양·인체 등 기존 재검사는 유지한다. 전용 OCR에서 검사한 경우 텍스트 전용 중복 재검사를 줄인다.

Paddle은 외부 이미지 전송/건당 API 요금이 없지만 CPU·메모리·저장 비용은 발생한다. `.venv-ocr`와 공식 가중치는 배포 시 설치/다운로드한다. 모델은 프로세스별 로딩하므로 현재 구현에는 초기화 비용이 있다. 독립 검사로 기존 방식보다 호출 수·처리 시간이 늘 수 있다. 그림 읽기/GPT 사용량은 기존 PoC7 공용 예약·정산을 사용한다. 작은 crop의 예약량은 실제 픽셀의 patch 수에 보수적 계수를 적용해 계산한다.

## 판정과 표시

- 원본 오탈자: 실제 획을 명확히 읽었고 독립 OCR과 전사가 일치하며, 교정 근거가 있는 경우 FAIL/빨강.
- 글자 외형 결함: 원본의 구체적 획 손상 증거가 있는 경우 FAIL/빨강. 전사가 성공했더라도 적용한다.
- OCR 불일치/인식 오류 후보, 전사 누락, 미확정: REVIEW/노랑. 실제 원본 오류로 확정하지 않는다.
- PASS/파랑: 독립 전사 일치 + 명시적 원본 획 검사 + 철자 정상 의견이 모두 있어야 한다. 대상 영역만 해당하며 모든 글자를 찾았다는 뜻이 아니다.
- 미검사/문자 아닌 후보는 이미지에 오류 핀을 강제하지 않고 검토 정보로 남긴다. OCR 미설치/장애도 PASS로 바뀌지 않는다.

상세 화면은 원본 crop, Paddle/NAVER 전사, GPT 독립 전사, 획 증거, 교정 후보를 함께 보여 준다. OCR 신뢰도는 이미지 정상 확률이 아니다. OCR 엔진 두 개의 전사가 다르면 NAVER가 GPT와 일치해도 차이를 삭제하지 않는다.

## NAVER 월 한도

`NAVER_OCR_API_KEY`, `NAVER_OCR_API_URL`, `NAVER_OCR_MONTHLY_LIMIT=100`을 사용한다. 한도 단위는 **실제 HTTP API 요청 1회**이다. 글자·검출 영역 수로 차감하지 않는다. 현재 API payload는 원본 이미지 한 장이다.

SQLite `BEGIN IMMEDIATE`로 네트워크 전송 전에 1회 예약하며, 동시 요청에서도 100회를 넘지 않는다. 실패·시간 초과·프로세스 중단의 예약은 보수적으로 유지하고 자동 재시도하지 않는다. **Asia/Seoul 매월 1일 00:00**부터 새 월 key로 100회를 사용한다. 과거 기록을 삭제하지 않으며 GPT 말일 갱신과 별도다.

이는 앱이 강제하는 한도이며 공급자 청구/잔액 API가 아니다. 다른 프로그램·콘솔의 사용은 자동 조회되지 않는다. 같은 API 키를 다른 서비스에서 사용하면 별도 합산 연동이 필요하다. 잔량 게이지와 사용량 화면에 월 단위/호출 내역/미확정 건을 표시한다.

## 평가와 남은 한계

`scripts/evaluate_text_pipeline.py`는 수정 전 소스 스냅샷의 판독을 기준선으로 저장하고, 개선 경로에 같은 첫 관찰을 제공한다. 모델에는 정답 JSON·정답 미리보기를 전송하지 않는다. `score` 단계만 정답 ROI를 사용한다. D-02-l 정답이 있는 8개 이미지(14개 문자 사례)가 비교 범위이며 전체 61개/25개 규칙 정확도 평가와 구분한다. 전사 누락률은 ROI 단위로 계산하며 문자별 CER/WER가 아니다. REVIEW는 검출 성공에 넣지 않는다.

실제 첫 시험에서는 `김처찌개`를 Paddle이 읽어 GPT의 `김치찌개` 복원과 불일치를 드러냈다. 그러나 `한복체험`의 미세한 글자 결함은 두 판독이 모두 정상으로 읽을 수 있었다. 고강도/다영역 GPT 검사에서 응답 출력 예산 소진도 관찰했다. 따라서 이 구조가 미세한 한글 결함을 모두 해결했다거나 대표적 정확도를 달성했다고 주장할 수 없다. API 한도 때문에 실행되지 않은 사례는 정확도 0 또는 정상으로 처리하지 않고 미평가로 남긴다.


### 실제 비교 결과와 기본값 결정

최종 설정에서 QA_03·QA_07의 D-02-l **5개 라벨(오류 4, 정상 1)**을 비교했다. 정확 검출(FAIL)률은 기존 0/4, 개선 0/4였고, 오탐은 양쪽 모두 0/1이었다. REVIEW는 기존 2/5에서 개선 3/5로 증가했고, ROI 전사 누락률은 1/5(20%)에서 2/5(40%)로 악화됐다. 즉 비빔밤 사례를 정상에서 판독 불일치로 바꾸는 효과는 있지만 오류 확정 검출률의 개선은 입증하지 못했다. 생성형 자연 이미지에서는 김처찌개 판독 불일치도 드러났다.

표본이 작고 개발 과정에 사용한 합성 자료이므로 일반화 성능 수치로 쓰면 안 된다. 다른 6개 이미지의 최종 동일 설정 비교는 공용 토큰 예약 한도·실행 실패 때문에 완료하지 못했으며 정량 집계에서 제외했다. 전체 14장/61개 규칙 정확도를 평가했다고 표시하지 않는다. 세부 근거·실행 시간·호출량은 [평가 JSON](ocr-evaluation-2026-10-30.json)에 보존했다.

이 결과에 따라 **OCR_ENABLED 기본값은 false**로 두어 기존 서비스의 판정·호출 시간을 즉시 바꾸지 않는다. 독립 OCR 경로는 설치·구현·회귀 시험을 완료한 선택 기능이며, 기본 판정 경로를 대체하는 정확도 개선 완료판이 아니다. 관리자가 실제 자료로 추가 검증한 뒤 .env에서 활성화할 수 있다. NAVER 월 사용량 표시는 OCR 기능 플래그와 별도로 제공한다.

NAVER 연결 시험은 시간 초과·HTTP 404·HTTP 400 이후 정상 응답으로 확인했다. 성공 호출은 자연형 홍보물에서 27개 문자 영역을 반환했다. `행정안정부가`, `한복`, `김처쩌개` 등의 판독이 있어 성공 응답을 곧바로 원본 정상으로 판단할 수 없다. 실패 3회와 성공 1회를 합쳐 월 4회 사용으로 보수적으로 기록했다. 이 연결 시험은 위 QA_03·QA_07 정량 비교에 포함하지 않는다. 키 변경·재발급도 해당 월 누적 사용량을 초기화하지 않는다.

평가 JSON의 baseline 사용량은 기존 문자 관련 검사 전체, improved 사용량은 첫 관찰을 재사용한 추가 OCR 검사만의 수치다. 전체 파이프라인 비용 절감으로 비교하면 안 된다. 최종 결과 병합은 기존 오류·검토 의견을 유지하며 OCR 정상 판독으로 삭제하지 않는다.
