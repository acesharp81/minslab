# 외부 접속 로딩 개선 — 2026-11-09

## 원인

기존 목록 인덱스·화면 경량 조회는 정상 동작했다. Exploratory_03의 로컬 화면 계산은 약 24ms였으나, 실제 홈페이지의 `poc11_proxy.py`가 httpx 응답의 `.content`를 읽어 gzip을 해제하고 압축 헤더를 버리고 있었다. 11월 6일 적용한 JSON 압축이 이 경로에서는 사용자에게 전달되지 않았다. 또한 ETag·Vary·조건부 요청 헤더가 누락되고 이미지가 `no-store`로 전달되어 같은 2.67MB 원본을 반복 다운로드했다.

## 적용

- 홈페이지 중계가 브라우저의 Accept-Encoding을 전달하고 응답을 raw bytes로 받아 압축 상태·Content-Encoding·Vary를 보존한다. 요청 헤더가 없으면 identity를 사용한다.
- 화면 JS·CSS·HTML·규칙 JSON에도 gzip을 적용한다. PNG·PDF 원본은 압축 변환하거나 해상도를 낮추지 않는다.
- 원본 이미지에 `private, no-cache`와 ETag를 적용한다. 재사용 전에 서버에 인증·자료 존재·변경 여부를 확인하고 동일할 때만 304를 반환한다. 로그인 없이 304를 받거나 삭제된 이미지를 재사용할 수 없다. 브라우저 캐시는 Cookie에 따라 구분된다.
- 정적 JS·CSS도 조건부 요청으로 갱신 여부를 확인한다. 검사 결과 JSON·규칙·보고서의 기존 no-store 정책은 유지한다.
- 외부 경로에서 ETag·Last-Modified·Vary·조건부 요청을 전달한다. HEAD·204·304 본문 처리를 보존한다. 위조 관리자 헤더나 다른 서비스의 쿠키는 전달하지 않는다.
- 웹 버전 `20261109-58`로 갱신했다. 췤미 서비스와 홈페이지 중계에 배포했다. PoC7 백엔드는 재시작하지 않았다.
