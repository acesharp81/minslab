# 문자·손 이상 후보 보강 — 2026-11-06

## 적용 범위와 현재 활성 상태

기존 25개 원문·156개 규칙, 판정/검토 기록, 기준자료, 모델 기본값과 비용 원장을 보존했다. 기존 OCR/관찰 뒤에 **로컬 후보 기록 계층**을 추가했다. 외부 저장소 코드나 pickle 가중치는 복제·실행하지 않았고 새 OCR/손 모델도 설치하지 않았다.

| 설정 | 기본값 | 효과 |
|---|---|---|
| `ARTIFACT_SCREEN_ENABLED` | `true` | 저장된 OCR 영역·관찰과 원본 픽셀로 후보를 기록. 추가 API 없음 |
| `ARTIFACT_MAX_REGIONS` | `48` | 문자 영역 상한. 전체 측정 창은 최대 96개 |
| `ARTIFACT_RECHECK_ENABLED` | `false` | 검증 전에는 새 후보에 따른 재판독·선정 변경을 하지 않음 |

`SHADOW`는 **기록만 수행**한다는 뜻이다. 새 후보만으로 오류/검토 필요 결과를 만들거나 이미지 번호를 늘리지 않는다. 기존에 확인된 FAIL과 기존 OCR 재판독 경로는 유지한다. 앞으로 실행하는 검사에서 기록하며, 과거 이력은 일괄 변경하지 않는다. 이 보조 계층이 실패해도 기존 검사를 계속한다.

## 구현

- `app/artifact_screen.py`: 문자 탐지 좌표를 재사용한다. 흐림 후보에는 기존의 ‘OCR 문자열 4글자 이상’ 조건을 적용하지 않는다. 따라서 한 글자·짧은 단어·전사 없는 영역도 실제 픽셀 측정 대상이다. 낮은 OCR 신뢰도만으로 흐림 후보를 만들지 않는다.
- 긴 문자 줄은 원본 크기의 겹치는 구간으로 측정한다. 긴 줄의 구간 수가 상한을 넘으면 일부만 샘플링하고 `WINDOW_SAMPLING_LIMIT`를 남긴다. 전체를 확인했다고 표시하지 않는다.
- OCR 다각형의 원근/회전을 비생성형 변환으로 정렬하고 역행렬을 보존한다. 측정 위치는 원본 좌표로 되돌린다. 정렬 과정의 보간 영향이 있을 수 있어 결과는 확인 후보일 뿐 결함 확정 근거가 아니다. 잘못된 다각형·작은 글자·큰 영역·낮은 대비·상한 초과는 진단 사유를 남긴다.
- 후보 종류: 탐지 후 무판독, 독립 판독 불일치, 기존 획 형태 충돌, 국소 흐림 신호, 구체적인 손 구조 이상 관찰. 후보 ID·기존 객체 ID·원본 영역·신호·처리시간을 저장한다. 신뢰도 확률은 만들어내지 않는다.
- 손은 `hands.visible_structure=ANOMALOUS`와 구체적인 관찰 근거가 있는 기존 객체만 사용한다. 주먹·브이·쥐기·부분 가림 자체로 새 후보를 만들지 않는다. 손 자체의 정확한 경계가 없으면 기존 객체 영역이라고 명시하며 손끝 좌표를 지어내지 않는다.
- `text_routing.py`: 향후 재판독 설정을 켠 경우, 두 판독이 일치해도 국소 흐림/획 충돌 신호가 있는 문자는 `QUALITY_CONFLICT`로 기존 재판독 후보에 포함한다. 전사와 획 품질을 분리한다.
- `verification.py`: 설정을 켠 경우 구체적 손 이상 후보를 기존 anatomy 확대 슬롯에 연결한다. 기존 손목·팔 주변 여백을 유지하고 공통 호출·객체 상한을 사용한다. 다른 영역의 호출 제한을 우회하거나 고비용 모델로 자동 승격하지 않는다.
- 원본·관찰·OCR 근거·설정·알고리즘 버전으로 로컬 캐시를 구분한다. 관찰 재사용 시 기존 기록을 복사하며 변경된 근거만 다시 계산한다.
- UI: ‘관찰 기록 · 토큰 사용량’ 안에 접힌 ‘로컬 이상 후보’를 표시한다. 후보 개수와 사유는 진단 정보이며 검출 완료/정상/오류 수가 아니다. 기존 이력 속도 개선도 유지한다.

## API를 호출하지 않은 평가

재현 스크립트: `scripts/evaluate_artifact_screen.py`.

```bash
.venv/bin/python scripts/evaluate_artifact_screen.py \
  --db data/inspection.sqlite3 \
  --output data/artifact-screen-evaluation.json
```

운영 DB는 읽기 전용으로 열며 이력에 검사를 생성하지 않는다. 저장 OCR 결과만 재사용하고 OCR 엔진 자체를 실행하지 않는다. 독립 합성 폰트가 없는 환경에서는 합성 시험을 미실행으로 표시한다. `--font`로 평가용 CJK TTC 글꼴을 지정할 수 있다.

### 통제된 합성 흐림

4가지 문구 길이 × 2가지 글자 크기 × 선명/흐림 × OCR 전사 있음/없음 = 32개 입력 조건이다. 동일 픽셀에 전사 유무를 달리한 조건을 포함하므로 32개의 독립 실사 이미지 시험이 아니다. Gaussian blur로 만든 흐림 신호만 비교했으며 한글 철자·손 왜곡 정확도 평가가 아니다.

| 측정 | 기존 픽셀 흐림 조건 | 새 후보 신호 |
|---|---:|---:|
| 흐림 16조건 중 포착 | 4 | 16 |
| 정상 16조건의 흐림 오탐 | 0 | 0 |

이 결과는 짧은 글자·무판독 조건의 기존 후보 누락을 줄였다는 증거다. 장식체·곡면·작은 자연 이미지 등에서 일반화 성능이 검증됐다는 뜻은 아니다.

## 검증과 운영

- Python 전체 277개 통과 / 2개 건너뜀, JavaScript 66개 통과. 전체 Python 검사에서 실제 외부 HTTP를 차단했고 호출 시도는 0회였다.
- 짧은 글자·전사 없음·선명한 글자·백지·낮은 OCR 신뢰도·회전 좌표 역변환·구간 상한·잘못된 OCR 기록·자연스러운 가림 손·구체적 손 이상 연결·캐시·비활성 설정·기존 확대 호출 상한을 검증했다.
- 신규 검사 설정 연결 오류가 전체 회귀 검사에서 발견되어 수정했고, 신규 검사·실패 재시도·규칙 이력·재사용 검사와 전체 시험을 재확인했다.
- 브라우저에는 평가 보고서를 메모리에서만 주입했다. 후보 표시 전후 번호/상태 불변, 기본 접힘, 모바일 가로 넘침 없음, JavaScript 오류 0개, 실제 분석 POST 0회를 확인했다. 이 브라우저 시험 역시 검수 이력을 수정하지 않았다.
- `poc11.service`만 갱신했다. 실제 GPT/NAVER/OpenRouter 호출·모델 비교 시험은 실행하지 않았다.

## 남은 검증과 도입 기준

`deferred-evaluation.json`에 보류 목록을 기록했다. 실제 모델 평가가 요청되면 GPT-5.4 + mini의 공용 일일 잔량을 확인한 뒤 동일 이미지/규칙/참고자료에서 기능 꺼짐/켜짐을 비교한다. 정답/ROI는 채점에만 사용한다. Exploratory는 개발 회귀용, QA 및 별도 정상 서체/손 표본은 평가용으로 구분한다.

결함별 회수율·정밀도, 실제 오류 위치 일치, 자연스러운 손 가림 및 정상 서체의 불필요 REVIEW, 평균/p95 처리시간, 단계별 입력/출력 토큰·호출 수를 함께 평가한다. 성능 이득과 오탐 억제가 입증된 항목만 재판독 설정을 활성화한다. 월 공용 GPT 크레딧과 NAVER 호출은 추가 소모하지 않는 평가부터 시작한다.

한계: OCR과 전체 관찰 양쪽에서 완전히 놓친 영역, 관찰 기록에 없는 손 왜곡, 복잡한 배경/곡면/장식체의 실제 결함은 이번 로컬 후보 계층만으로 해결하지 못한다. 손 전용 독립 검출기, 얼굴·물체 합체·그림자·건축 구조 검사는 이번에 도입하지 않았다.

## 영상 후속 계획

영상 입력은 여전히 미지원이다. 별도 확장 시 로컬 디코딩 → 샷 전환/텍스트 변화/주요 객체 등장에 따른 키프레임 추출 → 기존 이미지 검사 → 시간축 후보 비교를 구성한다. 프레임에는 영상 ID·시간코드·추출 이유를 기록하고, 가림/모션블러/압축/장면 전환을 실제 변형과 구분한다. 모든 프레임을 LLM에 보내지 않으며 영상 길이·프레임 수·총 토큰 상한을 별도 설계한다. 구현 전에 이미지 검수의 평가를 먼저 마친다.
