# 검토 필요 결과의 화면 표출 검증 — 2026-11-04

저장된 최신 실제 검사 25건의 `REVIEW` 의견 944개를 기존 화면 분류와 대조했다. 의견은 원문별 결과와 위치별 확인 목록에 보존되어 있었지만, 이미지 번호와 첫 화면의 위치 미확정 목록에서는 일부가 빠졌다. 분석 결과의 삭제가 아니라 표출 단계의 제외 조건과 목록 접근성이 원인이었다.

## 확인한 원인

1. `document_review=true` 또는 이유에 `승인된 기준자료 미확보`가 포함되면 구체적인 관찰 차이가 있어도 이미지 번호를 제외했다. Exploratory 01·02·03의 `행정안정부`, 지명·항공사 표기 불일치 의견에서 확인했다.
2. `READING_LIMIT`는 일부 문자 오류 유형만 이미지 표시에 허용했다. 손의 구조, 견장·경찰 문양과 `OCR_UNCERTAIN` 같은 판독 불확실성은 번호 없는 추가 확인으로 묶였다.
3. 위치가 미확정인 REVIEW는 번호가 없어 첫 화면의 ‘위치 확인 필요’에도 나타나지 않았다. 좌표를 추측하지 않는 처리는 필요하지만, 의견까지 눈에 띄지 않게 되는 문제가 있었다.

## 변경한 표시 기준

| 저장된 판단 | 화면 표시 |
|---|---|
| 구체적인 이상 관찰·문맥 충돌 | 위치가 있으면 해당 객체에 표시. 기준자료 부족으로 REVIEW인 경우 노랑 유지 |
| 문자·손·인체·도안의 판독 한계 | 해당 검수 행동과 관찰 객체가 연결되면 노랑으로 표시하고 ‘판독 한계 · 원본 확인’ 안내 |
| 공식 도안 비교의 불확실성·기준 부족 | 관련 객체에 노랑으로 표시하고 비교 필요 안내 |
| 위 의견의 위치가 불확실함 | 이미지 좌표를 만들지 않고 번호가 있는 ‘위치 확인 필요’ 목록에 표시 |
| 권리·문서·행정 승인, 분석 누락, 시각 근거 없는 모델 판정 상충 | ‘번호 없는 검토 의견’ 목록에 건수와 전체 의견 표시. 누르면 상세 근거·검토 기록으로 이동 |

동일 객체의 여러 의견은 번호 하나에 묶는다. 단순히 작은 배경 인물이라는 이유로 개인정보 위험을 이미지 오류처럼 표시하지 않는다. 정상 관찰을 사람이 검토해야 한다는 사정만으로도 이미지 번호를 만들지 않는다. 괘 구조 측정이 MATCH여도 같은 객체에 별도의 시각적 REVIEW가 있으면 파란 정상 표시로 덮지 않는다.

‘의견’은 세부 행동별 저장 판정 수이며 서로 다른 오류 수가 아니다. 번호 수는 객체 묶음 수로, 인접 번호 병합 때문에 화면 크기에 따라 달라질 수 있다. 위 값은 저장 스냅샷 재생과 1500×1000 브라우저에서 확인했다. Exploratory 01의 상단 문구는 실제 문자 결함 근거 없이 모델 판정만 상충한 경우여서 이미지 번호를 추가하지 않고 별도 목록으로 보낸다.
