1. 이번에 반영한 것

  • DB에 저장한 매칭 유지: 화면 조회·수집 갱신 때 기존 매칭을 다시 계산하지 않습니다. 확인 필요 상태도 보존합니다.
  • 기준 일정·병목·시나리오 관리: 담당자 입력, 변경 이유와 이력, 책임기관·조치기한, 공식 실적과 분리된 시나리오를 추가했습니다.
  • 전체 정책 원장과 11년 흐름: 기본은 135만 호 전체 원장, 과거 5년·현재·미래 5년입니다. 연결 사업 전체와 정책기간으로 바꿔 볼 수 있습니다.
  • 수집 확장: 전국 17개 시도 연도별 공급 통계, 인천 인구·가구·주택·고용·추계, 건축HUB 추가 수집을 반영했습니다.
  • 부족한 근거를 별도 표시: 실제값 미확보는 0으로 바꾸지 않습니다. 원천 오류와 미조회 범위를 구분합니다.

백엔드 269개 테스트 통과. 브라우저에서 차트·지역·연도·입력폼을 검증했습니다. 운영 DB에 테스트용 목표·병목·시나리오를 넣지 않았습니다. 같은 자료로 매칭 갱신을 반복했을 때 584개 단계 연결을 모두 유지했습니다.

2. 원본에서 화면까지의 흐름

① 공식 자료
국토부·LH·SH·KOSIS·건축HUB 등 API/공개 첨부
② 원본 보관
조회조건·수집시각·해시·성공/실패 기록
③ 표준화와 식별
날짜·단위·지역·사업 식별자 정리, 원본 판본 유지
④ DB 연결
정책 ↔ 프로그램 ↔ 사업, 단계 근거와 담당자 검토
⑤ 같은 기준으로 집계
정책 범위·기준일·중복 제거 후 지도·차트

예를 들어 LH 공급계획의 A4 블록과 청약 공고의 A4 블록은 별도 원본입니다. 같은 지구·블록 또는 충분한 상세 주소 근거로 후보를 만들고 연결을 저장합니다. 저장한 연결에는 근거와 확인 상태가 남습니다. 원본이 바뀌어도 담당자가 선택한 연결을 자동으로 다른 사업으로 바꾸지 않습니다.

연도별 전국 통계는 보관한 국토부 공식 응답의 해시를 검증한 뒤 기존에 제외했던 시도를 추가 추출했습니다. 이 통계를 9·7 정책의 실적으로 곧바로 더하지 않습니다. 인천도 KOSIS 원본과 API를 사용했으며 조원 데이터셋을 병합하지 않았습니다.

4. 매칭을 매번 새로 하지 않는 규칙

  1. 신규 항목에만 자동 후보를 계산해 가능성 높은 연결을 확인 필요(REVIEW)로 저장합니다.
  2. 기존 선택은 REVIEW·CONFIRMED 여부와 관계없이 유지합니다. 담당자가 해제한 것도 자동 복원하지 않습니다.
  3. 아직 연결되지 않은 단계는 사업·원천 판본 지문이 바뀌었을 때만 다시 후보를 찾습니다.
  4. 새 근거 후보 조회는 후보 목록을 갱신할 뿐 기존 선택을 바꾸지 않습니다.
  5. 선택한 원천에 새 판본이 생기면 표시하고 담당자가 검토하여 연결을 저장합니다.

현재 9·7 사업의 사업화·인허가 슬롯은 확인 필요 312개, 미연결 44개입니다. 이것은 정책–프로그램–사업 연결 누락 수가 아니라 단계별 증빙 연결 상태입니다. 전체 프로젝트의 584개 슬롯 반복 갱신 보존 결과와도 범위가 다릅니다.

5. 숫자를 읽는 기준

135만 호는 수도권 2026–2030 신규 착공 목표입니다. 공급 실적은 모집·분양 단계 도달입니다. 두 지표를 동일한 사건으로 취급하지 않습니다. 지도는 선택 단계까지 도달한 누적량, 면 차트는 기준일의 상호 배타적인 현재 단계 물량입니다.

현재 목표 내 식별 물량 21,172호(1.5683%), 미식별 잔여 1,328,828호입니다. 1.5683%는 정책 달성률이 아니라 사업 식별 비율입니다. 잔여를 정책수립 잔여 영역으로 보여주지만 실제 사업이 아직 시작하지 않았다는 뜻은 아닙니다.

정책 잔여 1,328,828 + 사업화 7,058 + 인허가 3,578 + 건설 3,431 + 공급 5,419 + 입주 시작 0 + 단계 미확인 1,686 = 1,350,000호입니다. 단계 미확인 물량을 임의로 다른 단계에 넣어 여섯 단계가 모두 확인된 것처럼 보이게 하지 않습니다. 연도별 공식표 합계와 정책 총량의 반올림 차이 1,000호도 잔여로 구분합니다.

입주는 시작일에 연결된 물량이며 실제 거주 가구 수가 아닙니다. 관측 근거가 없으면 지연 호수는 판단 대기입니다. 입주 전망을 목표로 사용할 수 있지만 전망 자체를 실적으로 처리하지 않습니다. 목표가 없는 단계는 목표 면을 그리지 않고 언제든 담당자가 입력할 수 있습니다.

6. 담당자는 어디서 무엇을 입력하는가

데이터 현황 → 정책–프로그램–사업 연결에서 ① 정책–프로그램, ② 프로그램–사업, ③ 단계 근거·목표, ④ 일정·병목·시나리오를 사용합니다. 저장은 기존 관리자 인증이 필요합니다.

  • 일정: 사업·단계·기한·물량·책임기관·근거·상태. 최초 승인 기준선은 보존하고 변경일정과 차이를 표시합니다. 최초 공식 약속인지 여부는 첨부 근거로 확인해야 합니다.
  • 병목: 인허가·보상·기반시설·재원·기관협의 등 원인, 책임·협력기관, 조치, 기한, 해결상태. 같은 사업의 영향 물량은 중복 합산하지 않습니다.
  • 시나리오: 비교 기준 데이터를 고정하고 선택한 미래 단계 일정을 개월 단위로 이동해 원안과 비교합니다. 공식 목표·실적은 수정하지 않습니다.
  • 수집 후속 조치: 실패·미착수·일부 수집·수집 기록 있음, 남은 법정동과 다음 조치를 확인합니다.

현재 신규 일정·병목·시나리오 등록은 0건입니다. 임의의 업무 약속을 공식자료처럼 입력하지 않았습니다. 시나리오는 선택 단계의 일정 이동 비교까지 구현했으며 공사기간·재정·가구추계에 따른 모든 후속 단계 자동 전파 모델은 아직 아닙니다.

9. API 키와 유지관리

이번 보완에는 새 API 키가 필요하지 않았습니다. 실키는 PoC/10-home/.env에 저장하고 .env.example에는 값을 넣지 않습니다. iH 전용 설정명은 POC10_IH_SERVICE_KEY이며 기존 LH 공고 키 대체 설정을 지원합니다. 같은 공공데이터포털 키여도 서비스별 활용승인은 별도로 확인해야 합니다.

iH 활용신청 페이지 · 건축HUB 주택인허가 활용신청 페이지

원본 수집 → 배치 상태/해시 확인 → 표준화 판본 저장 → 신규 미연결만 후보 생성 → 담당자 검토 → 정책 원장 보존합 검사 → 화면 검증 순서로 운영합니다. 정기 백업은 DB 볼륨과 원본 파일을 함께 대상으로 해야 합니다. 인증키·내부 인증값은 공유 JSON이나 이 보고서에 포함하지 않았습니다.
