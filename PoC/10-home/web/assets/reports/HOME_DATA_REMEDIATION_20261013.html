데이터 정비 방안

서로 다른 기관의 자료를 같은 정책·사업·물량으로 연결하고, 목표 대비 진행을 관리하기 위한 보고서

현행 구현과 기관 협의용 보완 명세를 구분했습니다.

01 · 비전문가를 위한 설명

같은 사업임을 찾아 맞추는 업무를 줄여야 합니다

주택공급 정보가 없는 것만이 문제는 아닙니다. 정책문서에는 사업명, 인허가에는 허가번호, 공사현황에는 공사번호, 공급공고에는 공고번호가 있습니다. 자료를 서로 연결할 공통 번호가 충분히 제공되지 않아 현재 HOME은 주소·지구·블록·호수·문서 내용을 조사하여 연결 후보를 만들고 담당자가 확인하도록 구성했습니다.

이 방식은 누락을 보완하는 데 필요하지만, 이름이나 물량 범위가 다르면 연결이 빠지거나 잘못 이어질 수 있습니다. 새 자료와 변경자료가 들어올 때마다 대조·검토가 필요해 업무와 처리 비용도 늘어납니다. 이미 검토한 연결은 DB에 저장하여 재사용하며, 화면 조회 때마다 새로 매칭하는 구조는 아닙니다.

정비 방향

관리 주체가 정책·프로그램·사업의 공통 식별정보를 관리하고, 원천기관이 기존 번호와 공통 사업번호의 대응을 제공해야 합니다. 여기에 어떤 물량을 언제까지 어느 단계로 진행할 것인지를 목표로 등록해야 일정·성과 관리가 가능합니다.

1. 현재 방식과 정비 후 업무

현재 · 자료를 보고 연결 판단

  1. 기관별 자료 수집·원문 보존
  2. 명칭·주소·블록·물량 상세 대조
  3. 연결 후보 저장·담당자 확인
  4. 검토된 범위로 정책·단계별 조회

새로운 별칭·부분 공고·정정이 생기면 조사와 검토가 다시 필요합니다.

보완 · 공통 기준정보로 연결

  1. 관리기관이 사업번호와 범위 확정
  2. 원천기관이 기존 번호와 대응 제공
  3. 시스템이 번호·범위·판본 검증
  4. 담당자는 충돌·예외와 목표 변경 관리

확인된 연결을 재사용하고, 담당자는 모호한 사례에 집중합니다. 이 체계는 기관 협의가 필요한 제안입니다.

2. 정책 ID 하나만으로는 충분하지 않습니다

관리 단위쉬운 의미함께 관리해야 하는 내용
정책무엇을 언제까지 달성할 것인가정책 고유번호, 목표 지표, 기간, 지역별·연도별·단계별 목표
프로그램어떤 실행 묶음으로 추진할 것인가프로그램 고유번호, 연결 정책, 대상 범위, 배정 목표, 담당기관
사업어느 실제 사업인가공통 사업번호, 기관 내부 사업번호 대응, 변경·분할·합병 이력
사업 내부 범위·사건사업의 어느 물량이 어떤 단계인가지구·블록·분양/임대 구분, 허가·공사·공고번호, 예정/실제 및 판본

같은 정책에 여러 사업이 있고, 같은 사업에도 허가·공사·공고가 여러 건 존재합니다. 한 사업이 여러 정책에 포함될 수도 있습니다. 따라서 정책 ID는 정책 귀속을, 사업 ID는 실제 사업의 동일성을 구분하는 데 사용해야 합니다.

왜 물량 범위까지 필요한가

성남금토 A2의 단지 633호, 국민임대 438호, 금회 모집 219호는 같은 사업의 서로 다른 범위입니다. 번호가 같아도 세 값을 더하면 중복됩니다. 입주 예정월이 확인됐더라도 실제 입주 세대수가 확보됐다는 뜻은 아닙니다.

3. 정책의 세부 목표가 있어야 지연을 판단할 수 있습니다

정책 총량 하나만으로는 ‘올해 어느 지역의 어느 단계가 얼마나 늦었는지’를 판단하기 어렵습니다. 정책 → 프로그램 → 사업의 목표를 연결하고, 최초 약속과 변경 계획을 보존하는 업무가 관리 시스템 안에 있어야 합니다.

등록할 정보업무 담당자가 결정할 내용
대상과 지표정책·프로그램·사업, 지역·블록·유형, 착공·공급·입주 등 목표의 의미와 호수
기간과 배분연도·월 또는 분기·반기 범위, 기간 물량인지 누적 물량인지, 하위 배분량과 미배분 잔여
최초 목표와 변경최초 기준선, 변경 목표, 변경 사유·승인자·근거. 입주 전망은 전망 목표로 따로 관리
계획 대비 진행같은 범위·지표·기준시점의 목표와 확인 실적 비교. 미확인 실적은 0으로 대체하지 않음

예를 들어 9.7 대책의 135만 호 신규 착공 목표를 같은 기간의 분양 또는 입주 목표로 자동 대체하면 안 됩니다. 단계별 목표가 없으면 미확인으로 남기고 담당자가 근거와 함께 입력해야 합니다. 하반기는 그래프에서 12월로 표시하되, 원문이 하반기라는 사실을 보존합니다.

현재 HOME에는 연결·목표·일정 입력과 이력이 있습니다. 기관 공통 ID 발급, 기관 간 공식 대응표, 승인된 세부 목표의 공통 제공 체계까지 완성된 상태는 아닙니다.

4. 누가 무엇을 맡아야 하는가

담당해야 할 일
정책·프로그램 관리자정책과 실행 묶음의 번호·범위·목표·기간을 정하고, 어떤 사업을 어떤 실적으로 인정할지 승인합니다.
사업 관리기관실제 사업과 블록·공급유형을 식별하고 기관 번호와 공통 번호의 대응을 확인합니다.
원천 제공기관허가·공사·공고·입주 자료에 사업 대응정보, 물량 범위, 기준일과 정정 이력을 제공합니다.
HOME 운영·업무 담당자기준정보를 검증·재사용하고, 예외 매핑·변경·해제 사유를 기록하며 목표 대비 진행을 조회합니다.

기존 API를 바로 바꾸기 어려우면 기존 번호 ↔ 공통 사업번호 대응표부터 CSV 또는 별도 API로 제공할 수 있습니다. 담당자 수동 연결도 유지하되 근거와 검토 상태를 남겨 공식 확인된 연결과 구분합니다.

먼저 합의할 세 가지

① 정책·프로그램·사업·물량 범위의 정의와 발급 책임, ② 단계별 목표·실적의 지표와 기준일, ③ 원천 번호 대응표와 변경 통지 방식입니다. 자세한 현행 구조는 2번 탭, 항목별 보완 명세는 3번 탭에서 확인할 수 있습니다.

02 · 서비스 유지관리 사업자

현재 DB와 수집·매핑 구현을 기준으로 설명합니다

업무 테이블은 12개입니다. 정책·사업화·인허가·건설·공급·입주의 여섯 단계가 각각 독립 물리 테이블로 구성된 것은 아닙니다. 원천·단계 근거의 상당 부분은 home_revision.kind와 payload로 저장하고 관계 테이블 및 저장된 연결 근거로 조회합니다.

ER·조인 키테이블·수집 방식매핑 규칙오류 유형·조치

1. 현행 ER 다이어그램과 실제 조인 키

실선 = DB FK, 점선 = 코드상의 논리 참조. 화살표에 실제 키와 관계 수를 표기했습니다. 같은 테이블은 설명을 위해 반복 표시하며 마이그레이션 메타테이블은 제외합니다.

PRO와 HPR을 혼동하지 않아야 합니다

PRO_…는 home_revision의 원천 사업 entity_id, HPR_…는 home_project의 통합 사업 후보입니다. 현재 home_mapping·evidence_bridge의 project_id를 home_project.id로 바로 조인하면 잘못 연결됩니다.

현재 관계실제 참조운영 해석

home_mapping.program_id → home_program_mapping.id		원천 사업 PRO의 프로그램 귀속. 모두 선언된 FK는 아님.

진도·지연 산식동일 범위·단계·지표·기준월의 기한 도래 누적 목표 − 누적 실적양의 차이만 부족량; 비율 = 부족량 / 기한 도래 목표목표 0이면 비율 없음. 확인량 부족이면 확정 지연 대신 자료 부족 표시. 연간 목표를 임의 월별 분배한 값으로 월별 확정 지연 판정 금지.

단계 코드는 POLICY / BUSINESS / APPROVAL / CONSTRUCTION / SUPPLY / MOVE_IN을 사용하되, 정책 총량에도 metric_code로 실제 목표 의미를 지정합니다. 예: 신규 착공 목표는 CONSTRUCTION + STARTED_UNITS. 정책 총량을 각 단계에 자동 복제하지 않습니다.

변경·정정과 실패 처리

  • 동일 원천키·판본 재수신은 중복 생성 없이 처리합니다. 같은 판본에 다른 본문이 오면 충돌로 격리하고 제공기관에 확인합니다. 신규 판본은 이전 판본과 연결하여 보존합니다.
  • RETRACT는 원천의 취소, RELEASED는 연결의 해제입니다. 취소·삭제 통지도 증분 조회에 포함하고, 적용일 기준 현행 집계에서 제외하되 과거 재현에 필요한 이력은 보존합니다.
  • updated_since 경계는 포함 조회하고 수신 측이 키·판본으로 중복 제거합니다. 페이지 누락·만료 커서는 동일 시점 전체 동기화 또는 재조회로 복구하며 마지막 성공 커서는 전체 페이지 완료 후 갱신합니다.
  • 제안 HTTP 상태: 400 형식·코드 오류, 401/403 인증·권한 오류, 409 판본 충돌, 422 참조·범위 정합성 오류, 429 호출 제한, 5xx 일시 장애. 오류 본문은 code, message, field, source_record_key, request_id를 제공합니다. 격리된 항목을 정상 데이터처럼 집계하지 않습니다.
