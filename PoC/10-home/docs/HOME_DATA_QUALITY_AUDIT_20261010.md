## 우선순위 1: 공급량의 의미와 중복을 확정

`home_supply_cohort`(동일한 실물 주택 묶음), `home_supply_measure`(근거 있는 물량 관측), `home_milestone`(단계 사건), `home_scope_baseline`(정책별 승인 모집단)을 순서대로 도입한다. 같은 지구 상위 총량과 하위 블록, 정책별 중복 귀속, 원공고와 정정공고를 별도로 식별한다. 모든 물량에는 `metric`(목표/계획/공고/준공/입주/기존 재고), `basis`(공식/관리자/추정), `stock_or_increment`, `stage`, `as_of`, `event_date`, `date_precision`, 지역·블록 범위, 출처 판본, 확인 상태를 붙인다. **공정률은 호수로 환산하지 않는다.**

첫 검증은 10개 실제 사업/블록에서 원문까지 역추적 가능한 공급묶음을 만들고, 상위 지구와 하위 블록 및 여러 정책에 걸친 합계가 중복되지 않는지 검사한다. 동일 정책 목표와 실제 공급의 단계·기간·지역이 다르면 달성률은 `null + 불일치 사유`로 반환한다. LH 준공예정은 실제 준공·입주 증거가 아니다.

## 우선순위 2: 누락과 충돌을 검토 가능한 작업으로 만들기

105건의 LH 단일 후보, 호수 차이 58건, 미연계 76건을 하나의 검토 대장으로 표시한다. 자동 규칙은 후보·근거·충돌 필드만 제시하고 승인 상태를 바꾸지 않는다. 공식 사업번호/허가 관리번호, 지구·블록, 위치·필지, 시행자, 공급 유형, 원문 일정 순으로 대조한다. 이름·거리만 같은 경우 자동 확정하지 않는다. 원천 키 체계는 [건축HUB 주택인허가](https://www.data.go.kr/data/15136560/openapi.do)와 [건축물대장](https://www.data.go.kr/data/15134735/openapi.do) 모두 기존 시스템에서 변경됐다고 명시하므로, 구키↔신키 및 변경/정정 이력도 보존해야 한다.

검토 대장은 `확정`, `다른 사업`, `복수 후보`, `근거 부족`, `원천 물량 충돌`을 구분하고, 후보가 해제됐을 때 재수집이 같은 잘못된 제안을 되살리지 않는지 테스트한다. 현재 홈페이지는 105건의 제안만 조정할 수 있어 **미연계 76건의 수동 연결 UI**가 필요하다.

## 우선순위 3: 시계열 완결성과 현장 공정의 기준일

`사업×연도×단계×원천` 매트릭스를 만들어 각 칸에 `관측`, `예정`, `미수집`, `원천 미공개`, `사업 미연계`, `충돌`을 기록한다. 2018~2024 과거 보고서가 60건이고 현재 사업 연결은 14건이므로, 과거 지역 통계가 풍부하다는 이유로 사업 이력도 풍부하다고 표시하지 않는다. 원천 공개일/수집일/공정 측정일을 각각 보관한다. LH 건설공사 공개본 87건의 2026-07-01은 **공개본 기준일**이며 현장 측정일로 승격하지 않는다.

서울·경기 최초 지정·변경·해제 원고시는 사업별 공식 번호를 수집한 뒤 사건 체인으로 연결한다. 고시가 명시하지 않는 연도별 균등 배분은 `ESTIMATED` 시나리오로만 유지하고 원래 계획값처럼 내보내지 않는다.

## 우선순위 4: 주택 재고와 가구의 비교를 순증가 기준으로 보완

현재 `관측 재고 + 확인 준공 + 예정 준공 − 장래가구`는 **검토 시나리오**다. 국토교통부는 주택보급률의 주택수를 기준 재고에 사용검사 주택수는 더하고 멸실주택수는 빼는 방식으로 설명한다. [국토교통 통계누리 작성방법](https://stat.molit.go.kr/portal/cate/statMetaView.do?hRsId=29), [e-나라지표 주택멸실현황](https://www.index.go.kr/unity/potal/main/EachDtlPageDetail.do?idx_cd=2839). 후자는 2018~2024년 연도별 원본 파일을 게시하며, 공식 수치에는 시스템 중복·누락과 다가구를 보정한다고 명시한다. **새 API 키 필요 여부와 파일의 시군구 범위는 다운로드·원본 검증 전 미확정**이다.

먼저 공식 멸실 파일의 서울·경기 시도/시군구·연도·유형 범위를 검증하고, 관측 `주택 재고 차이 ≈ 사용검사 − 멸실 ± 통계 보정` 대조표를 만든다. 보정 항목을 모르면 임의로 0 처리하지 않는다. 공실·비주거 거처·가격·입지와 가구 이동을 반영하지 못하므로 단순 `재고−가구`를 실제 입주 가능 주택의 부족량으로 부르지 않는다. [KOSIS의 주택보급률 정의](https://kosis.kr/visual/economyBoard/economyRegion.do)도 분자와 분모가 각각 다가구 구분거처를 포함한 주택수와 등록센서스 가구수임을 확인한다.

## 우선순위 5: 수집 범위와 갱신 품질의 자동 판정

기존 `home_coverage`를 인허가 기본·건축물대장·청약·LH/SH/GH·지역 통계에도 확장한다. `조회 대상 전체 행`, `성공적으로 받은 행`, `현재 판본`, `연도/지역 완결성`, `최근 성공`, `이번 실패`, `원천 공개 지연`을 분리한다. 서울·경기 전체 법정동을 무조건 동일 빈도로 순회하기보다 **정책 사업이 있는 법정동, 최근 신규 허가/고시가 있는 동, 장기간 미수집 동**을 우선하되, 미수집 모수는 계속 공개한다. 주기당 수집량은 기관 트래픽·응답시간·DB 증가량을 관찰하며 조정한다. 매 수집에서 원본 해시와 필드별 변화·누락을 비교하고, 호수 급변/사업 삭제/고시 변경은 검토 경보로 남긴다.

이 순서는 [`HOME_FINAL_APPLICATION_PLAN.md`](HOME_FINAL_APPLICATION_PLAN.md)의 다음 단계와 같다. 사용자가 추가 키를 바로 신청할 필요는 없다. 먼저 위 공식 멸실 파일의 다운로드 범위와 기존 키/공개 파일 사용 가능성을 실증하고, 필요성이 확인된 경우에만 신청 경로를 추가한다.
