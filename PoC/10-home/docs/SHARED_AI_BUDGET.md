화면 값은 **해당 계정에 연결된 서비스의 공통 운영 원장 추정치**입니다. 제공사의 실제 청구 잔액 조회 API가 아니며, 계정의 다른 도구·수동 호출·과거 미계측 사용은 포함하지 않습니다. 사용량 외에 진행 중 예약과 응답 유실로 미확정된 사용량도 차감합니다. OpenAI 무료 대상의 명목 비용을 크레딧 원장에서도 동시에 차감하지 않습니다. 기존 조직 확인값에 따라 5.4/mini는 일일 그룹, 6계열은 크레딧 그룹으로 분류합니다. 제공사의 혜택·대상 모델 변경 시 운영자가 분류를 검증한 뒤 변경합니다.

## 화면

- PoC10 **데이터관리 → 신규 자료 검토**: 접힌 자동화 설정 위에 일일 토큰·OpenAI 크레딧·Solar의 작은 4그룹 패널(OpenAI 일일·크레딧/OpenRouter/Solar). 모델명·잔여량/전체 한도·잔여율과 얇은 막대를 표시하며 패널을 누르면 전체 사용량, 예약/미확정, 초기화·종료 시각을 펼칩니다.
- PoC7 상단 모델 예산: OpenAI 공통 잔여량. Solar 원장은 같은 중앙 예산 서비스에서 기록한다. OpenRouter·Mistral의 기존 표시도 유지합니다.
- PoC11 워크스페이스 상단: 같은 공통 잔여량을 작은 3그룹 패널로 표시합니다. 초기화 시각·정확한 잔여량은 도움말에서 확인하며 모델을 누르면 공용 사용량 상세로 이동합니다. 로그인 후 표시합니다.

중앙 원장에 접속하지 못하면 잔여량을 미확인으로 표시하고 신규 모델 호출을 차단합니다. 소진을 무제한 또는 미확인을 잔액 0으로 바꿔 표시하지 않습니다.

## 세 역할 운영

[세 AI 작업자 설명](AI_AGENTS.md)이 최신 실행·승인 계약이다. 2026-11-03 운영 설정은 알고리즘 01시·수집 02시·업무담당 03시(한국시간), 세 역할 모두 예약 켜짐이다. 역할별 모델/예약을 선택하며 자동 일괄 작업은 01~05시 창에서 실행한다. mini/Nemotron의 선택적인 정밀 검토는 애매한 건만 수행한다. 같은 원문/판본/규칙/모델 구성/담당자 판단의 완료 분석은 다시 호출하지 않는다.

PoC10 일 $2·월 $30 등 설정은 공통 예산 안의 추가 작업 상한이다. 현재 Solar 키2에도 이 추가 작업 상한을 적용하며, 표준 단가 추정액을 기록한다. OpenAI·OpenRouter의 원자적 공통 제한은 그대로 유지한다. 자료 연결은 검증된 공식 근거에만 허용하고 실제 단계/물량 확정은 별개다.

## 현재 Solar 키2 운영

- HOME: `SHARED_SOLAR_POOL=key2`, `UPSTAGE_SECRET_KEY2`, `SHARED_SOLAR_UNLIMITED=false`. API와 AI worker에 같은 환경을 반영한다. 키2가 없을 때 기존 키로 조용히 대체하지 않는다.
- PoC13: 같은 Solar 키를 서버의 `HANDOVER_LLM_KEY`로 사용하고 `HANDOVER_SOLAR_SHARED_POOL=key2`로 공유 계측한다. 별도로 입력한 다른 개인 키는 키 식별값으로 구분한다.
- 중앙 원장: `solar_pool=key2`, 기간 ID `solar-key2-poc10-poc13`, **누적 $100**, 공유 허용 프로젝트 `poc10`·`poc13`. 기존 기본 Solar 원장과 OpenAI 원장은 유지한다.
- 화면: **Solar · 공유 한도**에 잔여액/$100과 잔여율을 표시한다. `잔여액 = 한도 − 확인된 사용 − 진행 중 예약 − 미확정 예약`이다. 초기화일을 임의로 다음 달로 표시하지 않는다.
- 이력: 이전 무제한 키의 토큰·환산 비용을 키2에서 차감하지 않는다. 동일 키의 기존 PoC13 사용은 이벤트 ID로 중복 없이 포함한다. 과거 응답에서 비용을 확인할 수 없는 호출은 보수적인 미확정 예약으로 유지하며 실제 청구액이라고 단정하지 않는다.
- 장애: 확인된 요청 거절은 비용 0, 연결 중단·응답 유실은 미확정으로 정산한다. 정산 실패는 로컬 outbox에 보존하고 재전송한다. 시간이 지났다는 이유만으로 미확정액을 해제하지 않는다.

**다음 키 교체 시에는** 예약 작업·진행 중 요청·미정산 outbox를 확인하고, 새 키가 같은 계정 잔액을 쓰는지 별도 잔액을 쓰는지 먼저 구분한다. 현재 키2의 $100/기간 ID는 코드 계약이므로 환경변수의 일반 Solar 한도만 바꿔 새 계정을 지원한다고 판단하지 않는다. 별도 계정이라면 별도 원장·공유 범위·한도를 구현·검증하고, 이전 원장을 보존한 뒤 두 서비스의 계측과 화면을 함께 확인한다. 키 값은 문서·브라우저·로그에 기록하지 않는다.

## 유지관리 계약

기존 `poc07-openrouter-gateway`에 아래 인증 API를 추가했습니다. 모델 키·원문은 예산 API로 보내지 않습니다.

- `GET /internal/budget/status`: 공통 잔여량·사용·예약·미확정·초기화 정보. HOME 키2는 `?solar_pool=key2`로 조회한다.
- `POST /internal/budget/reserve`: 요청 ID, 프로젝트, 모델, 입력/출력 상한으로 원자적 예약. 키2 Solar 요청만 `solar_pool=key2`를 함께 전달한다.
- `POST /internal/budget/settle`: 같은 요청 ID로 실제 사용량 또는 거절/미확정 정산.
- 인증: 서버 전용 `x-minslab-meter-token`. 브라우저로 전달하지 않습니다.

PoC7은 기존 PostgreSQL 그룹 원장에 직접 예약합니다. PoC10/11은 HTTP로 해당 원장에 예약하며, PoC13도 키2 Solar 요청을 같은 중앙 원장에 예약합니다. PoC11의 이전 PG 예약은 기존 코드로 정산할 수 있어 미전송 outbox를 잃지 않습니다. 각 클라이언트는 정산 이력을 먼저 로컬 저장하고 재전송하며 동일 ID가 중복 차감되지 않습니다. 진행 중·미확정 예약을 시간이 지났다는 이유로 자동 해제하지 않습니다.

중앙 migration `0061_shared_model_budgets`는 `shared_model_reservations`, `shared_solar_grant_usage`를 추가합니다. 기존 OpenAI 그룹/크레딧 원장을 초기화하지 않습니다. 기존 중앙 Solar 계측 이력도 이벤트 ID로 중복 없이 포함합니다. PoC10 업무 DB의 승인·매핑 schema 변경은 없습니다. 키2는 기존 중앙 테이블의 별도 기간 행을 사용하며, PoC13은 로컬 SQLite `solar_shared_calls`에 정산 outbox를 보존합니다.

Docker에서는 외부 네트워크 `minslab-ai-budget`에 기존 게이트웨이와 HOME API/AI 작업자를 연결하고, 키2 공유를 위해 PoC13도 같은 내부 예산 서비스에 접근하도록 구성합니다. 각 DB의 기존 네트워크는 유지합니다. 네트워크 생성 후 중앙 migration → 게이트웨이 → API/AI 작업자 순서로 적용합니다. 구성은 각 프로젝트 compose와 `.env.example`에 명시했습니다. PoC11은 호스트의 내부 게이트웨이 포트를 사용합니다. 기존 API 키는 각 프로젝트의 서버 환경에만 보관하고 새 키를 발급하거나 노출하지 않습니다.

PoC10 `data/runtime/ai-collection.sqlite3`의 실행/정산 outbox, 원문 보관 경로, 중앙 PostgreSQL 예산 원장을 함께 백업해야 합니다. 장애 복원 시 사용량 원장을 오래된 값으로 되돌리면 잔여량이 부풀려지므로 별도 대조가 필요합니다. 키를 재설정해도 기존 사용량은 유지합니다.

## 2026-10-30 표시·성능 보완

HTML `style` 속성의 막대 너비는 서비스 CSP에 의해 차단됐다. 신뢰된 스크립트가 DOM의 `style.width`를 설정하도록 바꿔 CSP를 완화하지 않고 정확한 잔여율과 처리 진행률을 표시한다. 0%·50%·100%·미확인, 실측 4.1% 크레딧과 78.4% 토큰을 브라우저에서 확인했다. 전체 한도는 중앙 원장의 `limit`, 잔여율은 `remaining/limit`을 사용하고 실제 제공사 잔액으로 표현하지 않는다.

AI 분석 이력만 저장되는 경우에는 정책 조회 캐시를 재생성하지 않는다. 원천·담당자 확인·매핑·연결 근거의 실질적인 변경은 계속 캐시를 무효화한다. 상세 측정은 [CPU·로딩·화면 검증](evidence/LOADING_CPU_20261030/README.md)을 참고한다.
