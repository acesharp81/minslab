**현재 구현의 경계:** 업무담당 작업자는 수집된 원문과 현재 사업 원장을 대조한다. 독립 인터넷 재검색, 규칙 개선안의 자동 격리 시험/배포, 단계별 실적 자동 확정은 아직 실행하지 않는다. 이 항목까지 완전 자동화됐다고 설명하지 않는다. 신규 출처 추가는 공통 수집 범위의 검색어·URL 설정에서 한다.

이는 이 업무의 운영 허용 목록이며 모델 능력의 절대 평가가 아니다. 현재 후보로 충분하므로 Sol·Astra를 추가하지 않았다. 연결 키가 없으면 선택 불가다. 키 설정이 모델 접근 권한을 영구 보장하지 않으며 제공사 실패는 보류 이력으로 남는다.

기본은 **모델 한 개**다. 수집의 1차 모델을 mini 또는 Nemotron으로 선택할 때만 선택적인 두 번째 정밀 검토 모델(GPT-5.4/Terra)을 표시한다. Solar는 독립 단일 모델로 선택하며 이 경제성 비교용 분할 후보에서는 제외한다. 근거·범위·관련성 문제가 있을 때만 호출하고, 정상 자료의 추가 유료 표본 호출은 하지 않는다. 3차 검토는 없다. 단순한 비공식 여부·기존 사람 판단·명백한 사업명 불일치는 코드로 보류해 불필요한 모델 호출을 줄인다.

경제성 판단에서는 Solar 무제한 키가 없는 것으로 본다. 무료 토큰/크레딧/무제한 혜택을 제외한 표준 단가로 2단계 호출액과 같은 1차 토큰을 정밀 모델 하나로 처리한 가정을 비교한다. **절감이 입증된다는 뜻은 아니다:** 후속 입력 길이·검토 비중·품질 차이가 있고 미확정 호출은 절감률을 산정하지 않는다. 화면에서 비용 증가로 나오면 정밀 검토를 끄거나 단일 모델로 바꿀 수 있다. Solar 현재 사용량 기록과 향후 유료 운영 경제성은 별개다.

같은 원문·판본·규칙·모델 구성·담당자 판단의 완료 분석은 다시 호출하지 않는다. 정밀 검토 한도 실패 때 1차 결과는 보존하며 같은 조건의 재실행은 1차 결과를 재사용한다. 모델이나 검토 구성이 바뀌면 새 구성으로 분석한다. 모델이 생성한 텍스트를 셸·DB 명령으로 실행하지 않는다.

Nemotron 3 Super 무료 경로는 2026-10-30 실제 요청에서 제공 종료 404를 반환했다. 사용 가능한 **3.5 Super VL 무료** 경로를 사용하며 유료 모델로 자동 우회하지 않는다. 공급자 모델 문서: [OpenRouter Nemotron 3.5](https://openrouter.ai/nvidia/nemotron-3.5-super-vl:free), [GPT-6.1 Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra), [Upstage Responses](https://console.upstage.ai/api/responses).

## 판단보류 CSV

- 상단: 수집 + 업무담당의 현재 판단보류 CSV를 한 번에 받는다.
- 각 수집/업무담당 작업자: 해당 역할의 판단보류 CSV만 받는다.
- 알고리즘의 규칙 변경 대기는 작업자 화면에서 확인한다. 수집+업무담당 CSV에 섞지 않는다.
- UTF-8 BOM, 쉼표/개행 인용, 스프레드시트 수식 시작 문자 이스케이프를 적용한다.
- 필드: 역할, 대상 ID/제목, 상태/단계, 보류 사유, 사람이 확인할 일, 원문 URL/판본, 모델/실행/시각, 근거 JSON, 분석 결과 JSON, 수집 본문.
- 같은 자료가 두 역할에서 서로 다른 이유로 보류되면 역할별 두 행이다. 합본은 두 CSV의 합집합을 역할 정보와 함께 보존한다.
- 이후 사람의 유효한 판단으로 해결된 건은 보류 목록에서 제외한다. AI 자료 연결만으로 단계 검토 보류까지 해결됐다고 하지 않는다. 과거 승인이 새 수집 실패를 가리지 않는다.

## 자동 연결의 보호 조건

관련성 점수만으로 승인하지 않는다. 공식 출처, 원문 판본, 기존 사업명, 별도의 숫자가 포함된 주소/사업번호/블록, 후보의 유일성, 비어 있지 않은 원문 직접 인용, 모델의 충돌 사항 없음, 기존 담당자 판단 없음을 검사한다. 저장 직전 원문·담당자 검토·사업 판본을 다시 확인하고 충돌 시 보류한다.

승인 주체는 **업무담당자 AI · 자동 근거 검증**으로 기록한다. 실제 김민 담당자 확인을 사칭하지 않는다. 연결은 근거 자료 연결이며 정책 귀속·물량·목표·실적을 바꾸지 않는다. 단계 정보가 제안되면 자료 연결과 별도로 `STAGE_HOLD`로 남긴다.

## 개발·운영

- `ai_agent_catalog.py`: 모델/역할 고정 허용 목록. 임의 모델·엔드포인트 입력 금지.
- `ai_agents_store.py`: SQLite 역할 설정 버전, append-only 결과, 비용 비교.
- `ai_agents_api.py`: 상태/설정/실행/CSV API. 관리 변경은 기존 HMAC 관리자 인증.
- `ai_agent_workflows.py`: 알고리즘 진단과 업무담당 검증. `ai_collection.py`는 수집.
- `ai_agents_inbox.py`: 최신 역할별 결과와 후속 사람 판단 해소, CSV.
- `ai_collection_worker.py`: 3개 역할의 단일 실행 큐. 기존 실행 이력을 유지한다.
- `GET /api/ai-agents`, `GET /api/ai-agents/{role}/items`, `GET /api/ai-agents/holds.csv?role=all|collection|officer`.
- `POST /api/admin/ai-agents/{role}/settings|runs`, 중지는 기존 `/api/admin/ai-collection/runs/{id}/stop`.

화면의 상태 조회는 업무 원장을 재구성하지 않는다. 결과는 역할 선택/수동 새로고침/실행 상태 전환 때 조회한다. 공통 예산은 서버에서 15초 캐시하며 패널이 닫히면 자동 폴링하지 않는다. 따라서 사용량은 실시간 스트림이 아니라 최근 원장 조회값이다. 비율 막대는 실제 `remaining/limit`과 동일하며 CSP를 완화하지 않고 신뢰된 JS로 너비를 지정한다. Solar 무제한에는 가짜 한도/100% 막대를 표시하지 않는다.

`data/runtime/ai-collection.sqlite3`에 `agent_settings`와 `agent_results`가 추가된다. 기존 호출 원장·작업 결과는 삭제하지 않는다. 원문 파일·업무 DB·SQLite 및 중앙 예산 원장을 함께 백업한다. 회귀 검사는 `tests/test_ai_agents.py`, 기존 수집/예산/캐시 테스트를 사용한다. 공유 원장 테스트는 운영 접속정보 없이 새 임시 Postgres 컨테이너에서 수행했다.


## 외부 검토 후 원문 복구와 업무판단 구분

수집 에이전트의 보류는 추출 품질·첨부 확보 과제이며, 업무담당자 보류는 사업/자산 동일성과 사건 범위의 판단 과제입니다. 같은 자료가 두 목록에 있을 수 있습니다. 결과 화면과 보류 CSV의 현재 업무상태·최근 업무판단사유를 함께 확인합니다. 이미 승인된 자료에 새로운 수집 실패가 생겼다고 기존 승인을 자동 철회하지 않습니다.

담당자가 복구한 원문은 `publication_supplement` 이력에 원문 판본·해시·수집시각·확인내용을 저장합니다. 업무담당자 에이전트는 같은 판본이며 기존 자동본문보다 최신인 수동본문을 사용할 수 있습니다. 더 최신 원문을 오래된 보충본문으로 덮지 않습니다. 수집 실패를 재확인하는 수동 실행은 `MANUAL`·모델 호출 없음으로 구분합니다.
