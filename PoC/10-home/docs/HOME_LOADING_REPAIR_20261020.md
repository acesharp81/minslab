# HOME 로딩 지연 재점검 및 개선 결과 — 2026-10-20

> 이 문서는 1차 완화 조치 기록이다. 남아 있던 최초 계산과 수집 중 재지연은 [후속 심층 점검](HOME_LOADING_DEEP_REPAIR_20261020.md)에서 추가 조사·개선했다. 최신 실행 구성과 최종 측정은 후속 문서를 우선 참조한다.

## 확인한 원인

운영 API 컨테이너의 메모리 한도는768MiB였다. 최초 점검에서747.6MiB(97.35%)를 사용했고,후속 표본에서는 한도에 더 근접했다. 컨테이너의 스왑 사용량은 약337.5MiB였으며 메모리 한도 도달 이벤트가15,955회 관측됐다. 프로세스가 강제 종료된 흔적은 없었다. 큰 화면의 재계산과 메모리 압박이 겹칠 수 있는 상태였다. [원시 측정](analysis/loading_20261020/observed_before.json).

큰 응답도 확인했다. 정책 모델은 약22.8MB,사업별 수집연계는 수정 후 기준 약20.8MB의JSON이다. 단순히 데이터를 더 모아서 행 수가 늘어난 문제만이 아니라,여러 화면의 큰 결과와 재계산이 겹치는 문제가 있었다.

또한 일반 인허가 대량수집의 후보 감사기록이 발생해도 관련 없는 사업 화면의 캐시가 폐기되고 있었다. 브라우저는 어느 원천이든 수집 상태가 바뀌면 현재 화면 전체를 다시 불러왔다. 실제 사업 원장이 바뀌지 않아도 사용자가 보고 있는 사업의 지도와 목록을 다시 그릴 수 있었다.

성능 외에 **사업별 수집연계가HTTP500으로 실패하는 오류**도 확인했다. 일부 부분범위 계획에는 `scope_partial=true`만 있고 `scope_label`이 없는데 표시 코드가 이를 필수값으로 읽었다. 지연처럼 보일 수 있는 조회 실패도 함께 수정했다.

## 적용한 변경

1. 큰 캐시 결과는 압축된 바이트로 보관하고,요청할 때 동일한JSON 바이트를 복원한다. 대표 정책 응답22,768,862바이트는 같은 내용을레벨1로 압축하면1,524,593바이트다. 이는 **서버 캐시 보관량**이며 응답 필드·근거·수량을 줄였다는 뜻은 아니다.
2. 큰 캐시 재계산의 동시 실행을2개로 제한했다. 이미 준비된 결과를 읽는 요청은 이 제한을 기다리지 않으며,동일 요청은 하나의 계산을 공유한다. 내부 캐시를 다시 호출하는 바깥 요청은 중첩 대기가 생기지 않도록 제한 대상에서 제외했다.
3. 사업정보·위치·정책목록·매핑의 변경 감지를 관련 원장 기준으로 좁혔다. 연결되지 않은 일반 인허가와 `START_CANDIDATE_FOUND` 감사만으로 사업 화면을 폐기하지 않는다. 담당자 확인·프로필·일정·정책 매핑 변경은 계속 감지한다.
4. 정책·프로그램·사업 화면은20초마다 가벼운 변경 지문을 확인한다. 지문이 같으면 재조회하지 않고 실제 변경 때만 갱신한다. 편집창이 열려 있으면 자동 재로딩을 보류하고 닫힌 뒤 갱신한다. 수집 중인 원천이 없어도 담당자 입력 변경을 감지한다.
5. 부분범위 설명이 없으면‘부분 범위 · 전체 목표 아님’으로 표시한다. 부분범위·참고값 구분과 집계 제외 의미는 유지한다.
6. API 메모리 한도를1536MiB로 조정하고 배포 스크립트에도 반영했다. `POC10_API_MEMORY_MB`로 조정 가능하며 재배포 시768MiB로 되돌아가지 않는다. 테스트 후 관측한 스왑과 메모리 한도 도달 이벤트는0이다.

DB의 업무 원장과 수량을 변경하지 않았다. 캐시를 읽을 때 변경 검사를 생략하거나 이전 담당자 값을 계속 보여주는 방식으로 속도를 맞추지 않았다.

## 실제 브라우저 확인

동일 호스트의Chromium,1440×1000 화면에서 주요 콘텐츠가 표시될 때까지 측정했다. 메뉴별1회 표본으로 일반적인SLA나 사용자PC의 네트워크 시간을 보장하는 수치는 아니다. 외부 지도 타일·시설 팝업 등 후속 로딩 완료와도 구별한다.

| 프로그램 추진현황 | 5.817초 | 1.295초 | 오류0 |

**재시작 직후 정책 모델의 첫 계산은23.7초로 여전히 느리다.** 최초 계산이 모두 제거됐다고 보고하지 않는다. 이번 변경은 메모리 압박·불필요한 무효화·반복 재로딩을 줄이고 정상 반복 조회를 안정화한 것이다. 서버의 첫 계산과 데이터가 실제로 바뀌어 필요한 재계산에는 여전히 시간이 필요하다. [최초 조회](analysis/loading_20261020/browser-after-cold.json),[반복 조회](analysis/loading_20261020/browser-after-warm.json).

반복API 조회에서는 정책 모델 약0.16초,사업별 수집연계 약0.26초,사업 선택목록 약0.01초,서울 지역통계 약0.005초가 관측됐다. 점검한9개 API를2회 요청했고 모두HTTP200이었다. 브라우저5개 화면에서JS오류와API실패는0건이었다. [API측정](analysis/loading_20261020/api-after.json).

원인 확인용 사전 브라우저 측정의 사업 화면60초는 예전 테스트 선택자 `#project-list table`가 없어 발생한 테스트 타임아웃이다. 이를 실제 사업 로딩60초 또는 개선 배수로 인용하지 않는다. 사전API 측정에서500 직후 지역 요청의 연결 종료는 같은HTTP연결 재사용의 영향도 있으므로 지역API자체의500으로 단정하지 않는다.
