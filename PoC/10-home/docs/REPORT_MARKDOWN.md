# 보고서용 MD 내보내기

2026-10-15 기준. 지역여건·정책·프로그램·사업 화면의 기존 상단 오른쪽에 공통 버튼을 두고, 외부 AI가 보고서를 작성할 때 사용할 수치와 프롬프트를 브라우저에서 하나의 UTF-8 Markdown 파일로 만듭니다.

## 동작과 파일

- 현재 조회 모델을 복사합니다. 화면 표시 문자열을 스크래핑하지 않으므로 채택된 수치의 정밀도와 `null`/`0`, 기준일·원문을 보존합니다. 보고서에서는 HOME 채택값과 담당자 확인·매칭값을 확정 분석 기준으로 사용합니다.
- 지역여건은 9개 비교 지표·가구 구성과 현재 조건, 정책·프로그램은 tracking 원시 계열·지도·6개 통계, 사업은 단계·공정계획·입지/생활 통계를 포함합니다. 정책·프로그램 화면 전환 직후의 마지막 원장 조회도 기다린 뒤 내보냅니다.
- 가구·공급 참고 시나리오와 인구 지수는 실제 차트 계산 결과를 재사용합니다. 사업에서 아직 보지 않은 입지 차트는 기존 lazy 조회를 완료한 뒤 수치를 담습니다.
- 병목·기관 조치는 현재 사업 식별자와 명시된 범위에 연결된 기록만 추립니다. 기술적 확보율·입력 분류·매칭 검토·산정 경위는 보고서에서 제외합니다. 원장과 화면의 내부 정보는 유지합니다.
- 표 ID R/M/P/C/S와 전체 정밀도의 D99 JSON 경로를 제공합니다. 표의 중첩 배열은 부록을 참조하고, 반복되는 tracking 객체와 다른 프로그램의 전체 프로필은 제외해 파일 크기를 줄입니다. 원래 목표 비교와 화면용 tracking 계열은 각각 보존하며 D99는 공백을 줄인 JSON입니다. 빈 배열·미확보·추가 조회 실패는 공식 실적 0으로 대체하지 않습니다.
- 생성 중 화면·조건이 달라지면 다운로드를 중단하고 재실행을 안내합니다. 동일 조건에서 비동기 지도 로딩이 차트 DOM을 바꾸면 새 차트의 조회 완료를 한 번 다시 기다립니다. 생성 버튼은 처리 중 중복 실행을 막고 완료·실패 뒤 복원됩니다.
- 필드의 API 키·토큰·쿠키·암호와 URL 인증정보를 제외하고, 경계 폴리곤은 수치 보고서에서 뺍니다. 원천 텍스트는 데이터로 취급하도록 프롬프트에 명시하고 Markdown 표와 JSON fence를 이스케이프합니다.
- 파일명은 화면·선택명·지역·시군구·비교 연도·기준일·KST 생성시각을 담습니다.

## 보고서 프롬프트

보고서의 핵심 질문은 **추진현황이 목표·일정에 맞는가 / 지금 우리가 어떤 조치를 취해야 하는가 / 장기적으로 무엇을 중점 관리해야 하는가**입니다. 첫 문장에서 점검 결론과 최우선 조치를, 다음 문장에서 장기 관리 방향을 제시한 뒤 수치·도표로 사유를 설명합니다. 목표 대비 진도·일정 이탈·단계 전환 정체·기관별 상태와 기존 조치의 이행·해결 근거를 점검합니다. 이전 상태 자료가 없으면 개선·악화를 단정하지 않습니다.

- 지금 취할 조치: 기준일부터 향후 3개월을 기본 제안 범위로 하여 3~5개 조치를 우선순위로 제시합니다. 대상·구체적 행동·담당/협력기관·기한·기대 효과·이행 확인 지표를 연결합니다. 우선순위는 도래 일정·영향 물량·수급 영향·실행 가능성으로 설명합니다.
- 장기 중점 관리: 향후 1~5년 또는 확보된 사업 기간의 구조적 위험·공급 안정성을 다룹니다. 현재 기준값·관리 지표·목표/경보 기준·점검 주기·책임 주체·기준 이탈 시 조치를 구체화합니다. 확보한 전망 기간을 넘는 정량 예측은 만들지 않습니다.
- 판단 자료가 부족하면 확인할 원천·담당 제안·기한·확인 뒤 결정할 조치를 제시합니다. 미등록 담당·기한·기준은 제안으로 표시하며, 확인되지 않은 원인이나 기대 효과의 수치를 만들지 않습니다.

매뉴얼의 `RequirementsManual.definitions()`에서 F-01~F-12를 읽습니다. 보고서의 F-10은 채택값 기준에 맞춰 갱신·변경 관리 항목으로 구성하며, 매뉴얼 원본은 변경하지 않습니다. 모든 세부 항목에 점검 결론·지금 취할 조치·장기 관리 과제·사유·수치 근거·적용 범위·추가 자료를 답하도록 지시합니다. 자료에 맞는 시각화 최소 5개를 권장하며 시각화할 수치가 없으면 필요한 자료 표로 대체합니다. 각 도표 앞에 그 수치가 어떤 조치·관리 판단으로 이어지는지 한 문장을 쓰게 합니다.

양식은 즉시 조치·장기 관리 요약 → 지금 취할 조치와 이행 계획 → 장기 중점 관리 과제 → 추진현황 점검·주제별 근거 → 요구사항별 답변 → 향후 공급·조치 시나리오 → 후속 점검 일정·의사결정 조건 → 근거 부록입니다. Markdown 표와 Mermaid를 병행하고 원 수치 표를 함께 쓰게 합니다. 실적·계획·대안 시나리오·제안, 지역 전체와 정책 귀속 실적, 예정·입주 시작·실거주, 원문 전망과 최신 통계를 구분합니다. 패키지 식별자는 `HOME_REPORT_MD_V4`입니다.

보고서 입력에서는 `inferred`/`input_status`/`field_provenance` 등 생성·검토 메타데이터, 해당 설명 문구와 기술적 확보 현황을 제외합니다. 자료의 생성 방식이나 매칭 경로를 근거로 신뢰도를 논평하거나 채택값 재검증을 과제로 제시하지 않도록 지시합니다. 채택된 물량·일자·공정률과 지연/주의는 보존하여 추진 점검·즉시 조치·장기 관리에 사용합니다. 미등록 값은 새로 만들지 않으며 향후 목표·일정과 대안 시나리오는 실적과 구분합니다.

## 인쇄·배포용 책자 편집 지침

최종 보고서는 인쇄 후 바로 배포할 수 있는 책자로 작성하도록 지시합니다. 기본 판형은 A4 세로, 양면 인쇄를 고려한 안쪽 22mm·바깥쪽 16mm·위아래 18mm 여백, 본문 10.5~11pt·줄간격 1.5배, 표·주석 9pt 이상입니다. 본문 12~20쪽 내외를 참고하되 선택 범위의 내용에 따라 조정합니다.

표지 → 실제 쪽번호를 반영한 목차 → 의사결정 요약 1쪽 → 즉시 조치·장기 관리 → 점검·주제별 근거 → 요구사항별 답변 → 시나리오·후속 점검 → 수치·출처 부록을 구성합니다. 장별 페이지 구분, 머리말·쪽번호, 표·그림 번호와 캡션·출처를 통일합니다. 표지의 기관·로고·작성자는 제공된 정보만 사용합니다.

차트는 SVG 등 실제 그림으로 렌더링하고 색·선·라벨을 함께 써서 흑백 인쇄에서도 읽히게 합니다. 긴 표는 머리글을 반복하고 행 잘림을 방지하며, 넓은 표는 분할하거나 해당 페이지만 가로로 편집합니다. 원시 JSON과 내부 필드명은 배포 본문에 나열하지 않고 독자에게 필요한 수치·출처만 부록에 선별합니다.

외부 AI가 파일을 만들 수 있으면 인쇄용 PDF를 제공하고, PDF를 만들 수 없으면 전체 내용·차트·인쇄 CSS를 포함한 독립형 HTML을 제공하도록 지시합니다. 직접 확인 가능한 환경에서는 글꼴·도표·잘림·빈 페이지·쪽번호를 확인합니다. 이 기능은 MD에 책자 제작 지침을 담는 기능이며, HOME에서 PDF를 자동 생성하는 기능은 아닙니다.

## 코드와 검증

- `web/assets/report-md.js`: 순수 Markdown 생성기, 범위별 수치 표, 공통 캡처·보완 조회, 정합성 확인, 다운로드.
- `web/assets/report-md.css`: 기존 상단의 한 행을 사용. 좁은 화면에서 기존 선택 조건은 가로 스크롤하고 버튼은 오른쪽에 유지.
- `housing-indicators.js`, `policy-907.js`, `project-information.js`: 현재 모델과 조건의 내보내기 컨텍스트.
- `policy-report.js`: 비동기 가구·인구·재고·시나리오 그래프의 실제 계산 결과와 완료 상태.
- `requirements-manual.js`: 요구사항 정의의 읽기 전용 복사본.
- `tests/js/report-md.test.cjs`: 원 정밀도, 0/미확보, 모든 요구사항·판단 질문, 인증정보·생성 메타데이터 제외, 채택 수치·관리 위험 보존, 범위 필터, Markdown 경계와 파일명, 동일 조건 재렌더·조회 조건 변경·추가 조회 실패 처리.

화면 검증은 네 화면의 실제 다운로드·선택 범위·원시 수치, 위쪽에서 사업 입지 차트 내보내기, 모바일 버튼 위치와 가로 넘침, 대상 외 화면 버튼 숨김을 포함합니다. 내보내기 자체는 외부 AI를 호출하거나 데이터를 수정하지 않습니다.
