## 날짜·식별자·물량 해석

- 공고 식별자는 `HOUSE_MANAGE_NO:PBLANC_NO`, 허가 식별자는 `mgmHsrgstPk`입니다. 21자리 허가 PK도 문자열로 저장해 숫자 정밀도를 보존합니다.
- 공고일과 인허가 레코드 생성일은 `source_date`, 표본 수집일은 `base_date`로 구분합니다. 과거 인허가가 표본에 포함되며 생성일로 현재 진행 중이라고 판단하지 않습니다.
- 건축HUB 공식 명세의 `useInsptDay`·`useInsptSchedDay` 설명과 필드명의 관계는 검토가 필요해 원천 필드명으로 표시하고 실제 준공·사용검사일로 확정하지 않습니다.
- 청약 공급세대수와 인허가 총세대수는 서로 다른 지표입니다. 인허가 원천 값 0은 0으로 보존하고 용도·집계 기준 확인 경고를 표시합니다.
- 일반 민간 공고를 포함할 수 있는 테스트 표본은 `UNMAPPED`이며 기존 정책·사업 레코드와 공식 공급 실적에 합산하지 않습니다. 기존 사업 후보 **150개(서울 12 / 경기 138)**, 공식 공급총량 `null`을 유지했습니다.

## 적재·재수집·보안 검증

세 API 배치 모두 SUCCESS입니다. 두 번째 실제 수집에서도 청약 20 / 인허가 20 / 주소 조회 12개가 모두 `unchanged`였습니다. API 표본 revision은 **52개, 모두 revision 1**, 정책 매핑 0개로 유지됐습니다.

인증키 query를 URL manifest에서 제거하고 응답에 인증정보가 포함될 경우 제거한 bytes를 snapshot으로 저장합니다. API 응답 파일 28개와 두 번 수집의 manifest 32개를 검사해 실제 파일 SHA-256이 manifest와 일치함을 확인했습니다. 같은 레코드의 API 응답 메타데이터가 달라 snapshot이 늘어도 내용이 같으면 레코드 revision은 늘지 않습니다. 저장 파일·배치·레코드·공개 API·CSV에서 설정한 API 키가 노출되지 않음을 검사했습니다.

원문은 `data/raw/{source_id}/{sha256}.json`에 보관하며 Git·정적 웹 경로에 공개하지 않습니다. 공개 상세 화면에는 인증정보를 제거한 요청 URL·응답 SHA-256·레코드 SHA-256·수집 revision을 제공합니다.

## 조회와 실행

공개 메뉴 **API 테스트 데이터**에서 지역·유형·표본명·주소·식별자로 검색하고 상세 근거·원천 날짜·좌표 결과를 확인합니다. CSV는 현재 조회 조건을 적용하며 수식 문자로 시작하는 원천 텍스트를 안전하게 처리합니다.

```bash
sudo docker exec poc10-home-api python -m scripts.collect --samples
```

MinsLab 관리자 로그인 후 같은 메뉴의 `표본 다시 수집`으로 재실행할 수 있습니다. 내부 `POST /poc/home/api/admin/refresh?mode=sample`은 기존 관리자 인증·동일 출처 검증을 사용합니다. 기본 24시간 수집은 7개 웹·파일 원천만 실행하고 API 표본 원천은 수동으로 실행합니다.
