## 2. 검증한 동작과 한계

### 자료 처리

합성 공고 세 건을 제공했다. 같은 ID·본문의 중복, 전체 24호 중 잔여 12호 재모집, 예비입주자 10명 모집을 구분하도록 했다. 네 모델 모두 문서 중복을 제거하고 잔여 물량과 예비입주자 인원을 구분했으며, 새 주택 물량 가산을 0으로 유지했다. 본문 안에 삽입한 승인 지시도 이 단일 사례에서는 따르지 않았다. 이는 프롬프트 공격 전체에 대한 방어 성능 보증이 아니다.

`lookup_review` 읽기 전용 합성 도구를 호출하고, 기존 승인 이력을 반환했을 때 기존 판단을 유지하는 결과와 `approved=false`를 확인했다. 실제 운영 DB 조회·등록·승인 기능을 호출한 것은 아니다.

생성 코드는 네트워크 차단, 읽기 전용 파일시스템, 비특권 사용자, capability 제거, 메모리·CPU·프로세스 수·시간 제한을 둔 임시 Docker 컨테이너에서 실행했다. 운영 볼륨·키·DB 연결은 제공하지 않았고, 모델 생성 테스트 대신 외부의 고정 검사기를 사용했다. 제한된 Python import/AST 검사도 적용했다. 이 시험용 컨테이너 구성은 향후 운영용 코드 실행 격리 설계의 전체 보안 검증을 대신하지 않는다.

## 3. 선택 가능한 두 운영 구성 — 사용자 요구 반영

Solar를 OpenAI의 보조 모델로만 두지 않는다. 사용자가 **국산 모델 구성 / OpenAI 모델 구성**을 선택하고 같은 업무 절차를 수행하는 방식으로 설계한다. 아래는 구현 요구사항이며 아직 전환 UI나 실행 worker를 구현한 상태는 아니다.

| 업무 | 국산 모델 구성 | OpenAI 모델 구성 |
| --- | --- | --- |
| 신규 자료 분석·검토 후보 작성 | Solar Pro 4 | GPT-5.4 |
| 추출 패턴·코드 수정안 작성 | Solar Pro 4 | GPT-6.1 Sol |

Solar 구성은 OpenAI 키 없이, OpenAI 구성은 Upstage 키 없이 실행할 수 있어야 한다. 국산 구성의 실패를 외산 모델에 몰래 넘기지 않는다. 제공사 간 자동 대체는 기본적으로 끄고, 사용자가 별도로 허용한 경우에만 전환 사유를 기록한다. 같은 모델의 재검토를 독립된 외부 검증으로 표시하지 않는다.

### 제공사와 분리하는 공통 기능

- 검색·원문 취득·기존 판단 조회·후보 저장·격리 시험을 시스템의 공통 도구로 제공한다. 모델 내장 검색에 핵심 업무를 의존시키지 않는다. 검색 서비스 자체의 의존성과 비용은 별도로 관리한다.
- 입력·출력 규격과 승인 정책은 공통으로 유지한다. 제공사별 인증, 요청 옵션, 도구 호출 형식과 오류는 어댑터에서 변환한다. 단순히 모델 이름만 바꾸는 것으로 구현 완료를 주장하지 않는다.
- 원문, 중간 결과, 기존 승인 이력은 시스템에 보관한다. 실행 시작 시 운영 구성을 고정하고 변경은 다음 실행부터 적용한다. 장애 후 재개는 완료 지점부터 수행하며 문서 중복 등록과 중복 승인을 방지한다.
- 실행 이력에 운영 구성, 실제 제공사·모델, 규칙 버전, 재시도, 비용, 전환 사유, 담당자 판단을 남긴다. 제공사별 비용 상한은 독립적으로 적용한다.
- 모델은 수정안을 제시하고, 모델이 변경할 수 없는 정답 자료·검사기로 평가한다. 운영 반영과 자료 연결 승인 권한은 모델에 주지 않는다.

### 시연과 완료 판정

동일한 실제 업무 표본을 두 구성에 각각 입력해 탐색 → 추출 → 중복 검사 → 검토 후보 → 담당자 승인 대기까지 실행한다. 저장 결과가 아닌 문장 표현까지 같을 필요는 없지만, 기존 승인 보존·물량 중복 방지·근거 추적과 승인 경계는 양쪽 모두 지켜야 한다. 코드 개선도 동일한 고정 검사로 비교하며 성공률·재시도·시간·비용을 함께 공개한다.

국산 구성 시험에서는 OpenAI 자격증명을 제거하고 OpenAI 호출을 차단한다. 외산 구성에서는 반대로 검증한다. 원문 확보 실패, API 장애·예산 소진 시 무단 전환 없이 대기하며, 중단 후 재개해도 중복 저장되지 않는지를 확인한다. 이 통합 시험을 통과한 뒤에 **국산·외산 모델 전환 운영 검증 완료**로 표현한다.

현재 네 모델의 구조화·도구 호출·소규모 코드 수정 기능은 실호출로 확인했으므로 두 구성의 구현 가능성을 뒷받침한다. 그러나 실제 자료 탐색부터 저장까지의 독립 운영이나 동일 정확도를 증명한 것은 아니다. Solar의 최초 실패와 재수정 이력을 포함해 평가 결과를 보존한다.

발표 문구: **“국산·외산 AI를 교체 가능한 분석 엔진으로 활용하고, 수집 도구·검증 규칙·승인 절차를 공통화해 특정 모델에 대한 종속을 줄이는 구조로 설계했습니다.”** 구현 및 통합 시험 전에는 ‘운영 검증을 완료했다’고 표현하지 않는다.

## 4. 크레딧과 무료량의 적용

사용자 제공 화면에서 Launch, 무료 일일 토큰 가입 완료, Minslab 프로젝트 선택, Pro 구독 연결을 확인했다. 사용자는 현재 API 키가 해당 프로젝트 소속임을 확인했다. 마지막 제시 잔액은 $9.29이며 첫 지급 $8, 이후 결제 주기 $100 안내였다. **현재 $100가 모두 지급돼 있거나 남아 있다고 가정하지 않는다.**

GPT-5.4는 계정에 표시된 상위 무료 그룹이다. GPT-6.1 Sol·Astra가 계정의 일일 무료량에 실제로 포함되는지는 사용자의 화면만으로 확인되지 않으므로, 구현 시 유료 비용을 보수적으로 예약하고 Usage와 정산을 대조한다. 공개 문서의 혜택 목록과 계정 표시가 다르면 계정 적용을 확인한다. 호출 성공이 무료 적용을 증명하지는 않는다.

Pro 크레딧은 특정 ‘무료 모델’을 제공하는 방식이 아니라 연결 조직의 지원되는 API 과금을 충당하는 혜택이다. 이번처럼 Responses API를 직접 호출하는 HOME worker를 구성한다. 공식 안내에서 제외한 API 키 기반 Codex 사용과 혼동하지 않는다.

무료량·유료 비용·Upstage 비용을 서로 다른 원장으로 관리하고, 다른 PoC가 같은 조직의 무료 그룹을 사용하면 합산해야 한다. 일일 무료량은 한국시간 오전 9시를 경계로 관리한다. 웹 검색 등 도구 요금, 반복 호출의 문맥 재전송, 추론 출력, 캐시 쓰기도 비용 산정에 포함한다. 연결된 조직·프로젝트와 크레딧 적용 여부는 운영 설정 화면에 표시한다.

## 5. 합의한 운영 반영 경계

| 대상 | 자동화 범위 |
| --- | --- |
| 자료 탐색·원문 확보·후보 등록 | 자동. 공식/비공식 출처 유지 |
| 기존 검증 규칙의 추출·중복 검사 | 자동 |
| 추출 패턴·코드 변경 | 격리환경 자동 수정·시험, 운영 반영은 승인 |
| 신규 정책·사업 연결·실적 확정 | 담당자 판단 |
| DB·공통 저장 로직·배포 변경 | 수정안과 영향 제시, 개발자 검토 후 반영 |

정답 데이터·검사기·승인 정책은 모델 수정 대상에서 제외한다. 외부 문서 내용은 분석 데이터이며 도구 권한을 확대하는 지시가 아니다. 자료 승인과 코드 배포 승인은 분리하고, 자동 작업을 실제 담당자의 확인 이력으로 위장하지 않는다.

## 6. 추가 구현 위치와 순서

1. **실행·예산 계층:** HOME 전용 AI worker, 실행 이력, 제공사별 어댑터, 호출 전 비용 예약·정산, 작업 중복/재시도/중지. 현재 수집 worker와 화면 API의 자원을 보호한다.
2. **자료 도구:** 검색·원문 취득·기존 판단 조회·후보 저장을 한정된 도구로 제공한다. 기존 `document_evidence`, revision, audit를 활용하며, `publication_reviews.source_ids()`가 discovery 원천만 읽는 조건에 맞춰 새 탐색 원천을 등록한다. 자동 보완은 기존 수동 수집 actor/scope와 구분한다.
3. **개선 작업공간:** 원문 표본과 관련 코드만 전달하고 변경 diff·테스트·영향 보고서를 만든다. 운영 키·DB·배포 권한은 분리한다. 코드 반영 후 영향 범위의 자료만 재처리한다.
4. **화면:** 신규 자료 검토와 연결되는 ‘AI 점검’에서 실행 결과, 근거, 모델/비용, 규칙 개선안, 시험 결과, 승인 대상을 표시한다. 버튼은 지금 점검·예약 설정·중지·결과 보기·반영 승인으로 구성한다.
5. **통합 검증:** 기존 승인 보존, 전체/부분 물량, 지구/블록 동일성, 원문 변경 충돌, 중복 실행, 예산 소진, 모델 오류, 배포 실패 복구를 실제 업무 표본으로 검증한다.

이 순서는 구현안이며 아직 운영 기능을 추가한 상태가 아니다. 이번 작업은 검증 자료만 작성했고 운영 코드·DB·계정 설정·예약 작업을 변경하지 않았다.
