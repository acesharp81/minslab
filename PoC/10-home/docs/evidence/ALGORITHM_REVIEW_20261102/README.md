# 알고리즘 개선안 사람 검토 인터페이스 — 2026-11-02

알고리즘 진단에 대한 사람의 조치 화면과 실제 추출 규칙 적용 경로를 추가했다. 신규 자료 검토 → AI 작업자 → 알고리즘 → 개선안 검토·조치 대기 → 개선안 검토·판단하기에서 사용한다.

## 실제 구현 범위

- 현재 방식·제안 사유·적용 범위·추출 전후 본문·검증 결과를 확인한다.
- 관리자만 원문 시험 및 판단을 저장한다. 담당자 이름·사유와 변경 이력을 남긴다.
- 패턴 반영 승인 / 일시 오류로 종료 / 재분석 요청 / 적용 해제를 지원한다.
- 승인 대상은 AI 자료 수집기의 HTML 본문 CSS 규칙이다. 운영 소스 코드, API 수집기, 날짜·물량 판정은 변경하지 않는다.
- URL 제한 또는 같은 사이트·경로 제한으로 저장한다. URL 제한 규칙은 다른 쿼리의 공고에 확대 적용되지 않는다.
- 같은 경로 적용은 서로 다른 과거 정상 자료 2건 이상의 기존 본문 보존 시험이 필요하다. 새 제안 모델이 생성한 시험 목록만으로 통과시키지 않는다.
- 승인한 규칙은 다음 AI 수집부터 적용한다. 불일치 시 기본 추출기로 복귀하고 수집 오류를 남긴다.
- 재분석 요청은 다음 알고리즘 실행에 담당자 의견을 전달한다. 버튼 저장만으로 모델을 호출하지 않는다.
- 편집 중 자동 목록 갱신을 막고 역할·분류 이동 시 미저장 내용을 확인한다.

## 확인 결과

관련 회귀 검사 142개 통과(경고 1개). 승인·적용 해제와 실제 추출 연결, 비인가 저장 차단, 오래된 진단·판본·검증 결과·규칙 버전 충돌, 동일 자료 중복 회귀 사례 차단, 사업자료 보존, 완료 입력의 불필요한 모델 재호출 방지를 검사했다.

실서비스 브라우저에서 상세 지연 로딩, 비로그인 입력 비활성화, 시험 전 승인 차단, 관리자 버튼, 미저장 입력 보호를 확인했다. 관리자 UI는 브라우저 내 상태만 바꿔 렌더링을 검사했으며 서버 인증을 우회하거나 운영 판단을 저장하지 않았다. 데스크톱 1440px·모바일 390px에서 수평 넘침과 브라우저 오류가 없었다. `browser-check.json`과 스크린샷을 참고한다.

알고리즘 NO_CHANGE 4건에 업무자료의 보류 상태가 덮어씌워지던 표시 오류를 정정했다. 집계는 검토 대기 57→53, 완료 23→27이다. 4건의 사업 연결 보류를 승인한 것은 아니다.

API와 AI 작업자 모두 정상 기동을 확인했다. 알고리즘 01시·수집 02시·업무담당 03시(KST), 모델 및 기존 수집 한도를 보존했다. 주요 로컬 API 응답은 약 0.03~0.25초였다. 운영 검토·검증·규칙 테이블은 각 0건으로, 기능 검사를 이유로 운영 규칙을 승인하지 않았다. 모델 호출을 요청하지 않았다.

첫 배포에서 기존 이미지의 defusedxml 의존성 누락으로 API 기동이 실패해 기존 버전으로 원복했다. 명시된 의존성을 포함하고 별도 포트 사전 기동 검사를 통과한 이미지로 재배포했다. 최종 이미지·복구 컨테이너 정보는 `deployment-final.json`에 기록했다. CSS 정렬 보완은 API에만 추가 적용했으며 AI 작업자에는 동일한 검증 완료 백엔드가 실행된다.
