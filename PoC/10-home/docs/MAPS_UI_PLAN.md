# HOME 공급현황 지도 UI 개편 플랜

작성일: 2026-10-03 · 상태: 2차 구현 완료, 공급 블록–건물 확정 연결·요약 API 분리 대기

프로젝트는 **HOME · Housing Operations Monitoring & Execution — 주택정책의 실행·모니터링**을 유지한다. MAPS는 이번 지도 UI 개편의 작업명이다. 대상은 기존 `/poc/home` 및 `/home`의 공급현황 화면이며 관리 범위는 서울특별시·경기도다.

## 1. 목적과 레퍼런스 적용

**Map = Dashboard**를 원칙으로 공급현황을 지도 중심의 작업 화면으로 바꾼다. **기본 동작은 시도·시군구의 2D 집계 → 확대 시 지구·블록 상세 → 확보된 블록·건물의 3D 전환**이다. 건물별 형상·규모가 연결된 곳은 근거에 따른 3D 건물까지 선택한다. 축소하면 2D 지역 집계로 돌아간다. 모든 확대 수준에서 건물 3D를 계속 표시하는 방식은 기본안으로 채택하지 않는다.

| 첨부 이미지 | 적용할 구조 | 데이터 원칙 |
| --- | --- | --- |
| 전체 공급현황 | 좁은 좌측 패널, 넓은 지도, 단지 목록과 일정 | 이미지의 단지명·세대수·날짜를 복사하지 않는다 |
| 단지·건물 선택 | 주변은 회색, 선택 사업 강조, 작은 건물 상세창 | 실제 연결된 식별자·형상·규모만 사용한다 |
| 넓은 지역 보기 | 낮은 대비의 도시 배경, 사업 위치의 간결한 표시 | 시도·시군구 통합 현황에서 지구·블록으로 전환한다 |

없는 수치는 `미확보`, 위치·정책 관계가 확인되지 않은 자료는 `미연계`, 예정일이 없는 자료는 `일정 미정`으로 표시한다. 지도 위의 반복 숫자·부가 차트는 줄이되 핵심 항목의 미확보 상태는 좌측 요약에서 확인할 수 있게 한다.

## 2. 현재 구현 점검과 재사용 범위

| 현재 구성 | 개편 방향 |
| --- | --- |
| Leaflet + VWorld 서버 타일 프록시 | 1차 레이아웃 개편에 재사용, 실제 건물 3D 단계에서 렌더러 교체 검증 |
| 시군구 원그래프, 블록별 세로 막대 | 집계·누적 전망 계산을 재사용하고 확대 단계와 선택 연동 정비 |
| 우측 정책 탭·시도 그래프·사업 상세 | 좌측 통합 패널로 이동, 선택 범위에 따라 내용 전환 |
| 지도 아래 큰 연도·단계 카드와 일반 대시보드 | 연도 조작은 지도 하단에 압축, 상세 표는 별도 메뉴로 연결 |
| 정책·프로그램·지역·원천·자료 연도 필터 | 유지하고 하나의 조회 상태로 통합 |
| 목표 관리·매칭 승인·CSV·근거 이력 | 기존 기능과 권한을 유지하고 좌측 상세에서 진입 |
| 실제 공정률·과거 보고서 | 공급량과 분리하여 공정률·보고 시점·원문 표시 |

**현재 입체 표현의 한계:** `web/assets/apartment-shapes.js`는 공식 공동주택 **용지 도형**을 화면상 높이로 돌출시키는 SVG 표현이다. `backend/map_data.py`의 `LT_C_LHBLPN` 자료도 지구에 속하는 공동주택용지를 모은 것으로, 개별 블록 경계나 실제 아파트 동의 외곽선·높이를 확정하지 않는다. 현재 입체 모양을 실제 건물로 설명하면 안 된다.

건축물대장 수집은 동명·세대수·허가/착공/사용승인일 등을 저장하지만 현재 정규화에는 건물 외곽선·높이·층수가 연결되어 있지 않다. 원본에 해당 항목이 있는지 먼저 검사하고 부족한 항목만 추가 원천을 검토한다. 건축물대장의 기존 주택 재고는 신규 공급량에 합산하지 않는다.

## 3. 전체 화면 배치

데스크톱 좌측 패널은 기본 **340px**, 조정 범위 **320~360px**로 구성한다. 지도가 남은 폭과 높이를 차지하고 공급현황 내부에서는 패널 목록만 스크롤한다.

```text
┌─────────────────────────────────────────────────────────────────┐
│ HOME 메뉴 · 정책/프로그램 선택 · 검색 · 자료 연도 · 공급 기준     │
├──────────────────┬──────────────────────────────────────────────┤
│ 서울·경기 > 지역 │ 선택 지역 경로     전체/위에서/비스듬히/북쪽 │
│ 공급 현황        │                                              │
│ 목표·현재·예정   │                                              │
│ 올해 목표·비율   │             MAIN MAP                         │
│ 자료 확보 범위   │  넓게: 시도·시군구 통합 진행 현황            │
│ ──────────────── │  확대: 지구·블록·연결 건물의 3D 보기         │
│ 지역/지구/단지   │                                              │
│ 목록과 진행 상태 │                              확대·축소·범례  │
│ ──────────────── │                                              │
│ 입주·준공 일정   │  자료 연도 이동 / +1·+2·+3년 예정 보기      │
│ 원문·자료 기준   │  축척 · 공간정보 출처                        │
└──────────────────┴──────────────────────────────────────────────┘
```

- 공급현황에서는 기존 전체 메뉴를 접기 가능한 메뉴/아이콘 레일로 줄여 넓은 사이드바 두 개가 생기지 않게 한다. 다른 메뉴의 구조는 유지한다.
- 큰 소개 제목과 범위 카드는 짧은 지도 헤더로 압축한다. 지도 아래에 정책·지역 요약을 반복하지 않는다.
- 정책 선택은 상단 탭/선택기로, 프로그램은 연결 필터로 제공한다. 탭이 많으면 가로 스크롤하며 전체 선택도 제공한다.
- 범례는 작은 버튼으로 열고 닫는다. 수치 근거와 긴 설명은 좌측 접기 영역에 둔다.
- 모바일에서는 지도를 기본 화면으로 유지하고 패널을 접기 가능한 하단 시트로 바꾼다. 긴 목록 아래로 지도가 밀려나지 않게 한다.

## 4. 탐색 구조와 확대 단계

정책·프로그램은 조회 관점이고 행정구역은 공간 탐색 축이다. 기존 모델에서 확인되지 않은 복수 정책/프로그램 관계를 임의 생성하지 않는다.

```text
조회 관점: 정책 → 연결 프로그램 → 관련 지구·사업
공간 탐색: 서울·경기 → 시도 → 시군구 → 지구 → 블록/단지 → 건물
```

두 축은 동일 사업 집합을 선택하는 필터로 결합한다. 정책·프로그램 변경 시 가능한 경우 지역·자료 연도·선택 사업을 유지한다.

| 단계 | 확대 수준 초안 | 지도 | 좌측 패널 |
| --- | --- | --- | --- |
| 시도 | 7~9 | 2D, 서울·경기 경계와 시도별 통합 원그래프 | 선택 정책의 시도별 목표·현재·예정 비교 |
| 시군구 | 10~12 | 2D, 시군구 경계·물량 원그래프・지연/이행 확인 표식 | 선택 시군구 요약과 지구 목록 |
| 지구 | 13~15 | 기본 2D, 확보한 용지/사업 경계・개별 블록 선택 표식 | 지구 개요와 블록/단지 목록 |
| 블록·단지 | 16~18 | 데이터 준비 후 3D, 정확히 연결된 경계·건물과 간결한 블록 막대 | 공급·공정·일정과 건물 목록 |
| 건물 선택 | 상세 상태 | 선택 동 강조와 작은 팝업 | 동명·세대수·층수·높이·근거 중 확보 항목 |

확대 숫자는 초기 설계값이며 화면 크기·도형 밀도로 조정한다. 사용자가 단계를 직접 선택할 수도 있고 선택 경계에 맞춰 이동한다. 경계 수준의 휠 조작에서 화면이 반복 전환되지 않도록 전환 여유를 둔다.

현재 경기 경계는 시·군 단위로 합쳐져 있다. 일반구 단위가 필요하면 공식 구 경계와 사업 귀속부터 확보한다. 시도 표시용 윤곽은 기존 시군구 도형 합집합을 활용할 수 있으나 생성 방법·원천 버전을 기록한다.

지구 대표점만 있는 블록은 해당 지구 목록으로 접근한다. 대표점 주변에 블록을 임의 배치하거나 실제 건물 지붕에 연결된 것처럼 그리지 않는다. 정확한 위치가 없는 자료도 좌측 `위치 미연계` 목록과 통계 확보 범위에 남긴다.

## 5. 좌측 패널

### 공급 요약

선택 정책·프로그램·지역·자료 연도·공급 기준을 먼저 적고 다음 값을 압축해 표시한다.

| 핵심 항목 | 표시 기준 |
| --- | --- |
| 목표 공급량 | 해당 범위의 중복 제외 사업계획량. 정책 발표 목표는 별도 줄에 대상 지역·기간 표시 |
| 현재까지 공급량 | 선택 기준의 실제 확인량. 본 모집공고만 확보하면 `모집공고 확인량` 표시 |
| 올해 목표 | 확보된 당해연도 원천 예정량. 관리자 목표는 별도 표시 |
| 올해·누적 달성률 | 동일 기준·동일 사업 집합의 분자/분모가 확보된 경우만 계산 |
| 향후 +1·+2·+3년 | 현재 확인량과 중복되지 않는 예정량의 누적 전망. 신규 증가분도 확인 가능 |
| 완료/입주 전망 | 원천 날짜와 대상 범위. 부분 사업의 마지막 날짜는 `확보 일정의 최종 예정` 표시 |
| 지연 현황 | 지연 확인·지연 후보·이행 확인 필요를 구분하고 목록으로 이동 |

정책 발표량과 서울·경기 확보 사업계획량은 범위가 다를 수 있다. 전국·수도권 목표를 서울·경기 부분 수집 사업 비율의 분모로 쓰지 않는다. 목록 전체의 계획량이 확인되지 않으면 `확보 계획 소계`로 표시한다.

현재 확인량이 부분 수집의 하한이면 `공고 확인 비율(하한·연결 검토)`처럼 의미를 드러낸다. 공급 실적이 없으면 공정률·공급계획으로 대체하지 않는다. 분모 미확보 또는 0이면 비율도 `미확보`다. 확인된 0과 결측값을 구분한다.

### 지역·지구·블록 목록

현재 공간 단계의 바로 아래 항목을 보여준다. 시도 선택 시 시군구, 시군구 선택 시 지구, 지구 선택 시 블록/단지 목록으로 바뀐다.

블록은 **이름 / 확보 공급계획량 / 현재 단계 / 원천 공정률 / 주요 예정일**만 기본 표시한다. 작은 계획/실적 그래프는 비교 가능한 원천 값이 있을 때 사용한다. 일정 자료만 있는데 계획 공정률 곡선을 만들지 않는다. 상세는 선택 시 패널 안에서 펼친다.

인허가·착공·분양/모집·준공·입주는 독립 이정표로 표시한다. 분양과 공사는 겹칠 수 있으므로 레퍼런스의 배열을 모든 사업에 동일한 순서의 진척률로 해석하지 않는다. 계획/예정은 옅은 선, 실제 확인은 채운 표식으로 구분한다.

### 일정과 근거

입주·준공 일정은 짧은 시간축과 목록을 함께 보여준다. 월 자료는 월까지 표시하고 임의 일자를 부여하지 않는다. 예정일 없는 사업은 `일정 미정` 목록으로 표시한다.

아래에 원문 링크, 보고 기준일, 수집일, 매칭 검토 상태를 제공한다. 공정률 보고 시점과 등록일을 구분하며 원본 사진 월을 사용하는 기록은 월 정밀도와 날짜 근거를 유지한다. 목표 수정·매칭 검토·CSV는 기존 기능으로 연결한다.

## 6. 지도 그래픽 규칙

### 시도·시군구: 통합 진행 현황

- 원의 **면적**을 확보 목표량에 비례시킨다. 최소·최대 표시 크기를 두고 실제 호수는 숫자로 확인한다.
- 12시 방향부터 시계 방향으로 현재 누적 확인 비율을 채운다. +1/+2/+3년은 현재 확인 구간 뒤에 증가분만 이어 붙인다.
- 잔여 구간은 옅게 표시한다. 미이행 계획과 실적 미확인 범위를 구분하여 실제 잔여 공급으로 단정하지 않는다.
- 올해까지 누적 목표는 외곽의 짧은 눈금으로 표현한다. 올해 연간 목표와 구분한다.
- 지도에는 지역명·핵심 비율만 기본 표시한다. 목표·확인량·향후 물량은 호버/선택 패널에서 확인하며 큰 흰 카드로 지도를 가리지 않는다.
- 목표·확인량 미확보이면 채워진 0% 원을 만들지 않는다. 점선/미확보 표시를 사용한다. 상한 초과는 그래픽만 제한하고 실제 숫자와 범위 검토 문구를 보존한다.
- 단계는 기본 색, 일정 지연은 경고 테두리/아이콘과 문구로 표시한다. 색만으로 의미를 구분하지 않는다.

### 지구·블록: 3D와 얇은 공급 막대

주변 도시·건물은 낮은 대비의 회색, 선택 지구·블록은 경계선, 연결 건물은 단계 색으로 강조한다. 한 블록의 공급 요약은 **얇은 세로 막대 하나**로 유지한다.

- 옅은 전체 막대: 확보한 블록 공급계획량.
- 아래쪽 채움: 선택 기준의 현재 확인량.
- 목표 눈금: 기준일까지 누적한 원천 목표. 관리자 연간 목표는 별도 표시.
- +1/+2/+3년: 현재 확인량 위에 중복 없는 증가분을 쌓은 구간과 눈금.
- 중첩되면 블록명·단계 표식만 남기고 상세는 패널에 모은다. 미확보 수치·근거 없는 미래 눈금은 생략한다.

건물의 **물리 높이**와 공급량 막대의 **물량 높이**는 의미가 다르므로 단위·범례를 분리한다. 공정률 50%를 이유로 건물을 절반 높이로 만들지 않으며 세대수로 동수·층수·배치를 추정하지 않는다.

### 건물 상세

실제 식별자·외곽선·블록 연결이 확보된 경우에만 건물을 선택할 수 있게 한다. 팝업은 동명, 확보된 층수/높이, 세대수, 연결 일정, 원천과 기준일을 짧게 표시한다. 블록 공정률은 `블록 공정률`로 표시하고 개별 동의 공정률로 전파하지 않는다. 블록의 입주 예정도 개별 동의 확인 입주일로 바꾸지 않는다.

동별 규모 차트는 동별 원천 값이 있을 때만 만든다. 높이 미확보이면 평면 외곽선을 유지하고 `높이 미확보`로 표시한다. 공식 계획 배치도는 계획 레이어로 분리하며 기존 건물·실제 건설 상태로 오해되지 않게 한다.

## 7. 실제 3D 지도 구현 경로

### 권장 구조

**레이아웃·지역 집계를 먼저 개편하고, 실제 건물 3D는 데이터 적합성 확인 후 렌더러를 교체한다.** Leaflet은 초기 작업과 장애 시 대체 화면에 활용한다. 과도기 용지 입체 표현에는 `용지 도형 시각화 · 실제 건물 형상/높이 아님`을 명시한다.

기본 검토안은 **MapLibre GL JS + 기존 VWorld 배경 타일 + 검증된 건물 외곽선/높이**다. 공식 예제는 건물 높이 속성을 사용하는 `fill-extrusion`과 카메라 기울기를 제공한다. 이는 렌더링 기능의 근거이며 서울·경기의 건물 데이터가 확보되었다는 뜻은 아니다. [공식 3D 건물 예제](https://maplibre.org/maplibre-gl-js/docs/examples/display-buildings-in-3d/).

지형·도시 전체 3D Tiles/모델이 필요한 경우 Cesium 또는 VWorld 3D 서비스의 접근·개체 선택·사업 연결 가능성을 별도 비교한다. Cesium은 공간 엔티티와 glTF 모델을 다룰 수 있다. [공식 Entity/모델 안내](https://cesium.com/learn/cesiumjs-learn/cesiumjs-creating-entities/). 실제 국내 데이터로 검증한 뒤 하나의 엔진을 정한다. 레퍼런스 같은 주변 도시 건물 표현은 배경 데이터 제공 범위·이용 조건 확인 후 적용한다.

전환 후에는 하나의 렌더러에서 지역 집계와 건물 상세를 모두 처리한다. 넓은 범위에서는 카메라 기울기 0도의 2D 보기와 요약 레이어를 사용하고, 블록 단계에서 필요한 공간정보를 조회한 뒤 3D 레이어와 기울기를 전환한다. 두 엔진을 겹쳐 독립 카메라를 움직이는 구조는 피한다. 조회·선택 상태는 렌더러 밖에 두어 2D 대체 화면에도 전달한다. 구체적인 부하·전환·개별 블록 연결 검토는 아래 13절을 따른다.

### 데이터와 연결 사전 점검

| 필요 자료 | 점검·확보 작업 | 없을 때 |
| --- | --- | --- |
| 시도·시군구 경계 | 기존 공식 경계 재사용, 행정 수준·버전 확인 | 상위 범위 목록 유지 |
| 정확한 지구/블록 경계 | 용지 원본의 블록 식별자 확인, 공식 사업 자료와 교차 검증 | 지구 용지만 표시, 블록 위치 미연계 |
| 실제 건물 외곽선·식별자 | 공식 건물 공간정보의 제공 범위·키/권한 확인 | 실제 건물 3D 생략 |
| 동별 높이·층수 | 대장 원본 필드 검증 후 정규화, 원천 식별자 연결 | 확보된 평면/속성만 표시 |
| 예정 건물 배치·규모 | 공식 설계·배치 자료의 좌표·동 식별자 검증 | 계획 경계만 표시, 가상 동 생성 금지 |
| 주변 도시 3D | 배경 데이터의 범위·날짜·사용 조건 검증 | 기존 2D 배경 유지 |

대장 표본은 이름·주소 일부가 같다는 이유로 정책 사업에 합산하지 않는다. 공간 일치·대장 식별자·사업/블록 근거를 검사하고 검토 상태를 남긴다. 과거 조회에 현재 형상을 쓰면 `현재 확보 형상 · 과거 형상 아님`을 표시한다.

MapLibre 렌더러 자체를 쓰기 위해 새 공급 데이터 API 키가 필요한 것은 아니다. 실제 건물·3D 배경 원천의 권한은 별도로 확인한다. **현재 VWorld 키가 모든 3D/건물 서비스의 사용을 보장한다고 가정하지 않는다.** 추가 키가 필요한 원천을 확정한 뒤 `docs/API_KEYS.md`와 `.env.example`에 정확한 서비스명·발급 링크·변수명을 추가한다. 이 설계 작업에서는 기존 키와 `.env`를 변경하지 않는다.

브라우저 공개 토큰이 필요한 SDK는 도메인 제한·허용 서비스·이용 조건을 확인한다. 기존 서버용 키는 브라우저로 전달하지 않는다. WebGL에 필요한 CSP/worker 설정은 구체적인 엔진 요구만 허용하고 정적 자산은 기존 배포 방식에 맞춘다.

## 8. 기존 데이터·API 유지와 최소 확장

source revision, mapping/승인, audit, 목표, 보고서 모델을 유지한다. 화면 개편을 위해 전체 Master 모델이나 공급량 산식을 다시 만들지 않는다.

| 기존 API | 재사용 역할 |
| --- | --- |
| `/api/map/dashboard` | 사업·분류 집계·시군구·지구·블록·누적 전망·이정표 |
| `/api/map`, `/api/tiles/{z}/{x}/{y}.png` | 도형·대표 위치·VWorld 배경 |
| `/api/policy-monitor` | 정책 개요와 연결 범위, 기존 상세로 연결 |
| `/api/projects`, `/api/history` | 사업 상세·과거 공정 보고·원문 이력 |
| `/api/map/supply.csv`, `/api/history/export.csv` | 조회 범위 물량·공정률 근거 다운로드 |

표에서는 접두사 `/poc/home`을 생략했다. 기존 query와 응답 필드는 유지한다. 지구·시도 요약은 기존 사업 ID 집합과 서버 중복 제외 규칙을 재사용하는 조회용 어댑터로 구성한다.

공간 선택과 CSV에 부족한 부분만 하위 호환 방식으로 확장한다. 선택 지역 식별자/단계, 건물 geometry 참조·연결 근거·높이 정밀도·공간정보 버전은 선택 필드로 추가한다. 공간별 CSV가 필요하면 기존 `group_by`에 시군구/지구/블록을 추가하되 기존 값의 의미를 바꾸지 않는다. 지도·패널·CSV는 같은 서버 범위 계산을 사용한다.

건물 원본과 대규모 대장 JSON 전체를 `/map/dashboard`에 포함하지 않는다. 건물 상세는 선택 블록 또는 `bbox`·확대 수준으로 제한하여 페이지/타일 단위로 조회한다. 지도 응답은 수 MB 규모가 될 수 있으므로 지역 요약과 상세를 분리 로딩하고 측정 결과에 따라 요약 응답을 추가한다. 연도·지역·필터별 캐시를 구분하며 원문·이력은 선택 시 조회한다.

조회 상태는 정책·프로그램·지역·자료 연도·수집 조회일·공급 기준·선택 사업·카메라로 관리한다. 요청 취소/응답 순서를 처리하여 오래된 결과가 최신 선택을 덮지 않게 한다. 뒤로 가기로 선택과 카메라를 복원한다.

## 9. 통계 범위·신뢰도·과거 자료

- 기본 집계는 **선택 지역 전체**다. 지도 이동만으로 합계가 바뀌지 않는다. 별도 `현재 지도 범위` 모드에서만 해당 사업을 집계하고 모드명을 계속 표시한다.
- 지도에 걸친 면적 비율로 공급량을 나누지 않는다. 포함 규칙을 명시하고 공간 귀속이 확인된 사업 집합을 계산한다.
- 기존 전역 중복 제외 결정을 유지한다. 정책별 값이 겹치면 전체를 단순 합산하지 않는다. 위치 미연계·수량 미확보·중복 제외의 사유와 영향을 확인할 수 있게 한다.
- `REVIEW`는 사용자 원칙대로 검토 통계에 반영하고 담당자 확정과 구분한다. `RELEASED` 제외 규칙을 유지한다. 승인이 공식 공급 실적의 진위까지 보장하는 것은 아니다.
- 임의의 신뢰도 종합 점수를 만들지 않는다. **원문 확보 / 보고 시점 / 정책 연결 / 공간 연결 / 실적 확인 / 누락 범위**를 각각 표시한다. 전체 모집단이 미확보면 전수 확보율을 만들지 않는다.
- 자료의 원천 기간과 수집 조회일을 분리한다. 당시 자료가 없으면 현재 공정률을 과거로 복사하지 않는다. 현재 정책 귀속을 발표 이전의 공식 실적으로 소급하지 않는다.
- 미래 슬라이더는 `예정 보기`이며 관측 실적 연도와 구분한다. 기존 누적 산식을 유지하고 관리자 목표를 원천 예정량에 합산하지 않는다.
- 지연 확인은 대응 계획·실제 이행·발표 이력이 함께 있어야 한다. 예정 경과·실적 미확인은 `이행 확인 필요`, 불완전한 비교는 `지연 후보`다. 계획 공정률 미확보이면 실제 공정률만으로 공정 지연을 판정하지 않는다.

## 10. 인터랙션·접근성

1. 정책/프로그램 선택 시 지역 집계와 좌측 요약을 함께 갱신한다.
2. 시도·시군구 원 클릭 시 해당 지역 선택·하위 단계 이동. 상단 경로로 상위 지역 복귀.
3. 블록 목록 선택 시 지도 강조·카메라·상세 연동. 정확한 좌표가 없으면 지구 위치와 미연계 상태 표시.
4. 건물 선택 시 해당 동 강조·작은 팝업. 닫아도 블록 선택과 정책 필터 유지.
5. 지도 위 휠은 포인터 중심 확대·축소, 패널 위 휠은 목록 스크롤. 기존 휠 동작 회귀 검증.
6. `전체 보기 / 위에서 보기 / 비스듬히 / 북쪽 위로`는 같은 선택 범위의 카메라만 변경. 실제 카메라 기능은 WebGL 단계에서 제공하고 SVG 화면에서는 미지원 조작을 활성화하지 않음.
7. 하단에 자료 연도 이동과 +1/+2/+3년 예정을 압축. 자료 없는 연도의 실적을 재생 중 추정 보간하지 않음.
8. WebGL 미지원/오류 시 동일 필터의 2D 지도·목록 제공. 타일 실패 시 목록·근거·조회 값 유지.
9. 키보드로 목록·단계·건물 상세 선택과 초점 복원. 경고는 문구/기호 병기, 지도 정보도 목록으로 접근 가능.

## 11. 실행 단계와 완료 조건

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1. 표시 계약·데이터 점검 | 응답/집계/연결 계약, 실제 블록·건물 데이터 적합성, 실데이터 와이어프레임 | 결측 처리·동일 범위 산식·3D 자료/엔진 선택 근거 정리 |
| 2. 지도 중심 레이아웃 | 기존 메뉴 압축, 좌측 패널, 지도 전체 높이, 우측 상세/연도 조작 이동, 모바일 시트 | 기존 조회·목표·승인 유지, 지도 중심 구성, 가로 넘침 없음 |
| 3. 지역 현황·드릴다운 | 시도/시군구/지구 집계, 원그래프·누적 전망, 경로·선택 연동, 미연계 목록 | 지도·패널·CSV 범위 일치, 결측과 0 구분, 미래 중복 없음 |
| 4. 블록·건물 3D | 선택 범위 건물 조회·WebGL, 회색 배경/선택 강조, 팝업, 얇은 블록 막대 | 실제 형상·높이·식별자 근거 검증, 임의 건물 없음, 2D 대체 동작 |
| 5. 통합 검증·적용 | 공개 조회·과거 자료·관리자 회귀, 성능·키·출처 점검, 기능 전환·복구 | 핵심 흐름 통과, 근거 없는 집계 없음, 이전 UI 복구 가능 |

건물 원천에 제약이 있어도 2·3단계 개편은 진행한다. 실제 건물은 확보 범위부터 적용하고 미확보 지역은 2D/용지 보기와 목록을 제공한다. 실제 근거가 있는 블록으로 레퍼런스의 카메라·선택 상호작용을 검증한다.

주요 수정 대상은 `web/index.html`, `web/assets/app.js`, `map.js`, `map-monitor.js`, `map-bars.js`, `block-monitor.js`, 지도 CSS와 `apartment-shapes.js`다. 선택 상태·패널·렌더러 어댑터를 분리한다. 백엔드는 `supply_dashboard.py`·`supply_geography.py`·`supply_export.py`와 필요 건물 조회/정규화만 확장한다. 정책별 진행현황·연결·과거 자료 화면은 유지하고 지도에서 바로 이동한다.

기능 전환 설정으로 운영 적용 전 기존/새 UI를 같은 데이터로 비교한다. **이번 문서 작성 단계에서는 런타임 수정·재수집·배포를 하지 않는다.**

## 13. 2D/3D 전환과 개별 블록 표시 검토 — 2026-10-03

### 13.1 선택안: 같은 지도에서 2D → 필요 범위의 3D

| 방식 | 부하와 사용성 | 판단 |
| --- | --- | --- |
| 모든 수준에서 건물 3D 표시 | 넓은 영역의 형상·모델까지 로딩하면 요청·메모리·그리기 부담 증가. 기울어진 지도는 지역별 원그래프 비교도 어려움 | 기본안으로 채택하지 않음 |
| Leaflet 2D → 별도 3D 엔진으로 전면 교체 | 초기 2D는 가볍지만 최초 3D 진입 시 SDK/스타일/카메라 재생성 필요. 왕복 전환·상태 복원 비용이 생김 | 저사양 대체 경로로 검토 |
| 하나의 WebGL 지도, 넓게는 2D·가까이서는 3D | 선택·카메라·배경을 유지하고 상세 데이터만 필요할 때 조회. 초기 WebGL 엔진 비용은 존재 | 권장 |

이 비교는 현재 데이터와 엔진 구조에 따른 설계 판단이다. 아직 실제 건물 3D 구현이 없으므로 두 완성 화면의 GPU/프레임 성능을 실측 비교한 결과는 아니다. 상시 3D도 적절한 상세도 제어를 하면 가벼울 수 있다. **부하를 결정하는 핵심은 화면 기울기보다 실제로 요청·보관·그리는 데이터 양**이다.

MapLibre 공식 성능 문서는 필요한 데이터만 나눠 로딩하는 방식, 벡터 타일, 단순화, 표시 확대 수준 제한을 안내한다. 이를 본 화면의 설계 근거로 사용한다. [공식 대용량 데이터 성능 안내](https://maplibre.org/maplibre-gl-js/docs/guides/large-data/).

### 13.2 현재 부하의 확인 결과

운영 API를 변경 없이 1회 읽어 확인했다. 아래 값은 `measure=SUPPLY`, 자료 연도 2026, 기준일 2026-10-03의 필터 없는 응답이다. 압축 없는 로컬 읽기 기준이며 공개망 속도·브라우저 그리기 시간의 측정값은 아니다.

| 항목 | 확인 값 |
| --- | ---: |
| `/api/map/dashboard` 응답 | 9,986,204 bytes, 약 9.52 MiB |
| 응답 읽기 시간 | 약 1.53초, 단일 관측 |
| 응답 내 시군구 부분 | 약 3.21 MB |
| 정책/프로그램/지역 집계 부분 | 약 2.76 MB |
| 블록 부분 | 약 2.54 MB |
| 지구 부분 | 약 0.96 MB |

상세·분류별 계산 결과가 여러 영역에 포함되어 있어 현재 응답 자체의 경량화가 선행 과제다. 2D 화면에서도 이 전체 응답과 모든 건물을 함께 내려받으면 기대한 부하 절감이 생기지 않는다.

구현 시에는 기존 상세 API를 유지하고 **요약 응답/선택 조회를 하위 호환 방식으로 추가**한다. 초기에는 선택 정책의 시도·시군구 요약만, 지구 진입 시 해당 블록 목록만, 블록 진입 시 화면 범위의 형상·확보된 높이만 받는다. 근거 문서·보고 이력은 상세 선택 시 받는다. 요약에서도 집계 산식은 기존 서버 로직을 공유한다.

### 13.3 전환과 자원 관리

- 시도·시군구에서는 기울기 0도, 건물/지형 상세 레이어 비활성화. **원본 건물 데이터도 선제 다운로드하지 않는다.**
- 지구 단계에서는 정확한 위치가 확보된 블록의 개별 표식과 경계를 표시한다. 3D 형상 조회는 블록 확대 진입 또는 명시적 선택 후 시작한다.
- 확대 16 진입을 3D 전환 초안으로 삼고, 축소 15 이하에서 2D로 복귀한다. 여유 구간에서는 현재 모드를 유지하여 휠 조작 시 반복 전환·재조회가 생기지 않게 한다.
- 데이터 준비 후 카메라를 서서히 기울인다. 확대 중 형상이 아직 미확보이면 2D 경계/표식을 유지하고 패널은 즉시 블록 정보로 전환한다.
- `bbox`와 선택 지구를 기준으로 필요한 형상만 요청한다. 기울어진 카메라의 실제 화면 영역을 고려하되 서울·경기 전체를 한 번에 가져오지 않는다.
- 빠른 이동·확대에서는 요청 취소와 짧은 지연 처리를 적용한다. 형상 캐시는 크기/영역 수를 제한하고 오래된 영역은 정리한다. 단순 레이어 숨김만으로 메모리가 해제되었다고 간주하지 않는다.
- 상세도가 필요한 선택 블록을 우선 처리한다. 주변 건물은 단순한 회색 외곽선/낮은 상세도로 제한하고 배경 미연계 건물에 정책 정보를 붙이지 않는다.
- 그림자·텍스처·높은 해상도·3D 지형은 기본 최소화하고 실제 효과와 비용을 측정한 뒤 적용한다. 모바일에서는 기본 2D를 제공하고 사용자가 3D를 선택할 수 있게 한다.
- 화면이 다른 메뉴로 전환되거나 숨겨지면 불필요한 갱신·재생을 중지한다. WebGL 실패 시 기존 2D 조회로 돌아간다.

### 13.4 A4·S1 등이 같은 위치에서 보이는 이유

현재 코드·응답·보관 원본을 확인한 결과다.

1. `supply_dashboard.py`는 지역·지구·블록 코드로 데이터 그룹을 나누지만, 위치는 해당 **지구의 대표점**을 모든 블록에 복사한다.
2. 위 운영 응답의 블록 98개 중 75개는 `DISTRICT_REPRESENTATIVE`, 23개는 `UNLOCATED`다. 정확한 블록 좌표로 표시되는 그룹은 이 응답에 없다.
3. `map-monitor.js`는 같은 지구 대표점에서 블록 막대를 화면상으로 펼치고 연결선을 그린다. 확대하거나 그래프 간격을 벌려도 실제 블록 위치가 생기지 않는다.
4. 보관한 VWorld `LT_C_LHBLPN` 응답 95개를 검사했다. 공동주택 feature의 속성은 `zonename`과 `blocktype`뿐이다. 개별 feature ID·도형은 있지만 그 feature가 A4인지 S1인지 알려주는 속성이 없다.
5. 수집기는 여러 feature를 지구별 MultiPolygon으로 묶는다. 원본의 개별 도형은 남아 있으므로 다시 분리할 수 있지만, **분리 도형에 A4·S1을 배정할 근거는 추가 확보가 필요**하다.
6. 보관된 LH 공사진행현황 상세도 검사했으나 현재 상세 정보에는 세대수·계약기간·공정률 등이 있고 좌표 필드는 확인되지 않았다. 공정률 수집만으로 위치 문제는 해결되지 않는다.

원본 파일 수는 저장 이력을 포함한 검사 범위이며, 사업 수나 현재 도형의 전수 확보율을 의미하지 않는다.

### 13.5 개별 위치를 확보하는 우선순위

| 순서 | 방법 | 확보 가능한 표시 | 확인할 조건 |
| --- | --- | --- | --- |
| 1 | LH 내집어디/비즈맵의 공개 블록·단지 위치와 기존 LH 지구/블록 코드 교차 확인 | 블록별 실제 위치 표식, 제공되면 개별 경계 | 공개 데이터의 접근·재사용 조건, 좌표계·식별자·제공 범위 검증 |

[LH 내집어디/비즈맵](https://bizmap.lh.or.kr/lhmap.do) 공개 화면에는 블록 검색·가구획지·토지이용계획도와 주택분양의 지구명/블록명/위치 항목이 있다. **해당 항목의 존재는 확인했지만 모든 대상 블록의 좌표·경계를 추출할 수 있는 공개 API까지 검증한 것은 아니다.** 다음 구현의 첫 점검 대상으로 삼고, 가져온 위치는 공식 공고와 교차 확인한다. SH·GH도 각 기관의 공식 자료를 사용하며 LH 화면이 두 기관 전체 사업을 포괄한다고 가정하지 않는다.

벡터 경계가 없고 이미지/PDF 도면만 있으면 확인 가능한 기준점으로 지도에 정합한 뒤 블록을 판독한다. 좌표계·정합 오차·근거 버전을 기록하고 담당자 검토를 받는다. OCR은 블록명 후보 추출에만 사용하며, 인접한 도형에 이름을 자동 확정하지 않는다. 정확도가 부족하면 공식 주소의 대표점만 표시하거나 위치 미연계로 남긴다.

### 13.6 데이터 연결과 화면 적용

공간 연결은 기존 사업 정보를 덮지 않는 추가 revision/관계로 저장한다. 다음 정보가 필요하다.

- 사업 ID, 원천 지구 ID/블록 ID, 표시 블록명과 정규화 코드, 원천 공간 feature ID.
- geometry 또는 공식 주소 대표점, 좌표계, `BLOCK_BOUNDARY / OFFICIAL_ADDRESS_POINT / DISTRICT_REPRESENTATIVE / UNLOCATED` 등 위치 근거.
- 공간정보 유효/자료 시점, 원문 URL·보관 hash, 연결 방법·공간 정밀도, 담당자 검토 상태와 변경 이력.

블록 키는 **지역 + 지구 식별자 + 블록 코드**로 구분한다. 서로 다른 지구의 A4를 묶지 않는다. `A4-1`과 `A4-2`처럼 분리된 블록도 별도 식별하고, 공식 근거가 있는 경우에만 `A-04` 등의 별칭을 정규화한다. 현재 키 해석은 단순 문자+숫자 코드 중심이므로 분리 블록 표기를 보완하되 기존 ID·중복 제외 결정을 임의 변경하지 않는다.

한 블록에 여러 공급 회차·단지·원천 행이 있으면 공간은 블록 경계로 공유하되 하위 사업/회차를 보존한다. 형상 개수나 공고 개수를 새 공급량으로 세지 않는다. 자동 매칭 후보는 근거와 검토 상태를 표시하고, 담당자 승인·해제는 기존 업무 원칙에 따른다. 경계/명칭이 모호하면 미연계로 유지한다.

**화면 적용 순서:**

1. 공식 위치가 확보된 블록부터 `A4`, `S1`처럼 실제 위치에 각각 표식·얇은 막대를 표시한다. 블록 경계가 있으면 `ST_PointOnSurface` 등의 내부 대표점에 고정하고 경계도 함께 강조한다.
2. 주소 대표점만 확보되면 위치 근거를 명시하여 개별 표식은 제공하되 블록 전체 경계나 건물 3D를 만들지 않는다.
3. 실제 위치는 고정하고 겹치는 라벨만 배치 조정한다. 선택 블록을 우선 표시하고 주변 블록은 짧은 이름으로 줄인다. 지도 축소 시 지역 집계로 돌아간다.
4. 지구 대표점만 남은 블록은 해당 지구의 `블록 위치 미연계` 목록에서 개별 선택한다. 필요한 경우 지구를 클릭해 별도 블록 비교를 열되 `공간 위치 미연계`임을 표시하고 지도상 실제 위치로 오인할 분산 배치를 하지 않는다.
5. 블록별 좌표/경계가 확보된 후 건물 외곽선·높이를 연결하여 3D를 적용한다. **개별 블록 표시를 실제 건물 높이 확보 완료까지 기다릴 필요는 없다.**

개별 블록 라벨 위치 연결과 2D↔블록 단계 전환은 1차 구현했다. 전체 대시보드 응답의 분리와 검증된 건물 외곽선·높이를 이용한 실제 3D는 후속 단계다.


## 14. 1차 구현·검증 (2026-10-03)

- 공급현황을 **좌측 340px 패널 + 지도**로 배치하고 모바일은 접는 하단 패널로 바꿨다. 정책 탭·시도 비교·블록 목록·사업 상세를 좌측 패널에서 조회한다.
- 확대 7~9는 시도 요약, 10~12는 시군구 원그래프, 13~15는 지구, 16~18은 블록별 막대로 전환한다. 좁은 범위에서만 기존 용지도형 입체 참고를 그린다. 현재 SVG는 실제 건물 형상이나 층수/높이가 아니다.
- LH [공개 지도](https://bizmap.lh.or.kr/lhmap.do)의 블록 **라벨점**을 키 없이 수집한다. `flag=4`, 서울·경기 행만 사용하고 EPSG:5174를 PostGIS에서 WGS84로 변환한다. 지역+정규화 지구명+블록 코드가 완전히 일치하고 좌표가 하나로 결정될 때만 사업에 연결한다. 원문·해시를 기존 수집 manifest에 남긴다. 공개 페이지의 수량·공급연도는 HOME 집계에 반영하지 않는다.
- 수집 결과 서울·경기 고유 라벨 블록 273개 중 현재 HOME 사업 블록 **66/98개**가 개별 라벨점에 연결됐다. 나머지 24개는 지구 대표점만 있고 8개는 위치가 없다. 고양창릉 A4, S1, S2의 좌표는 서로 다르다. 라벨점은 블록 경계·단지 경계·건물 위치가 아니며 개별 블록 승인 매칭을 뜻하지 않는다.
- 블록 라벨점과 현재 저장한 VWorld 공동주택용지의 단순화 도형을 공간 비교한 결과, 66개 중 50개 점은 단일 용지 도형 안에 있었지만 그중 부천대장 A1/A2 두 점은 같은 도형을 공유했다. 1개는 도형 바깥, 15개는 해당 지구 도형 자체가 없다. **점이 도형 안에 있다는 사실만으로 블록 경계라고 확정할 수 없으므로** 경계 자동 승격은 하지 않았다. 블록·용지 고유 ID나 공식 배치도로 추가 확인해야 한다.
- 지도 이동/확대 시 통계 패널의 전체 재계산·DOM 렌더를 피하고 지도와 블록 목록만 갱신한다. 초기 상세 응답은 현재 약 9.99MB로 여전히 크지만 1MB 이상 응답에 gzip을 적용해 이번 검증에서는 전송량 **약 0.91MB(90.9% 감소)**였다. 요약/선택형 API 분리는 미구현이다.
- HOME 백엔드 165개 테스트, Chromium의 데스크톱·모바일 2D→블록 전환·개별 블록·좌측 패널 점검이 통과했다. 실제 건물 3D, 블록 경계, 건물별 세대수·높이·층수, 미연계 32개 블록의 개별 위치는 확보되지 않았다.


## 15. 접이식 우측 패널·실제 주변 건물 3D (2026-10-04)

- 지도 상세 패널을 오른쪽에 두고 데스크톱에서 340px ↔ 48px로 언제든 접고 펼 수 있게 했다. 선택은 브라우저에 저장하며 지도 폭을 다시 계산한다. 모바일은 기존 하단 패널을 접고 펼친다.
- 시도·시군구는 Leaflet 2D를 유지한다. 개별 LH 라벨점이 연결된 블록을 확대 16 이상에서 선택하면 MapLibre GL JS 6.11.2를 **그때만 로드**해 3D로 전환한다. 축소하거나 `2D로 돌아가기`를 선택하면 WebGL 지도와 GPU 자원을 해제한다. 해당 블록의 검증된 건물 높이가 없거나 WebGL이 실패하면 2D를 유지한다. 다른 메뉴로 이동해도 3D 렌더러를 해제하고, 지도에 돌아오면 2D 상태에서 다시 선택할 수 있다.
- 기존 `POC10_VWORLD_API_KEY`로 국토교통부 [GIS건물통합정보](https://www.data.go.kr/data/15123970/openapi.do)의 `LT_C_BLDGINFO` 폴리곤·`height`를 블록 라벨점 주변 반경 180m에서 조회한다. 양수의 유효한 공식 높이만 미터 단위로 세우며 높이 0·미기재를 층수로 추정하지 않는다. 건물별 동명·층수·높이와 원천 링크를 제공한다. 브라우저에는 키를 전달하지 않으며 수집 원문 SHA-256을 패널에 표시한다. 6시간 캐시, 최대 1,000개 도형 제한을 둔다.
- 3D 건물은 **선택 블록 주변에 현재 존재하는 건물**이다. 공급사업의 계획 동, 해당 블록의 실제 건물 또는 공급 완료 세대로 자동 간주하지 않는다. 공급 수치·정책 통계는 기존 집계를 유지하고 지도 블록 막대에 목표·현재 확인량·+1/+2/+3년 예상만 별도로 얹는다. 현재 공식 블록 경계·건물 ID 관계가 없으므로 블록–건물 확정 연결과 장래 계획 건물의 3D는 남은 과제다.
- 실조회 예시: 고양장항 S2 인근 공식 건물 200개 중 실측 높이 125개를 3D로 표시했다(2026-10-04 수집). API는 `/poc/home/api/map/buildings?block_id=...`이며 개별 LH 위치가 없는 ID는 거부한다. 이는 건축 공급 실적 125개를 뜻하지 않는다.
- HOME 백엔드 168개 테스트와 데스크톱·모바일 지도 전환, 2D·3D 휠 확대/축소, 우측 패널 독립 스크롤, CSP 위반 없는 3D 렌더링 검증을 통과했다. MapLibre 정적 자산과 BSD-3-Clause 라이선스를 HOME에 고정했다. 기존 스타일 CSP 제한은 유지하고 동출처 Web Worker만 명시했다.

## 16. 개별 블록 위치 후속 대조 (2026-10-04)

- HOME 사업 블록 98개 중 66개는 LH 공개 지도에서 `시도 + 정규화한 지구명 + 블록 코드`가 모두 일치하는 개별 라벨점이다. 24개는 지구 대표점만 있고 8개는 지구 위치도 미확보다. 개별 라벨점도 블록 경계·건물 연결 근거는 아니다.
- 나머지 32개와 LH 공개 지도 서울·경기 라벨을 다시 대조했다. 지구는 있으나 해당 블록 코드가 없는 사례로 고양장항 S1, 고양창릉 S6, 하남교산 A2 등이 있다. 다른 지구에 동일한 `S1`·`A2`가 있다는 이유만으로 연결하지 않는다. 지구 자체가 공개 라벨 범위에 없는 블록도 있다.
- 다음 확보 순서는 공식 단지 주소/지번과 모집공고를 블록 코드까지 교차 확인하고, 공식 토지이용계획도나 사업 경계의 좌표를 맞춰 검증하는 것이다. 공식 자료로 확인되기 전까지는 24개를 지구 목록의 `블록 위치 미연계`, 8개를 `위치 미연계`로 유지한다. 3D를 주변 건물의 존재만으로 확장하지 않는다.
- 대시보드 본문은 아직 전체 집계 응답을 불러온다. 별도의 시도·시군구 요약 응답과 선택 지구 상세 조회로 나누는 성능 작업은 남아 있다. 실제 건물 3D는 선택 블록에서만 별도 요청하며 넓은 지도에서 건물 형상은 내려받지 않는다.

## 17. 참고 화면형 3D 인터페이스·주 메뉴 정정 (2026-10-04)

- 왼쪽 **HOME 메인 메뉴**에 별도 접기 버튼을 추가했다. 데스크톱에서는 236px 메뉴가 68px 아이콘 레일로 접히며 메인 화면 폭이 늘어난다. 모바일에서는 상단 메뉴 목록을 접는다. 선택은 브라우저에 저장한다. 지도 우측 상세 패널의 접기 버튼과는 독립적이다.
- 3D 진입 시 통합지도가 화면 전체를 차지하는 전용 보기로 전환된다. 상단 도구와 위치가 연결된 블록 선택, 오른쪽 공급 요약·블록 정보, 하단 연도 축을 유지한다. `전체 보기 / 위에서 / 비스듬히 / 북쪽 위로` 카메라 시점과 지도 안의 2D 복귀 버튼을 제공한다. 지도 위에는 회색 주변 기존 건물과 파란 선택 블록 공급 표식의 의미를 명시한다.
- 기존 첫 화면은 지도 위 필터·표 때문에 노트북 화면에서 3D가 아래에 가려졌다. 3D 버튼과 블록 진입을 누르면 지도에 초점을 이동하고, 3D에서는 전체 화면 레이아웃으로 전환한다. 지도 우측 패널은 3D 중에도 접고 펼 수 있다.
- 실제 3D 도형은 여전히 공식 **기존 건물 외곽선·높이**만 사용한다. LH 블록 라벨점만으로 장래 아파트 동의 배치·층수·블록 경계를 생성하지 않는다. 이를 참고 이미지처럼 확정 단지 모델로 표시하려면 블록 경계와 계획 동 배치의 공식 좌표·높이·식별자 연결이 추가로 필요하다.
- 공개 HOME에서 데스크톱 1600×1000, 노트북 1100×720, 모바일 390×844 크기의 3D 화면·메뉴·패널·2D 복귀를 확인했다. 건물 높이가 없는 경우 전체 화면을 닫고 2D를 유지한다.

## 18. 상시 3D 공급현황과 개념 아파트 모델 (2026-10-04)

이 절은 위 2D↔3D 전환 및 `3D는 공식 기존 건물만`이라는 이전 설계를 대체한다. 사용자 요청에 따라 공급현황은 첫 진입부터 MapLibre 3D 지도 하나를 연다. 확대·축소 시 같은 WebGL 캔버스를 유지하고 시도·시군구 집계 표식과 개별 블록 표식만 배율에 맞게 바꾼다. 3D↔2D 전환 버튼은 숨긴다. 왼쪽 340px 공급 패널, 남은 화면 전체의 지도, 하단 연도 축을 한 화면에 둔다. HOME 주 메뉴와 공급 패널은 서로 독립적으로 접고 펼친다. 메인 화면 `max-width`를 제거해 2560px 화면에서도 지도 캔버스가 오른쪽 끝까지 확장된다.

공급사업의 공식 계획 동 배치나 높이 데이터가 없어, **위치가 개별 확인된 LH 블록 라벨점**을 중심으로 단순 아파트 동 모델을 결정적으로 생성한다. 파란색은 가상 동, 빨간색은 선택 블록 가상 동이다. 동수·높이·방향·정확한 필지 경계는 시각화용 임의 값이며 공식 계획이나 실제 공정률이 아니다. 실제 공급량·목표량·달성률은 기존 API 집계 그대로 표시하고, 가상 동 개수를 세대수나 사업 수에 합산하지 않는다. 위치 미연계 블록은 가상 동을 만들지 않고 목록과 `위치 미연계` 문구로 표시한다. 회색 건물은 선택 블록 주변 VWorld 기존 건물의 공식 높이가 확인된 형상이며 해당 공급사업에 자동 연결하지 않는다. 건물 API가 실패해도 가상 공급 모델과 지도는 유지한다.

첫 지도 중심은 위치가 확인된 블록이 가장 많은 **실제 대시보드 지구**에서 고른다. 지구와 사업 ID가 다른 행을 잘못 조합해 고양장항 S2로 이동하던 초기 선택 오류를 수정했다. 처음 배율은 선택 블록의 3D 형상을 읽을 수 있는 16.1이다. 다른 지구는 블록 선택기·정책 탭·지도 표식으로 이동한다. 휠로 서울·경기 수준까지 축소한 뒤 블록 수준으로 다시 확대해도 캔버스를 재생성하지 않는다.

검증: HOME 백엔드 168개 테스트, Chromium 1600×1000·2560×1000·390×844 첫 진입, 메뉴·패널 접기, 정책·블록·연도 선택, 휠 축소/확대 후 동일 캔버스 유지, 기존 건물 API 503 시 가상 모델 유지가 통과했다. 2560px 화면에서 지도 영역은 **2,152px**이며 오른쪽 끝까지 닿는다. 현 자료의 개별 블록 라벨점은 **66/98개**, 가상 형상은 공급량과 무관한 표시 객체 **225개**다. 블록의 공식 경계·미연계 32개 위치·계획 동의 실제 배치/높이는 여전히 미확보다.

## 19. 주변 건물 범위와 1,000호 기준 막대 (2026-10-04)

- 주변 기존 건물 조회를 선택 블록 반경 180m에서 **최대 1km**로 넓혔다. VWorld GIS건물통합정보를 1,000개씩 페이지 조회하고 건물 ID의 중복·누락을 검사한다. 1km 안에 5,000개가 넘는 곳은 750m→500m→300m 순으로 범위를 줄여 응답과 그리기 부담을 제한한다. 6시간 서버 캐시는 최근 8개 블록, 브라우저 캐시는 최근 3개 블록으로 제한하고 원문 해시 보관은 유지한다.
- 공식 외곽선의 양수 높이를 우선 3D로 그린다. 높이가 없고 공식 지상층수가 있으면 **층수×3m 추정 높이**, 둘 다 없으면 **7.5m의 낮은 참고 형상**으로 그린다. 세 경우를 회색 계열로 구분하고 패널에 각각의 수량을 표시한다. 이는 선택 공급 블록의 실제 건물·층수·공정률을 뜻하지 않는다.
- 검증 예시: 고양창릉 A4 반경 1km에서 기존 건물 외곽선 3,640개, 공식 높이 459개, 층수 추정 824개, 높이 미확보 참고 형상 2,357개를 확인했다. 이 수량은 해당 시점의 VWorld 응답이며 공급량 집계에 포함하지 않는다.
- 가상 공급 동은 주변 건물과 비슷한 길쭉한 아파트 형태와 차분한 청회색·적갈색으로 표현한다. 형상 수·방향·배치·높이는 공식 계획이 아니다. 블록별 지도 진척 막대는 **1,000호 = 65px**를 기준으로 목표 공급량에 비례해 높이가 달라진다. 확인량·목표·1~3년 예정량은 이 동일 축에서 쌓인다. 시군구 원그래프 지름은 이전 대비 1.5배다.

## 20. 지하철·학교·병원 주변 인프라 (2026-10-04)

- 기존 `POC10_VWORLD_API_KEY`로 [VWorld 검색 API 2.0](https://www.vworld.kr/dev/v4dv_search2_s001.do)의 국가관심지점 장소를 선택 블록 라벨점 반경 **3.5km**에서 조회한다. 지하철역, 초·중·고교, 병원을 분류와 명칭으로 교차 필터링한다. 같은 이름의 150m 이내 중복 POI를 합치고, 시설 ID·주소·좌표와 원문 해시를 보관한다. 추가 API 키는 필요 없다.
- 3D 지도에 시설 종류별 표식을 표시하고 오른쪽 위 카드에 가장 가까운 지하철·학교·병원의 이름과 **블록 라벨점 기준 직선거리**를 표시한다. 카드를 누르면 해당 좌표로 이동하고 공식 분류·주소를 보여준다. 직선거리는 도보·차량 이동시간이나 개통·운영 여부를 뜻하지 않는다. 시설과 공급 블록의 정책 연결을 자동 확정하지 않는다.
- 고양창릉 A4 실조회에서 지하철역 5곳, 학교 25곳, 병원 8곳을 표시했다. 학교 표식은 화면 혼잡을 막기 위해 가까운 25곳까지만 표시하므로 이 수는 반경 내 전수라고 간주하지 않는다. 공개 3D 지도에서 주변 건물과 시설 표식 동시 표시, 시설 카드 클릭 후 카메라 이동·상세 주소, WebGL 캔버스 유지를 확인했다.
