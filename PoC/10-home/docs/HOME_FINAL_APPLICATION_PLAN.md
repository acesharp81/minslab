# HOME 최종 적용 플랜 — 원천 검증부터 정책·사업 집계까지

2026-10-10 현재 1단계 원천·커버리지와 2단계 정체성/계획 원장의 **최소 파일럿**을 운영에 적용했다. 집계 단위·정책 기준선·지도 전환 등 후속 단계는 미완료다. 최신 사실·수량은 [`HOME_IMPLEMENTATION_STATUS_20261010.md`](HOME_IMPLEMENTATION_STATUS_20261010.md), 담당자 행동은 [`HOME_OPERATIONS_NEXT_STEPS_20261010.md`](HOME_OPERATIONS_NEXT_STEPS_20261010.md)를 우선한다.

기준: 2026-10-10. 대상: 서울·경기 HOME PoC 10. 입력 자료는 `refs/HOME_CODEX_실행지시서.md`, `refs/HOME_source_verification.json`, `refs/HOME_데이터확보_검증보고서.md`, `refs/HOME_시스템아키텍처_설명.html` 네 파일과 현재 `backend/`, `db/migrations/`, `docs/PLAN.md`, `docs/HOME_GPT_REVIEW_BRIEF.md`, 2026-10-07 JSON 공유 스냅샷이다. 이 문서는 **적용할 설계와 순서**를 확정하는 문서이지, 신규 데이터 수집·DB 이관이 완료됐다는 기록이 아니다.

## 결론

네 파일의 큰 방향은 적합하다. 현재 HOME의 **원천 판본·배치·담당자 검토**를 유지하면서, `실제 사업의 안정 ID`, `법적 계획/고시 사건`, `정책 집계 기준선`, `중복 없는 공급묶음`, `별도 지역 공식통계`를 추가해야 한다. 다만 55개 조사 항목을 일괄 수집 목록으로 전환하거나 목표 ERD의 모든 테이블을 한 번에 만드는 방식은 채택하지 않는다. **작은 서울·경기 검증 사례에서 원천→실사업→공급묶음→지표→지도까지 한 줄로 재현**한 뒤 확대한다.

화면의 최상위 숫자는 세 층으로 구분한다.

1. **공식 정책 목표·공식 확인 실적:** 같은 단계, 기간, 지역 범위, 주택 유형이 입증될 때만 달성률 계산.
2. **관리 대상 사업의 계획·예정·확인 실적:** HOME이 동일 사업과 물량을 식별한 범위. `CONFIRMED` 연결과 `REVIEW` 후보를 나눠 표시.
3. **지역 전체 공식 통계와 인구·가구 맥락:** 개별 사업 원장과 별도 사실 계층. 정책 성과 분자에 자동 배분하지 않음.

## 2026-10-07 스냅샷에서 확인한 적용 전 기준선

- 물리 DB 모델은 `home_revision`, `home_batch`, `home_mapping`, `home_program_mapping`, `home_audit` 다섯 테이블이다. `home_policy`, `home_plan`, 안정 `home_project`, `home_supply_cohort`, `home_region_stat`는 현재 없다. `backend/sources.py`에 등록된 source ID 36개와 검증 JSON의 기존 source ID 36개는 정확히 일치한다.
- 현재 `home_mapping.project_id`는 원천별 사업 후보 `home_revision.entity_id`다. 이를 새 `HPR_*` ID로 직접 덮어쓰면 기존 관리자 검토·목표·감사가 깨진다. `home_program_mapping.id`도 최초 `seed_policy_id`의 영향을 받으므로 안정 프로그램 ID가 아니다.
- `entity_id`의 접두부는 `kind` 앞 세 글자지만 해시는 `source_id:원천키`를 사용한다. 서로 다른 `kind`가 동일 source/원천키를 쓸 때 설계상 충돌할 수 있다. **2026-10-07 공유 스냅샷 892,343개 판본을 읽기 전용으로 검사한 결과, 서로 다른 `kind` 사이 동일 `entity_id`는 0건**이었다. 이것은 앞으로 충돌이 불가능하다는 증명은 아니다. 새 식별 규칙은 전체 `kind`를 이름공간에 넣되, 과거 ID는 재발급하지 않는다.
- 공유본의 `source_registry.url`은 공식 진입점이고 실제 요청 URL·원본 해시·파서 버전은 `home_batch.manifest`에 있다. 수집 성공 판본 수가 공급 실적·전수 완결성을 뜻하지 않는다.
- 현재 `docs/PLAN.md`는 `SCOPE_BASELINE`, `SUPPLY_COHORT`, `PROJECT_SCHEDULE`, `PROJECT_SUPPLY_ACTUAL`, `FIELD_RESOLUTION_RULE` 등을 상세히 정의하지만 대부분 **목표 설계**다. 이 플랜은 PLAN의 개념을 유지하되 적용 순서와 집계 충돌을 정리한다.

정책별 공식 달성률은 `같은 범위·기간·지표·공급유형의 확인 실적 / 공식 목표`가 모두 입증될 때만 숫자를 돌려준다. 착공 목표에 준공·입주 실적을 넣지 않는다. **9·7 수도권 목표는 인천을 포함**할 수 있으므로 서울·경기 확인 물량만으로 공식 달성률을 만들지 않는다. 숫자를 못 낼 때는 `rate=null`과 `NON_COMPARABLE`, `SCOPE_UNKNOWN`, `NO_ACTUAL_EVIDENCE` 등 사유를 반환한다. `REVIEW` 연결은 사용자의 요구대로 탐색 통계에 포함할 수 있으나 **공식 성과와 명확히 분리**한다. 공개 여부(`PUBLIC/INTERNAL/RESTRICTED`)는 연결 신뢰도(`REVIEW/CONFIRMED/RELEASED`)와 다른 속성이다. 공개 가능한 원천에 근거한 REVIEW 후보는 검토 상태를 붙여 공개 조회에 표시할 수 있다.

상위 지구 목표 33,000호와 하위 두 블록 12,000+8,000호는 53,000호로 더하지 않는다. 동일 지구·지표·범위라는 것이 확인되면 목표 33,000호와 확인된 하위 배정 20,000호, **계산상 미배정 13,000호**를 별도로 보여준다. 미배정치는 가상 블록이나 준공 실적이 아니다. 상하위 범위가 다르면 잔여 자체도 `NON_COMPARABLE`이다. 단계 간 인허가+착공+준공 호수도 횡단 합산하지 않는다.

**마이그레이션 원칙:** 기존 5개 테이블·ID·승인·감사·목표는 보존한다. `home_mapping.project_id`를 곧바로 `HPR_*`로 바꾸지 않는다. 과거→새 ID crosswalk와 충돌함을 먼저 만들고, 새 조회를 병행한 뒤 범위·지표별 결과가 설명 가능할 때 전환한다. 이미 승인된 연결/수기 목표를 재수집이 덮지 못하게 한다. 첫 마이그레이션은 **정체성과 근거의 최소 원장**으로 제한하고, 기준선·cohort·통계는 검증된 골든셋의 실제 필요 필드를 확인한 뒤 후속 마이그레이션한다. PLAN의 `PROJECT_SCHEDULE`와 새 `home_milestone`을 중복 사실표로 동시 구축하지 않는다.

## 1차 릴리스의 명확한 종료 조건

- 서울 정비형과 경기 공공택지형에서 **출처가 확인된 실제 사업**을 연결하고, 확인 못한 단계·기간·물량은 `미확보/미연계/일정 미정`으로 남긴다. 검증 사례 규모는 품질 게이트이지 정책 전체 모집단 완료 선언이 아니다.
- 지도·정책 화면에 `공식 목표`, `승인된 매핑사업 계획`, `REVIEW 포함 후보`, `단계별 확인 실적`, `지역 전체 공식통계`를 **별도 이름·색/범례·근거**로 표기한다. 3D 예상 건물은 시각 모형으로 식별한다.
- 정책 달성률의 분자·분모 범위가 맞지 않거나 목표의 서울·경기 배분이 없으면 `null + 사유`를 반환한다. 실제 0, 원천 미수집, 수집 실패, 미연계, 일정 미정도 구별한다.
- 공식 지역 통계와 개별 정책 사업의 합계는 같은 값이라는 전제를 두지 않으며, 비교 가능한 범위일 때만 차이/포괄률을 제시한다.
- 기존 관리자 승인/해제·수기 목표·감사·원천 판본/manifest·기존 API가 유지되고, 새 API의 숫자는 원본까지 역추적할 수 있다. 운영 전환 전 격리 DB 복원과 shadow comparison을 통과한다.

## 판단을 바꿀 수 있는 확인 사항

1. 건축HUB 부가 endpoint와 국토부 월별 통계표의 **실제 인증 응답, PK, 시군구 해상도**. 카탈로그 문구만으로 확정하지 않는다.
2. 전국 정비사업 통합 CSV의 원본 컬럼/중복/서울·경기 범위와 기존 서울 upis·경기 원천의 교차율. 전국 파일은 현재 현황 후보만 제공할 수 있다.
3. 서울 upis의 현재 이용허락과 원고시 연결의 법적 근거; 경기 공공택지 지정·변경·해제의 **전수 취득 경로**. 어느 쪽도 현 단계에서는 전수 확보로 주장하지 않는다.
4. 기존 관리자 데이터와 한 실사업에 모이는 여러 후보의 정책·프로그램·목표 충돌. 충돌 건수와 담당자 검토 부담을 본 뒤 병합 규칙을 조정한다.

이 네 사항은 단계 0~2에서 확인할 **검증 과제**이며, 현 단계에서 플랜 수립 자체를 막지는 않는다.
