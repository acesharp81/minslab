# 수집 항목의 주기·자동화·전처리 표시

2026-10-20 운영 반영. 출처와 수집현황은 원문 확보와 항목 추출·파싱 등 전처리까지 설명한다. 정책·프로그램·사업 연결과 담당자의 연결 확인은 이 화면의 수집 방식 메타데이터에 포함하지 않는다.

- 제목 아래에는 실행 방식, 실제 예약 간격, 신규 자료 탐색 범위, 실제 수집 실행의 자동·수동 여부를 표시한다. ‘수집·전처리 방식’을 누르면 상세 설명을 확인한다.
- 주기는 작업 큐의 FAST 주기·refresh_days·미조회 보충 backfill_seconds를 따른다. API 키 미설정, 자동 수집 중지, 수동 전용을 구분한다. 호출 제한·대기열에 따라 실제 실행 시각은 달라질 수 있다.
- LH 후속 공모는 매일 등록 문서 5건을 재확인한다. 전체 공모 게시판의 신규 문서 자동 탐색은 아니다. 등록된 자료의 재확인·파싱은 자동이다. 수집 대상 등록과 추출 규칙 작성은 수집 방식 태그나 팝업에 표시하지 않는다.
- 공개 CSV는 포털 상세 페이지의 다운로드 링크·파일명 기준일을 재조회한다. 같은 데이터셋의 교체 파일 감지와 새로운 데이터셋 발견은 구분한다.
- 토지이음은 최신·과거 목록을 이어 조회하고 고시 ID·첨부를 추적한다. HWPX는 XML 파서로 문단·표를 읽는다.

## PDF를 정형화하는 방법

1. 원본 PDF를 다운로드하고 보관한다.
2. **pypdf 문자 추출 도구**가 PDF에 저장된 텍스트를 읽는다. 일부 수집기는 layout 모드로 배치를 최대한 유지한다.
3. 자료별 규칙 파서가 추출된 문자열·표에서 항목명·지역·블록·호수·날짜 등을 분리하고 형식을 정리한다.
4. 수집기별 필수 항목·수량·표 구조를 검증하고 추출 결과를 저장한다.

**pypdf는 PDF에 저장된 텍스트를 추출한다.** 스캔 이미지뿐인 PDF는 현재 자동 문자 인식을 하지 못한다. 토지이음에서는 OCR_REQUIRED로 남기며 구형 HWP는 원문 보관 상태로 남긴다. 다른 수집기도 이미지 표나 변경된 형식은 별도 판독·파서 보완이 필요하다. 수동 보완 필요 상태를 보완 완료로 표시하지 않는다.

원문·레코드 해시와 개정 이력으로 변경·중복을 관리한다. 다운로드 성공과 전처리 성공은 구분한다. 자료의 사업 귀속 판단은 이 전처리 설명에 포함하지 않는다.

검증: 수집 주기·실행 상태·PDF 설명·사업 연결 검토와 수집 메타데이터의 독립성에 대한 테스트 5개 통과.
