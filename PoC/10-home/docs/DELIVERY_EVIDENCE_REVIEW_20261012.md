# 정책 단계 근거·목표 관리 개편 (2026-10-12)

## 목적과 사용자 흐름

공급현황 지도와 정책 지역 그래프에서 같은 범위의 누적 공급량을 확인하고, 정책–프로그램–사업 연결에 이어 **사업–단계 근거**와 **단계별 목표**를 담당자가 검토한다. 가능성이 높은 연결은 우선 `REVIEW`로 저장해 통계에 반영하고, 이후 확정·수정·해제한다.

진입: 데이터현황 → 정책–프로그램–사업 연결 → **③ 사업 단계·목표 근거**. 기본 정책은 9·7. 정책 전체·사업별 목표 입력 창에서 사업화, 인허가, 건설, 공급, 준공, 입주 목표를 추가한다. 원천 목표와 별도로 담당자 확정 목표, 자료 기반 임시 목표, 분석 시나리오를 저장한다. 미등록 목표는 0이 아니며 목표면을 그리지 않는다.

## 수치 불일치의 원인과 수정

1. 공급현황은 연결 사업 전체, 정책 원장은 2026년 이전 착공 제외로 모집단이 달랐다.
2. 지역 그래프는 현재 단계의 잔량을 표시해 후속 단계 이동 시 값이 줄었다.
3. 계획량 미확보인 양주회천 A26은 정책 지도에서 통째로 제외돼 확인된 모집 792호도 빠졌다.
4. 인허가·사업화 근거 연결 경로가 없었고, 정책 이전 인허가일도 비교 집계에서 제외됐다.

정책 지역 그래프 기본값은 **공급·연결사업 전체**. 공급은 입주 단계 이동 후에도 누적으로 유지한다. 135만 신규 착공 원장은 별도 범위로 선택하며, 이전 착공을 목표 실적으로 몰래 합산하지 않는다. 계획량이 없는 사업의 확인 공급량은 표시하되 계획량을 역산하지 않는다.

같은 9·7 정책·자료 기준일로 검증한 값:

| 지역 | 연결 사업 계획 | 확인 공고 누적 |
|---|---:|---:|
| 서울 | 2,954 | 미확보 |
| 인천 | 5,550 | 미확보 |
| 경기 | 61,420 | 20,131 |
| 고양시 | 7,760 | 4,967 |

이는 정책 발표 목표의 전체 식별 결과가 아닌 현재 연결된 자료의 소계다. 135만 목표 원장 자체의 단계 합계 보존은 별도로 검증한다.

## 단계 근거 저장·검토

기존 `home_revision`의 새로운 kind `stage_evidence`를 사용한다. 프로젝트 × 단계에 하나의 현재 연결을 갖고, 이전 버전은 보존한다.

```text
policy ← program ← project
                       ├─ stage_evidence (BUSINESS / APPROVAL)
                       │    ├─ candidates[] → 원천 레코드 ID·revision·URL
                       │    └─ selected → 사건일 / 상태 확인일 / 물량 / 매칭 방법
                       ├─ delivery_setting.targets[] → 범위·단계·누적 목표·기한
                       └─ delivery_setting.events[] → 실제 단계·지연 사건
```

주요 필드: `project_id`, `stage`, `status(REVIEW/CONFIRMED/RELEASED/UNMATCHED)`, `selected`, `candidates`, `reviewed`, `revision_no`.

근거에는 `source_entity_id`, `source_revision_no`, `source_id`, `source_name`, `evidence_url`, `event_date`, `observed_on`, `units`, `score`, `method`, `basis`를 기록한다. 점수는 매칭 규칙의 우선순위 점수이며 통계적 확률이 아니다.

동일 시도·지구·블록과 사업명·지역 유사도를 비교한다. 구역만 같은 다른 블록은 자동 연결하지 않는다. 건축물 사용승인일을 건축허가일로 바꾸지 않는다. 정확한 허가 근거가 없고 공식 착공 기록이 있으면 `PREREQUISITE` 후보로 연결한다. 이때 허가일을 만들어 넣지 않고 착공일에 이미 선행 단계에 도달했을 가능성을 표시한다. 공식 사업별 공급계획은 사업화 검토 후보로 활용한다.

담당자 변경은 낙관적 잠금(`revision_no`)과 DB 잠금으로 보호하고 `home_audit`에 남긴다. 담당자가 확정·수정·해제한 연결은 자동 갱신으로 덮어쓰지 않는다. 변경 API는 기존 관리자 인증을 적용한다.

9·7 최초 갱신: 178개 원천 사업 × 2단계 = 356건 중 312건 임시 연결, 44건 근거 미연결. 임시 연결의 상당수는 착공 선행 단계 추정이며 정식 허가서 직접 매칭 건수로 해석하면 안 된다. 정책·프로그램 연결 미완료와 단계 근거 미연결은 서로 다른 문제다.

자동 매칭은 화면 조회 중 수행하지 않는다. 수집 후 또는 담당자의 자동 연결 갱신으로 수행한다. 인허가 원천은 시도별 일괄 검색하고 후보 수가 상한을 넘으면 조용히 잘라내지 않고 오류를 보고한다.

## 입주 전망과 목표

9·7 원문 PDF 5쪽(인쇄 2쪽)의 수도권 아파트 입주 전망을 사용자 요청에 따라 **입주 관리목표**로 채택한다. 수도권 2025년 161,000호·2026년 112,000호, 서울 48,000호·29,000호이다. 수도권 합계에 서울을 다시 더하지 않는다.

출처: https://eiec.kdi.re.kr/policy/callDownload.do?filenum=2&num=270716

이는 수도권 아파트 전체 전망이며 2026~2030 신규 착공 135만과 모집단이 다르다. `policy_delivery_plan.occupancy_outlook`에 원래 자료 역할, 채택 이유, 연도·지역·페이지를 저장한다. 독립된 입주 관리 영역에서 면으로 목표·실적·갭을 비교한다.

사업별 입주 예정물량은 LH 연간 입주계획, LH 원천 공급계획의 면적·유형별 입주 예정월, 본 모집공고의 입주 예정월을 활용한다. 동일 블록의 판본과 모집단을 중복 합산하지 않는다. 입주 시작일 관리와 실제 입주 가구수는 여전히 구분한다.

`delivery_setting.occupancy_observations[]`에는 지역·연도·실적 기준일·해당 연도 입주량·URL·근거를 담당자가 입력할 수 있다. 전체 시장 실적이 미확보이면 갭과 지연을 null/판정 대기로 유지한다. 연간 범위가 확인된 실제 자료가 있으면 목표와 차이를 계산해 지연 면을 그린다. 일부 기간의 확인량만으로 연간 지연을 확정하지 않는다.

## 그래프 표현

- 실색 면: 단계별 진행 구성. 서로 중복되지 않는 물량으로 표시한다.
- 사선 면: 원천 또는 담당자 목표의 단계별 구성. 점선·실선 목표 그래프를 사용하지 않는다.
- 빨간 겹침 면: 기한이 지난 목표와 이후에 확인된 수량의 차이(지연 검토). 확인된 개별 지연 근거는 별도로 표시한다.
- 목표·실적이 없는 구간에는 지연 면을 만들지 않는다.
- 목표 날짜 사이 면은 직선 연결 시각화이며 별도 월별 공식 목표를 생성하지 않는다.
- 정책 원장 Y축은 1,350,000호. 누적 도달량 지도와 단계 잔량 면적 그래프는 의미가 달라 단계별 누적값을 모두 더하지 않는다.
- 작은 도서·부속 폴리곤은 2D/3D 지역 그래프에서 단순화하며 수치 합계와 지역 목록은 보존한다.

## API와 유지관리

- `GET /api/policy-delivery`: 정책 원장, 전체 연결사업, 단계별 비교, 입주 관리목표.
- `GET /api/stage-evidence?policy_id=POL_2025_0907`: 후보·현재 선택·검토 상태·목표 설정.
- `GET /api/stage-evidence/{project_id}/{stage}/history`: 검토 이력.
- `POST /api/admin/stage-evidence`: 근거 선택·수정·확정·해제.
- `POST /api/admin/stage-evidence/refresh`: 자동 후보 갱신(담당자 검토 보존).
- `POST /api/admin/policy-delivery`: 단계 목표·사건·입주 확인량.

추가 API 키는 이번 수정에 필요하지 않다. 남은 과제는 근거 미연결 44건의 허가·사업화 원문 확보, 추정 연결의 담당자 확인, 동일 모집단의 실제 입주량 확보다. 자료 미확보를 0 또는 사업 지연으로 바꾸지 않는다.

## 검증 결과

백엔드 회귀 78개 통과. 운영 API에서 135만 원장 보존, 서울·인천·경기 공급현황/정책 그래프 수치 일치, 계획 미확보 사업의 확인 공급량 표시를 확인했다. 운영 브라우저에서 공급 기본값, 11년 슬라이더, 목표선 제거와 목표면 생성, 검토 상태·근거 수정·입주 확인량 전송을 검사했다. 브라우저 검사 중 저장 POST는 가로채 실제 DB에는 테스트 입력을 남기지 않았다.

## 2026-10-12 지역 선택 Y축 추가 수정

전체 범위의 정책 목표 축은 1,350,000호로 유지하되, 시도·시군구·사업 선택 시 선택 범위의 공식 목표 또는 확인 물량·목표에 맞춰 자동 조정한다. 지역 선택을 해제하면 전체 축으로 복원된다. 요구사항 적합성 점검은 HOME_REQUIREMENTS_AUDIT_20261012.html/JSON에 별도 기록하며, 진단에 따른 W0~W5 보완 계획을 이미 구현한 것으로 해석하지 않는다.
