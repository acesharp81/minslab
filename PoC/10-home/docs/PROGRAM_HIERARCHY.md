# 정책 → 프로그램 → 사업 연결 검증 (2026-10-07)

HOME의 **정책–프로그램–사업 연결** 메뉴는 두 단계 작업창으로 구성한다. `정책–프로그램`에서 프로그램 묶음의 상위 공급대책을 검토하고, `프로그램–사업`에서 개별 사업의 소속 프로그램을 검토한다. 두 단계는 각각 `REVIEW`(승인 대기), `CONFIRMED`(담당자 확정), `RELEASED`(연결 해제) 상태와 근거 URL, 판정 사유, 수정 번호, 변경 이력을 갖는다. 승인 대기도 검토 통계에 포함하며 해제된 연결은 해당 정책 집계에서 제외한다. 정책 미연계 사업은 별도의 **정책 미연계 · 검토 필요** 화면에 남겨 누락을 숨기지 않는다.

기존 `home_mapping.policy_id`는 초기 직접 정책 제안과 과거 이력 확인용으로 보존한다. 새 `home_program_mapping`이 프로그램의 상위 정책을 저장하며, `home_mapping.program_id`가 사업의 프로그램을 저장한다. 정책별 화면과 지도는 이 두 연결을 따라 유효 정책을 계산한다. 동일한 프로그램 이름도 원천 정책 제안이 다른 경우 별도의 검토 묶음으로 유지한다. 원천 `program` 문자열은 `source_program`으로 함께 제공하므로 담당자가 소속을 바꿔도 원본은 보존된다. 재수집은 담당자 연결을 덮어쓰지 않는다.

운영 자료 최초 이관 결과: **266개 사업 → 16개 프로그램 묶음**, 프로그램 미연계 사업 0건. 세 공급대책에 유효 연결된 사업은 237건, 정책 미연계 사업은 29건이다. 이 29건은 다음 여섯 프로그램 묶음에 있다.

`3기 신도시` 나머지 34건과 `공공주택 건설` 나머지 61건은 기존 9·7 정책 제안에 따라 **승인 대기** 상태로 남겨 두었다. 이관은 승인으로 간주하지 않는다. 담당자가 공식 원문으로 관계를 확인하면 프로그램 단위의 상위 정책을 승인하거나 바꿀 수 있다. 프로그램 모니터 2개는 공급대책 집계와 중첩되는 관점이므로 3개 공급대책 및 정책 미연계 29건과 합산하지 않는다.

공개 조회: `GET /poc/home/api/mappings`의 `programs`·`audit`, `GET /poc/home/api/programs`, `GET /poc/home/api/programs/{id}/history`, `GET /poc/home/api/tree`, `GET /poc/home/api/policy-monitor`. 관리자 쓰기: `POST /poc/home/api/admin/programs/{id}/policy`, `POST /poc/home/api/admin/projects/{id}/program`. 관리자 세션 서명 확인과 각 단계의 `revision_no` 충돌 검사를 유지한다. 기존 직접 정책 쓰기 API는 프로그램에 연결된 사업의 **정책 변경**을 거부하고, 현재 상위 정책을 유지하는 사업 상태 변경만 호환 처리한다.

DB 변경은 `0004_program_hierarchy`의 가산 마이그레이션으로 적용했다. 서비스 시작 시 이전 직접 매칭을 한 번 이관하며 반복 실행해도 중복 프로그램을 생성하지 않는다. 운영 DB 변경 전 `home_mapping`·`home_audit`·`alembic_version`을 백업했다. 테스트 186개 통과; 실제 운영 `tree`에서 266건 전부 확인했고, 두 단계 탭·정책 미연계 화면을 브라우저에서 확인했다. 운영 DB에 테스트용 승인 쓰기는 하지 않았다.

## 2026-10-07 자동 임시 매칭 적용

운영자가 **가장 가능성 높은 연결을 먼저 표시하고 이후 담당자가 확인·조정**하도록 요청하여, 최초 이관 때 정책 미연계였던 6개 프로그램(사업 29건)에 다음 임시 정책 후보를 넣었다. 이는 정책 발표문과 프로그램의 **유형 또는 같은 이름의 기존 검토 묶음**을 비교한 작업용 제안이다. 해당 사업이 발표문에 실제 포함됐다는 공식 확인으로 해석하지 않는다. 특히 2023년부터 존재하는 SH 사업을 2026년 정책에 연결한 것은 현재 공급대책의 관리 범주를 제안한 것이며, 과거 사업의 정책 귀속을 소급해 확정한 것이 아니다.

현재 16개 정책–프로그램 연결과 266개 프로그램–사업 연결은 모두 `REVIEW`(**확인 필요**)이고, 정책·프로그램 미연계는 각각 0건이다. 검토 통계에는 전체 266개 사업이 포함된다. 세 공식 공급대책별 사업은 9·7 152건, 1·29 47건, 8·13 67건이다. 프로그램 관점의 3기 신도시와 도심 공공주택 복합사업은 이 수치와 중첩되므로 합산하지 않는다.

자동 제안은 `PROGRAM_POLICY_AUTO` 이력으로 남기며 재기동·재수집 때 중복 기록하지 않는다. 담당자가 바꾼 연결, `CONFIRMED`, `RELEASED` 및 담당자가 의도적으로 미연계로 보류한 연결을 자동 규칙이 덮어쓰지 않는다. 새 프로그램도 원천 정책 제안이 있으면 우선 적용하고 없으면 유형 규칙의 임시 후보를 `REVIEW`로 생성한다. 사업은 원천 프로그램명으로 자동 연결하고 담당자가 개별 프로그램을 수정·확정할 수 있다. 두 단계 편집은 기존 관리자 세션과 수정 번호 검사를 그대로 사용한다.
