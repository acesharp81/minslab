# 주택파동 조원 배포용 재가공 양식 v1.4

## 무엇을 제출하나요?
**각자 보유한 기존 데이터를 8가지 공통 CSV 구조에 맞춰 변환해서 제출합니다.** 다시 수집할 필요는 없고, 신규 통합사업번호도 각자 확정하지 않습니다.

### 구조
**정책 → 프로그램 → 사업**은 공통규격의 상위 구조입니다. 실제 연계관계는 `정책사업연결_links.csv`에 근거·검토상태를 별도로 기록하며, 관련 정책·프로그램을 찾지 못한 개별 사업도 제출할 수 있습니다. 2번 조원의 `P-` 코드는 정책이 아니라 정비계획 자체 ID입니다.

## 작성 순서
1. `원천_sources.csv`: 기관, 데이터셋명, 수집일, 원천 ID 등록
2. `사업_projects.csv`: 개별 공공주택 사업 목록. `local_project_id`는 조원별 원래 ID를 유지하거나 조원 내부에서만 중복 없는 임시 ID 부여
3. `사업식별자_identifiers.csv`: PNU, 인허가관리번호, 사업지구·블록, 기존 내부번호를 행별로 기록
4. `공급물량_units.csv`: 계획물량, 공고물량, 입주 실적을 구분하여 기록
5. `진행이력_events.csv`: 인허가, 착공, 공정, 준공, 공급공고, 입주예정 정보를 행별로 기록
6. `정책_policies.csv`, `프로그램_programs.csv`: 원천이 있을 때 작성, 없으면 헤더만 제출
7. `정책사업연결_links.csv`: 정책↔프로그램, 프로그램↔사업, 정비계획↔사업의 실제 연결 근거 기록

## 유의사항
- 대상: 서울·경기·인천의 **공공주택**. 민간 재개발 전체 세대수를 공공 공급호수로 오인하지 않습니다. 공공임대가 일부 포함되는 사업은 공공 부분만 분리 확인합니다.
- `source_ref`는 반드시 `원천_sources.csv`의 `source_ref`를 가리킵니다.
- 실데이터만 제출하고 **DEMO 제외**. 모르는 값은 빈 칸으로 두고 0으로 채우지 않습니다.
- `review_status`는 `CONFIRMED` 또는 `REVIEW_REQUIRED`를 사용하며, 추정 연결은 `REVIEW_REQUIRED`로 남깁니다.
- 사업 단위(`project_unit`): `BLOCK`, `INDEPENDENT`, `AREA_UNKNOWN`. 동일 블록의 공급유형은 사업 1건 아래 유형별 물량으로 기록합니다.
- 일정은 YYYY-MM-DD 또는 YYYY-MM. 월만 있으면 임의로 날짜를 만들지 않습니다.
- 물량 `quantity_type`: `PROJECT_PLAN`, `PUBLIC_PLAN`, `SUPPLY_PLAN`, `NOTICE`, `MOVE_IN_ACTUAL`; 서로 중복 합산하지 않습니다.
- CSV는 UTF-8 BOM으로 저장되어 Excel에서도 한글이 표시됩니다.
- **세 자료의 통합 ID는 추후 중복제거·검증 이후 조원1·2가 공동으로 부여합니다.**

## 최소 제출
필수: 원천_sources + 사업_projects + 사업식별자_identifiers(식별자 확보 시) + 공급물량_units 또는 진행이력_events 중 확보한 자료. 정책·프로그램이 없다는 이유로 임의 생성하지 않습니다. 제출본의 빈 CSV 시트도 유지해 주세요.

## 제출전 점검
- CSV 헤더가 변경되지 않았는지
- local_project_id / source_ref가 다른 파일에서도 일치하는지
- 한 프로젝트를 유형별로 중복 등록하지 않았는지
- 정책↔프로그램↔사업 연결을 근거없이 CONFIRMED하지 않았는지
