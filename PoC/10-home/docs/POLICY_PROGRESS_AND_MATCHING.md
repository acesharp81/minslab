## 관리 항목과 지표

관리 항목은 9·7, 1·29, 8·13 공급대책과 3기 신도시, 도심 공공주택 복합사업의 5개입니다. 뒤의 두 항목은 이미 수집한 공식 정책 기원 이력과 원천 프로그램에 기반한 장기 프로그램 정책이며 새 공급대책이나 임의 발표 목표가 아닙니다. 공급대책과 프로그램은 중첩되는 관점이므로 항목별 수치를 합산하지 않습니다.

- 공식 발표 목표는 원문의 수도권 범위·착공 지표와 함께 별도 표시합니다. 인천 포함 발표 물량을 서울·경기 배정 목표로 바꾸지 않습니다.
- 서울·경기 연결 목표는 정확한 지구·블록에서 원천 중복을 검토한 확보 계획량입니다. 복수 현장·모호한 중복·미확보 물량의 제외 건수를 표시합니다.
- 올해 목표는 기준연도 전체의 공급 예정입니다. 사업별 관리자 공급 목표가 있으면 해당 사업 원천 연간 공급 예정 대신 사용합니다. 둘을 합산하거나 전체 정책 목표를 균등 배분하지 않습니다.
- 올해 확인량은 기준연도에 발표된 호환 본 모집공고이며, 누적 확인량은 기준일까지의 호환 공고입니다. 올해 달성률 = 올해 확인량 / 확보 올해 목표, 누적 달성률 = 누적 확인량 / 확보 연결 계획. 부분 수집 자료의 **공고 기준 검토 비율**이며 실제 착공·준공·입주 달성률은 미확보로 유지합니다.
- 전체 완료 전망은 연결 계획의 모든 물량 묶음에 준공·입주 일정이 있고, 각 묶음의 전체 계획량을 해당 일정이 포함할 때만 표시합니다. 일부 면적·회차 물량의 일정만으로 전체 완료를 추정하지 않습니다. 그 외에는 `전체 전망 미확보`, 마지막 확보 일정, 전체 물량 일정 확보 묶음 수를 표시합니다. 공식 2030년 착공 목표 기한과 개별 사업의 준공·입주 예정일을 구분합니다. 더 오래된 공고의 입주 계획으로 새 연간 계획을 덮어쓰지 않습니다.
- 1·2·3년 누적 전망은 기존 호환 기준량 + 중복 없는 미래 예정량입니다. 앞선 [지도 표시 기준](POLICY_MAP_MONITOR.md)을 유지합니다.

5개 요약 카드, 비교 표와 선택 정책의 진행 막대·누적 전망·지연 후보·이행 확인 항목을 제공합니다. 지역·원천·검색·수집 조회일을 적용할 수 있습니다. 이 대시보드는 조회일의 당해연도이며 과거 자료연도 선택은 기존 지도·이력 화면에서 계속 제공합니다.

## 자동 연결과 담당자 검토

새 원천 사업은 수집 트랜잭션 안에서 정책 제안 규칙을 적용하고 `REVIEW`로 연결합니다. 원천이 제안한 관리 정책을 우선하고, 그것이 없으면 명시된 원천 프로그램의 관리 항목을 사용합니다. 근거가 없으면 `UNASSIGNED`로 남기며 사업명으로 정책을 추측하지 않습니다. 담당자가 조정·승인한 기존 연결은 재수집으로 덮어쓰지 않습니다.

`정책–사업 연결` 화면에서 상태·귀속 정책·프로그램 필터, 사업 선택, 자동 제안과 근거, 정책 변경, 승인 대기/최종 승인/해제, 공식 URL과 판정 근거, 감사 이력을 확인합니다. 관리자 로그인 후 개별 검토와 선택 사업 일괄 검토를 저장할 수 있습니다. 프로그램 정책 대시보드에서 이동하면 해당 원천 프로그램의 사업을 조회합니다.

**승인 대기와 확정 연결은 검토 통계에 포함**, 해제 연결은 정책 대시보드·지도 공급 집계·현재 목표 집계에서 제외합니다. 해제 사업의 원천과 검토 이력은 조회 화면에 남깁니다. 승인 수와 검토 수를 함께 표시하며 검토 통계를 공식 정책 실적으로 승격하지 않습니다.

`home_mapping.revision_no`로 동시 수정 충돌을 검사하며 기존 `home_audit`에 신규 `MAPPING_AUTO`, 담당자 `MAPPING_REVIEW`를 보관합니다. 일괄 검토는 사업별 revision을 검사하는 순차 요청입니다. 일부 실패 시 성공·실패 건수와 실패 사업을 보여 주고 실패 사업 선택을 유지합니다. 일괄 원자적 저장을 주장하지 않습니다. 원문 물량·기존 수집 이력·원천 프로그램은 매칭 조정으로 수정하지 않습니다.

## API와 검증

- 공개 `GET /api/policy-monitor`: 5개 관리 항목, 연간·누적 공고 지표, 전망과 검토 상태.
- 공개 `GET /api/mappings`: 자동 제안, 현재 연결 상태와 통계 반영 여부.
- 공개 `GET /api/connections`: 기존 수집 연결과 추가 서비스의 신청·준비 상태.
- 기존 관리자 `POST /api/admin/mappings/{project_id}`를 사용합니다. 부모 MinsLab 관리자 세션·같은 출처 검사·서명 검증을 유지하며 부모 프록시나 타 PoC는 수정하지 않습니다.
- `GET /api/projects/{project_id}`에 `mapping_history`를 추가합니다.

자동 테스트 **98개 통과**: 신규 자동 연결·승인 전 반영, 담당자 승인 보존, 정책 이동, 해제 집계 제외, 프로그램 중첩·동일 블록 중복 제거, 연간 관리자 목표 대체, 과거 공고/올해 지표 구분, 일부 묶음·일부 물량 일정의 전체 완료 추정 방지, 오래된 공고의 이후 계획 덮어쓰기 방지, 인증과 키 비노출 등을 검증합니다.

공개 PC/모바일 화면과 임시 SQLite 승인 서버의 브라우저 검증을 통과했습니다. 임시 서버에서 실제 승인·정책 이동·일괄 승인·해제 후 통계 제외를 확인했고, 운영 서버에는 검증용 승인 쓰기를 하지 않았습니다. 기존 지도·블록·과거 자료·CSV 검증도 통과했습니다. 공개 지도 정책 탭은 전체 + 관리 항목 5개입니다. 콘솔·타일 오류 0, 모바일 가로 넘침 없음.

UI 검증은 `scripts/check-policy-workflow.cjs`를 사용합니다. `tests/workflow_fixture.py`는 `/tmp` SQLite와 테스트 전용 인증값만 사용하는 임시 서버이며 운영 DB를 사용하지 않습니다. 운영 화면 검증은 조회만 수행합니다. 기존 지도 검증은 `scripts/check-map-monitor.cjs`를 계속 사용합니다.

추가 서비스 신청 안내는 [API_KEYS.md](API_KEYS.md)를 참조하세요.

같은 날 후속 점검: 사용자가 입력한 건축물대장·LH 공고·통계누리 3종 키를 실행 서버에 적용하고 실제 자료 3,802건을 추가했습니다. API 연결 점검은 준비 상태 대신 배치 성공·건수·기간을 표시하며 기존 정책 사업 150건과 승인 상태를 보존했습니다. 이후 자동 테스트는 111개입니다. [실제 연결·수집 검증](ADDITIONAL_API_VERIFICATION.md).

## 정책 개요 · 지역/블록 시계열 재구성 (2026-10-03)

정책별 진행현황의 기본 화면을 **정책 선택 → 정책 개요 → 연도별 공급계획 → 시도/시군구/블록 시계열 → 관련 자료 원본** 순서로 변경했습니다. 상단 선택 목록과 5개 정책 탭을 제공하며 기존 사업 연결 조정 버튼은 유지합니다. 개요는 목적·위치·기간·공식 발표 목표·서울/경기 연결 사업계획·세부 공급 내역을 표시합니다. 공식 목표와 사업계획의 범위·지표를 구분합니다.

개요 근거는 [9·7 국토교통부 발표](https://www.molit.go.kr/USR/NEWS/m_71/dtl.jsp?id=95091185), [1·29 공식 브리핑](https://www.korea.kr/briefing/policyBriefingView.do?newsId=156742030), [8·13 공식 브리핑](https://www.korea.kr/briefing/policyBriefingView.do?newsId=156774369), [3기 신도시 최초 입지 발표](https://www.korea.kr/news/policyNewsView.do?newsId=148856563), [도심복합사업 도입 방안](https://www.korea.kr/news/policyNewsView.do?newsId=148883564)입니다. 기간의 최초 날짜는 발표일이며 법적 시행일이나 전체 완료일을 뜻하지 않습니다. 전체 종료 일정이 없는 프로그램은 사업별 일정으로 표기합니다. 자료 원본 링크는 화면 맨 아래에서 정책·사업·보고서·관리자 근거별로 조회합니다.

`/api/policy-monitor`의 기존 지표는 유지하고 각 항목에 `overview`, `timeline`을 추가했습니다. `timeline.years`는 정책 최초 발표 연도부터 확보한 예정 일정과 현재+3년까지입니다. 9·7은 공식 목표 종료 2030년도 포함합니다. 연도별 그래프는 **해당 연도**의 모집/공급·준공·입주 예정량을 구분하며 서로 합산하지 않습니다. 기본값은 준공 예정이고 기준 선택으로 전환할 수 있습니다. 수도권 공식 착공 목표(9·7 연 27만호)는 별도 설명하며 서울/경기 연결 사업의 연간 물량으로 배분하지 않습니다.

공급 수량은 기존 전역 `inventory`의 중복·모호성 제외 결정을 유지합니다. 단계별 원천 일정은 해당 단계의 전역 대표 원천만 사용합니다. 관리자 목표가 있는 블록·연도·단계에서는 해당 원천 예정량을 대체하며 이중 합산하지 않습니다. 물량 미확보는 null이고 화면의 빈 연도를 0호로 해석하지 않습니다. 복수 현장 계약의 물량·진행률은 블록별로 임의 분배하지 않습니다.

트리는 같은 표의 **시도 → 시군구 → 블록** 계층입니다. 공식 경계 및 기존 근거 기반 귀속 규칙을 사용하고, 미해결 사업은 시군구 연결 검토에 남깁니다. 블록이 명시되지 않은 후보지는 사업 단위로 표시하며 블록 코드를 만들지 않습니다. 전체/개별 펼침·접기, 현재 연도 이동, 고정된 좌측 이름·공급수량과 고정 연도 헤더를 제공합니다. 모바일에서는 표 안에서 가로/세로 스크롤합니다.

블록별 상단에는 **원천 계획 기간과 예정 단계/물량**, 하단에는 **실제 보고 공정률**을 놓습니다. 연도별 공정률은 current_project_id로 연결되는 과거 보고와 현재 사업 원천 중 해당 연도 마지막 확보 수치입니다. 공정률 미확보 연도를 보간하거나 0으로 바꾸지 않고 미래 실적을 만들지 않습니다. 여러 계약의 공정률은 각각 표시하며 평균을 내지 않습니다. 모집공고 수량/달성률을 실제 공사율로 대체하지 않습니다. 계획 기간은 날짜상의 구간이며 계획 공정률을 직선으로 추정하지 않습니다. 현재 정책에 연결된 사업의 과거 이력이라는 설명을 유지하여 과거 연도의 정책 귀속으로 오해하지 않게 합니다.

보안 정책을 변경하지 않고 SVG 좌표/폭/높이 속성으로 막대를 그립니다. 인라인 스타일이나 CSS 변수에 의존하지 않습니다. `test_policy_timeline.py`는 연간량과 누적량/단계 구분, 관리자 대체, 중복 블록, 실제 보고의 연도/기준일, 미확보·복수 계약·복수 현장·지역 귀속·공식 착공 지표 분리를 검증합니다. 기존 자동 테스트 포함 **131개 통과**. 브라우저 검증은 `scripts/check-policy-timeline.cjs`에서 정책 5개, 연간 수치, 실제 막대 폭, 계획 위/공정률 아래 배치, 지역 접기와 이름 고정, 원본 링크 하단 배치 및 모바일 표시를 확인합니다. 기존 승인·연결 흐름은 `check-policy-workflow.cjs`의 공개 읽기 전용 검증을 유지합니다.
