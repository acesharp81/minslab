# 성북구 조원 자료의 수집 방법 적용 점검

기준: 2026-10-10 HOME 운영 DB·운영 API·현재 코드. 비교 대상은 `refs/README.md`, `refs/schema.json`, `refs/seongbuk_public_housing.json`이다. 조원 JSON을 HOME에 적재하거나 조원 사업 ID를 채택하는 작업이 아니다. 조원의 **원천 선택, 범위 수집, 원천 간 연결, 검증 규칙**을 HOME 자체 수집에 적용했는지 판정한다.

## 판정

**부분 반영.** 성북구 주택인허가 기본개요와 주거용 건축물대장은 HOME 원천에 확보돼 있다. 동별개요·대지위치도 수집하지만 성북구 일부이고, 고시 이력·사업장 진행 단계·공공임대 단지·건축법 인허가·정비구역 경계는 수집기가 없다. 가장 큰 공백은 원천 행을 안정적인 실사업과 계획에 연결하는 처리다. 따라서 조원 상황판의 사업·계획 수량이 HOME에 나타나지 않는 것은 조원 데이터 병합 여부보다 **동등한 원천의 독립 수집 및 식별·연결 미완료**가 원인이다.

| 조원 방식 | HOME 실제 상태 | 판정 |
|---|---|---|
| 법정동별 `getHpBasisOulnInfo` 전체 페이지 | 서울·경기 1,110/2,629개 동. 성북구 원천 현재 판본 4,542행 | 수집 방식 반영, 전체 범위 진행 중 |
| `getHpDongOulnInfo`, `getHpPlatPlcInfo` | 서울·경기 266/2,629개 동. 성북구 각각 684행·1,908행. 조원 공유본은 2,910행·12,560행(서로 다른 수집 시점) | **성북구도 부분 수집**. 누락 수를 두 판본 차이로 단정하지 않음 |
| `getBrTitleInfo` | 서울·경기 1,102/2,629개 동. 성북구 주거용 표제부 26,336행 | 원천 수집 반영. 허가→대장 동 연결은 미완료 |

| SH 관리현황 OA-12027 연도별 XLS | 2024~2026 공개본 수집 성공, 전체 원천 2,364행 | 수집 반영. 인허가/PNU에 붙여 공공 여부 확인하는 연결은 미완료 |
| 마이홈 공공임대단지 `rentalHouseGwList` | 수집기 없음 | **미반영** |
| 건축HUB 건축법 인허가 `getApBasisOulnInfo` | 수집기 없음. 주택인허가와 별도 서비스 | **미반영** |
| 법정동 코드·V-World 좌표·정비구역 경계 | 법정동 코드와 주소 지오코딩, 공공주택용지·시군구 경계는 수집. 정비구역 `LT_C_UPISUQ161`은 없음 | 부분 반영 |
| 청약홈 공고·SH 공공재개발 | 각각 운영 수집 성공(전체 1,110행·16행). 그러나 공고→실사업·계획 연결은 제한적 | 원천 반영, 연결 미완료 |
| PNU·구역 키·사업 원천 별칭·계획↔사업·사업↔허가/대장 연결 | `HPR_*` 사업 후보 266개는 기존 사업 후보의 1:1 anchor. LH 준공예정 단일 일치 제안은 있으나 계획→사업 연결 0건. 필지 `bun/ji`는 저장하나 PNU 교차표와 별칭 기반 사업 통합은 없음 | **핵심 처리 미반영** |

운영 API `/poc/home/api/sources`의 수집 성공 및 범위, 운영 DB의 `home_revision` 현재 판본을 직접 확인했다. 조원 공유본과 수집 시점·주거용 대장 필터가 다르므로 단순 건수 차이를 공급사업 누락량으로 해석하지 않는다. 지도·사업 화면은 현재 `kind=project` 후보 266건 중 성북구 3건만 읽는다. 인허가 4,542행을 사업 4,542개로 승격해서는 안 된다.

## 바로 적용할 순서

1. **성북구를 독립 수집 검증 구역으로 완주:** 공식 39개 법정동의 주택인허가 기본·동별·필지·대장 조회 상태를 endpoint별로 확인하고 미수집 동만 재개한다. 현재 수집기의 서울·경기 확대는 계속하되 성북구 39개 동을 검증 배치로 우선 완료한다.
2. **별도 원천 추가:** [서울 정비사업 추진현황 OA-22856](https://data.seoul.go.kr/dataList/OA-22856/L/1/datasetView.do) 분기 파일과 정보몽땅 사업장 XLS를 버전별 원본으로 수집한다. 서울 [도시계획 정비사업 현황 upisRebuild](https://data.seoul.go.kr/dataList/OA-20281/A/1/datasetView.do)는 결정고시관리코드를 공식 결정고시 정보와 연결해 사건일을 확인한다. 공개 API 안내는 HTTP 주소이므로 기존 서울 API 키를 평문 전송하지 않는다. HTTPS 제공 경로 또는 공식 대체 내려받기 경로를 확인할 때까지 인증 수집은 보류한다.
3. **독립 활용신청·응답 확인:** [건축HUB 건축인허가 서비스](https://www.data.go.kr/data/15136267/openapi.do)는 현재 주택인허가 서비스와 별도 API다. 기존 공공데이터 키가 같아도 이 서비스의 활용신청·호출 권한은 별도 확인한다. 마이홈 `rentalHouseGwList`도 공식 API 카탈로그와 현행 활용신청·응답을 검증한 뒤 연결한다.
4. **관계 모델 적용:** 원천 `mgmHsrgstPk`·`mgmBldrgstPk`·결정고시관리코드·PNU·단지명·구역명을 별칭/근거로 저장한다. 주택인허가 부모 PK와 동별·대지위치, 대장, 모집공고, SH·마이홈을 실사업에 연결한다. 구역 지정/변경/해제는 `home_plan_event`에 누적하고 사업 연결은 `REVIEW`로 시작한다. 같은 필지의 재승인·해제, 변경허가, 지번 변경, 민간 등록임대 등 조원 문서의 오연결 사례를 회귀 검사로 만든다.
5. **서울·경기로 확대:** 서울 전역은 구별/법정동별 수집 완결성과 원천 공표 시차를 표시한다. 서울 전용 정비 원천을 경기에 복제하지 말고 경기의 동등한 지정·변경·사업 단계 원천을 별도로 확보한다. 검증된 원천만 지도·정책 지표에 연결한다.

## 키와 실행 조건

HOME 운영 환경에서 `POC10_SEOUL_OPEN_API_KEY`, `POC10_BUILDING_HUB_SERVICE_KEY`, `POC10_VWORLD_API_KEY`, `POC10_SH_SERVICE_KEY`의 **설정 여부만** 확인했다(값은 노출하지 않음). 서울 정비사업 공개 API를 수집할 때는 안전한 인증 전송 경로를 먼저 확정해야 한다. 건축법 인허가·마이홈은 같은 포털 키 재사용 여부가 아니라 **해당 서비스 활용승인 상태**를 확인해야 한다. 외부 API 직접 요청은 이 실행 환경에서 기존 주택인허가와 신규 건축인허가가 모두 HTTP 403으로 차단돼 승인 여부 판정에 사용하지 않았다.

기존 `refs/`와 위 공식 카탈로그는 수집 방법의 근거다. 목표는 조원 JSON을 병합하는 것이 아니라 HOME 자체 원본·판본·관계·검증 기록으로 같은 유형의 자료를 재현하는 것이다.
