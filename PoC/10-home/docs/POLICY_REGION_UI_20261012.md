# 9·7 정책 지역 지도와 단계 흐름 개편

적용 범위: 정책현황의 기본 정책인 9·7. 기존 공급현황의 지도 엔진과 가상 아파트 화면은 유지하고, 인천 집계·표식을 보완한다.

## 사용자 동작

- 서울·인천·경기를 독립된 지역 카드로 표시한다. 기본은 3D, 같은 데이터의 2D 탭은 색 농도로 수치를 표시한다.
- `정책 → 사업화 → 인허가 → 건설 → 공급 → 입주` 여섯 단계 버튼과 현재 ±5년 연도 슬라이더를 지도 아래에 둔다.
- 지도 높이는 선택 단계의 해당 연도 물량을 제곱근으로 정규화해 표현한다. 작은 물량도 식별하기 위한 높이 축이며 수치는 라벨·툴팁으로 확인한다. 동일 단계는 11년 범위에서 같은 최대값을 사용해 슬라이더 이동 시 값 변화를 숨기지 않는다. 기본 판의 두께는 구역 식별용이며 물량이 아니다.
- 지역 이름·면·지역별 수치 목록을 선택하면 하단의 단계 흐름, 연도별 목표·실적, 사업 목록을 해당 지역으로 한정한다. 각 시도 제목은 시도 전체 선택, 선택 해제는 수도권 전체 복귀다.
- 서울의 시군구 미연계 사업은 임의의 구에 배치하지 않는다. 카드 하단에 미연계 물량을 표시한다. 인천의 먼 서해 도서는 별도 위치임을 명시한 보조 지도에 표시한다.

## 시각화와 수치의 의미

전체 원장은 매월 1,350,000호를 보존한다. 원본 데이터의 `UNKNOWN`은 삭제하거나 실제 정책수립 실적으로 확정하지 않는다. 화면에서만 `POLICY + UNKNOWN`을 정책/확인 전 구간으로 묶으며, 해칭과 툴팁에서 사업 미특정 목표와 단계 미확인 사업을 구분한다.

| 단계 | 집계 기준 |
|---|---|
| 정책 | 사업 미특정 목표 잔여와 단계 확인 전 물량. 확인된 정책수립 실적을 의미하지 않음 |
| 사업화 | 사업화 도달 근거가 있고 뒤 단계로 이동하지 않은 물량 |
| 인허가 | 인허가 도달 근거가 있고 뒤 단계로 이동하지 않은 물량 |
| 건설 | 착공/건설 도달 근거가 있고 아직 공급 단계로 이동하지 않은 물량. 준공은 공정률·일정으로 별도 관리 |
| 공급 | 본 분양·모집공고로 확인된 물량. 부분 공급은 해당 물량만 이동 |
| 입주 | 입주 시작일이 확인된 사업의 이미 공급된 물량. 실제 입주 가구 수를 의미하지 않음 |

Y축은 0–1,350,000호다. 지역을 선택해도 축을 자동 축소하지 않는다. 원천의 동일 단계 목표선·확인 실적선과 단계 구성 면적을 함께 그린다. 공식 지역 착공 통계와 식별된 개별 사업은 서로 더하지 않는다.

미래 해칭은 원천 목표·일정에 따른 전망이며 실적이 아니다. 연간 착공 목표의 월별 배분은 기존 원장 시나리오를 사용한다. 연간 목표표 합계 1,349,000호와 발표 목표 1,350,000호의 차이 1,000호를 임의 배정하지 않는다. 사업화·인허가 등 목표가 없는 단계는 기존 담당자 목표 입력 기능을 이용할 수 있다.

확인된 지연만 해당 단계 면적 안에 빨간색을 겹친다. 지연을 별도 물량으로 더하지 않으며 동일 사업의 중복 지연 기록은 최대 미달 물량으로 제한한다. 실적 미발견만으로 지연을 단정하지 않는다.

## 기술 구성과 부하

- `policy-region-map.js`: Three.js 0.180.0의 실제 ExtrudeGeometry, 정사영 카메라, 재질·광원·그림자. 배경지도 타일·도로·건물 서비스는 호출하지 않는다. 행정경계는 기존 API 자료를 재사용한다.
- `policy-stage-flow.js`: D3 shape 3.2.0 / path 3.1.0으로 월별 누적 구성, 시점선, 미래 해칭, 지연 중첩, 툴팁을 렌더링한다.
- 라이브러리는 `web/assets/vendor/`에 버전·배포 URL·다운로드 해시·MIT/ISC 라이선스와 함께 보관한다. 외부 CDN 런타임 의존성과 추가 API 키가 없다.
- Three.js는 3D 사용 시 동적으로 불러온다. 프레임을 무한 반복하지 않고 데이터·크기 변경 때만 그린다. 그림자 맵 1024, 기기 픽셀 비율 최대 1.6, 단순화된 경계를 사용한다. 탭·화면 변경 때 GPU 자원을 해제한다.
- WebGL 사용 불가 시 같은 데이터의 2D로 전환한다. 지명 충돌 시 일부를 숨기되 면의 마우스 안내와 지역별 전체 목록으로 모든 지역을 조회할 수 있다.
- 외부 플러그인 검색 결과의 디자인·화이트보드 커넥터는 이 서비스의 실행 시 지도 렌더러 역할에 맞지 않아 연결하지 않았다. 사이트 내부에 필요한 렌더링 라이브러리를 직접 연결했다.

## 인천이 공급현황에서 누락된 원인과 수정

`supply_dashboard`의 시도 목록과 지도 표식의 지역명 분기가 서울·경기로 고정돼 있었다. 인천 공식 경계도 정책 전용 수집 자료에만 존재했다. 시도 목록을 3개로 확장하고 `policy_municipality` 경계를 ID로 중복 제거해 공통 지도에 제공한다.

인천 LH 원천 식별자는 기존 LH 공급·공사 원천과 같은 재고 중복 배제 및 모집공고 연결 규칙을 적용하되 `origin_source_id`에 실제 수집원을 유지한다. 원천명에 인천과 구명이 명시된 경우에만 현재 경계에 검토 연결한다. 구명이 없는 동 이름이나 행정구역 개편 전 서구를 임의로 새 구에 배치하지 않는다. 시군구가 미연결이어도 공식 시도별 물량 표식은 숨기지 않는다.

## 남은 데이터 한계

현 화면의 연결 사업 원장은 정책 목표 전체의 사업별 목록이 아니다. 사업 미특정 목표가 대부분이며, 서울의 연결 사업은 시군구 위치 미연계가 남아 있다. 이 물량을 지도 면에 임의 분산하면 잘못된 정책 판단을 유도하므로 미연계로 남긴다. 따라서 참고 이미지처럼 모든 단계에 큰 면적을 만들기 위해 임의 실적을 생성하지 않는다.

인천 iH 원천 API 신청과 지도 렌더링은 별개다. 추가 렌더링 API 키는 필요 없다. iH API의 응답 상태와 수집 여부는 수집현황에서 계속 관리하며 신청 완료를 수집 완료로 간주하지 않는다.

## 검증

`test_supply_dashboard`, `test_policy_geo`에서 인천 포함·원천 식별자·중복 배제·모집 연결을 검증한다. `check-policy-907.cjs`는 실제 브라우저에서 3D 캔버스 3개, 2D/3D 전환, 여섯 단계, 월별 135만 호 보존, 연도·지역 연동, 비교값, 담당자 입력을 검증한다. 담당자 입력 테스트는 요청을 가로채 실제 저장하지 않는다.

기존 공급지도의 초기화도 `load`(배경 타일 포함) 대신 로컬 `style.load`를 기준으로 공급 레이어를 구성하도록 보완했다. 배경 타일 오류를 주입한 브라우저 테스트에서도 인천 표식을 유지하는지 확인한다.
