# 데이터셋 개선 과정 도식 및 정책 보고서 붙임 분리

## 요청과 변경 이유

사용자가 데이터셋 공유 → 조원 피드백 → 내부 재검증 → 패턴 규칙·데이터 보강의 반복 과정을 세 번째 탭으로 요청했다. 첫 데이터셋 이후 날짜를 표시하지 않으며, 각 노드에서 발견 사항과 수정 결과를 확인하도록 했다. 외부 모델 조사자료도 조원 피드백 흐름에 묶되, 상세의 검토 자료 설명에는 실제 전달·검토 방식을 보존했다.

정책 추진현황 보고서의 붙임이 길다는 후속 요청에 따라 본문에서 붙임을 분리했다. 붙임은 버튼을 누를 때만 생성하며 본문과 동일한 입력 원장을 사용한다.

## 데이터셋 개선 과정

- 위치: 데이터 정합성 확인 → 세 번째 공개 탭 ‘데이터셋 개선 과정’. 기존 두 문서와 관리자 점검은 유지.
- 5개 대표 검토 회차, 데이터셋 V1~V6, 클릭 가능한 26개 노드.
- 첫 데이터셋에만 최초 공유 날짜 표시. 이후에는 버전·피드백 순번으로 표시.
- V1~V6는 분석 문서와 적용 기록을 묶은 설명용 버전이며, 전체 데이터베이스의 여섯 개 완전한 백업을 뜻하지 않는다.
- 각 노드: 검토 자료 성격, 발견 사항, 내부 재검증, 대상별 이전/반영 결과, 규칙, 반영·보류·정정 상태, 근거 발췌와 원문 해시.
- 원문 10개 참조의 파일 SHA-256 및 발췌 행을 확인. 실제로는 같은 문서를 두 번 참조한 경우가 있으므로 독립 문서 10개라는 의미는 아니다.
- 초기 성북구 검토는 부분 반영·과제 도출로 표시. 외부 모델 활용 검토를 조원의 독립 직접 검증으로 단정하지 않음.
- 정책 물량을 수정하는 기능 없음. 정적 파일 약 40KB이며 탭 선택 시 로드. 운영 DB와 분석 API를 추가 조회하지 않음.

구현: `web/assets/integrity-history/{index.html,history.css,history.js,rounds.json}`, `web/assets/data-integrity.js`, `web/index.html`.

## 보고서 붙임 생성

- 본문 화면, 인쇄/PDF, 본문 HTML·CSV·MD: 본문 7개 장만 포함.
- 최초 보고서 생성 시 붙임 표를 계산하거나 렌더링하지 않음. `appendices`는 빈 배열, `appendix_count`는 3.
- ‘붙임 자료 생성·다운로드’ 버튼: HTML / CSV / JSON / Markdown 선택. HTML을 브라우저에서 인쇄하여 PDF 저장 가능.
- 지연 생성 함수가 본문 생성 시 고정한 입력·범위·사건·계획 원장을 사용. 새 API 호출 없음. 같은 본문에서 재다운로드하면 생성한 붙임을 재사용.
- 본문 JSON은 기존 산출근거와 입력을 유지. 붙임 JSON은 별책의 3개 붙임 표와 같은 기준본 SHA-256을 포함.
- 조건 변경 시 다운로드 도구를 숨겨 이전 기준본을 새 조건 결과처럼 받는 것을 방지. 재생성 시 새 모델에 붙임 생성 함수를 연결.
- 붙임 다운로드 후에도 본문 HTML·목차·인쇄는 7개 장 유지.
- 산식·사업 매핑·실적·목표·DB 저장값 변경 없음.

구현: `web/assets/policy-brief-report.js`, 캐시 버전 갱신 `web/index.html`.

## 검증

- 정책 보고서·기존 보고서·정책 단계 그래프 JavaScript 테스트 총 60개 통과.
- 새 회귀검증: 지연 생성 전 붙임 미포함, 별책 3개만 출력, 원본 입력 변경과 무관한 고정 기준, 지역 필터 유지, 본문 불변, 재다운로드 및 JSON에서의 재생성.
- 운영 사이트에서 공개 탭 순서·키보드 이동·26개 노드·모바일 가로 넘침 없음 확인.
- 운영 177개 사업으로 본문 7장 / 별책 3종 확인. 본문과 별책의 scope·stages·snapshot 일치. 붙임 클릭 시 네트워크 요청 없음.
- 브라우저 오류 없음. 본문 인쇄 프레임에 붙임 없음.
- 기본 설정 샘플 PDF 22페이지. 페이지 수는 지역·유형·선택 기준에 따라 달라질 수 있음.
- 증빙: `docs/evidence/INTEGRITY_HISTORY_AND_APPENDICES_20261023/`.

정적 웹 파일만 운영 컨테이너에 배포했다. DB 변경과 서버 재시작은 수행하지 않았다.

## 후속: 보고서 표의 긴 문장 넘침 수정

사용자가 ‘등록 사유’ 문장이 셀 밖으로 넘어가는 현상을 제보했다. 화면 공통 스타일 `table { white-space: nowrap }`이 보고서 표에도 상속되어, 기존 `overflow-wrap:anywhere`만으로는 줄바꿈되지 않는 것이 원인이었다.

정책 보고서의 표 및 th/td에 `white-space:normal`을 명시했다. 보고서 스타일의 버전을 갱신하고, 내보내기용 스타일 조회·독립 HTML의 스타일 링크에도 같은 버전을 적용했다. 셀 너비에 맞춰 긴 문장과 연속 식별자를 줄바꿈하며 원문 내용은 자르지 않는다. 기존 모바일 표의 가로 스크롤 방식은 유지한다. 근거: `docs/evidence/POLICY_REPORT_WRAP_20261023/`.

## 후속: 산정 불가 달성률 숨김

사용자 요청으로, 달성률·목표 대비·참고비 열에 계산 가능한 값이 하나도 없는 경우 해당 열을 보고서에서 제외한다. 일부만 계산 가능하면 값은 표시하고 미산정 셀은 ‘—’로 표시한다. 착공 핵심 요약과 최저 달성 단계 설명에서도 미산정 비율 문구를 생략한다. 동일 표 모델을 사용하므로 HTML·인쇄·CSV·MD에 동일하게 적용된다.

기존 단계별 계산 결과 및 근거 JSON은 그대로 보존한다. 실제 계산 가능한 ‘확보 부분 달성률’은 전체 달성률과 구분하여 유지한다. 기존 보고서 테스트 14개 통과 및 고정 177개 사업의 계산값 불변 확인. 계산 가능한 별도 사례에서 100.0% 표시 유지 확인. 운영 화면 근거: `docs/evidence/POLICY_REPORT_RATES_20261023/`.
