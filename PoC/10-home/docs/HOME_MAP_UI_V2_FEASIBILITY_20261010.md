# HOME 지도·데이터 표현 v2 적용성 검증 및 보완 계획

검토일: 2026-10-10
검토 대상: 사용자가 전달한 「HOME 지도중심 3D 범위전환 및 내비게이션 개선 요구사항」 v2
이번 작업 범위: **현행 코드와 데이터에 대한 적용 가능성 검증 및 구현 순서 확정**. 누락 데이터의 추가 수집과 화면 구현은 이 문서의 다음 단계로 둔다.

## 결론

**정책현황 전용 3D 지역 그래프로 단계적으로 적용할 수 있다.** 기존 `공급현황` 지도와 조작·레이어·API는 유지한다. 정책별·프로그램별·사업별 추진현황에서만 공유하는 새 지도 컴포넌트에 화면 폭 확장, 한 지도에서의 선택·확대, 시군구별 주제도, 연도별 동기화를 적용한다. 다만 v2의 모든 지리 단위를 곧바로 '정확한 3D 공급량 면'으로 만들 수는 없다. 실제로는 **시군구 경계 56개**, **LH 공동주택용지도형에 근거한 지구 30개**, **블록 98개 중 경계 0개**다. 블록 66개는 LH 라벨점, 24개는 지구 대표점, 8개는 위치가 없다. 확인된 실입주 공급량도 없으므로 `누적 실제 공급`, `정책 달성률`, `입주량`, 그에 따른 정상/지연 판정은 현재의 계획·공고 연결량으로 대체하면 안 된다.

적용 경계: 새 3D 지역 그래프는 `정책현황`의 세 하위 화면에서만 보인다. `공급현황`의 현행 지도, 시군구 원그래프, 블록 표시, 기존 시계열과 조작 기능은 이번 3D 그래프 개편 대상이 아니다. 메뉴 그룹화로 공급현황 안에 옛 분석 화면을 이관하더라도 지도 자체를 교체하거나 새 정책 지도를 중첩하지 않는다.

또한 HOME의 정책·사업 수집 범위는 **서울·경기**다. 인천은 단일 수도권 바탕지도에 보일 수 있지만 공급 집계에서는 `범위 외/미확보`로 표시한다. 수도권 전체 수치로 보이는 정책 발표 목표와 서울·경기 사업 검토 합계의 분모·분자를 섞어 진행률을 만들지 않는다.

## v2 요구사항의 보완 결정

1. **정책현황 안에서만 하나의 전용 WebGL 지도**를 유지한다. 정책별·프로그램별·사업별 화면 전환 시 이 정책 지도 객체와 카메라 문맥을 재사용한다. 넓은 범위는 시도·시군구 공급량 주제도, 가까운 범위는 확인된 용지도형과 블록 위치 표식을 사용한다. `공급현황`의 기존 지도 및 가상 아파트 레이어는 그대로 둔다. 정책 지도에도 예시 건물 형상이 필요하다면 반드시 `가상 형상`으로 표기하고 정책 지표 높이와 분리한다.
2. **정책현황의 업무 선택 범위**(`policy → program → project → block`)와 **그 전용 지도의 공간 레벨**(`metro → sido → sigungu → project → block`)을 분리한다. 정책을 선택하더라도 시군구로 확대할 수 있고, 블록 선택 후 축소해도 정책 문맥과 선택 상태는 남는다. 지도 조작은 `공급현황` 메뉴나 그 지도를 자동으로 변경하지 않는다.
3. 주제도 높이에는 **선택한 지표의 수량만** 넣는다. 서울·경기 내 `검토 사업계획 물량`처럼 현재 확보된 지표를 기본으로 시작하고, 공식 인허가·착공·준공 지역 통계는 별도 지표/집계 범위로 제공한다. 규모 범례에는 지표명·단위·선형/비선형 높이 환산 규칙을 명시한다. 범위마다 높이 척도가 바뀌면 이를 표시하고, 정확한 수량은 클릭 상세에서 확인한다.
4. 색의 의미를 하나로 고정한다. 면의 기본 채도는 수량 구간, 윤곽선/아이콘은 `확인된 일정상 조기·정상·지연`, `확인 필요`, `판정 불가`, `범위 외`를 나타낸다. **예정일만 경과한 사업은 실제 지연 확정이 아니라 `이행 확인 필요`**다. 위치 근거와 관계 검토 상태는 배지·도움말로 따로 나타낸다.
5. `REVIEW` 연결은 이전 HOME 운영 원칙대로 **'검토 후보/모니터링' 통계에 포함**한다. 다만 공식 정책 성과와 구분하고 승인 `CONFIRMED`만으로도 실입주가 검증된 것으로 취급하지 않는다. v2 §15.4의 '승인 전 REVIEW를 공식 성과로 합산하지 않는다'와 양립하는 방식이다. 정책별 합계는 정책 중첩·여러 프로그램 연결에 따른 중복을 제거하거나 `중복 가능`으로 표시한다.
6. `0`은 실제 0이 확인된 경우에만 쓴다. `null`은 `미확보/미연계/일정 미정/범위 외` 등 이유를 함께 전달하고 회색·빗금·점 형태로 표현한다. 값이 없다고 임의의 입체 높이를 생성하지 않는다.
7. 시계열은 **사실의 연도**(`display_year`)와 **그 사실을 알고 있던 기준일**(`knowledge_as_of`)을 분리한다. 2026년에 수집한 과거 자료를 2020년에 이미 알고 있었던 것처럼 회고 화면에 소급 표시하지 않는다. 미래는 전망/관리자 목표/공식 예정의 출처를 분리한다. 연간과 누적은 같은 모집·준공·입주 단계 내에서만 전환한다.
8. 인구·가구·고용 및 주택 재고 비교는 v2 메뉴 요구에 맞춰 `공급현황`의 별도 분석 탭으로 옮기되 **현행 공급현황 지도를 유지**하고 기존 분석 필터/차트가 우선이다. 정책현황용 3D 그래프와 강제로 상태를 동기화하지 않는다. **재고(주택 수)**와 **흐름(연간 공급량)**을 바로 빼서 부족/초과를 만들지 않고, 시점·행정경계·통계 정의가 일치할 때만 가구 대비 재고 차이를 계산한다.
9. 인천은 바탕지도에 표시하되 서울·경기와 동일한 공급 주제도처럼 착색하지 않는다. 인천 경계·공급 시계열을 확보해 범위 확장을 검증하기 전에는 `범위 외` 안내로 고정한다.

## 화면 및 기존 기능 이관안

좌측 1차 메뉴는 요구사항대로 **공급현황 / 정책현황 / 데이터현황 / 매뉴얼** 네 개만 둔다. `정책현황`과 `데이터현황`은 펼침 버튼이며 빈 랜딩 화면은 만들지 않는다. 기존 홈의 `공급 현황`은 `공급현황`으로, `연도별 공급 비교`·`인구·가구·고용 분석`은 그 화면의 탭으로 이관한다. `정책별 진행현황`과 `정책 흐름·과거 자료`는 `정책별 추진현황`의 본문/연혁 탭, `사업 조회`는 `사업별 추진현황`, 현 정책 모니터의 프로그램 뷰는 **새 `프로그램별 추진현황` 읽기 화면**의 기반이 된다. `연도별 목표 관리`는 각 정책/프로그램/사업의 관리자 액션으로 둔다.

`정책–프로그램–사업 연결`은 `데이터현황 > 정책-프로그램-사업연결`로 이관하고, 정책↔프로그램·프로그램↔사업의 후보 근거/승인/해제/감사 기능을 유지한다. `데이터 검증`·`원천 검증 자료`·`수집 원천`·`API 연결 안내`는 `데이터현황 > 출처와 수집현황`의 하위 탭으로 모은다. CSV·검색·표본·원문 링크·관리자 수집 버튼은 각각 접근할 수 있어야 한다. `매뉴얼`에는 지표 정의, 상태값, 가상 형상, 권한, 해석 한계를 새로 정리한다.

새 화면을 위해 기존 해시 주소를 깨지 않는다. `#overview`는 기존 공급현황 지도로 계속 열린다. 새 정책 지도의 상태는 `정책현황`의 세 하위 화면에서만 적용한다. `#annual-supply`, `#area`, `#history`, `#projects`, `#tree`, `#validation`, `#samples`, `#sources`, `#keys` 등의 옛 주소는 새 화면+탭으로 해석한다. 새 주소 체계는 코드의 실제 라우터에 맞춰 확정하며, 사용자 클릭에서는 `pushState` 또는 해시 탐색을 사용하고 `popstate`/`hashchange`로 선택 상태를 복구한다. 현재 `replaceState`만 쓰는 동작은 브라우저 이전/다음 요구를 충족하지 못한다. 지도 선택·연도·필터는 유효한 URL 상태로 직렬화하고, 관리자 전용 화면도 서버 인증을 그대로 적용한다.

## 표시용 데이터 계약(제안)

기존 수집 테이블, 공급현황 지도 코드, `/api/map/dashboard` 계약은 유지한다. **정책현황 전용 표시용 읽기 모델/엔드포인트**를 버전 관리하고, 최종 정합성이 검증된 뒤 필요한 집계 뷰를 물리화한다. v2의 `map_metric_*_yearly` 이름을 그대로 신규 테이블로 먼저 만드는 것은 이르다. 같은 수치가 계획·공고·공식 지역통계·실입주 중 무엇인지 확정되지 않으면 집계 테이블만 늘어난다.

```text
ViewQuery = {
  scope: {kind: metro|policy|program|project|block, id: string|null},
  geo_level: metro|sido|sigungu|project|block,
  display_year: YYYY,
  knowledge_as_of: YYYY-MM-DD,
  period: annual|cumulative,
  measure: planned_capacity|recruitment_notice|permit|start|completion|move_in,
  region_filter: 서울|경기|전체
}

ViewFeature = {
  object_id, object_type, parent_ids, geometry_ref,
  geometry_role: official_admin_boundary|official_housing_land|official_block_boundary|label_point|representative_point|none,
  geometry_date, location_link_status,
  value: number|null, unit: 호, value_status: observed|official_plan|manual_goal|forecast|review|missing|out_of_scope,
  missing_reason, source_id, evidence_url, source_reference_date,
  mapping_status: REVIEW|CONFIRMED|DISCONNECTED|UNLINKED,
  status: early|on_time|late|verification_needed|undetermined,
  status_basis, counted_object_ids, dedupe_rule
}
```

`measure`의 표기명과 `value_status`를 조합하여 사용자에게 '계획 검토', 'LH 모집공고 연결 검토', '공식 시도 준공 통계'처럼 정확히 보여준다. `actual_delivery`가 비어 있는 한 그 선택지는 비활성화하고 이유를 노출한다. 정책/프로그램이 여러 사업을 공유할 수 있으므로 단일 `parent_policy_id`를 강제하지 않고 관계 ID 또는 별도 연결 배열을 참조한다. 한 화면의 정책별 수치를 더해 전체가 된다고 가정하지 않는다. 지리 도형의 기준일은 지표 연도와 독립적으로 둔다.

새 정책 지도 전송은 (1) 단순화된 시도/시군구 정적 도형, (2) 정책·연도별 지표 배열, (3) 현재 화면 내 상세 위치/도형으로 분리한다. 도형은 버전/ETag로 캐시하고 줌 단계·보이는 범위에 필요한 것만 가져온다. 현 공급현황의 7.4MB 단일 응답을 정책 슬라이더 조작마다 재사용·재전송하지 않는다. GeometryCollection은 polygon 요소만 검증해 주제도 입력으로 변환하고, 블록 경계가 없으면 geometry_role에 맞는 점 표식을 사용한다.

## 실행 순서와 완료 조건

### 0. 기능·지표 기준선 고정

현재 메뉴/탭/CSV/관리자 기능과 옛 해시 주소를 목록화한다. 정책·프로그램·사업의 연결 중복, 지역 전체 공식 통계와 사업 후보 합계의 차이, `null` 상태를 테스트 픽스처로 고정한다. 2026-10-10 응답은 변경 가능한 운영 데이터이므로 숫자를 테스트에 하드코딩하지 않고 데이터 계약·비교 규칙을 검증한다.

### 1. 메뉴·화면 틀과 URL 이관

네 가지 주 메뉴와 하위 3+2 메뉴, 하위 탭을 먼저 만든다. 현 기능을 컴포넌트로 옮기되 화면 전환 및 직접 주소/뒤로 가기/CSV/인증 회귀검증을 통과해야 한다. **기존 공급현황 지도 DOM·렌더러·CSS를 보존한다.** 정책현황용 `PolicyGeo3D` 마운트 지점을 기존 `policy-monitor-detail`의 재렌더 영역 밖에 두어 WebGL 캔버스가 정책 선택마다 파괴되지 않게 한다. 정책 화면에만 지도 전체 폭 스타일, 보조 패널 접힘, 모바일 드로어를 적용한다. **이 단계만으로도 v2의 정보구조는 실제 데이터 추가 없이 제공 가능**하다.

### 2. 지리·지표 읽기 모델

기존 API를 호환 유지하면서 위 표시용 계약을 만든다. 서울·경기 시군구 도형 56건의 형상을 정규화·캐시한다. 시도 도형은 그 검증된 시군구 경계 집합에서 만들고, 인천은 범위 외로 구분한다. 지구 LH 용지도형과 블록 라벨점의 geometry_role을 정확히 싣는다. `REVIEW` 계획량과 LH 모집공고 연결량, 공식 지역 통계, 관리자 목표가 같은 `value`로 뒤섞이지 않도록 자료 종류별로 테스트한다.

### 3. 정책현황 전용 지도 컴포넌트와 내비게이션

정책별·프로그램별·사업별 추진현황에서 공유할 `PolicyGeo3D`를 별도로 만든다. 세 화면에서 하나의 MapLibre 정책 지도 인스턴스를 재사용하되 `공급현황`의 `HousingMap`/`MapThreeD` 인스턴스와 DOM은 공유하지 않는다. 정책 화면으로 진입할 때만 지도를 지연 초기화하고 떠날 때 렌더링을 중지하거나 정리한다. 기존 MapLibre 설치 자산으로 주제도 면/테두리/선택 레이어를 추가한다. 시도→시군구→지구 관련 용지도형→블록 점/가상 형상 순서로 표현한다. 다섯 공간 레벨의 줌 임계값은 **줌인·줌아웃 동일 값**을 사용하고 임계 구간에서 투명도만 교차 전환한다. 선택 객체가 없는 경우 화면 중심에 가장 가까운 해당 수준의 객체를 선택하되 화면 중심에 범위 외 영역만 있을 때 서울·경기 값을 임의 선택하지 않는다. 정책현황의 지도 첫 시점에서만 서울·경기·인천이 한 바탕지도에 들어오도록 범위를 맞추고, 인천은 미수집/범위 외 표식을 둔다. 선택 정책이 있는 경우 해당 지역을 강조하되 화면 중심·방향을 불필요하게 재설정하지 않는다. 오른쪽 정보 패널과 좌측 메뉴는 접기/펼치기 가능하게 유지한다.

### 4. 11년 시계열·상세 패널 결합

정책현황 전용으로 현재연도 중심 과거 5·현재·미래 5년의 고정 창과 연간/누적 토글을 그 정책 지도·정책 차트에 동기화한다. 공급현황의 기존 연도 컨트롤은 유지한다. 2018년 등 창 밖 과거 자료로 이동할 수 있는 이전 기간 탐색을 유지한다. 공식 연도별 사실, 공고 검토 연결, 관리자 목표, 단순 배분 추정은 선·선 종류·범례를 달리한다. 정책/프로그램/사업/블록 정보 패널에는 확보된 수치만 보여주고 미확보 이유·원문·관계 검토 상태를 제공한다. `상위 10개` 목록은 전체 건수와 '더 보기' 경로를 함께 둔다.

### 5. 누락 데이터 보강(이번 검토 뒤 별도 실행)

먼저 데이터가 없는 것과 대상 단계가 아직 시작되지 않은 것을 원천 근거로 구분한다. 우선순위는 **블록별 공식 경계 또는 위치 근거**, **사업별 실제 착공·준공·입주 확인자료**, **정책·프로그램 목표의 지역 배분·연차 이력**, **인천 범위 확장 여부에 따른 경계·물량**이다. 해당 자료가 입수되면 geometry_role·value_status가 검증된 항목만 3D 면과 실적 지표를 활성화한다. 수집 경로·신청 키·이용조건은 이 단계 착수 시 별도 점검하며, 화면 개편을 위해 지금 새로운 API 키가 필요한 것은 아니다.

## 최종 수용 검증

- 정책현황의 3D 지역 그래프는 2560px 등 와이드 화면의 남는 폭을 실제로 쓰고, 패널을 접어도 정책 지도 캔버스가 재계산된다. 공급현황 지도 화면의 구조와 기능은 회귀검증으로 보존한다. 375px 모바일과 키보드·스크린리더로 메뉴 토글/탭/지도 선택 대체 목록을 사용할 수 있다.
- 정책현황의 한 전용 지도에서 정책/프로그램/사업/블록 선택, 줌인·줌아웃, 이전/다음 탐색 시 범위와 선택 문맥이 유지된다. 같은 줌값은 접근 방향에 관계없이 같은 지리 레이어를 보인다.
- 정책현황 11년 슬라이더 변경 시 그 지도·패널·그래프의 연도/연간·누적/자료 확보일이 일치한다. 과거 수집 시점으로 조회하면 그 이후 확보 근거는 나타나지 않는다.
- 시군구 56건에만 검증된 행정구역 면을 쓴다. LH 용지 30건은 법정 사업 경계로 보이지 않고, 블록 경계 0건은 가상 면을 공식 도형으로 표시하지 않는다.
- `null`, `0`, `범위 외`, `REVIEW`, `CONFIRMED`가 구분된다. 실입주 자료가 없는 항목에서 정책 실적률/입주 달성률 또는 확정 지연을 임의로 계산하지 않는다.
- 11개 기존 메뉴 기능과 기존 해시 경로·CSV·관리자 전용 액션이 새 메뉴에서 동등하게 작동한다. 특히 기존 공급현황 지도, 원그래프, 블록 표시, 지도 조작은 이전과 같은 진입점에서 동작한다. API 키 문자열은 화면·응답·문서에 노출하지 않는다.
- 새 정책 지도의 도형을 매년 반복 전송하지 않고, 슬라이더 연속 조작·정책 변경·모바일 저사양에서 응답성과 렌더링을 계측한다. WebGL 불가 시 읽기 가능한 목록·수치 대체 화면을 제공한다.

별도 3D 도구·서비스는 초기 필수 조건이 아니다. 기존 MapLibre `fill-extrusion`으로 시군구 56건의 주제도 시제품을 먼저 만들고, 실제 장치에서 지리 도형·애니메이션 성능이나 필요한 표현이 부족하다는 계측 결과가 있을 때 추가 렌더링 라이브러리를 검토한다. 도구를 추가하더라도 정책현황 전용 컴포넌트에만 연결한다. 새 외부 API 키는 현재 단계에 필요하지 않다.

이 문서의 적용 판단은 **정책현황 전용 UI/표현 구조의 착수 가능성**이다. 공급의 실제 달성 여부와 인천을 포함한 수도권 전체 실적이 확보되었다는 판단이 아니다.
