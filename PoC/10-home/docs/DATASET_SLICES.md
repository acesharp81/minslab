# 연계 시스템 데이터셋 추출

사업별 수집연계의 **전체 데이터셋 CSV 옆 → 연계 시스템 데이터셋**에서 생성한다. 현재 등록된 전달 대상은 제공받은 `HOME-슬라이스-전달-20261109.zip`의 **the-housing 상황판 / home-slices/1**이다. 다른 시스템은 해당 시스템의 명세를 검토·등록해야 한다.

## 사용 방법

1. 관리자로 로그인하고 **연계 시스템 데이터셋**을 누른다.
2. 기존 자료 갱신은 **변경분**, 최초 이관·복구는 **전체**를 선택한다.
3. 첫 변경분의 기본 기준일은 **2026-10-22 00:00 한국시간**이다. 다음 변경분은 실제 전달한 이전 ZIP의 `manifest.json`에 있는 UTC `until`을 한국시간으로 환산한 뒤, 그보다 1시간 앞을 선택한다. 생성만 하고 전달하지 않은 ZIP의 시각으로 기준일을 전진시키지 않는다.
4. **화면 수치 대조용 정답 자료 포함**을 권장한다. 제외하면 원천 31종, API 응답 10종, 화면 계산 JS 4종을 포함한다. 포함하면 지역·프로그램별 응답 등 수신 측 검증 입력도 추가한다.
5. **데이터셋 생성**을 누르고 완료되면 **ZIP 다운로드**를 누른다. 창을 닫아도 생성은 계속되며, 같은 브라우저 탭에서 다시 열면 상태를 확인한다. ZIP은 24시간 동안 받을 수 있다. 만료 파일은 다음 생성 시 정리된다.

이 추출은 수신 시스템의 원장 전체를 맞추기 위한 것이다. 현재 화면의 정책·지역·검색 필터를 적용하면 참조 사업과 검증 건수가 누락되므로 **목록 필터는 적용하지 않는다**. 필터를 적용한 행 자료가 필요하면 기존 전체 데이터셋 CSV를 사용한다. 외부 시스템으로 직접 업로드하지 않는다.

## 패키지와 검증

ZIP 루트에 `manifest.json`, `slices/`, `api/`, `web/`, 선택한 경우 `golden/`이 있다. 원천 판본 25종, 작은 표 4종, 실행·감사 표 2종을 전달한다. 변경이 없는 슬라이스도 빈 배열 파일을 유지한다. `null`과 실제 `0`은 구별한다. 호수·단계·정책 연결·실적을 수정하거나 새로 확정하지 않는다.

- DB 원천·현재 판 건수·해시·담당자 용어를 READ ONLY / REPEATABLE READ 트랜잭션에서 추출한다.
- 같은 API 요청은 한 번만 조회하고 여러 전달 파일에서 공유한다. 수집·LLM 호출은 실행하지 않는다.
- 원천 추출 전후 PostgreSQL 트랜잭션 스냅샷이 달라지면 시점이 다른 대조 자료가 섞일 수 있어 전달을 중단한다. 수집·검토 종료 후 다시 생성한다. 작업자를 임의로 중지하지 않는다.
- 담당자 이름·사유 필드는 필요한 원천 열에서 제외하고, 남는 글도 전달 규격의 제거 규칙으로 처리한다. API JSON에서도 담당자 필드를 제거한다. 전달 대상에 키로 의심되는 문자열이 있으면 값은 표시하지 않고 중단한다.
- 이름 제거 규칙이 변경분 밖 기존 행에 영향을 주면 `since: null`인 **전체 패키지로 자동 전환**하고 화면에 이유를 표시한다. 일부 행을 조용히 빼지 않는다.
- 각 파일의 SHA-256·행 수·허용 필드를 검증한다. 전체 패키지는 제공받은 수신 측 `apply`로도 복원 검사한다. 변경분에는 수신 측의 이전 판이 필요하며, 실제 수신 시스템의 화면 수치 대조는 그 시스템에서 수행해야 한다.
- 생성·상태·다운로드는 관리자 권한을 요구한다. 정답 입력에는 관리자 전용 데이터 정합성 대조 자료가 포함되기 때문이다. 실행 오류 시 다운로드를 열어두지 않는다.

## 제공된 초안에서 보완한 부분

원본 규격과 도구는 `backend/slice_contract/`에 보관했다. 통합은 `backend/dataset_slices.py`, 화면은 `web/assets/dataset-slices.{js,css}`에 있다.

1. 제공된 SQL/read_export 초안은 누적 표 `home_batch`, `home_audit`의 전체 현재 건수·해시를 채우지 않았다. 실제 내보내기는 변경분과 별도로 전체 보유 행의 검증값을 계산한다.
2. 실제 보관 원문에는 OCR에서 유래한 `\u0000`이 있어 JSONB 변환이 실패한다. DB 데이터를 수정하지 않고 JSON으로 읽어 동일한 담당자 용어를 추출한다.
3. 현재 공개 API에서 없어진 `validation`, `samples`, `connections`, `api-requests`는 보존된 계산 함수로 기존 응답 구조를 만드는 추출 전용 어댑터를 사용한다. 해당 공개 화면이나 API를 다시 노출하지 않는다.
4. 삭제 판본 대조는 반복 상관 쿼리를 피하고, 같은 종류의 조회를 묶는다. 서버별 한 번에 하나의 ZIP만 생성하고 페이지 진입 시에는 실행하지 않는다. 진행 중 창이 열렸을 때만 4초 간격으로 작은 상태 파일을 조회한다.
5. 변경 여부 검사는 보수적이다. 관련 없는 DB 쓰기도 생성 중단 사유가 될 수 있다. 이 경우 오류 문구를 확인하고 유휴 시간에 다시 생성한다.
6. 수신 도구의 텍스트 기반 키 검사는 공개 문서의 긴 다운로드 식별자도 키로 오인한다. 저장된 공개 문서의 정확한 호스트·경로·파라미터 조합을 제한적으로 등록하고, 인증키 검사를 먼저 수행한 후 해당 API JSON에 표준 슬래시 이스케이프(`\/`)를 적용한다. JSON 파싱 후 URL은 원본과 동일하며 수신 측 도구 변경은 필요 없다. 다른 호스트·경로의 긴 토큰이나 실제 인증정보는 계속 거부한다.

새 시스템을 추가할 때는 원천/필드 허용 목록·증분 규칙·개인정보 처리·검증 입력을 별도 프로필로 정의하고, 원천 이름과 임의 URL/SQL을 사용자 입력으로 받지 않는다. 수신 측 규격이나 사용하는 필드가 바뀌면 양쪽 명세를 함께 갱신한다.
