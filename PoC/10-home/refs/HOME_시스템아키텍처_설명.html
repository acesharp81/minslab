01 / DESIGN PRINCIPLES

무엇을 한 번만 세고, 무엇을 따로 볼 것인가

PLAN의 승인 기준선·공급묶음과 BRIEF의 실제 사업 정체성·법적 계획 이력을 결합합니다. 지역 공식 통계는 별도 사실 계층으로 둬서 정책 실적을 부풀리지 않습니다.

공식 정책목표·기간·원문
실행 프로그램정책과 N:M 연결
법적 계획 / 실제 사업고시 / 집행 단위 분리
블록 / 공급묶음중복 없는 물량
단계별 사건최초·변경·실제
지도·시계열근거와 품질 표시
IDENTITY

원천 기록 ≠ 실제 사업

기관별 사업명·허가번호·PNU는 후보 연결에 사용합니다. HOME 안정 사업 ID는 별도로 발급하고 담당자 승인을 보존합니다.

ACCOUNTABILITY

정책 확정 ≠ 공식 실적

정책 연결이 CONFIRMED라도 실제 준공이 아닙니다. 정책 목표의 범위·지표·공식 실적을 분리해야 합니다.

TEMPORAL

과거 사실 ≠ 당시 인지

효력일, 원천 기준일, 최초·변경 예정일, HOME 수집일을 별도로 저장하고 양 방향의 시간 조회를 지원합니다.

02 / SOURCE VERIFICATION

공식 원천 55개 조사 항목

공식 데이터셋 또는 서비스 존재를 확인한 범위입니다. 조사 55건은 수집성공 55건이 아닙니다. 아래에서 원천, 상태, 우선순위로 검색하고 미확인 작업을 확인할 수 있습니다.

G1 웹·명세 확인만 진행한 항목입니다. 실증은 G2 인증 응답 → G3 지역×연도×페이지 완전성 → G4 원문 해시·재수집·지표 대조가 필요합니다.
서울 정비사업 현황: 데이터가 스스로 법적 효력이 없다고 안내하며, 조회된 이용허락 메타데이터 판본끼리 표기가 달라 최신 허락 확인이 필요합니다.
원천 / ID상태수집 방식주 용도검증 상세 및 남은 작업공식 경로
JavaScript 없이도 공식 출처 전체 목록은 함께 제공된 MD 보고서를 참조하십시오.

즉시 실증할 수집 경로

  • 건축HUB: 기본 / 동별 / 대지위치 API의 인증 응답·전체 페이지·PK 확인
  • 국토부 통계누리: 인허가·착공·준공의 실제 통계표 컬럼과 원본파일 확보
  • LH 준공예정 CSV: 지구·블록·계획 호수와 미확정 0값 규칙 확인
  • 국토부 공공주택지구 원고시: 고시번호·이전 고시·효력일 체인 확보

확보 경로가 불충분한 부분

  • 경기도 공공주택지구 전수 지정·변경·해제 사건
  • 서울 upis/경기 온누리의 대량 조회와 과거 판본 범위
  • 사업별 지연 원인과 조치기한·담당기관을 담은 공식 공개 원장
  • 주택 멸실·철거의 정합한 호수와 사업별 교차식별자
03 / SYSTEM ARCHITECTURE

기존 HOME을 유지하는 3계층 설계

RAW·판본 기록은 보존하고, 정규화 사업원장과 지역통계 팩트를 병렬로 구축합니다. 두 데이터는 화면에서 같이 표시하되 하나의 실적처럼 더하지 않습니다.

① 기관별 원천 / 외부 입력

국토부 고시·통계 · LH/SH/GH 공고·계획 · 건축HUB · 청약홈 · 서울/경기 계획정보 · GIS · KOSIS/SGIS · 업무담당자 승인 입력

↓

② 공통 수집·판본·출처 계층 기존 HOME 보존

수집기 → `data/raw` 원본·SHA-256·파서버전 → `home_batch` → `home_revision` · 실패/부분수집 `home_coverage` · 근거/검토감사 `home_audit`

↓

③-A 사업·정책 원장 / 사건 Fact

정책 ↔ 프로그램 ↔ 정규화 사업 ←→ 법적 계획·고시 사건

  • 안정 사업 ID / alias / 승인·거절 증거
  • 블록 · `SUPPLY_COHORT` · 정책별 배분과 집계
  • 인허가·착공·공고·준공·입주 Fact / 계획·실제 분리
  • 고시·변경 일정 / 기관별 역할·병목 원장

③-B 지역 공식 통계 Fact

지역×월×지표×통계표×판본

  • 국토부 주택건설실적 월별 흐름
  • 인구·가구·재고 · 관측/추계 구분
  • 시도·시군구·행정구역 경계판본
  • 잠정/확정·통계 정의와 작성방법
↓

④ 집계·검증·품질 계층

승인 기준선 / Leaf cohort + 잔여 계획 / 정책·지역 중복 방지 / 지표 비교가능성 검증 / 근거 역추적 / 원천별 Cover­age / 시간 재현

↓

⑤ FastAPI / 지도·시계열 상황판 / 관리자 검토

시도·시군구는 공식 지역 통계 + 확인된 정책 사업의 범위를 구분 · 확대 시 지구/블록/사업 상세 · 단계별 목표/확인 실적/향후 일정 · 고시·API 원문 링크

시도 전체 준공 통계와 HOME 정책 연결 사업의 준공량은 모집단과 시각 규칙이 다를 수 있습니다. 비교 가능성이 확인된 경우에만 Coverage를 계산하고, 그 외에는 서로 다른 이름과 범위의 계열로 병치합니다.
04 / TARGET ENTITY RELATIONSHIP

목표 ERD — 승인 기준선과 물량 집계까지 포함

클릭/키보드 선택으로 엔터티의 의미를 확인할 수 있습니다. 이 관계도는 목표 논리모델이며, 현재 운영 DB에 이미 이 모든 물리 테이블이 존재한다는 뜻이 아닙니다.

엔터티를 선택해 설명을 확인하세요.

예: HOME_PROJECT는 실제 사업을 나타내고, HOME_REVISION은 원천 객체 판본이므로 동일한 ID가 아닙니다.

Interactive ERD
정책·기준선·검토프로그램실사업·공급묶음법적 계획·사건관측·관리 계층원천 식별·판본

필수 다대다 관계(N:M)

  • 정책 ↔ 프로그램: 후속대책/업무계획이 동일 프로그램과 관계 가능
  • 프로그램 ↔ 사업: 검토·확정/해제, 기간과 증거 보존
  • 법적 계획 ↔ 실제 사업: 하나의 구역에 다수 사업, 하나의 사업에 다수 법적 계획 가능
  • 사업 ↔ 기관: 시행·승인·관리의 서로 다른 역할

05 / METRIC & TEMPORAL RULES

정책 집행률은 산식보다 분모와 집계 단위가 먼저입니다

동일 세대가 인허가·착공·모집·준공·입주에 반복 등장하고, 상위 지구가 하위 블록 전체를 포함할 수 있습니다. 둘 모두 숫자를 더하면 공급량을 과장합니다.

A. 상위 지구 / 하위 블록 이중합산 차단

아래 숫자는 공식 집계가 아닌 가상 검증 fixture입니다.

33,000지구 공식 총계획
53,000잘못된 지구+블록 합
33,000중복 제거 계획량
A1 확인 블록
12,000A2 확인 블록
8,000미배정 잔여
13,000
미배정 13,000호는 실제 블록이나 준공 실적을 생성하는 값이 아닌 총계획의 집계상 잔여입니다. 하위 블록 범위의 완전성이 확인되지 않으면 부정확한 균등 배분을 금지합니다.

B. 정책 목표의 범위·단계 일치

01 / SCOPE

서울·경기 vs 수도권

서울+경기를 인천 포함 수도권 목표의 분모에 대입하지 않습니다.

02 / METRIC

착공 ≠ 준공

착공 목표는 같은 범위의 실제 착공으로만 비교합니다.

03 / REVIEW

매핑 확정 ≠ 공식 실적

REVIEW 수치는 탐색용, CONFIRMED는 관계 승인, 실적은 별도 증거 확인입니다.

비교 조건이 충족되지 않으면 달성률을 표시하지 않고 비교 불가 / 분모 미확정으로 표시합니다. 모든 시나리오에서 '0%'로 대체하지 않습니다.

C. 네 가지 시간을 분리

원천 효력일
현재 예정일
확인된 실제일
HOME 수집일

원천 사건의 효력일, 원천 자체의 기준일, 최초/현재 예정일, HOME가 해당 내용을 기록한 시각은 각각 구별합니다. 월·연 단위 날짜는 가짜 일자로 보간하지 않습니다.

06 / BUILD & MIGRATION

Codex 구현 순서 — 기존 HOME 파괴 없이 확장

현행 5개 물리 테이블을 삭제·치환하지 않고, 백업 가능한 읽기 검증부터 추가 마이그레이션과 골든셋·수집기·지도 API까지 단계적으로 진행합니다.

PHASE 0현행 시스템 감사

DB/코드/승인·목표·감사/ID 충돌·백업

PHASE 1수집 실증 G2~G4

API·CSV·고시 원문 해시, 0·실패·부분수집

PHASE 2최소 모델 추가

범위 기준선·cohort·사업ID·법적 사건

PHASE 3골든셋 연계

2정책 / 3프로그램 / 10사업 / 10cohort

PHASE 4통계·지도 API

지역 공식 통계 분리, 증거 drill-down

PHASE 5확대·운영 전환

Shadow read → 검증 → cutover → 복구

기존 DB 이관 금지사항

  • `home_mapping`, `home_program_mapping`의 담당자 확정·해제를 자동매칭으로 덮지 않음
  • `home_revision.entity_id`를 변경하여 원천판본·감사 링크를 끊지 않음
  • 실패 배치가 성공한 이전 raw 판본을 삭제하지 않음
  • 신규 원장 FK 제약은 교차표·충돌 격리 뒤 적용
  • 전환은 구·신 API의 동일 범위·계산 규칙 비교 후 승인

1차 수용 기준

  • 기존 공식/관리자 승인·감사/goal 건수 및 의미 보존
  • Leaf cohort 중복 제거와 상위 계획 잔여량 검증
  • 정책 분모 일치하지 않으면 달성률 NULL+사유 반환
  • 원천 성공·수집 중·실패·미조회·실제 0 구분
  • 지도/Tree 숫자에서 고시·API·공식 파일 원본으로 역추적
07 / DATA CONTRACT & HANDOFF

조장 지도 UI와 조원 수집기를 연결하는 최소 계약

HOME 전체 DB를 플랫폼에 복제하지 않습니다. 사업·블록·지역의 단위·지표 의미·근거가 보존된 조회용 Adapter를 정의하면 팀원별 수집 방법이 달라도 화면 지표가 일치합니다.

계약 핵심 필드

  • object_id / object_type — 정책·지역·사업·블록 구분
  • scope_baseline_id / as_of_date — 분모와 조회 시점
  • geometry / geometry_status — 공식 경계/대표점/미확인
  • plan_units / stage_metrics — 계획·단계별 관측값 분리
  • schedule / risk — 최초·변경·실제·병목
  • mapping_status / provenance — 승인상태·원문 근거
