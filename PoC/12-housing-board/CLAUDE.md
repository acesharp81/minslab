# CLAUDE.md

LLM 이 코딩할 때 자주 하는 실수를 줄이기 위한 행동 지침이다. 필요하면 프로젝트별 지침과 합쳐 쓴다.

**상충 관계:** 이 지침은 속도보다 신중함 쪽으로 기울어 있다. 사소한 일에는 판단해서 쓴다.

## 1. 코딩하기 전에 생각한다

**가정하지 않는다. 헷갈리는 것을 숨기지 않는다. 상충 관계를 드러낸다.**

구현하기 전에:
- 가정을 분명히 밝힌다. 확실하지 않으면 묻는다.
- 해석이 여럿이면 말없이 하나를 고르지 말고 모두 보여 준다.
- 더 단순한 방법이 있으면 그렇게 말한다. 필요하면 반대 의견을 낸다.
- 분명하지 않은 것이 있으면 멈춘다. 무엇이 헷갈리는지 말하고 묻는다.

## 2. 단순함이 먼저다

**문제를 푸는 최소한의 코드. 추측으로 넣는 것은 없다.**

- 요청받지 않은 기능은 넣지 않는다.
- 한 번만 쓰는 코드를 추상화하지 않는다.
- 요청하지 않은 "유연성"이나 "설정 가능성"은 만들지 않는다.
- 일어날 수 없는 상황에 대한 오류 처리는 하지 않는다.
- 200줄을 썼는데 50줄로 될 것 같으면 다시 쓴다.

스스로 묻는다: "시니어 엔지니어가 이걸 보고 지나치게 복잡하다고 할까?" 그렇다면 단순하게 줄인다.

## 3. 필요한 곳만 고친다

**꼭 건드려야 하는 것만 건드린다. 내가 어지른 것만 치운다.**

기존 코드를 고칠 때:
- 옆에 있는 코드·주석·서식을 "개선"하지 않는다.
- 고장 나지 않은 것을 리팩터링하지 않는다.
- 내가 다르게 쓰겠더라도 기존 스타일에 맞춘다.
- 상관없는 죽은 코드를 발견하면 알리기만 하고 지우지 않는다.

내 변경 때문에 남는 것이 생기면:
- 내 변경으로 쓰이지 않게 된 import·변수·함수는 지운다.
- 원래부터 있던 죽은 코드는 요청이 없으면 지우지 않는다.

기준: 바뀐 줄은 모두 사용자의 요청으로 곧바로 설명되어야 한다.

## 4. 목표 중심으로 실행한다

**성공 기준을 정하고, 확인될 때까지 반복한다.**

일을 확인 가능한 목표로 바꾼다:
- "검증을 추가해" → "잘못된 입력에 대한 시험을 먼저 쓰고, 통과하게 만든다"
- "버그를 고쳐" → "버그를 재현하는 시험을 쓰고, 통과하게 만든다"
- "X 를 리팩터링해" → "고치기 전과 후에 시험이 통과하는지 확인한다"

여러 단계의 일은 짧은 계획을 적는다:
```
1. [단계] → 확인: [검사]
2. [단계] → 확인: [검사]
3. [단계] → 확인: [검사]
```

성공 기준이 분명하면 혼자서 반복해 나갈 수 있다. "되게 해"처럼 기준이 약하면 계속 되물어야 한다.

---

**이 지침이 잘 작동하는 신호:** 차이(diff)에 불필요한 변경이 줄고, 지나치게 복잡해서 다시 쓰는 일이 줄고, 확인 질문이 실수한 뒤가 아니라 구현하기 전에 나온다.

## 5. 화면 점검·자료 수집은 ego lite 로 한다

**화면을 확인하거나 웹에서 자료를 가져와야 할 때는 `ego-browser` 스킬(ego lite)을 쓴다.**

- 대상: 화면 점검(스크린샷·DOM·동작 확인), 웹페이지 크롤링, 로그인이 필요한 포털의 자료 수집.
- Playwright 를 가져오거나 다른 브라우저를 따로 띄우지 않는다. 일반 `WebFetch`·즉흥 `curl` 보다 ego lite 를 먼저 쓴다.
- 차단·WAF 때문에 열리지 않거나 검색으로 안 나오는 사실 확인처럼 어려운 조사만 `insane-search` 를 쓴다.
- **ego lite 는 항상 백그라운드에서 쓴다. 사용자 화면 앞으로 띄우지 않는다.**
  - 앱을 앞으로 가져오는 명령은 쓰지 않는다: `open -a "ego lite"`, `open "/Applications/ego lite.app"`, `osascript … activate`, 스킬 폴더의 `scripts/install.sh`(마지막에 `exec open <앱>` 을 실행해서 `--help` 만 붙여도 앱이 앞으로 나온다).
  - 앱이 이미 떠 있으면 그대로 쓴다. 꺼져 있어서 꼭 켜야 하면 `open -g -a "ego lite"`(`-g` 는 앞으로 가져오지 않는다)로만 켠다.
  - `ego-browser nodejs` 스크립트와 개발 서버는 Bash 의 `run_in_background` 로 돌린다.
- 작업 공간(TaskSpace)은 **목표 전체에 하나만** 만들어 계속 재사용한다. 만든 번호는 출력하고(`.visual/.ego-space` 에 적어 둔다) 다음 실행에서 `taskSpace(번호)` 로 이어 쓴다. 실행마다 새로 만들고 닫으면 창이 계속 생겼다 사라져 사용자 화면을 방해한다. 닫는 것(`task.finish({ keep: [] })`)은 **목표 전체가 끝났을 때 한 번만** 한다. 사용자·다른 세션의 작업 공간은 건드리지 않는다.
- 화면 비교 도구는 `scripts/visual/shoot.js`(촬영)와 `scripts/visual/diff.mjs`(비교)를 쓴다. 설명은 `docs/product/Tailwind-shadcn-전환.md` 에 있다.
- `Page.captureScreenshot` 이 `CdpRequestTimeoutError` 로 멈추면 서버가 아니라 브라우저 창이 가려진 것이다. 앱을 앞으로 띄워서 풀지 말고, 이미 만든 작업 공간을 이어 쓰고(새 창을 만들지 않는다) 그래도 멈추면 사용자에게 알린다.
- 스킬에 적힌 Page API(`goto`·`click`·`evaluate`·`snapshot`·`screenshot` 등)를 먼저 쓰고, 픽셀 단위 촬영처럼 꼭 필요할 때만 `page.cdp()` 를 쓴다.
- 로그인된 포털 화면에는 인증키가 평문으로 보일 수 있다. 키 값은 출력·커밋하지 않고, 신청·변경 같은 쓰기 동작은 사용자가 요청할 때만 한다.
- macOS 에는 `timeout` 명령이 없다. 멈출 수 있는 명령은 `perl -e 'alarm 60; exec @ARGV' <명령>` 으로 시간을 제한한다.
