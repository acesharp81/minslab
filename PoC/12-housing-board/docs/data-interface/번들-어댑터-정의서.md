# 지도 번들 데이터 정의서 (어댑터 매핑 포함)

- 번들 스키마 버전: **1.1.0** (1.0.0에 선택 필드만 추가. 1.0.0 번들도 그대로 읽힙니다). 선택 파일 `infra.json`(입주 전 기반시설 점검)은 **1.3.0**으로 따로 더해졌습니다(1.2.0에서 시작, 1.3.0에서 버스 정류소·노선 추가 — 1.2.0 파일도 그대로 읽힙니다) — 3.6절
- 상태: **확정** — 지도 앱이 이 문서대로 번들을 읽습니다(인천 계양구·광주 광산구·전남 나주시 번들로 확인).
- 읽는 분: 지도 번들을 만드는 사람(수집·컴파일러 작성자)과, 지도에 올라간 값을 검토하는 사람
- 한 줄 요약: 번들 JSON을 이 문서대로 만들면, 화면은 **별도 설정 없이** 그 지역을 보여 줍니다. 값이 어디에 어떤 모양으로 나오는지, 비어 있으면 화면이 어떻게 동작하는지가 모두 여기 있습니다.

입력 쪽 규격(CSV)은 `정의서.md`에 있습니다. 이 문서는 그 **다음 단계**인 번들(JSON)과 화면을 다룹니다.

```
입력 CSV·GeoJSON ──(파이프라인: 상태 계산·윤곽 생성)──▶ 번들 JSON ──(어댑터 region.js)──▶ 지도 화면
   정의서.md 규격                            이 문서의 3절                  이 문서의 4~5절
```

## 1. 파일 구성과 불러오는 순서

지역마다 폴더 하나(`regions/<slug>/`)가 있고, 지역 목록 파일 하나(`regions/index.json`)가 모든 지역을 가리킵니다.

| 파일 | 필수 | 내용 | 화면에서의 용도 |
|---|---|---|---|
| `regions/index.json` | 예 | 지역 목록, 기본 지역, 공개 여부 | 처음 열 지역 결정, 지역 선택기 |
| `regions/<slug>/region.json` | 예 | 지역 설정: 제목, 시작 위치, 지구, 출처, 상태 순서 | 제목·문구, 지도 시작 위치, 지구 경계, 범례 |
| `regions/<slug>/projects.json` | 예 | 단지 목록(단지가 0개여도 파일은 있어야 함) | 단지 카드·목록·지도의 블록과 동 |
| `regions/<slug>/buildings.json` | 예 | 지역의 건물 윤곽과 높이(GeoJSON) | 지도의 3차원 건물 |
| `regions/<slug>/context.json` | 아니오 | 지하철역·학교 위치 | 카드의 "가까운 역·학교", 역 반경 |
| `regions/<slug>/infra.json` | 아니오 | 입주 전 기반시설 점검 자료(1.3.0): 신설예정 학교·학교 부지·통학구역·버스 정류소·노선·전기 시설 부지·인허가·대책 | 사이드바 "입주 전 점검" 구역, 지도의 기반시설 표시 |

**불러오는 순서:** 로딩 화면 → (주소에 표준코드 `?code=` `?sgg=` `?bjd=` `?pnu=`가 있으면 `/api/v1/resolve`로 해석해 번들이 있는 시군구의 지역을 정함. 둘 이상이면 `pnu` > `bjd` > `sgg` > `code`, 코드가 `?region=`보다 우선) → `index.json` → 지역 결정(주소의 `?region=` → 없으면 `default: true`인 지역) → `region.json` → `projects.json`·`buildings.json`·`context.json`·`infra.json`을 동시에 → 어댑터 변환 → 화면.

**실패할 때 화면 동작**

| 상황 | 화면 |
|---|---|
| `?region=`이 목록에 없음 | 지역 목록과 함께 안내 화면 |
| 표준코드 해석 실패(형식 오류 400 · 표에 없음 404 · 한도 429 · 서비스 오류 502·503 · 함수 없음 404·405 · 연결 실패) | 사유 문구와 지역 목록 링크(지도는 열지 않음) |
| 표준코드가 번들이 없는 지역(예: 서울 성북구) | 오류가 아님. **빈 번들**(단지 0·건물 0, `dynamic`)로 지도를 열어 경계를 강조하고, 보이는 칸의 건물을 `/api/v1/buildings`로 요청 시 받아 붙인다. 법정동·필지로 열면 그 법정동의 건축HUB 인허가 사업(`/api/v1/permits`)을 단지로 채우고(블록 단위 허가의 위치·합필로 사라진 지번·준공은 건축물대장 총괄표제부의 세대수·대지면적으로 보강하며, 필지로 열었는데 그 필지가 사업이면 그 단지를 열어 줌) 그 단지 가까이의 신설예정 학교·버스 정류장(`/api/v1/infra`)을 `infra.json`의 `schools`·`stops`처럼 넣어 입주 전 점검을 보이고, 위쪽 띠에 "지역 번들이 없어 경계·건물(요청 시 조회)·건축HUB 인허가 사업 N곳만 보여 줍니다", 없으면 "…경계와 건물(요청 시 조회)만…". 띠는 주소 이동 입력줄 아래 반투명 한 줄 요약("번들 없는 지역 · 인허가 사업 N곳 (대장으로 찾음 a · 제외 b)")이고 누르면 위 전체 문장이 펼쳐진다(2026-10-10). 지역 선택기에 "○○ (번들 없음)" |
| 표준코드는 맞지만 요청과 다른 범위로 열림(필지 없음→법정동, 리→읍면동, 경계 조회 실패) | 지도를 열고 위쪽 띠에 한 줄로 알림 |
| `region.json`·`projects.json`·`buildings.json` 불러오기 실패 | 오류 안내(어느 파일인지 표시) |
| `context.json`이 없음(404) | 오류 아님. 역·학교 기능만 숨김 |
| `infra.json`이 없음(404) | 오류 아님. "입주 전 점검" 구역·옵션·지도 표시가 모두 나오지 않음 |
| `projects.json`의 단지가 0개 | 건물만 보이는 **빈 지역 화면**(5.4절) |

## 2. 공통 규약

| 항목 | 규칙 |
|---|---|
| 좌표 | WGS84 `[경도, 위도]`. 소수 6자리 이내 |
| 날짜 | `YYYY-MM-DD`. 입주 월은 `YYYY-MM` |
| 인코딩 | UTF-8 JSON(BOM 없음) |
| 모르는 값 | **키를 빼거나 `null`**. 빈 문자열 `""`·`0`으로 채우지 않습니다 |
| 버전 | 모든 번들 파일의 `schema_version`은 `주.부.패치`. 화면은 현재 주버전과 직전 주버전을 읽습니다 |
| 정본 | 필드의 형식·필수 여부의 정본은 `schemas/bundle/*.schema.json` |

## 3. 필드 정의

표의 `●`는 필수입니다. **화면 용도**가 "사용 안 함"인 필드는 지금은 화면에 영향이 없지만 번들에는 보존됩니다.

|---|---|---|---|---|
| `schema_version` | ● | 문자 | 이 파일의 버전 | 호환 검사 |

| `properties.h` | | 공식 높이(m) | `src`가 `공식높이`일 때 |
| `properties.f`, `b` | | 지상·지하 층수 | |
| `properties.u`, `n`, `a`, `d` | | 용도, 건물명, 사용승인 연도, 법정동 | 건물 카드 |
| `properties.x` | | `1`이면 높이·층수 불일치 의심 | 건물 카드 |
| `properties.g` | | `1`이면 철거 의심(아래). 없으면 의심 없음 | 입체로 그리지 않고 평면으로만 그림, 건물 카드의 "현존 미확인" |
| `meta.existence` | | 철거 의심 표시를 붙인 방법 요약(`source`·`minCover`·`recentYear`·`flagged`). `g`를 붙인 번들에만 있음 | 화면은 읽지 않음 |

**`eh`를 정하는 순서(번들 작성자 규칙):** 공식 높이 `h`가 0보다 크면 `eh = h`(`src` = `공식높이`) → 아니면 지상층수 `f`가 있으면 `eh = f × 층고`(`src` = `층수환산`) → 둘 다 없으면 `eh = 3`(`src` = `정보없음`). `정보없음` 도형은 **솟지 않는 연한 평면 + 점선**으로만 그려지고 그림자도 없으며, 눌렀을 때 카드는 "건물 정보 없음 · 건축물대장과 이어지는 정보가 없는 도형이라 실제와 다를 수 있음"이라고 안내합니다. 원천(V-World 건물 레이어)에는 대장과 이어지지 않은 도형이 남아 있어 신도시에서는 차로·공원 위에도 놓이기 때문에, 실재 여부를 모르는 도형을 건물로 세우지 않습니다. 번들 작성자는 `정보없음` 도형을 지우거나 높이를 지어내지 말고 `src`만 정확히 적습니다(`dataset.md` 2.6절).

**`g`(철거 의심)를 붙이는 규칙(번들 작성자 규칙):** 신도시 지구 안(`region.json`의 `zones[].poly`)에서, 건물 면적의 50% 이상이 도로명주소 건물(V-World `LT_C_SPBD`)과 겹치지 않고, 사용승인이 2015년 이전이거나 없으면 `g = 1`. 신도시 조성 때 철거된 옛 건물이 대장 속성을 가진 채 건물 레이어에 남아 차로 위에 서 있는 것처럼 그려지는 것을 막기 위한 값입니다. **지구 밖에는 붙이지 않습니다**(농가·축사 등 도로명주소가 없는 실제 건물이 겹치지 않습니다). 도로명주소 건물을 받지 못했거나 지구 안 2008년 이후 승인 건물의 겹침이 60% 미만이면 자료가 불완전한 것이므로 붙이지 않습니다. `g`는 철거 확정이 아니라 현존을 확인하지 못했다는 뜻이고, 화면은 `정보없음`과 같이 평면으로만 그립니다. 도구: `tools/regiontools/flag_existence.py`(기존 번들) · `build_region.py`(새로 만들 때).

**`meta.factor`의 키:** `공동주택_1-5`, `공동주택_6-10`, `공동주택_11-15`, `공동주택_16-20`, `공동주택_21+`(층수 구간별 m/층)과 용도별 값. 키가 없으면 화면은 **2.85 m/층**을 씁니다.

### 3.6 `regions/<slug>/infra.json` (1.3.0, 선택)

입주 전에 학교·교통·전기가 준비되는지 **공개 자료로** 점검하는 자료입니다. 만드는 도구는 `tools/regiontools/build_infra.py`, 내려받아 둘 원본은 `data/raw/infra/README.md`에 있습니다. 모든 목록은 선택이고, 비어 있으면 키를 뺍니다.

| 필드 | 필수 | 뜻 |
|---|---|---|
| `schema_version` | ● | 이 파일은 `1.3.0`(`1.2.0` 파일도 읽힘. 1.3.0에서 `stops[]`의 `id`·`no`·`routes`, `busRoutes[]`, `busCityCode`가 더해짐) |
| `asOf` | ● | 만든 날. 구역 머리글에 "기준 …"으로 나옴 |
| `sources[]` | ● | 출처. 모양은 `region.sources`와 같음(`id`·`label`·`redistributable`·`url`·`asOf`…) |
| `schools[]` | | 신설예정 학교와 학교 부지 |
| `zones[]`, `attendance[]` | | 초등 통학구역 경계, 단지가 어느 구역에 드는지 |
| `stops[]` | | 버스 정류소(1.3.0부터 국토교통부 TAGO에서 한 번 받은 값) |
| `busRoutes[]`, `busCityCode` | | 정류소를 지나는 버스 노선, 실시간 위치를 부르는 노선의 도시코드(1.3.0) |
| `sites[]` | | 전기·교통(공영차고지) 시설 부지 면 |
| `permits[]` | | 지구 안 비주택 건축 인허가 |
| `measures[]` | | 보도·고시로 사람이 확인한 대책 |

**`schools[]`** — `id`·`name`·`level`(`유치원`·`초등학교`·`중학교`·`고등학교`·`특수학교`)·`status`·`lon`·`lat`·`sources`는 필수.

| 필드 | 뜻 |
|---|---|
| `status` | `신설예정` = 교육재정알리미에 개교 예정이 공시됨(`openYm` 필수) / `부지만` = 도시계획시설 학교 부지는 있으나 개교 일정 공시가 없음(`openYm` 금지) |
| `openYm` | 개교 예정 년월 `YYYY-MM`(공시 그대로) |
| `classes`, `students` | 계획 학급 수, 계획 학생 수(공시) |
| `poly` | 부지 윤곽(도시계획시설). 없으면 점만 그림 |
| `areaM2`, `address`, `note` | 부지 면적, 공시 주소, 짧은 메모 |

**`zones[]`** — 초등 통학구역 하나. `id`·`name`(자료 그대로, 예 `인천당산초통학구역`)·`school`·`poly`(닫지 않은 바깥 고리)·`asOf`·`sources` 필수, `schoolLon`·`schoolLat`(그 학교 위치)은 선택. **`attendance[]`** — `{projectId, zoneId}`: 단지 중심이 들어가는 구역.

**`stops[]`** — `name`·`lon`·`lat` 필수, 1.3.0부터 `id`(TAGO 정류소 id)·`no`(정류소 번호)·`routes`(지나는 노선 `busRoutes[].id`, 노선 번호 순) 선택. **`busRoutes[]`** — `id`(TAGO 노선 id)·`no`(노선 번호) 필수, `type`(`간선버스`·`지선버스`·`광역버스` … 자료 그대로)·`from`·`to`(기점·종점 이름) 선택, `live: true`는 **단지 중심 500 m 안 정류소를 지나 화면이 실시간 위치를 부르는 노선**이며 이 노선에만 `path`(정류소를 순서대로 이은 `[경도, 위도]` 목록, `path[정류소순서-1]`이 그 정류소)가 있습니다. **`busCityCode`** — TAGO 도시코드(인천 23), `live` 노선이 있으면 필수(화면이 아니라 서버 함수 `handlers/bus.js`가 씁니다). 버스 **위치**는 이 파일에 담지 않고 화면이 `/api/bus?region=<slug>`로 천천히 불러옵니다(응답 `{at, ttl, buses[{r, v, lon, lat, ord, stop}]}`, 실시간이 아니라 몇 십 초 전 값).

**`sites[]`** — `id`·`category`(`전기`·`교통`·`하수·환경`·`방재`)·`name`·`poly`·`sources` 필수, `areaM2`·`note` 선택. **`permits[]`** — `id`·`name`·`use`(주용도)·`permitDate`·`sources` 필수, `startDate`·`approvalDate`는 날짜 또는 `null`. **`measures[]`** — `id`·`category`(`교통`·`교육`·`전기`·`기타`)·`title`·`sources` 필수, `when`(`YYYY` 또는 `YYYY-MM`)·`status`(`완료`·`진행`·`예정`·`검토`·`미정`)·`detail`·`short`(타임라인에 쓰는 14자 이하 짧은 이름, 없으면 `title`) 선택. `stops[]`는 `{name, lon, lat}`.

**싣지 않는 값(작성자 규칙)**
- V-World 도시계획시설의 `집행완료`·`미집행` 표기는 싣지 않습니다. 계양 테크노밸리에서는 운영 중인 학교가 하나도 없는 학교 부지 9곳이 모두 `집행완료`로 적혀 있어 건립 현황을 뜻하지 않습니다.
- 지목(답·전)도 건립 근거가 아닙니다. 입주 직전인 A2·A3 부지도 준공 전까지는 `답`입니다.
- 개교·개통 시점은 공시·보도에 적힌 만큼만 적습니다(월을 모르면 연도만, 모르면 키를 뺌).
- 보도·고시에서 옮긴 값은 반드시 `measures[]`에 두고 출처(`sources`)에 원문 주소를 둡니다. `redistributable`은 기사 본문을 옮기지 않았더라도 `N`으로 둡니다.

## 4. 어댑터 변환 규칙

어댑터(`assets/js/region.js`)가 번들을 화면 코드가 쓰는 내부 모양으로 바꿉니다. 번들 작성자가 알아야 할 규칙은 아래가 전부입니다.

### 4.1 필드 매핑

| 번들 | 화면 내부 | 비고 |
|---|---|---|
| `id` | `id` | 내부 식별용. 주소의 `?block=`도 인식 |
| `label` | 화면에 보이는 단지 이름 | 카드·목록·지도 표지·HUD 모두 `label` |
| `outline.poly` | `poly` | |
| `outline.tier`, `outline.how` | 윤곽 문구 | 5.3절 |
| `dongs[].floorsAbove` | `dongs[].floors` | 층수도 높이도 없으면 그 동은 3D로 그리지 않음(4.3절) |
| `dongs[].heightM` | 동 높이 | 있으면 층수 환산보다 우선 |
| `contractAmountM` | `contractM` | |
| `progress.start/end/source` | 같은 이름 | |
| `sources[]` | 출처 문구 | `region.sources[].label`을 이어 붙임 |
| `sponsorClass` | 민간 스타일 여부 | `private_on_public_land`면 회색 톤 |
| `events[]`, `flags[]`, `zoneId`, `sponsor.type` | (사용 안 함) | 번들에는 보존 |

### 4.2 입주 표기 (`moveIn`)

| 번들 값 | 화면에 보이는 값 |
|---|---|
| `"2029-06"` | `입주 2029.06` (내부 형식 `2029.06`) |
| `"2028-09-30"`(날짜) | `준공 예정 2028-09-30` |
| `null`이고 `progress.end` 있음 | `준공 예정 <progress.end>` |
| `null`이고 `progress.end`도 없음 | `입주 시기 미정` |
| `null`이고 `status`가 `입주 단계` | `입주 일자 미상` (이미 입주한 단지에 '미정'은 어색해서 `progress.end`가 있어도 이 문구) |

### 4.3 층수와 높이

- 동 높이: `heightM`이 있으면 그 값. 없고 `floorsAbove`가 있으면 `floorsAbove × 층고`(층고는 `buildings.meta.factor`, 없으면 2.85 m). 둘 다 없으면 그 동은 3D로 그리지 않고 층수 분포에서도 뺍니다. `heightM`만 있고 `floorsAbove`가 없으면 층수는 `round(heightM ÷ 2.85)`로 표시합니다. (`eh = 3`은 지도에 이미 있던 **기존 건물**의 높이를 모를 때 두는 값이며, 화면은 그 도형을 3 m 건물로 세우지 않고 평면으로만 그립니다. 3.4절.)
- 동 카드의 높이 안내: `heightM`이 있으면 "높이 N m", 층수로 구했으면 "높이 약 N m (추정)".
- `dongs`가 없는 단지: 윤곽만 그려지고 카드의 층수는 "미확인".

### 4.4 단지 목록 순서

1. `region.projectOrder`가 있으면 그 순서 그대로(목록에 없는 단지는 뒤에 4번 규칙으로).
2. 없으면 상태 순서 `분양중 → 건설 단계 → 준공 임박 → 입주 단계 → 계획`.
3. 같은 상태 안에서는 세대수가 많은 순(`units`가 `null`이면 0으로 봄).
4. 그래도 같으면 `label` 문자열 순.

### 4.5 상태 → 종류·단계

| 상태 | 내부 종류 | 사다리 단계(`계획·분양·건설·입주` 4칸) |
|---|---|---|
| 계획 | `plan` | 0 — 모든 칸이 비어 있음 |
| 분양중 | `sale` | 1 |

### 4.7 입주 전 점검 판정 (`infra.json`)

단지마다 교육·교통·전기 줄을 만듭니다(`assets/js/infra.js`의 `projectChecks`). 모든 거리는 단지 중심에서의 직선거리이고, 줄에는 `▲ 주의`·`● 참고`·`○ 자료 없음` 표시와 글자가 함께 붙습니다(색만으로 구분하지 않음).

| 줄 | 기준 | 표시 |
|---|---|---|
| 통학구역 | `attendance`가 가리키는 구역 | 참고: `○○초등학교 통학구역 · 직선 약 N m`. 자료 기준일과 "신설 학교가 문을 열면 조정될 수 있음" |
| 신설 학교 | 1.2 km 안 `신설예정` 학교 중 가장 가까운 것(특수학교보다 일반 학교를 먼저) | 개교 예정이 입주(또는 준공 예정)보다 **6개월 이상 늦으면 주의**, 그보다 가까우면 참고. `입주(2026.12)보다 27개월 늦음`처럼 개월 수를 적음. 입주 시기를 모르면 참고(`입주 시기 미정`). 1.2 km 안에 없으면 자료 없음 |
| 학교 부지 | 600 m 안 `부지만` 학교 | 참고: `개교 일정이 공시되지 않은 학교 부지 N곳`. 0곳이면 줄 없음 |
| 버스정류장 | 300 m 안 `stops` | 있으면 참고(곳 수와 가장 가까운 정류장). 없으면, `asOf`부터 입주까지 **12개월 이내일 때만 주의**이고 그보다 먼 단지는 참고(아직 안 생긴 것이 당연). `stops`가 비어 있으면 줄 없음 |
| 가까운 역 | `context.json`의 가장 가까운 역 | 참고. `context.json`이 없으면 줄 없음 |
| 전기 시설 | 가장 가까운 `category: 전기` 시설 부지 | 참고: `전기공급설비 부지 약 N km (지구 안 N곳)` + "수전 가능 여부는 한전 협의 사항이라 공개 자료가 없음". 없으면 자료 없음 |

여러 단지에 되풀이되는 설명(자료 기준일·한계)은 카드마다 쓰지 않고 목록 아래에 한 번만 모아 보여 줍니다. 단지 카드는 **입주(또는 준공 예정)가 이른 순**입니다.

### 5.4 지역 선택기·미리보기·빈 지역

- **지역 선택기:** 공개 목록에 지역이 **2개 이상**일 때만 헤더에 드롭다운이 생깁니다. 고르면 `?region=<slug>`로 이동하며 다른 주소 매개변수는 유지하고 `block`과 코드 매개변수(`code` `sgg` `bjd` `pnu`)를 지웁니다. 사이드바가 접힌 채(기본) 열리므로 같은 선택기가 지도 오른쪽 위 가로 요약의 왼쪽 위에도 나옵니다(지역이 하나뿐이면 지역 이름만). 요약 쪽 선택기는 헤더 선택기에 변경을 넘기므로 이동 방식은 하나입니다.
- **미리보기 배너:** `visibility`가 `preview`인 지역을 열면 상단에 "미리보기 — 공개 전 자료입니다"가 나옵니다. `preview` 지역은 운영 사이트에는 파일 자체가 올라가지 않습니다.
- **빈 지역:** 단지 목록 영역에 "이 지역에는 아직 표시할 단지가 없습니다. 자료가 들어오면 이곳에 나타납니다."가 나오고, 합계·다음 일정·타임라인 영역은 숨겨집니다. 단지는 있지만 입주·준공 날짜가 하나도 없으면 타임라인 영역만 숨겨집니다.

### 5.6 HUD 유리

지도 위의 카드(단지 정보 카드·HUD 요약·상세 카드·하단 범례 띠·시간 바·방향 조절·옵션 창·툴바)는 모두 같은 **HUD 유리** 질감입니다. 표지·요약·범례 띠·시간 바는 낮에는 흰색 48~52%, 밤에는 남색 46~48% 투명도에 흐림 4 px을 쓰고, 뒤 지도를 낮에는 밝게(×1.45), 밤에는 어둡게(×0.5) 눌러 투명도를 낮춰도 글자가 읽히게 합니다. 상세 카드(팝업)·옵션 창·범례 펼침은 뒤 지도가 보이도록 한 단계 더 투명합니다: 낮 흰색 40%·밤 남색 42%, 흐림 1.5 px, 밝기 보정은 낮 ×1.1·밤 ×0.8만 하고, 대신 보조 글자를 더 진하게(낮 `#33373F`, 밤 `#CDD3DF`), 경고 글자를 낮 `#6E2F0D`·밤 `#FFC08A`로 씁니다. 테두리는 옅은 1 px 선이고, 상세 카드·요약·범례·옵션·시간 바에는 네 모서리에만 짧은 선(HUD 모서리 표시)이 붙습니다. `backdrop-filter`를 못 쓰는 브라우저는 거의 불투명(94% 이상)으로 바뀝니다.

글자 대비 기준은 그대로입니다: 가장 밝은 지도와 가장 어두운 지도 위에서(뒤 지도에 밝기 보정을 먼저 곱한 뒤) 본문·보조·상태 글자의 대비가 4.5:1 이상인지 `tests/js/glass.test.cjs`가 확인합니다. 유리 위 상태 글자는 사이드바의 상태 글자(`COLOR_D`)보다 조금 진한 값(`COLOR_G`)을 쓰고, 유리 위 보조 글자는 `#4A4E56`보다 옅은 회색을 쓰지 않습니다(상세 카드는 `--mute-card` `#33373F`). 상세 카드 검사는 별도로 카드 투명도·밝기 보정(`--glass-card-*`)과 카드에 실제 쓰이는 글자색만 대상으로 합니다. 지도 안 단지 라벨 알약(캔버스 그림)은 `backdrop-filter`를 못 쓰므로 바탕 투명도 70%로 둡니다. 투명도·밝기 값은 `assets/css/app.css` 맨 위 변수에 있습니다.

### 5.6b 상세 카드(팝업)

단지·학교·시설을 누르면 뜨는 카드는 폭 236 px의 **작은 유리 카드**입니다. 글자는 12.5 px(제목 14.5 px), 항목 이름은 짧게(공정율·층수·입주·공사·시공·교통·학교·신설 학교), 거리는 `약` 없이 `1.8 km`처럼 씁니다. 가까운 학교가 통학구역의 학교와 같으면 한 줄(`인천당산초 통학구역 · 520 m`)로 합칩니다. 출처는 한 줄만 보이고, 윤곽 설명·자료 출처 주석·"건립 여부는 알려 주지 않는다" 같은 긴 설명은 `자료 설명`을 눌러 펼칩니다.

**기존 건물 카드**: 제목은 건물 이름이고, 이름이 없으면 "이름 없는 건물"입니다. `src`가 `정보없음`인 도형은 제목이 "건물 정보 없음", 칩이 "정보 없음", 본문이 "높이를 알 수 없어 평면으로만 표시"이며 "건축물대장과 이어지는 정보가 없는 도형입니다. 실제와 다를 수 있어(철거된 건물이거나 건물이 아닐 수 있음) 입체로 그리지 않았습니다"를 덧붙입니다. 이 카드는 값이 없는 줄('정보 없음'·'미기재'·'연도 없음')을 늘어놓지 않고 값이 있는 줄(층수·용도·사용승인)만 보입니다. `g = 1`인 건물(철거 의심)은 칩이 "현존 미확인"이고 "지금 있는 건물(도로명주소 건물)과 겹치지 않습니다. 신도시를 만들며 철거된 옛 건물일 수 있어 입체로 그리지 않았습니다"를 덧붙이며, 옛 대장 값(높이·층수·용도·사용승인)은 그대로 보입니다.

### 5.6a 단지 지면 라벨과 하단 범례 띠

- **지면 라벨:** 단지 정보는 떠 있는 카드 대신 **지도 안 라벨**로 단지 위치에 붙습니다. 옅은 유리 알약(얇은 테두리, 왼쪽에 상태색 띠)에 `A2  747세대` / `15층 · 박촌역 860 m` / `▲교육 ▲교통` 세 줄이 들어갑니다. 둘째 줄은 층수이고, `· 가까운 역 거리`가 교통 정보입니다(역은 `context.json`). 점검 자료(`infra.json`)가 없는 지역은 셋째 줄이 없습니다. 라벨은 건물 위가 아니라 단지 발자국에서 **카메라에 가까운 쪽 가장자리 바깥의 땅 위**에 앉아 건물에 겹치지 않습니다(`frontPoint`). 지도를 20도 이상 돌리면 가까운 쪽이 바뀌므로 라벨도 새 자리로 옮겨 갑니다. 멀리서는 점과 단지 이름만, 가까이(확대 16.6 이상)서는 한 줄입니다. 알약끼리 겹치면 옆으로 비켜 서거나 세대수가 작은 쪽이 숨습니다.
- **카드는 옵션:** 옵션 "단지 정보 카드"(기본 켬, 끄면 `cards=0`)는 떠 있는 정보 카드와 모서리 표시선·연결선이 라벨을 대신합니다. 옵션 "단지 모서리 표시선"(기본 켬, 끄면 `hud=0`)은 표시선만 켭니다. "기존 건물 흐리게"는 옵션 창이 아니라 위 도구 줄의 "건물 흐리게" 단추입니다(`dim=0`이면 끔).
- **기존 기반시설 강조:** 지도의 기존 건물(`buildings.json`) 중 학교·병원·공공·복지 시설은 회색 높이 램프 대신 강조색으로 칠하고(교육 노랑 `#F7C600`, 의료 빨강 `#E5384F`, 공공·복지 청록 `#2EC4B6`. 어두운 지도 기준이며, 공공·복지는 준공 단계의 초록과 색상각이 가까워 청록으로 바꿨습니다) 이름 있는 건물에는 확대 15.2부터 이름표를 붙입니다. 분류는 `properties.n`(이름)의 키워드가 먼저이고(학교·유치원·어린이집 → 교육, 병원·의원 → 의료, 구청·주민센터·경찰·소방·경로당·복지관 등 → 공공·복지), 이름이 없거나 `가동`·`16동` 같은 일반명이면 `properties.u`(용도: 교육연구→교육, 의료→의료, 공공·노유자→공공·복지)를 따릅니다. 빌딩·아파트·오피스텔·프라자·타워·교회·농협 같은 상가·주거·종교 이름은 용도가 해당해도 칠하지 않습니다(`교육연구시설` 용도에 학원 빌딩, `노유자시설` 용도에 상가가 섞여 있어서). 같은 이름·같은 동(`properties.d`)의 건물이 여럿이면 이름표는 가장 높은 한 동에만 붙습니다. 건물 팝업 부제에 `교육시설`·`의료시설`·`공공·복지시설`이 붙고, 범례에 `기존 학교·병원·공공시설` 한 줄이 있습니다. `기존 건물 흐리게`를 켜도 이 건물들은 20%만 흐려집니다(그 밖의 기존 건물은 45%). 옵션 스위치는 없고 항상 켜져 있습니다. 규칙은 `assets/js/facility.js`(순수 함수), 시험은 `tests/js/facility.test.cjs`입니다.
- **하단 범례 띠:** 범례는 지도 맨 아래 **한 줄**(기호+짧은 이름: 상태, 기존 건물, 역·학교, 기반시설 기호, `▲ 개교 6개월+ 늦음`)입니다. 오른쪽 끝 `자세히`를 누르면 위로 자세한 설명 목록이 펼쳐집니다. 한 줄에 다 안 들어가면 옆으로 밀어 봅니다. 예전 하단의 "기존 건물 높이 신뢰도" 줄은 없앴고, 배경지도 출처는 오른쪽 아래 ⓘ에 있습니다(V-World 대신 OpenFreeMap을 쓰는 경우와 건물 자료가 없는 지역의 안내만 이 띠 오른쪽에 글자로 나옵니다). 좁은 화면(900 px 이하)에서는 띠를 숨깁니다.

### 5.6c 사이드바: 기본 접힘과 읽기 쉬운 크기

> 2026-10-10: 코드가 '기본 펼침·구역 제목 20px·단지 이름 18px·폭 420px'로 벗어나 있던 것을 이 절대로 되돌렸다(사용자 피드백 '기본 닫힘, 글씨가 너무 크다'). 합계 숫자는 32px. 지도 단지 상세 카드는 대비가 지켜지는 가장 옅은 유리(--glass-hud: 밝은 테마 .90, 어두운 테마 .87)다.

- **기본 접힘(데스크톱):** 처음 열면 사이드바가 숨고 지도가 전체 폭을 씁니다. 왼쪽 가장자리의 `› 공급 현황` 탭을 누르면(또는 `?panel=1`) 펼쳐집니다. 접힌 동안 합계·다음 일정·입주 전 점검 요약은 지도 오른쪽 위 **가로 요약**(#hudSum)이 대신합니다. 확대·축소·나침반 카드(.rctl) 바로 왼쪽에 붙는 2열 카드(약 466×109px)로, 왼쪽은 지역 이름(또는 지역 선택기)·`3,173세대 공급 예정 6개 단지`·상태 막대·번호만 있는 범례(이름과 %는 이름표, 이름 설명은 하단 범례), 오른쪽은 입주 전 점검 한 줄(`▲교육 3 ▲교통 1 ●전기 ›`)과 다음 일정 2건(날짜 줄·세대수는 사이드바에만)입니다. 화면 폭 1140px 이하에서는 상단 바와 겹치지 않게 상단 바 아래(top 60px)로 내려가고, 900px 이하(모바일)에서는 하단 시트가 대신해 보이지 않습니다.
- **상세 카드 자리:** 가로 요약과 확대 카드는 지도 위쪽을 가로로 차지하므로 상세 카드의 폭은 줄이지 않고, 카드가 이들과 가로로 겹치면 그 아래로 세로로 비켜 서게 합니다(지도 아래쪽 끝 밀어 넣기와 같은 방식). 요약·확대 카드와 겹치지 않습니다.
- **글자 크기:** 사이드바 글자는 13px 아래로 내리지 않습니다(그림 안 글자는 12px 이상). 구역 제목은 16px로 단지 이름(15.5px)보다 작지 않습니다. 보조 글자는 `#4A4E56`보다 옅은 회색을 쓰지 않습니다. 패널 폭은 360~380px입니다. `tests/js/sidebar.test.cjs`가 확인합니다.
- **길이 줄이기(기본 접힘·요약):** "입주 전 점검" 구역은 기본 접힘이고(구역 제목, 요약의 `기반시설 보기 ›`, 오른쪽 레일로 열림. 점검 자료가 있는 지역은 처음부터 열림) 안의 `개교 일정`·`계획·대책`·`자료 기준·출처`도 접어 둡니다. 단지 카드는 제목 한 줄과 주의(▲) 줄만 두고 카드를 누르면 지도로 이동합니다(참고 내용은 지도 상세 카드에 있음). 개교 일정은 일정이 공시된 학교만 늘어놓고 부지만 있는 곳은 개수로만 알립니다. 계획·대책 상세는 두 줄까지만 보입니다. 안내 문단과 `지구 안 건축 인허가` 목록은 사이드바에 두지 않으며(`infra.json`의 `permits[]` 자료는 그대로 둠), 푸터의 윤곽·공정율·출처 설명은 `자료 안내`로 접어 둡니다. 계양 기준 사이드바 전체 길이는 5,685px → 3,777px → 접힌 상태 1,320px입니다(점검 구역을 모두 펼쳐도 3,602px).

학교 부지 카드에는 "부지는 도시계획시설 결정 자료이며 학교가 지어졌는지는 알려 주지 않는다"는 문구가 붙습니다. 이 화면은 건립 여부를 말하지 않고 **공시된 개교 시점과 입주 시점의 차이**만 보여 줍니다.

화면에서는 카드 제목 `A-1`, 칩 `입주 단계`, 큰 글씨 `828세대 · 6개동`, 입주 줄 `입주 일자 미상`, 출처 줄 `출처: 마이홈포털 공공주택 모집공고 · V-World 건물 데이터`, 윤곽 줄 `블록 윤곽은 공식 자료 (V-World 공식 블록(LT_C_LHBLPN))`로 나옵니다. 동이 하나뿐이어도 층수 분포는 "25층 1개동"으로 그려집니다.

## 7. 버전과 호환

- 번들 스키마는 **입력 규격과 별도 버전**을 가집니다(입력 `1.0.0` 유지, 번들 `1.1.0`).
- **1.0.0 → 1.1.0은 선택 필드 추가뿐입니다:** `project.note`, `project.builder`, `project.contractAmountM`, `progress.start`, `progress.end`, `progress.source`, `region.projectOrder`. 1.0.0 번들은 이 필드가 없는 것으로 읽습니다.
- **1.2.0은 선택 파일 `infra.json` 추가뿐입니다.** 기존 파일의 필드는 바뀌지 않았고, 이 파일이 없는 번들(광주 광산구·전남 나주)은 화면이 그대로입니다. `region.json`·`projects.json`의 `schema_version`은 `1.1.0`으로 둡니다.
- 필드 삭제·의미 변경·필수 필드 추가는 주버전을 올립니다. 화면은 현재 주버전과 직전 주버전을 읽습니다.

## 8. 번들 작성자 점검표

- [ ] 모든 파일에 `schema_version`이 있고, `index.json`의 `default: true`가 정확히 하나다
- [ ] `projects.json`이 단지 0개여도 존재한다. `buildings.json`에 `meta.basis`가 있다
- [ ] 단지마다 `id`는 지역 안에서 유일하고 한 번 정하면 바꾸지 않았다. `label`은 지도에 짧게 보일 이름이다
- [ ] `status`는 입력 이벤트에서 계산한 값이고 5개 중 하나다. `region.statusOrder`와 같은 5개 목록이다
- [ ] 공공택지 위 민간 단지는 `sponsorClass`가 `private_on_public_land`다
- [ ] 동의 `floorsAbove`는 **지상** 층수다(`floorsBelow`와 바뀌지 않았다). 높이/층이 2.4~4.5 m 안인지 확인했다
- [ ] 모르는 값은 키를 뺐거나 `null`이다. `0`이나 `""`로 채우지 않았다
- [ ] `buildings.json`에서 높이·층수가 모두 없는 도형은 `src`를 `정보없음`으로(`eh = 3`) 적었다. 지우거나 높이를 지어내지 않았다(화면이 평면으로만 그린다)
- [ ] 신도시 지구가 있는 지역이면 `flag_existence.py`로 철거 의심(`g`)을 붙였거나, 붙이지 않은 이유(도로명주소 건물 자료가 불완전 등)를 확인했다. 지구 밖 건물에는 `g`가 없다
- [ ] 단지가 쓴 출처 `id`가 모두 `region.sources`에 있다. `redistributable`이 `Y`가 아닌 출처의 데이터는 `visibility: preview`로 뒀다
- [ ] `infra.json`을 쓴다면: 모든 항목에 출처 `id`가 있고, 학교 `status`와 `openYm`이 서로 맞고(`신설예정`만 `openYm`), `attendance`의 `projectId`가 `projects.json`에 있다. 집행 표기·지목을 건립 근거로 싣지 않았다
- [ ] 번들을 `python3 tools/regiontools/check_bundle.py regions/<slug>`로 검증했다 (`.venv/bin/python`, `jsonschema` 필요)
