# HOME 데이터와 원본 3D 화면 연결

## 변경 이유와 연결 방식

기존 변환기는 후보 위치를 별도 점 레이어에 넣었지만 원본 렌더러의 `projects.blocks.dongs` 입력을 비워 두었습니다. 아파트 모양이 나오지 않았던 원인입니다. 이제 HOME 후보를 원본 `region.js` 어댑터에 단지·동 자료로 전달하므로 기존 MapLibre 돌출 건물, 그림자, 지면 라벨, 선택 효과, 상세 카드를 사용합니다. 시작 화면도 아파트를 볼 수 있는 확대 수준과 58도 기울기로 엽니다.

## 추가 수집 결과

수집 기준은 `data/home10/scene.json`의 `readFinishedAt`이며 후보 기준은 `candidateSnapshotAt`입니다.

원본 `tools/regiontools/build_region.py`가 사용하는 V-World `LT_C_BLDGINFO` 조회 경로를 재사용했습니다. PoC 10의 `policy-geo/geometry`에서 LH 공동주택용지를 받아 라벨점이 한 개 용지 도형 안에 있을 때만 공간 연결했습니다. 그 안에 중심점이 포함된 공동주택 중 5층 이상이며 건물명에서 후보 지구명과 블록명이 함께 맞는 경우만 후보 형상으로 채택합니다. 이 대조도 정책 귀속 확정을 의미하지 않으므로 검토 상태를 보존합니다. 형상이 없는 이유를 미착공으로 단정하지 않습니다.

성남복정2 A1 용지 안에 3개 동이 있었지만 이름은 기존 **통보8차공원아파트**로 신규 후보와 달랐습니다. 주변 건물로만 남겼습니다. 따라서 이번 수집으로 확보한 후보의 실제 설계 형상은 없으며 모든 후보 모형은 가상임을 표시합니다. 밀집 구역 `12713,3744`, `12714,3744`는 원본 API의 최대 5쪽 제한으로 전체 건물 확보를 보증하지 않습니다. 수집 성공 95개가 모든 건물의 완전 수집을 뜻하지 않습니다.

## 가상 모형의 가정

- 원천 계획 호수에 따라 대략 96호당 1개 동, 화면상 3~16개 동을 배치합니다. 호수가 없으면 4개 동을 예시로 사용합니다.
- 층수는 20·24·27·22·25·18층 순환, 층고는 2.85m를 가정했습니다. 동 윤곽은 계단·승강기 코어가 있는 단순 아파트 평면입니다.
- 용지 도형이 있으면 그 안에 들어가는 예시 동을 배치합니다. 없으면 라벨점 주변에 가상 배치 범위를 만듭니다. 실제 동수·층수·배치·사업 경계로 해석하면 안 됩니다.
- 같은 위치의 여러 원천 후보는 모형 하나를 공유하며 상세 카드에서 모든 원천 후보를 엽니다. 계획 호수는 대표 원천 값을 쓰고 합산하지 않습니다.
- 위치 미확보 66건은 배경지도 없는 독립 장면으로 엽니다. 렌더링용 원점 (0, 0)은 실제 좌표로 저장하거나 사업 위치로 표시하지 않습니다. 원천의 결측 좌표는 그대로입니다.
- 모형의 가정은 후보의 실제 호수·공정률·예정일 등 원천 값에 덮어쓰지 않습니다.

## 사용과 갱신

`/home2` → **지도**에서 아파트를 누르거나 오른쪽 후보를 검색해 **3D 보기**를 누릅니다. **근거·상세**는 HOME 원천 정보로 연결됩니다. 위치 미확보 후보도 같은 방식으로 별도 가상 모형을 열 수 있습니다. 지역 선택에서 서울은 위치 미확보 가상 미리보기로 시작합니다.

갱신 순서는 `import-home10.py` → `build-home10-3d.py` → `npm run build` → `npm test` → 서비스 재시작입니다. 수집 캐시는 `.cache/home10-3d/`에 있으며 `--refresh`로 V-World를 다시 조회할 수 있습니다. 장면의 후보 스냅샷이 다르면 빌드가 중단됩니다.

## 검증 결과

- 운영 프록시(`/home2` → `/poc/housing-board`)에서 Chromium WebGL로 실제 지도 렌더링을 확인했습니다. 첫 화면은 61개 단지 모형·479개 동 데이터, 58도 기울기로 시작합니다.
- 오른쪽 목록 검색 → 후보 클릭 → 해당 3D와 원본 상세 카드 열기, 검색 결과가 없을 때 후보 모형 숨김, 위치 미확보 후보의 배경 없는 3D 미리보기를 확인했습니다. 브라우저 실행 오류는 0건입니다.
- 프로덕션 빌드, JavaScript 검사 555개, Python 검사 4개를 통과했습니다. `poc12.service` 재시작 후 운영 응답에서 후보 스냅샷 일치와 152건의 모형 연결을 확인했습니다.
