# 데이터 인터페이스 정의서·스키마·검증기 설계 (S1)

- 작성일: 2026-10-04
- 상태: 초안 (사용자 검토 대기)
- 상위 과제: 주택파동 공급 지도의 다지역 자동 확장. 이 문서는 첫 하위 프로젝트 **S1**만 다룬다.
- 근거 조사: 나주시·광주 선운2·인천 계양 스파이크(2026-10-04), 아래 "근거와 함정" 절 참고

## 1. 목적과 범위

팀원(데이터 수집·정리 담당)이 지도에 들어갈 데이터를 **정해진 표 형식**으로 넘기면, 받는 쪽이 같은 규칙으로 검증하고 오류를 되돌려 줄 수 있게 한다. 이를 위해 아래 네 가지를 만든다.

1. **데이터 인터페이스 정의서** (Markdown, PDF 동시 제공)
2. **입력 규격 명세**(`schemas/input.spec.json`)와 출력 번들 JSON Schema(`schemas/bundle/`)
3. **CSV 템플릿**과 **예시 입력 세트** 2개
4. **검증기** `tools/validate_input.py`

### 비범위 (후속 하위 프로젝트)

- 입력 CSV와 API를 합쳐 출력 번들을 만드는 컴파일러, API 어댑터 (B)
- 출처 간 자동 매칭, 윤곽 생성 (C)
- 앱의 지역 중립화와 계양 이전 (S2)
- 자동 수집·배포 운영 (D), 타일링 (E)

## 2. 결정 기록

| 항목 | 결정 | 이유 |
|---|---|---|
| 정의서를 받는 사람 | 데이터를 수집·정리해서 넘기는 팀원 | 입력 규격이 규범, 출력 번들은 참고 부록 |
| 대상 | 공공 시행 주택 + **공공택지 위 민간 건설** | 지도에서 공공/민간을 구분해 표시 |
| 공공택지로 치는 지구 | 택지개발, 공공주택지구, 혁신도시, 신도시 | 도시개발·산업단지는 제외(공공성 불명확) |
| 지역의 단위 | **시군구**. 지구(zone)는 지역 안의 구역 | 인허가·법정동 코드·건물 데이터가 시군구 단위 |
| 상태 분류 | 계획 · 분양중 · 건설 단계 · 준공 임박 · **입주 단계** | 선운2처럼 준공 후 잔여분양 단계를 표현 |
| 상태 입력 | 입력하지 않음. 이벤트에서 파생 | 계양의 손입력(`META`)이 확장 불가의 원인 |
| 정밀도 표기 | 윤곽 등급 3종(공식·실제 건물·근사)을 화면에 표기 | "현재처럼 표기" 결정의 확장 |
| 제출 방법 | 공유 폴더/ZIP 전달 → 받는 쪽이 검증기 실행 → 리포트 회신 | Git을 몰라도 됨 |
| 정의서 형식 | Markdown(저장소) + PDF | 버전 관리 + 전달용 |
| 공개 | 새 지역은 제공기관 이용조건 확인 전까지 미리보기만 | 출처별 `redistributable` 열로 통제 |

## 3. 계약의 경계와 책임

```
팀원 ──(입력 규격: CSV·GeoJSON, 이 문서의 규범)──▶ 파이프라인(B·C) ──(출력 번들: JSON, 참고)──▶ 앱(S2)
```

| 일 | 팀원 | 파이프라인 | 앱 |
|---|---|---|---|
| 단지·사건·동 사실 수집 | ● | | |
| 출처 기록(`source_id`, `observed_at`) | ● | | |
| 시행자 유형(`sponsor_type`) 판단 | ● | | |
| 상태 계산 | | ● | |
| 윤곽 생성(PNU·블록 → 폴리곤) | | ● | |
| 공공택지 판정(`on_public_land`) | (선택 입력) | ● | |
| 입력 검증·격리 | | ● (검증기) | |
| 지도 그리기·필터 | | | ● |

팀원은 **윤곽(폴리곤)을 보낼 의무가 없다.** 손으로 그린 윤곽이 있을 때만 `geometry_overrides.geojson`으로 보낸다. API 키도 팀원은 필요 없다.

## 4. 산출물과 저장소 구조

```
docs/data-interface/
  정의서.md                     정의서 본문 (0~11절 + 부록). 필드표는 생성 구간(마커)으로 자동 삽입
  정의서.pdf                    정의서.md에서 생성
  templates/                    CSV 템플릿 (헤더만) 7개 + geometry_overrides.geojson 빈 틀
  examples/
    incheon-gyeyang/            계양 예시 입력 세트
    gwangju-gwangsan/           선운2 A-1 예시 입력 세트
schemas/
  input.spec.json               입력 규격의 단일 원천 (열·형식·필수·열거형·규칙 메타)
  bundle/                       출력 번들 JSON Schema: index, region, projects, buildings, context
tools/
  validate_input.py             검증기 실행 래퍼
  datacheck/                    검증기 본체 패키지(표준 라이브러리만 사용): spec, model, readers, values, rules_rows, rules_domain, validate, report, cli
  gen_docs.py                   input.spec.json → 정의서 필드표·CSV 템플릿 생성 및 일치 검사
  build_docs_pdf.py             정의서.md → HTML → PDF (개발 전용: markdown 패키지 + Chrome 헤드리스. Chrome은 PDF를 쓰고도 종료하지 않아 파일이 완성되면 직접 종료한다)
tests/
  helpers.py                    정상 지역을 코드로 만들어 규칙마다 한 곳만 바꿔 시험하는 도구(고정 fixtures 폴더 대신)
  test_*.py                     검증기·생성기·예시·스키마·PDF 테스트 (unittest)
input/                          팀원 제출물을 푼 곳. 저장소에 올리지 않는다(.gitignore)
```

- `input.spec.json`이 입력 규격의 **유일한 원천**이다. 정의서의 필드표와 CSV 템플릿은 `gen_docs.py`가 여기서 만들고, 커밋된 파일과 다르면 테스트가 실패한다.
- 검증기는 표준 라이브러리만 쓴다(팀원이 자기 컴퓨터에서 실행할 수 있게). `markdown` 패키지는 PDF 생성에만 필요하고 검증기·테스트는 쓰지 않는다.
- 출력 번들 스키마는 JSON Schema 파일로 두고, 정의서 7절에 요약한다. S1에서는 스키마만 만들고, 번들 생성(컴파일러)은 B에서 한다.

## 5. 공통 규약

| 항목 | 규칙 |
|---|---|
| 파일 | 지역마다 폴더 하나 `input/<region_slug>/`. 폴더 이름 = `region_slug`. 폴더 안에 `regions.csv`는 **정확히 1행** |
| 인코딩 | UTF-8 (BOM 허용). CSV는 RFC 4180, 첫 줄은 영문 snake_case 헤더 |
| 목록 값 | 한 칸에 여러 값은 세미콜론(`;`)으로 구분 |
| 날짜 | `YYYY-MM-DD`. `move_in` 사건에 한해 `YYYY-MM`(월 단위)도 허용 |
| 좌표 | WGS84(EPSG:4326), GeoJSON은 `[경도, 위도]` 순서 |
| 단위 | 면적 ㎡, 높이 m, 공정율 % (0~100, 소수 허용), 세대수·층수 정수 |
| 불리언 | `Y` / `N` |
| **미상과 0** | **미상은 빈 칸. 0은 실제 0.** 건축HUB는 모르는 값을 0으로 주므로, 수집 단계에서 근거 없는 0은 빈 칸으로 바꿔서 넘긴다 |
| `region_slug` | 소문자 영문·숫자·하이픈. 권장 `<시도>-<시군구>`. 예 `incheon-gyeyang`, `jeonnam-naju`, `gwangju-gwangsan` |
| `zone_id` | 지역 안에서 유일한 slug. 예 `sunwoon2` |
| `project_id` | **지역 안에서 유일**하고 한 번 정하면 바꾸지 않는 문자열. 권장 `<zone_id>-<블록>`. 예 `sunwoon2-A1` |
| `block_label` | 지도에 짧게 보이는 이름. 예 `A-1`, `A6` (유일하지 않아도 됨) |
| 지역 코드 | 행에는 코드를 쓰지 않고 `region_slug`만 참조한다. 코드와 유효기간은 `region_codes.csv`에 둔다 (전남·광주 통합으로 나주가 `46170`에서 `12170`으로 바뀐 사례 때문) |

| 열 | 필수 | 형식 | 설명 |
|---|---|---|---|
| `region_slug` | * | slug | |
| `project_id` | * | 문자 | 지역 안에서 유일, 불변 |

| `address` | | 문자 | |
| `source_id` | * | 참조 | 이 행의 근거 출처 |
| `observed_at` | * | 날짜 | 수집한 날 |
| `verified` | | `Y`/`N` | 사람이 원문으로 확인했으면 `Y` |
| `note` | | 문자 | |

**지도에 올라가는 단지**: `sponsor_type`이 `public` 또는 `joint`이거나, `private`이면서 `on_public_land`가 `Y`(직접 입력 또는 지구 유형으로 계산)인 단지. `private`인데 공공택지 위가 아니면 `I201`(범위 밖)로 목록에만 남고, `unknown`은 `W105`로 지도에서 제외한다.
**표시 클래스**: `public`/`joint` → 공공, `private`이면서 공공택지 위 → "공공택지 민간"(회색 톤). 시행자 유형은 공고문·공사현황·마이홈 공급기관명처럼 **시행자를 직접 말하는 자료**로 정한다. 인허가의 세대 유형(공공임대·공공분양 호수) 필드는 약한 증거이며 단독 근거로 쓰지 않는다.

## 7. 이벤트에서 상태를 계산하는 규칙

파이프라인(B)이 **의심 표시가 없는** 이벤트만으로 아래 순서에 따라 처음 맞는 규칙으로 정한다. 기준일은 계산하는 날이다.

1. **입주 단계**: 실제(`is_planned=N`) `completion_inspection` 또는 `move_in`이 있다. 또는 `structure_observed`가 있고 `notice` 또는 실제 `permit_approved`가 있으며 아래 2·3에 해당하지 않는다.
2. **준공 임박**: 가장 최근 `progress` 값이 90 이상이고 `move_in`(예정 포함)이 기준일부터 3개월 안이다.
3. **건설 단계**: 실제 `construction_start`가 있거나 0보다 큰 `progress`가 있다.
4. **분양중**: 위에 해당하지 않고 `notice`가 있으며 가장 최근 공고일이 기준일로부터 12개월 안이다.
5. **계획**: 그 밖의 모든 단지(`permit_approved`만 있는 경우 포함).

변경허가 때문에 **준공 후에 찍힌 `permit_approved`는 상태 계산에서 무시**한다(계산 단위는 레코드가 아니라 단지).
이 규칙이 기준이다. 실제 데이터로 규칙을 바꿀 때는 정의서 버전을 올린다.

- **버전**: 정의서·`input.spec.json`·번들 스키마가 같은 `schema_version`(semver)을 쓴다. 열 추가는 부(minor), 열 삭제·의미 변경·필수 추가는 주(major)다. 변경 요청은 정의서 10절의 절차를 따른다.
- **제출 방법(11절)**: 팀원은 `input/<region_slug>/` 구조로 CSV를 만들고 ZIP으로 전달한다. 받는 쪽이 `python3 tools/validate_input.py <ZIP 또는 폴더> --out <리포트 폴더>`를 실행해 `validation_report.md`, `validation_report.json`, `quarantine/`를 회신한다. 팀원도 같은 명령으로 미리 확인할 수 있다.

## 11. 검증기 설계

- 입력: 폴더 또는 ZIP 하나(ZIP이면 임시 폴더에 풀어서 검사). 한 제출에 지역 폴더가 여러 개일 수 있다.
- 구조: ① 명세 로더 (`input.spec.json`) ② CSV·GeoJSON 읽기 ③ 규칙 모음(규칙마다 함수 하나, ID로 식별) ④ 리포트 작성(Markdown·JSON·격리 CSV).
- 옵션: `--today YYYY-MM-DD`(검증일, 테스트에서 고정), `--out`, `--strict`.
- 표준 라이브러리만 사용한다(`csv`, `json`, `zipfile`, `datetime`, `argparse`).
- 테스트(`unittest`): 정상 세트는 error 0이어야 하고, 규칙마다 그 규칙 하나만 어기는 최소 세트로 해당 ID만 발생하는지 확인한다. 예시 세트 두 개도 error 0이어야 한다.

## 13. 완료 기준
