# PoC 10 → PoC 12 위치 보강 결과 · 2026-10-11

## 반영 범위

- PoC 10 LH 분양·임대 공급계획의 단일 블록 접미어를 `district`, `block`에 보존한다. 경기 지구명에서 시군구 이름이 직접 확인되면 `municipality`도 채운다. `안산신길2 A1,A3` 같은 복수 블록명은 한 점에 배정하지 않는다.
- PoC 12 변환기의 지구·블록 대조에서 블록 앞의 0, `BL`, 지구 괄호 설명, `국제화계획`, `택지개발사업` 표기를 정규화한다. 정규화 전 원문 이름과 검토 상태는 보존한다.
- 같은 블록에 LH 건설·공정 자료와 공급계획 자료가 각각 하나씩 있으면 둘 모두 *검토용 라벨점*에 연결한다. 한 원천군에 복수 사업후보가 있는 블록은 보류한다.
- 기존 3D 지도에서 동일 라벨점의 후보를 점 하나로 그리고 팝업에 각 원천 후보의 상세 링크를 표시한다. 후보의 정체성과 공급호수를 합산하지 않는다.
- 각 후보에 `locationAnchorId`, `locationMatchRule`, `locationGapReason`을 남기고 변환 보고서에 원천별·사유별 잔여 공백을 기록한다.

## 남은 위치 근거 확보 순서

1. **LH 46건:** LH 공고문·토지이용계획도에서 지번 또는 블록 위치를 찾고 건축HUB 대지위치·PNU와 대조한다. 블록 라벨이 없는 곳에 지구 대표점을 넣지 않는다.
2. **SH 18건:** 공식 `위치` 문자열의 지번을 표준 PNU로 바꾼 다음, 해당 사업의 전체 대상 필지가 맞는지 SH 사업계획·고시로 확인한다. `일대`의 첫 지번은 대표 필지로만 표시한다.
3. **정책 후보 98건과 GH 2건:** 지정 고시·사업계획의 대상지 필지 목록과 구역도, 개별 공급공고를 수집한다. 법정동·시군구 중심점을 후보 위치로 사용하지 않는다.
4. **모호한 LH 16건:** 단일 블록 코드 확인 불가 12건(공급계획명 5건, 그중 복수 블록명 1건 포함)과 같은 블록의 원천 후보 중복 4건이다. 블록별 호수와 사업 관계를 공식 문서로 검토하며 같은 사업으로 자동 병합하지 않는다.

위치는 사업 정체성, 계획호수, 실제 공급·입주 실적과 별도로 검토한다. 현재 사업 API의 직접 좌표는 0/266건이고, 실제 준공·입주 호수 역시 0/266건이다. 주변 기존 건물의 3D 도형은 신축 예정 동 도형이 아니다.
