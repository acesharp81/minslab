- 상태: 2026-10-09 · 기획서 [결정 10](상황판-기획서.md)의 구현 설계. **결정**은 사용자가 정한 것, **제안**은 구현하며 확인할 것입니다.
- 짝 문서: [상황판-기획서.md](상황판-기획서.md)(무엇을·왜), [상황판-스펙.md](상황판-스펙.md)(계약, 8절 Next.js 이식 설계를 이 문서가 구체화·일부 대체).
- 결정(2026-10-09): ① 상황판 본체는 **Next.js(App Router, TS)로 지금 전환**한다. ② 상황판→지도 연결은 `window.open` 팝업이 아니라 **같은 창의 화면 전환(`/map`)** 이다. 지도 안 단지 클릭 카드는 요약으로 두고 '사업 상세' 링크만 더한다. ③ 메뉴는 **사이드바**(상단 메뉴였던 스펙 8.1을 대체).
- **변경(2026-10-09, 사용자 지시)**: 좌측 사이드바를 없애고 **상단 메뉴 바(한 줄 PC 64px·모바일 48px, 글자 메뉴 9개, ≤900px 은 햄버거 하나로 접혀 펼침)** 로 바꿨고, **라이트 모드를 기본**으로 한다(다크=옛 남색 팔레트는 상단 바의 토글, 선택은 이 브라우저에 기억). 이 문서의 '사이드바'·'56px 아이콘 레일' 표현은 상단 바로 읽는다. 지도(`/map`)도 상단 바를 쓰지만 색은 아직 어두운 채로 두었다(지도 UI 전체의 라이트 전환은 지도 재작성 단계). 구현·결정 경위는 `docs/product/Tailwind-shadcn-전환.md` 의 '상단 바·라이트 모드'.

## 1. 메뉴와 화면

사이드바에는 1차 목적지만 둔다. 파생 상세(월·시도·시군구·사업·단계·기관)는 위젯과 표를 눌러 내려가고, 위쪽 빵부스러기로 올라오며, 부모 메뉴가 강조된다. 전국→사업은 클릭 3번(기획서 "선택 5번 이내").

| 경로 | 화면 | 사이드바 | 데이터(등급) |
|---|---|---|---|
| `/` | 종합상황판(시안 이식) | ① 종합상황판 | 수치는 SAMPLE 표지 유지. 월별 실적 흐름·원천 목록만 실데이터(A) |
| `/map` | 지도(M3) | ② 지도 | 구현됨. 쿼리 계약(스펙 2.1) 그대로 |
| `/projects` · `/project/{PRJ-…}` | 사업(현황표) · 사업 상세 | ③ 사업 | 레지스트리 77건, 6단계·규모·위치(A). 일정·신호는 `schedule` 0/77이라 없음(C) |
| `/area` · `/area/{시도2}` · `/area/{시군구5}` | 지역별 · 시도 · 시군구 | ④ 지역별 | 시도 월별 실적·시행주체별 호수(A), 지연율·6단계 분포(B: 전국 적재 전) |
| `/stage` · `/stage/{01~06}` | 단계별(병목) | ⑤ 단계별 | 사업 수는 A, 머문 기간·지연 호수는 B |
| `/agency` · `/agency/{lh\|gh\|sh\|local\|mnd}` | 기관별 | ⑥ 기관별 | 호수 A, 기관별 신호 B. 국방부는 수작업 입력 대기 |
| `/month/{YYYY-MM}` | 월 상세 | ① 강조 | 인허가·착공·준공·분양 호수(A), 예정 월은 LH 준공 예정 블록(A) |
| `/sources` | 데이터 원본 | ⑦ 데이터 원본 | 스키마 있음(스펙 9.3), 카탈로그 파일은 미구현 |
| `/reports` · `/my-area` | 보고자료 · 우리 동네 | ⑧ ⑨ | 준비 중 |

등급: A 지금 계산 가능 · B 원천은 있으나 적재 전 · C 원천 없음. 데이터가 없는 칸은 숨기지 않고 "샘플 / 적재 전 / 원천 없음" 표지를 붙인다.

## 2. 위젯 → 상세 화면

| 종합상황판 위젯 | 내려가는 화면 |
|---|---|
| 17개 시도 타일 | `/area/{시도2}` → 시군구 행 → `/area/{시군구5}` → 사업 행 → `/project/{id}` |
| 병목 단계 막대 | `/stage/{01~06}` |
| 기관별 진행 | `/agency/{id}` |
| 월별 공급 파동의 월 | `/month/{YYYY-MM}` |
| 모든 숫자의 '출처' | `/sources` |
| 사업 상세의 '지도에서 보기' · 시군구의 '이 동네 지도' | `/map?project=PRJ-…` · `/map?sgg=` (같은 창) |

이동 식별자는 새로 만들지 않는다: 지역은 AreaRef 코드, 사업은 `PRJ-{시군구5}-{일련4}`(폐기된 id도 열린다).

## 3. 지도 화면 규칙

- (변경 전 결정) 사이드바는 지도에서 56px 아이콘 레일로 접어 둔다 → 지금은 지도에서도 상단 메뉴 바다. 지도의 '공급 현황' 패널은 지도 화면 안의 보조 패널로 유지한다.
- M3 머리 줄의 로고는 상단 메뉴 바가 대신하므로 숨기고, 지역 선택·6단계 필터·보기 전환은 그대로 둔다.
- 900px 이하는 상단 햄버거 드로어(지도 하단 시트와 겹치지 않게).
- 지도의 `history.replaceState`는 기록을 쌓지 않아 브라우저 뒤로가기가 그대로 동작한다.

## 4. 기존 링크 호환

`/`에 지도용 쿼리(`region` `code` `sgg` `bjd` `pnu` `project` `at` `block` `mode` 등)가 있으면 `/map?…`로 리다이렉트한다(기획서 M6 "기존 `?region=` 링크 유지"). 쿼리 이름·우선순위는 스펙 2.1 그대로다.

## 5. Next.js 전환 방식 (제안)

| 걸림돌 | 해법 |
|---|---|
| `app.js`는 마운트·해제 개념이 없는 최상위 스크립트(전역 상수·`location.assign` 재로드)라 클라이언트 라우팅으로 들어갔다 나오면 두 번 실행된다 | **루트 레이아웃을 둘로 나눈다**: `app/(dashboard)/layout.tsx`(사이드바+본문)와 `app/(map)/map/layout.tsx`(접힌 레일+지도). Next.js는 루트 레이아웃이 다른 경로 사이를 전체 문서 로드로 이동하므로 지도에 들어갈 때·나올 때 새 문서가 되고, `app.js`는 문서당 한 번만 돈다 |
| 지도 마크업과 스크립트 순서(기존 `index.html`) | 지도 섬: 서버 컴포넌트가 `index.html`의 `<div class="app">` 마크업을 그대로 넣고, 클라이언트 컴포넌트가 기존 로더와 같은 순서로 스크립트를 불러온다. `app.js`·시험은 건드리지 않는다. 모듈화(`lib/map/*.ts`)는 그 뒤 별도 단계 |
| API 7개는 Node `(req, res)` 핸들러(CJS)이고 루트 `api/`는 Next.js와 공존이 공식 확인되지 않음(공식 경로는 `app/api/**/route.ts`) | 핸들러는 `req.method`·`req.url`·`res.statusCode/setHeader/end`만 쓴다 → 약 25줄 어댑터가 `Request`를 req/res 모양으로 바꿔 부른다. 핸들러·`lib/*.js`·시험은 그대로, 루트 `api/`는 깊이가 같은 `handlers/`로 옮기고(핸들러의 `../../lib/…` 상대 `require`가 그대로 맞는다) 시험·스크립트의 파일 경로만 고쳤다 |
| 번들러(Turbopack)가 `__dirname`을 가짜 경로 `"/ROOT/lib"`로 바꿔 컴파일해 레지스트리·`infra.json`·지역 번들을 못 찾는다(`next start`에서 `?project=`가 `unknown-project`, `/api/bus`가 `no-live-routes`로 답해 발견) | `lib/root.js`의 `ROOT`: 일반 Node는 이 파일 위치로 계산한 실제 루트, 번들 안은 `process.cwd()`. 데이터 경로에 `__dirname`을 쓰지 않는다(`tests/js/root.test.cjs`가 막음). 런타임 경로를 읽는 `fs` 호출에는 `/*turbopackIgnore: true*/`를 달아(필요한 파일은 `outputFileTracingIncludes`가 명시) 프로젝트 전체 추적 경고를 없앴다 |
| `public/`은 지금 `scripts/build.js`의 산출물(gitignore)인데 Next.js도 `public/`을 정적 자산에 쓴다 | `prebuild`·`predev`에서 `build.js`가 `assets/`·`regions/`·`config.js`(V-World 키)를 `public/`에 채운다. 번들 제외·키 처리 규칙과 `build.test.cjs`는 그대로 |
| `vercel.json`의 함수 설정·헤더 | `functions.includeFiles/excludeFiles` → `outputFileTracingIncludes/Excludes`, `maxDuration` → 경로별 `export const maxDuration`, `headers` → `next.config`의 `headers()`(스펙 2.3 그대로). 함수 지역 `icn1`은 `vercel.json`의 `regions` 유지 |

배포: `vercel.json`의 `framework`를 `nextjs`로 바꾸고 `buildCommand: npm run build`·`outputDirectory: .next`를 **명시**한다(프로젝트 설정에 옛 파이프라인 값 `node scripts/build.js`·`public`이 남아 있어 비워 두면 그 값이 되살아나 배포가 `routes-manifest.json`을 못 찾고 실패했다: 2026-10-09 첫 미리보기). 배포 절차(`git archive` 사본 + `vercel --prod`)는 그대로. 처음에는 **미리보기 배포로** `/api/v1/*`·지도·보안 헤더를 확인한 뒤 운영에 올린다(운영 배포는 요청할 때만).

## 7. 열린 점

- 종합상황판 시안의 수치는 전부 SAMPLE이다. `/`는 시안 전체를 SAMPLE 표지로 이식하고(기획서 결정 11), 실데이터 위젯은 월별 실적·시행주체별·향후 12개월 LH 준공 예정·원천 수 네 가지다. 시안 파일 자체는 저장소에 올리지 않았고, 시안의 계산은 `lib/board/sample.ts`로 옮겨 원본 실행 기준값(`tests/fixtures/board-sample-golden.json`)으로 고정했다.
- 건축HUB 관리번호(`refs`)를 공개 화면에 보여도 되는지는 기획서 Q4가 미결이라, 사업 상세의 근거는 출처·기준일까지만 먼저 둔다.
- 시안은 Google Fonts를 쓰고 현 앱은 웹폰트가 없다(시스템 글꼴). 셸은 시스템 글꼴을 유지한다(제안).
- 지도 카드의 '사업 상세' 링크는 지도 안 단지에 사업 id가 있을 때만 보인다(번들 단지와 레지스트리의 연결 범위에 따름).
- TypeScript는 5.9.3으로 고정했다(npm 최신 7.x는 Next.js 16과 맞는지 시험하지 않았다). 설치본 Next.js 문서(`node_modules/next/dist/docs`)가 정본이다: 외부 요약 자료에 `proxy.ts` 설정 이름이 `proxyConfig`로 적혀 있었으나 설치본은 `config`다.
