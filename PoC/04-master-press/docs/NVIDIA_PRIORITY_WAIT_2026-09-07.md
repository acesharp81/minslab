# NVIDIA 우선 처리 5초 대기 확인 및 보완 — 2026-09-07

## 확인

`CASE_MODEL1_PRIORITY_SECONDS=5`이며 OpenAI는 NVIDIA 제공자를 사용할 수 있을 때만 신규 케이스 큐에 5초 우선권을 준다. 두 프로세스가 모두 유휴인지 직접 검사하는 구조가 아니라 제공자 가용성과 큐 등록 시각을 검사한다. NVIDIA 사용 불가 시에는 추가 대기 없이 OpenAI가 처리할 수 있다. 유휴 worker는 3초마다 확인하므로 실제 시작 시각은 정확히 5초에 고정되지 않는다.

운영 이력에서 NVIDIA가 신규 기사 큐를 등록 2초 후(08:12:49→08:12:51), 4초 후(08:23:40→08:23:44)에 처리한 예를 확인했다. 하지만 전체 큐에서 5초 이상 된 작업 하나만 있으면 OpenAI가 대기를 통과하고, 이후 묶음 크기 우선 선택에서 더 새로운 기사를 가져갈 수 있었다. 별도 합성 테스트 DB에서 오래된 2케이스와 새 3케이스를 만들어 새 묶음을 생성 0.3초 뒤 claim하는 현상을 재현했다. 실제 이력에도 OpenAI의 등록 후 2초 claim 사례가 있었다.

## 보완

- 실제 article bundle을 선택하는 SQLite `BEGIN IMMEDIATE` 트랜잭션 안에 최소 대기시간 검사를 추가했다.
- NVIDIA 사용 가능 시 OpenAI는 선택 대상 묶음의 `MIN(queued_at)`가 5초 이상 된 경우에만 가져간다.
- 다른 기사에 속한 오래된 작업이 신규 기사 우선권을 해제할 수 없다.
- NVIDIA 사용 불가 시 추가 대기시간은 0이다. NVIDIA 자신과 단건 worker에도 이 대기를 적용하지 않는다.
- 기존 기사 단위 제공자 유지, Nemotron 10케이스 상한, API 동시성은 유지한다.

- 새 묶음이 더 커도 오래된 묶음만 선택하는 회귀 테스트를 추가했다.
- 4초 대기 / 5초 처리 가능 경계, NVIDIA 사용 불가 시 OpenAI 즉시 경로를 검증했다.
- Python 전체 회귀 192개 및 diff 검사를 통과했다.
- 08:32:45 KST OpenAI 케이스 worker만 재기동했다. 해당 worker와 웹·NVIDIA·단건·수집 worker의 active 상태를 확인했다.
- 직후 운영에는 신규 대기 작업이 없어 수정 후 실제 신규 기사 claim 시각은 아직 관측하지 못했다. 위 시간 경계 검증은 테스트 DB에서 수행했다.
