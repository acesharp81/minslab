## 1. 목적과 증빙 범위

기존 행정안전위원회·예산결산특별위원회·법제사법위원회 외 위원회도 **애플리케이션 코드 수정·재배포·재시작 없이 위원회 식별자 설정을 추가하여 수집 범위를 확장**할 수 있는지 검증한다.

기존 구현에는 수집 어댑터, 부분 요약, 최종 보고서 작업, 보고서 조회에 각각 위원회 제한이 있었다. 이를 공통 설정으로 보완하는 최초 개발·배포와, 배포 완료 후 실제 위원회를 설정만으로 등록하는 행위를 구분한다. 최초 개발에 코드 변경이 없었다고 주장하지 않는다.

실방송 이전에 입증할 수 있는 것은 설정 반영·대상 제한·처리 경로·화면 구분이다. 실제 발언 수집 건수, 실제 모델 응답 품질, 최종 보고서 완료는 방송 이후 결과로 확정한다.

## 3. 적용 구조

### 3.1 운영 코드와 대상 설정 분리

- 공통 모듈: `backend/app/domain/assembly_expansion.py`
- 운영 설정: `data/config/assembly_expansion.json`
- 설정 이력: `data/config/assembly_expansion.audit.jsonl`
- 등록 도구: `scripts/manage_assembly_expansion.py`

운영 프로세스는 설정을 매번 읽으므로 등록·비활성화 시 재시작이 필요 없다. 원자적 파일 교체를 사용하며 스키마·시간대·최대 허용 기간·중복 회의 식별자를 검증한다. 잘못된 설정이면 추가 수집을 거부하고 기존 기본 위원회는 계속 처리한다.

다음 명령은 위원회 식별자와 날짜를 받아 공식 원천에서 채널·회의 식별자·위원회명을 자동 확인한다. 같은 날 방송 후보가 여러 개이면 자동 선택을 거부하고 정확한 `--meeting-id` 지정을 요구한다.

```bash
python scripts/manage_assembly_expansion.py register \
  --committee-id 9700513 --date 2026-11-11
```

재실행하여 같은 회의를 덮어쓰거나 재활성화하지 않는다. 조회는 `show`, 저장 없는 사전 확인은 `register ... --dry-run`으로 수행한다.

### 3.2 일회성 제한과 수집 종료

- 위원회 식별자·채널·회의 식별자 세 값이 정확히 일치할 때만 추가 수집한다.
- 재생 응답의 회의 식별자·채널도 재검증한다. 다른 방송으로 응답이 바뀌면 수집하지 않는다.
- 정회는 회의 종료로 간주하지 않는다. 같은 식별자의 속개는 허용 기간 내 계속 처리한다.
- 정상 종료 시 기존 생명주기 규칙으로 수집이 끝난다. 새 회의 식별자는 허용하지 않는다.
- 허용 기간 종료 또는 `enabled=false` 시 자막·음성 수집의 신규 작업과 진행 중 임대 갱신을 차단한다. 진행 중 연결은 다음 점검에서 멈춘다.
- 허용 기간 종료는 회의 종료를 의미하지 않는다. 실제 회의 생명주기는 공식 관측과 기존 판정 규칙을 유지한다.
- 허용 기간이 끝나도 기존 자료의 부분 요약·최종 정리·품질 검증·결과 조회는 이어진다.

수동 비활성화:

```bash
python scripts/manage_assembly_expansion.py disable \
  --meeting-id DCM000059224390901
```

설정 행을 삭제하지 않고 비활성화한다. 종료된 테스트의 식별·결과 조회·미완료 작업에 필요한 기록이기 때문이다. 기간 만료는 파일의 `enabled` 값을 직접 바꾸지 않아도 수집 허용 판정에서 자동 차단되며 상태는 `EXPIRED`로 표시한다.

### 3.3 기존 처리 흐름 재사용

공식 자막 수집과 기존 음성 대체 경로, 부분 요약, 실시간 주제 분류, 회의 보고서, 세부 쟁점 구조화·검증·온톨로지 검토 및 최종화에 동일 회의 허용 정보를 적용했다. 모델 우선순위·예산·재시도 정책을 새로 만들지 않고 운영 정책을 그대로 사용한다.

이번 증빙의 완료 범위는 실시간 자료에 기반한 비공식 회의 보고서이다. 이후 공개될 공식 회의록의 수집·대조를 이번 일회성 시험에서 완료했다고 주장하지 않는다.

### 3.4 일반 보고서와 테스트 보고서 구분

- 문체위 보고서는 기존 상단 회의 보고서 목록에서 다른 위원회와 함께 날짜순으로 표시한다. 별도 테스트 공간은 두지 않는다.
- DB 조회는 기존 일반 자료와 테스트 자료를 구분하고, 화면에서 방송 ID로 중복을 제거해 한 목록으로 합친다. 일반 목록의 추가 로딩 조건을 유지한다.
- 생방송·보고서 카드와 보고서 본문 상단에 **확장성 실험 · 1회성 수집** 태그를 표시한다. 모바일에서 제목 말줄임에 가려지지 않도록 본문 라벨 영역에 배치한다. 인쇄/PDF 및 보고서 MD에도 같은 문구를 표시한다. 전체 요약본 MD는 기존 **확장성 테스트용** 출처 표시를 유지한다.
- 주제별 검색·정책 인사이트의 기본 위원회 범위는 유지한다. 아직 종료되지 않은 회의를 완료 보고서로 미리 표시하지 않는다.
- 원본 방송 제목·출처·원문을 테스트용 가짜 출처로 덮어쓰지 않는다. 테스트 여부는 별도 표시 정보다.

### 운영 실검증에서 발견해 보완한 사항

1. 요약·최종 보고서 워커에 공유 설정 디렉터리 마운트가 없었다. 두 워커에 `data/config:/app/data/config:ro`를 추가하고 운영 컨테이너뿐 아니라 Compose·재배포 스크립트에도 반영했다. 이후 6개 서비스 모두 같은 회의 설정을 읽는지 확인한다.
2. 기존 자막 상태 갱신의 `FOR UPDATE`가 관심주제 처리의 참조 잠금과 충돌해 모니터 갱신을 지연시켰다. 키를 변경하지 않는 상태 갱신과 수집 임대 획득에 맞게 `FOR NO KEY UPDATE`로 조정하고 격리 DB 동시성 시험을 추가했다. 임대 획득의 `SKIP LOCKED`는 유지하여 복수 워커의 중복 획득을 방지한다. 기존 배포 이미지에서도 같은 과도한 잠금이 있었음을 확인했다.
3. 위 보완은 사전 기능 준비 단계에 포함한다. 준비 완료 후 등록 전후 증빙을 다시 수집하여, 그 이후의 설정 등록에는 코드·이미지·컨테이너 변경이 없음을 별도로 비교한다. 이전 사전 등록 이력은 감사 로그에 보존한다.

테스트는 모의 응답·격리 테이블을 사용했으며 운영 회의 원문을 추가 모델 시험에 전송하지 않았다. 운영 보고서 재생성이나 원본 수정은 수행하지 않았다.

## 5. 코드 변경 없는 확장 증빙 방법

1. 공통 기능 배포를 완료하고 배포 이미지·파일 SHA-256을 확정한다.
2. 대상 등록 전 `collect_assembly_expansion_evidence.py --phase before-registration` 결과를 저장한다.
3. 위원회 식별자 등록 명령을 실행한다. 이 단계는 설정 파일과 설정 이력만 변경한다.
4. 등록 후 `--phase after-registration` 결과를 저장한다.
5. 두 결과의 컨테이너 ID·시작 시각·이미지 ID·파일 SHA-256이 동일한지 대조한다.
6. 실방송 후 같은 방식으로 실수집·보고서 생성 결과를 보완한다.

```bash
python scripts/collect_assembly_expansion_evidence.py --phase after-broadcast
```

이 수집기는 읽기 전용으로 설정·방송 상태·테스트 보고서 목록·실행 이미지 정보를 저장한다. 작업 워커나 모델을 호출하지 않는다. 실행 이미지 검증에는 해당 호스트의 Docker 조회 권한이 필요하다.

## 6. 제출용 문구와 실방송 결과 작성란

### 사전 구현·검증 성과

> 국정ON의 위원회별 수집 대상을 코드와 분리하고, 공식 위원회 식별자로 대상 회의를 등록하는 설정 기반 확장 기능을 구현했다. 수집·요약·최종 보고서 처리 흐름을 재사용하며, 회의 식별자와 허용 기간을 통한 일회성 제한 및 일반 보고서와 구분되는 테스트 보고서 제공 기능을 적용했다. 사전 자동 시험과 격리 DB 검증을 통해 대상 제한·수집 종료·후속 처리·결과 분리를 확인했다.

### 실방송 후 확정할 결과

| 항목 | 결과 |
|---|---|
| 실제 개회·최초 감지 시각 | 방송 후 기록 |
| 첫 발언 저장 시각 | 방송 후 기록 |
| 실제 수집 발언·원문 건수 | 방송 후 기록 |
| 부분 요약·주제·과제 건수 | 방송 후 기록 |
| 수집 누락·오류·재시도 | 방송 후 기록 |
| 최종 보고서 완료 상태·시각 | 방송 후 기록 |

| 수집 비활성화와 결과 조회 유지 | 종료 후 기록 |

실제 수행이 완료된 경우에만 다음 문구를 사용한다.

> 동일 배포 버전에서 위원회 식별자 설정만 추가하여 신규 위원회 1개 회의의 생방송 수집·부분 요약·최종 보고서 생성을 완료했다. 수행 중 코드 수정·재배포 없이 기존 처리 흐름을 재사용했으며, 시연 종료 후 신규 수집을 차단하고 결과를 별도 보존했다.

실제 방송 지연·취소·원천 장애 또는 모델 예산 부족이 발생하면 그 상태를 그대로 기록한다. 방송 이전에 실수집·보고서 생성 성공으로 기재하지 않는다.
