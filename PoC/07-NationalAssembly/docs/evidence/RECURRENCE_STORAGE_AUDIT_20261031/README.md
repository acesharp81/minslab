# 대주제 과분할 재발 방지 및 호출·저장 감사 — 2026-10-31

## 범위와 방법

- 국정ON(PoC7) 운영 PostgreSQL 읽기 전용 조회. 호출 이력은 최근 7일(10월 24~31일), 저장량은 보관된 전체 데이터 기준이다.
- 호출 통계는 `meeting_topic_structure_batches`에 기록된 구조화·통합·검증·세부 요약 범위다. 실시간 부분요약·음성·주제별 보고서를 합한 서비스 전체 과금 통계가 아니다.
- 외부 모델을 새로 호출하거나 원문을 재전송하지 않았다. 기존 보고서·이전 버전·원문은 삭제하지 않았다.
- API 응답 ID가 없는 기록을 모두 외부 호출로 세지 않는다. 한도/입력 크기 사전 차단, 검증된 부분 결과 복구, 내부 병합 기록을 구분했다.

## 1. 대주제 과분할의 실제 원인

예결위 보고서 `8809d5e4-13bc-41dd-a9b4-291afca60c0c`의 원본 쟁점 122개를 48개 단위의 3개 파트로 GPT-5.4에 보냈다. 각 파트는 첫 시도에 성공했으나 부모 제목이 각각 25/18/17종이었다. 전체 통합은 새 모델 호출 없이 assignments를 합치는 방식이어서 최종 부모 제목이 47종으로 남았다. 화면 단계는 parent 문자열마다 별도 대주제를 만들었다. 최종 세부 쟁점은 기존 안전 검증을 거쳐 120개다.

지난 수정의 정책별 읽기 묶음은 정상 적용됐으나 지시 보완은 구형 `consolidation_prompt`에만 들어갔다. 실제 워커의 경로는 48개 이하면 `compact_consolidation.prompt`, 그보다 크면 `partitioned_consolidation.prompt`였다. 통합의 성공 기준은 전체 ID 포함/유효성 위주였고 분할 사이의 부모 제목 일관성은 강제되지 않았다. 모델 가용량 부족이나 이 회의 통합 호출 실패가 원인은 아니다.

### 이번 적용

1. 실제 단일/분할 요청에 동일한 전체 회의 `policy_parent_catalogue`를 전달한다. 검증된 정책 별칭만 정규화하며 다른 기금과 미등록 대상은 구분한다.
2. JSON Schema에서 parent를 공통 목록의 enum으로 제한한다. 분할마다 다른 새 표현을 만드는 경로를 차단한다. 분할 스키마는 `$defs` 참조를 써 목록을 쟁점마다 중복 전송하지 않는다.
3. parent 공유와 canonical issue 통합을 구분한다. 서로 다른 논점은 같은 parent 아래 별도 canonical ID로 보존한다.
4. 앞서 적용한 읽기 그룹화와 ID·과제·근거 보존 검증을 유지한다. 완료된 배치의 버전/입력을 강제로 바꾸지 않아 기존 요약을 전량 재호출하지 않는다.
5. 동일한 brief JSON을 다시 저장하면 UPDATE와 이력 저장을 생략한다. 행 잠금 안에서 비교하여 변경이 있을 때의 이전 원문 보관은 유지한다.

범위 한계: 공통 목록은 확인된 정책 별칭과 원래 부모 제목으로 만든다. 아직 등록되지 않은 정책의 의미상 유사 제목까지 무조건 같은 것으로 취급하지 않는다. 숫자로 대주제 개수를 강제하지 않는다. 향후 실제 새 회의에서 추가 과분할이 확인되면 근거를 확인하여 별칭/범위를 확장해야 한다.

### 추가 개선 우선순위

- **입력 크기 초과는 동일 입력·동일 모델 재시도 대상에서 제외**: 분할 또는 다른 허용 모델로 전환. 사전 차단을 품질 실패/호출 실적으로 세지 않는다.
- **한도·속도 제한은 provider별 다음 허용 시각까지 대기**: 고정 5/30분 재시도보다 실제 reset/Retry-After와 입력 fingerprint를 조합한다. 새 모델/설정 변경 시에는 다시 판단할 수 있어야 한다.
- **숫자·날짜 검증 실패의 오탐 점검**: 원문 숫자 표기와 단위 변환을 비교해 검증을 통과한 필드는 재사용하고 실패한 필드만 교정한다. 현재 부분 복구(527건)는 유지한다. 검증 자체를 완화해 오류를 숨기지 않는다.
- **일일 자동 감사**: 같은 입력 성공 후 재호출, 재시도 원인별 건수, 응답 ID 기준 실제 호출, 호출 전 차단을 별도로 집계한다. 이 감사의 정기 스케줄은 아직 추가하지 않았다.

공식 원문 워커의 `semantic_content_hash`와 저장소 `semantic_cache_hit` 경로는 현재 운영 이미지에도 존재한다. 최근 7일 새 공식 문서는 5개였으며, 조사한 대량 중복은 주로 기존 보관 데이터다. 이미 적용된 중복 억제와 과거 데이터 정리를 구분해야 한다.

### 저장 개선 순서

1. **진행 상태 분리**: 현재 finalization.updated_at은 재처리 순서에도 사용된다. 단순히 갱신을 중단하면 회의 간 처리 공정성을 해칠 수 있으므로 별도 상태 테이블/기존 progress 구조에 heartbeat와 단계 정보를 이관한다. 본문 버전은 의미 내용이 바뀔 때만 생성한다.
2. **요청 스냅샷 정규화**: 회의/분석 버전/요청 해시를 키로 불변 원문을 저장하고 재시도는 provider·model·오류·usage·시간만 추가한다. 기존 배치 요청을 복원하는 호환 조회를 제공한다.
3. **과거 공식 문서 중복 정리**: 화자·순서·본문·안건·공개단계·parser와 source_locator까지 비교하고, 발언 ID를 참조하는 대조·주석·보고서 링크를 열거한다. 백업 → 대표 버전/별칭 참조 표 → 읽기 검증 → 중복 정리 순으로 진행한다. 이번에는 삭제하거나 FK를 변경하지 않았다.
4. **원본 파일 아카이브**: 파일명/해시/자료 상태/원본 바이트를 보존하는 압축 묶음과 조회 인덱스부터 준비한다. 일정 기간 삭제 같은 임의 보존 정책은 도입하지 않는다.

호스트 전체 Docker 현황도 이미지 1,171개·컨테이너 684개(실행 22개)로 정리 후보가 많다. 여러 서비스가 공유하므로 PoC7 데이터와 구분해야 한다. Docker가 반환한 이미지 reclaimable 값은 음수여서 절감 용량 근거로 사용하지 않았다. 현재 이미지·롤백본·사용 볼륨을 확인하기 전 일괄 prune은 수행하지 않았다.

## 4. 검증

- 실제 단일/분할 통합 경로·대주제 보존·원문 구조·보고서 표시 테스트 71개 통과.
- 운영 DB와 분리된 TEMP 테이블에서 동일 내용 저장 10회에 대해 행 버전(CTID) 추가 변경 없음, 실제 변경 1회에 대해 이전 brief 이력 1개 보존 확인.
- 원문/모델 결과 삭제 및 추가 외부 모델 호출 없음. 신규 회의 모델 결과의 실제 품질은 다음 처리 이력에서도 확인해야 한다.
