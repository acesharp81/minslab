# 세부요약 재시도 대기 원인과 재개 (2026-11-05)

## 원인

07:15 KST 조회에서 법사위 제11차 135개·예결위 제03차 520개 쟁점이 모두 세부요약 0건 상태였다. 발언 분석·통합·주제 검증·정책 분류는 완료돼 있었다. 예결위 제04차가 LIVE로 남아 있어 세부요약의 전역 실시간 우선 조건이 모든 배치를 연기했다. 이 회의는 마지막 발언/자막이 00:15:17 KST, 마지막 방송 관측이 00:14:56 KST였고, 현재 공식 목록 모니터는 live_count=0이었다. 캡처 lease·updated_at 갱신은 계속됐지만 새 발언은 없었다.

모델 잔량도 매우 적었으나, 당시 세부요약은 모델 호출 전에 LIVE_OR_RECENT_MEETING으로 중단돼 있었다. 현재 재개된 요청은 기존 무료 Mini→OpenRouter→월 Luna/Mini 경로에서 예산 예약과 원문 검증을 그대로 사용한다. 한도 부족으로 거절된 요청과 실제 내용 검증 오류를 구분한다.

## 보완

- 우선권은 LIVE 행의 최근 15분 방송 관측·발언 수신·신규 발견으로 판단한다. 캡처 lease·일반 updated_at은 사용하지 않는다.
- 정회·생명주기를 이 조건으로 변경하지 않는다. 실제 새 방송과 최근 종료 15분·편성 임박 보호는 유지한다.
- 모든 배치가 실시간 우선으로 보류되면 LIVE_DEFERRED·reason을 상위에 보존하고 최종 정리 wait_reason에 남긴다.
- 기존 결과·근거·배치 ID를 지우지 않고 미완료 쟁점만 재개한다. 모델 선택·월 소한도·전체 예산은 변경하지 않았다.

## 확인

격리 PostgreSQL 활동 신선도 검사와 큐·세부요약·최종 정리 회귀 검사 21건 통과. 실제 새 발언·최근 관측·신규 발견 각각이 우선 대기를 발생시키고, 7시간 활동이 없는 LIVE는 차단하지 않으며 LIVE 상태 자체는 유지되는 것을 확인했다.

회의 정리 워커에 `poc07-narrative-priority:20261105`를 적용했다. 배포 후 background_defer_reason은 null로 바뀌었고, 실제 법사위 세부요약이 0/135→16/135로 증가했다. `after.json`은 후속 조회 시점의 저장 완료 수·잔여 배치와 상태를 기록한다. 이는 보고서 전체 완료를 의미하지 않는다. 운영에서 일일 한도를 변경하거나 전체 보고서를 재생성하지 않았다.

## 재발 방지 재점검

추가 점검은 외부 모델 호출 없이 진행했다. 운영 워커 3개 파일의 SHA-256이 저장소 소스와 모두 일치하고 컨테이너는 재시작 0회였다. Dockerfile의 app COPY와 compose의 backend build 경로에 수정 소스가 포함돼 다음 소스 빌드에도 반영된다.

활동 없음·최근 관측·새 발언·신규 발견·15분 경계 및 만료·모든 활동 시각 없음·최근 종료·편성 임박·09:00 한도 재개·모델 속도 제한 대기를 검사했다. 저장 이력을 읽은 뒤 같은 작업을 다시 실행해 완료된 요약에 추가 모델 호출과 저장이 없는지도 확인했다. 관련 검사 30건 통과.

`recurrence-check.json`의 07:33 KST 운영 이력 조사에서 법사위 118/135, 예결위 69/520으로 증가했다. 실제 사용량이 남은 세부요약 호출은 각각 15회·12회였고, 그 이전에 검증·저장 완료된 같은 fingerprint를 재전송한 경우는 0건이었다. 이 수치는 해당 구조화 revision에 대한 조사이며 보고서 전체 완료를 의미하지 않는다.

게이트웨이 무료 한도에 따른 429 이력은 대체 모델로 넘어가 처리되고 있다. 이번 점검은 모든 모델 오류가 사라졌다는 의미가 아니라, 오래된 LIVE 표시가 무기한 작업을 막는 원인과 완료 요약 중복 호출 방지를 확인한 것이다.
