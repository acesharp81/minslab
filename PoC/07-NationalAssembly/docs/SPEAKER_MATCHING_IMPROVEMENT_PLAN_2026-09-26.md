# 공식 회의록 화자 매칭 보완안 — 2026-09-26

## 확인된 상태

- 공식 문서가 연결된 국회 보고서 19건의 공식 발언 30,601건은 모두 화자 이름이 있다.
- LIVE/STT 기반 보고서 화자 요지 955개 중 863개가 공식 발언 ID에 연결됐고 92개는 미확인이다. 미확인 92개 중 34개는 근거 자막이 30자 미만이고, 현재 엄격한 자막 매칭에서 88개는 확정 후보가 없으며 4개는 한 자막 묶음에 복수 공식 화자가 연결된다.
- 연결된 863개의 방법은 요지·자막 유사도 563개, 자막 묶음 내용 46개, 짧은 구절 3개, 검토 보정 1개, 이전 근거 유지 250개다. 발언 ID가 연결됐다는 수치만으로 요지 내용까지 검증됐다고 보지 않는다.
- 자막의 공식 대조 상세 조회는 방송별 전체 과거 대조 기록 중 최신 행을 고른다. 현재 공식 문서 ID로 제한하지 않아 운영 자료 19건에서 선택된 대조 행 9,272개가 현재 문서가 아닌 과거 문서 버전을 가리켰다. 이는 9,272개 이름이 틀렸다는 뜻은 아니지만 원문 근거와 대조율을 신뢰할 수 없게 한다.
- 공식 대조본의 화자 요지는 공식 발언을 기준으로 새로 만든 것이 아니라 LIVE/STT 초안 요지에 이름을 투영한 것이다. 초안 요지의 내용 자체가 공식 발언과 어긋난 사례가 있다.

## 1. 현재 문서 기준 조회와 대조율 수정 (우선)

- `broadcast_reconciliation_details`에 현재 `official_document_id`를 필수로 전달하고, 현재 문서의 `MATCHED` 발언만 반환한다. 현재 문서에 매칭이 없으면 과거 이름을 재사용하지 않는다.
- 종료 자막 API와 보고서 근거 API가 보고서 API와 동일한 현재 문서 선택 함수를 사용한다. `/brief/evidence`도 `latest_for_brief_document`로 읽는다.
- `matched_segment_count`는 현재 문서에 연결된 최신 final 자막 revision만 세어 다시 계산한다. 이력 대조 행은 감사 목적으로 보존한다.
- 변경 전후 19건의 현재 문서 ID·대조 행·대조율을 비교하고, API가 다른 문서의 발언 ID를 반환하는 사례가 0건인지 확인한다. 조회 시간과 메모리 사용량을 비교해 필요한 경우 현재 문서 조회에 맞는 인덱스를 추가한다.

## 2. 화자 연결과 요지 검증 분리

- 먼저 자막 조각을 공식 발언 **ID**에 연결하고, 그 공식 발언의 화자명을 가져온다. 이름이 문장에 언급됐다는 이유로 발언자로 사용하지 않는다.
- 현재 9글자 연속 일치로 놓치는 ASR 차이는 짧은 글자 조각 후보 검색으로 보완하되, 주변의 고신뢰 발언 순서·위원회 안건·시간대를 함께 사용한다. 후보 검색 점수만으로 이름을 확정하지 않는다.
- 원본 화자 코드가 같아도 최대 5분 동안 이어 붙이는 자막 묶음은 공식 화자 경계에서 분리한다. 현재 대조 테이블은 자막 revision 단위여서 하나의 revision 안에 화자 둘이 있으면 표현할 수 없으므로, 자막 조각 또는 원문 구간별 대조 키를 추가한다. 복수 화자의 발언을 하나의 요지로 합친 경우 분할하거나 복수 발언 근거로 표시한다.
- 화자 연결 여부와 요지 내용의 공식 근거 일치 여부를 별도 상태로 기록한다. 숫자·부정·질문/답변·기관·행위가 충돌하면 이름만 붙이지 않고 요지를 재작성 또는 검토 대기로 보낸다.
- 방송 전체 화자 코드에 적용되는 수동 이름 덮어쓰기는 시간 구간·자막 조각 단위의 검토 기록으로 바꾼다. 검토 기록에는 공식 발언 ID, 문서 버전, 원문 해시, 검토자와 사유를 남긴다.

## 3. 공식 문서 기반 보고서

- 공식 문서가 게시되면 화자별 본문은 `OfficialTranscriptUtterance`의 발언 ID·이름·원문을 기준으로 만든다. LIVE/STT 보고서는 별도 비교 보기로 보존한다.
- 공식 발언에 없는 LIVE 요지는 공식 화자 섹션에 섞지 않고 “초안 전용/공식 미확인”으로 표시한다. 공식 발언에 있는 내용인데 초안 요지가 틀린 경우 공식 원문을 근거로 다시 작성한다.
- 기존 미확인 92개를 직접 검토해 **일치/복수 화자/요지 오류/공식 미수록**으로 분류하고, 일치가 확인된 항목만 새 파생 버전에 반영한다. 이미 이름이 붙은 863개도 방법·위원회·문서 단계별 표본을 검증해 오귀속을 찾는다.

## 4. 재발 방지와 배포 기준

- 파생 결과의 키는 `brief_id + official_document_id + official content hash + matcher version`으로 둔다. 새 공식 문서 버전이나 매칭 규칙 변경 때만 한 번 재처리하고, 조회·몇 분 간격 점검은 저장 결과만 읽는다.
- 상태를 **공식 원문 수집**, **자막 연결**, **요지 검증**, **화자 확정**으로 나누고 각각의 확인/검토 필요 수를 운영 화면에 표시한다. `READY` 하나로 전체 완료를 뜻하지 않게 한다.
- 배포 전 19건을 쓰기 없는 방식으로 재처리해 새로 확인된 이름, 제거된 이름, 문장 수정, 문서 버전 불일치를 비교한다. 현재 문서 외 발언 ID 0건, 근거 없는 이름 0건, 검토 표본의 잘못된 귀속 0건을 배포 기준으로 삼는다. 기존 초안과 통합 이력은 보존한다.
