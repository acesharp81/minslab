# Architecture Decisions

## ADR-050 · 공식 대조는 완료 건 순회가 아닌 영속 상태 큐로 처리

- 상태: Accepted
- 결정일: 2026-09-04
- 배경: UUID순 `LIMIT 5`가 이미 완료된 회의를 계속 선택해 뒤 회의가 영구 대기했고, 회의 기준으로 먼저 수집한 공식 본문은 나중에 생성된 LIVE publication과 연결되지 않았다. 또한 한 자료의 파싱 오류가 해당 실행의 후속 대조까지 중단했다.
- 결정: 최신 `(meeting_brief_id, official_document_id, integration_version)`에 READY 결과가 없을 때만 작업을 생성하고 PostgreSQL lease와 `FOR UPDATE SKIP LOCKED`로 선점한다. 대조 워커는 공식자료 수집과 분리해 15초마다 실행하며 오류는 작업별 지수 백오프로 재시도한다.
- 자료 연결: `meeting_id + conference_id`가 정확히 일치할 때만 publication 없는 보존 본문을 연결한다. 공식 링크·본문의 도착 순서와 동일 source version 충돌에 관계없이 비어 있는 `publication_id`를 채우되 원본과 이전 버전은 삭제하지 않는다.
- 비용·표시: 이미 READY인 동일 입력은 외부 LLM을 다시 호출하지 않는다. 화면은 게시·본문·큐·처리·재시도·완료 단계를 분리하고 현재 공식문서와 통합 결과의 문서 ID가 같을 때만 완료로 간주한다.

## ADR-049 · 국무회의 결과는 발화 주체와 자료 출처별로 분리한다

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 대통령실 브리핑의 관련 문단을 부처보고 요약에 덮어쓰고 같은 문단에서 지시 문구를 추출해 `부처보고 내용`과 `대통령 지시`가 사실상 같은 문장으로 반복됐다.
- 결정: 국무회의 보고 주제는 `부처 보고 내용`, `대통령 지시`, `부처 추가 발표`를 별도 필드와 시각 영역으로 유지한다. 대통령 문단과 부처 추가 발표는 부처 보고 내용을 덮어쓸 수 없다. 심의안건은 보고 주제와 분리한다.
- LIVE 결합: 회차·서울 날짜로 공식 자료와 연결된 LIVE 비공식 보고서에서 구체 주제명이 보수적으로 일치할 때만 부처 보고 내용으로 사용하고 PROVISIONAL임을 표시한다. 동점·저신뢰 또는 지시 문구와 유사도 0.72 이상이면 연결하지 않고 공식 결과문에서 확인된 보고 제목·담당 부처만 표시한다.
- 중복 억제: 같은 보고에 연결된 대통령 지시는 대상 부처와 함께 보고 카드 안에 표시한다. 연결되지 않은 공식 지시만 별도 목록에 두며 대통령실 브리핑 전체를 다시 나열하지 않는다.
- 비용·권위: 공식 원문, 기존 LIVE 보고서와 결정론 규칙만 사용하므로 추가 LLM 호출은 0회다. 공식 보고 제목·부처, 대통령 지시, 부처 발표는 OFFICIAL이고 LIVE 요약은 PROVISIONAL이다.

## ADR-048 · 기관 간 타임라인은 구체 주제의 보수적 연결만 허용

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 대분류와 일반 단어를 사용한 V3 규칙이 중대범죄수사청 시행령과 선거 특별검사법을 수사로, 국가재정운용계획과 경찰 인력 배분 발언을 예산으로 잘못 연결했다.
- 결정: 공개 타임라인에서 ADR-020의 대분류 연결을 사용하지 않는다. 정부 공식 안건과 국회 최신 회의 보고서의 구체 주제 사이에 제목 고유어가 직접 일치하거나, 소관기관이 같으면서 일반어를 제외한 복수 핵심어가 일치할 때만 후보를 만든다.
- 보수성: 수사·예산·재정·법률·법안·제도·정책·지원 같은 일반어는 단독 근거가 될 수 없다. 후보가 없으면 빈 타임라인을 정상 결과로 제공하며 LLM이나 제목 유사 생성으로 보완하지 않는다.
- 권위·비용: 연결은 SPECIFIC_REPORT_TOPIC_TOKEN_V1 · PROVISIONAL · DRAFT이며 인과관계가 아니다. 조회 LLM 호출은 0회다.

## ADR-047 · 쟁점 추세와 제도화 전환의 단위는 구체 회의 주제

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 법무·사법, 재정·예산 같은 대분류의 증감은 어느 정책이 반복되거나 제도화되는지 설명하지 못한다.
- 결정: 종료 회의별 최신 잠정 보고서 또는 공식 통합 보고서의 topics를 읽고, 구체 주제명·요약의 결정적 의미 토큰 유사도로 같은 쟁점을 묶는다. 간사 선임·개의·산회 같은 절차 주제는 제외하고 최근 14일과 이전 14일의 고유 방송 회의 수를 비교한다.
- 추세: 이전 14일 0회는 최근 횟수와 무관하게 신규다. 급증은 이전 1회 이상, 최근 3회 이상이며 2배 이상 증가한 경우로 제한한다. 양 기간에 모두 관측되되 급증 조건이 아니면 지속, 이전에만 있으면 최근 미관측이다.
- 단계: 연결 과제가 있으면 **후속 과제 도출**, 개정안·법률안·시행령 표현이 있으면 **보고서상 법안·제도개편**, 가결·의결·통과·시행 완료 표현이 있으면 **보고서상 의결·시행**, 공식 발언 근거 ID가 회의별 의안에 직접 연결되면 **공식 의안 직접 연결**로 표시한다. 직접 의안 연결 전의 상태는 발의 확인이나 실제 이행 완료를 뜻하지 않는다.
- 권위·비용: 주제와 과제는 PROVISIONAL 파생 읽기 모델이며, 공식 통합본이 있으면 이를 우선한다. 화면 조회와 재계산은 저장 자료만 사용해 LLM 0회다. 인과관계·영향·가결 가능성은 생성하거나 추정하지 않는다.

## ADR-046 · 공식화 변화는 최소 문구 패치와 설명 전용 LLM으로 제공

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 공백 단위 diff는 띄어쓰기 하나가 달라져도 이후 문장을 전부 교체한 것처럼 표시했고, 공식 문체로 전체 재작성하면 비공식 결과에서 무엇이 실제로 바뀌었는지 추적하기 어려웠다.
- 결정: 공백·문장부호를 제외한 문자 정렬로 동일 구간을 찾고, 이동한 삭제·삽입 문장을 짝지어 그 내부만 다시 비교한다. 동일 구간은 비공식 원문을 그대로 보존하며 공식 근거가 달라진 최소 문자 구간만 패치한다. 긴 문장의 정규화 유사도가 0.58 미만인 전체 재작성 후보는 본문 적용을 막고 공식 대안과 설명만 비교 카드에 둔다.
- 의미 보존 경계: 개조식·서술식과 독립 문장 순서 변경은 숫자·부정·결정/행위의 종류와 횟수, 정규화 의미 토큰, 기관·내용·행위가 묶인 의미 단위가 모두 같을 때만 문체 변경으로 제외한다. 단어 집합이 같아도 담당 기관과 행위가 교차되면 실제 변경으로 유지한다.
- LLM 경계: OpenRouter는 서버가 검증한 change ID, 전후 문구와 화자 통계만 받아 최대 6개 변화로 묶는다. 새 변경 판정·정책 사실 생성·근거 없는 ID 반환을 허용하지 않으며 결과는 입력 hash·모델·프롬프트 버전으로 저장한다.
- 비용·보안: 변경 0건은 호출 0회, 나머지는 공식 통합본당 1회다. 공식화 변화 전용 100회/UTC 일과 공용 500회/UTC 일을 함께 제한하고 공개 근거만 개인정보 패턴 제거 후 전송하며 data collection 거부와 provider fallback 금지를 요구한다.
- 버전 업그레이드: 동일한 공식 의미 해시와 이전 검증 변경 목록이 있으면 최신 결정론 비교 규칙으로 다시 필터링·패치해 새 파생 버전으로 저장한다. 이 재계산은 Mistral·OpenRouter 호출 0회이며 원본과 이전 통합 버전은 보존한다.
- 파생 인사이트: 추가기능의 타임라인은 공식 저장 자료를, 쟁점 증감과 논의→제도화는 회의별 최신 저장 보고서·공식 통합본의 구체 주제를 사용한다. 14일 회의 수와 근거가 확인된 전환 단계만 보여주며 원인·영향·가결 여부를 추론하지 않는다. 조회 LLM 비용은 0회다.

## ADR-045 · 부채형 의석도는 집계 설명 도구로 한정

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 정당별 의석수를 넓은 부채형 좌석도로 보면 연합 규모를 직관적으로 비교할 수 있지만, 실제 본회의장 지정석이나 좌우 이념 위치로 오인할 수 있다.
- 결정: 마지막 정상 `assembly_reference` 스냅샷의 정당별 집계만으로 6개 반원 열을 브라우저에서 그린다. 정당 순서는 공식 API 집계 건수 순이며 이념 또는 실제 좌석 위치를 뜻하지 않는다.
- 상호작용: 복수 정당을 선택해 합산하고 재적 과반, 3/5, 2/3의 산술 비교선을 보여준다. 각 기준은 용도가 다른 예시이므로 실제 안건 가결 가능성을 판정하거나 예측하지 않는다.
- 비용·접근성: SVG와 정족수 계산은 클라이언트 결정론 로직으로 수행해 외부 API와 LLM을 추가 호출하지 않는다. 정당 범례 버튼을 키보드 선택 수단으로 제공하고 모바일에서는 SVG를 화면 폭에 맞춰 축소한다.

## ADR-044 · 추가기능의 공식 읽기 모델과 무료 운영

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 월간 일정과 의석 현황은 일반 정보이지만 변동 가능하고, 페이지 조회마다 국회 API를 호출하면 장애 결합과 불필요한 무료 API 사용이 생긴다.
- 결정: 달력은 canonical `ScheduleEntry`를 최대 42일 범위로 읽고, 의석은 API key를 가진 schedule worker가 `ALLNAMEMBER` 원본 전체를 하루 한 번 raw-first 수집해 공개 집계 스냅샷을 만든다. API와 브라우저는 외부 국회 API를 직접 호출하지 않는다.
- 현역 규칙: 현행 대수가 `GTELT_ERACO`에 포함되고 `DTY_NM`이 비어 있지 않은 의원만 집계한다. 정당과 선출구분은 현행 대수 위치의 공식 API 값을 사용하며 임의로 현재 정당을 추정·통합하지 않는다.
- 장애·비용: 수집 실패 시 마지막 정상 스냅샷을 유지한다. 페이지 조회 LLM 0회, 외부 API 0회이며 의원 API는 최대 하루 한 차례만 호출한다.
- 개인정보 최소화: 공개 화면 스냅샷에는 집계값과 raw version hash만 넣고 의원 연락처·보좌진 정보는 복제하지 않는다.

## ADR-043 · 주제별 보고서 대표 논점의 결정적 순위

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 생성 모델이 반환한 첫 항목을 크게 표시하면 순서의 이유를 사용자에게 설명할 수 없고, 회의에서 반복적으로 다뤄진 논점이 대표 항목에 반영되지 않을 수 있다.
- 결정: 대표 논점은 관련성 30, 근거 권위·회의 범위 20, 언급 빈도 20, 정책 영향 15, 후속조치 10, 최근성 5의 합산 점수로 클라이언트에서 안정 정렬한다. 동점은 생성 결과의 원래 순서를 보존한다.
- 언급량: 잠정·통합 회의 보고서는 주제, 화자 요점, 연결 과제의 고유 `evidence_ids` 합집합을 사용한다. 공식 안건은 발언 빈도를 알 수 없으므로 항목당 1건만 인정한다. 한 장시간 회의가 순위를 독점하지 않게 보고서 안의 최댓값을 기준으로 로그 정규화한다.
- 설명 가능성: 화면에 총점과 여섯 항목 점수를 표시하고, 도움말에 고유 발언 근거와 공식 근거 건수를 보여준다. 순위 계산은 저장 자료만 사용하며 LLM을 호출하지 않는다.
- 결과: 대표 논점의 선정 이유를 재현할 수 있고, 검색·열람 때 추가 토큰 비용이 발생하지 않는다.

## ADR-042 · PoC 7 Kakao 나에게 보내기의 독립 운영 경계

- 상태: Accepted
- 결정일: 2026-08-31
- 배경: 초기 구현은 provider와 DB는 분리했지만 앱 키·암호화 키 이름과 배포 스크립트가 부모 `.env` 및 PoC 4 이름을 참조해 PoC 7 폴더만으로 운영 구성을 재현할 수 없었다.
- 결정: 런타임은 `WATCH_KAKAO_*`와 PoC 7 `.env`만 읽는다. OAuth state, 암호화 토큰, outbox, 재시도 및 연결 해제는 PoC 7 PostgreSQL 안에서 처리한다. 연결 해제는 로컬 계정과 outbox만 중단하고 앱 전체의 Kakao 원격 unlink를 호출하지 않는다. 환경 생성 도구는 PoC 7 전용 `WATCH_KAKAO_*`만 허용하고 다른 PoC의 앱 키를 자동 이관하지 않는다.
- 동의 검증: token 응답만 신뢰하지 않고 Kakao scope 조회 결과를 함께 확인해 `talk_message`가 없으면 계정을 저장하지 않는다.
- 결과: PoC 4 장애·토큰·배포 변경이 PoC 7 알림에 영향을 주지 않는다. 운영 자격증명은 별도 Kakao 애플리케이션을 사용하며, 전환 전 임시 공유 상태에서도 PoC 7의 연결 해제가 다른 서비스 토큰을 폐기하지 않는다.

## ADR-001 · 프로젝트 독립성

- 상태: Accepted
- 결정: NationalAssembly는 자체 설정, 의존성, API, 웹 화면, DB와 배포 구성을 가진다.
- 이유: 폴더 단독 공유·분석·실행 요구를 보장한다.

## ADR-002 · 상태 축 분리

- 상태: Accepted

- 이유: 종료된 회의에도 잠정 또는 공식 자료가 존재할 수 있어 단일 enum으로 표현할 수 없다.

## ADR-003 · PostgreSQL 우선

- 상태: Accepted

- 이유: 관계, 버전, 정형 필터와 Full Text Search를 하나의 POC 인프라에서 검증할 수 있다.

## ADR-004 · Semantic search 지연

- 상태: Accepted
- 결정: pgvector와 별도 vector DB는 정형검색·FTS 평가 후에만 도입한다.
- 이유: POC 성공 검증에 불필요한 초기 복잡도를 피한다.

## ADR-005 · 공식 파이프라인 우선

- 상태: Accepted
- 결정: AI enrichment는 raw ingestion, canonical model과 provenance가 동작한 뒤 구현한다.
- 이유: LLM이 원천 데이터나 공식 사실을 대신 생성하는 구조를 방지한다.

## ADR-006 · 대상 위원회와 전체 원문 보존 분리

- 상태: Accepted
- 결정: 제품 분석 대상은 행정안전위원회, 예산결산특별위원회, 법제사법위원회로 한정한다.
- 결정: 공식 일정 응답의 다른 위원회와 국회행사도 `ScheduleEntry`로 보존하되 `is_target_committee=false`로 구분한다.
- 이유: source 응답을 임의로 잘라 provenance를 잃지 않으면서 후속 수집·검색 범위를 명확히 유지한다.

## ADR-008 · 국회 LIVE polling과 단계적 자막 검증

- 상태: Accepted
- 결정: 국회 공식 LIVE 목록은 30초 polling하고 대상 위원회 방송에만 상세 player 계약을 조회한다.
- 결정: 자막 endpoint와 메시지 schema가 확인돼도 실제 대상 방송 handshake 전에는 `READY_TO_CAPTURE`로만 표시하며 `OFFICIAL` 발언으로 승격하지 않는다.
- 이유: 방송 시작 탐지 지연을 제한하면서 불필요한 요청을 줄이고, 접근 가능성 추정과 실제 발언 수집 성공을 구분한다.

## ADR-009 · 서버 소유 방송 생명주기

- 상태: Accepted
- 결정: 방송 감지·자막 수집·종료 처리·리뷰 생성·공식본 대조는 브라우저가 아니라 상시 worker가 수행한다.
- 결정: 중간 입장자는 DB snapshot과 event cursor를 먼저 받은 뒤 같은 cursor 이후의 실시간 delta를 구독한다.
- 결정: 종료 후 PROVISIONAL 리뷰와 게시 후 OFFICIAL 본은 LIVE 기록을 덮어쓰지 않고 함께 보존한다.
- 이유: 홈페이지가 닫혀 있어도 방송 처음부터 기록하고, 중간 입장·종료 후 입장·공식본 게시 시점에 동일 회의를 연속적으로 제공해야 한다.

## ADR-010 · 자막 원본 우선 저장과 DB lease

- 상태: Accepted
- 결정: 각 WebSocket 메시지를 raw artifact로 먼저 저장한 뒤 `TranscriptSegmentRevision`과 source version으로 연결한다.
- 결정: caption worker 소유권은 만료 가능한 PostgreSQL lease로 관리하고 대상 위원회 수에 맞춰 최대 세 연결만 허용한다.
- 결정: final segment는 늦게 도착한 partial 또는 과거 수신시각 메시지로 현재 텍스트가 후퇴하지 않게 한다.
- 이유: worker 재시작·중복 실행·메시지 재전송 상황에서도 provenance와 현재 읽기 모델의 일관성을 유지해야 한다.

## ADR-011 · Snapshot cursor와 delta polling

- 상태: Accepted
- 결정: 중간 입장 시 snapshot cursor를 먼저 고정하고 cursor 이하 최신 segment를 반환한 뒤, 이후 revision은 전역 단조 증가 cursor로 조회한다.
- 결정: 현재 통합 프록시가 streaming response를 버퍼링하므로 UI는 2초 delta polling을 사용하고 전송 실패 시 같은 cursor로 재시도한다.
- 이유: 브라우저 접속 이전 기록과 접속 이후 자막 사이의 누락을 막으면서 현재 배포 경로에서도 확실하게 동작해야 한다.

## ADR-012 · 종료 리뷰는 근거 기반 추출형으로 시작

- 상태: Accepted
- 결정: 종료 60초 후 final 자막만 주제별로 묶고 가장 긴 발언 원문을 대표 발언으로 선택한다.
- 결정: 모든 리뷰 주제는 대표 revision과 포함 revision 전체를 evidence로 가지며 `PROVISIONAL · AUTO REVIEW`로 표시한다.
- 결정: 매거진과 방송 기록에는 실제 수집 방송의 리뷰만 표시한다.
- 이유: 생성형 요약 없이도 종료 후 리뷰 흐름을 검증하면서 원문에 없는 내용을 만들어내지 않고 실제·합성 자료를 구분해야 한다.

## ADR-013 · 공식 게시와 본문 대조 상태 분리

- 상태: Accepted
- 결정: 공식 회의록 API의 위원회·서울 날짜 후보가 하나일 때만 방송과 `CONF_ID`를 연결한다. 후보가 없거나 복수이면 강제 연결하지 않는다.
- 결정: 회의록/PDF 링크 게시 확인은 `PUBLISHED`, 본문 미수집은 `LINK_ONLY`, 문장 대조는 `UNRESOLVED`로 각각 분리한다.
- 결정: 최근 30일 미게시 방송을 1시간 간격으로 다시 확인하고 원본과 source version을 보존한다.
- 이유: 공식 문서가 게시됐다는 사실과 LIVE 자막 문장이 공식본과 일치한다는 판단은 서로 다른 검증 단계다.

## ADR-014 · 공식 회의록 HTML source span 우선

- 상태: Accepted
- 결정: 공식 회의록시스템의 `type=view` HTML을 raw-first 저장하고 발언자 ID·문장 ID를 source span으로 사용한다. PDF/HWP는 HTML 계약 장애 시 검증할 fallback으로 둔다.
- 결정: 화면에 임시회의록으로 명시된 본문은 공식 사이트 자료이더라도 `PROVISIONAL`로 저장하고 정본 게시 시 새 버전을 `OFFICIAL`로 추가한다.
- 결정: LIVE final 문장은 정규화 후 길이 20자 이상이며 공식 문장 후보가 정확히 하나인 exact substring일 때만 자동 `MATCHED`로 기록한다.
- 이유: PDF 페이지 단위 추출보다 공식 HTML의 문장 ID가 더 정밀한 provenance를 제공하며, 잠정본을 정본으로 오인하거나 유사도만으로 발언을 강제 연결하는 일을 막아야 한다.

## ADR-015 · 공식 본문과 LIVE 방송 연결의 선택성

- 상태: Accepted
- 결정: 공식 회의록 본문은 `Meeting`에 필수 연결하고 `BroadcastOfficialPublication`은 실제 LIVE 방송 기록이 있을 때만 선택적으로 연결한다.
- 결정: 대상 위원회의 최근 공식 본문은 방송 기록 유무와 무관하게 수집해 위원회 행의 발언 상세에서 제공한다.
- 이유: 과거 공식 회의 자료의 탐색 가능성과 향후 LIVE→공식본 reconciliation을 한 모델에서 지원하되, 존재하지 않는 방송을 만들어내지 않아야 한다.

## ADR-016 · 공식 발언 인사이트는 검토 전 파생 데이터

- 상태: Accepted
- 결정: 공식 문장의 주제·관련 부처는 versioned 결정적 keyword rule로 생성하고 `OfficialUtteranceAnnotation`에 `PROVISIONAL · DRAFT`로 저장한다.
- 결정: UI는 공식 원문 상태와 자동 분류 상태를 별도 라벨로 표시하고, 분류 chip은 탐색 필터로만 사용한다.
- 이유: 현재 단계에서 근거 없는 생성형 요약을 도입하지 않으면서 국정 흐름 탐색을 제공하고, 공식 사실과 자동 해석의 혼동을 막아야 한다.

## ADR-017 · 기관명 masking과 정책 발언 전용 흐름 집계

- 상태: Accepted
- 결정: 주제·부처 keyword matching 전에 대상 위원회 정식명·약칭을 가려 기관명 자체가 정책 근거가 되지 않게 한다.
- 결정: 각 결과에 일치 keyword와 POLICY/PROCEDURAL/OTHER 유형을 보존하고 위원회 행의 핵심 흐름에는 POLICY만 집계한다.
- 결정: 부처 연결은 공식 소관 확정이 아니라 keyword 기반 `RELATED · PROVISIONAL · DRAFT`로 표시한다.
- 이유: “법제사법위원회 개회”를 법무부 정책으로, “예산결산특별위원회 개회”를 기획재정부 정책으로 오인한 실제 사례를 제거하고 사용자가 자동 분류 근거를 확인할 수 있어야 한다.

## ADR-018 · 통합 정책 흐름은 최신 공식 본문 기반 읽기 모델

- 상태: Accepted
- 결정: 세 위원회 비교는 회의별 최신 `OfficialTranscriptDocument`의 POLICY annotation만 실시간 집계하고 별도 요약 사실로 저장하지 않는다.
- 결정: 주제 강도는 해당 주제가 연결된 고유 발언 수이며 한 발언이 여러 주제에 연결되면 각 주제에 포함될 수 있음을 UI에 전제한다.
- 결정: 대표 근거는 생성 요약 대신 해당 주제의 가장 긴 공식 원문 발언과 source span을 사용한다.
- 이유: 원문·annotation 변경이 즉시 흐름에 반영되고, 파생 집계의 중복 버전 문제와 생성형 요약의 왜곡을 피하면서 사용자가 근거로 이동할 수 있어야 한다.

## ADR-019 · 발언-안건-의안은 명시적 번호 일치만 자동 연결

- 상태: Accepted
- 결정: 공식 발언의 `agenda_item_ref=itemN`과 같은 Meeting의 공식 `agenda_name` 접두 번호 `N.`가 정확히 같을 때만 `MATCHED · EXACT_ITEM_REF_AGENDA_PREFIX · 1.0`으로 저장한다.
- 결정: item0, 번호가 없는 안건, 회의별 의안 API에 없는 안건은 제목 유사도로 강제 연결하지 않는다.
- 결정: 정책 카드의 표결은 연결된 외부 BILL_ID와 검증된 본회의 표결 BILL_ID가 같을 때만 결합한다.
- 이유: 발언의 정책 주제에서 실제 입법 결과까지 연결하되 회의 안건 순서가 불명확한 자료를 잘못된 의안에 붙이지 않아야 한다.

## ADR-020 · 기관 간 정책 연결은 양쪽 공식 근거와 규칙 관계를 분리

- 상태: Accepted
- 결정: 국무회의 공식 안건과 국회 공식 발언에 동일한 versioned 정책 taxonomy가 적용된 경우만 기관 간 후보를 만든다.
- 결정: 법무·사법과 재난·안전처럼 일반 단어의 오연결 위험이 큰 주제는 별도의 강한 근거 단어가 일치할 때만 노출한다.
- 결정: 양쪽 원문은 각각 `OFFICIAL` 근거로 표시하되 동일 주제와 공통 근거 단어가 확인된 관계만 `EXACT_SHARED_TOPIC_AND_KEYWORD_V3 · PROVISIONAL · DRAFT`로 표시한다. `지방`, `행정`, `공무원`, `법률`, `법무`, `사법`, `안전` 같은 광범위 단어만 겹치는 관계는 제외한다.
- 결정: 날짜 순서는 사실 그대로 표시하되 인과관계를 주장하지 않으며, 의안은 국회 발언 쪽에 명시적으로 연결된 경우로 범위를 한정해 표시한다.
- 이유: 공식 자료가 양쪽에 존재한다는 사실이 두 기관의 공식적인 인과·소관 관계를 뜻하지 않으므로, 탐색 가능한 연결과 확정된 사실을 혼동하지 않아야 한다.

## ADR-021 · 의안 설명은 공식 PDF 구획 원문만 사용

- 상태: Accepted
- 결정: `ALLBILLV2.PDF_URL1`의 첫 번째 공식 PDF를 redirect 계약에 따라 수집하고 원본·hash·parser version을 보존한다.
- 결정: `제안이유`, `제안설명의 요지`, `주요내용`, `전문위원 검토보고의 요지`처럼 문서에 명시된 구획만 페이지 span과 함께 추출하며, 구획이 없으면 생성 요약으로 보완하지 않는다.
- 결정: 공식 자료 worker가 매시간 같은 URL도 다시 확인하고 content hash가 변경되면 기존 문서를 덮어쓰지 않고 새 source version으로 저장한다.
- 결정: FileGate가 동일 본문 PDF의 내부 바이트를 매 요청마다 바꾸는 경우 추출 본문 fingerprint가 같으면 새 canonical 문서로 저장하지 않는다. 실제 추출 본문이 달라질 때만 새 버전으로 보존한다.
- 이유: 사용자가 의안의 취지와 주요 내용을 빠르게 읽으면서도 화면 문구를 공식 PDF 페이지까지 역추적할 수 있어야 한다.

## ADR-023 · LIVE 인사이트의 기본 단위는 발언이 아니라 주제별 질의응답

- 상태: Accepted
- 결정: LIVE 화면은 원문 자막을 보조 근거로 접고, 같은 주제에 속한 질문과 답변을 정보 중심의 한 묶음으로 표시한다.
- 결정: 후속 과제는 일반 답변에서 생성하지 않는다. 확인·검토·조치 약속이나 `해야 한다`는 요구가 회의 안에서 완료·조치·해소되지 않은 경우만 `OPEN`으로 남기며 담당 부서는 그 과제에 직접 연결된 경우에만 표시한다.
- 결정: 같은 주제의 후속 발언에서 완료·조치·처리·해소가 확인되면 자동 후보를 제거한다. 의미상 동일 여부가 불확실하면 `AUTO GROUP · DRAFT` 상태를 유지한다.
- 결정: 공식 자막에 구조 정보가 없을 때의 질문·답변·주제·과제 연결은 `AUTO GROUP · DRAFT`로 표시한다. 명시적 부처명이나 검토 근거가 없으면 담당 부서를 확정하지 않는다.
- 결정: 공식 국회 player 계약의 HTTPS HLS 주소가 있을 때만 영상을 재생한다.
- 이유: 개별 발언 나열만으로는 질의의 맥락과 후속 책임을 판단하기 어렵고, 영상·자막·구조화 결과를 같은 시점에 함께 검토해야 하기 때문이다.

## ADR-024 · 방송 상태와 공식 자료 순환은 독립된 화면 상태

- 상태: Accepted
- 결정: LIVE·예정·종료 방송은 한 줄 목록으로 관리하고, LIVE와 종료 기록 모두 선택할 때 같은 전체 폭 분석 패널을 펼친다.
- 결정: 종료 기록은 최신 1건으로 제한하지 않고 방송 이력 API로 최근 N건을 노출하며, 방송 ID별 저장 자막·질의응답·미해결 과제를 다시 조회한다.
- 결정: 국무회의·국회 공식 자료 패널은 방송 상태와 분리하고 양쪽 모두 공식 source 자료만 5초마다 순환한다. LIVE가 시작되어도 공식 자료 패널을 덮어쓰지 않는다.
- 결정: 방송 예정 표시는 당일 공식 일정의 대상 위원회와 검증된 시작 시각만 사용한다.
- 이유: 실시간 관제와 확정 자료 브리핑은 사용 목적과 권위 상태가 다르므로 동일한 표시 영역을 경쟁적으로 사용하지 않아야 한다.

## ADR-025 · 종료 방송과 공식 회의록은 덮어쓰지 않고 나란히 대조

- 상태: Accepted
- 결정: 종료 방송 확장 화면은 `LIVE 저장본 · PROVISIONAL`과 공식 회의록의 잠정본·정본 권위 상태를 별도 칸으로 표시한다.
- 결정: 공식본이 게시되지 않았거나 회의 후보가 복수이면 `NOT_PUBLISHED`·`AMBIGUOUS` 상태를 그대로 표시하고 공식본이 있는 것처럼 대체하지 않는다.
- 결정: 문장 일치는 정규화된 20자 이상 final 자막이 공식 발언 한 문장에 유일하게 대응할 때의 exact 결과만 집계한다.
- 결정: 공식 회의록 링크와 공식 발언 수를 제공하되 기존 LIVE 자막·리뷰·미해결 과제는 보존한다.

## ADR-026 · 통합 후속 과제는 명시적 OPEN 근거만 사용

- 상태: Accepted
- 결정: 통합 후속 과제 보드는 최근 30일 LIVE·종료 방송의 final 자막 revision 중 `task_status=OPEN`과 과제 문구가 명시된 항목만 노출한다.
- 결정: 같은 방송·주제의 후속 근거가 `RESOLVED`이거나 해소로 표시되면 이전 OPEN 항목을 제거한다.
- 결정: 담당 부서는 같은 근거 payload에 명시된 값만 facet으로 제공하고 비어 있으면 `담당 부서 미확정`으로 유지한다.
- 결정: 과제를 선택하면 해당 방송을 열고 미해결 과제 필터를 적용하되 LIVE/종료·PROVISIONAL 표시는 보존한다.

## ADR-027 · 첫 화면은 방송 기록의 연속성과 공식 정책 탐색을 우선

- 상태: Accepted
- 결정: 서비스 첫 설명과 최상위 작업 영역에서 브라우저와 무관한 서버 기록, 중간 진입 시 누적 맥락 복원, 종료 후 공식본 대조를 명시한다.
- 결정: LIVE·예정·종료 기록과 후속 과제는 같은 작업 영역에 두고, 영상·주제별 질의응답·미해결 과제·담당 부서·시간순 원문을 한 번의 방송 선택으로 연다.
- 결정: 방송 상태와 독립된 공식 브리핑은 정부·국회로 나눠 유지하고, 하위 탐색은 정부의 주제·부처와 국회의 위원회·의안 축을 사용한다.
- 결정: 기본 본문은 16px을 기준으로 하고 핵심 정보 행과 상세 본문은 13px 미만으로 축소하지 않는다. 상태·근거 metadata에만 10~12px을 제한적으로 사용한다.
- 결정: 시각 체계는 밝은 중립 surface, 하나의 인디고 상호작용 색, LIVE 위험색, 얕은 elevation으로 한정하고 장식 목적 그래픽은 추가하지 않는다.
- 이유: 처음 방문한 사용자가 설명서 없이 현재 상황, 앞선 맥락, 남은 일, 공식 근거의 순서로 국정 흐름을 읽을 수 있어야 한다.

## ADR-028 · 오픈 베타 기본 단위는 발언이 아니라 회의 결과

- 상태: Accepted
- 결정: 종료 회의를 열면 전체 자막보다 회의 headline·요약·핵심 주제·화자별 요지·도출 과제를 먼저 표시한다.
- 결정: 주제·화자 요지·과제를 클릭할 때만 해당 항목의 근거 Utterance를 조회하고 전체 원문은 접힌 상세로 제공한다.
- 결정: 회의 브리프는 공식 사실과 분리된 `PROVISIONAL · DRAFT`이며 모든 항목은 현재 transcript snapshot에 존재하는 evidence ID를 하나 이상 가져야 한다.
- 결정: `OPEN + EXPLICIT`만 명시된 후속 조치로 표시하고 추론 과제는 AI 검토 후보, 담당부처 추론은 잠정 연결로 표시한다.
- 결정: Mistral 구간 분석과 회의 통합 결과는 transcript hash·provider·model·prompt version으로 저장하며 API 요청에서 외부 LLM을 호출하지 않는다.
- 이유: 사용자는 발언 나열보다 어떤 회의가 있었고 무엇이 논의됐으며 어떤 일이 남았는지를 먼저 이해해야 한다.

## ADR-029 · 기관별 화면 대신 하나의 회의 흐름과 출처 탭을 사용

- 상태: Accepted
- 결정: 공개 화면은 국회와 국무회의를 별도 작업 메뉴로 나누지 않고 진행 중·예정·결과 회의 레일에 함께 표시하며 기관은 카드 배지로만 구분한다.
- 결정: 수집 건수·수집 시간·자막 처리량·worker 상태는 사용자 가치가 아니라 운영 상태이므로 공개 화면에서 제거하고 향후 관리자 메뉴가 소유한다.
- 결정: 종료 결과의 기본 화면은 가장 최근 요약 완료 회의이며 주제·화자·과제를 선택한 근거 발언은 같은 화면 우측 sticky 패널에서 교체한다.
- 결정: LIVE·공식 자료 탭 바로 아래의 1·2열은 논의 주제·도출 과제 제목만 한 줄로 보여 주는 이동 인덱스로 사용한다. 선택 시 해당 주요 논의 내용으로 포커스하고, 주제별 과제는 화자 요약 바로 아래에 `과제 · 내용 · 원문 보기`의 동일한 행 구조로 붙인다. 별도 과제 보드는 두지 않으며, 근거의 AI 요약은 강조하지 않고 펼친 원문에서 가장 관련 높은 문장 전체만 강조한다.
- 결정: LIVE 저장본과 공식 자료는 서로 덮어쓰지 않고 탭으로 병렬 제공한다. 일정/회의 identity, 공식 publication, 발언 reconciliation 순으로 연결 상태를 높이며 미발행·미연결 상태도 명시한다.
- 결정: 공식 사이트에 게시됐더라도 임시 회의록의 authority가 PROVISIONAL이면 화면과 API에서 그대로 유지한다.
- 이유: 사용자는 기관별 데이터 파이프라인보다 지금 어떤 회의가 열리고 무엇이 결정됐으며 그 판단 근거가 무엇인지 한 흐름에서 이해해야 한다.

## ADR-030 · LIVE 화자 전환만 발언 완료 경계로 사용

- 상태: Accepted
- 결정: 같은 방송에서 연속된 동일 원본 화자 코드의 자막은 길이·시간과 무관하게 하나의 진행 중 발언으로 누적하며 화면에서 축약하지 않는다.
- 결정: source가 non-final 자막을 빈 화자나 `-1`로 먼저 보낸 뒤 확정 화자로 수정하는 구간은 직전 확정 화자에 임시 연결한다. 확정 revision이 다른 화자로 바뀐 시점만 실제 전환으로 처리한다.
- 결정: LIVE 요약 대상은 실제 전환으로 닫힌 직전 발언이며 원문 hash 캐시로 한 번만 외부 호출한다. 진행 중 마지막 발언은 다음 전환 또는 방송 종료 전까지 요약하지 않는다.
- 결정: 공개 화면은 최신 자막마다 진행 중 발언 묶음으로 자동 이동하고, 전환 뒤 DB에 저장된 요약만 다시 읽는다. API 요청 자체는 외부 LLM을 호출하지 않는다.
- 이유: 사용자가 현재 발언의 전체 흐름을 놓치지 않으면서 거짓 화자 경계로 인한 잘린 표시와 중복 요약 비용을 피해야 한다.

## ADR-031 · 종료 상태는 결과 포맷과 분리하지 않는다

- 상태: Accepted
- 결정: 영상·실시간 자막 중심 방송 포맷은 방송 생명주기가 `LIVE`인 동안에만 기본 화면으로 사용한다.
- 결정: `ENDED` 회의는 AI 브리프의 READY·PENDING·DEFERRED 상태와 무관하게 항상 법사위 결과와 동일한 회의 결과 포맷으로 연다.
- 결정: worker는 deterministic 방송 리뷰와 canonical 발언 묶음으로 근거가 연결된 fallback 결과를 먼저 DB에 저장하고 외부 LLM 통합 결과를 후속 생성한다.
- 결정: Mistral 결과가 저장되면 최신 결과로 교체하되 deterministic 결과도 출처를 `자동 정리 · 잠정`으로 명시한다. 전체 자막 포맷은 사용자가 명시적으로 선택한 경우에만 제공한다.
- 이유: 방송 종료와 AI 처리 완료는 서로 다른 상태이며 외부 모델 한도가 사용자 화면의 정보 구조를 되돌려서는 안 된다.

## ADR-032 · provider 한도는 동일한 호출 횟수가 아니라 과금 단위로 분리한다

- 상태: Accepted
- 결정: OpenRouter 무료 호출 정책은 기존 UTC 일 500회 원자 요청 예약을 유지한다.
- 결정: Mistral에는 일일 호출 횟수 제한을 적용하지 않고 성공 응답의 입력·출력·전체 토큰을 모델·UTC 월 단위로 누적한다.
- 결정: 실시간 완결 발언 요약과 종료 회의 브리프는 같은 Mistral 월간 토큰 장부와 1,500만 토큰 로컬 안전선을 사용한다.
- 결정: 로컬 토큰 안전선과 별개로 Mistral Workspace의 월간 지출 한도를 USD 10 이하로 설정한다.
- 이유: 서로 다른 provider의 무료·과금 계약을 하나의 500회 규칙으로 처리하면 Mistral 작업이 실제 월간 여유와 무관하게 중단되고, 회의별 결과 형식이 fallback과 AI 결과로 갈라진다.

## ADR-033 · LIVE 영상과 자막은 경쟁하지 않고 위아래로 분리한다

- 상태: Accepted

- 결정: 영상 위에는 자막을 겹쳐 표시하지 않고 공식 스트림 상태 배지만 유지한다.
- 결정: 영상 우측은 주제당 한 줄과 과제 건수만 누적 표시하며 발언·과제 본문을 반복하지 않는다.
- 결정: 우측 목록은 실제 영상 높이를 넘지 않으며, 주제가 많아지면 영상과 페이지가 아니라 목록 내부만 스크롤한다.
- 결정: 화자별 실시간 누적 원문과 전환 후 저장 요약은 영상 아래의 넓은 단일 자막 영역에서 최신 발언으로 자동 이동한다.
- 결정: 자막 갱신 시 사용자가 펼친 원문은 발언 ID로 상태를 보존하고 재렌더링 뒤에도 열린 상태를 유지한다.
- 결정: 노트북 기본 보기의 영상 높이는 화면의 42%, 최대 420px로 제한하고 아래 자막 영역에는 직전 발언과 현재 발언이 함께 보이도록 밀도를 높인다.
- 결정: 현재 발언은 카드 높이를 112px로 제한하고 새 자막마다 카드 내부를 끝으로 이동해 전체 레이아웃을 늘리지 않고 최신 문장을 노출한다.
- 결정: 시네마 모드에서는 우측 인사이트를 숨기고 영상을 전체 폭 16:9로 표시하되 아래 자막 영역은 유지한다.
- 이유: 사용자는 영상을 가리지 않고 시청하면서 필요할 때 시선을 아래로 내려 전체 발언 맥락과 요약을 함께 읽어야 한다.

## ADR-034 · LIVE 주제는 화자 요약과 같은 호출에서 생성한다

- 상태: Accepted
- 결정: 완결된 화자 묶음의 Mistral 응답은 요약과 함께 잠정 주제·역할·과제·담당 후보를 반환한다.
- 결정: 구조화 결과는 발언 content hash의 요약 캐시와 같은 행에 저장하며 동일 발언을 재호출하지 않는다.
- 결정: LIVE 화면은 저장된 구조화 결과만 표시하고 브라우저 키워드 규칙으로 실제 방송 주제를 만들지 않는다.
- 결정: LIVE 결과는 `PROVISIONAL`이며 방송 종료 후 전체 계층 분석 결과가 최종 논의 주제와 도출 과제를 담당한다.
- 이유: 별도 주제 추출 호출과 반복 문맥 전송 없이 실시간 이해도를 높이고, 잠정 결과와 종료 결과의 책임을 분리하기 위해서다.

## ADR-035 · 숫자 화자 코드는 인물이 아니라 원천 음성 경계다

- 상태: Accepted
- 결정: 국회 LIVE 자막의 `0/1/-1`은 방송 전체에서 재사용되는 음성 분리 코드이며 의원·장관의 고유 식별자로 해석하지 않는다.
- 결정: 한 source revision의 `speaker_segments`에 서로 다른 코드가 있으면 첫 코드로 전체 문장을 귀속하지 않고 원천 배열 순서의 파생 발언 조각으로 제공한다.
- 결정: 파생 조각은 원본 segment·revision·raw payload를 덮어쓰지 않는 읽기 모델이며, 같은 원본 segment의 새 revision이 도착하면 화면 상태에서 직전 파생 조각을 교체한다.
- 결정: source revision의 임시 화자 경계는 화면 갱신에만 사용하고, 실시간 LLM 요약은 final 구간으로만 구성된 닫힌 발언에 한정한다.
- 결정: 숫자 코드의 방송 단위 표시 이름 변경은 동일 인물임이 별도로 검증된 경우에만 사용하고, 미검증 상태는 이름 미확인으로 유지한다.
- 결정: LIVE 우측 인사이트는 1100px 초과에서 영상과 높이를 맞추고, 그 이하에서는 영상 아래의 제한 높이 내부 스크롤 영역으로 전환한다.
- 이유: 원천이 제공하지 않는 인물 정체를 추측하지 않으면서 실제 질의·답변 전환과 모바일 시청 폭을 보존해야 한다.

## ADR-036 · 종료와 결과 준비 완료는 별도 상태로 표현한다

- 상태: Accepted
- 결정: 방송 생명주기가 `ENDED`여도 회의 브리프가 저장되기 전에는 결과 내용을 확정형으로 노출하지 않고 `결과 정리 중` 상태를 표시한다.
- 결정: 준비 중 화면은 최종 결과와 같은 골격을 흐림 처리해 화면 전환을 예고하되 클릭과 읽기를 막고 명시적 진행 상태를 전면에 둔다.
- 결정: 사용자가 해당 회의를 보고 있는 동안에는 5초 간격으로 DB 저장 결과만 재조회하고 브리프가 준비되면 같은 화면을 실제 결과로 교체한다. 재조회 자체는 외부 LLM을 호출하지 않는다.
- 결정: deterministic fallback은 결과 공백을 막는 임시 읽기 모델일 뿐 `READY`로 판정하지 않으며 Mistral 근거 분석본이 저장된 경우에만 결과 준비 완료로 전환한다.
- 결정: 준비 중에는 회의 제목·기본 정보·자료 탭·전체 발언 접근을 유지하고 `요약된 논의 주제 / 도출 과제` 영역만 흐림 처리한 로딩 카드로 대체한다.
- 결정: 구간 분석이 끝날 때마다 전체 발언 수와 처리 완료 발언 수를 DB에 저장하고 화면 재조회에서 진행 단계와 함께 표시한다.
- 결정: 발언 경계 읽기 모델 변경 전 저장된 evidence ID는 현재 파생 발언 ID의 부모 source segment와도 일치시켜 기존 브리프의 근거 연결을 보존한다.
- 결정: 호환 대조 후에도 근거가 없으면 빈 영역으로 두지 않고 재대조 상태를 명시한다.
- 이유: 방송 종료와 AI 결과 준비는 다른 상태이며, 읽기 모델 개선이 이미 저장된 근거 추적성을 끊어서는 안 된다.

## ADR-037 · 종료 브리프의 과제는 근거 발언으로 하나의 주제에 귀속

- 상태: Accepted
- 결정: Mistral이 반환한 과제의 `topic_title` 문자열을 주제 연결 키로 사용하지 않는다.
- 결정: 과제와 주제가 공유하는 evidence ID 수를 최우선으로 비교하고, 같은 근거가 없을 때만 정규화 제목의 완전 일치·핵심어·문자열 유사도를 순서대로 사용한다.
- 결정: 모든 과제에는 하나의 canonical `topic_id`와 해당 주제의 정식 `topic_title`을 저장하며 화면도 `topic_id`로 배치한다.
- 결정: 기존 저장 브리프는 외부 LLM을 다시 호출하지 않고 같은 결정 규칙으로 보정한다.
- 이유: 생성 모델이 같은 쟁점의 제목을 다르게 표현해도 원문 근거가 가리키는 주제와 과제를 안정적으로 함께 보여줘야 한다.

## ADR-038 · 잠정 결과와 공식 자료는 변경 패치로 통합한다

- 상태: Accepted
- 결정: 저장 계층에서는 LIVE 잠정 브리프와 공식 회의록 버전을 계속 분리하고 어느 원본도 덮어쓰지 않는다.
- 결정: 화면은 별도 `LIVE 저장본 / 공식 자료` 결과 탭을 사용하지 않고, 잠정 결과에 공식 자료로 확인된 수정·추가·삭제 span만 합성한다.
- 결정: 수정 문구는 파란 굵은 글씨와 이전 문구 tooltip, 추가는 초록 굵은 글씨, 삭제는 붉은 취소선으로 표시하며 모바일은 focus/tap으로 같은 설명을 연다.
- 결정: 화자 분리·병합은 문자 구절과 공식 발언 순서의 결정적 대조로 처리하고 사용자에게 이력으로 노출하지 않는다. 공식 근거가 확인된 현재 화자 묶음만 표시한다.
- 결정: 의미 대조가 필요한 주제·과제 변경만 공식 문서 버전당 Mistral 1회로 제한하고 결과와 토큰 사용량을 문서·브리프·프롬프트 버전 키로 캐시한다.

## ADR-039 · 요약은 추상 의미를 보존하고 LIVE 능력을 과장하지 않는다

- 상태: Accepted
- 결정: 종료 브리프의 주제·화자 요지는 원문 발췌가 아니라 완결형 한국어 재서술이어야 하며 원문 복사와 비정상 영문은 저장 전 차단한다.
- 결정: 공식 화자 대조는 이미 생성된 추상 요약을 원문 앞부분으로 대체하지 않고 화자 표시와 공식 근거 ID만 보강한다.
- 결정: 공식 자료의 문체·어순·개조식 차이는 숫자·부정·정책 의미가 유지되면 사용자 변경 이력으로 표시하지 않는다.
- 결정: KTV 국무회의는 공식 편성 ONAIR와 공식 HLS를 국회와 같은 회의 레일·라이브 수명주기로 처리한다.
- 결정: 기계 판독 공식 자막이 없는 KTV 방송은 자막·화자를 추정하지 않고 제한을 화면에 명시하며 종료 후 공식 브리핑을 결과 계층으로 연결한다.
- 이유: 사용자가 요약과 원문을 구분해 읽고, 의미 없는 공식 변경이나 존재하지 않는 실시간 자막을 사실로 오인하지 않게 해야 한다.

## ADR-040 · 관심주제 후속 기능은 무료 결정론 경로를 기본으로 완결한다

- 상태: Accepted
- 결정: 알림 규칙은 서버 matcher용 stable revision과 적용시각을 권위 원본으로 사용한다. 브라우저 localStorage는 익명·오프라인 화면 복구용 cache이며 Kakao 연결 뒤에는 서버 원본과 비파괴 병합한다. 수정 전 자막은 새 조건의 알림 대상이 아니다.
- 결정: 화자별 최초 1회와 10·15·30·60분 간격은 신규 final 감지에서만 평가하고 시간 경과만으로 알림을 만들지 않는다.
- 결정: 회의 종료 digest, 운영 지표, 공식 근거 확인, 인쇄와 Markdown 대응자료는 저장된 발언·브리프·공식 대조만 사용하며 별도 LLM을 호출하지 않는다.
- 결정: 공식 유일 문장 대조가 성립한 개조식·서술식 차이는 `OFFICIAL_CONFIRMED`로 처리하고 의미 있는 변경으로 표시하지 않는다. FINAL 통합 후 근거가 없을 때만 `OFFICIAL_NOT_CONFIRMED`, 충돌은 `REVIEW_REQUIRED`로 둔다.
- 결정: Kakao와 watch 전용 LLM은 외부 동의·비용이 필요한 선택 기능으로 유지하며 무료 오픈 베타 기본값에서는 비활성화한다.
- 이유: 알림·근거·종료 결과를 비용이나 외부 provider 장애와 분리하고, 사용자가 잠정 기록과 공식 확인 상태를 혼동하지 않게 해야 한다.

## ADR-041 · 외부 알림·선택형 요약·운영판정은 독립 경계와 append-only 이력을 사용한다

- 상태: Accepted
- 결정: PoC 7 Kakao OAuth·암호화·발송 코드는 PoC 4를 import하지 않는 독립 adapter와 PostgreSQL outbox worker로 구현한다.
- 결정: API는 OAuth 설정만, notification-worker는 발송 비밀값만 allowlist로 받으며 watch-worker는 provider credential을 받지 않는다.
- 결정: 관심주제 통합 요약은 무료 추출 요약을 대체하지 않는 선택 레이어이며 evidence ID hash·월 USD 1 soft cap·세션 12회 제한을 적용한다.
- 결정: 관리자 decision은 자동판정 상태를 갱신하지 않고 원본 상태·결정·메모·운영자·시각을 append-only 행으로 저장한다.
- 결정: 실제 방송 조건을 관측하지 못한 회귀 검증은 PASS로 만들지 않고 `PENDING`으로 기록한다.
- 이유: 무료 핵심 흐름을 외부 장애와 분리하면서도 운영 활성화 후의 비용·중복·감사 가능성을 코드 수준에서 보장해야 한다.

## ADR-042 · 장시간 회의는 가변 회차로 체크포인트하고 종료 뒤 한 번 통합한다

- 상태: Accepted
- 결정: 같은 방송 ID의 저장 자막 사이에 30분 이상 공백이 생기면 1부터 증가하는 잠정 회차 경계를 만든다. 회차 수는 1·3회로 고정하지 않는다.
- 결정: LIVE 상태의 마지막 회차만 `ACTIVE`, 앞선 회차와 종료 방송의 회차는 `CHECKPOINTED`로 표시한다. 회차 경계는 공식 정회·산회 판정이 아니다.
- 결정: 동일 원본 화자 코드도 5분 넘게 끊기면 새 발언 묶음으로 시작해 장시간 정회 전후 발언이 하나로 합쳐지지 않게 한다.
- 결정: 방송이 다시 시작되면 저장·실시간 초안을 이어가고, `ENDED`가 2시간 안정된 뒤 모든 회차를 하나의 종료 브리프로 합성한다.
- 결정: 최종 합성은 모든 저장된 실시간 주제 cluster ID를 정확히 한 최종 주제에 귀속한다. 누락된 ID는 결정적 유사도 규칙으로 보정하고 추가 LLM을 호출하지 않는다.
- 결정: 동일 원본 cursor인 과거 Mistral 보고서에는 기존 결과를 재사용해 회차·계보만 보강하며 비용이 드는 재생성을 하지 않는다.
- 결정: 국회 자막 worker는 방송별 DB lease와 `SKIP LOCKED` claim으로 최대 3개를 독립 처리한다. 실제 2개 동시 저장은 운영 이력으로 검증하고, 3개 동시는 실제 발생 전까지 계약 검증 상태로 구분한다.
- 이유: 회의 횟수와 정회 길이가 매번 달라도 사용자가 중간 전체 흐름을 잃지 않고, 종료 결과의 형식과 무료 운영 원칙을 함께 지키기 위해서다.


## ADR-043 · 카카오 연결을 PoC7 다중 기기 계정 경계로 사용한다

- 상태: Accepted
- 결정: 익명 방문은 만료 가능한 보안 세션으로 시작하고, Kakao 연결 성공 시 Kakao 사용자 ID에 이미 연결된 canonical subscriber를 사용한다.
- 결정: 새 기기의 익명 규칙은 감지문구·기관·위원회가 같은 기존 규칙과 중복 생성하지 않고 추가 병합한다. 기존 계정·규칙·Kakao token은 자동 삭제하거나 다른 subscriber로 이동하지 않는다.
- 결정: session 원문은 브라우저의 HttpOnly·Secure·SameSite=Lax 경로 제한 cookie에만 두고 DB에는 SHA-256 hash만 저장한다. 구형 localStorage token은 자동 승격 후 제거한다.
- 결정: 현재 기기·전체 기기 session 폐기와 Kakao 연결 해제를 서로 다른 명시적 동작으로 둔다.
- 이유: PoC7 단독 배포를 유지하면서 여러 PC에서 같은 알람 설정과 저장 결과를 이어 보고, 브라우저 script가 장기 인증 token을 읽지 못하게 하기 위해서다.

## ADR-044 · 주제별 보고서는 로컬 검색 후 사용자 요청 때만 1회 생성한다

- 상태: Accepted
- 결정: 소관 부처·주제·기간 검색은 저장된 회의 brief와 공식 통합본의 구조화 의미·keyword만 사용하며 외부 LLM을 호출하지 않는다.
- 결정: 사용자가 작성 버튼을 누른 경우에만 선별된 공개 근거 snapshot으로 OpenRouter 작업을 한 번 예약하고, 동일 query·evidence·provider·model·prompt READY 결과는 재사용한다.
- 결정: OpenRouter 전체 500회/UTC 일 안에서 주제 보고서 100회/UTC 일과 사용자 10회/UTC 일을 추가 적용한다. 새로고침·목록·상세·Markdown·인쇄는 호출하지 않는다.
- 결정: OpenRouter API key는 전용 worker에만 제공하고 data collection 거부, fallback 금지, strict JSON schema를 강제한다. 주제별 보고서는 공개 회의 근거만 사용하고 PII 패턴을 제거한다. 무료 endpoint가 ZDR pool에 없으므로 이 경로는 ZDR을 강제하지 않으며, 모든 생성 항목의 evidence ID를 저장 snapshot과 검증한다.
- 결정: 카카오 연결 계정만 생성을 요청할 수 있으며 Kakao ID·token·browser session은 LLM payload에 포함하지 않는다.
- 이유: 사용자 요청 시점의 필요에 맞는 완결 보고서를 제공하면서 무료 호출량, 개인정보 노출, 근거 없는 생성과 반복 비용을 동시에 제한하기 위해서다.
