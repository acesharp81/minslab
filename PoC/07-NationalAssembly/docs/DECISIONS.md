# Architecture Decisions

## 2026-10-31 — 통합 요청 전체의 부모 제목 계약과 동일 내용 저장 생략

실제 통합 워커는 compact/partitioned 경로를 사용한다. 세부 쟁점의 canonical 대표 선택과 상위 정책 범위는 다른 단계이므로, 모든 분할이 전체 입력에서 만든 `policy_parent_catalogue`를 공유하고 schema enum으로 제목을 제한한다. 분할 스키마는 `$defs`로 동일 목록을 재사용한다. 기존 원본·배치 프로필·자식 ID를 재작성하지 않아 완료된 요약의 재호출을 유발하지 않는다.

`MeetingBriefRepository.update_brief`는 행 잠금 안에서 저장된 JSON을 비교하고 같으면 갱신을 생략한다. 실제 변경의 이전 이력은 보존한다. 진행 상태만 바뀌어 본문 전체가 복제되는 문제는 별도 상태 저장과 데이터 이관을 필요로 하므로 이번에 과거 이력 삭제나 불완전한 상태 저장으로 대체하지 않았다. 상세 조사와 개선 순서는 `evidence/RECURRENCE_STORAGE_AUDIT_20261031/README.md`에 기록했다.

## 2026-10-31 — 정책 대상별 부모 묶음과 세부 쟁점의 분리

구조화는 `parent` 전체 문자열로 대주제를 생성하여 같은 정책의 운용 기준·재원·통제 논점까지 별도 대주제로 남았다. `report_parent_groups.py`의 순수 읽기 변환을 구조화 materialize와 narrative projection에 적용한다. 검증된 재정·산업 대상의 부모만 통합하며 자식 ID·원문 span·role·과제 링크·요약 및 요약 fingerprint를 변경하지 않는다. 원래 그룹은 `source_groups`에 보존한다.

미래기금 약칭은 같은 보고서의 상위 제목에 미래대응기금이 있을 때만 연결한다. 미래투자기금·지방소멸대응기금 등 다른 기금명이나 두 기금의 비교는 임의로 동일시하지 않는다. 대상이 불명확하거나 등록되지 않은 대주제는 기존 제목을 유지한다. 신규 통합 프롬프트에도 정책 대상은 parent, 운용·찬반 등 논점은 issue로 구분하도록 명시했다. 기존 분석 버전과 배치 응답을 무효화하지 않는다.

## 2026-10-31 — 회의 파생 읽기 재계산 축소

- 회의 구조·검토·서술의 파생 읽기를 압축 메모리 캐시로 재사용한다. 저장량은 압축 기준 32MiB와 256항목으로 제한하고 5분 후 만료한다.
- 매 조회마다 구조 수정시각·분석 배치 건수/최신 시각·원본 brief 해시를 확인한다. 원본 또는 분석 이력이 바뀌면 즉시 다시 계산한다. 응답 객체는 호출자마다 분리한다.
- 완료된 진행 상태만 재사용하며, pending/retry 진행 판단은 매번 계산한다. 원본 응답·이전 버전·모델 응답·공식/AI 구분은 변경하지 않는다.
- 방송·자막·알림 워커의 주기와 모델 호출 정책은 변경하지 않는다. 회의 후처리 워커만 원본 보존 후 전환한다.


## 2026-10-30 — PoC11 시각 검사 게이트웨이

PoC11은 meter token 검증을 통과한 `user_consented_image` 요청에 한해 `image-observation`, `image-verification`, `text-ocr`, `text-ocr-recheck` 작업을 허용한다. 모델은 `nvidia/nemotron-3.5-super-vl:free`로 제한해 이미지가 텍스트 전용 fallback으로 전달되지 않게 한다. 기존 공용 요청 원장과 한도는 유지한다. 독립 OCR 경로는 PoC11에서 기본 비활성화하며, 별도 사용 신청 없이 기존 PoC7 수집 작업의 동작을 바꾸지 않는다.


## 2026-10-27 — 내부 분류값을 정상 쟁점으로 집계하지 않음

`UNCERTAIN`은 발언 역할 코드이며 주제 제목이 아니다. 신규 원문 분류는 `strict_labels=True`로 실질 역할의 내부값 제목을 거부한다. 과거 응답은 기본 읽기 검증으로 보존하고, `discussion-placeholder-review/1` 프로필로 해당 근거만 재분류한다. `automatic_review.invalid_label_atom_count`와 pending 수에 포함하므로 요약만 완료됐다는 이유로 품질 검증을 통과하지 않는다. 원문이 실제로 끊긴 경우는 UNCERTAIN 역할로 보존하며 추정 연결하지 않는다.

LIVE 묶음의 REVIEW_REQUIRED 상태는 일부 원문만 불명확한 경우도 포함한다. 화면에는 final_topic_ids 유무로 주제 연결 여부를 설명하고 별도 보존된 원문을 구분한다. 기존 원문 연결 상태·모델 응답은 숫자를 보기 좋게 만들기 위해 덮어쓰지 않는다.

## 2026-10-27 — 세부 요약 재시도 원인과 작업 순서 보존

세부 요약은 원문 검증 오류 뒤 Gemini/Groq의 가용성 오류가 남으면 마지막 오류만 보고 일시 실패로 판단해 30분 냉각을 반복했다. 첫 단일 쟁점 요청 라운드에서 NARRATIVE_* 오류가 한 번이라도 있었다면 기존 교정 라운드로 전환한다. 교정 라운드 자체의 횟수 제한은 유지하며 성공 결과를 무효화하지 않는다. `pending_batches`는 현재 재시도 가능한 요청을 앞에 배치해 쿨다운 항목이 `batch_limit`을 독점하지 못하게 한다. 숫자 검증을 완화하지 않고, 원문에 존재하는 숫자 표기 목록과 표기 보존 지시를 모델에 제공한다.

## 2026-10-27 — 보고서 단계별 완료 수와 Groq 모델 평가

`brief.finalization.stages`에 단계별 key/status/completed/total/unit을 작게 저장하고 `brief_progress.stages`로 목록과 상세 화면에 전달한다. 목록 조회 때 원문·구조화 결과를 다시 전부 읽지 않는다. 구조화 워커의 전환 시점에 현재 저장 결과로 갱신하며 원문 해시·AI 응답은 변경하지 않는다. 숫자는 진행 중 요청 수가 아닌 검증된 저장 완료 수다. 재검토 발언의 집합 차이로 완료 수를 산정하고, 총수는 새 대상 발견 시 변할 수 있음을 안내한다. 완료 후 임시 단계 태그는 제거하며 공식 결과가 생겨도 비공식 완료 태그는 유지한다.

Groq 공식 무료 표의 GPT-OSS 120B·20B·Qwen 3.8 27B는 동일한 8K TPM 제한이므로 모델 변경을 긴 입력 해결책으로 간주하지 않는다. 가상 한국어 발언 비교 결과 및 계정 가용성은 `GROQ_MODELS_AND_PROGRESS_20261027.json`에 기록한다. 비교 실패를 계정 전체 가용성 문제로 혼동하지 않도록 400/404는 짧은 대기만 적용한다. 401/403의 긴 대기, 429의 공급자 지시, 로컬 10만 토큰/400회 예산은 보존한다.

## 2026-10-26 — 보고서 진행률은 실제 분석 구간 기준

목록 태그는 `brief_progress.completed_chunks / total_chunks`를 사용한다. 이는 전체 보고서 완료율이 아니며 구간 분석 후 REDUCING/SYNTHESIZING이 남으면 계속 정리중이다. 상태가 COMPLETED인 과거 진행률을 새 보고서의 진행률로 재사용하지 않는다. 화면에서 종료 후 고정 2시간 대기를 추정하지 않고 실제 처리 단계와 재시도 상태를 표시한다.

## 2026-10-26 — 송출 상태와 회의 목록의 지속성 분리

공식 채널의 `is_live=false`는 정회·재개 대기에도 나타난다. 이를 저장 회의의 종료로 해석하지 않는다. 프런트엔드는 공식 회의 external ID와 미종료 저장본을 연결하고 실시간/보고서 양쪽 목록에 정회·누적 저장본을 표시한다. 공식 목록에 없는 최근 저장본은 송출 상태 확인 중으로 표시하며 DB 생명주기와 원문은 변경하지 않는다. 진행 중인 회의의 저장 보고서가 PROCESSING이어도 완료 상태를 조작하지 않고 저장된 내용을 볼 수 있게 한다.

사용량 카드는 사용자에게 잔여 비율만 보여주며 서비스에 설정한 배정량과 공급자 전체 무료 잔여량을 동일시하지 않는다. 요청 횟수와 토큰의 다중 제한, 예약 중 사용량을 모두 반영한다. 정보 누락을 잔여 100%로 간주하지 않는다. NIM 표시 제외는 사용자의 명시적 요청이며 실제 공급자 우선순위 변경은 아니다.

## 2026-10-26 — Gemini 무료 프로젝트 확인 및 활성화

사용자가 Google AI Studio 키의 결제 미연결 상태를 확인했다. 앞서 운영 프롬프트 품질 검증을 통과한 `gemini-3.1-flash-lite`를 활성화하며, 긴 한국어 입력에 더 여유가 있는 Gemini를 보조 풀에서 Groq보다 앞에 둔다. NIM·OpenRouter 우선과 OpenAI 소진 확인 조건은 유지한다. 자격증명은 설치 시 PoC7 자체 `.env`로 복사하며 다른 PoC를 실행 시점 의존성으로 삼지 않는다. PoC7의 일일 30만 토큰·200회 하위 예산과 15초 간격, 공급자 429 대응 정책을 적용한다. 활성화 후 API 사용량에도 Gemini를 표시한다.

## 2026-10-26 — 독립 자격증명과 제한된 무료 보조 모델

PoC4 모듈·DB·부모 `.env`를 PoC7 런타임에서 읽지 않는다. 설치 시 검증된 Groq 자격증명만 PoC7 소유 설정으로 복사했다. 회의 분석 공용 풀과 브리프 전환에 보조 모델을 넣되 NIM 우선·OpenRouter 소진 확인·OpenAI 기존 토큰 예약 정책을 보존한다. Gemini 어댑터는 준비했지만 무료 프로젝트 확인 전 비활성화한다.

Groq 실제 응답 헤더는 1,000 requests / 8,000 tokens 제한을 알렸다. 공식 문서의 무료 모델별 분당·일일 제한과 계정 응답을 함께 참고하며, PoC4 설정의 65만 토큰을 계정 보장치로 간주하지 않는다. PoC7에 10만 토큰/400회/65초/7천 예약 토큰의 보수적 하위 예산을 둔다. 다른 앱과 공유하는 계정 총량은 공급자가 집행하며 이 로컬 예산은 전역 무료 잔여량이 아니다.

`auxiliary_model_calls` 예약을 외부 호출 전에 커밋하고 모델 사용량으로 정산한다. DB 자문 잠금과 provider pacing으로 모든 프로세스의 동시 예약을 직렬화한다. 실패·강제 종료는 사용량을 낙관적으로 환급하지 않는다. 공급자 429에 명확한 일일 소진 정보가 있을 때만 다음 초기화까지 대기하고 보통 429는 짧은 속도 제한으로 처리한다. 입력 크기 제한은 근거 생략으로 해결하지 않는다. 상세 요약은 전체 쟁점 단위의 검증된 부분 저장을 재사용한다.

근거: [Groq 제한](https://console.groq.com/docs/rate-limits), [구조화 출력](https://console.groq.com/docs/structured-outputs), [Cloudflare 가격](https://developers.cloudflare.com/workers-ai/platform/pricing/), [Gemini 가격](https://ai.google.dev/gemini-api/docs/pricing). 실제 검증 기록은 `AUXILIARY_MODELS_20261026.json`.

## 2026-10-26 — OpenAI는 무료 풀 품질 실패가 아닌 OpenRouter 한도 소진 후에 허용

- 기존 기본 브리프 경로는 NIM 우선 및 OpenRouter 소진 후 OpenAI 정책을 지켰으나, topic_structure_worker.clients 공용 풀은 OpenAI를 항상 포함했다. 구조화·재분류·온톨로지·상세 요약의 검증 실패가 곧 유료 모델 전환으로 이어졌다. 사용자 기존 요구와 달라 동일 정책으로 통일한다.
- 공용 풀은 NIM을 첫 번째로 두고 OpenRouter 가용 상태가 True/None이면 OpenRouter만 다음 후보로 둔다. False(소진 확인)일 때만 OpenAI를 허용한다. 일시적 오류·RPM 제한·JSON/언어/숫자 검증 실패는 한도 소진과 구별한다. OpenAI 예약 시 다시 검사해 UTC 초기화 직전 생성한 클라이언트가 초기화 후 무료 풀을 우회하지 못하게 한다.
- NIM 일부 응답만 검증 실패하면 이미 유효한 쟁점을 저장하고 실패 쟁점만 다음 실행에서 분리한다. 성공 부분을 포함한 전체 요청을 다른 모델로 재전송하지 않는다. 제한된 재시도와 원본 응답·source fingerprint 기록은 유지한다.
- 과거 요약 보완은 기본 보고서 생성·구조화·재분류를 처리한 다음 실행한다. 해당 회차에 새 분류 작업이 있거나 실패하면 과거 보완은 다음 회차로 미룬다. 생방송 우선 보호와 UTC 00:00 한도 초기화는 그대로 유지한다.
- 오늘 행안위 화면의 3묶음은 미연결 실시간 주제 묶음, 7건은 원문 재분류 항목이다. 서로 다른 단위이며 합산하지 않는다. 점검 중 7→3→0건으로 자동 처리됐고 최종 46묶음 연결·5묶음 절차·미연결 0으로 확인했다.

## 2026-10-26 — 생성 요약의 언어 오류는 원문과 분리해 검증한다

- 생방송 자막에는 박덕흠·박주민·위원장직무대행이 한글로 존재했으나 AI 응답에는 임의 영문 조각과 한자가 있었다. JSON 형식 검사만으로는 표시 품질을 보장할 수 없어 요약 계약 2.2에서 모든 사용자 표시 필드를 검사한다.
- 한자는 생성 요약에서 허용하지 않으며, 영문은 실제 자막 문맥에 등장한 약어·고유명사만 허용한다. 원문을 일괄 치환하거나 깨진 이름을 추정하지 않는다. 한 항목만 실패하면 정상 항목을 먼저 저장하고 실패 항목을 기존 분할·5분 재시도 정책으로 처리한다.
- 오류 응답은 `transcript_summary_rejections`에 원문 문맥과 함께 추가 보관한다. 공급자가 모델을 대체할 수 있으므로 요청 모델과 별개로 실제 `response_model`도 기록한다. 과거 사용량에 요청 모델만 저장된 기록으로 실제 대체 모델을 단정하지 않는다.
- 캐시는 최신 버전을 우선하고 명백한 오염을 재사용하지 않는다. 이미 표시된 오늘 방송 9건은 자막에 직접 근거한 교정본을 추가하고 이전 행과 원문 해시를 보존했다. 절차적 발언 요청은 정책 과제로 재분류하지 않는다. 과거 모든 캐시의 일괄 재생성이 완료됐다는 의미는 아니다.

## 2026-10-26 — 상세 쟁점과 주요 논의 요약의 포함 범위를 일치시킨다

- 기존 `report_summary`는 구조화 이전 AI 브리프의 일부 요약을 보존했다. 추가로 분류된 쟁점이 요약에 반영되지 않아 요약 24개와 상세 쟁점 155개 사이에 실제 내용 누락이 생겼다. 동일 발언 ID가 공유된다는 이유만으로 요약에 포함됐다고 판정하지 않는다.
- `structured-narrative/1.2`은 쟁점별 원문과 역할을 입력으로 요약·세부 발언 요약을 생성한다. 모든 쟁점 ID와 발언 구간 ID를 검증하고 원문 복사·제목 대체·없는 근거를 거부한다. 의미와 사실 일치는 AI 검토의 한계가 있으므로 원문 추적을 유지한다.
- 완성된 요약만 기존 대주제 → 소주제 → 발언 요약 카드 형식으로 전환한다. 미완성 또는 원문 fingerprint가 바뀐 결과는 적용하지 않는다. 기존 모델 응답·원본·분류·과제는 덮어쓰지 않고 기존 구조화 batch 이력에 입력·응답을 추가한다. 직접 연결된 과제는 해당 쟁점 카드에 표시하며 연결 미확정 기존 과제는 이전 요약 카드와 함께 보존한다.
- 외부 원문 전송에 대한 자동 승인 검토 차단 후 사용자가 공소청 보고서 1건만 명시적으로 승인했다. 최초 실행은 보고서 ID를 요구하는 별도 명령으로 제한했다. 이후 사용자가 다음 날 재개를 요청하여 명시 등록한 작업만 기존 워커에서 이어서 처리하도록 보완했다. 기존 NIM → OpenRouter → OpenAI 경로와 사용량 한도, 회의별 잠금, 제한된 재시도를 사용한다.

- 인사이트 찾기는 서버 전체 목록 필터 후 페이지 처리한다. 현재 화면에 로딩된 10개만 필터링하지 않는다. 검색 갱신 시 요청 취소와 세대 번호 검증을 함께 사용해 늦은 이전 결과가 새 검색에 섞이지 않게 한다.

## 2026-10-22 — 기존 분류 뒤에 원문 검증 어휘를 추가하고 전체 인사이트를 페이지 조회한다

- 기존 제목/요약 키워드, 문맥 대조, 검증된 AI 의미 분류를 우선한다. 세 경로에서 미연결인 항목에만 `ontology_extensions.py`의 최신 보고서 표현을 적용한다. 대상 키·도메인·임계값·분모·회의 상태는 변경하지 않는다.
- 새 어휘도 현재 쟁점과 저장된 해당 발언의 검증 가능한 원문 구간이 함께 지지해야 한다. 짧은 일반 답변, 잘못된 원문 위치, 서로 다른 복수 대상은 보류한다. ‘양형의 적정성’처럼 조사 변형은 명시적 동의 표현만 허용한다. 원본/모델 응답은 재작성하지 않고 조회 시 파생 그룹에만 반영한다.
- 인사이트는 기존 전체 projection에 `offset`, `limit`을 적용한다. 제도화 필터는 페이지를 나누기 전에 적용한다. 화면은 10개만 요청하고 목록과 상세를 별도 dialog로 두어 목록 스크롤을 보존한다. 팝업 종료 시 진행 중 요청을 취소한다.

## 공식 대조본에도 현재 잠정 구조화 연결을 별도로 제시한다

- 결정일: 2026-10-19
- 공식 대조본의 기존 LIVE→요약 계보를 그대로 보존하되, 현재 구조화 결과를 함께 조회해 `live_topic_resolution`으로 제공한다. 기존 묶음 ID와 원문 발언 집합이 모두 일치해야 하며 다른 보고서 버전·중복 ID·없는 쟁점은 완료로 표시하지 않는다.
- 연결된 쟁점으로 이동하는 버튼과 남은 검토 원문 버튼을 제공한다. 이전에 연결됐던 묶음에도 불확실한 분류가 있으면 전체 추가 검토 수에 포함한다. 절차성 분류는 정책 연결과 구분하고 원문 접근을 유지한다.
- 실제 원문의 방안·계획서·대책안 제출 요구를 공통 자료 제출 과제에 포함한다. 요청하지 않은 문장이나 화면 제시 요구를 자료 제출로 간주하지 않는다. 구조화 projection은 1.2이며 저장 모델 응답은 보존한다.

## 온톨로지 1.15 · 짧은 단어로 구성된 정책 표현도 원문 일치로 검증한다

- 결정일: 2026-10-19
- 기존 제목 단독 분류와 원문·모델 응답은 유지한다. 문맥 분류용 정책 표현을 보강하고, 사전에 등록된 구체적 표현이 쟁점 제목과 해당 쟁점의 검증된 원문에 모두 존재하면 단어별 3글자 제한 때문에 제외하지 않는다. 표현은 공백·기호 제거 후 최소 4글자이며 여러 대상이 동시에 뒷받침되면 보류한다.
- `주택 가격`, `세제 개편`처럼 각 단어가 짧은 경우를 지원한다. 인접 발언이나 다른 쟁점의 답변을 가져오는 규칙은 추가하지 않는다.
- 기관·장소와 정책 쟁점을 구분한다. `소화기 내과`와 소방용 소화기, 의사 면허와 운전면허, 채용비리와 일반 공무원 채용을 혼동하지 않도록 구체 표현과 회귀 사례를 적용한다.
- AI 인용을 임의로 고치거나 판정을 승인하지 않는다. 원문과 다른 인용, 문맥 없는 짧은 응답은 계속 보류한다. 변경별 근거와 과거 분류 변화는 `ONTOLOGY_TERMS_20261019.json`에 기록한다.

## ADR-070 · 최종 합성 밖의 검증 가능한 실시간 쟁점을 잠정 읽기 모델로 복원한다

- 상태: Accepted
- 결정일: 2026-10-16
- 원인: 10월 15일 군사법원 국감 방송에는 법제처·군사법원 등 여러 세션이 함께 들어 있다. 최종 합성의 24개 주제 상한과 로컬 승격 상한 때문에 앞부분 쟁점이 대부분을 차지하고 군판사·군내 도박 등 뒤쪽 독립 쟁점이 빠졌다. 온톨로지 분류 보류와 LIVE→최종 주제 계보 미연결은 별도 지표다.
- 결정: 모델 최종 합성의 상한은 유지한다. 공개 잠정 보고서 조회에서 `UNMAPPED`이고 제목의 구체적인 정책 대상 및 저장된 발언 ID가 있는 항목만 `LIVE_TOPIC_SUPPLEMENT` 보완 쟁점으로 추가한다. 기존 핵심 주제·근거·저장 원본은 보존하고, 보완 내용을 공식 자료로 승격하거나 다른 핵심 쟁점에 억지로 배정하지 않는다. 교차 후보·진행 발언·모호한 표현은 계속 검토 대상으로 둔다. 정책별 상위 묶음 아래 개별 쟁점·근거를 유지한다.
- 분류: 온톨로지 1.12에 군 사법·군사기밀/방첩·군 시설 보상·군 불법도박을 독립 대상으로 추가한다. 전작권은 한미동맹·연합방위로 정리하고 최근 국감에서 확인한 법령해석·보조생식술·따릉이 유출·생활폐기물 등의 구체 표현을 보강한다. 짧은 범용어만으로 보완을 승인하지 않는다.
- 무결성: 최종 합성에서 유효하지 않은 항목을 버려 번호에 빈자리가 생기면 `len(topics)+1` ID가 기존 항목과 충돌할 수 있었다. 새 승격 ID는 LIVE cluster 기반으로 만든다. 과거 중복 ID는 근거 발언 우선으로 각각 분리하고, 어느 쪽인지 확인할 수 없는 참조는 교차 검토에 남긴다.
- 권위: 복원은 잠정 보고서 API·Markdown·근거 보기·온톨로지의 같은 읽기 모델에 적용한다. 현재 공식 대조본에는 자동 추가하지 않는다. `SUPPLEMENTARY_EVIDENCE`는 누락 실시간 쟁점 자체의 근거 보존 상태이며 기존 모델의 의미 연결 성공을 뜻하지 않는다. 화면과 다운로드에 잠정·공식 대조 필요를 표시한다.
- 검증: 42개 보고서 표본에서 기존 950개 주제를 유지하고 잠정 보고서 22건에 331개 보완 쟁점을 추가한다. 기존 정책 주제 939개를 같은 분모로 비교하면 사전 분류 887→916개, 보류 52→23개다. 보완 포함 정책 주제는 1,270개이므로 기존 분류율과 단순 비교하지 않는다. 군사법원은 주제 밖 78→17(단일 발언 64→16), 보완 61, 교차 2→3이며 근거가 없는 기존 연결 한 건을 교차로 되돌린 결과다. 원본 보고서 변경·추가 LLM 호출은 없다. 상세는 `ONTOLOGY_REVIEW_20261016.json`에 남긴다.

## ADR-069 · 온톨로지 1.11과 회의별 자료 제출 과제 묶음

- 상태: Accepted
- 결정일: 2026-10-14
- 온톨로지: 공개 보고서의 제목·요약에서 정책 대상이 명확한 표현만 기존 노드에 보강한다. 교정시설·수용자 처우와 우주개발·발사체는 다른 정책 대상에 억지로 넣지 않고 독립 노드로 둔다. 국정감사 개시·업무보고만 묘사한 주제는 근거를 유지한 절차 산출물로 분리한다. 공식 원문이 아직 없거나 문장이 모호한 나머지 주제는 계속 보류한다.
- 무결성: 과거 제44회 국무회의 저장 보고서에서 서로 다른 주제 두 개가 `topic-18`을 공유했다. LIVE 계보의 주제명과 일치하는 항목에 기존 ID를 남기고 다른 항목에 읽기 모델 전용 ID를 부여한다. 과제는 근거 발언으로 다시 연결하고 원본 보고서·계보는 덮어쓰지 않는다. 계보 대상이 불명확하면 자동 보정하지 않는다.
- 과제: 한 회의 안의 독립적인 자료·서류·보고서 제출 요구는 파생 `follow_up_task_groups`에서 `자료 제출 요구` 한 과제로 표시한다. 제출 대상, 기관, LIVE·공식 근거, 원래 과제 ID는 하위 항목으로 보존한다. 출석, 제도 개선, 공개, 검증처럼 별도 행위가 섞인 과제와 완료 과제는 묶지 않는다. 원본 `tasks`는 그대로 두고 보고서 화면과 Markdown에 같은 묶음을 적용한다.
- 검증: 2026-10-14 운영 보고서 40건의 읽기 전용 표본에서 정책 주제 892개 중 분류 836개·보류 56개·절차 산출물 10개·무결성 오류 1건이, 새 규칙 재계산 시 정책 주제 891개 중 분류 859개·보류 32개·절차 산출물 11개·무결성 오류 0건으로 바뀌었다. 저장 원본과 외부 모델 호출량은 바뀌지 않는다.

## ADR-068 · KJON 공인 도메인을 PoC7 내부 API에 독립 연결한다

- 상태: Accepted
- 결정일: 2026-10-10
- 결정: `kjon.aigov.go.kr` 전용 Nginx 80/443 가상호스트를 추가하고 루트 경로를 `127.0.0.1:18070`의 PoC7 API에 연결한다. 웹 자산과 API가 상대 경로를 사용하므로 외부 주소에 `/poc/national-assembly`를 노출하지 않는다. 기존 `minslab.kr` 가상호스트와 통합 앱의 `/poc/national-assembly/` 경로는 유지한다. 독립 인증서의 HTTP-01 검증은 `/var/www/letsencrypt`에서 처리한다.
- 보안: 새 공개 호스트에서는 통합 앱의 관리자 세션을 사용할 수 없으므로 `/api/live/` 쓰기를 Nginx에서 차단한다. 알림 세션 쿠키는 새 호스트 응답에서만 `Path=/`로 변환하고, 백엔드는 명시된 새 호스트에 한해 쓰기 요청 Origin과 Kakao callback URI를 선택한다. 임의 Host/Origin을 허용하지 않는다.
- 외부 의존성: Kakao Developers의 기존 앱에 `https://kjon.aigov.go.kr/api/watch/kakao/callback`을 추가 등록해야 새 호스트의 실제 로그인 교환을 검증할 수 있다. 등록 전에는 인증 URL 생성까지만 확인한다. 발송되는 기존 알림 메시지의 링크는 기존 `WATCH_PUBLIC_BASE_URL`을 유지한다.
- 롤백: 새 가상호스트 링크만 비활성화하고 Nginx 문법 검사 후 reload하면 기존 서비스는 그대로 남는다. API 이전 이미지는 `poc07-national-assembly-api:pre-kjon-20261010` 태그로 보존한다.

## ADR-067 · 온톨로지 1.10은 근거가 드러나는 표현만 보강한다

- 상태: Accepted
- 결정일: 2026-10-08
- 결정: 공개 보고서의 제목·요약에 정책 대상이 확인되는 경우에만 온톨로지 키워드를 추가한다. 공무원 인사·처우는 공직 후보자 검증과 별도 대상으로 두고, 기존 도메인 지도에 한 번만 배치한다. 재검표, 후원금 기록, 소방 대응, 정보보호, 양형기준과 허위 답변 정정은 각각의 정책 대상으로 분리한다. 범용 기관명이나 `회계보고`처럼 다른 정책에도 쓰이는 단어는 분류 근거로 삼지 않는다.
- 운영 확인: 공개 보고서 33건의 정책 주제 729개 중 분류 700→712건, 보류 29→17건이고 그룹 무결성 오류는 없다. 최신 행안위 보고서의 보류 11건은 모두 제목 또는 요약의 구체적 근거 표현으로 분류됐다. 남은 17건은 정책 대상을 안전하게 확정할 수 없어 보류하며 저장된 원본 보고서나 LIVE 주제 계보 연결은 바꾸지 않는다.

## ADR-066 · 최종 합성에 실시간 주제를 전달하고 완료본은 근거 기준으로 선택 재검토한다

- 상태: Accepted
- 결정일: 2026-10-07
- 결정: 회의 최종 합성 입력에 이미 계산한 LIVE 주제 묶음을 포함한다. 모델은 최종 주제와 정책 대상·쟁점·요구 조치가 같은 묶음만 연결하며, 다른 쟁점이나 회의 진행 발언을 임의로 연결하지 않는다. 24개 핵심 주제 상한과 근거 ID 검증은 유지하고, 보고서 프롬프트를 `assembly-meeting-brief/2.0`으로 구분한다.
- 결정: `auto` 공급자 경로는 같은 자막 커서의 완료 AI 보고서를 프롬프트 버전 변경만으로 일괄 재생성하지 않는다. 필요한 과거 보고서는 원본 행을 보존한 채 근거를 검토해 새 버전으로만 보정한다. API의 갱신 대기 표시는 새 프롬프트 작업이 실제 `PROCESSING` 또는 `DEFERRED`일 때만 사용한다. NIM의 긴 최종 합성은 한 번 시간초과되면 기존 경쟁 풀의 OpenRouter로 넘겨 반복 5분 대기를 막는다.
- 운영 확인: 10월 6일 법사위 보고서는 LIVE 60묶음 중 31묶음이 최종 주제 밖에 남았다. 단순 재생성은 수치를 22로 줄였으나 제목 손상과 핵심 쟁점 누락이 있어 표시본에서 제외했다. 기존 정상 보고서의 중복 주제 3쌍을 병합하고 근거가 확인된 독립 쟁점 3개를 보강하며 안전한 계보 연결 7건을 적용한 새 버전은 24개 주제, 추가 자동 연결의 근거를 검토하고 약한 연결 1건을 제외한 최종 수치는 연결 39·교차 1·미연결 20묶음이다. 남은 항목은 별도 근거로 보존한다.

## ADR-065 · 회의 보고서는 NVIDIA NIM 우선 경쟁 풀로 처리한다

- 상태: Accepted
- 결정일: 2026-10-07
- 결정: `MEETING_BRIEF_PROVIDER=auto`에서 PoC7 전용 NVIDIA 키와 활성화 플래그가 있으면 직접 NIM `nvidia/nemotron-3-ultra-550b-a55b`를 먼저 사용한다. NIM 요청 실패 시 같은 보고서를 OpenRouter 공용 게이트웨이로 넘긴다. OpenRouter 예약량이 운영 상한 950회에 이른 경우에만 OpenAI `gpt-5.4-mini`로 넘긴다. OpenRouter 일시 오류만으로 OpenAI를 쓰지 않는다.
- 결정: NIM 요청은 워커 안에서 최소 6초 간격으로 보내며 429 발생 시 2분간 NIM 선택을 쉬고 OpenRouter가 이어받는다. PoC4와 키를 공유하므로 계정 전체 RPM을 이 간격만으로 보장하지 않는다. 공급자 변경 시 원문 해시와 분석 버전이 같은 검증된 청크를 재사용한다. 완료한 AI 보고서는 공급자 전환을 이유로 다시 생성하지 않는다.
- 결정: NIM 키는 PoC7 전용 `.env`와 회의 보고서 워커에만 둔다. API에는 활성화 여부와 모델명만 전달한다. NIM 직접 호출의 토큰·횟수는 고유 요청 ID 기준 월 장부에 기록하고 상세 모델 사용량에 표시하되, 확인되지 않은 RPM·크레딧 한도를 수치로 표시하지 않는다.
- 검증: 합성 한국어 회의 4개 발언의 전체 청크 분석·최종 합성 2회에서 JSON 스키마, 근거 검증, 최종 주제 2개·과제 2개가 통과했다. 실제 국회 긴 회의의 품질이나 계정의 장기 무료 사용량을 입증한 것은 아니다.
- 이용 조건: NVIDIA 무료 API Catalog는 시험용이며 계정별 호출량이 달라진다. 실제 한도는 NVIDIA 계정 화면에서 확인한다. <https://forums.developer.nvidia.com/t/nvidia-nim-faq/300317>, <https://assets.ngc.nvidia.com/products/api-catalog/legal/NVIDIA%20API%20Trial%20Terms%20of%20Service.pdf>
- 이전 결정: ADR-063의 OpenRouter→OpenAI 순서를 이 결정의 NIM→OpenRouter→OpenAI 순서로 대체한다.

## ADR-064 · 정책 온톨로지 분류와 실시간 주제 계보 연결을 분리해 보정한다

- 상태: Accepted
- 결정일: 2026-10-07
- 온톨로지: 현재 공개 보고서의 제목·요약과 공식 근거 유무를 대조해 정책 대상이 특정되는 표현만 assembly-meeting-topic-grouping/1.9에 추가한다. 과거사 피해 회복은 별도 노드로 두고, 원유는 에너지 정책, 농가 면세유는 농업 정책으로 구분한다. 문장이 깨졌거나 대상 기관이 모호한 항목은 보류하며, 원본 보고서는 다시 생성하지 않는다.
- 계보: 보고서의 ‘미연결’은 최종 주제와 LIVE 주제 묶음의 연결 상태로, 온톨로지 분류 보류와 별도로 집계한다. OpenAI 보고서 생성 시 기존 의미 연결 검증을 실행한다. 일일 토큰 부족이면 실패로 확정하지 않고 나중에 재검토한다. 이미 생성된 최근 OpenAI 보고서는 새 보고서가 없고 UTC 일일 잔여 토큰이 150,000 이상일 때 한 주기 한 건씩 재검토한다. 연결은 기존 근거·정책어 검증을 통과한 경우만 확정하고, 최종 주제를 재생성하거나 미연결을 강제로 0으로 만들지 않는다.
- 이유: 10월 6일 국감 보고서의 계보 미연결 39·86묶음은 직접 OpenAI 생성 경로에서 의미 연결 단계를 건너뛴 영향이 있으며, 온톨로지 사전을 늘리는 것만으로 줄어들지 않는다.

## ADR-063 · 회의 보고서는 OpenRouter 공용 상한 이후 OpenAI 직접 호출로 복구한다

- 상태: Accepted
- 결정일: 2026-10-07
- 결정: 회의 보고서는 OpenRouter 공용 게이트웨이의 UTC 일 예약량이 운영 상한 950회에 이르면 PoC7 전용 키의 `gpt-5.4-mini` 직접 호출로 전환한다. 게이트웨이 상태를 확인할 수 없을 때도 OpenAI를 선택한다. 발언 요약과 다른 워커의 공급자는 바꾸지 않는다.
- 결정: OpenAI 입력·출력 토큰은 UTC 날짜별 데이터베이스 장부에서 요청 전에 보수적으로 예약하고 응답 후 실제 사용량으로 확정한다. UTF-8 바이트 예약만으로 한도에 걸리면 공급자 입력 토큰 계산값에 8,192토큰 여유를 더해 재예약한다. PoC7 직접 호출은 하루 650,000토큰을 넘길 수 없으며 사용량 불명 요청은 예약량을 계속 점유한다. 계정의 다른 프로젝트 사용량과 무료 혜택 적용 여부는 이 장부가 보증하지 않는다.
- 결정: 기존 OpenRouter 청크 분석은 원문 해시와 프롬프트 버전이 맞으면 OpenAI 보고서에서 재사용한다. `auto`와 OpenAI 복구 모드에서는 이미 완료한 AI 보고서를 공급자만 바뀌었다는 이유로 재생성하지 않는다. 생성 보고서의 근거 ID 검증과 임시 자료 권위 표시는 유지한다.
- 결정: OpenAI 키는 PoC7 전용 환경 파일과 회의 보고서 워커에만 주입한다. API는 모델명·토큰 한도와 사용량만 읽는다.
- 이유: 공용 무료 요청 한도 소진 시 종료된 방송의 보고서가 계속 `정리중`에 머무르지 않게 하면서 사용자 지정 일일 토큰 상한을 지키기 위해서다.

## ADR-062 · 종료 digest 정리는 일괄 삽입 뒤 실행하고 오래된 외부 알림은 보내지 않는다

- 상태: Accepted
- 결정일: 2026-10-02
- 한 워커 실행에서 조회한 종료 세션의 digest와 앱 내 알림을 모두 저장한 뒤 구독자별 보존 한도 정리를 한 번 실행한다. 조회 도중 다음 세션을 삭제하는 FK 오류와 전체 트랜잭션 재시도를 막는다.
- 자막 시각 또는 방송 종료 시각이 처리 시점보다 6시간 넘게 지난 경우 Kakao outbox는 만들지 않는다. 감지 이력과 앱 내 알림은 기존 규칙에 따라 보존한다. 테스트 출처의 Kakao 허용 규칙은 유지한다.
- 국감 운영 점검은 컨테이너 실행 상태 외에 `watch_worker_state.event_cursor`와 `transcript_segment_revisions`의 최대 커서 차이, 반복 오류, outbox 대기·실패를 확인한다.
- 이유: 배포 후 점검에서 알림 워커가 3.7일간 동일 FK 오류를 반복하며 새 자막 2,300건을 처리하지 못했고, 그대로 재개하면 오래된 Kakao 알림이 한꺼번에 발송될 수 있었다.

## ADR-061 · 온톨로지는 현재 공식 대조본을 우선하고 근거 불명 주제는 보류한다

- 상태: Accepted
- 결정일: 2026-09-27
- 읽기 모델: 공개 보고서 목록과 같은 수집 범위를 사용하고 `poc07.demo`·`poc07.test`·재생 출처는 제외한다. 국회는 대상 3개 위원회와 본회의만 포함한다. 방송별 최신 보고서에 대해 현재 연결된 공식 문서 ID, 같은 보고서 ID, `READY`, 임시 업데이트 유예 아님을 모두 만족하는 통합본만 온톨로지의 입력으로 사용한다. 하나라도 어긋나면 보존된 LIVE/STT 초안을 사용한다. 보고서별 공식·초안 사용 건수를 분리해 공개하고 추가 LLM 호출이나 정기 재생성은 하지 않는다.
- 분류: 운영 보고서 전수에서 확인된 재생에너지, 주택, 예산, 농업, 수사, 지역 인프라 등 명확한 정책 대상 표현을 온톨로지 1.7에 추가한다. 질의자 교체·인사 발언 등 정책 대상이 아닌 생성 산출물은 근거와 주제 ID를 보존한 채 별도 품질 지표로 분리한다. 문장이 깨졌거나 대상이 모호한 항목은 정책 분류를 강제하지 않는다.
- 2026-10-02 보완: 온톨로지 1.8은 같은 회의의 지방의회·정책지원관 논의를 단일 정책 대상으로 묶고 동물보호를 별도 대상으로 둔다. 법안은 `가결`·`개정안` 같은 절차어보다 제목의 정책 대상을 우선한다. 현재 근거로 정책 대상을 알 수 없는 요지는 동적·제목 보류 그룹에 남기며, 원본 보고서를 다시 생성하지 않는다.
- 화자 표기: 공식 대조본의 개별 발언 항목은 현재 공식 원문의 화자·문장을 표시한다. LIVE 초안에서 온 주제 요약에 남은 `화자 N`은 공식 이름으로 추정하지 않고 중립 표현으로 표시하며, 초안 원문과 상태를 별도 필드에 보존한다.
- 이유: 이전 온톨로지는 공식 대조 완료 보고서도 초안 JSON만 읽고 있었고, 요약 문장의 익명 번호가 공식 발언의 확정 이름처럼 보일 수 있었다.

## ADR-060 · 자정을 넘긴 국회 방송은 시작일과 회차로 공식 회의록을 연결한다

- 상태: Accepted
- 결정일: 2026-09-26
- 회의 식별: 국회 방송의 공식 회의록 후보는 서울 시각의 방송 시작일, 위원회, 회의 차수가 모두 일치해야 한다. 종료일은 다음 회의일 수 있으므로 출처 연결 날짜에 사용하지 않는다.
- 오연결 복구: 제438회 제3차 예결위 방송에 잘못 붙은 제4차 회의록 연결은 제거하고 원본 문서 버전은 실제 제4차 publication으로 이전했다. 잘못된 발언 대조는 `CONFLICT`로 남겨 현재 화자 표기에서 제외한다. 제3차 방송은 고유한 `N054404`에 다시 연결한다.
- 읽기 일치: 회의 보고서 API는 현재 공식 문서 ID의 통합본만 선택한다. 과거 다른 문서의 `READY` 결과가 새 회의록의 대조 중 상태를 완료처럼 보이게 하지 않는다.
- 이유: 회의가 자정에 끝나거나 다음 차수가 즉시 시작되면 종료일만으로는 서로 다른 회의의 공식 발언을 섞게 된다.

## ADR-059 · 완료된 주제별 보고서는 공개 읽기 모델로 제한 보존한다

- 상태: Accepted
- 결정일: 2026-09-23
- 공개 범위: `READY` 주제별 보고서는 생성 요청 계정이나 현재 브라우저 세션과 관계없이 목록·상세·Markdown을 읽을 수 있다. 공개 응답에는 `subscriber_id`와 upstream `usage_metadata`를 포함하지 않는다.
- 비공개 작업 상태: `PENDING`·`PROCESSING`·`FAILED`·`LIMIT_REACHED`는 요청자 세션에서만 조회한다. 생성 권한, Kakao 연결, 사용자·전체 일일 한도는 기존대로 유지한다.
- 보존: 완료본은 `generated_at` 기준 최근 30일 안의 최신 50건만 저장한다. 생성 완료와 공개 목록 조회 시 같은 정책으로 정리하고, 마이그레이션 시 기존 만료본도 한 번 정리한다. 30일을 넘긴 미완료·실패 작업 레코드도 제거한다.
- 모델 관측: 공급자·모델 상세에는 gateway의 영문 workload 코드를 사용자 기능명으로 변환해 주제별 보고서 생성, 회의 보고서 생성, LIVE-최종 주제 연관관계 분석, 공식 보고서-LIVE 초안 변화 분석을 함께 표시한다.
- 이유: 공개 회의 근거로 만든 결과를 계정별 사일로에 가두지 않으면서 저장량과 개인정보 노출을 제한하고, 보고서 계열의 실제 모델 사용을 운영 화면에서 빠짐없이 관측하기 위해서다.

## ADR-058 · AI 한도와 장애 예비는 공급자 단위로 관리한다

- 결정: 사용량 화면의 한도는 OpenRouter 공식 1,000회/UTC 일(운영 안전선 950회)과 Mistral 월 $10을 공급자별로 한 번만 표시한다. Nemotron·Dots·Liquid·Mistral Small·Voxtral은 각 공급자 아래의 모델별 사용 내역으로만 표시한다.
- 이유: 같은 공급자의 여러 모델은 같은 계정 한도와 장애 경계를 공유하므로 모델마다 한도를 반복 표시하면 독립 여유가 있는 것처럼 오해할 수 있다.
- 장애 예비: OpenRouter 내부 모델 교체는 모델 종료·형식 오류 보정에는 사용할 수 있지만 플랫폼 장애나 공용 무료 한도 소진의 예비 경로로 보지 않는다. 자동 장애 예비로 승격하려면 별도 공급자 자격 증명, 독립 장부, 동일 품질 계약과 원문 전송 승인을 모두 갖춰야 한다.
- 현재 상태: PoC 7에서 직접 사용하는 독립 플랫폼은 OpenRouter와 Mistral이다. 회의 보고서는 OpenRouter 기본, Mistral Small 직접 호출을 수동 콜드 스탠바이로 구성한다. 자동 전환은 Voxtral STT와 공유하는 월 $10를 예기치 않게 소진할 수 있어 사용하지 않는다. NVIDIA Nemotron은 OpenRouter 경유이며 NVIDIA NIM 직접 호출은 아니다. PoC 4에 남은 NVIDIA·Groq·Hugging Face 자격 증명은 PoC 7 사용량으로 합산하지 않는다.

## ADR-057 · 온톨로지 정책 커버리지와 보고서 산출물 품질을 분리한다

- 상태: Accepted
- 결정일: 2026-09-21
- 정책 분류: 운영 최신 보고서 전수 감사에서 반복 확인된 성폭력·범죄피해자 보호와 소비자·금융사기 보호를 독립 정책 대상으로 등록한다. 증인 협의·의결 절차·군 복무·공직자 재산 검증 등 명확한 누락어만 기존 대상에 추가하고, 뜻이 깨졌거나 대상이 없는 제목은 강제 분류하지 않는다.
- 산출물 분리: `사실 관계 확인`, 발언자 교정, 가정 질문 거부, 화자 간 신뢰성 다툼, 불명확 반복 발언은 정책 대상이 아닌 `REPORT_ARTIFACT`로 보존한다. 원문 근거와 상세 주제는 삭제하지 않되 정책 주제 분모와 분류 보류 수에서 분리하고 보고서 품질 검토 사유로 남긴다.
- 오병합 방지: `일부개정법률안`·`개정안` 같은 법안 형식어는 동적 그룹의 공통 정책 앵커가 될 수 없다. 등록 정책 대상의 더 구체적인 직접 일치를 우선하며, 의미가 불명확한 항목은 단독 보류한다.
- 설명 가능성: `assembly-meeting-topic-grouping/1.6`은 온톨로지로 분류한 각 세부 주제에 실제 일치 keyword·title/summary 필드·결정 점수를 남기고 스타맵에서 실제 사용 keyword와 건수를 공개한다. 조회 시 결정적으로 계산하며 추가 LLM 호출은 없다.
- 이유: 기존 적용률 97.1%의 미분류 30건에는 실제 정책 누락과 모델·대화 산출물이 섞였고, 법안 형식어만 같은 서로 다른 법률안이 동적 병합될 수 있었다. 분류 범위를 무작정 넓히지 않고 정책 분류 정확도와 보고서 생성 품질을 별도 관측하기 위해서다.

## ADR-056 · LIVE/STT 초안과 공식 대조본은 덮어쓰지 않고 병렬 보존한다

- 상태: Accepted
- 결정일: 2026-09-21
- 기본 읽기 모델: 공식 대조가 완료되면 회의 보고서 API의 `brief`와 화면 기본값은 공식 대조본이다. `official_brief`에도 같은 투영본을 노출하고 `provisional_brief`와 저장된 LIVE/STT 초안은 원형으로 보존한다. 공식 대조 전에는 잠정 초안이 기본이다. 마크다운 내보내기도 기본 읽기 모델을 사용한다.
- 발언 매칭: `ORDERED_BIDIRECTIONAL_CHAR_NGRAM_9_V2`는 LIVE와 공식 발언 양쪽의 문자 9-gram 포함률, 순서 역행, 후보 간 점수 차를 함께 본다. 같은 짧은 문구를 거의 전부 포함하는 후보가 여러 개면 고신뢰 exact가 아닌 한 연결하지 않는다.
- 공식 화자 보강: 24자 이상으로 정규화한 자막 조각이 이름이 있는 공식 발언 한 건에만 완전히 포함되면 `ORDERED_BIDIRECTIONAL_CHAR_NGRAM_9_V3`으로 연결한다. 여러 발언에 나타나거나 같은 자막 revision에 서로 다른 화자가 연결되면 보류한다. `official_brief`에서 근거와 함께 확인된 화자명만 같은 주제·요지 ID의 기본 API 응답·화면·마크다운에 표시하며 초안 내용은 보존한다. 임시회의록 이름은 잠정으로, 정본 이름은 정본 근거로 구분한다. 정본과 임시회의록의 과거 완료 건은 이미 확인된 이름을 보존하면서 `official-reconciliation/1.6-speaker-exact/1` 파생 버전으로 재계산한다.
- 변경 표시: 화자별로 합쳐진 긴 LIVE 묶음이 아니라 해당 공식 발언에 실제 매칭된 원본 자막 revision만 비교한다. 공식 문장을 기준으로 표시하며 하나의 교체를 삭제+추가 두 건으로 세지 않는다. 띄어쓰기·문장부호·조사와 발언 경계의 진행 문구는 변경 수에서 제외한다. 공식 문장에서 빠진 실질적인 LIVE 문구는 삭제하지 않고 `live_only_fragments`에 별도로 제공한다.
- 원본 보존: `meeting_briefs.brief`, 자막 revision, 공식 발언 원문과 기존 통합 이력은 수정하지 않는다. `official-reconciliation/1.6`과 `official-evidence-presentation/1.3` 파생 결과만 새로 생성한다.
- 이유: 공식 회의록의 정제된 문장과 실제 방송 발언의 차이 자체가 감사·정책 분석 정보이므로 어느 한쪽으로 덮어쓰지 않되, 표기 차이와 잘못된 발언 경계를 의미 변경으로 과장하지 않기 위해서다.

## ADR-055 · 회의 보고서 읽기 경로와 최종 주제 수에 운영 상한을 둔다

- 상태: Accepted (ADR-053의 무제한 최종 주제 정책 일부 대체)
- 결정일: 2026-09-21
- 읽기 cursor: 매 목록·상세 조회에서 약 39만 건의 `TranscriptSegmentRevision`을 다시 집계하지 않는다. revision 저장 트랜잭션에서 `LiveBroadcast.source_last_event_cursor`를 단조 증가시키고 보고서 freshness 판정은 이 값을 읽는다. revision 원본과 전역 cursor는 변경하지 않는다.
- 공식 대조 집계: `final_segment_count`와 `matched_segment_count`를 `LiveBroadcast` 읽기 모델에 저장한다. 최종 자막 수는 쓰기 시 증감하고 공식 대조 배치 종료 시 대상 방송만 정합성 재계산한다. 사용자 요청 경로에서는 대용량 원본 테이블 집계 함수를 호출하지 않는다.
- 목록 순서: 종료 방송 전체에 lateral 통계를 계산한 뒤 자르지 않고, `detected_at` 기준 최신 페이지를 materialized CTE로 먼저 선택한 뒤 선택된 방송에만 발언·공식화 통계를 계산한다.
- 즉시 표시: 최초 목록은 최신 보고서 한 건의 저장 본문을 함께 반환한다. 갱신 중인 회의는 기존 완성 보고서를 숨기지 않고 새 발언 반영 중임을 표시한다. 같은 탭에서 연 회의 상세는 버전 키 기반 메모리 캐시로 재사용하고 다음 2건을 선로딩한다.
- 품질 상한: 최종 합성 주제와 로컬 승격 주제의 합은 최대 24개다. 발언 수가 큰 회의에서 86~140개의 저품질 세부 제목이 생긴 운영 결과를 사람이 검토 가능한 보고서로 취급하지 않는다. 상한 밖의 LIVE cluster는 삭제·강제 연결하지 않고 lineage의 미연결 항목으로 남긴다.
- 버전·비용: 최종 계약은 `assembly-meeting-brief/1.9`이며 기존 `1.2` 청크 캐시는 재사용한다. `1.9`는 운영 표본에서 확인된 `서영교장`, `증인 혼의`를 각각 `서영교 위원장`, `증인 협의`로 표시 단계에서 교정한다. PoC 4 중단으로 남는 공용 OpenRouter 운영 한도는 이 최종 재합성에 사용할 수 있지만 950회 안전선과 gateway 원장은 유지한다.
- 이유: 저장 원본과 근거 완전성은 유지하면서 사용자 읽기 지연과 모델의 과분할을 별도의 읽기·표시 계약으로 제한하기 위해서다.

## ADR-054 · 회의 보고서는 정책 대상과 세부 쟁점을 별도 계층으로 표시한다

- 상태: Accepted
- 결정일: 2026-09-11
- 원본 보존: 종료 보고서의 topics는 근거 발언·화자 요지·과제·공식회의록 연결의 기준이므로 합치거나 삭제하지 않고 세부 쟁점으로 보존한다.
- 상위 읽기 모델: 별도 topic_groups를 정책 대상 단위로 계산한다. 요구·비판·찬반·필요성 같은 입장과 조치는 같은 대상 아래 서로 다른 세부 쟁점으로 남기고, 인물·부처가 같다는 이유만으로 다른 정책 대상을 합치지 않는다.
- 개수: 상위 대상 수에도 고정 상한을 두지 않는다. 제439회 제5차 본회의는 61개 세부 쟁점을 18개 대상으로, 제6차 본회의는 94개를 19개 대상으로 분류했으며, 다분야 예결위처럼 정책 대상이 넓은 회의는 필요한 만큼 표시한다.
- 호환성: API 조회 때 기존 보고서에도 topic_groups를 결정적으로 계산하고 새 보고서는 저장 시 함께 기록한다. 화면과 Markdown은 대상 주제 → 세부 쟁점 순서로 표시하며 상위 대상을 선택하면 모든 하위 근거의 합집합을 제공한다.
- 비용·실패 격리: assembly-meeting-topic-grouping/1.0 정책 대상 사전과 제목 대상부 fallback만 사용하므로 추가 LLM 호출과 비용은 0이다. 분류표 밖의 제목은 유사해 보인다는 이유로 강제 병합하지 않는다.
- 이유: 실시간 cluster 누락을 막기 위해 보존한 세부 쟁점 수와 사람이 훑어볼 보고서의 상위 목차 수를 같은 값으로 취급하지 않기 위해서다.

## ADR-053 · 종료 보고서 주제 수와 실시간 계보 연결은 서로 분리한다

- 상태: Accepted
- 결정일: 2026-09-11
- 주제 수: 최종 핵심 주제에 고정 상한을 두지 않는다. 중간 분석의 독립 쟁점이 4개를 넘으면 절반 이상을 최소 보존하되 실제 의미 중복만 합치며, 최종 출력 스키마와 서버 검증에서도 배열을 자르지 않는다.
- 연결 단계: 근거 ID와 결정적 유사도 연결을 먼저 적용한 뒤 남은 미연결·교차 cluster만 최종 주제 ID에 배정하는 OpenRouter Dots 3 Note 구조화 요청을 보고서당 한 번 실행한다. 추론은 비활성화하고 다른 모델로 자동 전환하지 않으며, 이 요청은 기존 제목·요약·주제·과제를 수정하지 않는다.
- 안전성: HIGH·MEDIUM 신뢰도이면서 양쪽에 고유 정책어·기관·대상어 교차가 있는 결과만 연결한다. LOW, 생략, 잘못된 ID, 중복 ID와 의미 근거 없는 고신뢰 결과는 미연결로 보존한다. 같은 최신 보고서는 매핑 버전과 입력 hash를 기록해 자동 재호출하지 않으며 실패도 보고서 생성 실패로 전파하지 않는다.
- 로컬 완결: 새 종료 보고서에서 의미상 연결되지 않은 실시간 cluster는 저장된 cluster 제목과 원문 근거 ID를 가진 독립 최종 주제로 승격한다. 실시간 단계에서 이미 중복 병합된 cluster를 실제 쟁점 단위로 사용하며, 외부 모델에 추가 내용을 보내거나 관련 없는 주제로 강제 연결하지 않는다.
- 범위와 비용: backfill은 행안위·법사위·예결위·본회의와 국무회의의 최신 AI 보고서만 대상으로 하며 비대상 위원회는 제외한다. OpenRouter 무료 모델을 사용하고 보고서당 upstream 요청은 1회다.
- 보고서 모델: 다른 텍스트 요약 workload의 모델은 유지하고 회의 보고서의 청크·병합·최종 합성만 `MEETING_BRIEF_MODEL`로 분리한다. 추론을 끈 Dots 3 Note를 첫 시도와 형식 재시도에 모두 사용해 Nemotron·Liquid의 강제 추론이 4% 구간에서 진행을 오래 막는 경로를 피한다. 허용되지 않는 영문 잔여는 첫 응답부터 결정적으로 정리한다.
- 버전: 최종 합성 계약은 `assembly-meeting-brief/1.7`, 연결 계약은 `assembly-live-topic-mapping/1.1`로 기록하고 기존 `1.2` 청크·병합 캐시는 재사용한다.
- 이유: 장시간 회의를 16개 주제로 강제 축약하지 않으면서도, 세부 실시간 신호를 최종 합성 프롬프트에 섞어 응답 실패를 키우지 않고 별도의 작고 검증 가능한 단계로 연결하기 위해서다.

## ADR-052 · 국회 실시간 범위는 3개 위원회와 본회의로 한정

- 상태: Accepted
- 결정일: 2026-09-10
- 결정: 상시 수집 위원회는 행정안전위원회·법제사법위원회·예산결산특별위원회만 허용하고 본회의는 별도 국가 회의체로 포함한다.
- 결정: `정기회`·`정기국회`·`국정감사`·`국감` 문구만으로 다른 위원회를 포함하지 않는다. 감시 parser, 요약·종료 보고서 작업 큐, 사용자 종료 회의 목록에 같은 allowlist를 적용한다.
- 결정: 과거 잘못 수집된 비대상 위원회의 raw·자막·파생 보고서는 감사 이력으로 보존하되 사용자 목록과 신규 자동처리에서 제외한다.
- 일정 표시: 전체 위원회 일정을 제공하는 달력에서는 위 수집 범위 밖 위원회에 `PoC7 생방송 수집 대상 외`를 표시한다. 일정에 있다는 사실만으로 방송 시작이나 수집 완료를 암시하지 않는다.
- 이유: 회기 명칭은 모든 위원회 제목에 나타날 수 있어 이를 범위 판정에 사용하면 3개 위원회 계약이 무력화된다.

## ADR-051 · 공용 OpenRouter 게이트웨이와 자막 우선 상태 머신

- 상태: Accepted
- 결정일: 2026-09-09
- 호출 제어: POC4·POC7은 한 API key와 SQLite 원장을 가진 게이트웨이를 사용한다. UTC 일 1,000회 중 50회를 안전 여유로 남기고, 모든 실제 upstream 시도는 성공 여부와 무관하게 센다. 분당 18회·동시 4회 우선순위 큐를 사용한다.
- 우선순위: 기본 모델과 공식 수집은 OpenRouter 부스터보다 우선한다. 700회부터 부스터/백필, 850회부터 비필수 생성, 950회부터 전 호출을 차단한다. POC4 단건은 기본 모델의 결과를 가로채지 않고 30초 지난 잔여 단건만 처리한다.
- 모델 경계: POC7의 공개 텍스트 생성은 OpenRouter, 음성 전사는 Mistral Voxtral이다. 외부 전송은 공개 공식자료로 한정하고 모델·공급자·요청 수를 기록한다.
- 자막 상태: `OFFICIAL_CAPTION → DEGRADED → AI_STT → RECOVERING → OFFICIAL_CAPTION`을 영속 상태로 관리한다. 45초 무수신에 STT를 시작하고, 공식 수신 재개 후 90초 안정 구간을 확인해야 복귀한다.
- 구조화 응답: HTTP 2xx라도 `json_schema` 응답 본문이 완결된 JSON 객체가 아니면 성공 캐시에 넣지 않고 실패 시도로 기록한다. 회의 보고서 워커는 Nemotron 형식 실패 때 출력 축약 지침을 추가하고, 형식 실패·공급자 400·5xx·timeout 요청은 짧은 청크·병합이면 Liquid, 긴 최종 통합이면 Dots 3 Note로 최대 2회 재시도한다. 409 중복 처리 중과 429 한도 응답은 같은 모델로 대기 재시도한다. 보조 모델에는 추론 비활성화 파라미터를 보내지 않으며, 정상 완료 청크와 기본 통합 모델은 그대로 유지한다.
- 주제·과제 축소 방지: 최종 통합은 중간 분석에 남은 주제와 과제 수를 기준으로 각각 최대 4개의 최소 개수를 계산한다. 최종본이 이보다 적으면 저장하지 않고, 정책 대상·소관·요구 조치가 다른 논의를 분리하고 근거가 있는 실행 과제를 복원하라는 전용 지침으로 재생성한다.
- 요약 품질 경계: 보고서 전체 요약과 주제 요약의 원문 복사·비정상 외국어는 결과 전체를 거절한다. 화자별 요지 하나만 같은 문제가 있으면 해당 요지만 제외하고 근거가 유효한 주제와 나머지 요지는 보존한다.
- 결과 이력: 위 품질 계약은 `assembly-meeting-brief/1.6`으로 구분해 기존 파생 보고서를 덮어쓰지 않고 새 결과로 저장한다. 같은 입력·모델·프롬프트 버전의 결과를 불변으로 다루는 저장 계약은 유지한다.
- 단계별 캐시: 변경되지 않은 청크 분석·병합 프롬프트는 `assembly-meeting-brief/1.2` 캐시를 계속 사용하고, 최종 통합 결과 버전만 `1.6`으로 올린다. 최종 품질 정책 변경 때문에 장시간 회의의 모든 청크를 다시 외부 전송하지 않는다.
- 표시 정제: 알려진 혼합 한자·비정상 영문 잔여는 결정론적으로 정리하고, 담당 부처 배열에 `EXPLICIT`·`INFERRED` 같은 소유 근거 enum이나 영문 오염값이 들어오면 제외한다. 유효 부처가 없으면 `owner_basis`는 `UNCONFIRMED`로 낮춘다.
- 미등록 한자 조각이 전체·주제 요약에 남으면 결과를 저장하지 않고 한국어 재서술을 요청하며, 화자별 요지에만 남으면 해당 요지만 제외한다.


## ADR-050 · 공식 대조는 완료 건 순회가 아닌 영속 상태 큐로 처리

- 상태: Accepted
- 결정일: 2026-09-04
- 배경: UUID순 `LIMIT 5`가 이미 완료된 회의를 계속 선택해 뒤 회의가 영구 대기했고, 회의 기준으로 먼저 수집한 공식 본문은 나중에 생성된 LIVE publication과 연결되지 않았다. 또한 한 자료의 파싱 오류가 해당 실행의 후속 대조까지 중단했다.
- 결정: 최신 `(meeting_brief_id, official_document_id, integration_version)`에 READY 결과가 없을 때만 작업을 생성하고 PostgreSQL lease와 `FOR UPDATE SKIP LOCKED`로 선점한다. 대조 워커는 공식자료 수집과 분리해 15초마다 실행하며 오류는 작업별 지수 백오프로 재시도한다.
- 자료 연결: `meeting_id + conference_id`가 정확히 일치할 때만 publication 없는 보존 본문을 연결한다. 공식 링크·본문의 도착 순서와 동일 source version 충돌에 관계없이 비어 있는 `publication_id`를 채우되 원본과 이전 버전은 삭제하지 않는다.
- 비용·표시: 이미 READY인 동일 입력은 외부 LLM을 다시 호출하지 않는다. 화면은 게시·본문·큐·처리·재시도·완료 단계를 분리하고 현재 공식문서와 통합 결과의 문서 ID가 같을 때만 완료로 간주한다.

## ADR-049 · 국무회의 결과는 발화 주체와 자료 출처별로 분리한다

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 대통령실 브리핑의 관련 문단을 부처보고 요약에 덮어쓰고 같은 문단에서 지시 문구를 추출해 `부처보고 내용`과 `대통령 지시`가 사실상 같은 문장으로 반복됐다.
- 결정: 국무회의 보고 주제는 `부처 보고 내용`, `대통령 지시`, `부처 추가 발표`를 별도 필드와 시각 영역으로 유지한다. 대통령 문단과 부처 추가 발표는 부처 보고 내용을 덮어쓸 수 없다. 심의안건은 보고 주제와 분리한다.
- LIVE 결합: 회차·서울 날짜로 공식 자료와 연결된 LIVE 비공식 보고서에서 구체 주제명이 보수적으로 일치할 때만 부처 보고 내용으로 사용하고 PROVISIONAL임을 표시한다. 동점·저신뢰 또는 지시 문구와 유사도 0.72 이상이면 연결하지 않고 공식 결과문에서 확인된 보고 제목·담당 부처만 표시한다.
- 중복 억제: 같은 보고에 연결된 대통령 지시는 대상 부처와 함께 보고 카드 안에 표시한다. 연결되지 않은 공식 지시만 별도 목록에 두며 대통령실 브리핑 전체를 다시 나열하지 않는다.
- 비용·권위: 공식 원문, 기존 LIVE 보고서와 결정론 규칙만 사용하므로 추가 LLM 호출은 0회다. 공식 보고 제목·부처, 대통령 지시, 부처 발표는 OFFICIAL이고 LIVE 요약은 PROVISIONAL이다.

## ADR-048 · 기관 간 타임라인은 구체 주제의 보수적 연결만 허용

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 대분류와 일반 단어를 사용한 V3 규칙이 중대범죄수사청 시행령과 선거 특별검사법을 수사로, 국가재정운용계획과 경찰 인력 배분 발언을 예산으로 잘못 연결했다.
- 결정: 공개 타임라인에서 ADR-020의 대분류 연결을 사용하지 않는다. 정부 공식 안건과 국회 최신 회의 보고서의 구체 주제 사이에 제목 고유어가 직접 일치하거나, 소관기관이 같으면서 일반어를 제외한 복수 핵심어가 일치할 때만 후보를 만든다.
- 보수성: 수사·예산·재정·법률·법안·제도·정책·지원 같은 일반어는 단독 근거가 될 수 없다. 후보가 없으면 빈 타임라인을 정상 결과로 제공하며 LLM이나 제목 유사 생성으로 보완하지 않는다.
- 권위·비용: 연결은 SPECIFIC_REPORT_TOPIC_TOKEN_V1 · PROVISIONAL · DRAFT이며 인과관계가 아니다. 조회 LLM 호출은 0회다.

## ADR-047 · 쟁점 추세와 제도화 전환의 단위는 구체 회의 주제

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 법무·사법, 재정·예산 같은 대분류의 증감은 어느 정책이 반복되거나 제도화되는지 설명하지 못한다.
- 결정: 종료 회의별 최신 잠정 보고서 또는 공식 통합 보고서의 topics를 읽고, 구체 주제명·요약의 결정적 의미 토큰 유사도로 같은 쟁점을 묶는다. 간사 선임·개의·산회 같은 절차 주제는 제외하고 최근 14일과 이전 14일의 고유 방송 회의 수를 비교한다.
- 추세: 이전 14일 0회는 최근 횟수와 무관하게 신규다. 급증은 이전 1회 이상, 최근 3회 이상이며 2배 이상 증가한 경우로 제한한다. 양 기간에 모두 관측되되 급증 조건이 아니면 지속, 이전에만 있으면 최근 미관측이다.
- 단계: 연결 과제가 있으면 **후속 과제 도출**, 개정안·법률안·시행령 표현이 있으면 **보고서상 법안·제도개편**, 가결·의결·통과·시행 완료 표현이 있으면 **보고서상 의결·시행**, 공식 발언 근거 ID가 회의별 의안에 직접 연결되면 **공식 의안 직접 연결**로 표시한다. 직접 의안 연결 전의 상태는 발의 확인이나 실제 이행 완료를 뜻하지 않는다.
- 권위·비용: 주제와 과제는 PROVISIONAL 파생 읽기 모델이며, 공식 통합본이 있으면 이를 우선한다. 화면 조회와 재계산은 저장 자료만 사용해 LLM 0회다. 인과관계·영향·가결 가능성은 생성하거나 추정하지 않는다.

## ADR-046 · 공식화 변화는 최소 문구 패치와 설명 전용 LLM으로 제공

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 공백 단위 diff는 띄어쓰기 하나가 달라져도 이후 문장을 전부 교체한 것처럼 표시했고, 공식 문체로 전체 재작성하면 비공식 결과에서 무엇이 실제로 바뀌었는지 추적하기 어려웠다.
- 결정: 공백·문장부호를 제외한 문자 정렬로 동일 구간을 찾고, 이동한 삭제·삽입 문장을 짝지어 그 내부만 다시 비교한다. 동일 구간은 비공식 원문을 그대로 보존하며 공식 근거가 달라진 최소 문자 구간만 패치한다. 긴 문장의 정규화 유사도가 0.58 미만인 전체 재작성 후보는 본문 적용을 막고 공식 대안과 설명만 비교 카드에 둔다.
- 의미 보존 경계: 개조식·서술식과 독립 문장 순서 변경은 숫자·부정·결정/행위의 종류와 횟수, 정규화 의미 토큰, 기관·내용·행위가 묶인 의미 단위가 모두 같을 때만 문체 변경으로 제외한다. 단어 집합이 같아도 담당 기관과 행위가 교차되면 실제 변경으로 유지한다.
- LLM 경계: OpenRouter는 서버가 검증한 change ID, 전후 문구와 화자 통계만 받아 최대 6개 변화로 묶는다. 새 변경 판정·정책 사실 생성·근거 없는 ID 반환을 허용하지 않으며 결과는 입력 hash·모델·프롬프트 버전으로 저장한다.
- 비용·보안: 변경 0건은 호출 0회, 나머지는 공식 통합본당 1회다. 공식화 변화 전용 100회/UTC 일과 공용 500회/UTC 일을 함께 제한하고 공개 근거만 개인정보 패턴 제거 후 전송하며 data collection 거부와 provider fallback 금지를 요구한다.
- 버전 업그레이드: 동일한 공식 의미 해시와 이전 검증 변경 목록이 있으면 최신 결정론 비교 규칙으로 다시 필터링·패치해 새 파생 버전으로 저장한다. 이 재계산은 Mistral·OpenRouter 호출 0회이며 원본과 이전 통합 버전은 보존한다.
- 파생 인사이트: 추가기능의 타임라인은 공식 저장 자료를, 쟁점 증감과 논의→제도화는 회의별 최신 저장 보고서·공식 통합본의 구체 주제를 사용한다. 14일 회의 수와 근거가 확인된 전환 단계만 보여주며 원인·영향·가결 여부를 추론하지 않는다. 조회 LLM 비용은 0회다.

## ADR-045 · 부채형 의석도는 집계 설명 도구로 한정

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 정당별 의석수를 넓은 부채형 좌석도로 보면 연합 규모를 직관적으로 비교할 수 있지만, 실제 본회의장 지정석이나 좌우 이념 위치로 오인할 수 있다.
- 결정: 마지막 정상 `assembly_reference` 스냅샷의 정당별 집계만으로 6개 반원 열을 브라우저에서 그린다. 정당 순서는 공식 API 집계 건수 순이며 이념 또는 실제 좌석 위치를 뜻하지 않는다.
- 상호작용: 복수 정당을 선택해 합산하고 재적 과반, 3/5, 2/3의 산술 비교선을 보여준다. 각 기준은 용도가 다른 예시이므로 실제 안건 가결 가능성을 판정하거나 예측하지 않는다.
- 비용·접근성: SVG와 정족수 계산은 클라이언트 결정론 로직으로 수행해 외부 API와 LLM을 추가 호출하지 않는다. 정당 범례 버튼을 키보드 선택 수단으로 제공하고 모바일에서는 SVG를 화면 폭에 맞춰 축소한다.

## ADR-044 · 추가기능의 공식 읽기 모델과 무료 운영

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 월간 일정과 의석 현황은 일반 정보이지만 변동 가능하고, 페이지 조회마다 국회 API를 호출하면 장애 결합과 불필요한 무료 API 사용이 생긴다.
- 결정: 달력은 canonical `ScheduleEntry`를 최대 42일 범위로 읽고, 의석은 API key를 가진 schedule worker가 `ALLNAMEMBER` 원본 전체를 하루 한 번 raw-first 수집해 공개 집계 스냅샷을 만든다. API와 브라우저는 외부 국회 API를 직접 호출하지 않는다.
- 현역 규칙: 현행 대수가 `GTELT_ERACO`에 포함되고 `DTY_NM`이 비어 있지 않은 의원만 집계한다. 정당과 선출구분은 현행 대수 위치의 공식 API 값을 사용하며 임의로 현재 정당을 추정·통합하지 않는다.
- 장애·비용: 수집 실패 시 마지막 정상 스냅샷을 유지한다. 페이지 조회 LLM 0회, 외부 API 0회이며 의원 API는 최대 하루 한 차례만 호출한다.
- 개인정보 최소화: 공개 화면 스냅샷에는 집계값과 raw version hash만 넣고 의원 연락처·보좌진 정보는 복제하지 않는다.

## ADR-043 · 주제별 보고서 대표 논점의 결정적 순위

- 상태: Accepted
- 결정일: 2026-09-02
- 배경: 생성 모델이 반환한 첫 항목을 크게 표시하면 순서의 이유를 사용자에게 설명할 수 없고, 회의에서 반복적으로 다뤄진 논점이 대표 항목에 반영되지 않을 수 있다.
- 결정: 대표 논점은 관련성 30, 근거 권위·회의 범위 20, 언급 빈도 20, 정책 영향 15, 후속조치 10, 최근성 5의 합산 점수로 클라이언트에서 안정 정렬한다. 동점은 생성 결과의 원래 순서를 보존한다.
- 언급량: 잠정·통합 회의 보고서는 주제, 화자 요점, 연결 과제의 고유 `evidence_ids` 합집합을 사용한다. 공식 안건은 발언 빈도를 알 수 없으므로 항목당 1건만 인정한다. 한 장시간 회의가 순위를 독점하지 않게 보고서 안의 최댓값을 기준으로 로그 정규화한다.
- 설명 가능성: 화면에 총점과 여섯 항목 점수를 표시하고, 도움말에 고유 발언 근거와 공식 근거 건수를 보여준다. 순위 계산은 저장 자료만 사용하며 LLM을 호출하지 않는다.
- 결과: 대표 논점의 선정 이유를 재현할 수 있고, 검색·열람 때 추가 토큰 비용이 발생하지 않는다.

## ADR-042 · PoC 7 Kakao 나에게 보내기의 독립 운영 경계

- 상태: Accepted
- 결정일: 2026-08-31
- 배경: 초기 구현은 provider와 DB는 분리했지만 앱 키·암호화 키 이름과 배포 스크립트가 부모 `.env` 및 PoC 4 이름을 참조해 PoC 7 폴더만으로 운영 구성을 재현할 수 없었다.
- 결정: 런타임은 `WATCH_KAKAO_*`와 PoC 7 `.env`만 읽는다. OAuth state, 암호화 토큰, outbox, 재시도 및 연결 해제는 PoC 7 PostgreSQL 안에서 처리한다. 연결 해제는 로컬 계정과 outbox만 중단하고 앱 전체의 Kakao 원격 unlink를 호출하지 않는다. 환경 생성 도구는 PoC 7 전용 `WATCH_KAKAO_*`만 허용하고 다른 PoC의 앱 키를 자동 이관하지 않는다.
- 동의 검증: token 응답만 신뢰하지 않고 Kakao scope 조회 결과를 함께 확인해 `talk_message`가 없으면 계정을 저장하지 않는다.
- 결과: PoC 4 장애·토큰·배포 변경이 PoC 7 알림에 영향을 주지 않는다. 운영 자격증명은 별도 Kakao 애플리케이션을 사용하며, 전환 전 임시 공유 상태에서도 PoC 7의 연결 해제가 다른 서비스 토큰을 폐기하지 않는다.

- 결정: 자막 endpoint와 메시지 schema가 확인돼도 실제 대상 방송 handshake 전에는 `READY_TO_CAPTURE`로만 표시하며 `OFFICIAL` 발언으로 승격하지 않는다.
- 이유: 방송 시작 탐지 지연을 제한하면서 불필요한 요청을 줄이고, 접근 가능성 추정과 실제 발언 수집 성공을 구분한다.

## ADR-009 · 서버 소유 방송 생명주기

- 상태: Accepted
- 결정: 방송 감지·자막 수집·종료 처리·리뷰 생성·공식본 대조는 브라우저가 아니라 상시 worker가 수행한다.
- 결정: 중간 입장자는 DB snapshot과 event cursor를 먼저 받은 뒤 같은 cursor 이후의 실시간 delta를 구독한다.
- 결정: 종료 후 PROVISIONAL 리뷰와 게시 후 OFFICIAL 본은 LIVE 기록을 덮어쓰지 않고 함께 보존한다.
- 이유: 홈페이지가 닫혀 있어도 방송 처음부터 기록하고, 중간 입장·종료 후 입장·공식본 게시 시점에 동일 회의를 연속적으로 제공해야 한다.

## ADR-010 · 자막 원본 우선 저장과 DB lease

- 상태: Accepted
- 결정: 각 WebSocket 메시지를 raw artifact로 먼저 저장한 뒤 `TranscriptSegmentRevision`과 source version으로 연결한다.
- 결정: caption worker 소유권은 만료 가능한 PostgreSQL lease로 관리하고 대상 3개 위원회와 본회의가 겹치는 경우까지 최대 네 연결을 허용한다.
- 결정: final segment는 늦게 도착한 partial 또는 과거 수신시각 메시지로 현재 텍스트가 후퇴하지 않게 한다.
- 이유: worker 재시작·중복 실행·메시지 재전송 상황에서도 provenance와 현재 읽기 모델의 일관성을 유지해야 한다.

## ADR-011 · Snapshot cursor와 delta polling

- 상태: Accepted
- 결정: 중간 입장 시 snapshot cursor를 먼저 고정하고 cursor 이하 최신 segment를 반환한 뒤, 이후 revision은 전역 단조 증가 cursor로 조회한다.
- 결정: 현재 통합 프록시가 streaming response를 버퍼링하므로 UI는 2초 delta polling을 사용하고 전송 실패 시 같은 cursor로 재시도한다.
- 이유: 브라우저 접속 이전 기록과 접속 이후 자막 사이의 누락을 막으면서 현재 배포 경로에서도 확실하게 동작해야 한다.

- 상태: Accepted
- 결정: 종료 60초 후 final 자막만 주제별로 묶고 가장 긴 발언 원문을 대표 발언으로 선택한다.
- 결정: 모든 리뷰 주제는 대표 revision과 포함 revision 전체를 evidence로 가지며 `PROVISIONAL · AUTO REVIEW`로 표시한다.
- 결정: 매거진과 방송 기록에는 실제 수집 방송의 리뷰만 표시한다.
- 이유: 생성형 요약 없이도 종료 후 리뷰 흐름을 검증하면서 원문에 없는 내용을 만들어내지 않고 실제·합성 자료를 구분해야 한다.

## ADR-013 · 공식 게시와 본문 대조 상태 분리

- 상태: Accepted
- 결정: 공식 회의록 API의 위원회·서울 날짜 후보가 하나일 때만 방송과 `CONF_ID`를 연결한다. 후보가 없거나 복수이면 강제 연결하지 않는다.
- 결정: 회의록/PDF 링크 게시 확인은 `PUBLISHED`, 본문 미수집은 `LINK_ONLY`, 문장 대조는 `UNRESOLVED`로 각각 분리한다.
- 결정: 최근 30일 미게시 방송을 1시간 간격으로 다시 확인하고 원본과 source version을 보존한다.
- 이유: 공식 문서가 게시됐다는 사실과 LIVE 자막 문장이 공식본과 일치한다는 판단은 서로 다른 검증 단계다.

## ADR-014 · 공식 회의록 HTML source span 우선

- 상태: Accepted
- 결정: 공식 회의록시스템의 `type=view` HTML을 raw-first 저장하고 발언자 ID·문장 ID를 source span으로 사용한다. PDF/HWP는 HTML 계약 장애 시 검증할 fallback으로 둔다.
- 결정: 화면에 임시회의록으로 명시된 본문은 공식 사이트 자료이더라도 `PROVISIONAL`로 저장하고 정본 게시 시 새 버전을 `OFFICIAL`로 추가한다.
- 결정: LIVE final 문장은 정규화 후 길이 20자 이상이며 공식 문장 후보가 정확히 하나인 exact substring일 때만 자동 `MATCHED`로 기록한다.
- 이유: PDF 페이지 단위 추출보다 공식 HTML의 문장 ID가 더 정밀한 provenance를 제공하며, 잠정본을 정본으로 오인하거나 유사도만으로 발언을 강제 연결하는 일을 막아야 한다.

## ADR-015 · 공식 본문과 LIVE 방송 연결의 선택성

- 상태: Accepted
- 결정: 공식 회의록 본문은 `Meeting`에 필수 연결하고 `BroadcastOfficialPublication`은 실제 LIVE 방송 기록이 있을 때만 선택적으로 연결한다.
- 결정: 대상 위원회의 최근 공식 본문은 방송 기록 유무와 무관하게 수집해 위원회 행의 발언 상세에서 제공한다.
- 이유: 과거 공식 회의 자료의 탐색 가능성과 향후 LIVE→공식본 reconciliation을 한 모델에서 지원하되, 존재하지 않는 방송을 만들어내지 않아야 한다.

## ADR-016 · 공식 발언 인사이트는 검토 전 파생 데이터

- 상태: Accepted
- 결정: 공식 문장의 주제·관련 부처는 versioned 결정적 keyword rule로 생성하고 `OfficialUtteranceAnnotation`에 `PROVISIONAL · DRAFT`로 저장한다.
- 결정: UI는 공식 원문 상태와 자동 분류 상태를 별도 라벨로 표시하고, 분류 chip은 탐색 필터로만 사용한다.
- 이유: 현재 단계에서 근거 없는 생성형 요약을 도입하지 않으면서 국정 흐름 탐색을 제공하고, 공식 사실과 자동 해석의 혼동을 막아야 한다.

## ADR-017 · 기관명 masking과 정책 발언 전용 흐름 집계

- 상태: Accepted
- 결정: 주제·부처 keyword matching 전에 대상 위원회 정식명·약칭을 가려 기관명 자체가 정책 근거가 되지 않게 한다.
- 결정: 각 결과에 일치 keyword와 POLICY/PROCEDURAL/OTHER 유형을 보존하고 위원회 행의 핵심 흐름에는 POLICY만 집계한다.
- 결정: 부처 연결은 공식 소관 확정이 아니라 keyword 기반 `RELATED · PROVISIONAL · DRAFT`로 표시한다.
- 이유: “법제사법위원회 개회”를 법무부 정책으로, “예산결산특별위원회 개회”를 기획재정부 정책으로 오인한 실제 사례를 제거하고 사용자가 자동 분류 근거를 확인할 수 있어야 한다.

## ADR-018 · 통합 정책 흐름은 최신 공식 본문 기반 읽기 모델

- 상태: Accepted
- 결정: 세 위원회 비교는 회의별 최신 `OfficialTranscriptDocument`의 POLICY annotation만 실시간 집계하고 별도 요약 사실로 저장하지 않는다.
- 결정: 주제 강도는 해당 주제가 연결된 고유 발언 수이며 한 발언이 여러 주제에 연결되면 각 주제에 포함될 수 있음을 UI에 전제한다.
- 결정: 대표 근거는 생성 요약 대신 해당 주제의 가장 긴 공식 원문 발언과 source span을 사용한다.
- 이유: 원문·annotation 변경이 즉시 흐름에 반영되고, 파생 집계의 중복 버전 문제와 생성형 요약의 왜곡을 피하면서 사용자가 근거로 이동할 수 있어야 한다.

## ADR-019 · 발언-안건-의안은 명시적 번호 일치만 자동 연결

- 상태: Accepted
- 결정: 공식 발언의 `agenda_item_ref=itemN`과 같은 Meeting의 공식 `agenda_name` 접두 번호 `N.`가 정확히 같을 때만 `MATCHED · EXACT_ITEM_REF_AGENDA_PREFIX · 1.0`으로 저장한다.
- 결정: item0, 번호가 없는 안건, 회의별 의안 API에 없는 안건은 제목 유사도로 강제 연결하지 않는다.
- 결정: 정책 카드의 표결은 연결된 외부 BILL_ID와 검증된 본회의 표결 BILL_ID가 같을 때만 결합한다.
- 이유: 발언의 정책 주제에서 실제 입법 결과까지 연결하되 회의 안건 순서가 불명확한 자료를 잘못된 의안에 붙이지 않아야 한다.

## ADR-020 · 기관 간 정책 연결은 양쪽 공식 근거와 규칙 관계를 분리

- 상태: Accepted
- 결정: 국무회의 공식 안건과 국회 공식 발언에 동일한 versioned 정책 taxonomy가 적용된 경우만 기관 간 후보를 만든다.
- 결정: 법무·사법과 재난·안전처럼 일반 단어의 오연결 위험이 큰 주제는 별도의 강한 근거 단어가 일치할 때만 노출한다.
- 결정: 양쪽 원문은 각각 `OFFICIAL` 근거로 표시하되 동일 주제와 공통 근거 단어가 확인된 관계만 `EXACT_SHARED_TOPIC_AND_KEYWORD_V3 · PROVISIONAL · DRAFT`로 표시한다. `지방`, `행정`, `공무원`, `법률`, `법무`, `사법`, `안전` 같은 광범위 단어만 겹치는 관계는 제외한다.
- 결정: 날짜 순서는 사실 그대로 표시하되 인과관계를 주장하지 않으며, 의안은 국회 발언 쪽에 명시적으로 연결된 경우로 범위를 한정해 표시한다.
- 이유: 공식 자료가 양쪽에 존재한다는 사실이 두 기관의 공식적인 인과·소관 관계를 뜻하지 않으므로, 탐색 가능한 연결과 확정된 사실을 혼동하지 않아야 한다.

## ADR-021 · 의안 설명은 공식 PDF 구획 원문만 사용

- 상태: Accepted
- 결정: `ALLBILLV2.PDF_URL1`의 첫 번째 공식 PDF를 redirect 계약에 따라 수집하고 원본·hash·parser version을 보존한다.
- 결정: `제안이유`, `제안설명의 요지`, `주요내용`, `전문위원 검토보고의 요지`처럼 문서에 명시된 구획만 페이지 span과 함께 추출하며, 구획이 없으면 생성 요약으로 보완하지 않는다.
- 결정: 공식 자료 worker가 매시간 같은 URL도 다시 확인하고 content hash가 변경되면 기존 문서를 덮어쓰지 않고 새 source version으로 저장한다.
- 결정: FileGate가 동일 본문 PDF의 내부 바이트를 매 요청마다 바꾸는 경우 추출 본문 fingerprint가 같으면 새 canonical 문서로 저장하지 않는다. 실제 추출 본문이 달라질 때만 새 버전으로 보존한다.
- 이유: 사용자가 의안의 취지와 주요 내용을 빠르게 읽으면서도 화면 문구를 공식 PDF 페이지까지 역추적할 수 있어야 한다.

## ADR-023 · LIVE 인사이트의 기본 단위는 발언이 아니라 주제별 질의응답

- 상태: Accepted
- 결정: LIVE 화면은 원문 자막을 보조 근거로 접고, 같은 주제에 속한 질문과 답변을 정보 중심의 한 묶음으로 표시한다.
- 결정: 후속 과제는 일반 답변에서 생성하지 않는다. 확인·검토·조치 약속이나 `해야 한다`는 요구가 회의 안에서 완료·조치·해소되지 않은 경우만 `OPEN`으로 남기며 담당 부서는 그 과제에 직접 연결된 경우에만 표시한다.
- 결정: 같은 주제의 후속 발언에서 완료·조치·처리·해소가 확인되면 자동 후보를 제거한다. 의미상 동일 여부가 불확실하면 `AUTO GROUP · DRAFT` 상태를 유지한다.
- 결정: 공식 자막에 구조 정보가 없을 때의 질문·답변·주제·과제 연결은 `AUTO GROUP · DRAFT`로 표시한다. 명시적 부처명이나 검토 근거가 없으면 담당 부서를 확정하지 않는다.
- 결정: 공식 국회 player 계약의 HTTPS HLS 주소가 있을 때만 영상을 재생한다.
- 이유: 개별 발언 나열만으로는 질의의 맥락과 후속 책임을 판단하기 어렵고, 영상·자막·구조화 결과를 같은 시점에 함께 검토해야 하기 때문이다.

## ADR-024 · 방송 상태와 공식 자료 순환은 독립된 화면 상태

- 상태: Accepted
- 결정: LIVE·예정·종료 방송은 한 줄 목록으로 관리하고, LIVE와 종료 기록 모두 선택할 때 같은 전체 폭 분석 패널을 펼친다.
- 결정: 종료 기록은 최신 1건으로 제한하지 않고 방송 이력 API로 최근 N건을 노출하며, 방송 ID별 저장 자막·질의응답·미해결 과제를 다시 조회한다.
- 결정: 국무회의·국회 공식 자료 패널은 방송 상태와 분리하고 양쪽 모두 공식 source 자료만 5초마다 순환한다. LIVE가 시작되어도 공식 자료 패널을 덮어쓰지 않는다.
- 결정: 방송 예정 표시는 당일 공식 일정의 대상 위원회와 검증된 시작 시각만 사용한다.
- 이유: 실시간 관제와 확정 자료 브리핑은 사용 목적과 권위 상태가 다르므로 동일한 표시 영역을 경쟁적으로 사용하지 않아야 한다.

## ADR-025 · 종료 방송과 공식 회의록은 덮어쓰지 않고 나란히 대조

- 상태: Accepted
- 결정: 종료 방송 확장 화면은 `LIVE 저장본 · PROVISIONAL`과 공식 회의록의 잠정본·정본 권위 상태를 별도 칸으로 표시한다.
- 결정: 공식본이 게시되지 않았거나 회의 후보가 복수이면 `NOT_PUBLISHED`·`AMBIGUOUS` 상태를 그대로 표시하고 공식본이 있는 것처럼 대체하지 않는다.
- 결정: 문장 일치는 정규화된 20자 이상 final 자막이 공식 발언 한 문장에 유일하게 대응할 때의 exact 결과만 집계한다.
- 결정: 공식 회의록 링크와 공식 발언 수를 제공하되 기존 LIVE 자막·리뷰·미해결 과제는 보존한다.

## ADR-026 · 통합 후속 과제는 명시적 OPEN 근거만 사용

- 상태: Accepted
- 결정: 통합 후속 과제 보드는 최근 30일 LIVE·종료 방송의 final 자막 revision 중 `task_status=OPEN`과 과제 문구가 명시된 항목만 노출한다.
- 결정: 같은 방송·주제의 후속 근거가 `RESOLVED`이거나 해소로 표시되면 이전 OPEN 항목을 제거한다.
- 결정: 담당 부서는 같은 근거 payload에 명시된 값만 facet으로 제공하고 비어 있으면 `담당 부서 미확정`으로 유지한다.
- 결정: 과제를 선택하면 해당 방송을 열고 미해결 과제 필터를 적용하되 LIVE/종료·PROVISIONAL 표시는 보존한다.

## ADR-027 · 첫 화면은 방송 기록의 연속성과 공식 정책 탐색을 우선

- 상태: Accepted
- 결정: 서비스 첫 설명과 최상위 작업 영역에서 브라우저와 무관한 서버 기록, 중간 진입 시 누적 맥락 복원, 종료 후 공식본 대조를 명시한다.
- 결정: LIVE·예정·종료 기록과 후속 과제는 같은 작업 영역에 두고, 영상·주제별 질의응답·미해결 과제·담당 부서·시간순 원문을 한 번의 방송 선택으로 연다.
- 결정: 방송 상태와 독립된 공식 브리핑은 정부·국회로 나눠 유지하고, 하위 탐색은 정부의 주제·부처와 국회의 위원회·의안 축을 사용한다.
- 결정: 기본 본문은 16px을 기준으로 하고 핵심 정보 행과 상세 본문은 13px 미만으로 축소하지 않는다. 상태·근거 metadata에만 10~12px을 제한적으로 사용한다.
- 결정: 시각 체계는 밝은 중립 surface, 하나의 인디고 상호작용 색, LIVE 위험색, 얕은 elevation으로 한정하고 장식 목적 그래픽은 추가하지 않는다.
- 이유: 처음 방문한 사용자가 설명서 없이 현재 상황, 앞선 맥락, 남은 일, 공식 근거의 순서로 국정 흐름을 읽을 수 있어야 한다.

## ADR-028 · 오픈 베타 기본 단위는 발언이 아니라 회의 결과

- 상태: Accepted
- 결정: 종료 회의를 열면 전체 자막보다 회의 headline·요약·핵심 주제·화자별 요지·도출 과제를 먼저 표시한다.
- 결정: 주제·화자 요지·과제를 클릭할 때만 해당 항목의 근거 Utterance를 조회하고 전체 원문은 접힌 상세로 제공한다.
- 결정: 회의 브리프는 공식 사실과 분리된 `PROVISIONAL · DRAFT`이며 모든 항목은 현재 transcript snapshot에 존재하는 evidence ID를 하나 이상 가져야 한다.
- 결정: `OPEN + EXPLICIT`만 명시된 후속 조치로 표시하고 추론 과제는 AI 검토 후보, 담당부처 추론은 잠정 연결로 표시한다.
- 결정: Mistral 구간 분석과 회의 통합 결과는 transcript hash·provider·model·prompt version으로 저장하며 API 요청에서 외부 LLM을 호출하지 않는다.
- 이유: 사용자는 발언 나열보다 어떤 회의가 있었고 무엇이 논의됐으며 어떤 일이 남았는지를 먼저 이해해야 한다.

## ADR-029 · 기관별 화면 대신 하나의 회의 흐름과 출처 탭을 사용

- 상태: Accepted
- 결정: 공개 화면은 국회와 국무회의를 별도 작업 메뉴로 나누지 않고 진행 중·예정·결과 회의 레일에 함께 표시하며 기관은 카드 배지로만 구분한다.
- 결정: 수집 건수·수집 시간·자막 처리량·worker 상태는 사용자 가치가 아니라 운영 상태이므로 공개 화면에서 제거하고 향후 관리자 메뉴가 소유한다.
- 결정: 종료 결과의 기본 화면은 가장 최근 요약 완료 회의이며 주제·화자·과제를 선택한 근거 발언은 같은 화면 우측 sticky 패널에서 교체한다.
- 결정: LIVE·공식 자료 탭 바로 아래의 1·2열은 논의 주제·도출 과제 제목만 한 줄로 보여 주는 이동 인덱스로 사용한다. 선택 시 해당 주요 논의 내용으로 포커스하고, 주제별 과제는 화자 요약 바로 아래에 `과제 · 내용 · 원문 보기`의 동일한 행 구조로 붙인다. 별도 과제 보드는 두지 않으며, 근거의 AI 요약은 강조하지 않고 펼친 원문에서 가장 관련 높은 문장 전체만 강조한다.
- 결정: LIVE 저장본과 공식 자료는 서로 덮어쓰지 않고 탭으로 병렬 제공한다. 일정/회의 identity, 공식 publication, 발언 reconciliation 순으로 연결 상태를 높이며 미발행·미연결 상태도 명시한다.
- 결정: 공식 사이트에 게시됐더라도 임시 회의록의 authority가 PROVISIONAL이면 화면과 API에서 그대로 유지한다.
- 이유: 사용자는 기관별 데이터 파이프라인보다 지금 어떤 회의가 열리고 무엇이 결정됐으며 그 판단 근거가 무엇인지 한 흐름에서 이해해야 한다.

## ADR-030 · LIVE 화자 전환만 발언 완료 경계로 사용

- 상태: Accepted
- 결정: 같은 방송에서 연속된 동일 원본 화자 코드의 자막은 길이·시간과 무관하게 하나의 진행 중 발언으로 누적하며 화면에서 축약하지 않는다.
- 결정: source가 non-final 자막을 빈 화자나 `-1`로 먼저 보낸 뒤 확정 화자로 수정하는 구간은 직전 확정 화자에 임시 연결한다. 확정 revision이 다른 화자로 바뀐 시점만 실제 전환으로 처리한다.
- 결정: LIVE 요약 대상은 실제 전환으로 닫힌 직전 발언이며 원문 hash 캐시로 한 번만 외부 호출한다. 진행 중 마지막 발언은 다음 전환 또는 방송 종료 전까지 요약하지 않는다.
- 결정: 공개 화면은 최신 자막마다 진행 중 발언 묶음으로 자동 이동하고, 전환 뒤 DB에 저장된 요약만 다시 읽는다. API 요청 자체는 외부 LLM을 호출하지 않는다.
- 이유: 사용자가 현재 발언의 전체 흐름을 놓치지 않으면서 거짓 화자 경계로 인한 잘린 표시와 중복 요약 비용을 피해야 한다.

## ADR-031 · 종료 상태는 결과 포맷과 분리하지 않는다

- 상태: Accepted
- 결정: 영상·실시간 자막 중심 방송 포맷은 방송 생명주기가 `LIVE`인 동안에만 기본 화면으로 사용한다.
- 결정: `ENDED` 회의는 AI 브리프의 READY·PENDING·DEFERRED 상태와 무관하게 항상 법사위 결과와 동일한 회의 결과 포맷으로 연다.
- 결정: worker는 deterministic 방송 리뷰와 canonical 발언 묶음으로 근거가 연결된 fallback 결과를 먼저 DB에 저장하고 외부 LLM 통합 결과를 후속 생성한다.
- 결정: Mistral 결과가 저장되면 최신 결과로 교체하되 deterministic 결과도 출처를 `자동 정리 · 잠정`으로 명시한다. 전체 자막 포맷은 사용자가 명시적으로 선택한 경우에만 제공한다.
- 이유: 방송 종료와 AI 처리 완료는 서로 다른 상태이며 외부 모델 한도가 사용자 화면의 정보 구조를 되돌려서는 안 된다.

## ADR-032 · provider 한도는 동일한 호출 횟수가 아니라 과금 단위로 분리한다

- 상태: Accepted
- 결정: OpenRouter 무료 호출 정책은 기존 UTC 일 500회 원자 요청 예약을 유지한다.
- 결정: Mistral에는 일일 호출 횟수 제한을 적용하지 않고 성공 응답의 입력·출력·전체 토큰을 모델·UTC 월 단위로 누적한다.
- 결정: 실시간 완결 발언 요약과 종료 회의 브리프는 같은 Mistral 월간 토큰 장부와 1,500만 토큰 로컬 안전선을 사용한다.
- 결정: 로컬 토큰 안전선과 별개로 Mistral Workspace의 월간 지출 한도를 USD 10 이하로 설정한다.
- 이유: 서로 다른 provider의 무료·과금 계약을 하나의 500회 규칙으로 처리하면 Mistral 작업이 실제 월간 여유와 무관하게 중단되고, 회의별 결과 형식이 fallback과 AI 결과로 갈라진다.

## ADR-033 · LIVE 영상과 자막은 경쟁하지 않고 위아래로 분리한다

- 상태: Accepted

- 결정: 영상 위에는 자막을 겹쳐 표시하지 않고 공식 스트림 상태 배지만 유지한다.
- 결정: 영상 우측은 주제당 한 줄과 과제 건수만 누적 표시하며 발언·과제 본문을 반복하지 않는다.
- 결정: 우측 목록은 실제 영상 높이를 넘지 않으며, 주제가 많아지면 영상과 페이지가 아니라 목록 내부만 스크롤한다.
- 결정: 화자별 실시간 누적 원문과 전환 후 저장 요약은 영상 아래의 넓은 단일 자막 영역에서 최신 발언으로 자동 이동한다.
- 결정: 자막 갱신 시 사용자가 펼친 원문은 발언 ID로 상태를 보존하고 재렌더링 뒤에도 열린 상태를 유지한다.
- 결정: 노트북 기본 보기의 영상 높이는 화면의 42%, 최대 420px로 제한하고 아래 자막 영역에는 직전 발언과 현재 발언이 함께 보이도록 밀도를 높인다.
- 결정: 현재 발언은 카드 높이를 112px로 제한하고 새 자막마다 카드 내부를 끝으로 이동해 전체 레이아웃을 늘리지 않고 최신 문장을 노출한다.
- 결정: 시네마 모드에서는 우측 인사이트를 숨기고 영상을 전체 폭 16:9로 표시하되 아래 자막 영역은 유지한다.
- 이유: 사용자는 영상을 가리지 않고 시청하면서 필요할 때 시선을 아래로 내려 전체 발언 맥락과 요약을 함께 읽어야 한다.

## ADR-034 · LIVE 주제는 화자 요약과 같은 호출에서 생성한다

- 상태: Accepted
- 결정: 완결된 화자 묶음의 Mistral 응답은 요약과 함께 잠정 주제·역할·과제·담당 후보를 반환한다.
- 결정: 구조화 결과는 발언 content hash의 요약 캐시와 같은 행에 저장하며 동일 발언을 재호출하지 않는다.
- 결정: LIVE 화면은 저장된 구조화 결과만 표시하고 브라우저 키워드 규칙으로 실제 방송 주제를 만들지 않는다.
- 결정: LIVE 결과는 `PROVISIONAL`이며 방송 종료 후 전체 계층 분석 결과가 최종 논의 주제와 도출 과제를 담당한다.
- 이유: 별도 주제 추출 호출과 반복 문맥 전송 없이 실시간 이해도를 높이고, 잠정 결과와 종료 결과의 책임을 분리하기 위해서다.

## ADR-035 · 숫자 화자 코드는 인물이 아니라 원천 음성 경계다

- 상태: Accepted
- 결정: 국회 LIVE 자막의 `0/1/-1`은 방송 전체에서 재사용되는 음성 분리 코드이며 의원·장관의 고유 식별자로 해석하지 않는다.
- 결정: 한 source revision의 `speaker_segments`에 서로 다른 코드가 있으면 첫 코드로 전체 문장을 귀속하지 않고 원천 배열 순서의 파생 발언 조각으로 제공한다.
- 결정: 파생 조각은 원본 segment·revision·raw payload를 덮어쓰지 않는 읽기 모델이며, 같은 원본 segment의 새 revision이 도착하면 화면 상태에서 직전 파생 조각을 교체한다.
- 결정: source revision의 임시 화자 경계는 화면 갱신에만 사용하고, 실시간 LLM 요약은 final 구간으로만 구성된 닫힌 발언에 한정한다.
- 결정: 숫자 코드의 방송 단위 표시 이름 변경은 동일 인물임이 별도로 검증된 경우에만 사용하고, 미검증 상태는 이름 미확인으로 유지한다.
- 결정: LIVE 우측 인사이트는 1100px 초과에서 영상과 높이를 맞추고, 그 이하에서는 영상 아래의 제한 높이 내부 스크롤 영역으로 전환한다.
- 이유: 원천이 제공하지 않는 인물 정체를 추측하지 않으면서 실제 질의·답변 전환과 모바일 시청 폭을 보존해야 한다.

## ADR-036 · 종료와 결과 준비 완료는 별도 상태로 표현한다

- 상태: Accepted
- 결정: 방송 생명주기가 `ENDED`여도 회의 브리프가 저장되기 전에는 결과 내용을 확정형으로 노출하지 않고 `결과 정리 중` 상태를 표시한다.
- 결정: 준비 중 화면은 최종 결과와 같은 골격을 흐림 처리해 화면 전환을 예고하되 클릭과 읽기를 막고 명시적 진행 상태를 전면에 둔다.
- 결정: 사용자가 해당 회의를 보고 있는 동안에는 5초 간격으로 DB 저장 결과만 재조회하고 브리프가 준비되면 같은 화면을 실제 결과로 교체한다. 재조회 자체는 외부 LLM을 호출하지 않는다.
- 결정: deterministic fallback은 결과 공백을 막는 임시 읽기 모델일 뿐 `READY`로 판정하지 않으며, 설정된 AI 공급자(Mistral 또는 OpenRouter)의 근거 분석본이 저장된 경우에만 결과 준비 완료로 전환한다. 다만 저장된 fallback이 있으면 종료 회의를 회의 보고서 목록에서 숨기지 않고 `정리중`으로 표시한다.
- 결정: worker의 완료 제외 조건도 AI 공급자의 저장본에만 적용한다. 재시도 유예 중인 실패 회의는 대상 조회에서 제외해 최신 한 건의 유예가 이전 회의 처리를 막지 않게 한다.
- 결정: 준비 중에는 회의 제목·기본 정보·자료 탭·전체 발언 접근을 유지하고 `요약된 논의 주제 / 도출 과제` 영역만 흐림 처리한 로딩 카드로 대체한다.
- 결정: 구간 분석이 끝날 때마다 전체 발언 수와 처리 완료 발언 수를 DB에 저장하고 화면 재조회에서 진행 단계와 함께 표시한다.
- 결정: 발언 경계 읽기 모델 변경 전 저장된 evidence ID는 현재 파생 발언 ID의 부모 source segment와도 일치시켜 기존 브리프의 근거 연결을 보존한다.
- 결정: 호환 대조 후에도 근거가 없으면 빈 영역으로 두지 않고 재대조 상태를 명시한다.
- 이유: 방송 종료와 AI 결과 준비는 다른 상태이며, 읽기 모델 개선이 이미 저장된 근거 추적성을 끊어서는 안 된다.

## ADR-037 · 종료 브리프의 과제는 근거 발언으로 하나의 주제에 귀속

- 상태: Accepted
- 결정: Mistral이 반환한 과제의 `topic_title` 문자열을 주제 연결 키로 사용하지 않는다.
- 결정: 과제와 주제가 공유하는 evidence ID 수를 최우선으로 비교하고, 같은 근거가 없을 때만 정규화 제목의 완전 일치·핵심어·문자열 유사도를 순서대로 사용한다.
- 결정: 모든 과제에는 하나의 canonical `topic_id`와 해당 주제의 정식 `topic_title`을 저장하며 화면도 `topic_id`로 배치한다.
- 결정: 기존 저장 브리프는 외부 LLM을 다시 호출하지 않고 같은 결정 규칙으로 보정한다.
- 이유: 생성 모델이 같은 쟁점의 제목을 다르게 표현해도 원문 근거가 가리키는 주제와 과제를 안정적으로 함께 보여줘야 한다.

## ADR-038 · 잠정 결과와 공식 자료는 변경 패치로 통합한다

- 상태: Accepted
- 결정: 저장 계층에서는 LIVE 잠정 브리프와 공식 회의록 버전을 계속 분리하고 어느 원본도 덮어쓰지 않는다.
- 결정: 화면은 별도 `LIVE 저장본 / 공식 자료` 결과 탭을 사용하지 않고, 잠정 결과에 공식 자료로 확인된 수정·추가·삭제 span만 합성한다.
- 결정: 수정 문구는 파란 굵은 글씨와 이전 문구 tooltip, 추가는 초록 굵은 글씨, 삭제는 붉은 취소선으로 표시하며 모바일은 focus/tap으로 같은 설명을 연다.
- 결정: 화자 분리·병합은 문자 구절과 공식 발언 순서의 결정적 대조로 처리하고 사용자에게 이력으로 노출하지 않는다. 공식 근거가 확인된 현재 화자 묶음만 표시한다.
- 결정: 의미 대조가 필요한 주제·과제 변경만 공식 문서 버전당 Mistral 1회로 제한하고 결과와 토큰 사용량을 문서·브리프·프롬프트 버전 키로 캐시한다.

## ADR-039 · 요약은 추상 의미를 보존하고 LIVE 능력을 과장하지 않는다

- 상태: Accepted
- 결정: 종료 브리프의 주제·화자 요지는 원문 발췌가 아니라 완결형 한국어 재서술이어야 하며 원문 복사와 비정상 영문은 저장 전 차단한다.
- 결정: 공식 화자 대조는 이미 생성된 추상 요약을 원문 앞부분으로 대체하지 않고 화자 표시와 공식 근거 ID만 보강한다.
- 결정: 공식 자료의 문체·어순·개조식 차이는 숫자·부정·정책 의미가 유지되면 사용자 변경 이력으로 표시하지 않는다.
- 결정: KTV 국무회의는 공식 편성 ONAIR와 공식 HLS를 국회와 같은 회의 레일·라이브 수명주기로 처리한다.
- 결정: 기계 판독 공식 자막이 없는 KTV 방송은 자막·화자를 추정하지 않고 제한을 화면에 명시하며 종료 후 공식 브리핑을 결과 계층으로 연결한다.
- 이유: 사용자가 요약과 원문을 구분해 읽고, 의미 없는 공식 변경이나 존재하지 않는 실시간 자막을 사실로 오인하지 않게 해야 한다.

## ADR-040 · 관심주제 후속 기능은 무료 결정론 경로를 기본으로 완결한다

- 상태: Accepted
- 결정: 알림 규칙은 서버 matcher용 stable revision과 적용시각을 권위 원본으로 사용한다. 브라우저 localStorage는 익명·오프라인 화면 복구용 cache이며 Kakao 연결 뒤에는 서버 원본과 비파괴 병합한다. 수정 전 자막은 새 조건의 알림 대상이 아니다.
- 결정: 화자별 최초 1회와 10·15·30·60분 간격은 신규 final 감지에서만 평가하고 시간 경과만으로 알림을 만들지 않는다.
- 결정: 회의 종료 digest, 운영 지표, 공식 근거 확인, 인쇄와 Markdown 대응자료는 저장된 발언·브리프·공식 대조만 사용하며 별도 LLM을 호출하지 않는다.
- 결정: 공식 유일 문장 대조가 성립한 개조식·서술식 차이는 `OFFICIAL_CONFIRMED`로 처리하고 의미 있는 변경으로 표시하지 않는다. FINAL 통합 후 근거가 없을 때만 `OFFICIAL_NOT_CONFIRMED`, 충돌은 `REVIEW_REQUIRED`로 둔다.
- 결정: Kakao와 watch 전용 LLM은 외부 동의·비용이 필요한 선택 기능으로 유지하며 무료 오픈 베타 기본값에서는 비활성화한다.
- 이유: 알림·근거·종료 결과를 비용이나 외부 provider 장애와 분리하고, 사용자가 잠정 기록과 공식 확인 상태를 혼동하지 않게 해야 한다.

## ADR-041 · 외부 알림·선택형 요약·운영판정은 독립 경계와 append-only 이력을 사용한다

- 상태: Accepted
- 결정: PoC 7 Kakao OAuth·암호화·발송 코드는 PoC 4를 import하지 않는 독립 adapter와 PostgreSQL outbox worker로 구현한다.
- 결정: API는 OAuth 설정만, notification-worker는 발송 비밀값만 allowlist로 받으며 watch-worker는 provider credential을 받지 않는다.
- 결정: 관심주제 통합 요약은 무료 추출 요약을 대체하지 않는 선택 레이어이며 evidence ID hash·월 USD 1 soft cap·세션 12회 제한을 적용한다.
- 결정: 관리자 decision은 자동판정 상태를 갱신하지 않고 원본 상태·결정·메모·운영자·시각을 append-only 행으로 저장한다.
- 결정: 실제 방송 조건을 관측하지 못한 회귀 검증은 PASS로 만들지 않고 `PENDING`으로 기록한다.
- 이유: 무료 핵심 흐름을 외부 장애와 분리하면서도 운영 활성화 후의 비용·중복·감사 가능성을 코드 수준에서 보장해야 한다.

## ADR-042 · 장시간 회의는 가변 회차로 체크포인트하고 종료 뒤 한 번 통합한다

- 상태: Accepted
- 결정: 같은 방송 ID의 저장 자막 사이에 30분 이상 공백이 생기면 1부터 증가하는 잠정 회차 경계를 만든다. 회차 수는 1·3회로 고정하지 않는다.
- 결정: LIVE 상태의 마지막 회차만 `ACTIVE`, 앞선 회차와 종료 방송의 회차는 `CHECKPOINTED`로 표시한다. 회차 경계는 공식 정회·산회 판정이 아니다.
- 결정: 동일 원본 화자 코드도 5분 넘게 끊기면 새 발언 묶음으로 시작해 장시간 정회 전후 발언이 하나로 합쳐지지 않게 한다.
- 결정: 방송이 다시 시작되면 저장·실시간 초안을 이어가고, `ENDED`가 2시간 안정된 뒤 모든 회차를 하나의 종료 브리프로 합성한다.
- 결정: 최종 합성은 모든 저장된 실시간 주제 cluster ID를 정확히 한 최종 주제에 귀속한다. 누락된 ID는 결정적 유사도 규칙으로 보정하고 추가 LLM을 호출하지 않는다.
- 결정: 동일 원본 cursor인 과거 Mistral 보고서에는 기존 결과를 재사용해 회차·계보만 보강하며 비용이 드는 재생성을 하지 않는다.
- 결정: 국회 자막 worker는 방송별 DB lease와 `SKIP LOCKED` claim으로 최대 4개를 독립 처리한다. 실제 2개 동시 저장은 운영 이력으로 검증하고, 대상 3개 위원회와 본회의가 모두 겹치는 4개 동시는 실제 발생 전까지 계약 검증 상태로 구분한다.
- 이유: 회의 횟수와 정회 길이가 매번 달라도 사용자가 중간 전체 흐름을 잃지 않고, 종료 결과의 형식과 무료 운영 원칙을 함께 지키기 위해서다.


## ADR-043 · 카카오 연결을 PoC7 다중 기기 계정 경계로 사용한다

- 상태: Accepted
- 결정: 익명 방문은 만료 가능한 보안 세션으로 시작하고, Kakao 연결 성공 시 Kakao 사용자 ID에 이미 연결된 canonical subscriber를 사용한다.
- 결정: 새 기기의 익명 규칙은 감지문구·기관·위원회가 같은 기존 규칙과 중복 생성하지 않고 추가 병합한다. 기존 계정·규칙·Kakao token은 자동 삭제하거나 다른 subscriber로 이동하지 않는다.
- 결정: session 원문은 브라우저의 HttpOnly·Secure·SameSite=Lax 경로 제한 cookie에만 두고 DB에는 SHA-256 hash만 저장한다. 구형 localStorage token은 자동 승격 후 제거한다.
- 결정: 현재 기기·전체 기기 session 폐기와 Kakao 연결 해제를 서로 다른 명시적 동작으로 둔다.
- 이유: PoC7 단독 배포를 유지하면서 여러 PC에서 같은 알람 설정과 저장 결과를 이어 보고, 브라우저 script가 장기 인증 token을 읽지 못하게 하기 위해서다.

## ADR-044 · 주제별 보고서는 로컬 검색 후 사용자 요청 때만 1회 생성한다

- 상태: Accepted
- 결정: 소관 부처·주제·기간 검색은 저장된 회의 brief와 공식 통합본의 구조화 의미·keyword만 사용하며 외부 LLM을 호출하지 않는다.
- 결정: 사용자가 작성 버튼을 누른 경우에만 선별된 공개 근거 snapshot으로 OpenRouter 작업을 한 번 예약하고, 동일 query·evidence·provider·model·prompt READY 결과는 재사용한다.
- 결정: POC4·POC7 공용 gateway의 950회/UTC 일 운영선 안에서 주제 보고서 100회/UTC 일과 사용자 10회/UTC 일을 추가 적용한다. 새로고침·목록·상세·Markdown·인쇄는 호출하지 않는다.
- 결정: OpenRouter API key는 공용 gateway에만 제공한다. gateway는 `public_official`·`public_web_news` 이외의 데이터를 거절하며, 2026-09-09 명시 승인에 따라 공개 데이터에만 data collection 허용과 승인된 무료 모델 fallback, strict JSON schema를 적용한다. 주제별 보고서는 공개 회의 근거만 사용하고 PII 패턴을 제거하며 모든 생성 항목의 evidence ID를 저장 snapshot과 검증한다.
- 결정: 카카오 연결 계정만 생성을 요청할 수 있으며 Kakao ID·token·browser session은 LLM payload에 포함하지 않는다.
- 이유: 사용자 요청 시점의 필요에 맞는 완결 보고서를 제공하면서 무료 호출량, 개인정보 노출, 근거 없는 생성과 반복 비용을 동시에 제한하기 위해서다.

## ADR-045 · 공식 자료 후처리는 원본 버전별 완료 상태로 종료한다

- 상태: Accepted
- 결정: 국회 임시 회의록은 정본이 게시될 때까지 확인하고, 정본의 원문 수집과 안건 연결이 끝나면 같은 회의·`CONF_ID`의 모든 발행 기록에서 다시 읽지 않는다. 안건이 늦게 들어온 회의의 문서만 연결 작업에 다시 넣는다.
- 결정: 한 날짜의 미게시 회의 때문에 원본 목록을 다시 수집하더라도, 이미 `PUBLISHED`인 다른 회의의 출처 연결·발언 대조는 반복하지 않는다. 출처 연결 이후 본문 수집은 임시본 변경과 정본 게시 확인을 계속 수행한다.
- 결정: 공식 발언 주석 대상도 문서·생성 규칙 버전별 완료 상태로 선택한다. 기존 전역 누락 검사로 처리된 안정된 문서는 한 번에 완료 상태로 이관하고 새 문서와 생성 규칙 변경 때만 다시 처리하며 오류는 간격을 늘려 재시도한다.
- 결정: 발언 전체를 매 주기 메모리로 읽는 연결 작업을 문서별 최대 1,000발언 배치와 영속 진행 위치로 대체한다. 기존 전역 검사로 처리된 오래된 문서는 마이그레이션에서 완료 상태를 부여하고 최근 문서는 한 번 확인한다.
- 결정: 법안 PDF는 법안 버전·원본 URL·파서 버전의 성공 기록이 있으면 재수집하지 않는다. 실패는 지수 간격으로 재시도하며 미처리 법안이 조회 앞부분의 완료 건에 가로막히지 않게 한다.
- 결정: 공식 통합 큐·처리기·API는 같은 최신 공식 문서 선택 규칙을 사용하고 큐에 지정된 브리프 ID와 문서 ID로 결과를 저장한다. 통합은 전용 워커만 수행한다.
- 결정: 임시 회의록 통합의 30분 안정화는 마지막 HTTP 확인 시각이 아니라 내용 해시가 식별하는 원본 버전의 최초 관측 시각으로 판정한다. 내용이 같으면 분석을 계속 미루지 않고 새 버전일 때만 대기 시간을 다시 시작한다.
- 결정: 공식 대조 OpenRouter 요청은 추론 비활성화를 강제하지 않는다. 무료 대체 모델 중 추론 필수 엔드포인트가 있으므로 모델 요구와 충돌하는 400 오류를 피한다. 근거 검증과 구조화 응답 조건은 유지한다.
- 결정: 국회 게시 대기 확인과 행정부 상세 수집을 별도 주기로 운용한다. 행정부의 최근 항목은 빠르게, 오래된 항목은 목록·파서 버전·상세 확인 시각에 따라 재사용한다. 값이 같은 매칭 행은 갱신하지 않는다.
- 이유: 정본 이후 불필요한 전체 스캔으로 인한 메모리 급등과 완료 작업의 무한 반복을 막으면서 임시본 변화와 늦게 도착한 안건은 계속 반영하기 위해서다.

## ADR-060 · 공용 AI 계량은 무료 요청과 직접 유료 호출을 별도 장부로 집계한다

- 상태: Accepted
- 결정: 기존 OpenRouter 게이트웨이의 무료 모델 요청 예약 950회/UTC 일은 PoC4·7에 그대로 적용하고, PoC9가 같은 키로 직접 호출한 유료 대화는 `external_usage_events`에 별도 기록한다. 두 계량값을 합산해 무료 요청 잔여량으로 표시하지 않는다.
- 결정: PoC9는 사용자 승인 범위인 현재 발화만 ZDR·데이터 수집 거부 설정으로 OpenRouter에 보내며, 공용 장부에는 프로젝트·모델·상태·HTTP 코드·토큰·공급자 비용만 보낸다. 발화 원문, 응답, 세션 식별자를 장부에 저장하지 않는다.
- 결정: 메타데이터 기록은 전용 토큰으로 인증하고 이벤트 ID로 중복을 제거한다. 게이트웨이 장애가 주문을 막지 않으며, 같은 OpenRouter 키의 달러 한도·잔액은 공급자 `/api/v1/key`를 최종 기준으로 확인한다.
- 이유: 여러 PoC가 공유하는 키의 비용과 무료 모델 요청 한도를 함께 볼 수 있으면서 손님 대화의 개인정보 경계를 지키기 위해서다.

## ADR-057 · 공식 대조본 화자 항목은 공식 발언 원문을 표시한다

숫자·날짜·원문 근거 검증을 통과하지 못한 보고서는 완료로 승격하지 않는다. 동일 날짜의 `년도`/`년에`/`월에` 조사 차이만 비교 시 정규화한다. 기존 0~3차 보정 실패 중 원문 지문과 발언 ID가 일치하는 응답에서 검증 실패 필드만 4차로 보정하며, 호출 상한은 기존 retry_allowance를 유지한다. 성공 응답·원문·실패 이력은 삭제하지 않는다. 기존 REVIEW_REQUIRED 작업은 이번에 사용자가 승인한 전체 보고서 복구 대상으로만 재개한다.

문맥 재분류에서는 기본 프롬프트의 문맥 근거 금지와 후속 프롬프트의 문맥 활용 요구가 충돌했다. 저장된 인접 원문으로 생략된 대상을 판별할 수 있도록 정리하되, 직접 인용과 span_index는 현재 발언에 한정하고 인접 화자의 주장을 전이하지 못하도록 명시했다. 자료 요구 재검토에는 인접 근거를 공유하는 기존 주제만 후보로 제공한다. 마지막 문장 검증 보정(4차)은 기존 verification 모델 풀을 사용하며, OpenAI는 OpenRouter 소진 조건과 기존 예산 보호를 그대로 따른다.

## 2026-10-30 — PoC7·10·11 공통 모델 예산

기존 OpenRouter 게이트웨이에 `/internal/budget/status`, `/reserve`, `/settle`을 추가하고 같은 PostgreSQL 원장을 사용한다. 새 서비스나 프로젝트 간 Python import 없이 인증된 HTTP 계약으로 연동한다. OpenAI mini/main은 일 1,000만/100만 토큰(입력+출력, UTC 00시/KST 09시), 유료 모델은 기존에 설정한 크레딧 기간, Solar는 누적 $110으로 관리한다. 월말 크레딧 갱신은 기존 사용자 설정을 유지한 운영 배정이며 실제 지급을 주장하지 않는다. 과금 분류는 기존 계정 확인값(5.4/mini 일일, 6계열 크레딧)을 유지한다.

모델 호출 전에 원자적으로 예약한다. PoC10/11은 정산 outbox를 먼저 저장하고 재전송한다. 중앙 연결 장애 시 신규 호출은 차단하며 화면의 미확인 잔액을 0 또는 무제한으로 대체하지 않는다. PoC10 로컬 일/월 상한은 공통 예산 안에서 추가 적용하는 작업별 안전 상한이다. 외부 자료는 실행 지시가 아닌 분석 입력이며 AI는 업무 승인·실적·운영 코드를 변경하지 않는다.


## 2026-10-30 공용 크레딧 월초 갱신 정정

사용자 확인: 월 $100이며 처음 입력한 $8은 이미 $92를 사용한 뒤의 잔액이다. 게이트웨이 카드 `limit`는 월 $100, `current_period_allowance`는 초기 잔액 $8로 분리한다. `opening_used`는 초기 이전 사용분, `tracked_used`는 원장 추적 사용분, `used`는 그 합계다. 예약 허용량은 기존 $8에서 추적 사용·예약·미확정을 차감하므로 표시 수정이 가용 예산을 늘리지 않는다.

`OPENAI_CREDIT_MONTH_START_RENEWAL=true`를 추가했다. 최초 기간은 2026-11-01 00:00 KST까지 기존 grant로 유지하고 이후 매월 1일에 날짜가 포함된 새 grant로 $100을 배정한다. 원장 삭제·이전 잔액 이월은 없다. 기존 MONTH_END 옵션은 호환용으로 유지하되 운영에서는 false로 바꾼다. PoC7 API·게이트웨이·관련 작업자와 PoC11 fallback에 같은 기간 설정을 적용한다. 스키마 변경은 없다.


## 2026-10-30: OpenRouter 실시간 보조 모델 교체

Dots의 공급자 요청 거절과 한국어 출력 규칙 위반이 반복되어 무료 Nemotron 3.5 Super VL로 교체한다. 공개 발언 재검증 4건과 가상 자료 제출·질의/답변 4건이 기존 검증기를 통과했다. Gemma 4 두 모델·Xing 4는 공급자 429, Flint는 공급자 503으로 품질을 판정하지 않았다. Nemotron 표본 응답은 약 16~103초로 느릴 수 있어 Mini와 서로 다른 발언을 병렬 처리한다. 허용 모델을 요청에 고정하고 Dots를 게이트웨이 대체 목록에서 제외한다. 추가 실제 원문 재전송 시험은 자동 승인 검토 차단으로 수행하지 않고 가상 발언을 사용했다.


## 2026-10-30: OpenRouter 적극 활용 및 추론 지연·복합 과제 방어

Mini 우선 단독 경로로 바꾸지 않고 Mini/OpenRouter 동시 실행을 유지한다. Nemo 3.5의 실시간 요약은 추론을 끄고 모델을 고정한다. 가상 12개 동일 입력 비교에서 기본 처리 속도와 과제 유무는 Mini와 근접했지만 복합 발언의 즉석 설명/답변을 과제로 혼입하는 사례가 발견됐다. 전용 지시와 저장 전 방어 규칙을 적용해 해당 결과만 기존 모델별 1시간 보류/Mini 재처리 대상으로 남긴다. 새로운 발언 시험에서 Mini에도 약속 과제 누락이 있어 전반 동급·완전 정확성을 주장하지 않는다. Gemma 4는 JSON 모드 재시험 429이므로 품질 미달로 제외하지 않는다. 측정값·원문 없는 가상 시험 결과·한계는 `docs/evidence/MODEL_REPLACEMENT_20261030/README.md`에 기록한다.


## 2026-10-30: 실시간 Nemo 1초 선점 주기

사용자 요청에 따라 OpenRouter Nemo는 공통 조회 주기의 0초, Mini는 1초 지점에 시작한다. 최초 시작에만 sleep을 두면 모델별 응답 시간 차이로 우선순위가 뒤집힐 수 있어 monotonic 기준의 공통 주기로 정렬한다. 각 모델은 독립 스레드에서 회의별 한 묶음씩 처리하며 기존 PostgreSQL 발언 잠금을 유지한다. 한 모델의 지연·오류가 다른 모델을 기다리게 하지 않는다. 긴 요청으로 지난 주기는 건너뛰어 밀린 호출을 연속 실행하지 않는다. 예외 시 기존 최소 60초 대기 후 자기 주기에 재진입한다. OpenRouter가 설정되지 않은 Mini 단독 구성은 추가 1초 지연을 두지 않는다. 이 우선권은 작업 조회 시작의 시간차이며 처리 비율이나 모든 발언의 선점을 보장하지 않는다.

### 2026-10-30 CPU 및 조회 부하 개선

새 자막 대기 확인은 EXISTS 범위 검색 대신 인덱스 MAX(event_cursor)와 워커 커서를 비교한다. 빈 테이블과 없는 워커 상태의 기존 false 의미를 보존한다. 종료 경계 계산은 로직을 유지하고 covering index로 최적화한다. 신규·늦게 도착한 자료를 건너뛰는 종료 캐시는 두지 않는다.

## 2026-10-31: 역사 보고서 규칙 소급 및 반복 저장·재시도 제한

중수청의 정식명/약어와 조직·인사·수사 독립성 등을 같은 정책 대상의 상위 주제로 묶는다. 서로 다른 하위 쟁점, 공소청과의 협력 주제, 다른 사건은 별도 보존한다. 규칙 버전은 `policy-parent-groups/2`이며 실제 단일·분할 생성 프롬프트의 공통 parent 목록과 과거 보고서 읽기/출력에 같이 사용한다. 숫자 목표에 맞춰 세부 쟁점을 삭제하거나 완료 보고서를 다시 모델에 전송하지 않는다.

진행 상태, 본문 버전, 요청 snapshot, 공식 원문/주석의 반복 바이트를 각각 공유 저장한다. 이전 버전과 출처 ID를 없애는 대신 읽기 호환 뷰로 원래 JSON을 재구성한다. 통합·세부 서술의 입력 크기/일일 한도/속도 제한은 응답 품질 실패와 구분한다. 같은 요청에서 같은 provider/시도 모델의 크기 초과는 재호출하지 않고, UTC 다음날 00:00(KST 09:00) 또는 Retry-After 이후에 재개한다. 실제 품질 검증 실패에 대한 교정 경로는 유지한다.
