## 2026-10-31 — 회의 파생 읽기 재계산 축소

- 회의 구조·검토·서술의 파생 읽기를 압축 메모리 캐시로 재사용한다. 저장량은 압축 기준 32MiB와 256항목으로 제한하고 5분 후 만료한다.
- 매 조회마다 구조 수정시각·분석 배치 건수/최신 시각·원본 brief 해시를 확인한다. 원본 또는 분석 이력이 바뀌면 즉시 다시 계산한다. 응답 객체는 호출자마다 분리한다.
- 완료된 진행 상태만 재사용하며, pending/retry 진행 판단은 매번 계산한다. 원본 응답·이전 버전·모델 응답·공식/AI 구분은 변경하지 않는다.
- 방송·자막·알림 워커의 주기와 모델 호출 정책은 변경하지 않는다. 회의 후처리 워커만 원본 보존 후 전환한다.


## 2026-10-30 — 실시간 보조 모델 교체 및 첫 방송 자동 열기

- Dots 대신 OpenRouter 무료 Nemotron 3.5 Super VL을 사용한다. Mini와 병렬 처리하며, 개별 요청 모델을 고정하고 게이트웨이 기본 대체 목록에서 Dots를 제외한다.
- 공개 발언 4건 및 가상 질의·답변·자료 제출 요구 4건을 검증했다. 한국어·JSON·근거 검증은 유지하며, 소규모 시험 통과를 전체 품질 보장으로 해석하지 않는다.
- 알람·실시간 탭 선택 시 첫 방송을 즉시 열고, 목록이 늦게 도착해도 한 번만 자동 선택한다. 다른 탭에서는 자동 열기를 수행하지 않는다.

## 2026-10-30 — 진행 중 회의 저장본 열기 오류 수정

## 2026-10-27 — 행안위 347/349 세부 요약 정체 보완

- 일반 교정까지 실패한 숫자·날짜·언어 검증에는 실제 거절된 응답과 원문에 없는 숫자를 전달하는 추가 교정 한 단계를 제공한다. 같은 원문 기준의 요청과 재시도 상한은 고정하고, 기존 성공 요약·원문·실패 이력을 유지한다.
- `스물여덟`을 `28`로 바꾸거나 `55.78`을 `55`로 줄여 발생하는 실패를 구체적으로 피드백한다. 숫자 검증을 완화하거나 원문 수량을 지워 완료시키지 않는다.
- 구체 오류 교정도 실패한 숫자 문장은 해당 문장과 직접 원문만 다시 요약한다. 최대 3개 실패 필드에 한정하고 나머지 요약을 보존하며, 합친 전체 결과를 기존 검증으로 다시 검사한다. 교정 원응답과 기반 실패 요청을 함께 기록한다.

## 2026-10-27 — 법사위 내부 주제값 재분류·초기화 후 모델 점검

- 분류 코드 `UNCERTAIN` 등이 실질 주제명으로 저장되는 것을 신규 분류에서 차단한다. 기존 응답은 보존하며, 잘못된 내부값을 제목으로 가진 발언은 별도 프로필로 재분류하고 완료 전 검증 대상에 포함한다.
- 실제 주제가 연결된 묶음에 짧은 불명확 원문이 섞인 경우 묶음 전체를 미연결처럼 표시하지 않는다. 주제 연결 수와 불명확 원문을 구분한 설명을 기본 접힘 상태의 `주제 연결·원문 처리 내역`으로 제공한다.
- 관심주제 요약의 OpenRouter 요청에서 `reasoning.effort=none`을 제거한다. 필수 추론 엔드포인트의 HTTP 400을 방지하고 추론문은 응답에서 제외하며 기존 무료 호출 예산을 유지한다.
- 발언 요약의 무료 모델 대체 경로와 공식 변경 보고서에도 남아 있던 추론 비활성화 옵션을 제거한다. 모델 경로에 따라 필수 추론 조건이 달라져 발생하던 실패 호출의 반복을 방지한다.
- 필수 추론은 `low` 수준으로 허용한다. 긴 발언 요약에서는 이 설정도 추론에 출력 한도를 소진하는 사례가 있어, 해당 작업만 Dots 직접 JSON 방식으로 운영하고 필수 추론 모델과 하나의 대체 경로에 섞지 않는다. Dots는 기존 8,192 출력 토큰 예산을 유지하며 회의 보고서의 NIM 우선 풀은 유지한다.

## 2026-10-27 — 세부 요약 마지막 항목의 장기 대기 보완

- 냉각 시간 중인 요청이 보고서의 앞쪽 처리 슬롯을 차지하지 않도록 현재 실행 가능한 요청을 먼저 배정한다. 이미 저장한 요약과 근거는 재생성하지 않는다.
- 원문 숫자 검증 실패 뒤 대체 모델의 한도·입력 크기 제한이 기록되어도 원래의 교정 필요성을 유지한다. 같은 잘못된 요청을 30분씩 여러 번 반복한 뒤에야 교정하던 지연을 없애고, 기존 한 번의 교정 라운드를 바로 사용한다.
- 교정 요청에는 쟁점별 실제 원문 숫자 표기를 제공한다. 한글 수량·연도·금액을 임의 변환하거나 계산·항목 번호를 추가하지 않도록 명시하며, 수량·기한·약속을 삭제해 검증을 통과시키지 않는다. 원문·근거 및 기존 숫자·날짜 검증은 유지한다.

## 2026-10-27 — 단계별 보고서 진행 태그와 Groq 모델 점검

- 비공식 보고서의 발언 분석·통합·주제 검증·정책 분류·세부 요약·최종 확인을 모두 태그로 표시한다. 완료/처리 중/대기/재시도 대기를 구분하고 실제 저장 완료 수/전체 대상 수를 제공한다. 전체 완료 후에는 단계 태그를 없애고 `비공식 정리 완료`만 남긴다. 공식 정리는 `공식 정리 완료`로 표시하며 비공식 완료 태그를 유지한다.
- 재검증이 남은 발언은 완료 수에 중복 포함하지 않는다. 통합 묶음 수와 발언 수·세부 쟁점 수를 혼용하지 않고, 대상 수 미확정은 숫자를 추정하지 않는다. 목록과 보고서 상세에 같은 진행 데이터를 사용한다.
- Groq의 공개 무료 모델 목록과 실제 계정 목록을 대조하고 가상 한국어 질의·답변·자료제출 요구로 JSON 분류를 비교한다. 운영 모델 교체는 검증 결과를 근거로 결정하며 기존 무료 하위 예산은 유지한다.
- 요청 형식 오류(400)·모델 없음(404)은 플랫폼 전체를 1시간 차단하지 않고 65초 간격을 적용한다. 인증·권한 오류와 공급자 일일/속도 제한 처리는 유지한다.

## 2026-10-27 — 검증·모델 재시도 정체 예방

- 여러 보고서의 후속 검증은 마지막 처리 시각이 오래된 순으로 순환하여 최신 보고서 하나가 큐를 독점하지 않도록 한다.

- 중간 통합의 분할 계획과 완료한 하위 결과를 캐시하여 재시작 때 상위 시간 초과 요청을 반복하지 않는다. 기존 버전에서 저장한 하위 응답도 재사용한다.
- 재검증에서 한 모델의 예산 부족을 전체 모델 소진으로 처리하지 않는다. 실패를 기록하고 가용 풀의 다음 모델을 시도하며, 냉각 시간 후에는 우선 모델부터 다시 순환한다. 원문 재검증은 UTC 날짜별 최대 9회 제한을 적용한다.
- 여러 발언 중 일부만 주제·원문 검증에 실패하면 정상 발언은 기존 원응답에서 검증해 추가 저장한다. 독립 재검증과 일반 재검토의 결과는 섞지 않는다.
- NIM 최종 통합은 긴 근거 ID를 짧은 전송용 번호로 치환하고 응답 후 원래 ID로 복원해 기존 검증을 수행한다. 주제 수·근거를 줄이지 않고 문장 길이를 제한하며, 잘린 JSON은 게시하지 않는다.
- 출력 길이 초과는 6시간 대신 5분 후 재시도한다. 공급자별 대기는 다른 공급자의 진행을 막지 않으며, 대기 검사만으로 진행률을 0으로 덮어쓰지 않는다. 예산 한도는 유지한다.

## 2026-10-27 — 무료 모델 역할 분담과 대형 회의 통합 분할

- NIM 중간 요약 통합의 큰 입력 및 시간 초과는 작은 요청으로 나눠 기존 캐시를 재사용한다. 쟁점 통합 재시도는 소진된 마지막 공급자에 고정되지 않고 풀의 앞에서 다시 시작한다. 진행률은 `쟁점 통합중 x/y`로 표시한다.
