# ㅁㅁㅈ(뭐먹지?) — 누구나, 자기 말로 주문할 수 있게

**제품:** QR/NFC로 들어온 손님이 평소 말이나 글로 원하는 식사를 설명하고, 매장에서 확인한 실제 메뉴를 추천받아 주문하는 AI 대화형 매장 주문 PoC입니다. 점주는 메뉴 정보를 확인·게시하고 주문을 접수합니다. AI는 발화를 이해하고 설명하지만 메뉴 존재, 가격, 옵션, 알레르기 상태, 총액, 주문 확정은 서버의 검증된 데이터가 결정합니다.

**현재 상태(2026-09-23): 팀 공유 준비.** `/mmj` 단축 주소와 준비 화면만 연결되었습니다. **메뉴 조회, 대화, 장바구니, 결제, 점주 화면은 아직 사용할 수 없습니다.** 구현 범위, 현재 진행률, 역할, 안전 기준, 단계별 완료 조건은 한 파일로 통합한 [공유·구축 계획](docs/PLAN.md)에 있습니다. 이 README는 실제 기능이 완성될 때마다 사용법·시연·운영 절차를 갱신하는 기준 문서입니다.

## 서비스가 완성되면: 손님 사용법

아래는 **목표 사용자 흐름**입니다. 현재 화면에서 실행 가능한 단계가 아닙니다.

1. 테이블의 QR을 스캔하거나 NFC 태그에 휴대폰을 대면 해당 매장 주문 화면이 열립니다. 앱 설치와 회원가입은 필요하지 않습니다.
2. “말로 주문하기”, “글자로 주문하기”, “메뉴 직접 보기” 중 편한 방법을 선택합니다. 마이크를 허용하지 않아도 글자와 터치로 끝까지 주문할 수 있습니다.
3. 필요하면 알레르기, 식이조건, 맵기, 언어, 큰 글씨를 설정합니다. 설정은 주문 중에만 쓰고, 이 기기에 저장할지는 별도로 선택합니다. 저장한 설정은 언제든 삭제할 수 있습니다.
4. “부모님과 셋이, 안 맵고 따뜻한 걸로 4만원 안에서 추천해줘”처럼 상황을 설명합니다. 한 기기에서 일행별 조건도 입력할 수 있습니다.
5. 추천 카드에서 실제 메뉴명, 가격, 옵션, 맵기, 추천 이유, 확인된 알레르기 정보의 범위를 읽고 메뉴를 고릅니다. 정보가 불명확하면 추천에서 제외되거나 확인 필요로 표시됩니다.
6. 장바구니의 메뉴·수량·옵션·총액을 확인하고 수정합니다. 요청을 바꾸면 서버가 가격과 조건을 다시 계산합니다.
7. **Mock 결제**를 진행합니다. 실제 카드정보를 입력하거나 돈을 지불하지 않습니다. 주문 완료 후 점주 화면에 주문이 표시됩니다.

조건에 맞는 메뉴가 없으면 시스템이 임의로 조건을 풀지 않고 이유와 직원 확인 방법을 안내합니다. 추천 결과가 마음에 들지 않으면 메뉴 직접 보기를 사용합니다.

## 서비스가 완성되면: 점주 사용법

아래 역시 **목표 운영 흐름**입니다.

1. 점주 데모 계정으로 점주 화면에 로그인합니다. 고객 화면과 점주 권한은 분리합니다.
2. 메뉴명, 가격, 옵션, 품절 상태를 직접 입력하거나 수정합니다. 메뉴판 이미지 분석 기능이 추가되면 결과는 초안으로만 표시합니다.
3. 재료와 알레르기 정보를 실제 근거에 따라 확인합니다. AI 추정 항목은 그대로 게시해도 “점주 확인”이 되지 않습니다. 메뉴·옵션·교차 접촉 범위를 구분해 기록합니다.
4. 메뉴를 게시하면 손님이 볼 수 있습니다. 판매 중 가격·옵션·품절을 바꾸면 새 주문은 최신 데이터를 기준으로 검증됩니다.
5. 새 주문이 들어오면 테이블, 메뉴, 옵션, 수량, 총액을 확인하고 `접수 → 조리 중 → 준비 완료 → 완료`로 상태를 변경합니다.

## 발표용 한 장면

테이블 T07의 손님이 땅콩 알레르기와 맵기 1을 설정합니다. “부모님과 셋이 4만원 안에서 따뜻하게”라고 말하거나 입력합니다. 시스템은 확인된 실제 메뉴만 보여주고, 손님이 한 메뉴를 바꾸면 총액을 다시 계산합니다. 손님은 Mock 결제 후 주문을 완료하고, 점주는 주문을 접수합니다. 시연 중 **실제 결제는 없으며 알레르기 안전을 보증하지 않는다**는 점을 함께 설명합니다.

## 추천과 안전 원칙

- LLM은 발화를 구조화하고 결과를 짧게 설명합니다. 메뉴 사실·가격·옵션·재고·총액은 DB와 서버 코드가 확정합니다.
- 알레르기와 엄격한 식이조건은 추천 전에 검사합니다. `unknown`, `ai_inferred`, `may_contain` 항목은 엄격한 알레르기 추천에 넣지 않습니다.
- “점주가 미포함으로 확인”은 확인한 정보의 범위만 뜻합니다. 주방 교차 접촉이나 모든 제조 상황에 대한 안전 보증 문구를 사용하지 않습니다.
- 품절, 유효하지 않은 옵션, 클라이언트 가격 조작, 중복 주문은 서버가 거부하거나 동일 요청으로 처리합니다.
- Jev 실험 기능이 실패하거나 비활성화되어도 룰 추천으로 전체 주문이 동작해야 합니다.

## 접근성과 개인정보

모바일 웹이 기본이며 360px 이상 화면, 큰 글씨, 키보드·스크린리더, 한국어·영어, 마이크 권한 거부 시 텍스트/터치 대체 수단을 목표로 합니다. 알레르기·식이 설정은 사용자가 선택할 때만 기기에 저장하고, 삭제 기능을 제공합니다. 음성 원본·전체 발화·개인 프로필 원문은 분석 로그에 남기지 않습니다.

## 구조와 환경설정

예정 기술은 **Next.js + TypeScript + PostgreSQL + Prisma**입니다. 앱·DB·seed·테스트·배포 설정은 이 폴더 안에서 관리합니다. MinsLab 루트 ASGI는 `/mmj` 단축 주소와 같은 출처 경로만 담당합니다. 현재는 정적 준비 페이지를 제공하고, 주문 앱이 완성되면 `/poc/mwomeokji/*`를 독립 서비스로 전달합니다.

API 키는 저장소 루트 `.env`에서 **서버 프로세스에 필요한 이름만** 전달합니다. 현재 확인된 공통 키 이름은 `OPENROUTER_API_KEY`입니다. PoC 09 폴더에 키를 복사하거나 `NEXT_PUBLIC_*`로 노출하지 않습니다. 키가 없어도 Mock LLM/STT/Vision/Payment와 룰 추천으로 데모가 가능해야 합니다. 앱별 DB 연결은 `POC09_DATABASE_URL`로 분리할 계획이며, **지금은 DB와 앱 실행 명령이 아직 없습니다.**

## 개발·운영자가 확인할 것

**지금 가능한 점검:** 루트 앱을 실행 중이라면 `GET /mmj`가 307로 `/poc/mwomeokji/`를 가리키고, 대상이 준비 페이지로 응답하는지 확인합니다. 이 준비 페이지가 열린다는 사실은 주문 서비스의 정상 동작을 뜻하지 않습니다.

**앱 구현 후 이 README에 추가할 항목:** 의존성 설치와 seed 명령, DB 마이그레이션·백업/복구, Mock/실 provider 전환, 점주 데모 계정 발급, 테스트 실행, 서비스 시작·중지·로그 확인, 오류 대응, 배포·롤백 순서, 보존 기간, 운영 지표입니다. 구현되지 않은 명령이나 계정을 실행 가능한 것처럼 적지 않습니다.

장애를 나눠 확인할 때는 ① `/mmj` 리다이렉트 ② 대상 페이지/프록시 ③ PoC 09 앱 헬스체크 ④ 전용 DB ⑤ 선택한 AI provider 순서로 조사합니다. 독립 앱이 실패하더라도 다른 MinsLab PoC는 정상이어야 합니다.
