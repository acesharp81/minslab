# PoC 09 구현 계획 — ㅁㅁㅈ(뭐먹지?)

기준일: 2026-09-23. 입력 문서: 사용자가 제공한 「ㅁㅁㅈ — AI 대화형 주문 플랫폼 Architecture & Codex Implementation Specification」.

## 1. 판단

제품 가설은 MinsLab의 실행형 PoC와 잘 맞는다. 기존 PoC는 각각 독립 폴더에서 운영하고, 홈페이지는 `PoC/*/project.json`을 읽어 카드를 만든다. 따라서 PoC 09는 자체 Next.js 서비스와 DB를 이 폴더에 두고, MinsLab은 같은 출처의 경로만 연결한다. 모바일 사용자는 홈페이지 카드에서 전체 화면 주문 앱으로 이동한다. 데모 카드에는 실행 화면을 표시할 수 있지만, NFC/QR 진입과 음성 주문의 주 경로는 전체 화면이다.

현재 저장소에서 확인한 연결점:

| 항목 | 현재 동작 | PoC 09 결정 |
| --- | --- | --- |
| 목록 등록 | `portfolio_loader.py`가 `PoC/*/project.json`을 자동 탐색 | 주문·안전·모바일 검증을 통과한 뒤 `project.json` 추가 |
| 실행 화면 | `main.py`가 `app_path`를 iframe과 새 창 링크로 표시 | `/poc/mwomeokji/`를 `app_path`로 사용하고 모바일은 직접 열기 |
| 독립 서비스 | PoC 07/08이 자체 런타임과 localhost 포트를 사용 | 별도 Next.js 프로세스, 기본 `127.0.0.1:18090` |
| 루트 비밀값 | 루트 `.env`에 `OPENROUTER_API_KEY`가 있음 | 서버 프로세스에 필요한 변수만 전달, 키 값 복사 금지 |
| PoC 08 프록시 | 일부 메서드만 허용, 본문 1 MiB 제한, 응답 전체 버퍼링 | 업로드·DELETE·스트리밍을 지원하는 PoC 09 전용 경계 구현 |
| 프레임 정책 | PoC 07/08은 `microphone=()` 정책 | PoC 09에는 별도 정책을 두고 실제 음성 테스트 |
| 홈페이지 문구 | PoC 소개가 “개인 PoC”, “개인적으로 만든 프로그램” 중심 | 팀 프로젝트 카드에 팀 정보·역할·협업 기여를 명시하고 PoC 소개 문구를 개인/팀 모두에 맞게 수정 |

## 2. 입력 설계에서 유지할 원칙

1. LLM은 발화를 구조화하고 검증된 결과를 설명한다. 메뉴 ID, 이름, 가격, 옵션, 총액, 주문 상태는 DB와 도메인 코드가 정한다.
2. 알레르기·엄격한 식이조건·품절·예산 검사는 추천 순위 계산 전에 시행한다. 확인되지 않은 항목은 안전 추천에서 제외한다.
3. 로그인 없이 QR/NFC URL로 진입하고, 음성·텍스트·터치 메뉴를 모두 제공한다. 실제 결제는 없다.
4. `RuleBasedDecisionProvider`만으로 전체 데모가 끝까지 동작한다. Jev는 검증된 후보의 정성적 순위 실험에만 쓴다.
5. 메뉴판 OCR 결과는 초안이며, 점주의 명시적 확인을 거쳐서만 게시한다.

## 3. 수정해야 할 설계와 이유

| 원안의 빈틈 | 보완 |
| --- | --- |
| 10개 마일스톤 중 장바구니·주문은 6번째, 점주 주문 화면은 8번째 | 초기 수직 흐름에 텍스트 추천 → 장바구니 → Mock 결제 → 점주 접수까지 포함한다. 음성/Jev/OCR은 그 후에 확장한다. |
| 알레르기 `merchant_verified=excludes`가 음식 전체의 안전을 보증하는 것처럼 보일 수 있음 | 메뉴·선택 옵션·교차 접촉 정보가 모두 확인된 범위에서만 “점주가 미포함으로 확인”이라고 표시한다. “안전하다”라는 보증 표현은 사용하지 않는다. 미확인/`may_contain`/AI 추정은 엄격한 알레르기 추천에서 제외한다. |
| 엄격한 식이조건의 데이터 부재 처리 미정 | 엄격한 식이조건도 확인 불가면 통과시키지 않는다. 후보가 없으면 조건 완화를 자동 실행하지 않고 확인 질문/직원 문의를 표시한다. |
| 로컬 프로필에 민감정보를 기본 영구 저장 | 주문 중에는 메모리 사용을 기본으로 하고, “이 기기에 저장”을 사용자가 선택할 때만 버전·만료시각과 함께 `localStorage`에 저장한다. 즉시 삭제 UI를 제공한다. |
| 대화 원문을 DB에 저장하는 모델과 개인정보 최소화 원칙이 충돌 | 세션 대화는 TTL이 있는 최소 상태만 저장한다. 원문 로그·음성 파일·전체 프로필은 기본 저장하지 않는다. 운영 로그에는 집계 이벤트만 남긴다. |
| `tableCode`/`token` 및 `sessionId`만으로 주문 API 접근을 제어하는 방식 불명확 | QR 토큰의 매장·테이블 바인딩을 확인하고 짧은 만료의 HttpOnly 세션 쿠키를 발급한다. mutation은 세션/Origin/CSRF, 점주 API는 별도 인증·권한으로 검증한다. 공유 QR은 결제 인증이 아니라 매장 위치 힌트로 취급한다. |
| 주문 재시도 시 중복 접수/가격 변경에 대한 원자성 미정 | 주문 요청에 idempotency key를 쓰고, DB 트랜잭션에서 판매 가능 여부·옵션·가격을 재검증해 주문·가격 스냅샷을 확정한다. 서버가 총액을 다시 계산한다. |
| 업로드를 PoC 08의 프록시에 붙일 경우 크기/메서드 한계 | PoC 09 전용 프록시 또는 기존 리버스 프록시의 경로 규칙으로 모든 필요한 메서드, multipart 크기 제한, 쿠키, 리다이렉트, 응답 스트리밍을 검증한다. 업로드는 소형 이미지로 제한한다. |
| Next.js의 `/s/...`와 홈페이지 `/poc/...` 경로가 충돌 | Next `basePath='/poc/mwomeokji'`를 빌드 시 고정한다. 모든 링크, API, 정적 자산, QR URL을 실제 경로로 테스트한다. |
| Jev의 모든 답에 `confidence`가 있는 것처럼 취급 | Score/Choice의 `confidence`와 Noul의 확률을 타입별로 처리한다. 원시 HTTP 응답 `usage.input_tokens`와 SDK의 `usage.inputTokens` 차이를 adapter에서 흡수한다. |
| `70:30` 점수와 `0.70` 임계값을 검증된 값처럼 가정 | 둘 다 실험 기본값이다. 룰 단독 결과를 기준선으로 고정하고 라벨링한 데모 케이스에서 선택 일치율·지연·비용을 비교해 조정한다. |
| PoC 범위에 메뉴판 OCR, 다국어, 그룹 추천, 네 종류의 Mock 결제 화면까지 동시 요구 | 4주 핵심 검증은 한국어/영어, 한 매장, 텍스트+터치+음성 폴백, 한 기기 그룹, Mock 결제 하나로 제한한다. OCR은 이후 단계에서 독립 검증한다. |

`Jev 1.13`의 모델 ID, Decisions API, Score/Choice/Noul 혼합 호출은 2026-09-23 공개 자료에서 확인했다. 가격은 배포 시 다시 확인하고 코드 상수로 고정하지 않는다. 참고: [OpenRouter 모델 페이지](https://openrouter.ai/typesafe/jev-1.13/api), [OpenRouter Jev API 예제](https://openrouter.ai/blog/insights/what-is-jev/), [Next.js basePath](https://nextjs.org/docs/pages/api-reference/config/next-config-js/basePath).

## 4. 아키텍처 및 경계

```text
NFC / QR -> MinsLab 동일 출처 /poc/mwomeokji/*
           -> 독립 Next.js 앱 (localhost:18090)
              -> Route Handlers + Zod
              -> 주문 도메인 / 추천 룰 / 대화 상태
              -> PoC 09 전용 PostgreSQL
              -> 서버 전용 LLM/STT/Vision/Decision adapters
              -> Mock Payment

MinsLab /poc?project=mwomeokji -> 소개 카드 -> 전체 화면 앱
```

- Next.js, TypeScript, Prisma, PostgreSQL은 PoC 09 안에서만 관리한다. 기존 Python 서비스의 DB/테이블을 공유하지 않는다.
- `POC09_DATABASE_URL`을 사용해 다른 PoC의 `DATABASE_URL`과 혼동을 피한다. PostgreSQL 컨테이너 이름·볼륨·포트도 09 전용으로 둔다.
- 루트 `.env`에 이미 있는 `OPENROUTER_API_KEY`는 OpenRouter LLM/Jev adapter에서 서버 전용으로 읽는다. Mock 모드에서는 키가 없어도 된다. 다른 STT/Vision provider는 필요 시 별도의 루트 변수명을 문서화한다.
- 개발용 실행 스크립트는 루트 `.env`에서 필요한 변수만 읽어 자식 프로세스에 전달한다. Docker Compose는 `--env-file ../../.env`로 변수 치환값을 얻고 `environment`에 필요한 이름만 명시한다. `env_file:`은 루트 비밀값 전체를 컨테이너에 주입하므로 사용하지 않는다. 루트 파일을 컨테이너에 마운트하거나 클라이언트 번들에 포함하지 않는다.
- `NEXT_PUBLIC_*`에는 공개 앱 주소 같은 비밀이 아닌 값만 사용한다. 앱의 기본 동작은 AI/STT/Vision/Payment Mock으로 재현 가능해야 한다.
- 고객 URL은 `/poc/mwomeokji/s/[storeSlug]?table=T07&token=...`; 점주 화면은 `/poc/mwomeokji/merchant/*`로 분리한다. 프록시는 Next.js의 `basePath`가 포함된 경로를 그대로 전달한다. QR 토큰을 세션으로 교환한 뒤 주소창에서 제거하고 `Referrer-Policy: no-referrer`를 적용한다. `project.json`은 앱 기동·헬스체크·모바일 smoke test가 끝난 뒤 등록한다.
- 실제 배포 경로가 HTTPS인지 확인한다. 모바일 마이크와 QR 진입은 HTTPS 페이지에서 실기기로 검사한다. 홈페이지 iframe을 제공한다면 PoC 09 경로의 Permissions Policy와 iframe `allow="microphone"`을 별도 검증한다.

## 5. 구현 순서와 종료 조건

| 단계 | 작업 | 통과 조건 |
| --- | --- | --- |
| 0. 기반 | Next.js 앱, 전용 DB·마이그레이션·seed, Mock providers, 환경 로더, 기본 CI 명령 | 키 없이 매장 메뉴와 헬스체크 실행, 다른 PoC 변경 없음 |
| 1. 주문 수직 흐름 | QR 진입, 메뉴 조회, 텍스트 주문 해석, 룰 추천, 옵션/장바구니, Mock 결제, 점주 접수 화면 | “안 맵고 따뜻한 것 1만원대” 요청 → 추천 → 주문 → 점주 접수까지 E2E |
| 2. 안전·개인화 | 알레르기/식이 검증 데이터, 점주 확인 UI, 프로필 세션·선택 저장, 언어/큰 글씨, 조건 충돌 설명 | unknown/AI 추정/포함/품절/가격 조작/중복 제출 테스트 통과 |
| 3. 음성과 그룹 | MediaRecorder + STT adapter, 텍스트 폴백, 한 기기 그룹, 개인/공유 메뉴 구분, 예산 재검증 | 마이크 허용/거부 모두 주문 완료, 3인 그룹 예산·제약 준수 |
| 4. 홈페이지 연결 | PoC 09 전용 프록시, 상태 표시, 카드 메타데이터, 전체 화면 링크, 데모 스크립트 | 실기기 QR/음성, 홈페이지 카드에서 앱 진입, 서비스 장애 격리 |
| 5. 실험 확장 | 실 LLM adapter, Jev batch adapter와 rule fallback, 지연·비용 계측; 메뉴판 이미지 → OCR 초안 → 점주 검토·게시 | Jev 실패에도 주문 완료, 하드 제약 불변, batch 1회; 게시 전 고객 노출 없음 |

시간이 4주라면 0~4단계를 발표용 필수 범위로 두고, 5단계는 품질 게이트를 통과한 실험만 공개한다. 점주 메뉴 등록의 최소 수단은 직접 입력/수정으로 먼저 제공하므로 OCR이 없어도 메뉴 데이터 운영이 가능하다.

각 단계 종료 시 `typecheck`, `lint`, 단위/통합 테스트, 해당 흐름의 Playwright smoke test를 실행한다. 테스트는 메뉴/옵션/알레르기 확정값과 서버 총액 계산처럼 오류 영향이 큰 규칙에 집중한다.

## 6. 데모와 지표

최소 데모: 점주가 확인한 데모 메뉴가 있는 테이블 T07 → 손님이 땅콩 알레르기·맵기 1을 설정 → “부모님과 셋이 4만원 안에서 따뜻하게” 입력/말하기 → 조건에 맞는 실제 메뉴 조합 확인 → 한 메뉴 교체 → 총액 재계산 → Mock 결제 → 점주 접수. 알레르기 확인 불가 메뉴는 추천에 넣지 않고 확인 필요로 표시한다.

필수 회귀: 매장 간 메뉴 격리, 옵션 가격과 알레르기 재평가, 그룹 개인/공유 메뉴의 제약, 주문 중 가격/품절 변경, 중복 요청, 로그인 없는 점주 API 접근 거부, 루트 키의 클라이언트 번들 누출 검사. 집계 지표는 주문 완료율, 완료시간, 텍스트/음성 폴백률, 확인 질문 횟수, Jev fallback/호출 비용으로 시작한다. 개인 발화 원문은 분석 이벤트로 저장하지 않는다.

## 7. 출시 판단

1. 룰 단독·Mock provider·키 없음 상태에서 전체 주문과 점주 접수가 재현된다.
2. 알레르기/엄격 식이/가격/품절/옵션 검증 실패 시 잘못된 주문이 생성되지 않는다.
3. 실기기 QR 진입, 모바일 화면, 마이크 권한 거부 후 텍스트 주문이 동작한다.
4. 독립 서비스 장애 시 홈페이지의 다른 PoC가 정상 동작하고, 카드에는 명확한 연결 오류가 표시된다.
5. 위 조건을 통과한 뒤 `project.json`과 루트 프록시 경로를 등록한다. 실제 외부 노출/배포는 그때 별도 검증한다.
