# 구축계획 검토 및 보완안

검토일: 2026-09-14 (KST)

## 결론

원안의 목표·공개자료 원칙·근거 중심 판정·실패 격리·MVP 우선순위는 타당합니다. 다만 실제 운영 가능성과 폴더 단독 재현성을 확보하려면 아래 항목을 선행 게이트로 추가해야 합니다. 본 PoC 골격에는 해당 보완을 반영했습니다.

## 준비사항 검증 결과

| 항목 | 검증 결과 | 반영 |
| --- | --- | --- |
| Python | 요구사항은 3.11+, 검증 환경은 3.12.3 | Docker 이미지를 3.12로 고정 |
| 로컬 패키지 | FastAPI·SQLAlchemy·문서 파서가 전역 환경에 없음 | `requirements.txt`와 Docker로 격리 |

| 본공고 API | 공식 Swagger에서 `BidPublicInfoService`와 용역/e발주 operation 확인 | 목록과 후보 대상 첨부 어댑터 분리 |
| API 키 | 저장소에 키 없음, 활용신청 필요 | mock 기본값, live 설정 검증, 키 비로그화 |

| HWP·XLSX | 바이너리 HWP, 확장자 위장 HWPX, 표 형식 사업설명서 처리 필요 | SHA-256 검증한 `hwp-cli` v0.17.0 격리 실행, HWPX·XLSX는 안전한 OOXML 추출 |
| 독립성 | 상위 저장소 의존은 공유 시 장애 요인 | 모든 경로·설정·UI·샘플·테스트·Docker를 폴더 내부에 배치 |

## 원안에서 보완한 설계

1. **수집 실행 이력과 감사로그**: 공고 테이블만으로는 “오늘 API가 0건이었는지 실패했는지” 구분할 수 없어 `pipeline_runs`, `audit_logs`를 추가했습니다.
2. **후보 기반 첨부 호출**: 개발 트래픽 1,000건에서 본공고마다 e발주 첨부 API를 호출하면 일일 한도를 빠르게 소진하므로 목록 메타 규칙을 먼저 적용합니다.
3. **원문 인용 검증**: JSON schema만으로는 만들어낸 인용을 막지 못하므로 정규화한 입력 본문에 quote가 실제 존재하는지 검사합니다.
4. **판정 버전과 캐시**: 입력뿐 아니라 모델·프롬프트 fingerprint를 `input_hash`에 반영해 동일 구성의 재호출을 줄이고 모델 변경 결과를 분리합니다.
5. **다운로드 보안**: 확장자 외에 HTTPS, 허용 호스트, redirect 금지, 비표준 포트, 선언/실제 크기 제한을 추가했습니다.
6. **ZIP 폭탄·경로 검사**: path traversal뿐 아니라 누적 압축해제 크기를 제한하고 허용 문서만 메모리에서 처리합니다.
7. **시간대 명시**: 수집·리포트 기준은 KST, 저장시각은 UTC로 구분합니다.
8. **표본 검토**: 제외 키워드는 최종 제외가 아니며 AI 근거 또는 고예산 조건이 있으면 심층 후보로 유지합니다.
9. **운영 인증 게이트**: local mock은 무인 실행이 가능하고 production은 인증 미설정 시 degraded로 노출합니다.
10. **데이터 보존 정책**: 원문·추출문은 Git에서 제외하고 무결성 manifest가 있는 휴대형 백업을 제공합니다. 보존기간·삭제주기·RPO/RTO 목표는 운영 정책 승인사항입니다.
11. **다단계 LLM 비용 가드**: 2차 입력 8,000자, 3차 100,000자, 3차 일 10건·동시 1건을 기본값으로 두고 Cohere 실패 시 GPT-5.4 mini로 전환합니다.
12. **DB 분리**: 기존 `SUPABASE2_URL`과 `SUPABASE2_SERVICE_ROLE_KEY`로 Data API를 사용합니다. `poc08_` 전용 테이블과 RLS로 다른 서비스와 분리하고, 커밋 후 동기화·시작 시 재조정·로컬 장애 캐시를 둡니다.
13. **공통기반 3대 자격 게이트**: 망·데이터 처리, 제공 LLM/RAG 대체 가능성, 국가·위탁사무 범위를 각각 원문 근거로 검증합니다.
14. **6개 업무 분류**: 적합·사용, 적합·미반영, 전환검토·미반영, 사용명시·조건점검, 조건불충족·미사용, 비AI 사업으로 분류하고 2·3·4번에 본공고 보완 안내문을 생성합니다.
15. **판정기준 버전 관리**: 심층결과에 common-platform-v3-six-categories를 기록하고 이전 결과는 완료·우선조치 통계에서 제외한 뒤 최우선 재분석 큐로 보냅니다.
16. **미분석 적체 축소**: 규칙상 명확한 비AI 사업은 외부 LLM 호출 없이 6번 태그를 저장하고 신규 후보보다 구기준 재분석을 먼저 처리합니다.

## 보완된 단계와 완료 게이트

### Gate 0 · 외부 계약 확인

- 두 OpenAPI 활용신청과 Decoding 키 준비
- 실제 1일 응답 fixture를 비식별 저장하고 필드 매핑 확인
- e발주 첨부 URL의 실제 호스트와 Content-Disposition 확인
- 조직의 범정부 AI 공통기반 기능목록·적용 제한·표준 안내문 확보

현재 상태: **G2B 키와 기존 Supabase 2 URL/service-role 키 확인 및 전용 스키마 반영 완료**. Supabase Data API 연결·로컬 캐시 재조정·일괄 upsert가 검증됐습니다. Cohere V2 2차·Command A 3차와 GPT-5.4 mini 대체 경로를 구성했고, 공개 공고 심층분석에서 직접 인용·의미 검증을 통과했습니다.

### Slice 1 · 매일 쓸 수 있는 mock MVP

- 독립 실행, DB, 안전한 문서처리, 규칙/AI mock, 화면, 리포트, 회귀테스트

현재 상태: **구현 완료, 자동 검증 수행 대상**.

구현 검증 결과:

- Python 문법 및 Git diff 검사 통과
- 전체 pytest 135건 통과
- 격리 데이터에서 샘플 5건 수집·첨부 5건 파싱·분석 5건, 실패 0건
- 2회차 실행 신규 row 0건으로 upsert 확인
- G2B 최근 1일 실데이터 12건 수집, 재실행 신규 row 0건
- 실운영 누적 HWP/HWPX를 Docker의 hwp-cli로 재처리해 HWP 계열 실패·미지원 0건 확인. XLSX 사업문서 3건도 복구했으며 본문 없는 ZIP·이미지형 PDF 2건은 오류 큐에 유지
- 누적 1,581건 전량 현재 v3 기준 분류 완료: 2차 성공 이력 1,052건, 실제 심층 84건, 유형 5 84건, 유형 6 1,497건, 미분류·심층대기·분석실패·기준갱신 0건
- 수집문서 중 국가·위탁사무 직접 근거가 없고 공통기반 유일 언급도 `활용 가능성 우선 검토`였으므로 유형 1~4는 0건이며, 이를 모델 오류가 아닌 보수적 근거 판정 결과로 보고서에 표시
- AAM을 AI로 해석하고 일반 사무보조 가능성만으로 C를 부여한 실데이터 오탐을 발견해, 명시적 AI 기능 가드 적용 후 D/low로 재분류
- Supabase 원격에 공고·첨부·분석·판정·조치·실행이력·감사로그 저장 확인
- 구조화 웹·독립 HTML·JSON·Markdown 리포트 생성, 인쇄/PDF, 배치 상태 표시 및 최종본 스냅샷 보존 확인
- 첫 화면과 보고서에 `신규 수집 → 유형 분류 → 2차 LLM → 3차 심층 → 조치 필요 → 실제 조치`를 동일 기준으로 표시하고, 2·3·4유형의 발견 문제·조치 문안·나라장터 사전규격 의견등록 링크 제공
- 대시보드에 6개 운영 큐, 다음 처리 대상, 문서 일괄 재처리, 문서 오류 지표를 연결
- Docker 이미지 빌드 및 UID/GID bind mount 방식의 컨테이너 health/UI 확인
- 검증 호스트에는 Docker Engine은 있으나 Compose 플러그인이 없어 `docker compose` 명령 자체는 미실행. 공유 대상 호스트의 Compose v2 설치를 Gate 0 준비사항에 추가

### Slice 2 · 실데이터 shadow run

- `G2B_MODE=live`, 1일 범위, 분석 비활성으로 3일 이상 shadow 실행
- 누락률, 중복률, 첨부 성공률, HWP 비중, API 소모량 기준선 수집
- 실제 fixture 기반 필드 매핑 테스트 고정

승인기준: 수집 중복 0, API 실패 재시도 가능, 공고 단위 실패 격리, 원천 payload 보존.

### Slice 3 · AI 평가와 품질 게이트

- 사람이 판정한 30~50건 골든셋 작성
- 후보 재현율을 우선 지표로 정하고 B/C/D의 근거 정확도와 질문 유용성 평가
- Cohere/GPT별 프롬프트·모델 버전, 비용, 지연, 실패율 관측

승인기준 제안: 근거 quote 원문 일치 100%, schema 성공 99% 이상, 후보 재현율 목표는 골든셋 승인 후 확정.

### Slice 4 · 제한 운영

- systemd로 03:10 KST 1차 수집·분석, 04:40 실패 시 조건부 재시도, 07:00 최종 일일 보고서
- API·CLI·타이머 전체에 파일 잠금을 적용해 중복 수집 방지
- 성공 배치가 없으면 07시 service를 실패 처리하고, 성공 배치의 일부 오류는 `partial`로 명시
- 대시보드와 health API에 최근 배치, 스케줄, 실패 사유 노출
- 기존 홈페이지 프레임과 큰 창 경로, 리버스 프록시 인증, Supabase Data API 재동기화 적용
- SQLite 온라인 스냅샷과 원문·추출문·보고서, SHA-256 manifest를 묶는 키 비포함 백업 스크립트 적용

현재 상태: **제한 운영 구조 구현, 호스트 타이머 설치, 최종 배포·공개 경로 검증 완료**.

운영 정책 미결정: 원문 보존기간, LLM 처리 리전, 실패 알림 수신 채널, SLO/RPO/RTO. 이메일·메신저 자동 발송은 수신처와 권한이 정해지기 전까지 수행하지 않습니다.

## 하지 않은 가정

- 공통기반의 최신 기능목록과 기관별 사용 가능 범위는 제공되지 않아 코드의 키워드 규칙은 예시입니다.
- 실키로 최근 1일 수집과 단계별 LLM 연결을 검증했지만, 나라장터 API 명세 변경 가능성 때문에 실행 이력을 계속 관찰해야 합니다.
- HWP 자동 변환은 격리된 CLI, 실행시간·출력크기 제한, 고정 버전·해시 검증으로 적용했으며 신규 형식은 계속 오류목록에서 관찰합니다.
- 자동 이메일 발송과 기관 담당자 연락은 외부 상태 변경이므로 MVP 범위에 포함하지 않았습니다.
