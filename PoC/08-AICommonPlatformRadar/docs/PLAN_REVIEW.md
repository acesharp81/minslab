# 구축계획 검토 및 보완안

검토일: 2026-09-11 (KST)

## 결론

원안의 목표·공개자료 원칙·근거 중심 판정·실패 격리·MVP 우선순위는 타당합니다. 다만 실제 운영 가능성과 폴더 단독 재현성을 확보하려면 아래 항목을 선행 게이트로 추가해야 합니다. 본 PoC 골격에는 해당 보완을 반영했습니다.

## 원안에서 보완한 설계

1. **수집 실행 이력과 감사로그**: 공고 테이블만으로는 “오늘 API가 0건이었는지 실패했는지” 구분할 수 없어 `pipeline_runs`, `audit_logs`를 추가했습니다.
2. **후보 기반 첨부 호출**: 개발 트래픽 1,000건에서 본공고마다 e발주 첨부 API를 호출하면 일일 한도를 빠르게 소진하므로 목록 메타 규칙을 먼저 적용합니다.
3. **원문 인용 검증**: JSON schema만으로는 만들어낸 인용을 막지 못하므로 정규화한 입력 본문에 quote가 실제 존재하는지 검사합니다.
4. **판정 버전과 캐시**: 입력뿐 아니라 모델·프롬프트 fingerprint를 `input_hash`에 반영해 동일 구성의 재호출을 줄이고 모델 변경 결과를 분리합니다.
5. **다운로드 보안**: 확장자 외에 HTTPS, 허용 호스트, redirect 금지, 비표준 포트, 선언/실제 크기 제한을 추가했습니다.
6. **ZIP 폭탄·경로 검사**: path traversal뿐 아니라 누적 압축해제 크기를 제한하고 허용 문서만 메모리에서 처리합니다.
7. **시간대 명시**: 수집·리포트 기준은 KST, 저장시각은 UTC로 구분합니다.
8. **표본 검토**: 제외 키워드는 최종 제외가 아니며 AI 근거 또는 고예산 조건이 있으면 심층 후보로 유지합니다.
9. **운영 인증 게이트**: local mock은 무인 실행이 가능하고 production은 인증 미설정 시 degraded로 노출합니다.
10. **데이터 보존 정책**: 원문·추출문은 Git 제외, 운영 전 보존기간·삭제·백업 복구 목표를 별도 승인사항으로 둡니다.
11. **다단계 LLM 비용 가드**: 2차 입력 8,000자, 3차 100,000자, 3차 일 10건·동시 1건을 기본값으로 두고 GPT 실패 시 Nemotron으로 전환합니다.
12. **DB 분리**: 기존 `SUPABASE2_URL`과 `SUPABASE2_SERVICE_ROLE_KEY`로 Data API를 사용합니다. `poc08_` 전용 테이블과 RLS로 다른 서비스와 분리하고, 커밋 후 동기화·시작 시 재조정·로컬 장애 캐시를 둡니다.

## 보완된 단계와 완료 게이트

### Gate 0 · 외부 계약 확인

- 두 OpenAPI 활용신청과 Decoding 키 준비
- 실제 1일 응답 fixture를 비식별 저장하고 필드 매핑 확인
- e발주 첨부 URL의 실제 호스트와 Content-Disposition 확인
- 조직의 범정부 AI 공통기반 기능목록·적용 제한·표준 안내문 확보

현재 상태: **G2B 키와 기존 Supabase 2 URL/service-role 키 확인 완료**. Supabase 자격정보는 유효하고 Data API에 연결되며, 전용 테이블 마이그레이션만 최초 한 번 실행해야 합니다. Gemini 2차, GPT-5.4 mini 3차, Nemotron 3 Super 대체 경로는 공개 샘플 실호출로 스키마·근거 검증까지 통과했습니다.

### Slice 1 · 매일 쓸 수 있는 mock MVP

- 독립 실행, DB, 안전한 문서처리, 규칙/AI mock, 화면, 리포트, 회귀테스트

현재 상태: **구현 완료, 자동 검증 수행 대상**.

구현 검증 결과:

- Python 문법 및 Git diff 검사 통과
- pytest 55건 통과
- 격리 데이터에서 샘플 5건 수집·첨부 5건 파싱·분석 5건, 실패 0건
- 2회차 실행 신규 row 0건으로 upsert 확인
- Markdown/HTML 리포트 생성 및 로컬 HTTP health/API/UI 응답 확인
- Docker 이미지 빌드 및 UID/GID bind mount 방식의 컨테이너 health/UI 확인
- 검증 호스트에는 Docker Engine은 있으나 Compose 플러그인이 없어 `docker compose` 명령 자체는 미실행. 공유 대상 호스트의 Compose v2 설치를 Gate 0 준비사항에 추가

### Slice 2 · 실데이터 shadow run

- `G2B_MODE=live`, 1일 범위, 분석 비활성으로 3일 이상 shadow 실행
- 누락률, 중복률, 첨부 성공률, HWP 비중, API 소모량 기준선 수집
- 실제 fixture 기반 필드 매핑 테스트 고정

승인기준: 수집 중복 0, API 실패 재시도 가능, 공고 단위 실패 격리, 원천 payload 보존.

### Slice 3 · AI 평가와 품질 게이트

- 사람이 판정한 30~50건 골든셋 작성
- 후보 재현율을 우선 지표로 정하고 B/C/D의 근거 정확도와 질문 유용성 평가
- Gemini/GPT/Nemotron별 프롬프트·모델 버전, 비용, 지연, 실패율 관측

승인기준 제안: 근거 quote 원문 일치 100%, schema 성공 99% 이상, 후보 재현율 목표는 골든셋 승인 후 확정.

### Slice 4 · 제한 운영

- cron 또는 작업 큐로 08:00 KST 실행, 중복 실행 잠금
- Supabase Data API shadow 전환, 재동기화·백업·복구훈련, 보존기간 적용
- TLS, 기관 SSO 또는 리버스 프록시 인증, 접근/변경 감사

운영 전 미결정: 원문 보존기간, LLM 처리 리전, 실패 알림 채널, SLO/RPO/RTO.

## 하지 않은 가정

- 공통기반의 최신 기능목록과 기관별 사용 가능 범위는 제공되지 않아 코드의 키워드 규칙은 예시입니다.
- API 키가 없어 실응답과 첨부 다운로드 성공은 검증하지 않았습니다.
- 바이너리 HWP 변환 도구의 보안·라이선스·정확성이 확정되지 않아 자동 변환을 넣지 않았습니다.
- 자동 이메일 발송과 기관 담당자 연락은 외부 상태 변경이므로 MVP 범위에 포함하지 않았습니다.
