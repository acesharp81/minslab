## 1. 서비스 개요

조달췤은 나라장터 사전규격과 본공고의 제안요청서·과업지시서 등 공개 문서를 수집하고, AI로 사업 내용과 범정부 AI 공통기반 활용 조건을 분석하는 업무지원 서비스입니다. 활용 가능 사업을 발주 초기에 찾아 사용자가 근거를 검증하고 의견을 전달한 뒤, 담당자의 회신과 실제 공고 반영 여부까지 추적하는 것이 목적입니다.

분석 결과는 위반 여부를 확정하는 행정판단이 아닙니다. AI가 원문 근거와 확인 질문을 제시하고, 최종 판단과 대외 의견 등록은 사람이 수행합니다.

### 문제 정의

범정부 AI 공통기반을 구축했지만 개별 정보화사업의 발주 단계에서 활용 여부를 확인하는 체계가 부족했습니다.

- 인지도 부족 등으로 유사 AI 인프라를 개별 구축하는 사례가 발생했고 이에 대한 국회 지적이 제기되었습니다.
- 다수의 정보화사업을 수작업으로 확인해야 해 활용 가능 사업을 조기에 발굴하기 어렵습니다.
- 활용을 권고한 뒤 사업 담당자의 검토·회신과 실제 사업계획 반영 여부를 체계적으로 추적하기 어렵습니다.

### 추진 방향

| 단계 | 업무 | 시스템 지원 |
|---|---|---|
| 01 자동 탐지 | 조달 문서 수집과 AI 사업 판별 | 사전규격·본공고와 사업 관련 첨부를 수집하고 후보를 선별 |
| 02 사람의 검증 | 공통기반 기본 조건과 이용 여부 확인 | 원문 인용, 조건별 판정, 확인 질문과 심층 분석 제공 |
| 03 의견 전달 | 발주 담당자에게 활용 검토 요청 | 자연어 의견 초안과 나라장터 입력 보조 제공 |
| 04 후속 추적 | 회신과 본공고 반영 여부 관리 | 조치중·조치완료 상태와 전환 성과를 기록 |

- **AI 기반 발굴:** 사전규격 공개 단계의 제안요청서·과업지시서를 자동 분석해 활용 가능 사업을 식별합니다.
- **사람 중심 검증:** 사용자가 분석 결과와 원문 근거를 최종 확인한 뒤 담당자에게 의견을 등록합니다.
- **전주기 관리 연계:** 등록 의견의 회신과 본공고 반영 여부를 모니터링해 발굴부터 후속 조치까지 연결합니다.
- **확장 방향:** 발주 단계 모니터링에서 시작해 정보화사업 전 과정의 공통기반 활용을 지원하는 생태계를 지향합니다.

### 시험운영 성과

| 지표 | 결과 | 의미 |
|---|---:|---|
| 분석 사업 | 약 3.2만 건 | AI 자동 분석 |
| 활용 의견 제시 | 21건 | 활용 가능 사업 발굴 |
| 사업 변경 공고 | 5건 | 공통기반 활용 반영 |

9월 20일부터 약 2주간 시험운영한 결과, 약 3.2만 개 정보화사업을 분석해 21개 사업에 공통기반 활용 의견을 제시했고 그중 5개 사업이 관련 내용을 반영해 변경 공고했습니다. 이는 AI 기반 모니터링이 실제 발주 내용의 변경으로 이어질 수 있음을 확인한 단기 실증 성과입니다.

현재는 담당 업무 변경으로 실제 운영에 활용하지 않으므로 위 수치를 상시 운영 성과로 확대 해석하지 않습니다. 정확한 표현은 **단기 시험운영을 통한 정책 적용 가능성 검증**입니다.

### 200자 내외 소개 글

> **조달췤 | 3만 건을 살펴 AI 공통기반 활용 기회를 찾아내다**<br>
> 범정부 AI 공통기반을 활용할 수 있는 사업, AI가 먼저 찾아냅니다. 조달췤은 사전규격 공개 문서를 자동 분석해 활용 가능 사업을 발굴하고, 담당자 확인을 거쳐 의견 등록부터 회신 모니터링까지 지원합니다. 약 2주간 3.2만 건을 분석해 21건에 의견을 제시했고, 5건의 사업 변경 공고로 이어지며 AI 기반 정책 실행 가능성을 확인했습니다.

## 2. 판단 범위

### 공통기반 기본 조건

1. **망·데이터:** 행정망·업무망·내부망 또는 그 연계망에서 운영되거나 내부 데이터를 처리하는 서비스인지 확인합니다. 인터넷망에서 완결되는 서비스는 별도 인터넷 LLM이 더 적합할 수 있습니다.
2. **제공 모델로 구현 가능:** 공통기반이 제공하는 국내 독자 파운데이션 모델, 공개 대형모델과 공공 데이터 RAG로 구현 가능한지 확인합니다. 독자 모델이나 풀 파인튜닝이 필수라면 별도 협의가 필요합니다.
3. **국가사무:** 중앙부처·지방정부의 국가사무 또는 법적으로 위탁받은 국가사무인지 확인합니다. 공공기관 자체 내부 업무는 이용 대상에서 제외합니다.

문서에 정보가 없으면 불충족으로 단정하지 않고 **검토 필요**로 분류해 담당자에게 확인합니다.

### 업무 분류

| 코드 | 분류 | 의미 |
|---:|---|---|
| 1 | 적합·이용 | 기본 조건을 충족하고 공통기반 이용이 확인됨 |
| 2 | 적합·미이용 | 기본 조건을 충족하지만 이용 또는 우선 검토 장치가 확인되지 않음 |
| 3 | 전환·확인 필요 | 국가사무이며 망·모델 등의 보완 또는 사실 확인 후 이용 가능 |
| 4 | 명시·조건 불일치 | 이용을 명시했지만 기본 조건과 충돌하거나 확인이 필요 |
| 5 | 부적합 | 국가사무, 망·데이터, 특화모델 요건 등으로 이용 대상이 아님 |
| 6 | 비AI·적용범위 외 | AI 사업이 아니거나 감리·일반 연구·연수 등 구축 검토 대상이 아님 |

## 3. 현재 운영 상태

기준일: **2026-11-11**

- 신규 수집은 담당 업무 변경에 따라 기본적으로 비활성화되어 있으며, 기존 공고·분석·조치 기록 조회 기능은 유지합니다.
- 운영 기준 저장소는 `data/supabase-cache.db`의 로컬 SQLite입니다.
- Supabase 미러는 `POC08_SUPABASE_SYNC_ENABLED=false`로 중지되어 있습니다.
- 운영 컨테이너 이름은 `poc08-ai-common-platform-radar`, 내부 서비스 포트는 `18081`입니다. 새 독립 환경의 기본 호스트 포트는 `18080`입니다.
- JEV 연계는 인증 만료 후 제거했으며 현재 운영 구성에 포함하지 않습니다.
- 이 폴더만 복사해도 Docker Compose로 독립 실행할 수 있습니다.

### 구현 범위

- 나라장터 사전규격·본공고 수집, 재시도, 중복 제거와 단계 연결
- 사업 관련 문서만 선별하고 동일 문서의 여러 형식 중 파싱 품질이 높은 한 형식 선택
- TXT, DOCX, PDF, HWPX, ZIP과 격리된 `hwp-cli` 기반 바이너리 HWP 본문 추출
- 규칙 기반 1차 선별, 소형 모델 2차 검증, 대형 모델 3차 심층 검증
- AI 사업 근거, 사업 개요, 세 가지 기본 조건, 이용 여부, 원문 인용과 확인 질문 표시
- 조치 대상·조치중·이용 확인 공고의 최신순 목록과 페이지네이션
- 의견 초안 생성, Chrome 확장프로그램 입력 보조, 회신 확인과 수동 최종 판정
- 판정오류 신고와 수동 정정 이력
- 상태별 현황, 부적합 사유, 검토 필요→적합 및 미이용→이용 전환 성과 통계
- 의견 등록이 확인되어 조치중으로 전환될 때 SMTP 알림
- 낮은 관련성 분류의 첨부파일 자동 정리

## 사용자 안내

### 주요 화면

- **대시보드:** 어제 09:00부터 오늘 09:00까지 수집·분석한 상태와 지금 확인하거나 조치할 사업을 보여줍니다.
- **공고 목록:** 단계, 분류, 조치 상태, 기관, 기간 등으로 검색하며 한 페이지에 10건씩 확인합니다.
- **분석 내용:** 사업 개요, AI 사업 근거, 세 가지 기본 조건, 공통기반 이용 여부, 원문 근거와 확인 질문을 확인합니다.
- **통계:** 최근 30일·이번 달·이번 해 등 기간별 전체 상태와 전환 실적을 비교합니다.
- **설정:** 관리자 인증 후 담당자 정보, 나라장터 입력값, 의견 템플릿, SMTP와 판정오류 이력을 관리합니다.

### 업무 흐름

1. 대시보드에서 **조치 확인이 필요한 사업**을 엽니다.
2. 분석 내용과 원문 인용을 대조하고 부족한 정보는 담당자에게 확인합니다.
3. 판정이 잘못되었으면 **판정오류 신고**로 비AI 또는 부적합 사유를 기록합니다.
4. 사전규격의 의견 초안을 검토한 뒤 확장프로그램으로 나라장터 입력을 보조합니다.
5. 실제 저장을 확인하면 해당 사업을 **조치중**으로 전환합니다.
6. 담당자 회신이나 본공고 반영을 확인하고 이용·미이용·부적합 중 하나로 조치완료합니다.

### 의견 작성 원칙

- 법적 근거만 나열하지 말고 해당 사업의 현재 상태와 확인된 사실을 먼저 설명합니다.
- 문서에 없는 망·모델·사용자 정보는 “확인안됨”으로 표시하고 질문으로 전환합니다.
- “공통기반을 사용하지 않았다”와 “우선 검토 장치가 부족하다”를 구분합니다.
- 계획·ISP·연구용역은 향후 구축사업이 공통기반을 검토하도록 계획 반영을 요청합니다.
- 자동 생성 문구는 발송 전에 사람이 원문과 연락처를 확인합니다.

### Chrome 확장프로그램

상단 메뉴의 **확장프로그램 설치**에서 ZIP 파일과 설치 방법을 받을 수 있습니다. 확장프로그램은 나라장터 공지창 닫기, 대상 사전규격 검색, 의견 등록 화면 이동과 설정값·의견 초안 입력을 보조합니다.

보안과 오등록 방지를 위해 최종 **저장** 버튼은 누르지 않습니다. 사용자가 내용을 확인하고 직접 저장한 뒤 조달췤에서 의견 등록 여부를 확정합니다. 상세 내용은 `browser-extension/README.md`를 참고합니다.

### 통계 해석

최종 현황은 `수집 건 = 비AI 사업 + AI 사업`이며, AI 사업은 `적합(이용·미이용) + 검토 필요 + 부적합`으로 나뉩니다. 서비스의 핵심 전환 실적은 다음 두 항목입니다.

1. **검토 필요 → 적합:** 담당자 확인으로 부족 정보를 보완해 활용 가능성을 확정한 건수
2. **미이용 → 이용:** 의견·권고 후 공통기반 이용을 반영한 건수

시험운영 수치와 현재 선택 기간의 운영 통계를 혼용하지 않습니다.

### 사용 시 주의

- 공개 문서에 개인정보가 포함되어 있더라도 업무 목적에 필요한 최소 범위만 사용합니다.
- AI 분석은 보조 자료이며 최종 행정판단으로 간주하지 않습니다.
- 의견 등록, 조치완료와 판정 정정은 감사 이력에 남습니다.
- 수집이 비활성화된 동안 수동 수집·재파싱 요청은 거부될 수 있습니다.

`http://localhost:18080`을 열면 초기 환경에서는 샘플 공고 5건이 적재됩니다. 종료는 `docker compose down`이며 데이터는 이 폴더의 `data/`에 남습니다.

기본 바인딩은 `127.0.0.1:18080`입니다. 외부에 직접 공개해야 할 때만 `HOST_BIND=0.0.0.0`을 사용하고 앞단 프록시와 접근통제를 적용합니다. MinsLab 통합 경로는 `/poc/ai-common-platform-radar/`입니다.

Linux 계정 UID/GID가 1000이 아니면 `.env`의 `LOCAL_UID`, `LOCAL_GID`를 `id -u`, `id -g` 결과로 바꿉니다. 모든 런타임 경로는 프로젝트 위치를 기준으로 해석하므로 폴더 이름이나 위치가 달라도 독립 실행할 수 있습니다.

로컬 Python 실행:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python scripts/seed_sample.py
python scripts/preflight.py
uvicorn app.main:app --host 127.0.0.1 --port 18080
```

### 실데이터 전환

1. 공공데이터포털에서 **조달청 나라장터 사전규격정보서비스**와 **입찰공고정보서비스** 활용신청을 완료하고 Decoding(원본) 서비스키를 준비합니다.
2. `.env`를 다음과 같이 설정합니다.

```env
G2B_MODE=live
G2B_SERVICE_KEY=발급받은_원본_키
AUTO_SEED_SAMPLE=false
```

3. 운영 전 작은 범위로 수집만 시험한 뒤 `/health`의 `g2b_mode=live`와 `pipeline_runs`의 수신 건수·필드 매핑을 확인합니다.

```bash
python scripts/run_collector.py --lookback-days 1 --no-analyze
python scripts/reparse_failed.py
python scripts/apply_attachment_policy.py
```

개발계정 호출량을 보호하기 위해 목록을 먼저 수집하고 e발주 첨부 API는 규칙상 검토할 공고에만 호출합니다. OpenAPI base URL과 operation은 명세 변경에 대비해 환경변수로 관리합니다.

수집 활성화 상태는 `data/runtime_settings.json`과 `data/collection.disabled`에 저장되며 운영 상태 파일은 Git으로 배포하지 않습니다.

정규 배치는 04:25, 오전 재시도는 05:50, 보강 배치는 12:35, 보강 재시도는 12:55까지 종료되도록 제한합니다. 타이머는 `Persistent=false`이므로 서버가 꺼져 있던 동안의 작업을 사용자 이용 시간에 뒤늦게 실행하지 않습니다. API·CLI·systemd 동시 요청은 `DATA_DIR/poc08-collection.lock`으로 한 실행만 허용합니다.

### 분석 모델

- 2차 검증: Upstage Solar Pro 4 우선, Mistral Small 대체
- 3차 심층 검증: GPT-5.4 mini 우선, NVIDIA Nemotron 3 Super 대체
- API 키가 없거나 제공자가 실패하면 구성된 대체 경로를 사용하고, 최종 실패는 재시도 상태로 기록합니다.

키 발급 위치와 입력 방법은 [API 키 안내](docs/API_KEYS.md)를 참고합니다. 공개 메타데이터와 공개 첨부 추출문만 모델에 전달하며, 저장 전 Pydantic 스키마와 원문 인용 검증을 통과해야 합니다.

- 파싱 결과: `data/parsed/`

- 로그: `data/logs/`

현재 Supabase 미러는 비활성화 상태입니다. 다시 사용할 때는 [Supabase 마이그레이션](supabase/migrations/20260911000000_poc08_radar.sql)을 적용하고 URL·서버 전용 키를 넣은 뒤, 소량 데이터로 일관성과 장애 시 로컬 지속성을 먼저 검증합니다. 재활성화하면 비워 둔 원격 테이블에 로컬 데이터가 다시 적재될 수 있습니다. 여러 서비스가 하나의 SQLite 파일을 공유하지 않도록 합니다.

### 백업·복구와 보안

- `python scripts/backup_data.py`로 DB와 핵심 설정을 백업합니다.
- 로그까지 필요하면 `python scripts/backup_data.py --include-logs --output-dir ./backups`를 사용합니다.
- 생성된 `.sha256` 파일로 압축파일을 검증하고, 복구 전 현재 파일을 별도로 보존한 뒤 서비스와 배치를 중지합니다.
- `.env`, DB 백업, 담당자 연락처와 의견 내용은 외부에 공개하지 않습니다.
- 원문 다운로드는 허용 도메인·HTTPS·확장자·크기 제한을 유지합니다.
- 판정·상태 변경 API의 관리자 인증과 감사로그를 제거하지 않습니다.
- Docker의 `hwp-cli` 바이너리 해시 검증, 문서별 실행시간·출력크기 제한과 ZIP path traversal 차단을 유지합니다.

### 처리 파이프라인

```text
나라장터 수집
  → 공고 upsert·단계 연결
  → 사업 문서 선택·중복 제거
  → 안전한 다운로드·본문 추출
  → 규칙 기반 후보 판정
  → 2차 AI 사업 검증
  → 3차 공통기반 심층 검증
  → 근거 인용 검증·1~6 분류
  → 사람의 검토·의견 등록
  → 회신·본공고 반영 추적
  → 상태·전환 성과 집계
```

### 핵심 설계 규칙

1. **미확인과 불충족을 분리합니다.** 문서에 없는 정보는 검토 필요이며 부적합 근거가 아닙니다.
2. **조달청 표기를 발주기관으로 오인하지 않습니다.** 국가사무 판단은 원문의 주관·발주 부서와 위탁 관계를 사용합니다.
3. **공공기관 자체 업무를 적합으로 올리지 않습니다.** 법적 국가사무 위탁 근거가 없다면 부적합 또는 확인 필요입니다.
4. **선택적 사용 명시와 이용 확정을 구분합니다.** “활용할 수 있다”는 이용 확인이 아니라 우선 검토 장치의 강도를 판단하는 근거입니다.
5. **AI 판정에는 검증 가능한 원문을 남깁니다.** AI 사업 근거와 세 가지 기본 조건마다 인용 또는 미확인 상태가 있어야 합니다.
6. **상태 전환은 이력으로 남깁니다.** 자동 분석, 사용자 정정, 의견 등록, 회신과 조치완료를 덮어쓰지 않습니다.
7. **비AI·부적합 자료만 정리합니다.** 판정과 감사로그는 보존하고, 공통기반 이용 가능성이 있는 원문은 유지합니다.

### 분석 결과 계약

심층 분석은 최소한 다음 내용을 구조화해 반환해야 합니다.

- `0. 개요`: 사업 목적과 AI 서비스 내용 요약
- AI 사업 여부와 원문 근거
- `1. 망·데이터`: 운영망, 데이터 위치, 연계 가능성, 근거 또는 확인 질문
- `2. 모델·서비스`: 제공 모델/RAG로 구현 가능한지와 특화학습 필요성
- `3. 국가사무`: 발주·주관기관, 위탁 관계, 공공기관 내부 업무 여부
- `4. 공통기반 사용 여부`: 확정 이용, 선택적 명시, 미반영을 구분한 근거
- 1~6 최종 분류, 신뢰도, 문제 발견 내용과 권고 조치

프롬프트만 바꾸지 말고 스키마, 저장 투영, 기존 데이터 재분류와 화면 표시를 함께 변경합니다.

## 4. 문서 유지 원칙

- 정책 목적, 판단 기준, 시험운영 성과와 한계는 모든 파생본에 동일하게 유지합니다.
- 현재 운영 상태에는 기준일을 적고, 설정·모델·스케줄이 바뀌면 코드와 함께 수정합니다.
- 시험운영 성과와 실시간 운영 통계를 구분합니다.
- 비밀키, 실제 비밀번호, 개인 연락처와 운영 DB 내용은 문서에 넣지 않습니다.
- 사용자 화면 명칭과 상태값은 실제 UI·API·통계 정의와 일치시킵니다.
- 영상이나 다른 프로젝트의 산출물은 이 문서에 포함하지 않습니다.
