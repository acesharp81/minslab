# AIWorks 구축 계획

## 검증 결론

원안의 플랫폼/활용 서비스 분리, 계약 우선, 최소권한 원칙은 유지한다. 다만 초기 단계에서 각 화면을 독립 개발하면 계약이 어긋날 위험이 있으므로 예산요청서 한 건의 수직 흐름을 먼저 완성하고 공통 계약을 추출한다.

## 경계

- Platform Core: 의도 분석, 실행 계획, 모델 라우팅, 권한 승인, 감사 이벤트
- Capability MCP: 문서 어댑터, 예산 양식, SW 대가 산정, 공통데이터
- Experience: 문서 편집기, MCP 제작기, MCP 스토어
- Data Plane: 원문/출처, 공통데이터 버전, 산출물, 감사 로그

## 단계

1. 계약 기반 초기 버전: Manifest, 공통데이터, 실행 계획 Schema와 브라우저 샌드박스
2. 서버 실행 계층: 서명된 일회용 승인 토큰, SQLite 실행 큐·영속 감사 저장소 (초기 구현 완료)
3. 무료 모델 라우팅: 로컬 의도 분석, 무료 전용 모델 레지스트리, 외부 전송 승인 (초기 구현 완료)
4. 문서 어댑터: HWPX 분석·검증·재패키징·다운로드 초기 구현 완료. RHWP 연계는 로컬 인증 IPC 기반 Windows 네이티브 브리지 계약 정의 완료, 구현 대기
5. 조직 스토어: Manifest·권한·고정 의존성 정적 검사, 번들 SHA-256과 조직 서명, 버전 고정 설치, 실행 계획 연계와 롤백 초기 구현 완료. 운영용 비대칭 게시자 서명·실제 번들 악성코드 검사는 후속
6. 지식 계층: 문서·공통데이터·노트 그래프, 출처 기반 질의응답, 접근등급·기준일 필터, 시점별 값·변화량 비교와 근거 필수 노트 저장 초기 구현 완료
7. 멀티모달 확장: 문서·코드·이미지·음성·영상 어댑터 계약, 실제 바이트 기반 로컬 검사, 최소권한 프리셋 계획과 준비/미리보기 상태 분리 초기 구현 완료. 이미지 생성·음성 전사·영상 요약 실행기는 후속 연결
8. 운영 보강: 저장소·서명·모델·출처·키·어댑터 readiness, 예산요청서 승인 E2E, stale-document 실패 주입과 영속 수용성 이력 구현 완료
9. MCP 제작 수직 흐름: 자연어 명세 영속 초안, 정확한 의존성 버전과 최소권한 생성, 서버 계약 검증, 공개 범위·원본 포함 재확인, 서명 게시와 스토어 고정 설치 구현 완료
10. 제작기 사용성: HWPX·PDF·Markdown·TXT 기준 문서 실제 업로드, 로컬 구조 검사, 초안별 영속 저장·재개, 원본 선택 포함, 문서 SHA-256 재검증과 변조 패키지 격리 구현 완료. PDF 본문 추출, 기준 문서별 테스트 사례 자동 생성과 조직별 인증·카탈로그 분리는 후속
11. 작업공간 사용성: 기본 문서의 제목·본문·표 직접 편집과 로컬 초안, 저장·되돌리기·HTML 내보내기, 가져온 HWPX 전체 문단 편집·순차 충돌 검사·버전 저장·다운로드 구현 완료. 편집기·관리 화면·사이드바·채팅의 독립 스크롤과 Firefox 상호작용 회귀 테스트 추가 완료
12. 문서 생명주기: 일반 문서의 서버 저장·revision 충돌 방지·목록·재열기, HWPX 산출물 바이트 영속화·재열기, 안전한 기본 서식과 실시간 미리보기 구현 완료. Firefox에서 직접 편집→서식→저장→재열기와 HWPX 다중 문단 수정→다운로드→버전 재열기 흐름 검증. HWPX 구조 서식 편집과 RHWP 네이티브 실행은 후속
13. RHWP 전체 기능 MCP: document.rhwp@1.0.0 스토어 기본 설치, 20개 고수준 도구, HAction/HParameterSet 확장 실행, 같은 사용자 Windows COM 에이전트, 허용 폴더·HMAC·nonce·만료·권한·명시적 확인·감사 로그 구현 완료. Linux 자동화 테스트는 계약과 모의 브리지까지 수행하며 실제 한글 버전별 액션 호환성은 Windows 수용성 환경에서 확인
14. HWPX 구조 렌더링: 평문 문단 목록을 section/block 구조로 교체하고 표·행·셀·rowSpan·colSpan·빈 셀·셀 내부 문단과 개체 경계를 렌더링. 병합 표가 포함된 Firefox HWPX에서 표시→다중 문단 수정→저장→다운로드→버전 재열기 검증 완료. 글꼴·도형 좌표·페이지 나눔의 픽셀 단위 충실도는 Windows RHWP 미리보기 연동 대상
15. MCP 네이티브 문서 세션 전면 개편: 가져온 문서의 contenteditable 제거, 의도·형식 분석 후 document.rhwp 우선 선택, Windows RHWP transform/PDF 스냅샷/원본 산출물과 HWPX 안전 대체를 동일 session·command·revision 계약으로 통합. 캔버스 선택→MCP 명령→원본 변경→새 스냅샷→다운로드·재열기를 Firefox에서 검증. HWP/HWT/HML은 Windows RHWP가 없으면 명시적으로 차단
16. Prompt-first·편집기 MCP 작업공간: 첫 화면의 명령+첨부에서 의도 분석 후 업무 MCP와 형식별 편집기를 함께 로딩. 좌측 Orchestrator, 우측 편집기 구조로 전환하고 RHWP 0.8.2 Studio/WASM을 내부 자체 호스팅. HWP/HWPX/HWT/HML 원본 UI 직접 편집, HWPX AI 선택 모드, Markdown 분할 미리보기와 코드 편집기, 선택 영역 제안·적용 및 revision 저장을 Firefox에서 검증 완료
17. RHWP 네이티브 AI 선택 편집: RHWP 원본 커밋 `2dced7b`에 `selection-edit-v1` 임베드 capability를 추가하고 본문·표 셀 선택 조회와 원자적 `ReplaceSelectionCommand`를 구현. 공식 wasm-pack 0.15.0과 RHWP Studio 전체 계약 테스트 641개로 빌드한 뒤, 네이티브 선택→Orchestrator 비교 제안→적용→원본 산출물 revision 저장·다운로드 흐름을 AIWorks에 연결하고 Firefox 회귀 검증 완료

## 초기 버전 완료 기준

- 동일 Manifest가 제작기, 스토어, 실행 계획에서 보인다.
- 외부 전송 권한은 기본 거부이며 실행 전 설명과 승인이 필요하다.
- 공통데이터의 값에 기준일, 출처 위치, 신뢰도와 변경 이력이 있다.
- 문서 제안을 적용·취소·되돌릴 수 있고 감사 로그가 남는다.
- 샘플 데이터와 계약 테스트가 자동 검증된다.
