# AIWorks 범용 MCP Builder vNext

> 기준일: 2026-08-15
> 현재 구현: AIWorks 0.24.0 데이터 MCP RAG 체험 슬라이스
> 문서 역할: MCP Builder의 제품 범위와 후속 구현 기준

## 제품 정의

MCP Builder는 양식 등록 전용 도구가 아니다. AIWorks의 모든 확장 기능을 사용자가 만들고 검증하고 공유하는 단일 제작 환경이다.

사용자는 코드를 직접 작성하지 않아도 다음 내용을 입력해 MCP 초안을 만들 수 있어야 한다.

- 무엇을 처리하는 기능인지
- 어떤 입력과 결과를 사용하는지
- 실행 시 지켜야 할 유의사항
- 작업을 수행하는 처리 순서
- 사용자가 기능을 호출할 수 있는 요청 예시
- 필요한 기준 파일, 양식, 데이터 Schema와 샘플
- 모델·외부 통신·문서 및 데이터 읽기·쓰기 권한
- 개인·프로젝트·조직·공개 공유 범위

Builder는 입력 내용을 Manifest, Capability, 입출력 Schema, 실행 가이드, 권한과 참조 자산으로 패키징한다. 검증을 통과한 정확한 버전만 서명해 MCP 스토어에 게시한다.

## 유형은 제작을 돕는 프로필이다

유형은 플랫폼 Core의 고정 업무 분류가 아니라 사용자가 빠르게 만들 수 있도록 기본 입력과 검증 규칙을 제공하는 제작 프로필이다. 새로운 유형 프로필도 향후 플러그인으로 추가할 수 있어야 한다.

| 유형 | 사용 목적 | 핵심 입력 | 기본 검증 |
|---|---|---|---|
| 양식 MCP | 문서·데이터를 등록 양식으로 변환 | 양식 원본, 작성 유의사항, 필드 대응 및 처리 순서 | 양식 파일 포함, 내용 보존 정책, HWPX/PDF 구조 |
| 처리 MCP | 반복 업무와 승인 단계를 자동화 | 처리 순서, 조건, 체크포인트, 입력·결과 예시 | 2단계 이상 절차, 부작용·재시도·승인 경계 |
| 데이터 MCP | DB·API·파일 데이터를 조회·정규화 | 데이터 출처, 조회 조건, 기준일, 응답 Schema | 출처·권한·기준일·읽기/쓰기 경계 |
| 일반 도구 MCP | 특정 도구 또는 변환 기능 제공 | 호출 지침, 인자, 결과와 오류 계약 | 입력·출력 Schema, 런타임과 최소권한 |

## 양식 MCP 제작 흐름

1. 사용자가 HWPX 또는 PDF 양식 파일을 `양식 원본` 역할로 올린다.
2. 양식 자체의 작성 유의사항을 한 줄씩 입력한다.
3. 프롬프트 또는 단계 입력으로 다음 처리 절차를 작성한다.
   - 고정 영역과 입력 영역 구분
   - 원천 문서의 제목·문단·표·메타정보를 양식 필드에 대응
   - 확인할 수 없는 값의 처리 방식
   - 검증, 사용자 확인과 새 revision 저장 방식
4. 사용자가 실제로 부를 요청 예시를 입력한다.
5. Builder가 `document.template.apply` Capability와 HWPX 입출력 계약을 생성한다.
6. 양식 파일 해시, 파일 포함 여부, 처리 가이드와 권한을 샌드박스에서 검사한다.
7. 통과한 패키지를 서명·게시하고 프로젝트 또는 조직에서 버전을 고정 설치한다.

양식 파일만으로 의미가 충분하지 않다. 파일, 유의사항, 처리 절차와 결과 검증 규칙을 합친 것이 하나의 양식 MCP다.

## 0.21에서 구현한 범위

- `template`, `process`, `data`, `tool` 유형 선택 UI
- 유형별 Capability와 입출력 Schema 생성
- 실행 지침, 유의사항, 처리 순서, 호출 예시와 데이터 출처 구조화
- 첨부파일 역할: 양식 원본, 가이드, 입력·결과 샘플, 데이터 Schema
- 양식 MCP의 원본 파일 포함 및 `document.read/write` 권한 검사
- 처리 MCP의 2단계 이상 절차 검사
- 데이터 MCP의 데이터 출처 검사
- 로컬 파일 구조·SHA-256, 최소권한, 네트워크 경계와 고정 의존성 검증
- 기존 서명 게시·스토어 설치 흐름 유지

## 0.22에서 구현한 동적 실행 범위

- Builder Manifest에 `prompt` 또는 `composite` 실행 Adapter를 자동 선언한다.
- 게시 시 Capability를 `mcp_capabilities`에 색인하고 기존 Builder 패키지도 시작 시 백필한다.
- 활성 설치 상태이고 서명·해시가 유효한 정확한 고정 버전만 Registry에 노출한다.
- Resolver가 호출 예시, MCP 이름과 실행 가이드의 일치도를 계산한다.
- Planner가 선택한 Capability, 패키지 버전, 권한과 실행 Adapter를 Binding으로 저장한다.
- 기존 승인 토큰의 최소권한·만료·일회성 소비 경계를 통과한 동적 계획만 Builder Runtime에서 실행한다.
- Prompt Runtime은 실행 가이드와 텍스트 참고자료를 모델 입력으로 조립한다.
- Composite Runtime은 처리 절차를 실행 파이프라인으로 노출하고 보고서 HWPX를 생성할 수 있다.
- 양식 Composite Runtime은 등록 HWPX의 `{{title}}`, `{{content}}`, `{{body}}`, `{{date}}`, `{{source_filename}}`를 현재 HWPX 내용으로 치환하고 새 revision 적용 결과를 만든다.
- Builder 패키지의 임의 코드는 실행하지 않는다.

## 0.23에서 구현한 체험 가능한 Studio 범위

- 문서 탐색기와 채팅 패널을 숨긴 전체 폭 제작 화면에서 Studio가 독립 작업공간을 사용한다.
- 양식·처리·데이터·일반 도구 카드를 선택하면 실제 편집 가능한 빠른 예시가 입력된다.
- 초안, 자료, 검증, 게시, 설치의 5단계 진행 상태와 저장·설치·Capability 수를 한 화면에서 확인한다.
- 검증된 초안을 게시하면 화면을 이탈하지 않고 권한 확인 후 바로 설치할 수 있다.
- 설치가 끝난 MCP만 Capability Registry에 표시되며 호출 문구의 선택 예정 패키지·버전·매칭 근거를 미리 본다.
- `채팅에서 실행`으로 동일 요청을 승인·실행하고 생성된 HWPX 산출물을 RHWP 편집기에 연다.
- HWPX 시작 양식을 내려받아 한글에서 서식을 편집하고 플레이스홀더를 유지한 채 양식 MCP 원본으로 올릴 수 있다.

## 0.24에서 구현한 데이터 MCP RAG 범위

- `검색 데이터 원본` 역할로 PDF·HWPX·Markdown·TXT 여러 파일을 한 번에 첨부한다.
- PDF는 로컬 `pdftotext` 경계에서 페이지별 텍스트를 추출하고 1,200자·180자 중첩 청크를 만든다.
- 초안 화면에서 게시 전에 질문을 입력해 검색 점수, 발췌문과 원문 페이지를 확인한다.
- 데이터 원본 포함, RAG 청크와 출처 인용 계약이 없으면 샌드박스 검증·게시를 차단한다.
- 게시된 청크는 패키지·버전·원본 해시와 함께 고정하고 `retrieval` Adapter로 실행한다.
- Resolver는 호출 예시뿐 아니라 데이터 질의 의도와 등록 PDF 본문 주제를 비교해 설치 MCP를 선택한다.
- 로컬 모드는 검색 근거를 그대로 인용하고, 외부 모델 전송을 명시 승인한 경우 Solar Pro 3가 검색 청크만 받아 근거 번호가 붙은 답을 합성한다.
- 스캔 PDF는 원본으로 첨부할 수 있지만 검색 청크가 없으므로 OCR 전에는 데이터 MCP 검증을 통과하지 못한다.

## 현재 제한과 다음 구현

0.23은 사용자가 설치형 Builder MCP를 직접 만들고 대화에서 발견·승인·실행해 볼 수 있는 최소 종단 흐름이다. 전체 플랫폼 Runtime은 아직 다음 제한이 있다.

- 양식 자동 적용은 플레이스홀더가 들어 있는 HWPX만 지원한다. PDF는 현재 작성 가이드 자료로만 사용한다.
- 표·결재란·반복 행을 자동으로 분석해 필드 후보를 만들고 사용자가 보정하는 화면은 아직 없다.
- 데이터 MCP는 PDF·HWPX·UTF-8 텍스트 파일의 로컬 RAG를 지원한다. 실제 DB·API Connector와 자격증명 Vault는 아직 연결되지 않았다.
- Prompt/Composite/Retrieval은 지원하지만 격리된 Code Runtime은 의도적으로 비활성 상태다.
- Resolver는 호출 예시와 문자열 일치 기반이며 평가 점수·호환성·비용·지연시간 순위는 아직 없다.
- 기존 `plans/executions` 호환 경로를 사용하므로 단계별 재시도·중단 후 재개는 아직 제공하지 않는다.

다음 구현 순서는 다음과 같다.

1. 양식 필드·표·결재란 자동 분석과 사용자 보정 화면
2. Builder 샌드박스에서 샘플 입력→예상 결과 비교 실행
3. 실제 DB·API 데이터 Connector와 자격증명 경계
4. 프로젝트별 설치·승인 Grant와 Capability 선호 정책
5. MCP 평가 점수, 호환성, 비용·지연시간 순위와 롤백 검증
6. 단계별 영속 Workflow Runtime과 실패 Step 재개
7. 검증된 Code Runtime과 제작 유형 프로필 플러그인 계약

이 실행 계층이 연결되면 사용자가 만든 양식 MCP, 처리 MCP와 데이터 MCP가 기존 하드코딩 MCP와 동일한 방식으로 대화 중 동적 로딩된다.
