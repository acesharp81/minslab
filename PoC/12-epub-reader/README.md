# 12 · 책자리 — EPUB · PDF 리더

EPUB·PDF 파일을 브라우저에서 열어 읽고, 책·읽던 위치·책갈피를 같은 브라우저에 저장하는 로컬 서재입니다.

- 서비스: `/epub` → `/poc/epub-reader/`
- 메뉴: **포트폴리오 12** · `/portfolio?project=epub-reader`
- 홈페이지 메뉴 분류만 변경했습니다. `PoC/12-epub-reader/` 폴더, 번호 12, `/epub`와 `/poc/epub-reader/` URL 및 기존 IndexedDB는 유지합니다.
- 기존 루트 ASGI에서 정적 파일을 제공합니다. 별도 운영 프로세스·포트·DB·환경변수가 필요하지 않습니다.

## 사용 방법

1. **책 추가**로 EPUB 또는 PDF를 선택하거나 서재로 파일을 끌어놓습니다. 여러 파일도 추가할 수 있습니다.
2. 서재의 책을 열면 기본으로 두 쪽이 나란히 표시됩니다. 이전·다음 쪽 버튼, 방향키·PageUp/PageDown, 마우스 휠이나 좌우 스와이프로 넘깁니다. 장 끝에서는 다음 장으로 이어지고, 목차로 원하는 장을 바로 열 수 있습니다.
3. **＋ 책갈피**는 현재 펼친 페이지의 첫 문장을 저장합니다. **목차 · 책갈피 → 책갈피**에서 이동하거나 삭제합니다.
4. 다시 방문하면 마지막으로 열었던 책과 읽던 문단을 복원합니다. **서재**로 돌아가 종료하면 다음 방문에도 서재가 열립니다.
5. 글자 크기(14–30 px), 두 쪽·한 쪽 보기와 종이·밝게·어둡게 테마도 저장합니다. 읽기 도구 모음을 한 줄(데스크톱 48 px, 모바일 44 px)로 합치고, 하단 진행 표시도 30–32 px로 줄여 본문에 화면을 최대한 할당합니다. 좁은 화면의 도구 모음은 가로로 밀어 설정을 선택할 수 있습니다. 책 삭제는 확인 후 해당 책·책갈피·독서 기록을 함께 제거합니다.

동일한 파일은 SHA-256으로 식별합니다. 파일 이름을 바꿔도 기존 책과 책갈피를 유지합니다. 내용이 변경된 EPUB은 별도의 책입니다.

## 저장 방식과 지원 범위

브라우저 IndexedDB `bookjari-poc12`에 책 정보(`books`), 원본 EPUB Blob(`files`), 읽기 설정(`settings`)을 분리 저장합니다. 최초 파일과 메타데이터 등록·삭제는 하나의 트랜잭션입니다. 진행 위치와 책갈피는 책별로 저장되며 본문 변경 없이 설정만 바꿔도 문단과 문단 내 글자 위치를 사용해 복원합니다. 창 크기나 보기 설정이 바뀌면 같은 글자가 포함된 페이지를 다시 펼칩니다. 기존 스크롤 방식의 책갈피도 해당 문단으로 복원합니다. 쪽 번호는 현재 장 안의 번호이며, 화면 크기·글자 크기에 따라 바뀝니다. 화면 진행률은 장 수와 장 안의 페이지 비율을 이용한 근사치입니다.

파일과 독서 기록은 서버로 전송하지 않습니다. 저장 범위는 **접속 주소의 출처·브라우저·프로필**이며, 기기 간 동기화는 없습니다. 브라우저 데이터 삭제·시크릿 창 종료·브라우저의 저장 공간 회수 시 데이터가 없어질 수 있으므로 원본 EPUB은 보관하세요. 저장 실패 시 성공으로 표시하지 않고 안내를 제공합니다.

지원:

- DRM 없는 EPUB 2/3, OPF spine, EPUB 3 nav 및 EPUB 2 NCX 목차
- 한국어·영문 본문, 장 내부 앵커, 장 간 링크, 이미지, SVG 이미지 표지, 표·루비·인용문
- 파일당 50 MB. EPUB 압축 해제 예상 총량 150 MB, 최대 5,000개 항목
- 데스크톱·모바일 반응형 레이아웃

제한:

- DRM으로 암호화된 본문, 오디오·비디오·스크립트 실행은 지원하지 않습니다.
- 읽기 전용 재배치 화면입니다. 출판사 CSS·내장 글꼴·고정 레이아웃을 재현하지 않습니다. 만화·교재 등의 복잡한 고정 레이아웃은 원본과 다르게 보일 수 있습니다.
- 장 텍스트는 8 MB, 개별 이미지는 15 MB까지 처리합니다.
- 초기 사이트 접속은 네트워크가 필요하며 서비스 워커 기반의 완전한 오프라인 실행은 제공하지 않습니다.

## 구조와 보안

```text
project.json              # 포트폴리오 12 메뉴 등록
web/index.html            # 서재·리더·삭제 확인
web/styles.css            # 반응형 UI 및 테마
web/app.js                # 파일 등록, 읽기, 책갈피, 설정
web/pagination.js         # 두 쪽 페이지 나누기·글자 위치 복원
web/epub.js               # EPUB 파싱·로컬 이미지·본문 정화
web/pdf.js                # PDF.js 문서·두 쪽 캔버스·확대·목차
web/storage.js            # IndexedDB 트랜잭션
web/vendor/               # JSZip 3.10.1 / DOMPurify 3.4.17 / PDF.js 6.4.299 + 라이선스
tests/browser_reader.py  # 생성 EPUB 기반 실제 Chromium 검증
```

본문은 [DOMPurify](https://github.com/cure53/DOMPurify)로 정화하고 앱 DOM과 분리된 iframe에서 표시합니다. iframe은 `allow-same-origin`만 허용하고 스크립트·폼·팝업·상위 탐색을 허용하지 않습니다. 본문 CSP는 네트워크와 스크립트를 차단하고 ZIP에서 만든 Blob 이미지만 허용합니다. 출판사 스타일과 이벤트, 외부 URL을 제거합니다. [JSZip](https://stuk.github.io/jszip/documentation/api_jszip/load_async.html)으로 브라우저에서 압축을 읽으며 라이브러리를 서비스 자체에서 제공하므로 CDN에 의존하지 않습니다.

공용 `main.py`는 `/epub` 단축주소와 `/poc/epub-reader/`의 GET/HEAD만 추가합니다. 정적 파일 요청은 웹 디렉터리 내부로 제한하고, 파일 업로드 API는 만들지 않습니다.

## 실행과 검증

독립 화면 확인:

```bash
python3 -m http.server 18122 --bind 127.0.0.1 --directory PoC/12-epub-reader/web
# http://127.0.0.1:18122/
```

루트에서 실행:

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_epub_reader.py' -v
.venv/bin/python -m unittest discover -s tests -p 'test_portfolio_catalog.py' -v
# Playwright가 설치된 Python 사용. browser_reader.py의 Chromium 경로는 환경에 맞춰 조정합니다.
python PoC/12-epub-reader/tests/browser_reader.py --url http://127.0.0.1:18122/
```

브라우저 검증은 임시로 생성한 EPUB으로 파일 열기, EPUB 2/3 목차, 로컬 이미지, 읽던 문단의 새로고침 복원, 책갈피 추가·이동·삭제, 중복 파일, 잘못된 파일, 검색·삭제 지속성, 글자 크기·테마, 모바일 가로 넘침, 외부 요청·스크립트 차단을 검사합니다. 실제 사용자의 EPUB이나 브라우저 저장소는 사용하지 않습니다.

2026-10-31 검증: 공용 API 27개, PoC 12 라우트 4개, 카탈로그 2개 테스트 통과. 운영 주소의 데스크톱(1440 px)·모바일(390 px) Chromium에서 위 독서 흐름을 통과했고, 저장 용량 부족 시 등록 트랜잭션과 책갈피 롤백도 확인했습니다. 홈페이지 포트폴리오 12 임베드 및 `/epub` 접속은 정상입니다.

두 쪽 보기 검증: 데스크톱·모바일에서 연속된 두 페이지 표시, 장 경계 이동, 즉시 새로고침 복원, 책갈피·글자 크기·한 쪽 전환과 도구 모음 높이를 검사합니다.

두 쪽 보기 운영 검증 완료: 기존 스크롤 책갈피, 960↔1440 px 창 크기 변경, 방향키·휠, 마지막 페이지 경계, 한 쪽↔두 쪽 전환 후 같은 글자 복원을 확인했습니다.

## PDF 읽기

PDF도 같은 서재에서 추가·검색·삭제합니다. 첫 페이지가 표지가 되고 문서의 제목·저자·페이지 수를 표시합니다. 파일에 제목이 없으면 파일명을 사용합니다. PDF와 EPUB의 파일 및 책갈피는 같은 IndexedDB에 형식별로 저장되며 기존 EPUB 데이터의 변환이나 삭제는 없습니다.

- 기본 두 쪽 보기(1–2, 3–4 …). 마지막 페이지가 홀수이면 오른쪽을 비웁니다.
- 한 쪽·두 쪽 전환, 목차가 있는 PDF의 내장 목차, 페이지 번호 입력 이동
- 문서 전체의 실제 페이지 번호로 읽던 곳과 책갈피 저장·복원
- 원본 배치를 유지하므로 글자 크기 대신 **화면 맞춤·125%·150%·200%** 확대 제공. 확대 상태에서는 스크롤로 페이지의 나머지 영역을 읽습니다.
- 테마는 도구 모음과 배경에 적용합니다. PDF의 그림·글자 색상은 원본을 유지합니다.
- 텍스트 PDF, 스캔 이미지 PDF, 회전·가로 페이지 지원. 암호가 걸린 PDF는 안내 후 등록하지 않습니다.

[Mozilla PDF.js](https://mozilla.github.io/pdf.js/) 6.4.299를 작업자와 CMap·표준 글꼴·WASM·ICC 자산까지 서비스 자체에서 제공합니다. 파일은 브라우저 메모리와 IndexedDB에만 존재합니다. PDF는 캔버스에 표시하고, 폼·문서 스크립트·첨부파일·외부 링크 실행은 제공하지 않습니다. 인쇄용 주석·폼 오버레이는 표시하지 않습니다. 페이지당 렌더링 버퍼를 최대 400만 픽셀로 제한하고 이전 페이지의 렌더링 작업과 자원을 정리합니다.

PDF 브라우저 검증:

```bash
python PoC/12-epub-reader/tests/browser_pdf.py --url http://127.0.0.1:18122/
```

테스트는 생성 PDF로 두 쪽·한 쪽, 이미지·회전·가로 페이지, 확대·테마·창 크기 변경, 목차·페이지 이동, 홀수 마지막 쪽·1페이지 문서, 책갈피·새로고침 복원, EPUB 혼합 서재, 중복·삭제·손상 파일을 검사합니다.

2026-10-31 PDF 운영 검증: 데스크톱·모바일에서 PDF 읽기 전 흐름과 한국어 CMap, 혼합 서재를 통과했습니다. EPUB 회귀·기존 사이트 API 27개·리더 라우트 4개·카탈로그 2개도 통과했습니다. 홈페이지 포트폴리오 선택 및 유지된 서비스 URL을 브라우저에서 확인했습니다.
